    Batch meta txn: ALTER TABLE SET TAG transactional isolation.
    Verifies:
    1. ROLLBACK reverts tag value (single table)
    2. Other sessions cannot see uncommitted tag changes
    3. COMMIT makes tag visible
    4. ROLLBACK reverts multi-table tag changes
    5. Multi-table isolation
    6. Multi-table COMMIT visibility
    7. Non-txn ALTER TAG conflict when another session holds PRE_ALTER
    8. Virtual child table SET TAG: in-txn visibility, out-txn isolation,
    ROLLBACK reverts, COMMIT visible, concurrent conflict blocked
    9. Virtual child table CREATE/DROP: duplicate CREATE→error, DROP+ROLLBACK→restored,
    DROP+COMMIT→removed, base-table pre-exists CREATE+ROLLBACK→not exist,
    base-table pre-exists CREATE+COMMIT→visible to all
    10. Virtual child table created in txn: CREATE+SET TAG+COMMIT, CREATE+DROP+COMMIT
    11. Virtual super table ADD/DROP COLUMN: in-txn visibility, out-txn isolation,
    ROLLBACK reverts, COMMIT visible
    12. Virtual super table ADD/DROP TAG: in-txn visibility, out-txn isolation,
    ROLLBACK reverts, COMMIT visible
    13. Virtual normal table CREATE/DROP: in-txn visibility, out-txn isolation,
    ROLLBACK reverts, COMMIT visible
    14. Repeated SET TAG on same child in one txn (single-table path): outside session
    always sees the ORIGINAL value, COMMIT shows the last value, ROLLBACK reverts
    to the ORIGINAL (regression: txnOrigVer must keep the pre-txn version, not the
    previous in-txn version)
    15. Repeated WHERE-based bulk SET TAG on same children in one txn (pre-scan path):
    same guarantees as s14 across multiple children
    16. Repeated SET TAG on the same VIRTUAL child in one txn: outside session sees the
    ORIGINAL value (not the previous in-txn value), ROLLBACK reverts, COMMIT wins
    (mirrors the user-reported virtual-table repro)
    17. Repeated SET TAG via super table with a single named child (`using stb ...
    where tbname='x'`, action 20 pre-scan, nChildren==1): keeps ORIGINAL version
    18. WHERE-based bulk SET TAG takes a per-child txn lock on every matched child, so
    a concurrent non-txn ALTER on those children is refused and cannot clobber the
    recorded pre-txn version; unmatched children stay writable (regression)
    path: cases/21-MetaData/test_meta_batch_txn_alter_tag.py

    Batch meta txn: batch (multi-object) statement semantics.
    Verifies:
    1. DROP TABLE batch: in-txn isolation, ROLLBACK restores all, COMMIT removes all
    2. DROP TABLE batch is atomic when a clause names a missing table (nothing is
    dropped); a duplicated name succeeds outright without dedup
    3. IF EXISTS protects only the clause it is attached to; a later missing table
    still fails the whole statement atomically
    4. DROP VTABLE batch rejects a non-virtual table and a missing table atomically,
    then rollback/commit behave correctly for a clean batch
    5. Cross-database batch drop in one statement: isolation, ROLLBACK, COMMIT
    6. Multi-subtable CREATE in one statement: isolation, ROLLBACK, COMMIT
    7. Multi-table SET TAG across vgroups: isolation, ROLLBACK, COMMIT
    8. WHERE-based bulk SET TAG (vnode pre-scan path): isolation, ROLLBACK, COMMIT
    9. WHERE-based bulk SET TAG takes a per-child txn lock so a concurrent session
    cannot clobber the recorded pre-txn version (regression)
    10. Object counting: a batch statement is charged per object and there is no
    per-statement object cap
    11. WHERE-based bulk SET TAG accounting: the vnode reports its real match count
    back so the statement is charged per object rather than as 1, and the
    per-vnode budget share does not spuriously reject statements that fit
    12. CREATE TABLE .. FILE and uid-replay DROP .. WITH <uid>: both batch forms
    behave transactionally (isolation / ROLLBACK / COMMIT)
    path: cases/21-MetaData/test_meta_batch_txn_batch_ops.py

    Batch meta txn: full ALTER action matrix inside a transaction.
    Verifies, each through in-txn visibility / ROLLBACK / COMMIT. Numbers match the
    m<N> case names, so a gap here means a genuinely missing case:
    m1. MODIFY COLUMN (widen varchar) on super table and normal table
    m2. MODIFY TAG (widen tag) on super table
    m3. RENAME COLUMN on super table (new this release); child tables follow and
    data stays readable since colId is preserved
    m4. ADD COLUMN with ENCODE/COMPRESS/LEVEL, then MODIFY that column's compression
    within the same txn
    m5. MODIFY COLUMN compress/level on a column that predates the txn, so ROLLBACK
    restores the old codec instead of dropping the column
    m6. Table options: TTL on a normal table, COMMENT on both normal and super table
    m7. Virtual table column references: ADD COLUMN .. FROM, ALTER COLUMN .. SET ref,
    ALTER COLUMN .. SET NULL
    m8. Virtual normal table tag references: ADD TAG .. FROM, ADD TAG (owned),
    SET TAG = literal, SET TAG = ref, DROP TAG
    m9. Six different ALTER actions on one super table in a single txn: the schema
    observed in-txn must be exactly what COMMIT publishes (guards against the
    statement-time and COMMIT-time action sets drifting apart)
    m10. CREATE INDEX / DROP INDEX rejected inside a txn without poisoning it, and
    still working outside
    m11. DROP TAG / RENAME TAG cascade onto an existing tag index: applied on COMMIT
    (regression — the COMMIT path used to leave a dangling index object),
    untouched by ROLLBACK
    m12. ADD/DROP BASE ON virtual super table inheritance in a txn (regression — a
    groupId-0 redo action broke COMMIT under TRN_EXEC_GROUP_PARALLEL), plus the
    parent-with-children guard inside a txn

    Batch meta txn: ADD/REMOVE SERIES (actions #22/#23) inside a transaction.
    SERIES is an InfluxDB-only binding from an alias to one fully-specified
    tag set. Its ALTER actions change only the entry's `series` array and
    `colRef.version`, never the column schema, so they need coverage
    independent of the column-ref cases in the op_matrix file.
    x1. ADD SERIES is visible in-txn, invisible to other sessions, undone by
    ROLLBACK
    x2. ADD SERIES + a column bound to it COMMIT together and the column then
    reads through to the pinned InfluxDB series
    x3. REMOVE SERIES of a pre-txn series: ROLLBACK restores the series array
    even though no column schema ever changed
    x4. Repeated ADD/REMOVE of one alias in a single txn keeps `txnOrigVer` at
    the pre-txn version, so the rollback restores the pre-txn set rather
    than an intermediate one
    x5. SERIES plus a column-ref repoint in one txn revert and commit together
    (FS §7.4)
    path: cases/21-MetaData/test_meta_batch_txn_series.py

    taosX snapshot-mode replication tests (s18-s20)
    Verifies that a TMQ consumer with td.enable.snapshot=1 correctly
    delivers committed DDL to the target under the current snapshot design.
    Design: tqMeta.c caps snapshotVer at min(committedVer, minTxnBeginIndex-1).
    buildSnapContext stops iterating at version > snapshotVer, so in-flight
    PRE_CREATE/PRE_ALTER/PRE_DROP entries are NEVER included in the snapshot.
    After snapshot, WAL replay starts at snapshotVer+1; individual in-txn DDL
    entries are filtered (WAL_IS_TXN_MSG); TXN_COMMIT triggers atomic delivery
    via STxnWalManager; TXN_ROLLBACK is silently skipped (no PRE_CREATE was
    ever seen by the consumer, so nothing to clean up on the target).
    18. snapshot_committed_data
    19. snapshot_inflight_txn_commit
    20. snapshot_idempotent_replay
