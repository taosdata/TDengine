    07-SubQuery¶

    ¶

    Merge daily aggregates when a group has no input on other vgroups.
    1. Distribute 48 meter groups over four vgroups, filtering out 16 groups.
    2. Replay three historical daily windows with and without COUNT.
    3. Check every group's timestamps, tags, aggregates and empty results.
    path: cases/18-StreamProcessing/07-SubQuery/test_external_window_empty_group_order.py

    ¶

    Five-leaf external-window JOINs preserve per-trigger-group results.
    1. Trigger one group first to cover a singleton multi-group request.
    2. Add two groups with colliding timestamps and JOIN keys.
    3. Run two window-bound and three broadcast leaves through four JOINs.
    4. Compare every grouped output subtable with its single-child stream.
    5. Prove valid-input empty-middle, duplicate, collision, and fallback cases.
    path: cases/18-StreamProcessing/07-SubQuery/test_external_window_multigroup.py

    ¶

    Customer SOC JOIN reloads fixed dimensions for the next request.
    1. Use four groups with three distinct piles and an all-zero group.
    2. Join fragmented one-row brand/rule children with duplicate keys.
    3. Verify group-specific thresholds and the pre-filtered sibling.
    4. Restart the cluster to restore the saved customer Broadcast plan.
    5. Update dimensions and verify the next request reloads both relations.
    path: cases/18-StreamProcessing/07-SubQuery/test_external_window_multigroup.py

    ¶

    Customer five-leaf SOC JOIN preserves results with sparse dimension matches.
    1. Replay four groups against 2737 brand/rule rows and a duplicate brand.
    2. Keep p2's valid trigger group unmatched while other groups publish.
    3. Change p1's brand/station keys between completed request batches.
    4. Compare every ordered output column and the newly loaded rule values.
    path: cases/18-StreamProcessing/07-SubQuery/test_external_window_multigroup.py

    ¶

    Fixed normal/child sources preserve grouped JOIN results.
    1. Build three trigger groups and independent fixed normal/child sources.
    2. Exercise aggregate, time-bound scalar fallback, and Broadcast scalar.
    3. Check exact values, all-NULL empty outcomes, and fixed-source routing.
    4. Verify output tables and %%1/%%2/_tgrpid partition identities.
    path: cases/18-StreamProcessing/07-SubQuery/test_external_window_multigroup.py

    ¶

    Composite JOIN keys preserve NULL exclusion and duplicate multiplicity.
    The TAG key is only referenced by the outer ON clause. Compare ordinary
    planning and hash JOIN on the same timestamp with duplicate TAG values.
    path: cases/18-StreamProcessing/07-SubQuery/test_external_window_multigroup.py

    ¶

    Customer SOC publishes exact results across continuous batches.
    1. Share one pile across two gun groups and add a filtered sibling.
    2. Run the exact five-branch state/count-window customer query.
    3. Send twelve four-row batches without waiting between writes.
    4. Check all SOC deltas and thresholds from both gun groups.
    5. Prove the filtered group creates no output subtable.
    path: cases/18-StreamProcessing/07-SubQuery/test_external_window_multigroup.py

    ¶

    A new order must not reuse the previous order's nonzero SOC scope.
    Run the exact five-branch SQL across an order transition, then keep the
    new order zero before introducing nonzero rows. A third group stays
    legally empty. Assert literal window ends, order values and SOC deltas.
    path: cases/18-StreamProcessing/07-SubQuery/test_external_window_multigroup.py

    ¶

    Customer SOC preserves groups and empty results across Reader sources.
    1. Create forty gun groups across three vgroups with one shared pile.
    2. Keep every seventh group's SOC zero and add a pre-filtered sibling.
    3. Execute the five-branch state/count-window customer query.
    4. Write eight batches without waiting for individual group results.
    5. Verify exact SOC values, cardinality and output table identities.
    path: cases/18-StreamProcessing/07-SubQuery/test_external_window_multigroup.py

    ¶

    Compare sequential SOC groups with the same offline window SQL.
    1. Stagger four groups' ranges and use distinct orders per group.
    2. Write three equal batches, flushing after the first publication.
    3. Keep one group empty and start another group's new order at zero.
    4. Expand the stream SELECT for every valid adjacent-frame window.
    5. Compare each group's exact rows, including the persisted prefix.
    path: cases/18-StreamProcessing/07-SubQuery/test_external_window_multigroup.py

    ¶

    Verify Reader fetch results with a TAG-filtered SOC dimension table.
    1. Create twelve monitor groups across three vgroups.
    2. Store pile_code as a TAG on the pile dimension stable.
    3. Keep two groups empty and write continuous four-row batches.
    4. Give two dimension rows distinct sink timestamps and verify every row.
    5. Change TAG membership, create/drop a matching child between batches.
    6. Verify another batch after restoring the original TAG membership.
    path: cases/18-StreamProcessing/07-SubQuery/test_external_window_multigroup.py

    ¶

    Filter scalar external-window results by state and window duration.
    Verify the customer's nested STATE_WINDOW query for physical and virtual
    tables, in history and realtime processing. Reject short state 103 and
    duration exactly 120000, retain longer state 103 and later other states.
    path: cases/18-StreamProcessing/07-SubQuery/test_external_window_output_filter.py

    ¶

    Continue external-window output after a whole block is filtered.
    A first state window fills multiple result blocks with rejected rows.
    A later state window must still be emitted after filtering those blocks.
    path: cases/18-StreamProcessing/07-SubQuery/test_external_window_output_filter.py

    ¶

    Apply TRUE_FOR when history forces the last state window to close.
    Reject an insufficient tail without losing preceding valid windows.
    Retain tails that meet duration, count, AND or OR conditions.
    path: cases/18-StreamProcessing/07-SubQuery/test_external_window_output_filter.py

    2. Output results include 4 dimensions:
    No grouping
    Group by table name
    Group by tags
    Group by ordinary columns
    3. Generate 100 SQL statements using the following syntax combinations:
    Tables: system tables, super tables, child tables, normal tables, virtual super tables, virtual child tables
    Functions:
    Single-row functions (math/string/conversion/time functions)
    Aggregate functions
    Selection functions
    Time-series-specific functions
    Geometry functions
    System functions
    Queries: projection queries, nested queries, join queries, window queries (time/event/count/session/state), SHOW commands, GROUP BY, PARTITION BY, ORDER BY, LIMIT, SLIMIT, UNION, etc.
    Filters: time comparisons, ordinary column comparisons, tag column comparisons
    Operators: arithmetic, string, bitwise, comparison, logical, JSON operators
    Others:
    Queries on databases/tables same as/different from the trigger table
    View queries
    4. Include the following combinations in step 3 query results:
    Use all data types: numeric, binary, string, geometry, json, etc.
    Use all pseudo-columns: _qstart, _qend, _wstart, _wend, _wduration, _c0, _rowts, irowts, _irowtsorigin, tbname, etc.
    Include data columns and tag columns
    Randomly include None and NULL in result sets
    Result set sizes: 1 row, n rows
    Include duplicate timestamp in result sets
    5. Test placeholder usage in step 3's queries, including:
    Placeholders in various positions like FROM, SELECT, WHERE
    Each placeholder: _twstart, _twend, _twduration, _twrownum, _tcurrent_ts, _tgrpid, _tlocaltime, %%n, %%tbname, %%tbrows
    6. Validation checks:
    Verify table structures and table counts
    Validate correctness of calculation results
    Validate the accuracy of placeholder data, such as %%trows
    path: cases/18-StreamProcessing/07-SubQuery/test_subquery_count_1.py
