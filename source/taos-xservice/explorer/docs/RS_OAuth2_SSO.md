# 引言

## 2.1 术语与缩写名词

- **OAuth 2.0**: 开放授权标准，允许第三方应用在用户授权的情况下访问用户资源
- **SSO**: Single Sign-On，单点登录，用户只需登录一次即可访问多个相关系统
- **OIDC**: OpenID Connect，基于OAuth 2.0的身份认证协议
- **IdP**: Identity Provider，身份提供商
- **JWT**: JSON Web Token，用于安全传输信息的开放标准
- **PKCE**: Proof Key for Code Exchange，OAuth 2.0的安全扩展

## 2.2 相关文档资料

- RFC 6749: The OAuth 2.0 Authorization Framework
- RFC 7636: Proof Key for Code Exchange by OAuth Public Clients
- OpenID Connect Core 1.0 规范
- TDengine Explorer 系统架构设计文档
- TDengine 安全策略文档

## 2.5 实现约束

由于 TDengine 后端技术限制，OAuth 2.0 单点登录实现需遵循以下约束：

1. **用户预创建要求**: OAuth 用户必须预先在 TDengine 中创建对应的数据库用户账户
2. **手动凭据绑定**: OAuth 用户首次登录时需要手动绑定现有的 TDengine 用户凭据
3. **权限管理**: 用户权限完全由 TDengine 原生权限系统管理，不支持从 IdP 自动映射权限

## 2.3 优先级要求

- **优先级**: 高
- **期望交付时间**: 2个Sprint（4周）
- **业务价值**: 提升企业用户体验，降低管理成本，增强安全性

## 2.4 版本要求

- **开源状态**: 企业版功能
- **发布版本**: TDengine 3.3.0
- **支持范围**: 仅企业版支持，社区版不包含此功能

# 需求目标

随着企业数字化转型的深入，越来越多的企业采用统一身份管理系统来管理员工账户和权限。目前 TDengine Explorer 采用独立的用户认证系统，用户需要单独创建和维护账户，这给企业用户带来了额外的管理负担和安全风险。

本需求旨在为 TDengine Explorer 集成 OAuth 2.0 单点登录功能，实现以下目标：

1. **统一身份管理**: 用户可以使用企业现有的身份提供商（如 Active Directory、LDAP、SAML等）登录 Explorer
2. **提升用户体验**: 用户无需记忆额外的用户名密码，实现一次登录多系统访问
3. **增强安全性**: 利用企业级身份管理系统的安全特性，如多因素认证、密码策略等
4. **简化认证流程**: 通过 OAuth 2.0 标准协议实现与企业身份系统的无缝集成

**注意**: 由于 TDengine 后端技术约束，OAuth 用户仍需预先在 TDengine 中创建对应的数据库用户，并在首次登录时进行凭据绑定。

## 功能流程图

```
用户访问Explorer
        ↓
    检查登录状态
        ↓
   [未登录] → 显示登录页面 → [选择OAuth登录]
        ↓
   重定向到IdP授权页面
        ↓
   用户在IdP完成身份验证
        ↓
   IdP重定向回Explorer（携带授权码）
        ↓
   Explorer后端交换访问令牌
        ↓
   获取用户信息并同步到本地会话
        ↓
   [首次登录] → 用户绑定现有TDengine凭据
        ↓
   创建Explorer会话
        ↓
   用户成功登录Explorer
```

# 性能需求

1. **认证响应时间**: OAuth 2.0 认证流程的总响应时间不超过 5 秒（包括重定向时间）
2. **Token 验证性能**: Access Token 验证响应时间不超过 100ms
3. **并发支持**: 支持至少 1000 个并发 OAuth 2.0 认证请求
4. **会话管理**: 支持至少 10000 个活跃会话的同时管理
5. **缓存策略**: 用户信息和权限数据应合理缓存，缓存命中率不低于 90%

# 安全需求

1. **传输安全**: 所有 OAuth 2.0 相关的通信必须使用 HTTPS 加密传输
2. **凭证存储**: Client Secret 等敏感配置信息必须加密存储
3. **Token 安全**: 
   - Access Token 有效期不超过 1 小时
   - Refresh Token 有效期不超过 30 天
   - Token 必须安全存储，防止 XSS 攻击
4. **状态验证**: 必须实现 state 和 nonce 参数验证，防止 CSRF 和重放攻击
5. **错误处理**: 不得在错误信息中泄露敏感的配置或用户信息
6. **审计日志**: 记录所有认证相关的操作日志，包括登录、登出、Token 刷新等
7. **权限控制**: 确保用户只能访问其被授权的资源和功能

# 其他需求

## 1. 兼容性需求

- **浏览器兼容**: 支持主流浏览器（Chrome 90+、Firefox 88+、Safari 14+、Edge 90+）
- **身份提供商兼容**: 兼容标准的 OAuth 2.0 和 OpenID Connect 1.0 规范
- **现有系统兼容**: 不影响现有的用户名密码认证方式，支持平滑迁移

## 2. 接口需求

- **REST API**: 提供 OAuth 2.0 配置管理的 REST API 接口
- **回调接口**: 提供标准的 OAuth 2.0 重定向回调接口
- **用户信息接口**: 提供获取当前登录用户信息的接口
- **登出接口**: 提供单点登出的接口

## 3. 运维需求

- **配置管理**: 支持通过配置文件或环境变量进行 OAuth 2.0 配置
- **健康检查**: 提供身份提供商连通性检查功能
- **监控指标**: 提供认证成功率、响应时间等监控指标
- **日志规范**: 提供详细的操作日志和错误日志，便于问题排查

## 4. 易用性需求

- **配置向导**: 提供图形化的 OAuth 2.0 配置向导，简化管理员配置工作
- **错误提示**: 提供友好的错误提示信息，帮助用户理解认证失败原因
- **凭据绑定指引**: 为 OAuth 用户提供清晰的 TDengine 凭据绑定流程指引
- **文档支持**: 提供详细的配置文档、常见身份提供商的配置示例以及用户绑定操作说明

## 5. 测试需求

- **单元测试**: OAuth 2.0 相关功能的单元测试覆盖率不低于 90%
- **集成测试**: 提供与主流身份提供商的集成测试用例
- **安全测试**: 进行安全扫描和渗透测试，确保无安全漏洞
- **性能测试**: 进行并发认证性能测试，验证性能需求达标
- **兼容性测试**: 验证与不同身份提供商和浏览器的兼容性
