#### 1. 第一部分，笔试题目，所有人回答

1. TDgpt 的功能特点
   - 通过 SQL 提供时序数据预测、异常检测、补齐和分类的功能
   - 支持各种 AI 算法、时序模型、大语言模型传统统计算法的动态切换
   - 开发的SDK, 任何新的算法、模型都可以无缝集成，而无需修改应用
2. TDgpt 的主要亮点
   - 零学习门槛，仅需一行 SQL
   - 零初期投入，立即享受AI红利
   - 零时间差，最新算法轻松集成
3. TDgpt 支持那些时序模型，由哪些厂家提供
   - TDtsfm：TDengine
   - Uni2TS：SalesForce
   - Chronos：Amazon
   - TimesFM：Google
   - Time-MOE：小红书
4. 虚拟表能解决哪些问题
   - 数据建模：采集层常采用单列模型，应用层常采用宽表多列模型，IT 和 OT 间需要桥梁
   - 标签维护：一个设备存在多张子表时，带来标签重复存储，多个子表的标签更新存在原子性问题
   - 查询易用性：跨表查询需要编写的 JOIN + 嵌套查询语句
   - 查询效率：按时间戳对齐跨表数据的效率低，查询延迟显著增加
   - 查询维护：视图需定义固定的查询逻辑，维护困难，且查询条件无法下推
5. 虚拟表的功能特点
   - 列选择与拼接：用户可从多个表中选择指定列，按需组合到一张虚拟表，查询语法和普通表完全相同
   - 时间戳对齐：以时间戳为依据对数据进行对齐，如果多个表在相同时间戳下存在数据，则对应列的值组合成同一行；若部分表在该时间戳下无数据，则对应列填充为 NULL（提供 padding 函数对空值进行插值）
   - 动态更新：虚拟表根据原始表的数据变化自动更新，确保数据的实时性
6. 虚拟表的亮点
   - 更简单：一个设备一张表，用户无需编写复杂 JOIN + 嵌套查询语句
   - 更快速：动态计算减少冗余存储，归并排序优化数据对齐效率
   - 实时性：实时反映原始表变更，支持毫秒级数据更新
   - 易扩展：支持动态添加/删除列，适配业务需求变化
7. 虚拟表和视图的区别

| 属性 | 虚拟表 (Virtual Table) | 视图 (View) |
| --- | --- | --- |
| 定义 | 虚拟表是一种动态数据结构，根据多表的列和时间戳组合规则生成逻辑表 | 视图是一种基于 SQL 查询的虚拟化表结构，用于保存查询逻辑的定义 |
| 数据来源 | 来自多个原始表，可以动态选择列，并通过时间戳对齐数据 | 来自单个或多个表的查询结果，通常是一个复杂的 SQL 查询 |
| 数据存储 | 不实际存储数据，所有数据在查询时动态生成 | 不实际存储数据，仅保存 SQL 查询逻辑 |
| 时间戳处理 | 通过时间戳对齐将不同表的列整合到统一的时间轴上 | 不支持时间戳对齐，数据由查询逻辑直接决定 |
| 更新机制 | 动态更新，原始表数据变更时，虚拟表数据实时反映变化 | 动态更新，但依赖于视图定义的查询逻辑，不涉及对齐或数据整合 |
| 功能特性 | 支持空值填充和插值（如 prev、next、linear） | 不支持内置填充和插值功能，需通过查询逻辑自行实现 |
| 应用场景 | 时间序列对齐、跨表数据整合、多源数据对比分析等场景 | 简化复杂查询逻辑、限制用户访问、封装业务逻辑等场景 |
| 性能 | 由于多表对齐和空值处理，查询复杂度可能较高，尤其在数据量大时 | 性能通常取决于视图的查询语句复杂度，与单表查询性能相似 |

1. 以智能电表数据模型为例，讲解 COLS 函数的作用，编写一个使用 COLS 函数的 SQL 语句
COLS 函数是 TDengine 特有的时序数据函数，用以获取单行选择函数所在行的其他列值，可以和 max、min、last 等选择函数配合使用。如下语句能够按照时间窗口取得电流平均值、最大值、最小值、最大值的时间、最小值的时间
```plaintext {wrap}
  select tbname, _wstart, avg(current),
    max(current), cols(max(current), ts), 
    min(current), cols(min(current), ts) 
    from meters
    partition by tbname
    interval(1d);
```

1. 讲解流计算事件通知机制的作用
在流计算功能中，窗口（如时间窗口、状态窗口、会话窗口等）是数据聚合和处理的重要方式。当前， 流计算过程中，窗口的打开、关闭等事件仅在 taosd 内部处理，无法通知外部系统，难以满足外部系统的实时监控、报警及事件驱动需求。因此，为了增强流计算的交互能力，支持在窗口事件发生时向指定目标发送通知。
以下示例创建一个流，计算电表电流的每分钟平均值，并在窗口打开、关闭时向两个通知地址发送通知，计算历史数据时也强制发送通知，并且不允许在通知发送失败时丢弃通知：
```sql
CREATE STREAM avg_current_stream FILL_HISTORY 1
  AS SELECT _wstart, _wend, AVG(current) FROM meters
  INTERVAL (1m)
  NOTIFY ('ws://localhost:8080/notify', 'wss://192.168.1.1:8080/notify?key=foo')
  ON ('WINDOW_OPEN', 'WINDOW_CLOSE');
  NOTIFY_HISTORY 1
  ON_FAILURE PAUSE;
```

1. 讲解流计算计算最小持续时长的作用
对于事件窗口和状态窗口，在数据偶尔波动的情况下，往往会生成许多持续时间极短的窗口。从业务角度来看，这些窗口通常会被视为误报。在判断是否构成一个新的窗口时，以往的方法是一旦满足条件即视为窗口开启。本功能可以要求窗口必须持续一段时间之后，才被认定为真正开启。
为 `STATE_WINDOW`、`EVENT_WINDOW` 窗口新增关键字 `TRUE_FOR`，用于指定窗口的最小持续时长。
```sql
window_clause: {
  | STATE_WINDOW(col) [TRUE_FOR(true_for_duration)]
  | EVENT_WINDOW START WITH …… END WITH …… [TRUE_FOR(true_for_duration)]
}
```

1. 讲解 DECIMAL 的使用场景，参数说明与限制
TDengine 开始被用于多种场景，一些特殊的数据，例如经纬度、货币、表计等，需要精确的小数位数。
1. Precision: 精度，指整个数值中有效数字个数，包括了小数点左右两侧的所有数字
2. Scale: 小数位数，指位于小数点右侧的小数个数，必须为非负整数
当 precision 值不大于 18 时, 内部使用 8 字节存储（DECIMAL64），当 precision 范围为 (18, 38] 时，使用 16 字节存储
