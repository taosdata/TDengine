## 2. 背景

[河北电力](https://project.feishu.cn/taosdata_td/feature/detail/6594391614)子表数很多，单个超级表有 3000 多万子表。他们需要定期根据关系库里的台账更新子表标签。
[IDMP](https://taosdata.feishu.cn/wiki/SBftwJxjUisxPhkqtJmcCzxan4f) 需要批量更新、增加、删除虚拟子表的标签，由于子表必须包含超级表的所有标签，故删除标签等价于将标签值置为 `NULL`，增加标签等价于将标签值置为非 `NULL` 值。

## 3. 行为说明

原始需求分别针对普通子表和虚拟子表，但从实现的角度，二者区别不大，故以下仅以普通子表为例进行说明。

### 3.1 针对新标签值无法统一指定的情况（主要支持河北电力的场景）

增强当前多标签修改语法，使其支持一次修改多个子表，标签值可以为 `NULL`，用于清空标签值。
```sql {wrap}
-- 现有语法
ALTER TABLE tb1 SET TAG tag_11 = tag_val_11, tag_12 = NULL;

-- 增强后的语法
ALTER TABLE tb1 SET TAG tag_11 = tag_val_11, tag_12 = NULL tb2 SET TAG tag_21 = NULL, tag_22 = tag_val_22 ...;
```

### 3.2 针对新标签值可以统一指定的情况（主要支持 IDMP 的场景）

#### 3.2.1 最终目标

新标签值可以统一指定意味着新标签值可通过表达式计算得到，故需增加一种新的语法。
```sql {wrap}
ALTER TABLE USING stb SET TAG tag1 = expression1, tag2 = NULL WHERE condition;
```

其中，标签值表达式和 WHERE 条件表达式需要满足以下条件：
- 表达式只能包含常量、标签列、标量函数（含算术运算），不允许使用聚合函数、数据列、子查询等。
- 标签值表达式的计算结果类型必须兼容标签类型，`WHERE` 条件表达式的计算结果必须兼容布尔类型
- 表达式计算时，作为输入的标签值始终是修改前的原始值（暂定）。
- 标签值表达式可以为 `NULL`，用于清空标签值。

#### 3.2.2 本期目标

最终目标的语法具有足够的灵活性和可扩展性，可以满足未来需求，但支持表达式计算涉及查询模块的大量工作，开发周期较长，无法满足 IDMP 的时间需求，故本期目标为支持下面的简化语法。
```sql {wrap}
ALTER TABLE USING stb SET tag1 = REGEXP_REPLACE(tag1, regexp, replacement), tag2 = NULL WHERE condition;
```

上述语法考虑了未来实现最终目标时的兼容性:
- `REGEXP_REPLACE` 是一个关键字而非函数，且本期不支持将其替换为其他函数，其在语法中以函数形式出现，是考虑未来实现最终目标时（届时其将被实现为函数）不影响已有应用。
- `REGEXP_REPLACE` 的第一个参数仅为兼容未来函数语法，无实际作用，使用时，建议将其置为目标标签名称，以保持语法语义的一致。
- 可在 `replacement` 参数中使用 `$0` - `$9`代表匹配组（match group）。
- 使用 `REGEXP_REPLACE` 修改的标签必须是字符串类型，设置为 `NULL` 的标签无类型限制。
- `WHERE` 条件与查询语句基本相同，但不允许使用数据列、聚合函数等。
- 此语法仅供内部使用，不对外公开。

### 3.3 数据订阅和流计算修改

1. Vnode 修改标签的地方，需要更新数据订阅的 tablelist
2. Vnode 里订阅meta 数据时，需要根据新的wal 数据结构做过滤。
3. 数据迁移接口 tmq_get_json_meta，获取订阅的meta 消息的 json 结构处需要修改（包括多表和超级表两种情况）。
4. 数据迁移写入目标数据库时，需要修改taosAlterTable 的逻辑（包括多表和超级表两种情况）。
5. 流计算读取wal meta 消息时，如果是 alter tag，需要处理。

## 8. 约束和限制

1. 批量更新过程中，某个子表更新失败会导致整个操作失败，但已经更新成功的子表无法回滚。
2. 其他约束和限制参见 3.2.2 节。
