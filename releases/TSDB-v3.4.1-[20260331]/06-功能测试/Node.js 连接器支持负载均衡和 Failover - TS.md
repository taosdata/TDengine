## 2. 测试目标

1. 验证多地址场景下负载均衡策略符合实现：最少连接优先，并在并列时随机打散。
2. 验证网络异常下自动重连、指数退避、地址切换与并发重连收敛行为。
3. 验证请求恢复语义：可重放请求在重连后可恢复，非可重放请求及时失败。
4. 验证模块级恢复能力：SQL、STMT2、TMQ 在单地址与多地址故障场景下可继续工作。

## 4. 测试结论

测试整体通过，功能符合预期。自动化单测全部通过，说明连接层 failover 核心能力稳定可用，包括最少连接选址、重连收敛、重试参数处理和 STMT2/TMQ 恢复逻辑。

## 7. 安全测试

- Failover 前后用户名/密码/token/bearer_token 生效一致。
- 日志中不出现明文 password/token/bearer_token。
- 连接池 key 输出中认证信息应为 hash 或脱敏形式。

## 8. 兼容性测试

- 单地址兼容：单地址 DSN 行为不变，旧配置可直接运行。
- 多地址兼容：增加多地址后不影响已有 API（WsSql、WsStmt2、WsConsumer）调用方式。
- 参数兼容：不提供重试参数时使用默认值；非法参数输入不会导致崩溃，回退默认值。
