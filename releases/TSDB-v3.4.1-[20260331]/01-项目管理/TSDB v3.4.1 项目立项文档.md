## 2. 项目目标

本项目聚焦于开发与发布 TDengine v3.4.1​​，致力于达成以下核心目标：
1. 实现关键功能的安全与高可用加固
2. 显著提升复杂查询与分析能力
3. 大幅优化数据建模与管理的便捷性
4. 拓展生态兼容性与智能化分析边界

## 3. 项目范围

### 3.1 **数据查询**

1. **子查询能力**：支持完整的子查询语法，解决多层级嵌套查询问题，并对外层查询进行并行化优化以提升性能。
2. **查询管理增强**：`SHOW QUERIES`命令将支持显示执行进度，并提供无效 SQL 清理功能，提升运维效率。
3. **窗口与插值功能**：`INTERVAL`窗口支持指定插值时间范围；`FILL PREV`支持填充前一个非 NULL 值；事件窗口功能进一步增强。

### 3.2 虚拟表

1. **建模**：虚拟表引用虚拟表
2. **变更**：支持源表元数据自动同步至虚拟表/虚拟超级表
3. **性能**：提升虚拟表批量查询性能
4. **订阅**：支持订阅虚拟表的变更，例如创建、删除、修改

### 3.3 **流计算**

1. **定时触发**：支持按自然月定时触发
2. **事件触发：**`TRUE_FOR`条件支持以记录条数作为窗口开始条件判断，`TRUE_FOR`允许应用与窗口结束判断
3. **功能改进**：支持预先创建结果表，子查询中支持 TDgpt 异常窗口查询、支持识别虚拟子表变更
4. **性能优化**：分组批量计算、虚拟表触发等性能优化

### 3.4 **数据存储**

1. **数据修复**：开发数据修复工具，最大化恢复数据库可用数据，确保异常状态下数据库可快速恢复并启动。
2. **标签管理**：支持批量增删改多个子表或虚拟子表的多个标签值。
3. **数据缓存**：支持强制刷新与动态调整分片数量

### 3.5 **安全与可靠**

1. **审计与监控**：审计日志记录客户端 IP，支持配置多个监控地址、审计不通过  taoskeeper 记录等
2. **测试用例**：针对 3.4.1 版本补充安全测试用例。
3. **漏洞修复**：修复通过工具扫描发现的系统漏洞，提升系统整体安全性。

## 4. 项目工期

项目总工期为 4个月，自 2026-01-01 至 2026-04-30。项目进度计划遵循经典的“设计-开发-测试”瀑布模型，但各子功能的开发可以敏捷迭代，确保在紧凑的工期内高效交付。
1. 需求与设计阶段：2026-01-01 ~ 2026-01-31，完成需求分析和功能设计。
2. 开发及功能测试阶段：2026-02-01 ~ 2026-03-31 ，完成代码开发和功能测试，发布可测试的软件版本。
3. 系统测试与验收阶段：2026-04-01 ~ 2026-04-25，完成系统测试和缺陷修复，完成软件版本的验收。
4. 项目总结阶段：2026-04-25 ~ 2026-04-30，项目成果评审、文档归档、经验总结与复盘。

## 8. 项目成功标准与验收条件

1. 功能完成与文档就绪：规划的所有核心功能均已实现，并通过功能测试；用户手册已编写完成；已发布可供测试的版本。

3. 通过性能基准测试：​当开启安全功能时，和 3.4.0 版本比较，性能衰减低于 10%。
4. 通过系统兼容性测试：从 3.4.0 版本可以升级至 3.4.1 版本，数据文件向上兼容
5. 通过交付验收：通过交付部门的验收审核，确认其质量与稳定性满足向客户升级发布的要求。
6. 过程符合规范：本次开发过程遵循了既定的研发体系与规范，各项实践应用有效。
