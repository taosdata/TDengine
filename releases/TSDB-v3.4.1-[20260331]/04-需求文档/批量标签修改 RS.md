## 3. 需求目标

针对河北电力子表数量庞大（单个超级表3000多万子表）、需定期根据台账更新子表标签，以及IDMP需批量更新、增加、删除虚拟子表标签的核心需求，增强TDengine标签修改语法，实现子表标签的批量操作。明确批量标签修改的两种应用场景及对应语法，其中删除标签等价于将标签值置为NULL，增加标签等价于将标签值置为非NULL值，为批量标签修改功能的开发落地提供明确指导，提升标签操作效率，适配实际业务场景需求。

## 4. 功能需求

现有标签修改语法仅支持单个子表的多标签修改，无法满足河北电力3000多万子表批量更新、IDMP虚拟子表批量操作的需求，且不支持标签的批量增加、删除（等价置NULL）。基于此，需分两种场景增强标签修改语法，实现批量标签操作，具体需求如下：
说明：原始需求分别针对普通子表和虚拟子表，但从实现角度二者区别不大，以下仅以普通子表为例进行说明，虚拟子表适用相同逻辑。

### 4.1 场景一：新标签值无法统一指定（主要支持河北电力场景）

增强当前多标签修改语法，支持一次修改多个子表，标签值可灵活指定，支持置为NULL（用于清空标签值，即删除标签），具体语法要求如下：

#### 4.1.1 现有语法

仅支持单个子表的多标签修改，无法批量操作多个子表：
```plaintext {wrap}
ALTER TABLE tb1 SET TAG tag_11 = tag_val_11, tag_12 = NULL;
```

#### 4.1.2 增强后语法

支持一次指定多个子表，每个子表可独立设置标签值（支持NULL），实现批量修改：
```plaintext {wrap}
ALTER TABLE tb1 SET TAG tag_11 = tag_val_11, tag_12 = NULL tb2 SET TAG tag_21 = NULL, tag_22 = tag_val_22 ...;
```

### 4.2 场景二：新标签值可以统一指定（主要支持IDMP场景）

新标签值可通过表达式计算得到，需分两期实现，本期优先满足IDMP时间需求，实现简化语法，未来迭代至最终目标语法，确保两期语法兼容。

## 5. 性能需求

本次新增的批量标签修改语法均为简化操作的语法糖，不增加额外性能损耗，对系统吞吐量、响应延迟无明显影响。
