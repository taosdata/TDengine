### 2. 风险描述回顾

<callout emoji="gift" background-color="light-red">
TDengine 存在危险函数注入安全漏洞。攻击者可通过 SQL 注入在查询中调用危险系统函数（如 LOAD_FILE、INTO OUTFILE 等），读取服务器敏感文件或写入恶意数据，导致服务器被入侵、敏感信息泄露、数据被篡改。当前缺乏专门的危险函数管控机制，防护存在严重隐患。
</callout>


| 评估维度 | 评估结果 |
| --- | --- |
| 风险类别 | 技术风险 - 安全漏洞 |
| 风险概率（P） | 中（P = 2）：防护机制缺失，但需要特定的攻击条件和权限，不是必然发生 |
| 风险影响（I） | 高（I = 3）：可导致服务器被入侵、敏感信息泄露、数据完整性破坏 |
| 风险暴露值（RE） | RE = P × I = 2 × 3 = **6** |
| 风险等级 | 高优先级风险（红色），RE = 6，必须重点关注 |

### 3. 评审讨论要点

#### 3.1 当前现状分析

- TDengine 目前对用户提交的 SQL 查询中的系统函数调用缺乏有效拦截机制。
- UDF（用户自定义函数）脚本调用权限管控不足，存在调用危险系统函数的可能。
- AST（抽象语法树）层面的检测逻辑尚未覆盖危险函数识别场景。
- 当前无任何危险函数调用的审计或告警机制，异常操作无法被及时发现。

#### 3.2 风险影响范围讨论

- **直接影响**：攻击者可读取服务器上的敏感配置文件（如 `/etc/passwd`），或将恶意数据写入文件系统。
- **间接影响**：用户数据完整性遭到破坏，企业声誉受损，可能引发合规审查风险。
- **影响对象**：所有具备数据库连接权限的外部用户及内部运维人员均在潜在影响范围内。

#### 3.3 应对策略讨论

与会人员一致同意采用**减轻（Mitigate）**策略，通过实施多层次防护机制，降低风险发生的概率和影响。
