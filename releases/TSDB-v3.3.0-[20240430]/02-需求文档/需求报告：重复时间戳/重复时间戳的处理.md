# 重复时间戳的处理

在金融等行业，由于时间精度往往是毫秒，而一毫秒内往往产生多条记录，这样导致一个时间戳，系统拥有多条记录。在目前的TDengine设计中，这是不容许的。因此我们需要有一个解决办法。
最彻底的解决办法是复合主键，除时间戳之外，再指定一列为主键，这样就解决了。但目前的设计，要实现复合主键的开发量很大，不合适。因此本文讨论一个简单方法，容许时间戳重复。
核心的思路是：应用采用的时间精度仍然毫秒，但系统自动将某个唯一ID字段取模，作为纳秒，组成新的时间戳，存入到数据库中。具体处理方法如下：

### 1. 唯一ID

对于时间戳重复的场景，一张表里一定有一个字段是唯一的（一般是自增的，比如交易ID，序列号），这个字段在一毫秒内可以肯定是不可能重复的，本文中我们将这个字段称之为uniqueId。

### 2. 记录时间戳

假设应用提供的时间戳是 ts（毫秒进度），那么写入数据库的记录时间戳（recorded ts) rts = ts*10^6 + uniqueId mod 10^6. 这样任何一条记录的时间戳都会是唯一的。而且也能支持数据的更新和删除操作。

### 3. 元数据的修改

普通表或超级表新增一个属性columnId, 缺省为0，如果大于0，表示支持重复的时间戳，而且该column ID的所在列包含的数据是uniqueId，该表的时间精度自动为纳秒。如果columnId不大于0, 表示不支持重复的时间戳。
创建表或超级表的语句增加新的关键词key
create table tb-demo (ts timestamp, uid int key, ......) 
如果某个字段标有key, 那么该列包含uniqueID，columnId设为其对应的所在列的列ID（比如上述SQL语句里，columnID将设为1）。如果多个列包含有key, 那么取第一个（也可以报错，看如何处理更为方便）  

### 4. 写入的修改

客户端(taosc)在发现表的属性columnId大于0，那么自动将时间戳改为 rts = ts*10^6 + uniqueId mod 10^6., 其中uniqueId从columnId列取出。服务器侧，不用做任何调整。

### 5. 查询的修改

如果SQL语句where字句里包含ts的条件，客户端需遵循如下规则做处理：
1. ts >= timestamp, 不做任何处理
2. ts = timstamp, 客户端需要将其自动改为 ts >= timestamp and ts < timestamp + 1(ms), 这样确保一个毫秒内的所有记录都被处理
3. ts < timestamp, 不做任何处理
4. ts <= timestamp, 客户端需要将其自动改为 ts < timestamp + 1(ms), 这样确保一个毫秒内的所有记录都被处理

### 6. 查询返回结果的修改

客户端自动将纳秒精度的时间戳降级为毫秒精度，返回给应用

### 7. 应用的修改

应用仅仅需要在创建表或超级表时，指定某列为key即可，表示该列包含unique Id, 需要支持重复时间戳

上述的方法，服务器代码的修改很小，仅仅是为表的元数据增加了一个columnId的字段。主要的修改在客户端，但逻辑仍然是相对简单的。
