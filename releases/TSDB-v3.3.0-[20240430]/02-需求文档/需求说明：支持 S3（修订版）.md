## 3. 功能需求

实现原理：将数据文件（data）拆分为多个固定大小的对象，当对象大小满足一定阈值（1GB）之后上传至 S3，上传动作是自动进行的。因此，无论数据是否在 S3 中，均可以做到随时更新、删除。数据上传触发周期、对象大小阈值可以配置。S3 功能与多级存储功能不相关，由单独的上传天数参数来决定，不通过 trim database 语句提供迁移至 S3 的语义。

### 3.1 第一阶段（支持多次写入）

| 需求编号 | **需求描述** | 研发确认 |
| --- | --- | --- |
| R101 | 数据库配置，增加与 S3 有关的参数（多级存储和 S3 功能 DB 级别互斥）： 1. 上传对象的大小阈值（不可修改） 1. 上传数据的天数（允许修改） 1. 上传动作的触发周期（允许修改） 1. 第一次上传是否进行 compact（允许修改） | 确认 |
| R102 | 无论数据是否在 S3 中，均可以查询、写入、更新、删除 | 确认 |
| R103 | 支持检查 S3 配置是否正确，提供检查脚本或者 SQL 语句 | 确认 |
| R104 | 支持副本移动相关操作： redistribute、alter replica | 确认 |
| R105 | 支持 compact | 确认 |

### 3.2 第二阶段（查询、运维优化）

| 需求编号 | **需求描述** | 研发确认 |
| --- | --- | --- |
| R201 | 读取 S3 数据之前精确计算待读取的页范围，并传递到 tsdb 读取函数中，做到 - 对于单个数据表，尽可能只读取一次数据 - 对于单个数据表，尽可能只在最前、最后两个位置，冗余读取不超过一个 tsdbPageSize 的数据 |  |
| R202 | 修改 S3 数据缓存机制为全局分配 |  |
| R203 | 支持类似 show table distribute 的 SQL 语句，用以查看数据压缩比和总大小 - 可以查看 data 文件在 1/2/3 级的分布、压缩比、大小 - 可以查看 data 文件在本地与 S3 上的分布、压缩比、大小 - 允许以 vgroup、数据库名、时间范围作为参数 |  |
| R204 | 通过 Explain 语句或者其他类似方法，能看到查询执行的如下信息，用以支持性能分析和优化 - 从 S3 下载数据的次数、每次下载的数据量 - 读取 tsdbPage 的数目，来源统计（包括本地、缓存、S3） |  |

| R206 | 支持上传 BLOB 数据文件 |  |
