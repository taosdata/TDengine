# 普通列和标签列数据写入行为统一

## 1. 背景

- 该需求的主要目标是：对标签列（tag 列）在`手动建表和自动建表` 两种情况下的 `异常写入` 行为进行统一。
- TDengine 的数据列包括普通列和标签列，建表方式包括手动建表和自动建表。为提升写入速度，将写入语法从其他语法中拆分出来进行了单独解析，这就造成 `普通列写入/自动建表 tag 列写入`和`手动建表 tag 列写入/修改 tag 列`采用了不同的逻辑，在行为上存在不一致的地方，在`异常写入` 时尤为明显。为了保证 TDengine 数据写入行为的一致性与合理性，需要对上述行为进行统一。 
- JIRA链接：[TS-4421](https://jira.taosdata.com:18080/browse/TS-4421) [【大连海心】-标签过滤查询故障](https://jira.taosdata.com:18080/browse/TS-4421)

## 3. 定义

### 3.1 手动建表

- 通过 `create table {childTableName} using {superTableName} tags(...)` 语法创建子表。

### 3.2 自动建表

- 通过 `insert into {childTableName} using {superTableName} tags(...) values(...)` 语法在写入的同时自动创建子表。

### 3.3 异常写入

- 写入数据类型与目标列（包括普通列与 tag 列）数据类型不一致。

## 7. 兼容性

### 7.1 写入

- 本文主要涉及`异常写入` 的处理，对 `手动建表 tag 列写入` 兼容性有一定影响，具体如下：
```python {wrap}
1）如果用户应用的 '手动建表 tag 列存在异常写入'，会造成升级前后的写入行为不一致，导致建表失败，从而导致写入失败；
2）如果用户应用的 '手动建表 tag 列不存在异常写入', 则不受影响。
```

- 如果目标列类型为 timestamp，`手动建表 tag 列/自动建表 tag 列/普通列` 针对单引号或双引号中内容为 `now/today/now()/today()` 的写入，改动前会报错，改动后会转换为对应的 timestamp 数值。功能增强，可以认为不会有兼容性问题。
- 扩展了二进制和十六进制的支持范围。功能增强，可以认为不会有兼容性问题。
