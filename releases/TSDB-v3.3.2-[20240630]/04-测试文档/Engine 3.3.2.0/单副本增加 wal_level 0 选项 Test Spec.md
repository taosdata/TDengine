# 单副本增加 wal_level 0 选项 Test Spec

## 一、测试目标

  测试的需求文档：[单副本增加 wal_level 0 选项](https://taosdata.feishu.cn/wiki/WFENwMc2MiuqJNk8ivHcEEUnnNh)
TS-4843 POC 测试中，客户磁盘限速导致写入速度无法继续提升，需要不写 WAL 的选项以达到更高的写入速度；这个选项将在 TS-4885 中添加，由于未落盘数据有可能丢失，不建议在生产系统中使用。

## 三、测试结论

1、功能测试正常，提出的bug均已修复。但从可靠性来看，仍不建议在生产环节使用。由于wal文件的特殊性，部分场景的测试后可能出现无法启动的现象，需要删除wal文件后再启动。
2、性能测试结论：
测试场景a（9.1章节）：对比前版本和对比版本在wal_level=1时，数据插入的耗时和速度各有千秋，波动较大，和明磊、翟坤沟通，结果合理，同时日常的性能测试中，插入测试的波动也是比较大，符合预期。
测试场景b（9.2章节）：对比版本在wal_level=0和wal_level=1的插入对比中，wal_level=0的性能明显优于wal_level=1的插入性能，同样配置条件和json情况下，不论是相同vgroup或者相同子表不同vgroup下，wal_level=0/wal_level=1基本都是2～2.8倍，且波动很小。

## 六：测试范围及重点

 本测试主要对是否写WAL （=0，不写WAL、=1，写WAL）变更相关功能的重点测试，包含
  a：WAL=0时，流，订阅，副本变更等功能无法使用，其余功能不影响。
  b：WAL=0时，比WAL=1的性能提升幅度。
  c：WAL=1时，对比版本 比 对比前版本的性能不下降。

## 七、测试数据 

schema一共20列（一列ts，8列数据列，4列浮点列，4列字符串类型，1列bool，2列tag）。
- a：固定子表场景数据集 。固定10亿数量，10w子表，vgroup不同进行组合(10、20、50）。
- b：固定vgroup场景数据集 。固定10亿数量，50个vgroup，子表数量不同进行组合（1w、5w、10w、50w）。
