# 需求报告：taosX支持从参数名中提取数据

## 1. 需求描述

目前河北电力分布式光伏从营销用采系统Kafka消费数据入库TDengine，拟采用taosX替换之前采用的nifi方案。
Kafka Payload格式如下
```sql {wrap}
{
    "DATA_ITEM_ID": "监测数据项代码",
    "MONITOR_OBJ_TYPE": "被监测对象类型",
    "MONITOR_OBJ_CODE": "被监测对象代码",
    "PRO_MGT_ORG_CODE": "省编码",
    "MGT_ORG_CODE": "管理单位编码",
    "PUSH_DATE": "推送时间",
    "U0000": "0点0分电压",
    "U0001": "0点1分电压",
    "U0002": "0点2分电压",
    ...,
    "U2359": "23点59分电压",
    "PHASE_FLAG": "相位标识",
    "DATA_POINT_FLAG": "数据点标志",
    "DATA_DATE": "数据日期",
    "CMD_TYPE": "业务对象操作类型",
    "PRODUCT_CODE": "采样方式",
    "DEV_ID":"设备标识",
    "TERMINAL_ID":"终端标识"
}
```

### 1.1 需求说明与示例

#### 1.1.1 需求说明

1. 写入时间戳从Payload中两处解析获得：DATA_DATE数据值(如2024-3-20) + 参数名的后四位 (如U2359 -> 2359 -> 23:59)
2. 一条Payload可能包含多条记录，需拆分为多条记录入库：写入时间戳参见第一条，写入值为参数对应值(如U2358参数对应值、U2359参数对应值)

#### 1.1.2 示例

```sql {wrap}
{
    "DATA_ITEM_ID": "aaa-0123456",
    "MONITOR_OBJ_TYPE": "bbb",
    "MONITOR_OBJ_CODE": "ccc",
    "PRO_MGT_ORG_CODE": "hebei",
    "MGT_ORG_CODE": "ddd",
    "PUSH_DATE": "2024-3-20 12:23:30",
    "U2358": "223",
    "U2359": "219",
    "PHASE_FLAG": "1",
    "DATA_POINT_FLAG": "3",
    "DATA_DATE": "2024-3-20",
    "CMD_TYPE": "eee",
    "PRODUCT_CODE": "fff",
    "DEV_ID":"xxx",
    "TERMINAL_ID":"zzz"
}
```

该Payload将被拆分为两条数据入库
```sql {wrap}
'2024-3-20 23:58:00',223
'2024-3-20 23:59:00',219
```
