# S3 对象存储 - 功能规格

## 1. 背景

此功能是 3.0 版本规划中的一个，在 [TD-18808](https://jira.taosdata.com:18080/browse/TD-18808) 中有全部需求历史，原标题为：3.0 增加对 S3 的支持。初始需求为一个支持 S3 的 POSIX API 文件系统，供 TDengine 内部使用；后面考虑到性能方面的影响，最终把目标定为：把多级存储最后一级中的 data 文件存放到 S3 存储中。

## 3. 定义

S3 对象存储：一种可扩展的，高可用的分布式存储系统，能够存储大量的非结构化数据对象。

## 4. 行为说明

TDengine 如果在配置文件 taos.cfg 中配置了合法的 S3 相关参数，那么在多级存储系统中，会把最后一级存储中存放时序数据的 data 文件上传到 S3 存储 ；即，只会对第二级或第三级进行处理，如果只有一级存储，数据均会存储在本地。主要流程有：
1，数据迁移，当最后一级某个数据文件一天（可配置）没有修改更新时，data 文件会被上传到 S3；
2，数据查询，涉及 S3 部分的数据会按需下载到内存，并在内存中缓存，后续查询可以直接读取 LRU 缓存中的数据。
3，数据写入，数据文件上传到 S3 后，写入对应文件相关的数据会在 TSDB 落盘的过程中忽略（相当于过期数据），如果存在 stt 文件则不会触发 merge 流程。
4，数据过期，当数据过期需要删除时，S3 上过期的 data 文件会同步删除；
5，数据删除，由于 TSDB 数据删除命令的实现是逻辑删除，相关信息均记录在本地，所以可以对所有级使用删除命令，与是否配置 S3 无关；当删除某个 DB 时，相关 vnode 的 S3 数据会一同被物理删除。
6，vgroup 操作, split 暂不支持。支持 redistribute 命令对 vnode 在 dnode 之间进行迁移操作；支持 DB 的副本变更，增加或减少副本数量。compact 操作需要在 data 文件上传到 s3 之前进行，或将文件下载到本地再操作。

#### 4.0.1 配置参数

##### 4.0.1.1 访问控制参数

| # | 参数 | 示例值 | 描述 |
| --- | --- | --- | --- |
| 1 | s3EndPoint | http://cos.ap-beijing.myqcloud.com | 用户所在地域的 S3 服务域名 |
| 2 | s3AccessKey | AKIDsQmwsfKxTo2A6nGVXZN0UlofKn6JRRSJ:lIdoy99ygEacU7iHfogaN2Xq0yumSm1E | 冒号分隔的用户 SecretId:SecretKey |
| 3 | s3BucketName | test0711-1309024725 | 存储桶名称，减号后面是用户注册 COS 服务的 AppId |

s3EndPoint 支持 http 和 https，bucket 的区域需要与 endpoint 的保持一致，否则无法访问。
其中 AppId 是 COS 特有，AWS 和阿里云都没有，配置时需要作为 bucket name 的一部分，使用减号分隔。参数值均为字符串类型，但不需要引号。不同的 dnode 需要配置不同的 s3BucketName。

##### 4.0.1.2 数据上传及缓存参数

| # | 参数 | 默认值 | 最小值 | 最大值 | 描述 |
| --- | --- | --- | --- | --- | --- |
| 1 | s3UploadDelaySec | 86400 | 60 | 2592000 (30天） | 默认最后一级存储 data 文件 1 天不再变动后上传至 S3，单位：秒 |
| 2 | s3PageCacheSize | 4096 | 4 | 1024*1024*1024 | s3 page cache 缓存页数目，单位：tsdb 页 |

## 5. 性能

1. 对写入性能基本没有影响，与多级存储功能下性能保持一致。
2. 对不涉及 data 文件的查询没有影响，head, sma, tomb, stt 等文件存储在本地。
3. 涉及 data 文件的查询性能需要配置合适的 s3PageCacheSize 参数，默认配置情况下，会有 16 M 的缓存数据，可以根据连续发起同一个查询两次的响应时间，判断缓存是否合适。

## 7. 运维

#### 7.0.1 历史数据导入

当历史数据较多，导入时间较长，最后一级本地存储空间有限等情况下，可以按时间段分批次写入到最后一级。默认情况下，data 文件一天不再变动后将上传至 S3；如果按一个 duration 的时间完成一组文件的写入后，需要尽快腾出存储空间，可以 flush database 将内存中数据落盘，然后如有必要可以进行 compact 操作。
之后，可以将 s3UploadDelaySec 参数动态修改到最小值:
`alter dnode <dnodeId> 's3UploadDelaySec' '600';`
十分钟后（从 data 文件的最后修改时间开始）进行 trim database 操作（默认情况下，mnode 会每小时下发一次 trim 命令），data 文件将开始上传到 S3。
上传操作完成后，TSDB 会将本地已上传的 data 文件删除，释放存储空间，然后可以进行下一个批次的数据导入。

## 8. 使用场景

1. 公有云 S3 服务，如腾讯云 COS
2. 私有云 S3 服务，如私有化部署的 minio 集群
由于多级存储最后一级通常情况下会有大量的 data 数据文件，这些文件一般比较大，而 S3 存储的成本大致是 SSD 存储的十分之一，把这些文件存放到 S3 上面可以大幅降低用户的存储成本。

## 9. 约束和限制

#### 9.0.1 约束

需要配置多于一级的多级存储；如果只有一级，不管配置了多少磁盘，无法使用 S3 功能。

#### 9.0.2 限制

Data 文件上传到 S3 之后，继续写入对应时间段的数据，会在落盘时作为过期数据处理。为避免数据丢失，需要在 data 文件上传之前，flush database 或写入下一个时间段足够的数据，保证当前时间段的数据均已落盘（上传 S3 之前）。
如果要补写历史数据或进行 compact 操作，需要手动将文件下载到本地之后进行。
暂不支持 split vgroup 命令。

## 10. 常见错误和排查

由于上传功能生效时间较长，配置完成后可以检查下是否正确；也可以在配置前使用 s3cmd, s3fs 等三方工具验证参数是否可用。
所有配置均为 dnode 级别，每个 dnode 都需要配置，如果没有配置或配置错误，对应 dnode 的 S3 功能不会生效，数据将存储在多级存储配置的目录。
