# S3 性能优化 - block cache

[COS对象存储用户手册](https://taosdata.feishu.cn/wiki/OjmwwCmqdiENPckuo4icjb5fnzc) 

## 1. 目前问题

cos 目前查询时会把涉及的 data 文件下载到本地磁盘，供本次及后续查询使用。由于最小下载单位是一个 data 文件，当文件较大时，会下载较长时间。比如查询一周的数据，如果一个 data 文件是十天的数据，则可能下载两个文件，首次查询的利用率大概只有三分之一；如果只是查询某一行等少量的数据，则利用率更低。

## 2. 解决方案

为了减少下载时长，必须减小单次的下载数据，在 tsdb 文件页的基础上引入 block 组织方式。目前 tsdb 读取 s3 文件时会缓存一个页，下次如果还是读取这个页，则会重复利用。通过修改这里的缓存方式，把上一个页的缓存修改为 tsdb 层面的 block 缓存，~~可以有效降低大数据量读取时，磁盘的读~~~~IO~~~~次数~~。对于 cos 存储来说，如果目标 block 不在缓存里，则可以去对象存储下载。
**解决方案中有两个关键部分，一是部分拉取，即从一个文件中只拉取需要的部分，最小单位为一个 block，block 大小可配置为页大小的倍数，默认为 4096页，即 16MB。另一个关键是本地缓存（内存中），缓存大小可配置。**
关于 block 和 缓存的具体组织方式，需要梳理下目前 tsdb 更多的实现细节，之后再补充到这里。

## 3. 优化目标

[S3 性能测试报告(腾讯云)](https://taosdata.feishu.cn/wiki/NBY1wRKq3iHZjDkZI5lcFMNMn31) 
第五部分性能总结中，只有1和4是问题，其它好像是建议，其中第4条需要验证，下载单元是一个 data 文件，并不是所有 data 文件。优化目标：如上所述，不再以 data 文件作为下载单元，消除下载所带来的过长等待时间。
**对以下几种查询会有明显的性能优化：**
1. **投影查询，查询短时间范围内的数据**
2. **子表查询，查询单一子表的数据**
3. **重复查询，重复执行以前执行过的查询**
**定性来看，单次查询涉及 S3 中的数据量越少越集中，性能优化越明显。如果查询数据量很大，则和上一版本中的性能不会有明显区别，因为同样要下载很大的数据量。但如果重复执行大数据量的查询，则优化效果取决于缓存大小。定量优化效果需等待测试完成。**

## 5. 新增配置参数

TSDB 缓存的 page 与写入有关系，所以这里实现的缓存仅用于 s3 的数据下载读取。新增两个参数用于控制每次下载的数据量和整个缓存的大小。其中 s3BlockSize 默认值 4096，表示每次从 s3 拉取 4096 个 tsdb 页，默认每个页的大小为 4096 字节，所以默认情况下，每次从对象存储下载 16M 的数据。s3BlockCacheSize 的单位是块，默认缓存 16 个块，即，默认情况下，每个 tsdb 的缓存大小为 256 M。如果内存有限，可以适当减小缓存大小。

| # | 参数 | 默认值 | 最小值 | 最大值 | 描述 |
| --- | --- | --- | --- | --- | --- |
| 1 | s3BlockSize | 4096 | 2048 | 1048576 | 每次从s3 下载的块大小，单位：tsdb page size |
| 2 | s3BlockCacheSize | 16 | 4 | 1048576 | s3 block cache 内存大小，单位：tsdb block |
