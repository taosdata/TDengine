# 20251128 传输安全设计评审记录

## 1. 评审信息

1. 评审目的：评估 “传输安全” 设计的合理性、安全性、性能、兼容性及可维护性
2. 评审文档：[传输安全 FS](https://taosdata.feishu.cn/wiki/UzIcwoxz6ikM7WksBSMclmqrnhd)

6. 会议形式：线下
7. 会议地点：taosX
8. 会议记录人：关胜亮

## 2. 评审记录

1. 设计合理性
   - 动态证书更新机制合理：采用`ALTER INSTANCE RELOAD TLS`指令，通过mnode协调、heartbeat触发、证书热更新不影响现有连接的方案，平衡了管理便利性与集群稳定性，设计合理。
   - SASL集成增强安全：计划结合Libsasl与TLS，实现身份验证和传输加密，能有效抵御中间人攻击和数据篡改，符合传输层安全的设计原则。
   - 资源限制维度全面：定义的5项会话与资源控制参数（如`sessionPerUser`, `sessionConnectTime`等）覆盖了连接数、时长、空闲时间、并发调用等关键资源管控点，有助于防止资源滥用。
   - 功能边界明确：文档正确指出数据大小限制和消息校验已在传输层实现，无需在本期重复开发，避免了冗余工作。
2. 安全性设计
   - 采用标准安全协议：基于TLS和SASL等成熟标准协议构建安全传输层，并计划集成符合国家标准的密码算法，为身份验证和数据传输提供了基础安全保障。
   - 证书管理安全：动态更新TLS证书的功能设计，明确了企业版且开启TLS的前提条件，并指出TSDB不存储证书信息（无状态），降低了证书管理相关的风险。
   - 会话超时控制：通过`sessionConnectTime`和`sessionConnIdleTime`参数实现会话生命周期管理，有助于减少因长期闲置或异常连接导致的安全风险。
3. 性能影响
   - 文档已预估引入安全机制可能带来不超过10%的性能开销，该评估值在可接受范围内。
   - 资源限制功能本身即旨在保障系统整体性能和高可用性，防止因个别用户或会话过度消耗资源而影响系统稳定性。
4. 兼容性设计
   - 向后兼容性：文档明确要求需向后兼容，确保从版本3.3.8升级至本版本时无需手工干预。
   - 连接管理兼容：TLS证书更新采用“新建连接使用新证书，现有连接维持至关闭”的策略，最大限度地保证业务连续性和平滑升级。

## 3. 评审结论

通过。
