# 20251120 加密算法设计评审记录

1. 评审目的：评估 “加密算法” 设计的合理性、安全性、性能、兼容性及可维护性
2. 评审文档：[加密算法 FS](https://taosdata.feishu.cn/wiki/RIOow1Zg9iOHkQkDp7dceEMGnib)

8. 会议记录人：关胜亮

## 2. 评审记录

评审团队对设计文档进行了全面审查，认为所有设计合理，具体评审意见如下：
1. 设计合理性
   - 算法管理架构清晰：通过`show encrypt_algorithms`统一管理内置和自定义算法，设计合理
   - OpenSSL 集成完善：充分利用 OpenSSL 的 EVP 接口，支持丰富的加密算法
   - 自定义算法扩展性：提供用户自定义算法机制，支持动态加载 .so 文件
2. 待改进：
   - 算法类型定义不完整：目前仅支持 "Symmetric Ciphers CBC mode"，缺乏非对称加密、散列算法等完整分类
   - ECC 算法缺失：文档提到ECC算法因无对应类别而未实现，但OpenSSL实际支持椭圆曲线加密
   - 自定义算法限制：用户无法定制非对称加密算法，限制了扩展能力
3. 安全性设计
   - 算法标准化：采用国家标准 SM4、SM2、SM3 算法，符合安全要求
   - 密钥管理：支持 key 和 IV 配置，具备基本的密钥管理机制
   - 风险点：
      - 密钥派生机制：文档提到"将key和IV设计成相同的值"，存在安全隐患
      - 自定义算法安全审核：用户自定义算法缺乏安全审核机制，可能引入安全漏洞
      - 算法强度不明确：未说明不同算法的安全强度和适用场景
4. 性能影响
   - 算法选择灵活：支持多种算法，用户可根据性能需求选择
   - OpenSSL 优化：利用 OpenSSL 的高性能实现
5. 兼容性设计
   - OpenSSL 版本兼容：基于标准 OpenSSL 接口，具有良好的跨版本兼容性
   - 旧版本兼容：考虑 SM4 算法 ID 保持为 1，确保向后兼容
   - 升级机制：设计 upgrad e机制支持算法动态添加
6. 可维护性
   - 模块化设计：加密功能封装为独立模块，接口清晰
   - 配置化管理：通过 encryptExtDir 配置自定义算法路径
   - 统一管理接口：提供完整的 CRUD 操作接口

## 3. 评审结论

通过。

## 4. 后续行动项

1. 技术设计问题
   - 算法分类不完整：当前仅支持对称加密 CBC 模式，应扩展支持更多模式（如 GCM）和算法类型
   - ECC 算法误解：OpenSSL 实际支持椭圆曲线加密（EC），文档中的理解有误
   - 密钥安全：key 和IV 相同存在安全风险，应设计更安全的密钥派生机制
2. 实现细节问题
   - 接口一致性：不同算法类型的调用接口需要统一封装
   - 错误处理：加密失败时的回滚和错误传播机制不明确
   - 资源管理：OpenSSL 上下文对象的内存管理需要详细说明
3. 运维管理问题
   - 算法部署：自定义算法的部署和更新流程需要规范
   - 监控告警：加密操作的成功率、性能指标需要监控
   - 密钥轮换：缺乏密钥生命周期管理机制
