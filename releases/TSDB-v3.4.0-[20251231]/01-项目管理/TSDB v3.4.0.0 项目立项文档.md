## 2. 项目目标

本项目聚焦于开发与发布 TDengine 安全版（v3.4.0.0）​​，致力于达成以下核心目标：
1. 产品目标​：通过系统性的安全加固与性能优化，显著提升产品安全水位与运行可靠性。
2. 过程目标​：协同改进研发测试、质量保障与安全流程，建立高效交付高质量产品的能力。
3. 商业目标​：打造符合严苛安全要求的企业级产品，为开拓重点行业市场、提升市场份额提供关键支撑。

## 3. 项目范围

### 3.1 安全功能

本次版本迭代的核心目标之一是全面提升 TDengine 的安全性、可靠性和合规性，主要围绕以下八大安全维度进行建设：
1. 身份鉴别：支持多因子认证，强密码策略，确保用户身份的真实性。
2. 访问控制：实施基于角色的访问控制，实现库、表级别的权限管理。
3. 存储安全：支持配置文件、用户信息、时序数据文件的加密存储，支持国密算法和密钥生命周期管理。
4. 传输安全：对重要数据的传输过程进行加密，防止消息重放攻击，优化白名单，建立消息认证机制。
5. 安全函数：提供一系列内置安全函数，方便开发者处理常见安全需求。
6. 安全审计：建立完整的审计流水线，记录关键操作，满足合规性要求。
7. 加密算法：集成国密等符合行业要求的加密算法套件，提供更多算法选择。
8. 编码安全：优化静态、动态检查机制，降低因编码不当引入的安全漏洞风险。

### 3.2 通用功能

在安全增强的基础上，本次版本迭代将对以下核心通用功能进行迭代和优化，以提升产品性能和用户体验：
1. 虚拟表​：优化虚拟表继承机制，提升其在多场景下的查询性能与稳定性。
2. 流计算：增强流式计算能力，支持按自然月触发计算任务、处理子事件复杂逻辑，并显著提升其性能，缩小与先进计算框架（如 Flink）在特定场景下的差距。
3. TDgpt：引入相关性分析功能，为用户提供更深层次的数据洞察。
4. OAuth 2.0：支持通过 OAuth 2.0 与第三方身份提供商集成，实现单点登录和集中式身份管理。
5. taosX 分布式能力增强：进一步提升 taosX 工具在分布式环境下的数据同步与备份能力。

### 3.3 过程改进

为确保产品高质量交付并提升团队长期研发效能，本项目范围内还包括以下研发过程改进工作，旨在建立更规范、更高效、更质量可控的研发体系
1. 管理体系与流程优化
   - 组织架构与准则​：制定并推行组织级的研发管理准则和过程体系大纲。
   - 项目生命周期管理​：建立覆盖立项、规划、开发、测试、发布、验收、投产的全流程管理规范，并制定明确的变更规则与进度管控机制。
   - 日常运维制度化​：完善缺陷管理、异常告警、客户支持、代码仓库管理、问题复盘及周报、月报等日常运维制度。
2. 质量与安全规范建设
   - 技术基线规则​：统一测试用例编写、编程语言开发、关键字增删及日志撰写的规范与标准。
   - 全面安全管理​：建立贯穿整个开发周期的安全开发管理制度，涵盖安全需求、设计、编码、测试（渗透测试、工具扫描、安全自查）、审计及新技术引入评估等环节。
   - 质量保障体系​：完善风险管理制度、供应商管理、配置管理、变更控制流程、质量保证制度及质量自查体系。
3. 知识沉淀与资产复用
   - 研发文档模板化​：制定并应用统一的需求、设计、测试、验收、评审及会议记录模板，提升文档质量和编写效率。
   - 培训与考核​：建立培训制度与绩效考核制度，确保各项流程规范得以有效贯彻和持续改进。

## 4. 项目工期

项目总工期为 4个月，自 2025-10-01 至 2026-01-31。项目进度计划遵循经典的“设计-开发-测试”瀑布模型，但各子功能的开发可以敏捷迭代，确保在紧凑的工期内高效交付。
1. 需求与设计阶段：2025-10-01 ~ 2025-10-31，完成需求分析和功能设计。
2. 开发及功能测试阶段：2025-11-01 ~ 2025-12-31 ，完成代码开发和功能测试，发布可测试的软件版本。
3. 系统测试与验收阶段：2026-01-01 ~ 2026-01-31，完成系统测试和缺陷修复，完成软件版本的验收。
4. 项目总结阶段：2026-01-25 ~ 2026-01-31，项目成果评审、文档归档、经验总结与复盘。
过程改进的安排，参照 “[研发文档编制计划](https://taosdata.feishu.cn/wiki/GSYywFkYxisymGkUJMaceGRqnqb)”，主要节点如下
1. 第一阶段：2025-09-25 至 2025-09-30 必要文档编制。
2. 第二阶段：2025-10-01 至 2025-10-24 全部初稿编写。
3. 第三阶段：2025-10-24 至 2025-10-31 审核与修改。
4. 第四阶段：2025-11-01 至 2025-11-06 流程宣贯。

## 8. 项目成功标准与验收条件

1. 功能完成与文档就绪：规划的所有核心功能均已实现，并通过功能测试；用户手册已编写完成；已发布可供测试的版本。
2. 通过系统测试：通过测试部门组织的系统测试，并获取了正式的系统测试报告。
3. 通过性能基准测试：​当开启安全功能时，和 3.3.8.0 版本比较，性能衰减低于 10%。
4. 通过系统兼容性测试：从 3.3.8.0 版本可以升级至 3.4.0.0 版本，数据文件向上兼容
5. 通过交付验收：通过交付部门的验收审核，确认其质量与稳定性满足向客户升级发布的要求。
6. 过程符合规范：本次开发过程遵循了既定的研发体系与规范，各项实践应用有效。
