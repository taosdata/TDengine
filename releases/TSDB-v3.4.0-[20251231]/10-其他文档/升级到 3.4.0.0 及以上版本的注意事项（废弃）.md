# 升级到 3.4.0.0 及以上版本的注意事项（废弃）

## 1. 请参考：

[安全相关功能兼容现存行为](https://taosdata.feishu.cn/wiki/OidzwtXOVisZyEksa4Ocx7I3nbg)

## 2. 身份鉴别相关

3.4.0.0 版本新增了密码过期等功能，user 对象增加了多个字段用于记录相关信息，这些字段在之前的版本中并不存在，所以升级处理时设置成了默认值。这些默认值可能导致升级后登录时提示密码过期等。

### 2.1 提示密码过期的解决方案

- root 用户：登录后执行 `ALTER USER root PASS '<new password>'` 修改密码后可恢复正常。
- 其他用户：
  - 如用户可以正常登录但不能执行其他命令，登录后修改密码后可恢复正常。
  - 如登录时提示用户被禁用，使用 ROOT 用户登录后修改该用户密码后可恢复正常。
- 使用 ROOT 用户登录后，执行 `ALTER USER user_name PASSWORD_LIFE_TIME UNLIMITED` 可使该用户的密码永不过期（但 ROOT 用户的 PASSWORD_LIFE_TIME 不能修改）。云服务建议对所有用户执行此操作。

### 2.2 连续输入密码错误导致用户被锁定

- Root 用户不会出现此情况。
- 其他用户被锁定后：
  - 等待 PASSWORD_LOCK_TIME （默认1天）后，可自动恢复。
  - 通过 ROOT 用户修改其密码后可恢复。
  - 重启服务端后可恢复。

### 2.3 用户新增属性

用户新增属性列表和作用请参考官网文档：https://docs.taosdata.com/reference/taos-sql/user/

## 3. 用户权限相关 (无需特殊处理)

- 升级至 [3.4.0.0+ 版本后](https://taosdata.feishu.cn/wiki/SxFfwi3p0iTPZxkO5pRco9BmnKd)，在老版本设置的用户权限，会由数据库自动转换为 3.4.0.0+ 版本的用户权限，理论上，不需要人工干预，升级后可通过 `show users` 查看用户角色，通过  `show user privileges` 查看用户权限，通过 `show role privileges `查看角色权限。因为 3.4.0.0+ 版本的权限种类较细，不能 100% 保证升级后没有任何权限问题。如果遇到了，请联系运维或研发人员处理。
- 另外，3.4.0.0+ 版本的权限整体改动较大，对语法进行了统一，部分旧语法不再兼容，新的语法请参考 [官网用户手册](https://docs.taosdata.com/next/reference/taos-sql/grant/)。 不兼容的语法列表如下：

| 序号 | 权限作用对象 | 3.3.x.y | 3.4.0.0+ |
| --- | --- | --- | --- |
| 1 | 数据库 | 授予/撤销 db1** **`读/写/所有`权限： grant read/write/all on <db1> to <user1>; revoke read/write/all on <db1> from <user1>; 或 grant read/write/all on <db1>.* to <user1>; revoke read/write/all on <db1>.* from <user1>; | 针对 3.3.x.y 中的语法： - 3.4.0.0+ 对于下述语法报错: grant read/write/all on <db1> to <user1>; revoke read/write/all on <db1> from <user1>; 无对应的数据库级的语法，因为拆分为更细的语法了。 - 3.4.0.0+ 对于下述语法，read/write 报错，all 不报错，但是含义也不同。3.4.0.0+ 在未指定作用对象时，默认是指 table。 grant read/write/all on <db1>.* to <user1>; revoke read/write/all on <db1>.* from <user1>; |
| 2 | 表 | 授予/撤销 db1 下表 tb1 的`读/写/修改/所有`权限： grant read/write/alter/all on <db1>.<tb1> to <user1>; revoke read/write/alter/all on <db1>.<tb1> from <user1>; | 针对 3.3.x.y 中的语法，read/write 报错，alter/all 兼容； 3.4.0.0+ 相关的语法为： grant select/insert/alter/all on <db1>.* to <user1>; revoke select/insert/alter/all on <db1>.* from <user1>; 或 grant select/insert/alter/all on table <db1>.* to <user1>; revoke select/insert/alter/all on table <db1>.* from <user1>; 说明：all 对应的具体权限为 select/insert/alter/delete/drop/show/show_create |
| 3 | 视图 | 授予/撤销 db1 下视图 view1 的`读/写/修改/所有` 权限： grant read/write/alter/all on <db1>.<view1> to <user1>; revoke read/write/alter/all on <db1>.<view1> from <user1>; | 针对 3.3.x.y 中的语法报错： 3.4.0.0+ 相关的语法中，需要指定作用对象 view。 grant select/alter/drop/show/show create on view <db1>.<view1> to <user1>; revoke select/alter/drop/show/show create on view <db1>.<view1> from <user1>; |
| 4 | 订阅 | 授予/撤销 topic1 的 `订阅`权限： grant subscribe on <topic1> to <user1>; revoke subscribe on <topic1> to <user1>; | 针对 3.3.x.y 中的语法报错： 3.4.0.0+ 相关的语法中，需要指定作用对象 topic 以及 topic 所属的 db： grant subscribe on topic <db1>.<topic1> to <user1>; revoke subscribe on topic <db1>.<topic1> to <user1>; 注：根据 subscribe 也能推断出 topic 和 db1，但为了统一语法，没有做兼容。 |
