# 多级存储数据恢复

本文档对多级存储期望的目标行为进行说明。

## 1. 当前行为

1. 配置：通过配置文件中的 dataDir 来指定
在 taos.cfg 中，形如
```shell
dataDir [path] <level> <primary>

dataDir /mnt/data1 0 1
dataDir /mnt/data2 0 0
dataDir /mnt/data3 1 0
dataDir /mnt/data4 1 0
dataDir /mnt/data5 2 0
dataDir /mnt/data6 2 0
```

1. 使用约束如下：
   - 多级存储不允许跨级配置，合法的配置方案有：仅 0 级，仅 0 级+ 1 级，以及 0 级+ 1 级+ 2 级。而不允许只配置 level=0 和 level=2，而不配置 level=1。
   - 0 级存储必须有且只有一个挂载点是 primary
   - 1 级和 2 级存储不能配置主挂载点
   - 禁止手动移除使用中的挂载盘，挂载盘目前不支持非本地的网络盘。
   - 多级存储目前不支持删除已经挂载的硬盘的功能。
2. 主挂载点
   - 所有 vnode 的 WAL 都位于主挂载点
   - 所有 vnode 的 TQ
   - 所有 vnode 的 Meta
   - 所有 vnode 的 Cache.RDB
   - 所有 vnode 的 current 文件 （包含这个 vnode 所有数据文件在0，1，2级挂载点上的分布）
3. TSDB
   - 每个 vnode 在 Keep0 参数指定时间范围内的落盘数据（data, stt）以 round robin 形式分布在所有 0 级挂载点（包含主挂载点）
   - 每个 vnode 在 keep1 参数指定时间范围内的落盘数据（data）以 round robin 形式分布在所有 1 级挂载点
   - 每个 vnode 在 keep2 参数指定时间范围内的落盘数据 (data）以 round robin 形式分布在所有 2 级挂载点

## 2. 当前行为中的问题

- [ ] WAL 全部位于主挂载点，负担重，影响整个系统的写入性能，且磁盘容易损坏
- [ ] 不管哪个挂载点损坏，都要恢复整个 dnode 的全部数据才能恢复
   - 当从挂载点损坏时，虽然可以从每个vnode 的 current 文件经过计算知道要恢复的数据。但目前尚不具备这个能力。即使只有一个从挂载点损坏时，也要恢复整个 dnode 的全量数据。
   - 当主挂载点损坏时，因为 current 文件丢失，所有 vnode 都要做全量数据恢复（从其它副本恢复 0, 1, 2 三级存储上的所有数据），并重构 current 文件以及其它 meta data。

## 3. 期望行为

1. WAL 负担能够分散到多个 0 级挂载点上，提高系统写入吞吐量，并降低主挂载点坏的概率
2. 主挂载点只存储元数据（可配置）
3. 任意一块或多块磁盘损坏，在更换磁盘后，能够通过 restore dnode **只恢复损坏的磁盘上的数据**
4. 能够以 dnode, vnode, disk 为单位展示数据分布: show dnode <dnode_id> distributed, show vnode <vnode_id> distributed, show disk <path> distributed

## 4. 设计方案 （High Level）

### 4.1 数据结构

1. 保持现有挂载点的配置方式不变（暂不考虑支持动态添加方式）
2. dnode 的主挂载点根据配置可以只存储 meta data （meta data 的详细列表待定）
   - taos.cfg: primaryMetaOnly
   - true: 主挂载点不存储时序数据
   - false: 主挂载点存储时序数据
   - default: false
3. meta data 存储在 mnode 集群中（三副本）
4. 每个 vnode （假定其 ID 为 1，其它vnode 同理）以 round robin 方式被分配 0 级挂载点中的一个作为它的主挂载点，在主挂载点上保存
   - WAL
   - TQ
   - Meta
   - Cache.RDB
   - Current （仅包含本挂载点上 vnode 1 的数据文件分布）
5. 0 级挂载点中的所有其它挂载点都是 vnode 1 的从挂载点，其中存有
   - TSDB 数据文件
   - vnode 1 在本挂载点上的数据存储的 current
6. 从以上两点可以看出，对于任意一个 vnode 来说，主从挂载点的差异是：WAL/TQ/Meta/Cache.RDB。共同点是 TSDB数据文件和本挂载点上的 current文件

### 4.2 设计关键点

1. WAL 分布在 0 级挂载点中，消除单点性能瓶颈
2. current 文件分布在所有挂载点上，且每个 current 文件只存储所涉及 vnode 在该挂载点上的数据分布元数据，任意两个 current 文件之间没有交集，消除单点故障恢复瓶颈

### 4.3 创建 vnode 

创建 vnode 时会为其分配 一个 0 级挂载点（非主）作为该  vnode 的主挂载点，则其它 0 级挂载点自动成为它的从挂载点

### 4.4 数据落盘

数据落盘的流程完全不变，在生成新的落盘文件（STT or data）时，会以 round robin 方式从所有 0 级挂载点（不含主挂载点）中选择一个生成落盘文件，并**更新该挂载点上该 vnode 的 current 文件**。

### 4.5 数据迁移

从 0 级到 1 级迁移的逻辑不变，**但要更新源盘和目标盘上的 current 文件**。

## 5. 恢复能力

### 5.1 主挂载点损坏后的恢复

因为主挂载点只存储 meta data，利用 mnode 集群从其它副本恢复 meta data 即可。

### 5.2 1个 dnode 有磁盘损坏

可以恢复，且不影响系统读写。对这种情况下面进行了细分，结论是解决方案无差别。

#### 0 级某挂载点损坏

因为每个挂载点上都有所有 vnode 的一部分数据，所以恢复实质上是恢复该  dnode （的所有 vnode）在该挂载点上的数据。具体实现上，通过其它副本能够得到一个 vnode 的数据范围的全集（即所有表以及每个表的时间范围的集合），减去该  vnode 在仍然存活的挂载点上的 current 所表示的数据范围的合集，其差集即为该 vnode 要恢复的数据；其它 vnode 同样处理即可以完整恢复该挂载点上的数据，并重构 current 文件和其它数据。

#### 1 级 或 2 级 某挂载点损坏

与 0 级同理。

#### 0 级多个挂载点同时损坏

与 一个挂载点损坏时的处理方式相同，但计算出的差集要以 round robin 方式分布在多个损坏的挂载点上，并重构 current 文件。理论上即使所有 0 级挂载点全部损坏也能够重建，但重建出的结果只保证整个数据集与原先相同，不能保证每块盘上的数据分布都与损坏之前相同。

#### 1 级或2 级多个挂载点同时损坏

同上

### 2 个 dnode 同时有磁盘损坏

可以恢复，恢复原理同上，但恢复过程中不可读写，因为任何一个 vgroup 都只有一个 leader 存活，无法形成多数。

### 3 个 dnode 同时有磁盘损坏

必然会有数据丢失，因为没有一个 dnode 的数据是完整的。有一种特殊情况是，如果各自缺失的部分没有交集，理论上也能恢复，但过程过于复杂，不考虑支持。
