# 故障注入测试机制

## 背景

- taos/taosd 代码中，存在很多 `异常处理不合理`或者`异常未处理`的情况，这些异常轻则导致逻辑错误，重则导致 core/死锁引发卡死/资源泄露并最终引发 OOM 等情况。因此，增加随机失败测试，以尽早发现问题。
- [TD-31375](https://jira.taosdata.com:18080/browse/TD-31375) 增加文件 I/O 的混沌测试机制。

## 实现原理

### 2.1 编译选项

- 在非 release 版本中，通过编译选项 BUILD_WITH_RAND_ERR，控制是否嵌入随机失败的代码。
```plaintext {wrap}
1) 包含编译选项 BUILD_WITH_RAND_ERR 时表示嵌入随机失败代码，例如，-DBUILD_WITH_RAND_ERR
2) 不包含表示不嵌入，默认不嵌入
```

### 2.1 随机失败模块

- 随机失败主要以资源分配及访问类为主，例如，内存分配、文件访问、网络访问、锁操作等。目前，支持的随机失败模块如下表(后续可视实际需求进行扩展)。为便于测试，可通过参数 [randErrorScope](https://taosdata.feishu.cn/docx/ZdRHd1o4Jo3SzVxdkGKcqaq6nhc?open_in_browser=true#LRcod28KAoZ78TxIs7BcWb3on2l) 控制随机失败模块的范围：

| 随机失败模块 | 支持的操作详情 | 错误提示信息 |
| --- | --- | --- |
| 内存分配 | - 内存分配 taosMemoryMalloc taosMemoryCalloc taosMemoryRealloc taosMemoryMallocAlign - 字符串拷贝 taosStrdup | Out of Memory |
| 文件访问 | - 文件打开 taosOpenFile taosOpenCFile - 文件读取 taosReadFile taosPReadFile taosReadFromCFile - 文件写入 taosWriteFile taosPWriteFile taosWriteToCFile | Input/output error |
| 网络访问 |  | Unable to establish connection |

## 3. 控制参数 

### 3.1 参数列表

- 通过参数 randErrorChance/randErrorDivisor/randErrorScope 控制随机失败的概率及模块范围。参照下表（以默认值 1/10001/3 为例，表示内存分配和文件操作，均以 1/10000 的概率返回失败）

| 参数 | 说明 | 取值 | 默认值 | 作用范围 | 动态修改 |
| --- | --- | --- | --- | --- | --- |
| randErrorChance | 随机失败概率 - 分子。一般与 randErrorDivisor 配合使用。 | [0, 10000] | 1 | 服务端 | 是 |
| randErrorDivisor | 随机失败概率 - 分母。一般与 randErrorChance 配合使用 | [1, INT64_MAX] | 10001 | 服务端 | 是 |
| randErrorScope | 随机失败范围。使用 bit 位表示某个模块是否开启。 | [0, INT64_MAX] 通过位运算表示。目前支持的位取值如下: 1: 0x01 内存分配随机失败 2: 0x02 文件操作随机失败 4: 0x04 网络访问随机失败 | 7: 0x07 表示"内存分配/文件操作/网络访问"均会随机失败 | 服务端 | 是 |

### 3.2 参数设置

- 支持通过 taos.cfg 配置文件修改。该修改会永久生效，修改后需要重启 taosd 才能生效。
```plaintext {wrap}
// 示例，文件操作以 3/100000 的概率返回失败
randErrorChance   3
randErrorDivisor  100000
randErrorScope    2
```

- 支持通过命令动态修改。动态修改的优先级更高，会覆盖 taos.cfg 中相同配置项的内存值；动态修改目前不支持持久化，重启后失效：
```plaintext
alter all dnodes 'randErrorChance 2'; // 将所有 dnode 的随机失败概率分子改为 2
alter dnode 2 'randErrorDivisor 500000'; // 将 dnode 2 的随机失败概率分母改为 50 万
alter all dnodes 'randErrorScope 2'; // 将所有 dnode 的随机失败模块范围改为 "文件操作"
```

## 使用方法

### 3.1 编译选项

- 编译时，包含编译选项 -DBUILD_WITH_RAND_ERR。

### 3.2 控制参数

- 通过控制参数 randErrorChance/randErrorDivisor 调整随机失败的概率。示例如下：
```plaintext {wrap}
1）默认关闭所有模块的随机失败：
   randErrorChance 0 // taos.cfg
2）动态将随机失败概率分子调整为 2:
   alter all dnodes 'randErrorChance 2';
3) 动态关闭所有模块的随机失败： 
   alter all dnodes 'randErrorChance 0';
4）动态将 dnode 3 的随机失败概率调整为 7/200000: 
   alter dnode 3 'randErrorChance 7';
   alter dnode 3 'randErrorDivisor 200000';
```

- 通过控制参数 randErrorScope 调整随机失败的模块范围。示例如下：
```sql {wrap}
1）默认开启 "内存分配/文件操作/网络访问" 随机失败：
   randErrorScope 7 // taos.cfg
2) 将 dnode 5 的随机失败模块范围设置为 "内存分配"
   alter dnode 5 'randErrorScope 1';
3) 关闭所有 dnode 的所有模块的随机失败
   alter all dnodes 'randErrorScope 0';
```
