## 3. 需求目标

开发文件修复工具，该工具能够检测/修复特定类型的文件，且涉及文件的范围可扩充。

## 4. 功能需求

在相关文档资料中，可以看到从 2.X 版本开始，在特定客户中就出现过文件损坏的情况，包括 mnode/tsdb 等模块涉及的文件都可能由于断电/人为篡改等方式出现损坏。这一期要提供一个文件修复的程序框架，后续逐渐补充。
1. 检测和修复都需要 taosd 的文件解析代码，而 taosd 的主要逻辑在可执行文件中，并没有实现为动态链接库；如果提供单独的工具，那这个工具的二进制程序会很大；因此，为 taosd 增加若干命令选项，作为修复工具的入口，例如下游的 taosd -dTxn。
2. 支持检测/修复两种选项，暂时不支持自动修复的功能（看需求来源酌情增加，但可能会影响 taosd 启动时间）
3. 支持文件的范围，例如
   - 数据文件：文件类型可以进一步细分
   - WAL 文件
   - Mnode 文件
   - 配置文件
   - 流计算文件：checkpoint 等
4. 本期实现 TS-5795 所覆盖的特定数据文件类型

## 5. 性能需求

1. 如有可能，在修复数据文件/WAL 文件时，能够支持多线程并行执行。
2. 测试时，给出 100 GB 数据文件的扫描和修复时间，作为基准。

## 6. 其他需求

1. 需编写测试用例，提前准备特定损坏情况的数据文件，编写成压缩包（文件位置和王旭沟通），用例可检测文件损坏的位置，修复损坏的内容。
2. 检测和修复的结果应该以可读的控制台信息输出，建议采用 JSON 文件，打印扫描过的文件列表，发生损坏的文件名以及损坏位置的详细信息。
3. 应该无兼容性/接口的变更的要求。
