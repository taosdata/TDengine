# 流计算的需求整理 RS

流计算是由事件(event)触发的，触发后，具体计算的形式也有多种，下面做一需求说明：

### 1. 触发方式

触发流计算的方式有多种，具体而言，如下：
1. **收到新的数据点**：新的数据点可以是一列或多列数据。就是当指定的列有新的数据时，就进行触发。当一个表有很多列，比如c0, c1一直到c99，但指定触发的列是c1, c8, 只有当c1或c8列有新的数据时，就进行触发。如果这两列没有新的数据，但其他列有，也不触发。
2. **周期定时：**每隔固定的时间就触发计算。
3. **窗口打开或关闭：**窗口是指TDengine已经定义的session, state, count, event窗口。这些窗口打开或关闭时可以触发计算。这些窗口一定是定义在单个子表，或单个流上的。对于窗口，有更多的需求：
   - 对于计数窗口，可以指定具体的列，只有这些列有数据才计数。缺省是任何列有数据都计数。
   - 对于event window，如果条件为多个OR 条件，比如 A or B or C, 第一个满足的条件称之为effective trigger,  满足后就马上返回，引起触发。但新的数据进来后，第一个满足的条件如果改变了，也要引起触发。比如第一次满足的条件是C，系统引起触发，这时又有新的数据进来，条件B也开始满足（C可能仍然满足，也可能不满足），那么再次引起触发，更进一步，新的数据进来，条件A开始满足，那么再次引起触发。这种设计便于解决父事件、子事件的场景。比如，CPU超过70%，是warning,  超过80%，是critical, 达到100%，是error. 通知应用时，需要告知是哪个条件满足，这样应用就可以take不同的action.

### 2. 计算形式

计算，我们需要支持如下形式：
1. **表达式(Expression)**: 指某一具体时刻对一张表的单行查询（包括函数、四则运行等）。这一具体时刻可以是触发计算的时间，也可以指定相对触发时间的offset。比如触发时间是t0, 计算的时刻可以是t0, t0-1m, 甚至是未来的时间 t0+1m。对于未来的时间，一般用于时序数据预测。 
2. **聚合 (Rollup)**: 分为两类聚合
   - 时间轴上数据的聚合：可以指定时间范围, 支持: 
      - Interval：相对触发时间，过去的一段时间
      - Window：窗口关闭时，窗口的开始到结束
      - 任一时间段：假设触发时间是t0, 可以指定 t0 - start-offset : t0 + end-offset。对于窗口关闭的触发，可以指定 wstart - start-offset : wend + end-offset. Interval 以及window只是任一时间段的特殊形式。
   - 某一具体时刻，多个子表某一列的数据的聚合。对于时刻，缺省是触发时间t0, 但用户可以指定 t0 + offset。
  对于聚合，应用仅仅可以选择一种。
对于任何一种触发方式，应用可以选择表达式或聚合，但只能选择一种。

### 3. 通知

对于任何一个触发，无论何种触发方式，系统都可以通知应用。通知里包括：触发方式、触发的时间、窗口是开还是关。（注意：定时也可以有通知，比如一个日报生成完了，邮件主动通知）

### 4. 乱序数据处理

1. 应用可以主动重算
2. 对于定时计算，可以指定offset, 在offset时间过后，才真正计算，减小乱序数据影响

### 5. 其他

1. 触发是基于一个子表或超级表的数据进行的，但计算的对象可以是另外一个子表或超级表
2. 对于基于窗口的流计算，因为会存在两个触发，应用可以定义两个计算，计算的对象可以不同。
3. 上述文档中提到的子表或超级表，完全适用于虚拟子表、虚拟超级表。
