# 2.6->3.0 多表低频同步性能优化

## 1. 背景

当前实现中在 2.6 到 3.0 数据迁移或同步时，对于超级表，首先获取表结构并拉取所有子表信息，之后对每个子表进行时间分段查询后同步数据。这种查询方案对于子表数据量大的查询比较友好，能够获得更好的性能，也能够便捷的通过增加并发数提升同步效率，但对于多表低频或者少表低频的超级表，查询消耗较大，尤其在多表低频场景下，性能太差。本次优化将提供一种基于超级表查询的方案，以减少查询消耗，增加查询效率。
关联 Jira 见：
TS-4440

## 2. 定义

- 多表低频：指超级表的子表数量很多，但每个子表的数据分布比较稀疏，单个子表的数据量很小的情况。

## 4. 行为说明

### 4.1 概述

通过数据源参数增加一种查询模式开关 `sparse` （稀疏模式），仅对超级表查询生效。当开启时，使用 `select tbname, * from <stable> where <time-range>` 从超级表查询所有数据，之后按行拼装 SQL，形如 `insert into <table> using <stable> tags(<tags>) values(<values>)`，达到某个阈值（默认使用 `max-sql-length=800k`）后写入目标库。

### 4.2 数据源参数：`sparse`

`sparse` 是一个布尔类型参数，取值为 `true/false`，`true` 可省略。使用方式如下：
```bash
taosx run -f "taos:///db1?sparse" -t "taos:///db2"
```

### 4.3 Explorer UI

UI 上增加参数 `sparse` ，其中英文描述为：
- 启用此模式以提升多表低频场景下的性能。
- Enable `sparse` mode to improve performance in case of high-cardinality and low data ingestion frequency.

### 4.4 适用情况说明

- 启用 `sparse` 后，会显著降低并发能力（表现为 CPU 使用率明显下降，可能降低到 200% 以下），如果 `(end - start) / unit) < workers` ，则 `workers` 参数基本失效，此时，可以降低 `unit` 来提高并发度（CPU 使用率）。
- 在列数较多时，提高写入端参数 `concurrent-limit` 对性能有帮助。
- `sparse` 模式下，不统计指标 `tables` 数量，`total-tables` 数量统计与超级表数 + 普通表数量相等。

## 5. 性能

- 多表低频场景可显著提升性能：
  构造一个极端场景，建立一个 10 万子表的超级表，每个子表仅有一行数据。
  ```bash
  taosBenchmark -y -n 1 -t 100000 -T 8 -d db1
  ```

  使用原来的查询方案需要 22 秒，使用 `sparse` 模式仅需要 1 秒。
- `sparse` 模式不总是能够提升性能：
当每个子表行数增加到 1000 时，原来的查询方案耗时 65 秒，此时 `sparse` 模式已经需要 200 多秒了（均在默认参数下）。
故，请仅对非常低频或极大规模子表的超级表使用此模式（单位查询间隔 `unit` 下子表平均行数少于 `10` 可能是适合的，使用 `sparse` 模式时，请配置 `unit` 为一个合适的值）。

## 6. 兼容性

`sparse` 模式对 `remap` 参数和 `-T` 参数进行了兼容，支持 `remap` 参数进行列名重命名，以及使用 -T 参数进行超级表或子表重命名，与之前的行为保持一致。参考 8.3./8.4.。
服务模式下，`sparse` 支持断点续传，断点续传的维度是超级表的查询时间进度（此行为与之前每个子表的时间进度不同）。

## 8. 使用场景

### 8.1 多表低频下使用 `sparse` 模式

源库下所有超级表均使用 `sparse` 模式，普通表同步方式不变：
```bash
taosx run -f "taos:///db1?sparse" -t "taos:///db2?assert" 
```

指定超级表使用 `sparse` 模式：
```bash
taosx run -f "taos:///db1?stables=meters&sparse" \
  -t "taos:///db2?assert"
```

### 8.2 CPU 资源受限时使用 `sparse` 模式

`sparse` 模式带来的额外的好处，是降低 CPU 占用率，所以，在 CPU 资源受限的场景中，可以使用 `sparse` 模式，配合较小的 `unit` 来获得合适的性能。

### 8.3 `sparse` + `remap` 列重命名

使用 `sparse` 模式，目标端参数使用 `remap` ：
```bash
taosx run -f "taos:///db1?sparse" \
  -t "taos:///db3?assert&remap=@./tests/legacy/remap.csv"
```

以超级电表 Schema 为例，源库中 `meters` ：
```sql
taos> desc meters;
             field              |          type          |   length    |    note    |
=====================================================================================
 ts                             | TIMESTAMP              |           8 |            |
 current                        | FLOAT                  |           4 |            |
 voltage                        | INT                    |           4 |            |
 phase                          | FLOAT                  |           4 |            |
 groupid                        | INT                    |           4 | TAG        |
 location                       | VARCHAR                |          24 | TAG        |
```

目标库结果：
```sql
taos> desc meters;
             field              |          type          |   length    |    note    |
=====================================================================================
 _ts                            | TIMESTAMP              |           8 |            |
 _current                       | FLOAT                  |           4 |            |
 _voltage                       | INT                    |           4 |            |
 _phase                         | FLOAT                  |           4 |            |
 _groupid                       | INT                    |           4 | TAG        |
 _location                      | VARCHAR                |          24 | TAG        |
```

### 8.4 `sparse` + 表重命名

与之前的行为保持一致，使用 `-T` 参数可以对表进行重命名：
```bash
taosx run \
  -f "taos:///db1?sparse" \
  -t "taos:///db3?assert" \
  -T rename-table:prefix:_
```

也可同时使用`remap`，表重名的同时进行列重命名 ：
```bash
taosx run \
  -f "taos:///db1?sparse" \
  -t "taos:///db3?assert&remap=@./tests/legacy/remap.csv" \
  -T rename-table:prefix:_
```
