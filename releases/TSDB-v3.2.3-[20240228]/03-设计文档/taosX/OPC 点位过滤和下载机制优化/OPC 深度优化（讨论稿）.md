## 一、CSV 模版文件校验

上传 csv 文件后，目前没有做任务校验，这些错误的 csv 文件在 data in task 执行过程中，会引起各种莫名其妙的错误，难以查错。所以在上传 csv 模版文件后，需要对该文件做完整性校验，避免后续的很多问题。
下面列举必要的校验规则，评审确定具体要实现哪些规则。
1. 文件编码错误
要求文件必须以 utf8bom 格式存储，否则无法正确解析。
兼容：utf8bom / utf8 ，内部做转码，检查gbk?
1. 空数据点位列表
文件中没有任何点位数据。
1. 字段必填规则：分为三类规则
   - 必填：必须存在，并且必填。包括 point_id、tbname 。
   - 可选:  可删除，如果保留则必须填写。包括 enabled、stable、value_col、quality_col、ts_col、received_ts_col 。
   - 可留空：可删除，保留可不填写。包括 type、value_transform、ts_transform、received_ts_transform。
2. 规则合法性
   - Transform val   (语法合法性校验)
   - 时间戳  Transform
   - 根据点位id，多行间可以重复
      - Tbname 可以不同
   - 不能有重复列
   - 不能有同名 tag 
   - 数据类型给出的值 在 int, float, double, varchar 范围内
   - 表名是否合法，表名不能包含 `.`, 参考官网规则
   - tag 列的定义是否合法，列名、类型 是否符合 TDengine 规范要求，写清楚具体的校验规则。
   - 同一超级表下的所有点位配置的字段名要保持一致：original_ts/received_ts/quatity。
   - 支持两个点位映射到同一个子表： Val 列必须不同，做到宽表的实现（需要开发验证）

## 三、数据类型 转换问题

问题来源：详见。
TD-28801

产品预期：通过 transform 后，数据能够转成设置的目标数据类型入库。比如源类型为 int, 经过 transform 规则`log(x) + 10` 对于输入值 25，能够转成目标类型数值 `11.39794` 。
目前实现现状，结果值被转成源类型`int`。
@杨志宇 @霍琳贺 请在此处整理解决方案。
**Option 1：**
目前的做法是先进行计算，可以改成先进行类型转换，再进行 Transform 计算。
Pros: 解决问题直接，Transform 规则不变
Cons: 这个结果不一定符合所有用户预期。
**Option 2:**
不修改代码的做法，将 Transform 规则对于类型转换的操作显式交给用户： `log(x.to_float()) + 10` vs `log(x.to_int()) + 10)`
Pros: 用户自定义转换、计算规则
Cons：Transform 规则复杂，学习成本增加
**建议：**
确认一个默认规则，并开放 Transform 中的可选类型转换。

讨论：
1. 在 Tranform 之后不转为原始类型，而是目标类型
2. 由用户对默认行为之外的类型转换操作进行处理，文档中应当解释默认的行为。
