### 1.3 优先级要求

License 独立控制直接影响到 2024 年的产品定价，因而在 2023-12-25 的版本规划会议上，提升为最高优先级。
预期在二月底的 3.1 和 3.2  版本发布。

### 1.4 版本要求

仅在企业版支持。

## 2. 需求目标

- 通过独立控制的 License，让授权机制更加灵活，进而支持多种产品定价策略
- 企业版所有功能通过单一授权码控制，包括 taosd、taosX 等各个组件
- 自动识别集群复制或硬件扩容导致的机器码变更，减少免费使用授权的可能性

## 3. 功能需求

采用状态机描述不同授权状态下的产品行为，约束各个授权状态之间转换条件。集群创建后自动进入未授权状态，然后在其他三种状态之间互相转换，覆盖新建集群、集群首次授权、集群授权过期、集群授权叠加、集群授权回收、复制集群、集群硬件变更这几种典型场景。

| 状态名称 | 产品行为 |
| --- | --- |
| 未授权状态 | 授权项有固定取值 |
| 已授权状态 | 授权项的取值来自于授权码，允许叠加多个授权码 |
| 授权过期状态 | 授权项有固定取值 |
| 授权回收状态 | 授权项有固定取值 |

不同授权状态下的产品行为通过授权项取值来描述，其中未授权状态、授权过期状态、授权回收状态下各授权项都有固定取值，已授权状态下各授权项取值来自于授权码，允许叠加多个授权码。在下表中，有如下简称
- CT（Create time）：集群创建时间、集群从老版本升级至新版本的时间，取最大值
- ET（Expire time）：集群进入授权过期状态的时间
- IET（Item expire time）：各授权项进入授权过期的时间
- RT（Revoke time）：集群进入授权回收状态的时间
- LV（Last value）：集群上次处于已授权状态时各授权项的取值，如果集群从未进入已授权状态，那么使用未授权状态的取值

### 3.1 授权码定义

| 需求编号 | **需求描述** | 研发确认 |
| --- | --- | --- |
| R101 | 企业版所有功能通过单一授权码控制，包括 taosd、taosX 等各个组件提供的基本功能和可选功能 | 确认 |
| R102 | 授权码生成时需要提供 clusterId，也可提供其他信息且被记录在授权码中 - 可选择是否提供机器码（1-3个）（用于弥补集群复制的漏洞） - 可选择是否提供上次授权码（交付人员有历史记录，用于弥补集群复制的漏洞） | 确认 |
| R103 | 授权码有两种类型 - 完整授权：在设置授权码操作时使用，必须设置所有的必选授权项 - 叠加授权：在叠加授权码操作时使用，包含任意数目的授权项 | 确认 |
| R104 | 授权码包含 encode / decode 的版本号，便于以后扩展解析、加密方法 | 确认 |
| R105 | 授权码包含生成时间、激活时限，以应对“必须在发放日期的 3 天之内使用，超过 3 天后失效”的需求，其中“激活时限”的默认值为 3 天 | 确认 |
| R106 | 授权码支持不检查硬件变更的选项，作为超融合需求的后门 注意：使用此类授权码的集群，可以随意复制，不会自动进入回收状态（可手动进入） | 确认 |
| R107 | 授权码的字符串内容只包含大小写字母和数字，不包含其他字符（涉及 base64 算法改造） | 确认 |
| R108 | 授权码的字符串长度不固定，随授权项数目不同而变化，完整授权的授权码很长，叠加授权则很短 | 确认 |
| R109 | 授权码的字符串内容不宜过长，通常不超过 1000 字节 | 确认 |
