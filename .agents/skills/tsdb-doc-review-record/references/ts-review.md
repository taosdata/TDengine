# 测试报告评审记录 (TS Review) 格式规范

## 文件命名与存放

- **文件名:** `YYYYMMDD {Feature Name} 测试报告评审记录.md`
- **目录:** `docs/releases/TSDB-v{version}-[YYYYMMDD]/09-会议纪要和评审记录/04-产品开发/03-功能测试/`

## 评审目的（固定用语）

```
评估 "{Feature Name}测试报告" 的合理性、安全性、性能、兼容性及可维护性
```

## 评审文档链接

链接指向 TS 文档，相对路径示例：
```
[{Feature Name} TS](../../../06-功能测试/Feature%20Name%20TS.md)
```

## 评审记录格式

### 结构

Section 2 **无子标题**，由 **1 个开头段落** 紧跟 **6 个编号段落** 组成。段落与编号列表之间无空行，编号项之间也无空行。

### 开头段落

```markdown
评审团队对测试文档（{Feature Name}功能测试相关）进行了全面审查，认为所有设计合理、内容详实、流程规范，具体评审意见如下：
```

### 六个编号段落

每一项以**固定短语**开头，冒号后接详细展开，整段不换行：

| 编号 | 开头短语 | 聚焦 |
|---|---|---|
| **1** | 测试目标明确 | 测试聚焦点、覆盖的功能维度、正常/异常场景定位 |
| **2** | 测试用例设计全面 | 用例数量、模块划分、覆盖场景清单 |
| **3** | 测试覆盖维度完整 | 功能覆盖/不支持范围覆盖/边界场景/回归覆盖等维度 |
| **4** | 测试方法规范 | 测试要点说明、正常/异常区分、过程中发现的问题及修正 |
| **5** | 测试结论数据充分 | 用例执行通过率、自动化覆盖状态、结论客观性 |
| **6** | 文档信息完整 | 修订记录、测试目标、参考文档、测试环境、测试结论等关键章节 |

### 示例

```markdown
## 2. 评审记录

评审团队对测试文档（XXX功能测试相关）进行了全面审查，认为所有设计合理、内容详实、流程规范，具体评审意见如下：
1. 测试目标明确：针对 XXX 功能开展专项测试，目标聚焦{测试聚焦描述}，同时覆盖{异常场景描述}，定位清晰、重点突出。
2. 测试用例设计全面：覆盖{模块描述}（{用例数量}条），{各模块概述}，用例设计科学合理、覆盖全面。
3. 测试覆盖维度完整：涵盖{覆盖维度描述}，测试严谨性强。
4. 测试方法规范：明确各功能模块测试要点，详细列出测试用例、测试描述及测试结果，清晰区分正常场景与异常场景的验证重点，{额外亮点}，测试流程规范，结果可验证、可追溯。
5. 测试结论数据充分：{通过率描述}，结论客观真实，具备参考价值。
6. 文档信息完整：包含{关键章节列表}，修订记录清晰，逻辑连贯、格式规范，便于后续查阅与维护。
```

**注意：** 编号项之间**不**留空行。开头段落与第一个编号项之间**不**留空行。

## 评审结论

固定措辞（除非评审未通过才修改）：

```
测试文档整体合格，符合测试文档规范要求，同意归档。
```

## 后续行动项

默认：`无`。若有行动项，使用编号列表并注明负责人。

## 与设计评审 (FS) 的关键差异

| 方面 | FS 评审 | TS 评审 |
|---|---|---|
| 评审目的用语 | "{Name} FS" 设计的合理性… | "{Name}测试报告" 的合理性… |
| 评审记录条数 | 4 条 | 6 条 |
| 开头段落 | "整体设计XXX、逻辑严谨、可落地性强" | "所有设计合理、内容详实、流程规范" |
| 评审结论 | 综合总结含特性关键词 | 固定句："测试文档整体合格，符合测试文档规范要求，同意归档。" |
| 关注维度 | 设计目标/功能设计/文档结构/安全兼容性能 | 测试目标/用例设计/覆盖维度/方法规范/结论数据/文档信息 |
