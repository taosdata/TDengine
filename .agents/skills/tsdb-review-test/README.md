# TDengine PR 测试质量审查技能使用说明

作者：beryl

## 简介

`SKILL.md` 定义了一个 Agent 技能，用于自动审查 TDengine PR 的测试用例质量。
给定一个 GitHub/GitLab PR URL 或 PR 号，技能会自动获取 PR diff，从三个维度
（测试存在性、描述质量、场景覆盖）对测试用例进行评分，并输出结构化审查报告。

---

## 前置条件

| 条件 | 说明 |
|------|------|
| `gh` CLI | 审查 GitHub PR 时需安装并完成 `gh auth login` |
| `glab` CLI | 审查 GitLab MR 时需安装并完成 `glab auth login` |
| 仓库访问权限 | 需要对目标仓库有读取权限 |

---

## 使用方法

在 Agent 对话中提供 PR URL 或 PR 号即可触发，例如：

```
帮我 review 这个 PR 的测试：https://github.com/taosdata/TDengine/pull/12345
```

```
给这个 PR 的 test-case 打分：https://github.com/taosdata/TDengine/pull/12345
```

```
检查 PR 12345 有没有测试覆盖（默认仓库 taosdata/TDengine）
```

---

## 技能执行流程

```
用户提供 PR URL / PR 号
        │
        ▼
① 解析 PR 信息 → 提取平台、仓库、PR 号
        │
        ▼
② 通过 gh / glab CLI 获取 PR diff 和文件列表
        │
        ▼
③ 维度一：存在性检查（0–30 分）
   识别测试文件 vs 功能实现文件
        │
        ▼
④ 维度二：描述质量检查（0–30 分）
   逐函数评估名称可读性、注释存在、描述完整性
        │
        ▼
⑤ 维度三：场景覆盖检查（0–40 分）
   提取 PR 功能场景 → 逐一判断测试覆盖状态
        │
        ▼
⑥ 综合打分，输出结构化审查报告 + 改进建议
```

---

## 评分规则总览

### 维度一：测试用例存在性（满分 30 分）

| 情况 | 得分 |
|------|------|
| 包含一个或多个新增测试文件 | 30 分 |
| 只修改了已有测试文件 | 20 分 |
| 无测试文件，但变更均为文档/配置/脚本 | 20 分（豁免） |
| 有功能实现代码却无任何测试文件 | 0 分 |

### 维度二：描述质量（满分 30 分）

对每个测试函数/类按以下权重打分，取均值映射到 30 分区间：

| 要素 | 权重 |
|------|------|
| 函数/类名可读性 | 40% |
| docstring / 注释存在 | 30% |
| 描述内容完整性 | 30% |

### 维度三：场景覆盖（满分 40 分）

```
覆盖率 = (已覆盖 × 1.0 + 部分覆盖 × 0.5) / 总场景数
维度得分 = round(覆盖率 × 40)
```

---

## 质量等级

| 总分 | 等级 |
|------|------|
| 90–100 | 优秀 ✅ |
| 70–89  | 良好 🟡 |
| 50–69  | 待改进 🟠 |
| 0–49   | 不合格 ❌ |

---

## 报告输出示例

技能最终输出包含：
- PR 基本信息（URL、标题、作者）
- 各维度得分及详细评价表格
- 功能场景与测试覆盖对应关系
- 综合总分和质量等级
- 可操作的改进建议

---

## 注意事项

- 本技能仅执行**只读**静态分析，不修改任何仓库文件，不运行任何测试代码
- 评分基于静态代码分析，不代表运行时的实际代码覆盖率
- 若 CLI 认证失败，技能会提示用户手动粘贴 PR diff 内容继续分析
