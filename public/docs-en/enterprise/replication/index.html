Data Replication

Introduction​

This section describes how to synchronize data between TDengine clusters using the taosX command line. The target side of the data synchronization function must be TDengine 3.0, and the source side can be TDengine 3.0 or 2.6. For command line arguments to taosX, see taosX. You can also use taos-explorer's visual interface for data synchronization, please refer to Visual Management. For service installation and deployment, please refer to Installation and Deployment.

TDengine 3.0 to TDengine 3.0​

Synchronizes stock and incremental data from the source cluster to the target cluster between two TDengine clusters of the same version (both 3.0.x.y).

The following parameters are supported in command line mode:​

NameDescriptionDefault
group.iddata subscription group IDgenerated by hash if empty
client.iddata subscription client IDtaosx
timeoutdata subscription timeout period; set to never to never time out.500ms
offsetdata subscription offset in format <vgroup_id>:. use commas to separate multiple vroups.starts at 0 if empty
tokentarget source parameter Used for authenticationNone

Examples​

taosx run \
  -f 'tmq://root:taosdata@localhost:6030/db1?group.id=taosx1&client.id=taosx&timeout=never&offset=2:10' \
  -t 'taos://root:taosdata@another.com:6030/db2'

TDengine 2.6 to TDengine 3.0​

Migrate data from a version 2.6 TDengine cluster to a version 3.0 TDengine cluster.

Command Line Parameters​

NameDescriptionDefault
libraryPathin option mode specify taos db pathNone
configDirspecify taos.cfg file pathNone
modeData source parameter history indicates historical data. realtime indicates real-time data. all indicates both historical and real-time data.history
restroData source parameter. Goes back a specified length of time to synchronize data before synchronizing real-time data. restro=10m indicates that real-time synchronization is initiated after backtracking the last 10 minutes of data.None
intervalData source parameter. Query interval, mode=realtime&interval=5s indicates 5 seconds between queriesNone
excursionData source parameter. Allow out-of-order data for a specified period500ms
stablesData source parameter. Only replicate specified supertables. Separate supertable names with commas.None
tablesData source parameter. Synchronize only the data of the specified sub-table, the table name format is {stable}. {table} or {table}, multiple table names are separated by comma , support @filepath to input a file, each line is regarded as a table name, such as tables=@. /tables.txt means from . /tables.txt means read each table name by line, empty lines will be ignored.None
select-from-stableData source parameter. Get select {columns} from stable where tbname in ({tbnames}), in this case tables use {stable}. {table} data format, e.g. meters.d0 means d0 sub-table under meters super table.Uses select * from table by default
assertTarget source parameter. taos:///db1?assert detects whether the database exists and creates it if notDoes not create databases by default
force-stmtTarget source parameter. Uses STMT mode ingestion when TDengine version is later than 3.0.raw block ingestion by default
batch-sizeTarget source parameter. Sets the maximum number of batch inserts in STMT write mode.
intervalTarget source parameter. Hibernation time after each write batch.None
max-sql-lengthTarget source parameter. Maximum length of the SQL used to build the table, in bytes.800_000 bytes by default
failes-toTarget source parameter Add this parameter with the value of the file path to write the table that was written incorrectly and the reason for the error to this file, and perform the synchronization task for other tables normally.Exit on error by default
timeout-per-tableTarget source parameter. Adds a timeout to a sub-table or normal table synchronization task.None
update-tagsTarget source parameter. Check whether the sub-table exists or not, if it does not exist, build the table normally, if it exists, check whether the labeled values are consistent or not, if they are not consistent, then update them.None

Examples​

Synchronizing data using native connections

taosx run \
  -f 'taos://td1:6030/db1?libraryPath=./libtaos.so.2.6.0.30&mode=all' \
  -t 'taos://td2:6030/db2?libraryPath=./libtaos.so.3.0.1.8&assert \
  -v
  1. Synchronizing data from the data super table stable1 and stable2 using WebSocket
taosx run \
  -f 'taos+ws://<username>:<password>@td1:6041/db1?stables=stable1,stable2' \
  -t 'taos+wss://td2:6041/db2?assert&token=<token> \
  -v
