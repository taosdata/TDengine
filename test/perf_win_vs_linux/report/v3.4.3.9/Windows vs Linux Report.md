## 3. 写入性能

工作负载：10 亿行 = 10000 子表 × 100000 行，8 线程，每请求 5000 行，共 4 轮（W1 `taosc` / W2 `stmt2` × 冷启动 / 热缓存）。每轮先 DROP + CREATE 数据库。

### 3.1 吞吐

| 轮次 | Windows real 口径 | Linux real 口径 | 倍数 |
|---|---|---|---|
| W1 冷启动（taosc） | 758,206 rows/s | **1,699,677 rows/s** | **2.24×** |
| W1 热缓存 | 755,343 rows/s | **1,670,939 rows/s** | 2.21× |
| W2 冷启动（stmt2） | — | **1,679,435 rows/s** | — |
| W2 热缓存 | 758,828 rows/s | **1,663,784 rows/s** | 2.19× |

冷/热差异两端都小于 2%，说明**写路径不受页缓存影响**，瓶颈在落盘环节。

### 3.2 延迟

| 指标 | Windows | Linux |
|---|---|---|
| W1 delay p90 / p95 | 7.98 / 24.93 ms | **6.22 / 6.50 ms** |
| W1 delay p99 / max | 1655.46 / 6726.10 ms | **790.80 / 4945.81 ms** |
| W2 delay p90 / p95 | 7.98 / 22.94 ms | **2.09 / 3.63 ms** |
| W2 delay p99 / max | 1781.44 / 6722.10 ms | **864.21 / 4625.57 ms** |

p95 差距尤为突出：Linux 在 6.5 ms 就收敛，Windows 的 p95 高达 24 ms。尾部延迟 Windows 明显更差，与下文 IO 粒度差异一致。

### 3.3 差异根因

先排除三个常见解释：

| 假设 | 判定 | 证据 |
|---|---|---|
| 写放大 | ❌ 排除 | 物理写入量几乎相同：Windows 38.49 GB / Linux 37.41 GB（数据集 34.2 GB，放大率 1.13× / 1.09×） |
| 磁盘物理速度 | ❌ 方向相反 | 裸盘顺序写 Windows 152 MB/s > Linux 102 MB/s（Windows 分区在盘外圈），若由磁盘主导 Windows 应领先 1.5×，实际落后 2.2× |
| CPU 瓶颈 | ❌ 排除 | taosd CPU 两端相同（0.35 vs 0.36 核） |

**为什么两块分区速度不一样**：盘片是圆的、转速固定（5400 转 = 每秒 90 圈）。外圈周长比内圈大，转一圈扫过的数据更多，所以同一块盘上外圈快、内圈慢，典型差 1.5–1.9 倍。`sda3` 在盘片中部到外圈，`sda5` 在最内圈，于是硬件上 Windows 占 1.5 倍便宜——但实测写入仍慢 2.2 倍。扣掉硬件优势后，软件差距粗算约 3.3 倍。

真实差异在 **IO 粒度**：

| 指标 | Windows | Linux | 倍数 |
|---|---|---|---|
| 累计 IO 次数 | **271,187** | **58,761** | Windows 4.6× |
| 平均每次 IO | **139 KB** | **622 KB** | Linux 4.5× |
| IOPS | 197.3 | 93.5 | — |
| 吞吐 | 26.7 MB/s | 56.8 MB/s | Linux 2.1× |
| 平均写服务时间 | 16.1 ms | 35.1 ms | — |
| 推算队列深度 | 3.2 | 3.3 | 相同 |
| 裸盘顺序写 | 152 MB/s | 102 MB/s | Windows 1.5× |
| **裸盘利用率** | **17.5%** | **55.7%** | — |

**机理**：5400 rpm 盘每转 11.1 ms。139 KB 的纯传输时间只有约 0.9 ms（按 1.69 MB/转），但实测每次写要花 16.1 ms——**约 94% 的时间在等旋转/寻道**，而不是在传数据。Linux 每次搬 622 KB，把同样的固定开销摊薄 4.5 倍，因此即使磁盘本身更慢，净吞吐仍高 2.1×。

两端模型均自洽：

- Windows：139 KB ÷ 16.1 ms × 3.2 并发 ≈ 27.6 MB/s ≈ 实测 26.7
- Linux：622 KB ÷ 35.1 ms × 3.3 并发 ≈ 58.5 MB/s ≈ 实测 56.8

> **尚未证实的部分**：Windows 为何产生 4.6 倍更小、更多的 IO。候选机制包括（a）POSIX `writev` 散射聚集写 vs Windows 无等价接口、（b）NTFS 元数据日志产生的小 IO、（c）块层合并窗口差异。现有数据只能证明相关性，需下列实验进一步区分：
>
> 1. **IO 粒度扫描（决定性）**：在两块分区上用相同参数直接写 `bs = 4/16/64/128/256/512/1024K`（`dd ... oflag=direct conv=fdatasync`）。若两端均在 128K→512K 出现 2 倍级跃升，则瓶颈是盘的旋转摊销、OS 差异只决定"谁合并得更多"；若仅 Windows 在小 bs 下崩溃，则是其存储栈的合并策略问题。
> 2. **IO 来源归属**：Windows 用 ETW/`xperf` 抓写窗口，区分 taosd 发出的小写与 NTFS 日志产生的小写；Linux 用 `blktrace` 做同样统计。
> 3. **放大块验证**：调大落盘批量化参数（`STT_TRIGGER`、`MINROWS/MAXROWS`、WAL 刷盘批次）后，Windows 的 IO 粒度能否接近 Linux？能则问题在 TDengine 的 Windows IO 路径，不能则在 NTFS/驱动层。

## 4. 查询性能

数据：同一份 10 亿行热数据集，客户端与服务端同机。

| 编号 | SQL | 线程 | 次数 | Windows | Linux | 快慢比 |
|---|---|---|---|---|---|---|
| Q1 | `select * from meters` | 1 | 3 | 95.04 s | **92.82 s** | 1.02× |
| Q2 | `select count(*) from meters` | 1 | 20 | 72.92 ms | **54.96 ms** | **1.33×** |
| Q3 | `select last(*),tbname from meters group by tbname` | 1 | 20 | 150.68 ms | **96.81 ms** | **1.56×** |
| Q4 | `select count(*) from meters interval(1m)` | 1 | 3 | 1210.40 ms | **1027.76 ms** | **1.18×** |
| Q5 | `select * from meters` | 8 | 3 | 490.35 s/轮 | **341.83 s/轮** | **1.43×** |

延迟分布：

| 编号 | Windows p90 / p99 | Linux p90 / p99 |
|---|---|---|
| Q1 | 97.85 s / 97.85 s | **92.85 s / 92.85 s** |
| Q2 | 82.66 / 83.78 ms | **60.19 / 79.46 ms** |
| Q3 | 158.58 / 159.25 ms | **107.91 / 108.16 ms** |
| Q4 | 1452.34 / 1452.34 ms | **1047.91 / 1047.91 ms** |
| Q5 | 616.49 s / 642.85 s | **370.70 s / 378.58 s** |

**分析**

1. **小结果集查询**（Q2/Q3/Q4）Linux 领先 1.18–1.56×。其中 Q3（逐 10000 个子表取末行）差距最大，属真实遍历开销差异。
2. **超大结果集单线程**（Q1）两端基本持平（1.02×）。Q1 需回传 10 亿行，瓶颈在结果集序列化 + loopback 传输，与文件系统和存储引擎关系不大——这正是两个完全不同的操作系统能跑出几乎相同时间的原因。**该指标不应用于衡量存储引擎能力。**
3. **多线程投影**（Q5）Linux 快 1.43×，且并行扩展性差异显著：

   | | 单线程 | 8 线程每轮 | 等效单次 | 加速比 |
   |---|---|---|---|---|
   | Windows | 95.04 s | 490.35 s | 61.3 s | **1.55×** |
   | Linux | 92.82 s | 341.83 s | 42.7 s | **2.17×** |

4. `count(*)` 走元数据（Q2 仅 55–73 ms），`count(*) interval(1m)` 需真实扫描（Q4 约 1.0–1.2 s），两者区分度良好。

## 5. 资源占用

**整体结论：完成相同的写入 + 查询任务，Windows 消耗的资源明显更多，Linux 更省。**

| 维度 | 谁更省 | 差距 |
|---|---|---|
| CPU（折算单位工作量） | **Linux** | Windows 多耗 **1.5–1.6×** |
| 磁盘 IO 次数 | **Linux** | Windows 用 **4.6×** 的 IO 搬运同样字节 |
| 内存占用 | 写入阶段 Windows 高 11%；查询阶段基本持平 | 11% / 约 0 |
| 线程数 | 基本持平 | 207 vs 202 |

> ⚠️ **最容易看错的地方**：绝对 CPU 数值 Windows 反而更低（写入 1.20 核 vs Linux 1.68 核），但这只是因为 Windows 每秒只完成一半的写入量。**折算到单位工作量后，结论完全反转——Windows 多耗 1.5–1.6 倍 CPU。**

| 场景 | Windows | Linux | Windows 多耗 |
|---|---|---|---|
| 写入：每 1 M rows/s 消耗 CPU | 1.20 ÷ 0.758 = **1.58 核** | 1.68 ÷ 1.700 = **0.99 核** | **1.60×** |
| Q1 单轮 CPU·秒 | 1.59 × 95.04 = 151.1 | 1.05 × 92.82 = 97.5 | **1.55×** |
| Q5 单轮 CPU·秒 | 9.85 × 490.35 = 4830 | 8.68 × 341.83 = 2967 | **1.63×** |

**一句话**：同样的活，Windows 要多花一半以上的 CPU、多打 4.6 倍的磁盘 IO，内存也略高——**慢的代价同时体现在时间和资源两端**。

**要点**

- **taosd CPU 绝对值两端相同（0.35 vs 0.36 核）**：说明写入瓶颈不在计算能力，而在 IO 提交方式（按单位工作量折算后 Windows 多耗 1.5–1.6×，见本章开头）。
- **客户端 CPU：Linux 反而更高**（W1 1.32 vs 0.85 核）。这不是缺陷——Linux 的客户端没有被 fsync 阻塞，能更密集地提交；Windows 客户端大部分时间在等待 IO 完成。**该指标必须结合吞吐看，绝对值无意义。**
- **RSS：Windows 略高**（1950 vs 1756 MB，+11%），W2 更明显（2011 vs 1813 MB，+11%）。
- **IO 粒度是最大差异**：622 KB vs 139 KB，直接决定了 2.1× 的吞吐差。
- **写延迟绝对值 Linux 更高**（35.1 vs 16.1 ms），但每次 IO 搬的数据多 4.5 倍，单位数据的等待成本反而更低。

## 6. 口径与已知偏差

1. **冷启动**：重启 taosd 并清空页缓存。Linux 写 `/proc/sys/vm/drop_caches`；Windows 无官方等价接口，仅重启服务，冷的程度弱于 Linux。因写入不受页缓存影响、查询只测热数据，该偏差对结论无实质影响。
2. **热缓存**：不做清理，紧接冷启动轮次执行。
3. **查询**：仅在最后一份热数据上执行，不区分冷热。
4. **吞吐**：同时给出 bench 自报口径与 real 端到端口径，本文均采用 real 口径。
5. **CPU**：Linux 取 `/proc/<pid>/stat` 前後差分除以墙钟；Windows 取 typeperf `Process\% Processor Time` 均值（单核 100%，可超 100%）换算为核数。两端均 2 s 采样。
6. **磁盘**：Linux 取 `/proc/diskstats` 整盘计数；Windows 取承载数据目录的 `PhysicalDisk` 实例（`0 C: F:`）。均为整盘口径，含其他进程。
7. **分区几何差异**：同一块盘，`sda3` 位于盘片中部到外圈、`sda5` 位于最内圈，外圈线速度高，裸盘性能 Windows 侧高约 1.5×。这是**固定的硬件偏差，方向对 Windows 有利**——即 Windows 的实测结果已偏乐观，扣掉此优势后软件差距更大（粗算约 3.3×）。
8. **CPU 调频**：两端均为出厂默认（平衡 / powersave），未锁定频率。
9. **Windows 写入数据来源**：来自改造前的手工采集流程，工作负载与配置与 `main.py` 完全一致，但未经同一脚本产出。如需完全对称，可在 Windows 上补跑 `--only writes`（约 90 分钟）。

## 7. 复现方式

```bash
# Linux：写入 4 轮 + 查询（约 60 分钟）
python3 script/main.py --skip-install --only all --tag linux_q1

# Windows：查询（约 35 分钟）
python script\main.py --skip-install --only queries --tag win_q1

# 生成单平台报告（含跨平台对比章节）
python3 script/report.py results/linux_q1/result.json report/linux_q1.md results/win_q1/result.json

# 若采样器有缺陷，可从原始 CSV 重算聚合指标而无需重跑
python3 script/recompute.py results/linux_q1/result.json
```

数据来源：全部由 `script/main.py` 单入口采集，原始输出落在 `results/<tag>/`（每次运行生成，不入库）；Windows 写入轮次沿用改造前手工采集的 typeperf 采样。
