# Skill：Lemon → goyacc 语法迁移专家

## Skill 名称

lemon_to_goyacc_migration

---

# 🎯 Skill 目标

本 Skill 用于将 `lemon` 目录中的 C 语法实现完整迁移至 Go + goyacc，要求：

- 行为完全一致
- 语义完全一致
- 优先级与结合性完全一致
- 错误处理完全一致
- AST 构建顺序完全一致
- 分支覆盖率 100%
- 严禁凭感觉或经验臆造实现

该 Skill 适用于**解析器级别迁移工程**，强调行为复制而非重写优化。

---

# 🔴 核心原则

## 1️⃣ Lemon 是唯一真理来源

- `lemon` 目录中的 C 实现是唯一权威实现
- 永远不允许修改 `lemon` 目录内容
- Go 实现必须严格对齐 Lemon 行为
- 若行为不一致，必须修改 Go，而不是调整 Lemon

---

## 2️⃣ 禁止猜测原则

在修改任何 Go 代码之前：

- 必须先查看 Lemon 中对应实现
- 必须确认其行为逻辑
- 必须确认 reduce 动作

如果找不到对应实现：

- 立即停止
- 输出缺失点
- 请求补充 C 实现
- 严禁自行补写逻辑

---

## 3️⃣ 小步迁移原则

迁移必须：

- 按模块分批进行
- 每次只改一个子语法
- 每次修改都必须加测试
- 每次修改 `.y` 文件后必须运行 goyacc

---

# 📌 适用范围

本 Skill 可操作：

- lexer.go
- td_sql.y
- parser 相关 Go 文件
- AST 构建代码
- 单元测试
- 构建逻辑

本 Skill 禁止：

- 修改 lemon 目录
- 删除非项目文件
- 自创语法规则
- 简化 reduce 动作

---

# 🟡 执行流程

---

## 第一阶段：Lexer 对齐

### 步骤

1. 查看 Lemon 的词法实现
2. 提取：
   - token 类型
   - 关键字匹配逻辑
   - 大小写规则
   - 字符串转义规则
   - 数字解析规则
   - 注释处理逻辑
3. 对齐 `lexer.go`
4. 添加测试

### 测试要求

- 所有 token 类型覆盖
- 正常路径覆盖
- 错误路径覆盖
- 边界输入覆盖
- 极端输入覆盖

---

## 第二阶段：语法规则迁移

### 迁移顺序建议

1. 基础表达式
2. 运算符优先级
3. 函数调用
4. SELECT
5. INSERT
6. UPDATE
7. DELETE
8. 子查询
9. 特殊语法结构

---

### 每次修改 td_sql.y 必须执行：

1. 修改规则
2. 运行 goyacc
3. 检查：
   - 是否存在 shift/reduce 冲突
   - 是否存在 reduce/reduce 冲突
4. 若冲突：
   - 回到 Lemon 查优先级定义
   - 对齐 `%left` `%right` `%nonassoc`
5. 再次生成并验证

---

## 第三阶段：语义动作对齐

对每个 reduce 动作：

必须确认：

- AST 构建顺序
- 子节点插入顺序
- 错误触发时机
- NULL 处理逻辑
- 默认值处理逻辑

禁止：

- 重排逻辑顺序
- 合并多个动作
- 改变执行副作用

---

# 🟢 测试体系设计

## 测试层级

### 词法层

- Token 序列精确对比

### 语法层

- AST 结构对比
- 优先级对比
- 嵌套结构对比

### 错误路径

- 错误类型一致
- 错误位置一致
- 错误触发条件一致

---

## 分支覆盖要求

- 所有语法规则至少触发一次
- 所有 reduce 分支触发
- 所有错误分支触发
- 所有边界条件触发

---

# 🟣 冲突处理策略

当出现：

- goyacc 冲突
- 行为差异
- AST 差异

必须：

1. 回到 Lemon
2. 找优先级定义
3. 找 reduce 顺序
4. 找触发条件
5. 再修改 Go 实现

禁止：

- 调整规则顺序“试试看”
- 随意改变优先级
- 用经验判断

---

# 🔵 一致性验证策略（推荐）

可建立双解析验证机制：

1. Lemon C 版本解析
2. Go goyacc 版本解析
3. AST 序列化
4. JSON 对比结构

若存在差异：

- 必须修正 Go 实现
