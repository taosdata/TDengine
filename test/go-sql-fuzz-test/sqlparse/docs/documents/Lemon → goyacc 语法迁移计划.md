# Lemon → goyacc 语法迁移计划

## 迁移阶段划分

### 1. 词法对齐阶段

**输入**：
- Lemon C 词法定义（lemon/sql.y 中的 token 定义）
- 当前 Go 词法分析器（lexer.go）

**输出**：
- 与 Lemon 完全对齐的 Go 词法分析器
- 词法测试用例

**执行步骤**：
1. 提取 Lemon 中的所有 token 定义
2. 对比当前 Go 词法分析器的 token 定义
3. 补充缺失的 token
4. 确保 token 类型和行为完全一致
5. 实现缺失的词法规则

**验证方式**：
- 运行词法测试用例
- 确保所有 token 都能正确识别

**失败处理策略**：
- 若发现 token 行为不一致，回溯 Lemon 实现
- 若发现缺失的 token 定义，补充实现

### 2. 基础语法迁移阶段

**输入**：
- Lemon 基础语法规则
- 当前 Go 语法文件（td_sql.y）

**输出**：
- 迁移后的基础语法规则
- 基础语法测试用例

**执行步骤**：
1. 提取 Lemon 中的基础语法规则
2. 按照相同的结构迁移到 Go 语法文件
3. 确保语法结构完全一致
4. 实现基础语义动作

**验证方式**：
- 运行 goyacc 生成解析器
- 检查是否有语法冲突
- 运行基础语法测试用例

**失败处理策略**：
- 若发现语法冲突，回溯 Lemon 实现
- 若发现语义动作不一致，修正实现

### 3. 运算符优先级对齐阶段

**输入**：
- Lemon 运算符优先级定义
- 当前 Go 语法文件中的优先级定义

**输出**：
- 与 Lemon 完全对齐的运算符优先级
- 运算符优先级测试用例

**执行步骤**：
1. 提取 Lemon 中的运算符优先级定义（%left, %right, %nonassoc）
2. 对比当前 Go 语法文件中的优先级定义
3. 调整优先级顺序和结合性，确保完全一致

**验证方式**：
- 运行 goyacc 生成解析器
- 检查是否有优先级冲突
- 运行运算符优先级测试用例

**失败处理策略**：
- 若发现优先级冲突，严格按照 Lemon 定义修正
- 若发现结合性不一致，调整为与 Lemon 一致

### 4. 复杂语法迁移阶段

**输入**：
- Lemon 复杂语法规则
- 当前 Go 语法文件

**输出**：
- 迁移后的复杂语法规则
- 复杂语法测试用例

**执行步骤**：
1. 提取 Lemon 中的复杂语法规则（如 SELECT、JOIN、子查询等）
2. 按照相同的结构迁移到 Go 语法文件
3. 确保语法结构和语义动作完全一致
4. 实现复杂语义动作

**验证方式**：
- 运行 goyacc 生成解析器
- 检查是否有语法冲突
- 运行复杂语法测试用例

**失败处理策略**：
- 若发现语法冲突，回溯 Lemon 实现
- 若发现语义动作不一致，修正实现

### 5. 语义动作对齐阶段

**输入**：

**输出**：
- 与 Lemon 完全对齐的语义动作
- 语义动作测试用例

**执行步骤**：
1. 提取 Lemon 中的所有语义动作

3. 修正不一致的语义动作
4. 确保 AST 构建顺序完全一致

**验证方式**：
- 运行语义动作测试用例

**失败处理策略**：

### 6. 错误处理对齐阶段

3. 修正不一致的错误处理逻辑

**验证方式**：

**失败处理策略**：
- 若发现错误处理不一致，回溯 Lemon 实现
- 若发现错误代码或消息不一致，修正实现

### 7. 全量一致性验证阶段

**输入**：
- 所有迁移后的代码

**输出**：
- 验证报告
- 修复后的代码（若有）

**执行步骤**：
1. 运行完整的测试用例集
2. 对比 Lemon 和 Go 解析结果
3. 对比 AST 序列化结果
4. 确保分支覆盖率 100%

**验证方式**：
- 运行所有测试用例
- 检查覆盖率报告
- 手动验证复杂 SQL 语句

**失败处理策略**：
- 若发现不一致，回溯到对应阶段修正
- 若发现覆盖率不足，补充测试用例

## 每次修改规则

1. **修改粒度**：一次只处理一个子语法规则
2. **生成验证**：修改 td_sql.y 后必须运行 goyacc 生成解析器
3. **冲突检查**：必须检查是否有语法冲突
4. **测试补充**：必须添加对应的测试用例
5. **回溯验证**：测试失败必须回溯 Lemon 实现

## 冲突处理策略

当 goyacc 出现冲突时：

1. **Shift/Reduce 冲突**：
   - 回到 Lemon 查优先级定义
   - 对齐 `%left`、`%right`、`%nonassoc` 定义
   - 重新运行 goyacc
   - 重新测试

2. **Reduce/Reduce 冲突**：
   - 回到 Lemon 查语法规则定义
   - 确保语法规则结构完全一致
   - 重新运行 goyacc
   - 重新测试

## 一致性验证机制

1. **Lemon 解析结果**：
   - 运行 Lemon 解析器解析测试用例
   - 记录解析结果和 AST 结构

2. **Go 解析结果**：
   - 运行 Go 解析器解析相同的测试用例
   - 记录解析结果和 AST 结构

3. **AST 序列化对比**：
   - 序列化两个 AST 结构
   - 逐字段对比
   - 确保完全一致

若存在差异：
- 必须修改 Go 实现，确保与 Lemon 一致

## 风险控制

### 常见迁移风险点
- Token 定义不一致
- 运算符优先级不一致
- 语义动作实现差异
- 错误处理行为差异

### 优先级陷阱
- 运算符优先级顺序错误
- 结合性定义错误
- 优先级冲突处理错误

### Reduce 顺序陷阱
- 语法规则顺序错误
- 语义动作执行顺序错误
- AST 构建顺序错误

### 错误恢复差异风险
- 错误处理逻辑不一致
- 错误代码定义不一致
- 错误消息格式不一致

### Token 行为差异风险
- Token 识别规则不一致
- Token 类型定义不一致
- 特殊字符处理不一致

## 完成标准

1. **行为完全一致**：与 Lemon C 实现的行为完全一致
2. **语义动作完全一致**：语义动作实现和执行顺序完全一致
3. **优先级与结合性完全一致**：运算符优先级和结合性完全一致
4. **错误处理完全一致**：错误处理逻辑和错误消息完全一致
5. **AST 构建顺序完全一致**：AST 结构和构建顺序完全一致
6. **分支覆盖率 100%**：所有语法分支和语义动作都有测试覆盖
7. **goyacc 无冲突**：生成的解析器无语法冲突
8. **不修改 lemon 目录**：保持 Lemon 实现不变
