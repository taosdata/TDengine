# Deploy Case Docs — Design Spec

**Date:** 2026-03-26  
**Project:** taosx  
**Reference:** [TDengine deploy-case-docs.yml](https://github.com/taosdata/TDengine/blob/main/.github/workflows/deploy-case-docs.yml)

---

## Problem Statement

The taosx project has three categories of test cases spread across different directories and languages:

- **Python E2E tests** — `tests/e2e/test_function/*_test.py`
- **Playwright TypeScript tests** — `explorer/tests/*.spec.ts`
- **Rust integration tests** — `tests/integration/**/*.rs`

There is an existing basic workflow (`publish_mkdocs.yaml`) that deploys e2e test docs on push to `main`, but it:
- Only covers Python e2e tests
- Uses `mkdocs gh-deploy --force` (single version, no branch versioning)
- Has no automated markdown generation (docs are static/pre-generated)
- Does not trigger on PR merge

The goal is a proper, versioned, automatically-updated test case documentation site — consistent with the TDengine project's approach.

---

## Approach

Adapt the TDengine `deploy-case-docs.yml` workflow for taosx, covering all three test types with a unified Python generate script. Use `mike` for per-branch versioned docs on `gh-pages`.

---

## Components

### 1. `.github/workflows/deploy-case-docs.yml`

A new GitHub Actions workflow file (does not replace `publish_mkdocs.yaml`).

**Triggers:**
- `workflow_dispatch` (manual trigger for testing)
- `pull_request` to `main` (types: `[closed]`) when these paths change:
  - `tests/e2e/test_function/*_test.py`
  - `explorer/tests/*.spec.ts`
  - `tests/integration/**/*.rs`

**Condition:** Only runs when PR is merged (`github.event.pull_request.merged == true`) or triggered manually.

**Job: `generate_and_deploy`**
- `runs-on: ubuntu-latest`
- `permissions: contents: write`

**Steps:**
1. Checkout with `fetch-depth: 0`
2. Set up Python 3.9
3. `pip install mkdocs mkdocs-material mike mkdocstrings[python]`
4. Determine `BRANCH_NAME` from PR base ref or `github.ref_name`
5. Run `.github/scripts/generate_case_md.py` — generates/updates all markdown files and `mkdocs.yml` nav
6. Configure git identity (`GitHub Actions` / `actions@github.com`)
7. `cd tests/e2e && mike deploy --push $BRANCH_NAME --config-file mkdocs.yml --branch gh-pages --allow-empty`

### 2. `.github/scripts/generate_case_md.py`

New Python script. Scans all three test directories and generates plain markdown files.

**Python E2E tests** (`tests/e2e/test_function/*_test.py`):
- Uses `ast` module to parse each file
- Extracts all functions starting with `test_` that have a docstring
- Generates `tests/e2e/docs/e2e_test_cases/<module_name>.md`
- Each test function renders as: `## test_function_name\n\n<docstring>`

**Playwright TypeScript tests** (`explorer/tests/*.spec.ts`):
- Uses regex to extract `test.describe('...', ...)` and `test('...', ...)` blocks
- Captures any leading `//` comment block above each test as description
- Generates `tests/e2e/docs/playwright_test_cases/<file_stem>.md`
- Format: `## describe title > test title\n\n<comment if any>`

**Rust integration tests** (`tests/integration/**/*.rs`):
- Uses regex to extract `#[test]` / `#[tokio::test]` attributed functions
- Captures preceding `///` doc comment lines as description
- Generates `tests/e2e/docs/integration_test_cases/<module_name>.md`
- Format: `## test_function_name\n\n<doc comment if any>`

**Nav generation:**
- Reads existing `tests/e2e/mkdocs.yml`
- Rebuilds the `nav:` section with three top-level categories:
  - `E2E Test Cases` → list of e2e_test_cases/*.md entries
  - `Playwright Test Cases` → list of playwright_test_cases/*.md entries
  - `Integration Test Cases` → list of integration_test_cases/*.md entries
- Writes updated `mkdocs.yml` back

### 3. `tests/e2e/mkdocs.yml` (updated)

Add:
- `nav:` section (auto-managed by generate script)
- `mike` versioning plugin

```yaml
site_name: TaosX Cases Docs
theme:
  name: "material"

plugins:
  - search
  - mkdocstrings
  - mike

nav:
  - Home: index.md
  # ... auto-generated by generate_case_md.py
```

---

## Data Flow

```
PR merged to main
  → workflow triggers
  → checkout repo
  → run generate_case_md.py
      → scan tests/e2e/test_function/*.py    → docs/e2e_test_cases/
      → scan explorer/tests/*.spec.ts         → docs/playwright_test_cases/
      → scan tests/integration/**/*.rs        → docs/integration_test_cases/
      → update mkdocs.yml nav
  → mike deploy --push main
      → builds MkDocs site
      → pushes versioned site to gh-pages
```

---

## Error Handling

- Script prints warnings for files that fail to parse but continues processing
- If a test file has no docstrings/comments, the markdown page still lists test names (with no description)
- `mike deploy --allow-empty` ensures deployment succeeds even if no markdown changed
- Git fetch of `gh-pages` uses `|| true` to handle first-run when branch doesn't exist yet

---

## Testing

- The workflow includes `workflow_dispatch` so it can be run manually to verify the full pipeline
- The generate script can be run locally: `python .github/scripts/generate_case_md.py`
- MkDocs can be previewed locally: `cd tests/e2e && mkdocs serve`

---

## Out of Scope

- Shell test files (taosx has no `*.sh` test cases unlike TDengine)
- Utils documentation (no `new_test_framework/utils/` equivalent)
- Replacing the existing `publish_mkdocs.yaml` workflow
