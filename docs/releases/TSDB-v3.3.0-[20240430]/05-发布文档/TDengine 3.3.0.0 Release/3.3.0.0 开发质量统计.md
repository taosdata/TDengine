# 3.3.0.0 开发质量统计

前言：Bug 数量不能完全等同于开发质量，毕竟各个特性的复杂度不同、紧急程度不同，质量有多方面的原因。但 Bug 数量作为一个最直观且唯一可以量化的维度，还是有它的统计意义。本文中统计出了**每位开发人员按特性**在 3.3.0.0 版本在测试组的内部验证中发现的**阻塞性 Bug 数量、有效 Bug 数量和待优化项的数量**。目的是督促每位开发人员加强自测环节、尽可能减少初级或基础问题、提升下游环节的效率，从而使我们有更多测试资源投放在复杂场景测试、兼容性测试、压力测试和性能测试上，最终起到提升发布质量的目的。
