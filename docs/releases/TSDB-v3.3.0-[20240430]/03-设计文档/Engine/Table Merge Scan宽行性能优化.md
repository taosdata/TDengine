# Table Merge Scan宽行性能优化

## 1. 背景

TD-26207 提出了 table merge scan 宽行性能优化的任务。根据任务要求，引入新算法：当数据行多且查询数据列长度较长时，初始形成多路数据后，排序中只使用时间戳和待排序数据行的 ID，最后输出时，再根据行 ID 输出最初的数据。

## 4. 行为说明

缺省情况下不使用此算法, 只有以下条件满足时, 使用新算法
- 当查询数据列长度大于等于256字节，
- 没有limit，
- 没有查询提示 smalldata_ts_sort() 时
第一条 SQL中, 如果三列长度之和大于等于256, 使用新算法. 第二条SQL使用smalldata_ts_sort禁用新算法
```json
select col1, col2, col3 from super_table order by ts [desc]
select /*+ smalldata_ts_sort() */ col1, col2, col3 from super_table order by ts [desc]
```

## 5. 性能

数据行数少于千万时，性能有可能比不使用提示降低. 此时可以使用smalldata_ts_sort()，禁用新算法。
新旧算法对比, 参考性能测试报告[TD-26207 开发性能测试报告](https://taosdata.feishu.cn/wiki/MQQfwvhYviY9H2kO3JWctwE3n43)

#### 10.0.1 附录

- 新算法具体实现如下
  - 读取数据块，进行最初的多路归并。当累积的数据块到512MB时，生成由行构成的实际数据文件和由TS+行ID构成的索引块，新成一路数据。直至数据块读完，形成多路数据。
  - 排序中，只使用索引块。如果多层归并排序，每一层排序时，只涉及索引块的读写
  - 最后，根据行ID，去数据文件找到数据行输出至下游算子
