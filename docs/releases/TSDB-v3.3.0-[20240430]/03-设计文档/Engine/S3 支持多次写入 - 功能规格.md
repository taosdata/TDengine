# S3 支持多次写入 - 功能规格

## 1. 背景

在 3.2.3.0 及以前版本中，在最后一级存储中的 data 文件上传到 S3 存储之后，将无法再次写入对应时间段的时序数据，所以对于多级存储最后一级的历史数据只能导入一次。如果需要二次写入，要手动把相应的 data 文件下载到本地磁盘存储，由于 data 文件通常比较大，这个过程不能自动完成，且操作较为繁琐。
[需求文档](https://taosdata.feishu.cn/wiki/HBUqwXZIGiZZ1ukzE4zcpxCanlf) 3.2 节中提出了多次写入的需求，并且在 [需求文档修订版](https://taosdata.feishu.cn/wiki/RFYOwfYq9ibw69k1YeocVE2BnXe) 3.1 节中重新整理细化了相关的周边需求，主要是在 DB 级别多级存储与 S3 功能不再耦合，也就是 S3 功能不再依赖多级存储，可以独立使用，这样就需要把部分参数和命令从多级存储模块平移到 S3 模块，本次优化将通过完成 [TD-28945](https://jira.taosdata.com:18080/browse/TD-28945) 来支持 [需求文档修订版](https://taosdata.feishu.cn/wiki/RFYOwfYq9ibw69k1YeocVE2BnXe) 3.1 中的需求。

## 3. 定义

S3 对象存储：一种可扩展的，高可用的分布式存储系统，能够存储大量的非结构化数据对象。

## 4. 行为说明

### 4.1 配置参数

#### 4.1.1 DB 参数

##### 4.1.1.1 s3_keeplocal

数据在本地保留的天数，即 data 文件在本地磁盘保留多长时间后可以上传到 S3。缺省值为 365 天，取值范围 [1, 365000]，且必须大于或等于3倍的 duration 参数值。可以使用加单位的表示形式，如 S3_KEEPLOCAL 100h、S3_KEEPLOCAL 10d 等，支持 m（分钟）、h（小时）和 d（天）三个单位。也可以不写单位，如 S3_KEEPLOCAL 50，此时默认单位为天。

##### 4.1.1.2 s3_chunkpages

上传对象的大小阈值，与 tsdb_pagesize 参数均不可修改，单位为 TSDB 页，只能配置为数字；缺省值为 262144 页，最小值为 131072 页，最大值 1048576 页。

##### 4.1.1.3 s3_compact

首次上传 S3 时，是否 compact 文件组。缺省值为 1，取值范围为 [0, 1]。
0：表示首次上传不 compact。w
1：表示首次上传 compact。
在触发 s3 数据上传流程时，会首先检查 data 文件是否进行过 compact 操作，如果没有并且 s3_compact 参数值为 1，则发起本文件组的 compact 操作，下次触发 s3 数据上传时会直接进行上传操作。

##### 4.1.1.4 使用 DB 参数示例

下面分别是创建正确及错误的例子：
```sql
taos> create database db duration 1d s3_chunkpages 32768 s3_keeplocal 3d s3_compact 1;

Create OK, 0 row(s) affected (2.220857s)
taos> create database db duration 1d s3_chunkpages 32768 s3_keeplocal 2d s3_compact 1;

DB error: Invalid parameters, should be s3_keeplocal >= 3 * duration (0.000615s)
taos> create database db vgroups 1 duration 1d s3_chunkpages 32767 s3_keeplocal 3d s3_compact 1;

DB error: Invalid option s3_chunkpages: 32767 valid range: [32768, 1048576] (0.001414s)
taos> create database db vgroups 1 duration 1d s3_chunkpages 32768 s3_keeplocal 3d s3_compact 2;

DB error: Invalid option s3_compact: 2 valid range: [0, 1] (0.000758s)
```

当 duration 与 s3_keeplocal 参数值不符合约束关系时，会返回一个 DB error 提示信息。各个参数均会进行范围检查, 如果用户提供的参数不正确，会提示正确的参数范围。

#### 4.1.2 新增 dnode 配置参数

s3MigrateIntervalSec
本地数据文件上传 S3 的触发周期，单位为秒，只能配置为数字；缺省值为 3600 秒（1 小时），最小值为 600 秒，最大值 100000 秒。
手动触发 SQL 命令：s3migrate database <db_name>;
s3MigrateEnabled
是否自动进行 S3 迁移，缺省值为 0，表示默认情况下不进行自动 S3 迁移；如果配置为 1，则可以开启 S3 自动迁移。
原有的配置参数 s3EndPoint, s3AccessKey, s3BucketName, s3PageCacheSize, s3UploadDelaySec 保持不变；s3BlockSize s3BlockCacheSize 不再使用。
下面三个是必须配置的：

| # | 参数 | 示例值 | 描述 |
| --- | --- | --- | --- |
| 1 | s3EndPoint | http://cos.ap-beijing.myqcloud.com | 用户所在地域的 S3 服务域名 |
| 2 | s3AccessKey | AKIDsQm6JRRSJ:lIdoy99yg0yumSm1E | 冒号分隔的用户 SecretId:SecretKey |
| 3 | s3BucketName | test0711-1309024725 | 存储桶名称，减号后面是 COS 服务的 AppId |

下面两个和新增的两个参数是可选的：

| # | 参数 | 默认值 | 最小值 | 最大值 | 描述 |
| --- | --- | --- | --- | --- | --- |
| 1 | s3UploadDelaySec | 60 | 1 | 2592000 (30天） | data 文件 1 分钟不再变动后上传至 S3，单位：秒 |
| 2 | s3PageCacheSize | 4096 | 4 | 1024*1024*1024 | s3 page cache 缓存页数目，单位：tsdb 页 |

##### 4.1.2.1 配置参数可用性检查

为 taosd 程序增加 --checks3 参数，如果执行成功，返回当前节点所配置 S3 的 bucket 列表；执行失败时，执行过程中的错误信息会实时输出在终端。

### 4.2 写入

在 3.2.3.0 及以前的版本中，数据文件上传到 S3 后，再写入对应文件相关的数据（相当于过期数据）会在 TSDB 落盘的过程中被忽略，即不支持写入过期数据。在本次优化后，数据文件上传到 S3 后，依然可以对其所对应的时间范围进行写入（即写入过期数据），且不影响落盘、merge 及 compact 等流程。**从用户视角看，写入行为对用户全透明，用户可以在任意时刻写入任意时间范围的数据，无论是否配置了 S3，也无论所对应的数据文件是否上传了 S3**。

### 4.3 查询

缓存部分的逻辑保持不变，涉及 S3 部分的数据，将会根据数据的位置计算所在的文件块及块内偏移，涉及多个文件块的查询将在读取数据时自动切换不同的文件块。**查询行为对用户全透明**，**无论是否配置了 S3，也无论所对应的数据文件是否上传了 S3。**

### 4.4 数据上传

数据上传以文件块为基本单元，文件块的大小为 s3_chunkpages * tsdb_pagesize，默认值情况下，为 1G 字节。文件块的大小在创建 DB 时确定，后面不可修改。
S3 数据迁移流程中会检查每组数据的大小，如果超过文件块 1G 字节，比如 1.2 G，会将这部分数据拆分为多个文件块，比如第一部分 1G，第二部分 0.2G，然后将 1G 的文件块发送到 S3 存储中，剩余的 0.2G 数据保留在本地磁盘。**即从按文件上传改为按文件块上传，此行为对用户透明**。

### 4.5 数据删除

#### 4.5.1 过期数据

优化前，所有过期的 data 文件会从 S3 存储中删除；优化后，所有过期的文件块会从 S3 存储中删除。**即从按整个文件删除修改为按文件块删除，此行为对用户透明**。

#### 4.5.2 显式删除

删除某个 DB 时，优化前，会把 S3 存储中所有相关 data 文件删除；优化后，会把 S3 存储中所有相关文件块删除。超级表及子表的删除是元数据操作，目前实现与 TSDB 无关，所以也与本优化无关。

### 4.6 运维操作

| # | 名称 | 支持情况 |
| --- | --- | --- |
| 1 | alter replica | 支持 |
| 2 | redistribute | 支持 |
| 3 | compact | 支持 |
| 4 | split | 暂不支持 |

优化后，由于支持多次写入，所以之前由于无法二次写入导致的使用限制将不存在；vgroup 操作, split 操作与优化前一样，暂不支持。其它操作如 DB 的副本变更，增加或减少副本数量, redistribute, compact 均支持。

### 4.7 微软 Blob 存储

#### 4.7.1 授权

企业版中，Blob 功能需要 S3 授权项。

#### 4.7.2 使用

用户界面同 S3，不同的地方在于下面三个参数的配置：

| # | 参数 | 示例值 | 描述 |
| --- | --- | --- | --- |
| 1 | s3EndPoint | [https://fd2d01c73.blob.core.windows.net](https://fd2d01c73.blob.core.windows.net) | Blob URL |
| 2 | s3AccessKey | fd2d01c73:veUy/iRBeWaI2YAerl+AStw6PPqg== | 冒号分隔的用户 accountId:accountKey |
| 3 | s3BucketName | test-container | Container name |

其中 fd2d01c73 是账户 ID；微软 Blob 存储服务只支持 Https 协议，不支持 Http。
accountKey 的配置请参考：[S3 API for Azure Blob Storage (Flexify.IO)](https://taosdata.feishu.cn/wiki/Hq9dw8BIpiZRhGkHXdMcNQiYncd)

## 5. 性能

1. 对写入性能基本没有影响，与 S3 功能开启前性能保持一致。
2. 由于 head, sma, tomb, stt 等文件存储在本地，不需要访问 data 文件的聚合类查询性能不受影响。
3. 需要访问 S3 数据的查询性能可以配置合适的 s3PageCacheSize 参数，默认配置情况下，会有 16 M 的缓存数据，可以根据连续发起同一个查询两次的响应时间，判断缓存是否合适。
4. 跨文件块的查询，需要对两个相邻文件块分别进行数据请求，相比优化前会多出一次 HTTP 请求的性能损耗。

## 6. 兼容性

S3 部分的数据，与之前版本不再兼容，必须使用新的存储方式。

## 7. 运维

除 S3 相关参数的配置外，无其它运维操作。

## 8. 使用场景

一次或多次批量导入历史数据。

## 9. 约束和限制

#### 9.0.1 约束变更

优化后，与多级存储功能解耦，S3 功能不再依赖多级存储，可以独立使用。

#### 9.0.2 限制

暂不支持 split vgroup 命令。
优化后下面的使用限制删除：
~~Data 文件上传到 S3 之后，继续写入对应时间段的数据，会在落盘时作为过期数据处理。为避免数据丢失，需要在 data 文件上传之前，flush database 或写入下一个时间段足够的数据，保证当前时间段的数据均已落盘（上传 S3 之前）。~~
~~如果要补写历史数据或进行 compact 操作，需要手动将文件下载到本地之后进行。~~
