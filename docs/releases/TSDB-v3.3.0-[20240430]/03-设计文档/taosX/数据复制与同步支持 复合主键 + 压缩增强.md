# 数据复制与同步支持 复合主键 + 压缩增强

## 1. 背景

根据新版本开发计划 [3.2.4.0 开发计划追踪](https://taosdata.feishu.cn/wiki/U4KbwxWBii31aJkNRuYcL43RnAh)，TDengine 新增[复合主键](https://taosdata.feishu.cn/wiki/OLQjwCpQhiRFE3kS8Uvc3sornRb) 和 [TDengine 压缩增强](https://taosdata.feishu.cn/wiki/St4WwSX5Ei3VfMk3yMUcv2DMnMh)功能，其中涉及到表结构语法的变更和部分 SQL 语句返回格式的修改，对 taosX 和 Explorer 适配提出了相应要求。根据讨论确定，新版本版本号应为 3.3.0.0，且新版本数据格式不兼容旧版本（无法回退），故本文档仅涉及 taosX 在 TDengine 新版本（3.3.0.0）到 TDengine 新版本（3.3.0.0）同步数据过程中 taosx 需要修改的内容。

## 4. 行为说明

### 4.1 基于订阅的 TD3 数据源

对于 taosX 版本 >= 1.6.0 :

| 数据源版本 | 目标版本 | 是否支持 | 行为 |
| --- | --- | --- | --- |
| >=3.3.0.0 | <3.3.0.0 | 不支持 | 创建任务时报错 |
| >=3.3.0.0 | >=3.3.0.0 | 支持 | 正常同步 |
| <3.3.0.0 | any | 支持 | 正常同步 |

### 4.2 基于查询的 TD3 数据源

对于 taosX 版本 >= 1.6.0 :

| 数据源版本 | 目标版本 | 是否支持 | 行为 |
| --- | --- | --- | --- |
| >=3.3.0.0 | <3.3.0.0 | 不支持 | 创建任务时报错 |
| >=3.3.0.0 | >=3.3.0.0 | 支持 | 正常同步 |
| <3.3.0.0 | any | 支持 | 正常同步 |

### 4.3 数据备份恢复

taosX 数据备份格式是透明的，依赖于 TDengine 的版本兼容性，因此，新版本数据备份文件不可恢复到旧版本。对此 taosX 应更新备份文件版本号，以对备份文件版本进行检查，在备份恢复任务创建时检查版本合法性，即：新版备份数据文件不可恢复到旧版本 TDengine，详见 4.3.2 节。

#### 4.3.1 备份文件格式变更

taosx 的备份文件使用两位版本号 `x.y` 进行标记，1.5.0 之前完全兼容，版本号为 0.0 。为保证文件格式解析时的正确性和可扩展性，将文件格式进行扩展：
- 从 taosx 1.6.0 版本开始，文件格式版本号从 0.0 升级为 1.0。
- taosx 版本号 （1.6.0）和 TDengine 版本号（3.3.0.0）写入备份文件头（文件格式版本之后）。
- taosX 读取时，检查 taosx 版本号和 TDengine版本号兼容性

#### 4.3.2 数据恢复时的版本检查

为便于解释，将版本兼容列表如下：

| 文件格式 | 备份 taosx 版本 | 备份 TDengine 版本 | 恢复 taosx 版本 | 恢复 TDengine 版本 | 行为 |
| --- | --- | --- | --- | --- | --- |
| 0.0 | 无 | 无 | any | >=3.0 | 正常 |
| 1.0 | >=1.6.0 | <3.3.0.0 | <1.6.0 | >=3.0 | 数据文件版本较新，请使用新版本 taosX 进行数据恢复。 |
| 1.0 | >=1.6.0 | <3.3.0.0 | >=1.6.0 | >=3.0 | 正常 |
| 1.0 | >=1.6.0 | >=3.3.0.0 | >=1.6.0 | <3.3.0.0 | 不支持新版本备份文件恢复到旧的 TDengine 版本 |
| 1.0 | >=1.6.0 | >=3.3.0.0 | >=1.6.0 | >=3.3.0.0 | 正常 |

## 6. 性能

在自动建表频率高的场景中，因为增加了 DESCRIBE 请求，可能会发生性能降低的情况，但对大部分场景无影响。

## 7. 兼容性

以下行为将报错（在创建任务时进行版本兼容性检查，不符合则报错）：
1. 从 3.3 版本订阅或查询方式同步数据写入 3.2/3.1/3.0
2. 从 3.3 版本生成的备份文件恢复到 3.2/3.1/3.

## 12. 附录：实现说明

为保证新版本向新版本订阅并写入的功能不被破坏，taosX 的适配包括：

### 12.1 订阅接口

`tmq_get_json_data` 创建表数据结构里增加列是否是复合主键的参数（"isPrimaryKey":**true**）。其相应的 Rust API 应进行同步。

### 12.2 DESCRIBE 接口

鉴于 API 中 TAOS_FIELD 结构不再能够完整反应建表语句，同步过程中出现的自动建表情况，均应修改为通过 DESCRIBE 结果进行 SCHEMA 重建。这也意味着使用 TAOS_FIELD 进行 SCHEMA 重建的所有 taosx API 应当在新版废弃。
旧版本 DESCRIBE 格式如下：
```sql
taos> desc information_schema.ins_databases;
             field              |          type          |   length    |        note        |
=============================================================================================
 name                           | VARCHAR                |          64 |                    |
 create_time                    | TIMESTAMP              |           8 |                    |
 vgroups                        | INT                    |           4 |                    |

```

新版本 DESCRIBE 格式如下：
```sql
taos> describe stbname;
         field          |      type      |   length |  note |encode  | compression  |
=====================================================================================
 _ts                    | TIMESTAMP      |        8 |       |  RLE   | gzip, medium |
 c0                     | BOOL           |        1 |       |  XOR   | disabled     |
 t0                     | NCHAR          |        2 | TAG   |disabled| disabled     |
Query OK, 3 row(s) in set (0.004352s)
```

复合主键的表示形式如下：
对于如下 SQL：
```sql
CREATE TABLE t (
     ts TIMESTAMP,
     obj_id VARCHAR(64) PRIMARY KEY,
     data1 FLOAT,
     data2 int
 );
```

DESCRIBE 结果如下：
```sql
taos> desc t;
             field              |          type          |   length    |        note        |     encode     |    compress    |     level      |
================================================================================================================================================
 ts                             | TIMESTAMP              |           8 |                    | delta-i        | lz4            | medium         |
 obj_id                         | VARCHAR                |          64 | PRIMARY KEY        | disabled       | lz4            | medium         |
 data1                          | FLOAT                  |           4 |                    | delta-d        | lz4            | medium         |
 data2                          | INT                    |           4 |                    | simple8b       | lz4            | medium         |
```
