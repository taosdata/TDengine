# TDengine 复合主键 Test Spec

## 1. 测试目标

- TDengine支持通过复合主键实现重复时间戳功能，用户在创建普通表或超级表时，可以通过关键字 PRIMARY KEY 额外指定一列，与时间戳列共同组成复合主
- 复合主键实现不会影响其他原有功能
- 插入和查询性能出指定的性能目标外，其他性能测试项目完成摸底测试

| 测试项目 | 测试结论 | 备注 |

| 删除功能 | 测试通过 |  |
| 订阅功能 | 测试通过 |  |
| 流计算功能 | 测试通过 | spec有所变更，窗口目前仅支持 interval 和 session，其它 window 建流按照报错处理； 1. 性能： - 无乱序场景下，有 PK 和无 PK 列的写入性能及流计算性能相当，有 PK 列时内存消耗较多； 1. 乱序 50% 场景下，写入 QPS 下降了 33 %，因乱序带来大量重算，流的 latency 升高了 143%，CPU 资源占用有小幅上涨； |
| 性能测试 | 测试通过 | 1. 本次属于摸底测试，写入性能下降幅度在10%以内，查询性能在部分复杂SQL场景有14%到24%的性能下降，详情请见：[性能测试用例](https://taosdata.feishu.cn/wiki/P3BxwbkZciCNL0k41d3cKsQJnzf) 1. 配置复合主键后，相同的查询，在查询过程中内存资源消耗峰值有明显的上升趋势，幅度在3到4倍 1. 流计算：无乱序场景下，有 PK 和无 PK 列的写入性能及流计算性能相当，有 PK 列时内存消耗较多；乱序 50% 场景下，写入 QPS 下降了 33 %，因乱序带来大量重算，流的 latency 升高了 143%，CPU 资源占用有小幅上涨 |
