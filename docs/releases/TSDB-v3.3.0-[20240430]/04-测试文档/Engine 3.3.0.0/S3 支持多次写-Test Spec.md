# S3 支持多次写-Test Spec

## 1. 测试目标

目前 S3 功能本次是第三轮迭代，前两轮迭代始终未能解决补录历史数据的问题，这次迭代后即可彻底解决历史数据补录问题。
该文档对此改进功能进行全面测试，功能需求文档为： [S3 支持多次写入 - 功能规格](https://taosdata.feishu.cn/wiki/Nvd1wb8iKiw2z6kNhSAcJh9ansb)

## 3. 测试范围

测试范围如下：
- 可无限次历史数据补录
- 数据正确性验证（正常写入及补录历史数据）
- 新增配置参数验证
- 运维功能验证
- 上传 S3 断网下处置正确性
- 异常测试

## 4. 测试结论

功能符合预期，测试通过，遗留有1个内存泄露的问题，不严重，不影响功能通过。
写入性能与未配置 S3 相同
数据迁移至 S3 及查询主要依赖于带宽，在千兆局域网带宽下测试，需要从S3上拉数据的查询与未配置 S3下查询慢一倍左右，不需要从S3 上获取数据的聚合查询性能基本一样。

### 9.2 兼容性

- 与原有 S3 功能不兼容
    已在使用以前版本 S3 功能的，本次修改后完全不兼容，需重新建库
- 一旦使用不可回退
     一旦启用 S3 功能，不可再回退至非 S3 状态，只能使用导出备份再新建集群导入来
- 对订阅及流计算支持

### 9.3 性能

- 写入速度
   写入都在本地，所以写入速度预期和不使用S3相当
- 查询速度
    查询速度主要取决于网络下载速度，本次改进对一个文件进行了强制分块儿，存在跨块访问的性能损耗，预期略逊于与上一版
- 上传速度
 基于分块，一个文件上传分为若干次，预期相同带宽情况下上传速度略逊于上一版。同时本次暂不支持断点续。
- 性能测试步骤
1. 创建3节集群3副数据库
2. 创建1个超级表，全类型普通列及TAG
3. 生成子 表50 个，每个子表20万数据
4. taosBenchmark 写入数据, 记录写入时间
5. 记录DATA 文件在本地时各SQL 查询耗时
6. 配置 S3 参数，重启服务，开始 S3 上传
7. 使用网络监控记录数据开始上传时间
8. 使用网络监控记录数据上传结束时间
9. 确认数据都已上传及上传大小与在本地时数据大小做核实
10. 记录本地及S3 上数据文件大小
11. 开始查询测试，记录时间
