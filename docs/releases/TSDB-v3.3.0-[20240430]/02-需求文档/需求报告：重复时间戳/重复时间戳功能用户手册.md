# 重复时间戳功能用户手册

本文是根据《[重复时间戳的处理](https://taosdata.feishu.cn/docx/VA6gdU0KDoYWYrxsSU1cyBAvnnd) 》所提出的方案而编写的重复时间戳功能用户手册，从用户感知角度描述此功能。
1. DDL语句变更
   - CREATE TABLE 语句增加UNIQUE列约束
    ```sql
     CREATE TABLE [IF NOT EXISTS] [db_name.]tb_name (create_definition [, create_definitionn] ...)
        [TAGS (create_definition [, create_definitionn] ...)]
        [table_options]
    
    create_definition:
        col_name column_definition
     
    column_definition:
        type_name [comment 'string_value'] [UNIQUE]
    ```

      - 使用 UNIQUE 约束的表只能定义在纳秒精度的数据库下。如不满足则建表时会报错。
      - UNIQUE 约束的列只能为整数类型，且要求此列的值在一毫秒内用10^6取模后是唯一的。
      - 此表中存储的数据的有效业务精度实际为毫秒，即用户在查询使用时，只会使用毫秒级别的过滤条件、窗口间隔等时间精度相关的值。
   - DESC 语句返回的note列的内容增加 UNIQUE。仅在表创建时指定了 UNIQUE 约束时才会显示。
   - SHOW CREATE TABLE/STABLE 语句返回的建表语句中增加 UNIQUE 约束。仅在表创建时指定了 UNIQUE 约束时才会显示。
1. 写入
   - 写入语法没有变化。
   - 写入列必须同时包含时间戳列和 UNIQUE 列，且用户要提供正确的 UNIQUE 列的值。
   - 对于时间戳列和 UNIQUE 列同时相等的数据，认为是修改操作，会覆盖之前的数据。
2. 查询
   - 查询语法没有变化。
   - 数据查询的有效精度是毫秒，查询语句的支持情况等同于毫秒库。
3. 使用限制总结
   - 用户的数据模型中，必须存在一个一毫秒内用10^6取模后是唯一的整形列。
   - 用户的业务精度为毫秒，没有微秒和纳秒级别的需求。
