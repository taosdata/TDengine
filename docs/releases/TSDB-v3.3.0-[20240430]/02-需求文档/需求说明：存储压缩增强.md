## 2. 需求目标

很多客户在选型时考虑总拥有成本，其中磁盘开销的占比很高。存储压缩算法增强后，TDengine 的压缩比预期可再提升一倍以上。本需求将集成更多主流的压缩算法到 TDengine，在用户选型和 POC 过程中，可以有更多选择。

| 需求目标 | 重要性 | 其他 |
| --- | --- | --- |
| 提升一级压缩 | 次要 | 可不开发 |
| 提升二级压缩 | 重要 | 压缩效果已得到验证，需要开发 |
| 增加三级压缩 | 中等 | 视压缩效果决定是否开发 |

## 3. 功能需求

### 3.1 扩展一级压缩

第一级压缩支持多种编码方法，建议 SQL 语法如下
```sql
CREATE TABLE t (
    ts TIMESTAMP ENCODE 'Simple8B',
    i int ENCODE 'XOR',
    j float ENCODE 'RLE',
    k varchar(20) ENCODE 'disabled'
    ……
);
```


| 需求编号 | **需求描述** | 研发确认 |
| --- | --- | --- |
| R101 | 在现有 Simple8B 基础上增加至少一种编码方法，参照[竞品文档](https://bbs.huaweicloud.com/blogs/314775)，例如 XOR、RTE | 第二期，调研后再开发 |
| R102 | 支持为每个数据列指定单独的编码算法，各数据类型有不同的默认编码方法 | 第二期，调研后再开发 |
| R103 | 支持修改数据列的编码算法（*在每个 BLOCK 头部记录所使用的编码方法，自适应解码*） | 第二期，调研后再开发 |

### 3.2 扩展二级压缩

第二级压缩支持多种压缩算法，建议 SQL 语法如下
```sql
CREATE TABLE t (
    ts TIMESTAMP COMPRESS 'lz4' Level 'high',
    i int COMPRESS 'gzip' Level 'high',
    j float COMPRESS 'tsz' Level 'medium',
    k bigint COMPRESS 'xz' Level 'low',
    m BLOB COMPRESS 'disabled',
    ……
);
```


| 需求编号 | 研发确认 |
| --- | --- |
| lz4 | 第一期开发（已有） |
| disabled(无压缩) | 第一期开发（优先级中） |
| zlib | 第一期开发（优先级高） |
| zstd | 第一期开发（优先级高） |
| tsz | 第一期开发（优先级低） |
| xz | 第一期开发（优先级低） |
| 更多其他压缩算法 | 第二期开发 |
| R202 | 第一期开发 |
| R203 | 第二期开发 |
| R204 | 第一期开发 |

### 3.3 增加三级压缩

研发第三级压缩功能，考虑把数据文件拆分多个子块后对子块压缩，并在 COMPACT 过程中同步进行。建议 SQL 语法如下
```sql {wrap}
COMPACT VGROUP 2 COMPRESS 'lz4' RANGE(ts1, ts2); 
COMPACT DATABASE d1 COMPRESS 'gzip' BLOCK '100MB';
COMPACT DATABASE d2 COMPRESS 'disabled';
```


| 需求编号 | **需求描述** | 研发确认 |
| --- | --- | --- |
| R301 | 支持通过 SQL 语句进行第三级压缩： 1. 可以指定采用的压缩算法（支持多种压缩算法，例如 zstd、snappy 等） 1. 可以指定压缩块大小，在查询量较小时，用来提高解压速度、缩小解压范围 1. 可以指定压缩时间段，与该时间范围产生交集的数据文件都被压缩 1. 可以指定被压缩的数据库名和 VGroup 编号 | 第二期调研后再开发 |
| R302 | 数据查询时如果需要解压数据，占用的最大磁盘空间和数据目录可配置 | 第二期调研后再开发 |
| R303 | 与数据重整类似，第三级压缩时不能阻塞数据写入 | 第二期调研后再开发 |
