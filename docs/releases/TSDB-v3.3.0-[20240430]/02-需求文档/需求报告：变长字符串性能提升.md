# 需求报告：变长字符串性能提升

## 一、需求描述

随着 VARCHAR 定义长度增加，数据写入速度会有下降，网络曲线抖动明显，CPU、内存消耗明显升高，磁盘占用率越来越高。期望在写入完全相同字符串时，写入性能和网络带宽随建模长度的增长而基本不变。

## 二、意向用户

字符串写入需求特别常见，但无必须使用此功能的用户。本功能实现后，可以提高产品能力、降低用户建模难度。

## 三、用户场景

以告警信息为例，字符串内容大多为空，或只有很少的字符，但极限情况却可能很长。在交付、售前给用户数据建模时，经常的问题是：“请问您能不能将 VARCHAR(1024) 修改为 VARCHAR(16)”。针对这个问题，给测试组提出了测试需求 [[测试需求] 变长字符串性能](https://taosdata.feishu.cn/wiki/TkmswFTFsivvd4kJ6kIc2QwJned) ，形成了阶段测试报告：[[Test Report] TS-4054 变长字符串性能](https://taosdata.feishu.cn/wiki/SIXiwSVdqiu8mgkf3k8cNElsn5b) 
此现象在 VARCHAR、NCHAR、VARBINARY 数据类型中同时存在，猜测原因如下
- 建模长度对网络带宽影响巨大，猜测在网络传输过程没有压缩
- 写入速度下降明显，猜测 tsdb 侧内存占用没有优化
