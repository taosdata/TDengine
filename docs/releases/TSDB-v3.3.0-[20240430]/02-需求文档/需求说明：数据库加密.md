# 需求说明：数据库加密

## 1. 引言

### 1.1 术语与缩写名词

| 名词 | 描述 |
| --- | --- |
| 透明加密 | 1. 在数据库层执行静态数据加密，阻止可能的攻击者绕过数据库直接从文件系统读取敏感信息 1. 数据库内数据的加密和解密，对数据库的访问程序是完全无感知的，应用系统不需要做任何修改和编译，就能够直接应用到加密库上 1. Oracle、MySQL、PostgreSQL、SQL Server、达梦、瀚高都支持透明加密 |
| 非透明加密 | 1. 读写数据时调用系统函数对数据进行加解密，需要用户自主完成，用户在每次访问时提供密钥 1. 可以保证个人私密数据不被包括 DBA 在内的其他人获取 1. Oracle、MySQL、PostgreSQL、SQL Server、达梦、瀚高都支持非透明加密 |
| 半透明加密 | 1. 为用户设置独立的加密密钥，不同用户向数据列中写入数据时，使用各自的密钥加密数据 1. 用户仅可以看到自己写入的数据，而看不到其他用户的数据 1. 仅达梦支持半透明加密 |
| 传输加密 | 1. 一般指使用 TLS 协议支持客户端和服务器之间的加密连接，在建立连接、数据传输的多个阶段有效 1. Oracle、MySQL、PostgreSQL、SQL Server、达梦、瀚高都支持传输加密 |
| 数据脱敏 | 1. 给定脱敏规则和策略的情况下，对敏感数据比如手机号、银行卡号等信息进行转换或者修改，防止敏感数据在不可靠的环境下使用 1. 部分数据库提供数据脱敏的规则配置，可以归类于用户权限控制，不属于数据库加密 |

## 2. 需求目标

`数据库加密功能目的是满足信创、国产化项目的招标需求，不必过于关注加密后的数据库性能。`

## 3. 功能来源

### 3.1 透明加密功能

在透明数据加密 (TDE) 中，密钥管理、加密范围是两个最重要的话题。为了简化实现，提出如下实现思路，将密钥存储在授权码（License Code）中，而不是存储在第三方管理器中
1. 当使用 TDE 时，需要用户提供设备的机器码
2. 交付人员将密钥作为一个特殊的授权项，并使用用户提供的机器码生成授权码
3. 将加密算法、加密范围、授权码作为配置项，在 taosd 配置文件中设置 
4. taosd 启动时，将机器码、密钥从授权码中取出，如果设备的机器码发生变更，我们认为取出密钥的过程错误，taosd 的启动过程将被终止，并报告“由于机器码发生变更，无法获取密钥”的错误
5. taosd 启动后，使用解析后的密钥，按照配置的加密算法，在写入数据时加密数据，在读取数据时解密数据
根据开发难度，可选择如下加密范围
1. WAL 文件：加密每条 WAL 记录
2. Mnode 数据文件：通常小于 10MB，写入/读取是对整个文件进行的，可对整个文件加密
3. TSDB 数据文件：包括 data、stt 文件 ，加密每个 BLOCK
4. TDB 数据文件（Meta）：难度可能较大
如何测试
1. 使用 VI 工具，打开二进制文件，查看文件中是否有明文

### 3.2 非透明加密功能

参照 MySQL、达梦数据库，提供加密函数、解密函数，仅作用在 VARBINARY 字段，建议语法如下
```sql {wrap}
CREATE TABLE t (ts timestamp, data varbinary(32));
INSERT INTO t VALUES (1, ENCRYPT('明文数据', 'DES', 'Key')）；
SELECT ts， DECRYPT(data, 'DES', 'Key') from t;
```


| 需求编号 | **需求描述** | 研发确认 |

| R202 | 在 SQL 语句中支持 to_base64 和 from_base64 函数，便于查看密文（优先级较低，可不做） |  |

### 3.3 半透明加密功能

参照 [达梦半透明加密](https://blog.csdn.net/juracka/article/details/113522660) 功能，由于暂不开发，所以不再提要求。

### 3.4 传输加密功能

参照 MySQL、达梦数据库，建议采用 TLS 协议，用以支持客户端和服务器之间的加密连接，配置参数如下
- 服务器配置参数
```sql {wrap}
ssl_ca=ca.pem
ssl_cert=server-cert.pem
ssl_key=server-key.pem
```

- 客户端配置参数
```sql {wrap}
ssl_ca=ca.pem
ssl_cert=server-cert.pem
ssl_key=server-key.pem
require_secure_transport=ON
```

- 其中
  - ssl_ca：证书颁发机构 (CA) 证书文件的路径名
  - ssl_cert：服务器公钥证书文件的路径名
  - ssl_key：服务器私钥文件的路径名
