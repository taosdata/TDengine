## 2. 需求目标

对于字符串类型的普通列（有别于标签列），包括 varchar、nchar、varbinary，以及未来可能开发的 blob、json，当写入完全相同的数据时，各性能指标只与实际数据长度有关而与建模长度无关。

## 3. 功能需求

无

### 5.2 测试需求

#### 5.2.1 测试参数

| 类别 | 明细 |
| --- | --- |
| 测试环境 | - 不需特殊的硬件环境，两台普通的 2 核 4GB 内存机器即可 - 操作系统应为常见 Linux，例如 Ubuntu 2004 |
| 数据库参数 | - vgroups 为 1 - last 内存设置为 16K，表示字符串长度为 8 时，last 缓存全部在内存（不需 LRU 换入换出） - 其他参数默认 - taosd 和 taosc 不打开任何模块的日志 |
| 写入模式 | - 可使用 taosBenchmark 测试，native 方式写入 - 写入程序和 taosd 部署在不同机器上 - 线程数目为客户端机器核数的 2 倍 - Interlace 和 batch 模式都需要测试 |
| 查询模式 | - 查询时等待数据写入完成后进行 - 使用多线程查询，线程数目为客户端机器核数的 2 倍，每个线程进行 5 轮查询 - 投影查询读取超级表全部数据，读取结果不写磁盘 - Last 查询采用 group by 读取每个子表的最新数据，读取结果不写磁盘 |
| 压缩比 | 使用 flush database 命令之后，统计磁盘文件大小 |
| 数据规模 | - 1000 个子表 - 每子表 100,000 条记录 |
| 超级表标签列 | 1 个标签列，类型为 int32，递增 |
| 超级表数据列 | 2 个数据列，类型 timestamp，第二列参加具体测试场景 - timestamp 列：从 T 开始，每行增加 1 秒作为基准值 |
