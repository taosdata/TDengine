# 需求报告：重复时间戳

### 1. 背景

目前在金融场景(华锐金融)、工业场景(通力电梯)中，均存在重复时间戳的问题：在同一时刻有多个相同时间戳的记录需要存入TD，需要对这些记录进行统计、计算。
在金融行业中，每个股票、债券行情逐笔委托、逐笔成交记录，默认时间戳精度为ms。但每支股票、债券可能在同一时间有多条记录。目前已知同一毫秒最大的笔数为超过100万。
金融场景中，每条记录一般都有单调递增序号字段，该序号每天重置；工业场景中，则没有该序号字段。
同时，在对时间戳进行区间时间段的比较运算时，金融行业多采用“左开右闭”方式，即：ts > start and ts <= end。在进行重复时间戳方案设计时需考虑到业务应用场景，无需用户修改现有业务代码。

### 2. 客户功能需求

1. 同一张子表、普通表，允许写入相同的时间戳
2. 同一时刻(ms)允许写入不少于200万条相同时间戳的记录
3. 用户可选择重复时间戳精度：ms、s。毫秒、秒为已知客户需求
4. 按时间戳排序时，同一时间戳后写入的时间戳位列先写入的时间戳之后，或序号大的记录位列序号小的时间戳之后（2023-12-21：无法保证顺序，需要通过 Order by 语句实现）
5. 对时间戳进行比较运算时，无需应用修改代码即可支持“左开右闭”、“左闭右开”、“左开右开”、“左闭右闭”等情形

### 3. 引申需求

1. 企业版专属功能
2. 支持聚合类函数(count...)，需返回对所有符合条件的记录进行聚合计算的结果，相同时间戳的记录分别统计
3. 支持选择类函数(first/last/last_row...)，需返回符合条件的记录：同一时间戳后写入的时间戳位列先写入的时间戳之后，或序号大的记录位列序号小的时间戳之后
4. 支持时序特有函数(csum/twa...)，需返回符合函数定义的结果
5. 针对时间戳的distinct函数需返回不重复的时间戳，去除重复值
6. 支持TDengine子句、UDF，包括未来将实现的LEFT JOIN、ASOF JOIN、Window JOIN等
7. 支持流计算。重复时间戳的记录应被当做独立的记录进行处理
8. 支持数据订阅。重复时间戳的记录应被当做独立的记录进行处理

### 4. 性能需求

写入、查询重复时间戳的性能，与基准版本相比性能不得低于80%
