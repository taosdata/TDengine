# S3-2 性能测试报告(腾讯云) 

## 一、目的

     S3 存储的优势是空间大，存储成本低，所以我们把 TDengine 多级存储中最后一级存储内的数据存放在 S3 上，可以极大降低用户的存储成本。

## 二、实现原理

    在 TDengine 存储文件中，.data 文件存放时序数据，占用空间最大，所以仅把多级存储中最后一级中的 .data 文件存储在 S3 上，其它小文件仍然原地不动，这样即简化了功能实现，又降低了存储成本。
    当配置了 S3 存储后，多级存储中第二级向第三级迁移时，.data 文件会移动至 S3, 本地存储空间将被释放出来。
    当查询引擎需要获取 S3 上的数据时，上个版本中设计的下载数据所在的整个 DATA，修改为只下载 DATA 文件中需要的数据部分，即所谓按需下载模式，提高单次查询的响应速度。

## 三、测试说明 

###       1、写入速度

        因为多级存储中咱们约定是不允许在第三级上写入数据的，数据写入只发生在第一级和第二级上，第一级与第二级的写入都是本地磁盘，所以写入性能与原来一样。

### 2、查询速度分类

  1）查询时间范围只在第一级和第二级上的查询速度与原来一致
  2）查询时间范围包括第三级上的数据时，查询时间 = 原来的查询时间 + 下载 DATA 中需要下载数据部分的时间

## 五、性能总结        

###      1、本次改进整体效果比上一版要好

      除全部都下载的场景性能差不多外，小范围查询及点查效果非常明显。使用在 S3 上的数据查询多为小范围的拉取数据，所以这种模式更贴近用户真实使用场景 。

###      2、配置大缓存后使用更顺滑

      下载过的 BLOCK 会缓存在本地，如果有足够内存，配置超大缓存后，频繁访问的数据像在本地一样，非常顺滑

###      3、无需再规划 data 文件的大小

       上一版中需要规划好 DATA 文件大小，太大的 DATA 文件下载一次需要很长时间，本次方案这个问题不需要考虑。

###      4、所有查询都能支持

        上一版中由于本地存储空间有限的问题，除了慢外，不是所有查询都可以支持，本次改进后使用了按需下载 ，故所有查询都能支持。
