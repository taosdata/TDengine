## 2. 当前行为

- 自 3.1.0.0 起，在开源版代码中对 taosd 启动过程进行了检查，不在白名单的 os 会报如下错误并退出运行：
```cpp {wrap}
failed to init dnode since unsupported platform, please visit https://www.taosdata.com for support
```

存在问题：** **检查过程在开源版代码中，已知有用户通过修改代码绕过去了。 
</callout>

## 3. 期望行为

- 自 3.2.0.0 版本开始，企业版无法降级至 3.2.0.0 及之后的社区版 (降级至 3.2.0.0 之前的社区版不进行该检查，如果没有其他兼容性问题，可以降级)
- 社区版可以升级至企业版（升级至 3.2.0.0 及之后的企业版，无法再降级至 3.2.0.0 及之后的社区版）。
- 云服务版不通过用户直接安装，不适用该检查。
- macOS 目前只发布社区版，不适用该检查。
- 用户无法通过修改开源代码的方式绕过检查。
- 不同版本启动行为

| 版本及启动场景 | 社区版行为 | 企业版行为 |
| --- | --- | --- |
| 自 3.2.0.0 之前的版本升级至 3.2.0.0 及之后的版本 | 生成加密文件，启动成功 | 生成加密文件，启动成功 |
| 3.2.0.0 及之后的版本：首次启动 | 生成加密文件，启动成功 | 生成加密文件，启动成功 |
| 3.2.0.0 及之后的版本：后续启动 | 加密文件不存在，启动失败 加密文件校验失败，启动失败 clusterId 与集群不一致，启动失败 加密文件由企业版生成，启动失败 | 加密文件不存在，启动失败 加密文件校验失败，启动失败 clusterId 与集群不一致，启动失败 加密文件由社区版生成，修改加密文件，启动成功。 |

- 检查逻辑适用版本

| Linux | 适用 | 适用 | 不适用 |
| Windows | N/A | 适用 | N/A |

## 4. 设计方案

- 把一个 dnode 启动时一定要做的一个无法绕过去的步骤封装在 TDinternal 的代码里，把它的 .a 放在 TDengine  仓库中，这个步骤有一个总入口函数，如果用户修改 TDengine 代码把它绕过去了，后面集群一定无法工作。 找到一个这样的步骤后，把要做的其它检查封装在里面，比如 os 的检查。 
- 对于企业版，因为涉及回退，仅仅通过代码还不够，还要在集群中留下一个加密的文件，同样，这个加密和解密的函数也要在 .a 中提供。 对这个文件中版本的检查也要封装在那个总入口函数中。 因为总入口无法跳过，那么它内置的其它检查也无法跳过。
