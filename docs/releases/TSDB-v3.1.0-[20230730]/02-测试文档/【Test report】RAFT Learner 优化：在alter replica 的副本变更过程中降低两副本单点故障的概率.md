# 【Test report】RAFT Learner 优化：在alter replica 的副本变更过程中降低两副本单点故障的概率

设计文档：[Raft membership change 设计](https://taosdata.feishu.cn/wiki/YZrwwyMaai8eVwkhpDkcdXyWnNb) 

### 1. 测试目的：

在现有的RAFT Learner方案中，增加一个 learner（阻塞），learner 追平（不阻塞），learner->follower 并再增加一个 follower（阻塞），这个逻辑的弊端是在第二个follower 追平的过程中如果leader和另一个已经追平的follower中有一个宕机，则阻塞写入，因为此时虽然能够选主成功，但是因为folloer没有追齐无法确认。
为了解决在alter replica的变更过程中出现新增加两节点单点故障的问题，提出以下解决方案：
**单副本->多副本**
1. 一次增加两个 learner （阻塞）
2. learner 追齐（不阻塞）
3. 等两个 learner 都追齐后同时变为 follower （阻塞）
**多副本->单副本**
在single-server configuration change方案中，采用transfer leader的方法避免这个问题。所以3->1的流程为：
 (force node3 become follower, 3->2) --> check --> drop node3 --> (force node2 become follower, 2->1) -- > check --> drop node2
副本变更过程中会触发两次选主，且在2副本停留状态的时长取决于选举的时长。
**此方案无法完全避免两副本单点故障造成的集群不可用问题，但是从2节点阶段的时长排除了节点追齐数据的时间，缩短为成员变更一个请求处理的时间，在概率上大大缩减了系统不可用的可能性。**
