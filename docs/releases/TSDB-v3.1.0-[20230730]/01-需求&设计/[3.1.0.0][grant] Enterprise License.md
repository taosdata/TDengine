## taosGrant

- `taosGrant` is an internal tool to generate the licenses for TDengine, and only the Delivery Team has the authority to generate the licenses.
- The updated functions of `taosGrant` since version 3.1.0.0:
```cpp
1) Support specify distribution time by the parameter -dist explicitly(default use taosGrant server time)
2) Support specify short form of connector parameters, e.g. -c_a/-c_n/-c_s/-c_e
3) Support parse active code automatically during generation, besides taosGrant -a still supports
```

## TDengine and connectors

### 3.1  Only the `latest active codes` utilized

- The activcCode/cActiveCode supports `distribution time` since 3.1.0.0, only `the latest` active codes in the cluster take effect. The specific rules for the `latest active codes` are as follows:
```cpp {wrap}
Suppose "nLatest" as the the number of active codes with "latest distribution time" in the cluster. 
1) If nLatest > 1, only the latest active codes would take effect;
2) If nLatest == 1, the active code with a difference of less than 24 hours from the "latest distribution time" would take effct.
```

### 3.2  Delay time for active code to take effect

- The server side parameter `grantMode` imported: 
```cpp {wrap}
1) Default value is 0: Means the active code would take effect immediately (in 5-30 seconds) regardless the metrics increase or decrease.
2）Value 1: The grant logic before TDengine 3.1.0.0 used. The active code would take effect immediately ( in 60 seconds) when metrics increase, and in 1 hour when metrics decrease. The distribution time would be neglected and all active codes would take effect.
```

- Update the  grant HeartBeat interval from 1 minute to 5 minutes.

### 3.3 Show the active codes in taos.cfg by command "show dnodes\G"

- If activeCode/cActiveCode is not set in a dnode sdb, but set in taos.cfg, then activeCode/cActiveCode in taos.cfg will be automatically fetched and stored in sdb. Thus the active codes in taos.cfg could be shown by command `show dnodes\G;`
```cpp {wrap}
1) The command "alter dnode 1 'activeCode/cActiveCode'" will reset the active code in dnode sdb, thus trigger TDengine to read the active code in taos.cfg again.
```

## Cautions

### 4.1  Compatibility of active codes

- Compatibility matrix between TDengine/connectors and taosGrant：

|  | taosGrant 3.0.5.0 | taosGrant 3.1.0.0 - Support distribution time | taosGrant 3.1.1.7 - Support undefined c_app items | taosGrant 3.1.1.27+ - Extend activeCode length to support more connectors |
| --- | --- | --- | --- | --- |
| TDengine/connectors < 3.1.0.0 | Y | N(not compatible) | N(not compatible) | N(not compatible) |
| TDengine/connectors 3.1.0.0-3.1.1.6 | Y (without distribution time) | Y | N(not compatible) | N(not compatible) |
| TDengine/connectors 3.1.1.7-3.1.1.26 | Y (without distribution time) | Y | Y | N(not compatible) |
| TDengine/connectors 3.1.1.27+ | N(not compatible) | N(not compatible) | N(not compatible) | Y |

### 4.2 Accuracy of server time

- The following validations have been imported since version 3.1.0.0:
```cpp
1) Distribution time of the activeCode/cActiveCode.
2) Cumulative running time of the cluster since its creation.
3) Cumulative running time of dnode since its certain startup.
```

- The above logic needs to ensure `the correctness of the server time during the execution of the cluster/taosGrant servers`.
