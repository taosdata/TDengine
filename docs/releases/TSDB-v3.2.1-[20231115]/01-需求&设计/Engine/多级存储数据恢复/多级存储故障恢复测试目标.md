# 多级存储故障恢复测试目标

### 1. 测试集群部署

配置了多级存储磁盘，三副本集群，有例如64个vgroup。

### 2. 假定

磁盘更换后，该磁盘上数据全部丢失。

### 3. 操作

节点重启后，执行restore dnode <did>命令。show vnodes on dnode <did>显示restored全部为true,表示恢复结束。

### 4. 功能对比

#### 4.1 优化之前

多级存储磁盘中，任一个损坏替换，该节点上全部磁盘上的数据需要清空（手工进行），全部磁盘数据需要进行全量恢复。

#### 4.2 优化之后

dnode主磁盘，vnode主目录磁盘，vnode非主目录磁盘，执行restore命令后，可按照需要恢复；其中主目录损坏的虚拟节点进行全量恢复，非主目录磁盘损坏的虚拟节点，按照部分恢复。
dnode主磁盘：该 dnode 的 0 级存储的第 0 块盘 。（dnode范围内唯一）
vnode主目录磁盘： 该 vnode 的 vnode.json 目录所在的磁盘，可能是0 级存储中的任意一个磁盘 。（vnode范围内唯一）
vnode非主目录磁盘：该 vnode 的非 vnode.json 目录所在磁盘，可能是0级、1级和2级存储中的任意一块盘 。（vnode范围内不唯一）

### 5. 优化效果测试

在大数据量下(例如几百个G)，恢复时长变化。

### 6. 升级兼容性测试

1）有部分数据之前版本写入的（是或否）；2）升级之前有未完成的快照复制（是或否）。

### 7. 其它使用方式

除了磁盘损坏更换场景外，在多副本情况下，该功能还可用于支持tsdb目录下数据文件缺失，恢复：包括tomb、data、sma和head文件等；在单副本场景下，发生了数据文件缺失，在启动时节点将报错退出。
