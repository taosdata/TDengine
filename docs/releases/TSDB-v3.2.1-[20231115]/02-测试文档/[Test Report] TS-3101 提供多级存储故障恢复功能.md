# [Test Report] TS-3101 提供多级存储故障恢复功能

## 一、测试目的

测试多级存储中某一级上有多个挂载点，当某个挂载点上的磁盘损坏后，原来的功能是需要把这一级上所有挂载点的数据都需要恢复，改进后只需要恢复损坏更换新磁盘部分的数据，这一级上其它挂载点的数据无需恢复。

## 二、测试环境设计

使用单台服务器建立不同端口创建 3 节点服务器进行测试，数据库创建为三副本，数据单副本是无法支持数据恢复的。

## 三、测试方案设计

### **1、准备数据：**

    创建数据库一个, vgroup ： 1 ，三副本
    创建超级表一个，10 个字段，100 个子表，每个子表 10 W 数据量， 共 100亿数据量
    一行写入 1K 数据，共计原始数据 100G ，10% 的压缩率，压完 10G 磁盘占用空间

### **2、多级存储配置**

   配置三级存储 ，每一级上共 2 个磁盘挂载点，共 6 块磁盘

### **3、测试以下几种情况：**

   1）共 对 3 个场景进行测试

|  |

|  |

| 场景2 | 一级存储副挂载点磁盘坏 |
| 场景3 | 一级存储主目录磁盘坏 |

   2）数据正确性验证

## 四、测试报告

###    1、测试步骤

- 安装 TDengine 3.1.1.6 版本
- 搭建三节点集群环境
- 根据要求配置 taosBenchmark 所需要的 json 配置文件
- 使用 taosBenchmark 写入数据
- 数据生成完成后复现备份一份儿出来，做为后面测试的基础数据
- 停止 TAOSD 服务
- 删除根据不同场景所需要的目录，同时记录删除目录的大小
- 启动 TAOSD 服务
- 根据不同场景执行 RESTORE 命令进行恢复，记录用时
- 以上步骤在最新版本中也做一次，记录数据

## 五、测试结论

 1、在大部分场景下确实本次恢复改进后只恢复了损坏盘上的内容
 2、但在有 HEAD 文件和 DATA 文件分离的情况下，恢复范围被扩大了，有改进空间，已提JIRA
 3、存在恢复后的数据比原损坏盘上的数据少的情况，原因是本次恢复时数据被重新分配到其它挂载点了，属正常现象。
 4、如果主挂载盘损坏，所有挂载盘上数据都需要恢复，这个有改进空间，已提JIRA.

整体测试功能通过！
