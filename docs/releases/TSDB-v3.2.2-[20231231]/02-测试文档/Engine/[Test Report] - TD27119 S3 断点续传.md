# [Test Report] - TD27119 S3 断点续传

## 一、测试目的

     因为 S3 的 DATA 文件一般都比较大，有几G 或百G 级别都有，所以断点续传功能在这里非常有必要

## 二、测试步骤

     1、配置minio S3 环境，设置 s3UploadDelaySec 为 10 分钟
     2、使用 taosBenchmark 写入生成大数据量的 DATA 文件
     3、写入完成后，执行 flash database , 过 10 分钟后，执行 trim database 触发数据上传
     4、使用 dstat 查看磁盘及网络流量
      5、同时查询服务器上传文件的大小并记录
      6、停止服务器端 查询服务，相当于网络断开
      7、 间隔一段时间后，再恢复 S3 服务
      8、验证是否接着上面记录大小的文件开始继续上传
      9、中间再随机停止 TAOSD 服务，再启动，验证服务不稳定情况下的情况
      10、预期是仍然会接上面服务停止前的大小继续上传
      11、所有数据上传完后，验证数据正确性，和没有上传完做比较
      12、重启服务，再次验证数据正确性
      13、以上步骤在 腾讯 cos 也做一遍，验证 COS 对断点续传的支持
       上面步骤验证的场景：
           1）上传被中断场景：a 网络断开       b taosd 重启
           2）支持的系统场景：a minio 环境    b 腾讯云 cos 环境
           3）数据正确性验证：a 数据量验证   b 数据规模验证
