### 3.2 测试方案

   测试方案是通过使用 python接口的 UDF 创建出各种类型的自定义函数，自定义函数抽取原来 tdengine 中内置的一些函数进行实现，再用UDF的结果与原函数的结果进行比对，两个相同说明 UDF 在传入参数返回参数这两个最重要的环节是没有问题的。

####   1、投影函数

    在投影查询中使用到的函数，完成表达式的计算，如转化大小写，取绝对值等计算函数。
    1）数学函数 ABS(int) pow(int|float|unsign int)  round(float)
    2)  字符串函数 concat(str1,str2,str3) lower(str) upper(str) substr(str,pos, len) length(str)
    3)  时间转化函数   timediff(expr1, expr2)

####   2、聚合函数

         在聚合函数过程中使用到的函数。
  1）普通聚合函数 COUNT(field) SUM(number) AVG(number) 
    2)  选择聚合函数 MIN(number) MAX(number) first(field) last(field) 
    3)  时序数据特有的 CSum(number) DIFF(number)
     以上几类抽取的函数基本上覆盖了 TDengine 支持的大部分类型函数，也覆盖了大部分使用场景，自定义函数如果能完成以上这些函数的应用场景，功能基本上已经足够了。

####   3、非预期内的返回值测试

       python UDF 函数的返回值是由用户控制的，所以用户可能会返回各种各样的非预期内的返回值，所以需要加强对返回值的验证，遍历所有用户可能输入的返回值，保证不管用户输入的是什么样类型的返回值，都不能让程序崩溃，都需要做到合理处理。

####   4、异常场景测试

 1） updf 退出后会不会影响 taosd 进程
 2） udf 函数不按约定的类型返回，看下会是什么情况，有预期

####   5、其它场景测试

 1） 集群场景下测试
 2） 大数据量场景下测试
         3)   tmq 中标量函数的测试
         4） 流中 parition by 的测试支持

### 3.3 集成到CI中

如何把上面这些自定义函数集成在 ci 中完成自动化验证，是需要仔细考虑一下的
1） 首先需要把上面需要使用到的文件都上传至GIT 仓库，在目标机器上可以接下来所需文件
2）自定义函数名统一以 udf 开头，如 udf_sum udf_count
3)   创建 13 种全类型超级表 st, 普通字段 c1 ... c13 , TAG 字段 t1 ... t13
4)   创建子表 10 个 t0 ... t9
5)   写入数据 100 条，数字类型的值为行数，binary nchar 类型为 binary + 行数 和 nchar + 行数
6） 能接受数字类型的函数依次把所有数字类型字段都传入，能接受字符串类型的把字符串类型字段都传入，保证所有类型的字段都有调用验证
       7）  返回结果与调用库中原函数进行比较，一致为通过验证
8） 投影函数及聚合函数都验证一遍，无不符合预期为整个 CASE 验证通过。
