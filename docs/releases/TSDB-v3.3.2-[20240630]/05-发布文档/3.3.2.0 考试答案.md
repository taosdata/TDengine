# 3.3.2.0 考试答案

#### 1. **那些场景下可能用到复合主键？**

TDengine 作为时序数据库，要求每个表（子表）中必须有主键时间戳列。在一些特定场景下，只用时间戳作为主键会有大量的重复记录，这些记录在生产应用中都是有价值的，不能丢弃。为了解决重复时间戳的问题，TDengine 在创建普通表或超级表时，可以通过关键字 PRIMARY KEY 额外指定一列，与时间戳列共同组成复合主键。例如：
1. 有些工业用户，事件数据的时间戳精度到毫秒。当在一个毫秒内同一设备产生多个事件时，时间戳产生重复。他们会采用事件类型来区分不同的事件。
2. 在通信基站中，一个基站会处理来自不同设备的通信消息。当在一个微秒内同一基站收到多个通信消息时，时间戳产生重复。他们会采用设备 ID 来区分不同的通信。
3. 在红绿灯路口，通过拍照获得经过路口的车牌号。当同一张照片中有多个车时，时间戳产生重复。他们会采用车牌号来区分不同的通过行为。
4. 在 IOT 通信网关中，会把所有设备的数据写到少数的几张网关表中。无论时间精度多高，都会产生重复时间戳。他们会采用设备 ID 来区分不同的数据。
5. 有很多处理金融行情数据需求的用户，之前接触过的例如：易方达、启林、顽岩资产、国家外汇中心、华锐金融、宽睿、通达信等。证券交易所提供的逐笔成交、逐笔委托数据，时间精度到毫秒。当一个毫秒内同一只股票产生多次交易时，时间戳产生重复。除时间戳外，这些数据采用一个整型序列号标志不同的交易。

#### 2. 什么是 ASOF Join？

指不完全匹配连接，用于时间序列数据，按照主键时间戳最接近的方式进行匹配。事件 A 发生后，紧接着发生了事件 B，“紧接着”是一个模糊时间范围的概念，所以，只能用“时间戳最接近”来表达。以 Left ASOF Join 为例，左表中每一行记录与右表中符合连接条件的记录合并，右表记录按主键列排序后，取时间戳最接近的 jlimit_num 条记录作为输出结果。 以智能电表样例数据为例，如下 SQL 先获取表 d1001 电压值大于 220V 的记录，再寻找表 d1002 中同一时刻之后电压大于 220V 的记录。
```sql {wrap}
SELECT a.ts, a.voltage, b.ts, b.voltage FROM d1001 a 
LEFT ASOF JOIN d1002 b 
ON a.ts <= b.ts 
WHERE a.voltage > 220 AND b.voltage > 220;
```

#### 3. 什么是 Window Join？

指窗口连接，以 Left Window Join 为例，根据左表中每一行的主键时间戳和 WINDOW_OFFSET 构造窗口，然后据此进行窗口连接，返回窗口内的至多 jlimit_num 条记录。如下SQL 可以获取错误事件发生的 60 秒内，出现的告警事件明细。
```sql {wrap}
SELECT A.ts, A.event, A.val, B.ts, B.event, B.val val2
FROM alarm1 A
LEFT WINDOW JOIN fault1 B WINDOW_OFFSET(0s, 60s)
WHERE A.event = 6 AND B.event = 1
```

#### 4. TDengine 有哪些窗口，对其进行简单解释

窗口将时序数据拆分成有限大小的“存储桶”，每个桶包含若干条记录。通过划分窗口，可对这些记录进行聚合计算。
1. 时间窗口（time window），可分为滑动时间窗口和翻转时间窗口，INTERVAL 子句用于产生相等时间周期的窗口，SLIDING 用以指定窗口向前滑动的时间。每次执行的查询是一个时间窗口，时间窗口随着时间流动向前滑动。例如温度传感器每秒采集一次数据，但需查询每隔 10 分钟的温度平均值，这种场景可以使用窗口子句来获得需要的查询结果。例如：
```sql {wrap}
SELECT COUNT(*) FROM temp_tb_1 INTERVAL(1m) SLIDING(2m);
```

![](./images/img_RG6tbRfPkolDGnx1s1qcwMkxnyd.png)

1. 状态窗口（status window），使用整数（布尔值）或字符串来标识产生记录时设备的状态量。产生的记录如果具有相同的状态量数值则归属于同一个状态窗口，数值改变后该窗口关闭。如下图所示，根据状态量确定的状态窗口分别是 [2019-04-28 14:22:07，2019-04-28 14:22:10] 和 [2019-04-28 14:22:11，2019-04-28 14:22:12]。例如
```sql {wrap}
SELECT COUNT(*), FIRST(ts), status FROM temp_tb_1 STATE_WINDOW(status);
```

![](./images/img_J5TUbEV0GokvM7xG4OzcNavZnab.png)

1. 会话窗口（session window），根据记录的时间戳主键的值来确定是否属于同一个会话。如下图所示，如果设置时间戳的连续的间隔小于等于 12 秒，则以下 6 条记录构成 2 个会话窗口，分别是：[2019-04-28 14:22:10，2019-04-28 14:22:30] 和 [2019-04-28 14:23:10，2019-04-28 14:23:30]。因为 2019-04-28 14:22:30 与 2019-04-28 14:23:10 之间的时间间隔是 40 秒，超过了连续时间间隔（12 秒）。
```sql {wrap}
SELECT COUNT(*), FIRST(ts) FROM temp_tb_1 SESSION(ts, 12s);
```

![](./images/img_Ssf5bE7KMof2J1x26V8caJU0nlg.png)

1. 事件窗口（event window），根据开始条件和结束条件来划定窗口，当 start_trigger_condition 满足时则窗口开始，直到 end_trigger_condition 满足时窗口关闭。例如
```sql {wrap}
SELECT _wstart, _wend, count(*) FROM t event_window START WITH c1 > 0 END WITH c2 < 10;
```

![](./images/img_PCP1bDke9oa1x8xfxofcWsA9nbg.png)

1. 计数窗口（count window)，按固定的数据行数来划分窗口。将数据按时间戳排序，再按照 count_val 的值，划分为多个窗口，然后做聚合计算。例如
```sql {wrap}
SELECT _wstart, _wend, count(*) FROM t count_window(4);
```

#### 5. 什么是 TSMA，能解决什么问题？

TSMA 是 Time-Range Small Materialized Aggregates 缩写，基于时间范围的小颗粒度聚合物化视图，能提高大数据量聚合函数的查询性能。对固定时间窗口内的数据进行预计算， 将计算结果存储下来， 查询时通过读取预计算结果以提高查询性能。在大屏或者报表的场景中，某张表的某些列可能经常性的做聚合查询，例如绘制月度电流均值的曲线图，使用 TSMA 可以将每日的电流均值预先计算出来，大屏或者报表即可做到实时显示。

#### 6. TDengine 支持那些压缩算法，那种压缩算法最好，相比 LZ4 有多少提升？

TDengine 在 3.2 及之前版本仅支持 LZ4 算法，从 3.3 版本开始，增加 ZLIB、ZSTD、TSZ、XZ 四种压缩算法。在质量部给出的测试报告中，以 taosBenchmark 某个数据集为例，在测试环境完全相同情况下，ZSTD 压缩算法可以提升一倍的写入速度，提升近八倍的压缩率。在完全随机的汽车 CAN 总线数据集中，ZSTD 能提升一倍的压缩率。

#### 7. TDengine 对 S3 的支持有哪些特点，适合哪些客户

对象存储通常用于存储冷数据，适合于两类场景
1. 冷数据查询、写入的需求低，但是作为公司的数据资产，不能彻底删除
2. 对数据存储成本敏感，希望能降低本地磁盘占用，必要时还可以读取冷数据
TDengine S3 有如下特点
1. 显著降低存储成本
2. 支持冷数据写入、更新、删除，行为透明，用户对数据上传至 S3 的过程无感知
3. 查询速度仅下降一倍，查询行为透明，用户对数据从 S3 下载的过程无感知

#### 8. TDengine 的双副本与 TDengine 的双活有哪些不同 ，各自用在那种场景？

1. 三副本：高可用性最好，成本也最高
2. 双副本：时序数据的副本数为 2 ，但节点数大于等于 3，可显著降低成本，高可用性较差；适用于数据安全性要求较高，高可用性要求相对较低，且希望降低成本的客户
3. 双活：可仅部署两个节点，高可用性较好，但有可能丢数据；适用于有且仅有两台服务器，同时希望实现一定程度的服务高可用和数据高可靠的场景；也可用于两套 TDengine 集群（不限节点数目）之间的灾备场景
|  | 三副本 | 双副本 | 双活 |
| --- | --- | --- | --- |
| 集群数目 | 部署一个集群 | 部署一个集群 | 部署两个不同集群 |
| 节点数目 | 大于等于三 | 大于等于三 | 只需两个节点 |
| 选主原理 | Raft 协议 | 管理节点仲裁选主 | 无需选主 |
| 同步原理 | Raft 协议 | Raft 协议 | 通过 taosX 进行数据同步 |
| 同步延迟 | 无延迟 | 无延迟 | 依赖于 taosX 的同步速度，秒级 |
| 数据安全性 | 无数据丢失 | 无数据丢失 | 依赖于 WAL 的保存时长 |
| 数据一致性 | 实时一致性 | 实时一致性 | 最终一致性 |
| 高可用性 | 任意两个副本存活即可提供服务 | 不能处理连续宕机场景，只有一个副本存活时，不保证能提供服务 | 一个副本存活即可提供服务 |

#### 9. TDengine 的数据库加密支持对那些数据进行加密，性能如何？

TDengine 采用国标 sm4 加密算法对所有数据文件进行加密，包括
1. 预写日志文件（WAL）
2. 元数据文件（meta）
3. 时序数据文件（data、stt）
性能瓶颈是 CPU 而不是磁盘的场景，写入性能下降 20% 左右；性能瓶颈是磁盘的场景，写入性能下降一倍。查询速度下降 50% 左右。 

#### 10. 如何和用户介绍企业版、社区版、行业版的不同点

1. 社区版：是一个开源的高性能时序数据库，核心优势在于集群开源、云原生架构和高性能；社区版不提供企业级服务，故障和需求通过 Github 社区报告。
2. 企业版：提供了增强的辅助功能，包括权限管理、视图、备份/恢复、异地容灾、边云协同、多级存储、运行监测、可视化管理工具、支持 MQTT/Kafka/OPC/PI System/Wonderware 等多种数据源；根据合同约定，提供不同级别的企业服务；支持国产操作系统、国产 CPU。
3. 行业版：针对特定行业的业务场景定制开发的企业版，裁剪该业务场景不需要的部分功能，满足各种中、小型应用的需要，通常为单机版本。
