# 权限管理：普通用户没有建库权限

## 1. 背景

### 1.1 需求

- 当前 TDengine 所有用户都可以创建数据库。用户的权限过大，应由超级管理员授予指定用户创建数据库权限，普通用户默认没有创建数据库权限。
- [TS-3737](https://jira.taosdata.com:18080/browse/TS-3737) [仅root可创建数据库，普通用户默认没有建库权限](https://jira.taosdata.com:18080/browse/TS-3737)

### 1.2 现状

- 用户表有 super、enable、sysinfo 三个控制字段，分别对应是否超级管理员、是否启用、是否可查看系统信息
  - 创建新用户时默认非超级管理员、启用状态、可查看系统信息。
- 通过 alter 命令修改用户权限
  - 支持修改用户启用状态
  - 支持修改查看系统信息状态
  - 不支持修改 super 字段-授予超级管理员权限，只有 root 一个超级管理员
- 未限制用户创建新数据库的权限
- 通过 grant 命令授予用户指定数据库/表的读、写权限
  - 用户创建新数据库后自动成为数据库 owner，可任意操作该数据库

### 1.3 目标

- 普通用户默认没有权限创建数据库，需要被超级管理员授权后才可以。

## 3. 定义

### 3.1 DDL(Data Definition Language)  数据定义语言

- 用于定义或改变库/表/索引的结构，数据类型，表之间的链接和约束等初始化工作。如 create、drop、alter 等。

### 3.2 DCL(Data Control Language) 数据控制语言

- 用于对数据库中的用户进行访问控制和权限管理。如 grant、deny、revoke 等。

### 3.3 DML(Data Manipulation Language) 数据操纵语言

- 用于操作数据库中的数据，如 select、insert、update、delete 等。

## 4. 行为说明

- 执行 sql 命令时，先校验用户身份
1. 如果查不到该用户，则身份校验失败拒绝服务，返回失败；
   - 如果 enable=0，返回用户禁用信息
2. 如果是创建数据库命令，检查 user 是否 `超级用户`，或有 createdb 权限，不满足则返回失败
3. 其他:如果是 DDL 命令，检查 user 的 privilege 信息，若没有权限则返回失败，有则继续执行返回执行结果

### 4.1 用户权限管理

#### 4.1.0 总体原则

- `超级用户`拥有所有权限，且不可更改 super/enable/sysinfo。
- 只有`超级用户`拥有 create/alter/drop user 和 grant/revoke privileges 权限。
- `db 创建者`自动拥有该 db 和该 db 拥有的 table、index 等子对象除 grant/revoke 之外的所有权限。
- 只有 `超级用户`和 `db 创建者` 拥有 alter/drop/compact/trim db 的权限。

#### 4.1.2 用户表新增 createdb 字段

- 在用户表（information_schema.ins_users）新增 createdb 字段，用于标识用户是否有  `创建数据库(createdb)` 权限。
```python
taos> describe information_schema.ins_users;
             field              |          type          |   length    |        note        |
=============================================================================================
 name                           | VARCHAR                |          24 |                    |
 super                          | TINYINT                |           1 |                    |
 enable                         | TINYINT                |           1 |                    |
 sysinfo                        | TINYINT                |           1 |                    |
 createdb                       | TINYINT                |           1 |                    |
 create_time                    | TIMESTAMP              |           8 |                    |
 allowed_host                   | VARCHAR                |       49152 |    
```

- 新建普通用户，默认没有 createdb 权限。
```python
// ordinary user without privilege of createdb
taos> create database d2;
DB error: Insufficient privilege for operation. (0.000108s)     
```

- 超级用户自动获取 createdb 权限。

##### 4.1.2.1 授予/取消 createdb 权限

- 可以通过  alter 命令授予或取消普通用户的 createdb 权限。
```sql
taos> alter user test1 createdb 1;
Query OK, 0 row(s) affected (0.003650s)

taos> alter user test1 createdb 0;
Query OK, 0 row(s) affected (0.003650s)
```

- 只有`超级用户（root）`拥有 alter 普通用户权限的权限。

##### 4.1.2.2 查看 createdb 权限

- 通过 `show users;` 或 `select * from information_schema.ins_users;` 命令查看用户的 createdb 权限。

### 4.2 只读权限用户

- 只读权限用户没有 DDL、DCL、和除 select 之外的 DML 权限。
- 使用数据库前，检查用户是否有该数据库的权限，没有则拒绝
```sql
taos> use d1;
DB error: Insufficient privilege for operation (0.001444s)
```

#### 4.2.1 只读权限用户禁止创建超级表 （create stable）、删除超级表（drop stable）

```sql
taos> create stable stb1 (ts timestamp, f1 int) TAGS(tag1 int, tag2 binary(500));
DB error: Permission denied or target object not exist (0.000275s)

taos> drop stable stb1;
DB error: Permission denied or target object not exist (0.000190s)
```

#### 4.2.2 只读权限用户禁止修改超级表 （alter stable）

```sql
taos> alter stable stb1 add column c2 int;
DB error: Permission denied or target object not exist (0.001390s)
```

#### 4.2.3 只读权限用户禁止创建表（create table）、删除表（drop table）

```sql
taos> create table t1(ts timestamp, q_int int);
DB error: Permission denied or target object not exist (0.000901s)

taos> drop table t1;
DB error: Permission denied or target object not exist (0.002294s)
```

#### 4.2.4 只读权限用户禁止修改表（alter table）

```sql
taos> alter table t1 rename column c1 c_int;
DB error: Permission denied or target object not exist (0.001735s)
```

#### 4.2.5 只读权限用户禁止创建索引（create index）、删除索引（drop index）

```sql
taos> create index idx2 on stb1(tag2);
DB error: Insufficient privilege for operation (0.003622s)

taos> drop index idx2;
DB error: Insufficient privilege for operation (0.002917s)
```

#### 4.2.6 只读权限用户禁止 `grant/revoke` DCL 操作

```sql
taos> grant read on d1.* to u2;
DB error: Insufficient privilege for operation (0.001876s)

taos> revoke write on d1.* from u2;
DB error: Insufficient privilege for operation (0.003303s)
```

## 6. 兼容性

- 用户感受到的显著变化是未授权无法创建数据库，而之前建数据库是不受限制的。
- 支持升级和降级。升级后，普通用户需要显式授予建库权限；降级后，普通用户均拥有建库权限。

## 7. 运维

- 如果`普通用户`仍然要保留`建库权限`，则升级后，需要通过`超级用户`给对应的`普通用户`授予 `建库权限`。

## 8. 使用场景

1. 超级管理员创建数据库成功
2. 超级管理员授权某普通用户创建数据库权限
3. 超级管理员收回某普通用户创建数据库权限
4. 普通用户没有创建数据库权限，创建数据库失败
5. 普通用户获得创建数据库权限后，创建数据库成功，并自动获得新数据库的读写权限

## 15. 附录

### 15.1 PostgreSQL

- 在PostgreSQL数据库中，普通用户的权限取决于在创建用户时指定的选项以及后续通过GRANT命令赋予的权限。具体来说，在创建用户或角色时，可以指定的权限包括：
1. SUPERUSER 或 NOSUPERUSER：超级用户权限，拥有所有权限，默认是NOSUPERUSER。
2. CREATEDB 或 NOCREATEDB：建库权限，默认是NOCREATEDB。
3. CREATEROLE 或 NOCREATEROLE：建角色权限，拥有创建、修改、删除角色的权限，默认是NOCREATEROLE。
4. INHERIT 或 NOINHERIT：继承权限，可以把除超级用户权限外的其他权限继承给其他用户/角色，默认是INHERIT。
5. LOGIN 或 NOLOGIN：登录权限，作为连接的用户，默认是NOLOGIN，除非是CREATEUSER（默认登录）。
数据库管理员可以通过GRANT命令赋予用户对数据库中各种对象的查询、增、删、改的权限。
PostgreSQL中的权限是按照数据库逻辑对象的层次进行管理的，如database、schema等。
```sql
CREATE USER name [ [ WITH ] option [ ... ] ]

where option can be:

      SUPERUSER | NOSUPERUSER
    | CREATEDB | NOCREATEDB
    | CREATEROLE | NOCREATEROLE
    | INHERIT | NOINHERIT
    | LOGIN | NOLOGIN
    | REPLICATION | NOREPLICATION
    | BYPASSRLS | NOBYPASSRLS
    | CONNECTION LIMIT connlimit
    | [ ENCRYPTED ] PASSWORD 'password' | PASSWORD NULL
    | VALID UNTIL 'timestamp'
    | IN ROLE role_name [, ...]
    | IN GROUP role_name [, ...]
    | ROLE role_name [, ...]
    | ADMIN role_name [, ...]
    | USER role_name [, ...]
    | SYSID uid
```

### 15.2 MySQL

- 在MySQL 5.7及更高版本中，新用户默认具有以下权限：
1. 登录权限：新用户可以登录到MySQL服务器。
2. 创建权限：新用户可以在MySQL服务器上创建数据库和表。
3. 删除权限：新用户可以在MySQL服务器上删除数据库和表。
4. 修改权限：新用户可以在MySQL服务器上修改数据库和表的数据。
5. 复制权限：新用户可以在MySQL服务器上复制数据库和表。
6. 排序权限：新用户可以在MySQL服务器上使用ORDER BY语句对表中的数据进行排序。
7. 索引权限：新用户可以在MySQL服务器上为表创建索引。
8. 视图权限：新用户可以在MySQL服务器上创建视图。
9. 存储过程权限：新用户可以在MySQL服务器上创建存储过程。
10. 触发器权限：新用户可以在MySQL服务器上创建触发器。
需要注意的是，这些默认权限可能会因MySQL的配置而有所不同。
- 在创建新用户后，可以通过GRANT语句为新用户授予其他权限或限制某些默认权限。
```python
mysql> grant create on *.* to 'test2'@'localhost';
Query OK, 0 rows affected (0.00 sec)

mysql> show grants;
+--------------------------------------------+
| Grants for test2@localhost                 |
+--------------------------------------------+
| GRANT CREATE ON *.* TO `test2`@`localhost` |
+--------------------------------------------+
1 row in set (0.00 sec)
```
