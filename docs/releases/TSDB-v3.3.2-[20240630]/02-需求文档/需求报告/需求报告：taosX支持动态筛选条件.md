# 需求报告：taosX支持动态筛选条件

## 1. 需求描述

目前河北电力分布式光伏从营销用采系统Kafka消费数据入库TDengine，拟采用taosX替换之前采用的nifi方案。
Kafka主题里面混合存放了普通用户电能表、分布式光伏电能表信息，业务需求是，仅导入分布式光伏电能表的采集数据，忽略掉其他采集数据。

### 1.1 需求说明与示例

#### 1.1.1 需求说明

1. taosX与外部数据定期交换筛选条件清单，支持白名单和黑名单两种机制
2. 每隔一段时间(可配置，如30秒)，taosX查看指定文件夹下是否存在筛选清单文件，如存在则将该筛选清单热加载至运行实例，即时生效
3. taosX之Kafka 连接器接收到数据后，逐一比对指定Key值是否满足条件，如满足则放行，否则丢弃
4. 记录热加载行为、筛选清单，备查

#### 1.1.2 示例

假设筛选Key为DEV_ID，筛选模式为白名单，筛选清单格式为CSV，每行一条记录
```sql {wrap}
xxx-1
xxx-101
...
```

Kafka Payload
```sql {wrap}
{
    "DATA_ITEM_ID": "aaa-0123456",
    "MONITOR_OBJ_TYPE": "bbb",
    "MONITOR_OBJ_CODE": "ccc",
    "PRO_MGT_ORG_CODE": "hebei",
    "MGT_ORG_CODE": "ddd",
    "PUSH_DATE": "2024-3-20 12:23:30",
    "U2358": "223",
    "U2359": "219",
    "PHASE_FLAG": "1",
    "DATA_POINT_FLAG": "3",
    "DATA_DATE": "2024-3-20",
    "CMD_TYPE": "eee",
    "PRODUCT_CODE": "fff",
    "DEV_ID":"xxx-1",
    "TERMINAL_ID":"zzz"
}
```

根据筛选清单设定的规则，上述报文因DEV_ID = xxx-1，符合筛选条件，给予放行。
