### 2. 风险描述回顾

<callout emoji="gift" background-color="light-yellow">
Parquet 数据源在处理列投影时，当用户指定的列不存在时，系统会自动过滤不存在的列并继续执行，而不是抛出错误或警告。这种静默处理机制可能导致用户无法察觉到数据导入的不完整性，造成数据质量问题。特别是在批量导入多个 Parquet 文件时，如果文件结构不一致，可能导致某些文件的关键列被意外过滤，影响数据的准确性和可追溯性。

### 3. 评审讨论要点

#### 3.1 当前现状分析

- Parquet 数据源列投影逻辑当前对"列不存在"场景采用静默过滤策略，不输出任何警告或错误信息。
- 用户在完成批量导入任务后，无法通过系统日志或任务报告得知哪些列被过滤。
- 当批量处理结构不一致的 Parquet 文件时，关键列丢失的风险尤为突出。
- 现有单元测试未覆盖列投影异常场景，行为边界不明确。

#### 3.2 风险影响范围讨论

- **直接影响**：导入的数据集缺失预期列，数据不完整，下游分析结果失真。
- **间接影响**：数据质量问题难以追溯，增加排查成本；在合规场景下可能引发数据审计问题。
- **影响对象**：所有使用 Parquet 数据源进行批量导入的用户，尤其是多文件、混合 Schema 场景下的用户。

#### 3.3 应对策略讨论

与会人员一致同意采用**减轻（Mitigate）**策略，通过改进系统提示、增加配置选项及完善文档，降低用户无感知风险的可能性。
