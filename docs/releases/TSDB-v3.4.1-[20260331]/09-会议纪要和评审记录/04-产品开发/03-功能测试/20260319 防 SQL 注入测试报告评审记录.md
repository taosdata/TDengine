## 2. 评审记录

1. **测试目标与设计文档契合度** ：测试报告明确将“验证 TDengine SQL 防火墙的黑名单、白名单及学习模式功能”作为核心目标，与 TS 文档及对应的 FS 文档[防 SQL 注入 - FS](../../../05-设计文档/防 SQL 注入 - FS.md)的背景与设计目标高度一致。报告直接响应了 FS 中关于通过字符串层检查、AST 语义检查及规则文件实现黑/白名单、防注入、学习模式和配置同步机制的核心诉求，测试方向精准。
2. **功能测试覆盖度与深度** ：报告的功能测试部分分为两个主要模式，覆盖了 SQL 防火墙的核心防护逻辑：
  - **黑名单功能测试** ：验证了在仅黑名单模式下，系统能正确拦截恶意 SQL（如 `UNION SELECT` 注入、`DROP TABLE` 等），并不影响正常业务 SQL 的执行。测试用例设计典型，结果符合“匹配规则即拒绝，不匹配规则正常执行”的目标。
  - **白名单学习模式与白名单功能测试** ：验证了白名单学习模式能自动收集高频正常 SQL 模式，生成规则文件，并在启用白名单后仅放行已学习模式，拒绝未学习的异常 SQL。测试步骤涵盖了准备阶段、基本学习验证及值归一与阈值测试，结论表明白名单模式能够根据学习结果正确区分“已知良性模式”和“未授权模式”。
1. **其他测试模块的评审** ：
  - **易用性测试** ：报告认为安全相关参数统一通过 `taos.cfg` 或 `alter local` 管理，支持运行时调整，规则文件格式标准，对于熟悉 SQL 与正则的用户较为直观。
  - **长期稳定性测试** ：报告指出在模拟高频场景及多轮学习/切换/重启下，SQL 防火墙与学习模式表现稳定，无明显资源泄漏或规则错乱迹象。
  - **安全测试** ：报告总结了在注入防护能力、规则优先级与黑/白名单冲突、审计与日志等方面的测试情况，认为 SQL 防火墙在典型注入、破坏性 DDL、未学习模式访问等方面表现出预期的安全防护能力。同时，报告也指出了 AST 级别恒真条件检测、多语句注入、编码混淆等复杂攻击模式在规则与测试层面仍有扩展空间。
  - **兼容性测试** ：报告标注为“无”。
1. **测试文档规范性与可追溯性** ：报告结构完整，包含了修订记录、测试目标、参考文档、测试结论、测试环境及详细的功能测试用例列表，符合标准测试文档的规范。报告明确列出了参考的 FS 文档链接，确保了测试活动与需求的可追溯性。
2. **测试结论的客观性与决策价值** ：报告基于现有测试用例结果，给出了“综合黑名单与白名单（含学习模式）测试结果，TDengine SQL 防火墙在当前实现下能够可靠拦截典型注入模式，并在白名单学习模式下自动归纳正常 SQL 模式并进行保护”的结论。该结论与已执行的功能测试结果相符，认为功能基本符合 FS 文档描述，可以满足生产环境常见安全需求。同时，报告也客观指出了已知不足与改进建议。
