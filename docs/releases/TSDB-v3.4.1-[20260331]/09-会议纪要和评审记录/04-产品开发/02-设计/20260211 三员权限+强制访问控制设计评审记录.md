## 2. 评审记录

评审团队对设计文档进行了全面审查，认为所有设计合理，具体评审意见如下：
1. **功能完整性**：1）明确了`强制三权分立(SoD mandatory)`和`强制访问控制(MAC)` 在 TDengine 3.4.1.x 版本的具体行为。2）需要增加 `通过命令行参数`启用 `强制三权分立` 的能力；3）需要澄清是否支持 SYSSEC 为用户临时提升安全等级；4）需要澄清 view/topic/stream 等包含对象本身和关联对象的安全等级时，在创建和后续使用时主体和客体安全等级的关系。
2. **语法设计合理性**：1）支持通过 SQL 命令开启 `强制三权分立(SoD mandatory)`；2）支持通过 SQL 命令设置、修改和查看 `用户/角色/数据库/超级表`的安全等级(security_level)；支持通过 show security_policies 等命令查看系统安全策略。
3. **行为逻辑正确性**：1）开启 `强制三权分立(SoD mandatory)` 后，永久禁用 root 且不可再激活。 2）遵循 MAC 的基本原则：`禁止上读`和`禁止下写`，并且明确了 insert 的行为，只支持在相同`安全等级` 的客体（即表）写入。3）审计库拥有 Top Secret 等级，SYSAUDIT 和 SYSAUDIT_LOG 也拥有 Top Secret 等级，结合 SoD，实现 SYSAUDIT 只能查询，SYSAUDIT_LOG 只能建表和写入。4）普通用户无法通过查询命令直接查看审计库中自己的行为。如有必要，后续可以考虑增加一个 SQL 命令，例如，show self_operations，用于检索自己的操作记录。 
4. **兼容性与影响**：1）支持从老版本直接升级至新版本，只支持停机升级，不支持滚动升级，升级后不支持降级。2）升级后，root 和普通用户根据自身的角色自动添加对应的安全等级，db/stable 的 security_level 设置为 1(与普通用户默认拥有的 security_level 一致)，以防止根据 owner/creator 拥有的 security_level 进行设置而导致 security_level 过高，原来拥有读/写权限的普通用户无法正常读写。后续，SYSSEC 可根据实际需求，先手工更新用户和角色的 security_level，再更新 db/stable 的 security_level。
5. **性能评估**：由于支持 SoD 和 MAC，几乎在所有操作的执行路径上增加了校验，预计会对性能产生的一定的影响，总体影响预计在 [5%-30%] 之间。
