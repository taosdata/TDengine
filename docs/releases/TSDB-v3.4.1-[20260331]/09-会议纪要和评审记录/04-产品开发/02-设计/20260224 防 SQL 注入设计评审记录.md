## 2. 评审记录

1. 功能完整性：明确了防 SQL 注入的多层防护机制（字符串级+AST 级过滤），覆盖黑白名单两种工作模式，定义了核心术语及常见 SQL 注入场景的防护方案，贴合防火墙机制的需求；配置项、规则管理、审计日志、自动学习等功能设计完整，可满足 SQL 注入防护的核心需求，无需额外补充功能。
2. 设计合理性：防护架构设计合理，采用“字符串级快速过滤+AST 级精确检查”两层过滤，既减少后续处理开销，又能精准识别恶意 SQL，不受格式化、注释等方式绕过影响；配置项设计全面，支持在 taos.cfg 中配置安全检查开关、工作模式、规则文件路径等，同时支持动态增删改规则，适配不同运维场景；规则文件支持自定义正则，灵活性强；黑白名单优先级规则清晰，审计日志分级记录（WARN/DEBUG/INFO），便于安全事件排查和追溯；白名单自动学习模式流程完整，可自动适配正常业务 SQL 模式，降低手动配置成本，整体设计贴合实际应用场景。
3. 行为逻辑正确性：明确黑白名单两种工作模式的核心行为，黑名单模式（默认）拒绝匹配规则 SQL，白名单模式仅允许匹配规则 SQL，逻辑无歧义；两层过滤的行为逻辑正确，字符串级过滤覆盖关键字、注释、编码绕过、长度限制等场景，AST 级过滤覆盖 WHERE/HAVING 条件、函数、子查询、JOIN 等核心语法节点，防护场景全面；配置项安全管理逻辑合理，通过 taosk 密钥加密保护配置文件，仅允许通过带权限检查的 SQL 命令修改配置，防止配置被随意篡改；客户端配置缓存及更新机制清晰，兼顾安全性和易用性；常见 SQL 注入场景（恒真条件、UNION 拼接、注释截断等）均明确了屏蔽方案，防护逻辑贴合攻击场景，可有效抵御各类常见 SQL 注入攻击，行为逻辑无异常。
4. 兼容性与影响：设计文档明确无兼容性影响，不影响现有业务 SQL 的正常执行，与 TDengine 现有版本、功能完全兼容，无需修改现有业务代码，适配性强；配置项仅在 taosd 第一次启动时加载，后续修改需通过指定机制操作，客户端配置缓存更新存在心跳周期延迟，该机制设计合理，不影响核心功能运行，相关设计细节清晰可落地。
5. 性能评估：启用 SQL 安全检查后，虽会增加字符串匹配、AST 遍历等校验操作，但文档中已明确优化方向（高优先级条件先检查、AST 缓存），可有效控制性能损耗，无需额外补充性能测试预期，能实现防护功能与系统性能的平衡。
