## 2. 评审记录

评审团队对设计文档进行了全面审查，认为整体设计合理，贴合外部窗口计算、时间偏移的实际业务场景需求，有效实现 TS-4900、TS-5707 相关需求，具体评审意见如下：
1. 功能完整性：明确了 ExternalWindow 的核心设计目标，针对性解决 TS-4900（外部窗口计算）、TS-5707（窗口时间偏移）两大需求，覆盖外部窗口生成、内外查询交互、窗口内计算、分组对齐、嵌套调用等核心功能；定义了完整的语法规范，新增 lag()、lead() 辅助函数及相关伪列，明确核心概念与语义模型；补充多类典型业务场景示例（故障报警、按钮-电梯门、动态复权因子等），覆盖不同使用场景；明确特殊场景处理、约束限制及运行时错误机制，功能设计完整，可满足外部窗口计算的核心业务需求，同时兼顾本期开发范围与未来扩展空间，无需额外补充功能。
2. 设计合理性：设计思路贴合实际业务痛点，引入外部查询定义窗口作用域的机制，打破窗口依赖自身时间线的局限，可适配外部数据、CSV文件、文本串等多种窗口来源，实用性强；语法规范设计严谨，完整定义 EXTERNAL_WINDOW 子句及相关语法规则，窗口实例的时间区间、属性引用、分组关联等逻辑清晰，与现有 SQL 语法兼容；分场景明确窗口排序、重叠、重复、非法窗口的处理规则，分组对齐逻辑（内外分组正交、自动关联匹配）贴合业务使用习惯；辅助函数（lag/lead）的设计贴合窗口计算需求，本期实现简单模式（前后1行），预留未来增强空间；整体设计兼顾语义清晰性、可落地性与扩展性，符合 TDengine 查询语法设计规范，同时同步实现两大需求，提升开发效率。
3. 行为逻辑正确性：ExternalWindow 的整体行为逻辑清晰，核心语义（窗口规范、窗口实例、时间区间开闭）定义准确、无歧义；窗口生成、内外查询交互、分组对齐、嵌套调用的行为逻辑合理，符合设计目标；特殊场景（乱序窗口、重叠窗口、分组匹配）的处理规则明确，运行时错误（无效窗口、时间区间异常）的判定与处理逻辑严谨，可有效避免异常场景影响功能运行；lag()、lead() 函数的功能逻辑、参数约束符合设计说明，窗口时间偏移的等效实现方式合理，与 TS-5707 需求完全匹配；约束限制（流计算、订阅暂不支持等）的逻辑一致，无矛盾点，行为逻辑无异常，可有效保障功能稳定运行。
4. 兼容性与影响：设计文档明确本期功能的约束范围（流计算、订阅暂不支持），不影响现有系统核心功能及已有查询语法；新增语法、辅助函数及伪列均为扩展内容，未修改原有功能逻辑，与 TDengine 现有版本、其他查询功能完全兼容；Insert into select、STMT 等支持场景的设计合理，变更范围可控；语法报错机制完善，对非法用法（如 WHERE 子句引用窗口属性列）、不支持场景均返回明确错误信息，避免误用，兼容性设计合理，可满足业务平滑升级与使用需求。
5. 性能评估：设计文档明确性能影响因素（分组/窗口数量、嵌套深度），未引入额外无效计算，窗口计算基于现有查询机制扩展，性能开销可控；本期开发范围聚焦核心功能，避免复杂逻辑导致的性能损耗，同时明确分组、窗口数量及嵌套深度对性能的影响，为后续性能优化提供方向；功能设计贴合实际业务场景，可满足故障报警、事件关联等常见场景的性能需求，能实现功能实用性与系统性能的平衡，无需额外补充性能优化措施。
