### 2. 安全评审记录

评审团队对设计文档进行了审查，评估其安全机制、架构和实现细节是否足以抵御威胁。具体评审意见如下：

#### 2.1 身份认证与访问控制

- **评审意见与发现：** 本功能通过 DSN 参数传递 KingHistorian 连接凭据（如 `kinghist://sa:sa@127.0.0.1:5678`），遵循 taosX 现有的 DSN 凭据管理框架。凭据的存储与保护由 taosX 统一处理，无新增认证逻辑。两个新功能（查询同步模式、点位自动更新）均复用现有连接凭据，不引入额外的身份校验表面。
- **状态：** 通过
- **说明/依据：** 凭据管理机制与现有 history 和 realtime 模式一致，无额外风险引入。

#### 2.2 数据安全

- **评审意见与发现：** 本功能采集的数据为工业设备时序数据（传感器/变量读数），属于内部运营数据，不含个人身份信息。数据传输路径为 KingHistorian Server → taosX（IPC SDK）→ TDengine，整条链路位于客户内网，数据安全依托现有网络隔离策略和 taosX 框架。FS 未涉及加密存储或传输加密的新增需求。
- **状态：** 不适用
- **说明/依据：** 功能定位为内网数据采集通道，数据安全依赖部署环境的网络安全边界，与现有采集模式一致。

#### 2.3 输入/输出验证与编码

- **评审意见与发现：** 新增 DSN 参数包括 `start`（datetime）、`time_range`（duration）、`restro`（duration）、`interval`（ms，number）、`sync_interval`（duration）、`update_interval`（s，number）、`update_mode`（枚举）。FS 第 4.1.2 和 4.2.2 节明确了各参数的类型和默认值。taosX 基于 Rust 实现，DSN 解析层提供强类型约束，非法格式将在解析阶段报错。`tag_name_mask` 为 KingHistorian SDK 原生表达式，由 SDK 自身处理。错误排查章节（第 10 节）描述了典型参数错误的排查方式，未见敏感信息泄露场景。
- **状态：** 通过
- **说明/依据：** Rust 类型系统在编译期和运行时提供输入约束，DSN 解析框架统一处理参数边界校验。

#### 2.4 会话与通信安全

- **评审意见与发现：** taosX 与 KingHistorian Server 的通信通过 KingHistorian SDK 的 IPC 协议完成，该协议为 Windows 平台专有协议，不在本 FS 的设计范围内。taosX 与 TDengine 之间的通信遵循现有连接框架（含 TLS 配置）。本功能未引入新的通信通道。
- **状态：** 不适用
- **说明/依据：** 通信安全由 KingHistorian SDK 和 taosX 现有框架分别负责，本功能无新增通信接口。

#### 2.5 安全日志与监控

- **评审意见与发现：** FS 第 11 节（可观测性）说明任务运行状态可通过 taos Explorer 的任务管理界面查看，查询同步任务进度可追踪。点位自动更新模式下，`KingHistPointUpdater` 组件周期性轮询并通过 flume 通道向 collector 推送新增点位，遵循 taosX 现有任务日志框架。整体可观测性设计与现有采集模式一致。
- **状态：** 通过
- **说明/依据：** 可观测性依托 taosX 现有任务状态管理机制，满足基本运维追踪需求。

#### 2.6 威胁缓解机制

- **评审意见与发现：** 威胁建模报告（TM-TSDB-KHQS-001）识别了 6 个威胁，主要集中在拒绝服务和信息泄露类别。设计中已内置关键缓解措施：（1）`interval` 参数限制查询频率，防止对 KingHistorian Server 造成过载（T-KHQS-03）；（2）`update_mode` 默认 `none`，三条件联合启用自动更新，降低误触发风险（T-KHQS-02）；（3）"只追加不删除"策略避免意外取消订阅造成数据中断（T-KHQS-04）。
- **状态：** 通过
- **说明/依据：** 交叉引用威胁建模报告 TM-TSDB-KHQS-001，主要威胁已在参数设计层面得到合理缓解。

#### 2.7 默认安全配置

- **评审意见与发现：** `update_mode` 默认值为 `none`（不启用点位自动更新），符合最小功能原则。点位自动更新需同时满足 `dataset_mode=Query`、`mode=realtime`、`update_mode=append` 三个条件，精准的启用门槛防止误用。查询同步模式需显式指定 `mode=sync` 或 `mode=query_sync`，不影响现有任务。
- **状态：** 通过
- **说明/依据：** 两个新功能均采用"显式启用"设计，默认配置不改变现有行为，符合安全默认配置原则。

#### 2.8 依赖组件安全

- **评审意见与发现：** 核心依赖为 KingHistorian SDK（Windows 专有），FS 第 9.2 节已明确说明该 SDK 仅支持 Windows 平台，功能在非 Windows 平台不可用。SDK 版本管理和已知漏洞追踪在 TSDB v3.4.1 SBOM 中统一管理，不在本 FS 范围内。
- **状态：** 不适用
- **说明/依据：** 依赖组件安全纳入 SBOM 管理流程，本 FS 无需重复覆盖。

#### 2.9 隐私设计

- **评审意见与发现：** 本功能采集工业设备时序数据（传感器读数、设备状态变量），不涉及个人身份信息（PII）。KingHistorian 为工业历史数据库，数据内容为设备运营数据，无隐私合规要求。
- **状态：** 不适用
- **说明/依据：** 功能定位于工业 IoT 数据采集，数据性质不涉及隐私法规约束范围。

#### 2.10 其他（可扩展性、运维安全等）

- **评审意见与发现：** FS 第 6 节（兼容性）明确指出两个新功能均为向后兼容设计：查询同步为新增模式，不影响现有 history/realtime；点位自动更新默认关闭，现有任务配置无需修改。FS 第 7 节（运维）标注为"无"，表明无特殊运维操作。功能扩展性良好，参数化设计支持灵活调整性能与实时性的平衡。
- **状态：** 通过
- **说明/依据：** 设计充分考虑向后兼容性，不引入新的运维安全风险。

### 3. 评审结论

1. **总体安全风险等级：** 低风险
   - 功能为内网数据采集扩展，不引入新的认证机制、外部接口或数据持久化方案。两个新功能均为向后兼容的参数化扩展，主要威胁场景（DoS、信息泄露）已在设计层面通过参数约束和默认安全配置得到缓解。

2. **评审结论：** 通过
   - 设计安全完备，能有效实现安全需求，准予进入开发/发布阶段。
