### 2. 安全评审记录

评审团队对设计文档进行了审查，评估其安全机制、架构和实现细节是否足以抵御威胁。具体评审意见如下：

#### 2.1 身份认证与访问控制

- **评审意见与发现：** FS 设计采用用户名/密码方式登录 IDMP 服务端，获取 Token 后用于后续 API 调用。Token 仅保存在进程内存中，不落盘（FS 第 6 节）。在 4xx 错误时自动重登录并重试一次（FS 第 4.1 节）。由于 MCP Server 是单用户 stdio 进程，本地无需额外访问控制层，认证完全依赖 IDMP 服务端。启动时检查验证码状态，若启用则主动退出，避免无法完成认证的情况。
- **状态：** 通过
- **说明/依据：** 认证方案符合该工具的定位——作为 IDMP 的 MCP 协议适配层，认证职责合理委托给 IDMP 服务端。Token 不持久化降低了凭据泄露风险。自动重登录机制仅重试一次，不会导致无限循环。

#### 2.2 数据安全

- **评审意见与发现：** FS 第 6 节明确指出：账号密码来自启动参数或环境变量，Token 仅保存在进程内存中不落盘。FS 建议生产环境使用 HTTPS 的 `base_url`，并建议避免在命令历史中明文传递 `--pass`，优先使用环境变量注入。该工具本身不存储、处理或缓存任何业务数据，仅做透传。
- **状态：** 通过
- **说明/依据：** 数据安全设计合理。工具定位为无状态代理层，不缓存业务数据，敏感凭据仅在内存中存活，降低了数据泄露面。FS 已给出密码传递的安全建议。

#### 2.3 输入/输出验证与编码

- **评审意见与发现：** 该工具对外暴露两个 MCP Tool：`chat(prompt: string)` 和 `system_config()`（FS 第 4.2 节）。`chat` 工具接收用户 prompt 字符串后直接透传给 IDMP `/api/v1/ai/chat/stream` 接口，输入验证由 IDMP 服务端负责。错误信息处理方面，FS 第 11 节列出了常见错误提示，均为功能性错误描述，未暴露内部路径或堆栈信息。
- **状态：** 通过
- **说明/依据：** 作为协议适配层，输入验证职责合理委托给 IDMP 服务端。工具自身仅做参数存在性检查（如缺少 prompt 时报错）。错误信息未泄露敏感的系统内部信息。

#### 2.4 会话与通信安全

- **评审意见与发现：** MCP Server 与客户端之间通过 stdio 通信（FS 第 8 节），属于本地进程间通信，不涉及网络传输。MCP Server 与 IDMP 服务端之间通过 HTTP/HTTPS 通信，FS 第 6 节建议生产使用 HTTPS `base_url`。Token 基于 IDMP 服务端的会话管理机制，失效时自动重登录。
- **状态：** 通过
- **说明/依据：** stdio 通信为本地管道，安全性由操作系统进程隔离保证。与 IDMP 服务端的通信安全取决于部署时是否使用 HTTPS，FS 已给出明确建议。

#### 2.5 安全日志与监控

- **评审意见与发现：** FS 第 12 节指出可观测性现状为"主要是进程标准日志"。从示例日志（FS 第 4.2 节）可以看出，工具调用和结果均有日志记录，包含时间戳和工具名称。但未设计专门的安全事件日志（如登录成功/失败、重登录触发等）。
- **状态：** 通过
- **说明/依据：** 作为轻量 CLI 工具，标准日志已覆盖主要操作记录。安全事件（登录、鉴权）的详细审计由 IDMP 服务端负责，MCP Server 作为客户端无需重复记录。进程标准日志已足够用于问题排查。

#### 2.6 威胁缓解机制

- **评审意见与发现：** 针对威胁建模报告中识别的威胁（详见「IDMP MCP Server - 威胁建模报告」），设计中已包含以下缓解措施：（1）针对 T-IDMPMCP-01 凭据泄露风险，FS 建议使用环境变量代替命令行参数传递密码；（2）针对 T-IDMPMCP-02 中间人风险，FS 建议生产使用 HTTPS；（3）针对 T-IDMPMCP-05 重登录滥用风险，设计限制仅重试一次。
- **状态：** 通过
- **说明/依据：** 对于该工具的攻击面规模，已有的缓解措施是合理的。主要安全防护依赖 IDMP 服务端（如认证、授权、输入验证、审计），MCP Server 自身的攻击面有限。

#### 2.7 默认安全配置

- **评审意见与发现：** 工具无默认端口监听，通过 stdio 通信（FS 第 8 节）。`base_url`、`user`、`pass` 均为必填项，无不安全的默认值。启动时强制校验登录配置和验证码状态。
- **状态：** 通过
- **说明/依据：** 默认配置安全。无网络监听端口，无硬编码凭据，无不安全的默认行为。必填参数设计避免了因遗漏配置导致的安全隐患。

#### 2.8 依赖组件安全

- **评审意见与发现：** 该工具依赖 IDMP HTTP API 服务（FS 第 4.2 节列出 4 个 API 端点）及 MCP SDK（stdio 模式）。工具以 Go 语言实现，编译为单二进制（FS 第 13 节）。
- **状态：** 通过
- **说明/依据：** Go 语言编译为静态二进制，减少运行时依赖风险。IDMP API 为公司内部服务，其安全性由 IDMP 产品团队负责。MCP SDK 为标准协议实现，风险可控。

#### 2.9 隐私设计

- **评审意见与发现：** 该工具不收集、存储或处理用户个人隐私数据。`chat` 工具传入的 prompt 和返回的 AI 回答均为透传，不在本地持久化。用户登录凭据仅在内存中存活。
- **状态：** 不适用
- **说明/依据：** 工具定位为无状态协议适配层，不涉及隐私数据的收集或处理，隐私保护由 IDMP 服务端负责。

#### 2.10 其他（可扩展性、运维安全等）

- **评审意见与发现：** 工具为单二进制部署，运维复杂度低（FS 第 8 节）。无管理接口、无配置文件持久化、无远程管理通道。工具生命周期与 MCP 客户端会话绑定，进程退出即清理所有内存状态。
- **状态：** 通过
- **说明/依据：** 简洁的架构设计减少了运维安全风险。无持久化状态意味着无需密钥轮换机制。进程退出即完成清理，不留残余敏感信息。
