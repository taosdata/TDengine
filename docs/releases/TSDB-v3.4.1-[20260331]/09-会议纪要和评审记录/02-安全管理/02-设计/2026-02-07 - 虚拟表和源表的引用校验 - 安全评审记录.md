### 2. 安全评审记录

评审团队对设计文档进行了审查，评估其安全机制、架构和实现细节是否足以抵御威胁。具体评审意见如下：

#### 2.1 身份认证与访问控制

- **评审意见与发现：** FS 第 6 节明确描述：「虚拟表的创建、查询与源表的权限体系保持一致，无额外权限配置，仅拥有源表查询权限的用户可创建并查询关联的虚拟表，防止未授权的源表数据访问」。权限控制复用现有权限体系，符合最小权限原则。新增的 `SHOW VTABLE VALIDATE FOR` 和 `SHOW REFERENCES FOR` 命令作为 DQL 操作，应受现有认证和连接鉴权保护。
- **状态：** 通过
- **说明/依据：** 权限继承机制清晰，无越权风险。虚拟表仅作为逻辑视图，不会绕过源表的权限校验。

#### 2.2 数据安全

- **评审意见与发现：** FS 第 6 节描述了两项关键数据安全设计：（1）**元数据安全**：系统表 `ins_virtual_tables_referencing` 仅支持查询，不支持插入、更新、删除，保证引用关系元数据不可篡改；（2）**数据隔离**：虚拟表为逻辑表，自身不存储任何实际数据，所有数据动态从源表获取，且虚拟表无法访问源表中未被引用的列/标签，实现了列级数据隔离。
- **状态：** 通过
- **说明/依据：** 系统表只读设计有效防止元数据篡改（对应威胁 T-VTREF-04）；列级隔离设计限制了数据访问范围（对应威胁 T-VTREF-06）。

#### 2.3 输入/输出验证与编码

- **评审意见与发现：** 新增的 `SHOW VTABLE VALIDATE FOR [db_name.]tableName` 和 `SHOW REFERENCES FOR [DB_NAME].TB_NAME` 命令接受表名作为输入，由 TDengine SQL 解析器统一处理参数校验，符合现有安全规范。FS 第 4.1.2 节与 4.1.3 节提到报错时「出错信息会尽可能清晰」，有助于用户定位问题，但实现时应注意错误信息不包含内部路径或系统敏感配置（对应威胁 T-VTREF-05）。
- **状态：** 通过
- **说明/依据：** SQL 解析层面已有标识符校验，不存在 SQL 注入风险。错误信息设计依赖实现阶段遵循现有规范。

#### 2.4 会话与通信安全

- **评审意见与发现：** 此功能为元数据查询功能，仅新增 SQL 语法层面的 SHOW 命令和系统表，不引入新的通信端点、协议或接口。通信安全完全复用 TDengine 现有机制（连接层加密、认证等）。
- **状态：** 不适用
- **说明/依据：** 未引入新通信端点，不在此项评审范围内。

#### 2.5 安全日志与监控

- **评审意见与发现：** `SHOW REFERENCES FOR` 是重量级操作（需遍历所有 VNODE 元数据，FS 第 5 节已说明），FS 第 8 节从运维角度建议避免频繁执行。此类高代价操作应纳入操作审计日志，以便排查集群性能问题时溯源（对应威胁 T-VTREF-07）。TDengine 现有审计框架应覆盖 DQL 操作。
- **状态：** 通过
- **说明/依据：** 依赖 TDengine 现有操作日志框架，SHOW 命令作为 DQL 操作已在审计覆盖范围内。

#### 2.6 威胁缓解机制

- **评审意见与发现：** 针对本次威胁建模报告（参见《虚拟表和源表的引用校验 - 威胁建模报告》）识别的主要威胁，FS 设计中的缓解情况如下：
  - **T-VTREF-01（DoS - SHOW REFERENCES 重量级查询）**：FS 第 8 节运维指南已提示，但未设计限流机制，建议实现阶段关注是否需要增加执行频率约束；
  - **T-VTREF-02/03（跨 DB 信息泄露）**：FS 权限管控描述覆盖了虚拟表创建和查询，对于 SHOW REFERENCES 和 SHOW VTABLE VALIDATE 结果集的权限过滤，实现时应与权限体系对齐；
  - **T-VTREF-04（系统表篡改）**：系统表只读设计已有效缓解；
  - **T-VTREF-05（错误信息泄露）**：实现阶段应遵循统一错误处理规范；
  - **T-VTREF-06（列级权限绕过）**：列级隔离设计已有效缓解。
- **状态：** 通过
- **说明/依据：** 主要威胁均已在设计层面有所考量，DoS 防护依赖运维规范，建议在实现阶段补充说明。

#### 2.7 默认安全配置

- **评审意见与发现：** 系统表 `ins_virtual_tables_referencing` 默认只读（不支持 INSERT/UPDATE/DELETE）；虚拟表权限默认与源表一致，无额外开放；无新增系统级配置项。默认状态即为安全配置。
- **状态：** 通过
- **说明/依据：** 系统表只读是硬约束，无需额外配置，默认安全。

#### 2.8 依赖组件安全

- **评审意见与发现：** 此功能不引入新的第三方库、外部框架或外部服务依赖，完全基于 TDengine 内部组件（mnode/vnode 元数据系统）实现。
- **状态：** 不适用
- **说明/依据：** 无新增第三方依赖，不在此项评审范围内。

#### 2.9 隐私设计

- **评审意见与发现：** TDengine 为工业物联网时序数据库，此功能处理的是表结构元数据（表名、列名、引用关系），通常不涉及个人隐私数据。FS 描述的使用场景（智能电表、传感器）亦为工业数据。
- **状态：** 不适用
- **说明/依据：** 该功能不涉及个人隐私数据处理，不在此项评审范围内。

#### 2.10 其他（可扩展性、运维安全等）

- **评审意见与发现：** FS 第 5 节对性能特性有明确说明（SHOW REFERENCES 为重量级查询，虚拟表常规查询与源表基本一致），第 8 节提供了运维操作指导，覆盖源表变更前的引用关系检查、列长度修改规则和大集群下的查询频率建议。运维操作文档完整。无新增密钥/证书管理需求。
- **状态：** 通过
- **说明/依据：** 运维安全文档已充分描述，性能风险已明确告知，无额外运维安全问题。

### 3. 评审结论

1. **总体安全风险等级：** 低风险
   - 该功能为元数据查询功能，不引入新的认证机制、通信端点或第三方依赖。FS 第 6 节已从数据完整性、权限管控、元数据安全、数据隔离四个维度进行了明确的安全设计，整体安全设计完备，能有效实现安全需求，可进入开发阶段。

2. **评审结论：** 通过
   - 准予进入下一阶段（编码实现）。主要威胁已在设计中得到缓解，建议实现阶段关注 SHOW REFERENCES/SHOW VTABLE VALIDATE 结果集的权限过滤与错误信息规范，无需重新评审。
