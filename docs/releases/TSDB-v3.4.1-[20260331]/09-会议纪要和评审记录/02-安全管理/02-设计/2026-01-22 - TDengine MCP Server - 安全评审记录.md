### 2. 安全评审记录

评审团队对设计文档进行了审查，评估其安全机制、架构和实现细节是否足以抵御威胁。具体评审意见如下：

#### 2.1 身份认证与访问控制

- **评审意见与发现：** MCP Server 通过 `--user` / `--pass`（或 `TDENGINE_USER` / `TDENGINE_PASS` 环境变量）配置单一 TDengine 账号凭据，并以该账号身份执行所有工具调用。FS 未对 TDengine 账号权限等级给出明确约束，存在使用高权限账号（如 `root`）运行的风险。从 `SHOW USERS FULL`、`SHOW USER PRIVILEGES`、`SHOW GRANTS FULL` 等工具可知，高权限账号被配置后，任意 MCP Client 均可通过 `show` 工具枚举集群用户与权限体系。
- **状态：** 待定
- **说明/依据：** 建议在部署文档中明确要求为 MCP Server 创建专用只读账号，授予仅满足工具所需的最小权限（SELECT + 相关 SHOW 权限），禁止使用 `root` 或超级用户账号。

#### 2.2 数据安全

- **评审意见与发现：** FS 第 6 节明确说明"配置支持环境变量避免泄漏信息"，推荐通过 `TDENGINE_PASS` 等环境变量传递凭据，规避命令行历史（`ps aux`）导致的凭据暴露风险。`SchemaOverviewFilePath` 指向本地只读文件，不含写操作，文件内容为静态业务描述文本，数据安全风险低。TDengine 连接可通过 `DSN` 配置项灵活设置连接参数（含 TLS），支持加密传输。
- **状态：** 通过
- **说明/依据：** 环境变量配置机制已实现凭据保护基线；DSN 配置项支持按需启用 TLS，满足传输安全需求。

#### 2.3 输入/输出验证与编码

- **评审意见与发现：** 两项核心输入路径均实施了严格约束：① `show` 工具通过枚举白名单限制 `metadata` 参数，涵盖 80+ 种合法 SHOW 规则，未知规则直接拒绝（返回 `unsupported show metadata item`）；② `query` 工具强制限制为 SELECT 语句，非 SELECT 语句在执行前即被拒绝（返回 `only select statements are allowed`）。参数校验完整，错误信息均为通用描述，不泄露系统内部路径或堆栈信息（见 FS 第 11 节常见错误列表）。
- **状态：** 通过
- **说明/依据：** `show` 枚举白名单防止任意 SHOW 语句注入；`query` SELECT 限制防止 DDL/DML/管理类语句执行；输入参数类型校验完备，已覆盖主要注入路径。

#### 2.4 会话与通信安全

- **评审意见与发现：** MCP Server 以 `stdio` 方式运行，由 AI 工具（如 Claude Desktop、Cursor）作为子进程启动，MCP Client ↔ MCP Server 通信在本地进程间完成，无网络暴露面。MCP Server ↔ TDengine 的连接参数通过 `DSN` 配置项支持按需启用 TLS。FS 未提供独立的 TLS 开关配置项，但 DSN 方式已覆盖该需求。
- **状态：** 通过
- **说明/依据：** stdio 本地通信模式无传统网络会话风险；TDengine 侧 TLS 可通过 DSN 配置，满足加密传输基本需求。

#### 2.5 安全日志与监控

- **评审意见与发现：** FS 第 12 节与各工具示例表明，所有 MCP Tool 调用（含工具名、入参、响应结果）均以 INFO 级别记录日志，时间戳精确到毫秒，日志源标识包含 MCP 服务器实例名。日志提供完整的操作溯源能力。注意：日志中完整记录查询结果，包含 `SHOW USERS` 返回的用户名、角色、允许主机等敏感配置信息，需对日志存储权限进行适当管控。
- **状态：** 通过
- **说明/依据：** 操作溯源信息完整；日志敏感性由日志文件访问控制在运维层面管理，属部署侧责任，不影响设计层面安全评估。

#### 2.6 威胁缓解机制

- **评审意见与发现：** 针对 MCP Server 主要威胁的缓解措施如下（交叉引用威胁建模报告）：① T-MCP-01（SQL注入）：`query` 限制 SELECT、`show` 枚举白名单，已有效缓解；② T-MCP-02（元数据过度暴露）：通过枚举白名单限制可查询的元数据类型，范围可控；③ T-MCP-04（资源耗尽）：`query` 默认 `max_rows=500`，LLM 调用时有缺省保护；`max_rows=-1` 为可选配置，由调用方承担相应风险；④ T-MCP-05（凭据泄露）：环境变量机制已缓解命令行暴露风险。
- **状态：** 通过
- **说明/依据：** 核心威胁均有对应防护措施；`max_rows=-1` 的无限查询风险在面向受信 LLM Agent 的部署场景下属可接受的设计权衡。

#### 2.7 默认安全配置

- **评审意见与发现：** `query` 工具 `max_rows` 默认值为 500，限制单次查询返回行数，防止 LLM 调用触发大规模数据扫描。`show` 工具通过枚举参数隐式约束了操作范围。`get_schema_overview` 在 `SchemaOverviewFilePath` 为空时不注册该工具，遵循最小暴露原则。未发现默认开启不安全选项的配置。
- **状态：** 通过
- **说明/依据：** 默认配置遵循最小暴露原则，`max_rows=500` 提供合理的缺省保护。

#### 2.8 依赖组件安全

- **评审意见与发现：** MCP Server 依赖标准 MCP 协议库（版本兼容 2024-11-05、2025-03-26、2025-06-18）及 TDengine 官方 Go 驱动。MCP 协议为 Anthropic 开源协议，TDengine Go 驱动为官方维护组件，均属受控依赖。FS 未引入高风险第三方库。
- **状态：** 通过
- **说明/依据：** 依赖组件来源可信，无已知高风险第三方库引入。

#### 2.9 隐私设计

- **评审意见与发现：** TDengine MCP Server 定位为面向工业物联网时序数据的查询代理，FS 无明确 PII 处理需求。
- **状态：** 不适用
- **说明/依据：** 产品无 PII 处理设计需求，隐私设计评审维度不适用。

#### 2.10 其他（可扩展性、运维安全等）

- **评审意见与发现：** 凭据更新通过修改环境变量并重启服务实现，无热更新机制，符合此类轻量工具的运维模式。`get_schema_overview` 文件仅在启动时读取，文件内容异常时直接退出（Fail-Fast），避免带错误配置运行。MCP 配置存储于 AI 工具的本地配置文件，受操作系统文件权限保护。
- **状态：** 通过
- **说明/依据：** 运维操作模式简洁明确；Fail-Fast 策略优于静默忽略错误配置。

### 3. 评审结论

1. **总体安全风险等级：** 低风险
   - 系统设计通过枚举白名单与 SELECT 限制有效收窄攻击面；以 stdio 本地通信方式消除网络暴露；核心安全机制均已实现并在 FS 中得到体现。

2. **评审结论：** 有条件通过
