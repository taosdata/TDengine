### 2. 安全评审记录

评审团队对设计文档进行了审查，评估其安全机制、架构和实现细节是否足以抵御威胁。具体评审意见如下：

#### 2.1 身份认证与访问控制

- **评审意见与发现：** 本功能为 Interval 窗口的 `fill` 子句新增 `surrounding_time_interval` 和 `fill_values` 参数，以及 `surround` 子句，属于 SQL 查询语法扩展。该功能不引入新的身份认证机制或访问控制模型，用户执行包含新语法的查询时，仍复用现有的数据库连接认证与权限校验体系。查询结果的数据访问范围受 `where` 条件约束（FS 4.0.3.1 节明确说明"Sti 不会破坏 `where` 条件，探索数据将同时满足这两个限制"），不会绕过已有的权限边界。
- **状态：** 不适用
- **说明/依据：** 纯查询语法扩展，不涉及认证与授权变更，复用已有权限体系。

#### 2.2 数据安全

- **评审意见与发现：** 该功能仅改变查询时的数据探索范围和插值逻辑，不涉及新的数据存储、传输或加密方案。插值操作作用于查询结果集（窗口聚合数据），不修改底层原始数据。`fill_values` 作为默认填充值在查询执行期间使用，不进行持久化存储。数据隔离和多租户安全机制不受影响。
- **状态：** 不适用
- **说明/依据：** 不涉及新的数据存储或传输，原始数据只读，无数据安全新风险。

#### 2.3 输入/输出验证与编码

- **评审意见与发现：** 新增的 SQL 参数通过现有 SQL 解析器进行词法和语法分析，参数校验规则在 FS 中有明确定义：(1) `surrounding_time_interval` 数值需大于 0，在 interval 子句中需大于等于 interval 值，不支持年（y）和月（n）作为时间单位；(2) `fill_values` 数目必须与 `select_list` 元素数目一致，且必须能正确解析为对应列数据类型。这些约束由解析器和执行器在编译期与运行期强制校验，畸形输入将被拒绝并返回错误码，不会泄露内部信息。
- **状态：** 通过
- **说明/依据：** FS 明确定义了参数取值范围与类型约束，复用现有 SQL 解析器的输入校验框架，参数校验规则清晰完整。

#### 2.4 会话与通信安全

- **评审意见与发现：** 本功能不引入新的通信协议、网络端口或 RPC 接口，所有查询通过现有客户端-服务器通道传输，会话管理和 TLS 配置不受影响。
- **状态：** 不适用
- **说明/依据：** 无新的通信路径或会话机制。

#### 2.5 安全日志与监控

- **评审意见与发现：** 使用新语法的查询与普通查询一样，纳入现有的慢查询日志和审计日志框架。FS 未提出新的安全日志需求，基于该功能的纯查询扩展性质，现有日志机制已足够。
- **状态：** 不适用
- **说明/依据：** 复用现有查询审计和慢查询日志，无额外安全事件需要记录。

#### 2.6 威胁缓解机制

- **评审意见与发现：** 根据威胁建模报告（参见 T-ITVFILL-01 至 T-ITVFILL-05），本功能的主要威胁集中在资源消耗方面。针对 T-ITVFILL-02（超大 `surrounding_time_interval` 导致资源耗尽），FS 设计中 interval 窗口的实际数据探索范围受公式 ⌊sti/w⌋ 约束，配合现有查询超时机制可有效缓解。其余威胁（SQL 解析安全、类型校验、流计算资源控制）均由现有框架覆盖。
- **状态：** 通过
- **说明/依据：** 已识别威胁均为低-中风险，现有机制可有效缓解，详见威胁建模报告。

#### 2.7 默认安全配置

- **评审意见与发现：** 本功能的新参数 `surrounding_time_interval` 和 `fill_values` 均为可选参数，缺省时不对探索范围进行限制，保持与现有行为一致。不引入新的配置项或默认端口，不改变系统默认安全配置。
- **状态：** 不适用
- **说明/依据：** 无新配置项，缺省行为与现有功能一致。

#### 2.8 依赖组件安全

- **评审意见与发现：** 本功能在现有 SQL 解析器和执行引擎基础上扩展，不引入新的第三方库、外部框架或外部服务依赖。
- **状态：** 不适用
- **说明/依据：** 无新依赖组件。

#### 2.9 隐私设计

- **评审意见与发现：** 本功能不涉及个人信息收集、处理或存储，不改变数据主体权利的实现方式。插值结果为基于已有数据的计算值，不涉及隐私数据的新增暴露。
- **状态：** 不适用
- **说明/依据：** 不涉及隐私数据处理。

#### 2.10 其他（可扩展性、运维安全等）

- **评审意见与发现：** 本功能为查询语法扩展，不涉及密钥管理、证书轮换或运维管理通道。FS 第 5 节提及预期性能衰减小于 5%，对系统可用性影响可控。流计算场景下每个触发窗口的计算相互独立（FS 4.0.5 节），不会因跨窗口数据引用引入额外复杂性。
- **状态：** 不适用
- **说明/依据：** 不涉及运维安全和密钥管理，性能影响可控。

### 3. 评审结论

1. **总体安全风险等级：**
  - 低风险：该功能为纯 SQL 查询语法扩展，不引入新的攻击面、网络接口或数据存储机制。参数校验规则清晰，数据访问范围受现有权限体系约束，安全设计完备。

2. **评审结论：**
  - 通过：准予进入下一阶段（编码实现）。该功能安全风险极低，现有安全框架足以覆盖所有已识别威胁。

### 4. 后续行动项

无。本次评审各维度均为"通过"或"不适用"，未发现需要后续跟进的安全缺陷。
