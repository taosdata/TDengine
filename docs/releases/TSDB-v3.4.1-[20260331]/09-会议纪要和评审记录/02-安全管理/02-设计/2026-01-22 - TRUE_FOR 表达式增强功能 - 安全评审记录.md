### 2. 安全评审记录

评审团队对设计文档进行了审查，评估其安全机制、架构和实现细节是否足以抵御威胁。具体评审意见如下：

#### 2.1 身份认证与访问控制

- **评审意见与发现：** TRUE_FOR 表达式增强功能属于纯 SQL 语法扩展，不引入新的认证或授权机制。使用该功能（CREATE STREAM、SELECT）的权限校验完全依赖 TDengine 现有的访问控制体系，无新增访问控制面。
- **状态：** 不适用
- **说明/依据：** FS 中未定义任何认证/鉴权相关逻辑，功能本身不涉及用户身份或权限的变更；现有系统的权限控制（表级、流级权限）对该语法扩展同样生效。

#### 2.2 数据安全

- **评审意见与发现：** 本功能仅扩展窗口触发条件的判断逻辑（COUNT 阈值判断 + AND/OR 组合），不涉及任何敏感数据的存储、传输或加密方案变更，数据流路径与原有窗口计算一致。
- **状态：** 不适用
- **说明/依据：** FS 第 6 节"安全"明确表述"不涉及"；功能不新增数据持久化路径，COUNT 计数器为纯内存状态量，随窗口生命周期销毁。

#### 2.3 输入/输出验证与编码

- **评审意见与发现：** FS 第 4.5 节对四类参数错误均给出了明确的错误处理规范：① COUNT 为负数；② COUNT 超出 INT32_MAX；③ 在不支持的窗口类型（INTERVAL/SESSION）上使用；④ 语法格式错误。错误信息内容明确，不包含内部路径、内存地址等敏感系统信息。COUNT 参数有效范围（0 ≤ COUNT ≤ 2,147,483,647）已在 FS 第 4.2.1 节清晰定义，解析层须对输入进行严格边界校验。
- **状态：** 通过
- **说明/依据：** 设计上对所有非法输入均有对应错误码和提示，未见遗漏。错误消息（如 `COUNT must be a non-negative integer not exceeding 2147483647`）不暴露系统内部状态。

#### 2.4 会话与通信安全

- **评审意见与发现：** 本功能为 SQL 层语法扩展，不涉及会话管理、TLS 配置或内部组件通信协议的变更。
- **状态：** 不适用
- **说明/依据：** 语法解析与窗口计算在现有执行引擎内处理，不新增对外暴露的接口或通信通道。

#### 2.5 安全日志与监控

- **评审意见与发现：** FS 第 12 节"可观测性"明确表述"不涉及"。使用 TRUE_FOR 新语法创建流任务的操作，可通过 TDengine 现有的 CREATE STREAM 操作审计日志进行溯源，无需新增专项日志机制。
- **状态：** 不适用
- **说明/依据：** 该功能属于 SQL 语法级增强，语法中 COUNT 阈值参数作为 SQL 语句的一部分，已可通过现有 SQL 审计日志记录。

#### 2.6 威胁缓解机制

- **评审意见与发现：** 主要关注威胁为流任务窗口永不触发引发的内存累积风险（详见威胁建模报告 T-TRUEFOR-01）。FS 第 4.2.1 节通过限制 COUNT 上界为 INT32_MAX、COUNT 0 等同无约束来收窄极端配置，但对超大 COUNT 值导致流任务内存长期累积的场景暂无明确防护设计。该风险整体可接受（攻击者需要有创建流的权限）。
- **状态：** 通过
- **说明/依据：** 交叉参考威胁建模报告 T-TRUEFOR-01（中危）、T-TRUEFOR-02（低危）、T-TRUEFOR-03（低危）、T-TRUEFOR-04（低危）。该功能安全攻击面极小，整体防护完备。

#### 2.7 默认安全配置

- **评审意见与发现：** 本功能不引入任何新的可配置项，无默认配置需评估。现有语法默认不指定 COUNT，即等同于原有仅时间触发的行为，保持向后兼容（FS 第 7 节"兼容性：完全兼容"）。
- **状态：** 不适用
- **说明/依据：** 无新增配置项，不存在"默认不安全配置"风险。

#### 2.8 依赖组件安全

- **评审意见与发现：** 本功能为 TDengine 内部 SQL 解析器和流计算引擎的语法扩展，不引入新的第三方库或外部服务依赖。
- **状态：** 不适用
- **说明/依据：** FS 未提及任何新增外部依赖（第 15 节"参考文档：无"）。

#### 2.9 隐私设计

- **评审意见与发现：** 本功能处理的是时序数据窗口聚合的触发条件，不涉及个人身份信息（PII）的收集、存储或处理，无隐私合规需求。
- **状态：** 不适用
- **说明/依据：** 典型使用场景（传感器状态监控、告警聚合、用户行为分析）中，功能本身不负责数据内容的处理，仅控制窗口触发时机。

#### 2.10 其他（可扩展性、运维安全等）

- **评审意见与发现：** FS 第 8 节"运维：不涉及"。功能扩展本身为无状态语法规则，无密钥轮换、运维通道等安全考量。FS 第 10.1 节注明流任务 TRUE_FOR 条件不支持动态修改，变更需删除重建，该约束不引入额外安全风险。
- **状态：** 不适用
- **说明/依据：** 语法级别变更，不涉及密钥、证书、管理接口等运维安全要素。

### 3. 评审结论

1. **总体安全风险等级：** 低风险
   - 安全设计完备，功能仅为 SQL 语法层扩展，新增攻击面极小。现有的输入验证和错误处理设计已覆盖主要风险点。可进入开发阶段。

2. **评审结论：** 通过
   - 准予进入下一阶段（编码实现）。
