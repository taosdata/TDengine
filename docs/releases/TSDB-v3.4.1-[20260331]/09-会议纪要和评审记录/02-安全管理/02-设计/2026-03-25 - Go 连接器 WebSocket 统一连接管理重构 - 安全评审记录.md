### 2. 安全评审记录

评审团队对设计文档进行了审查，评估其安全机制、架构和实现细节是否足以抵御威胁。具体评审意见如下：

#### 2.1 身份认证与访问控制

- **评审意见与发现：** FS 设计支持多种认证机制：用户名/密码（Config.User、Config.Passwd）、云服务 Token（附加到 Endpoint URL query string）、Bearer Token 以及 TOTP 双因素认证。认证凭据在 `Connect()` 阶段通过 Bootstrap 握手过程传递给服务端。多节点 failover 场景下，重连后会重新执行 Bootstrap 握手，确保新连接经过完整认证流程。访问控制由服务端（taosAdapter / taosd）负责，客户端 SDK 不涉及授权模型设计。
- **状态：** 通过
- **说明/依据：** 认证方案完整，覆盖了单节点、多节点、云服务等多种部署场景。Token 和 Bearer Token 互斥设计合理。TOTP 支持为双因素认证提供了基础。Bootstrap 在每次连接建立（含重连）时都会执行，确保认证一致性。

#### 2.2 数据安全

- **评审意见与发现：** FS 第 6 节"安全"明确提出：（1）错误消息中对 OTP 等敏感字段进行脱敏处理（`request_log_context.go` 中的 OTP redaction）；（2）密码不出现在错误日志和 DSN 字符串回显中；（3）Bootstrap 握手过程通过安全通道传递认证凭据。Config 结构体中密码以明文保存在内存中，这是 Go 数据库驱动的标准做法（如 `database/sql`），在客户端 SDK 场景下可接受。
- **状态：** 通过
- **说明/依据：** 敏感数据保护措施已在设计中体现，密码和 OTP 的日志脱敏是关键安全特性。内存中明文凭据在客户端 SDK 场景下属于行业通用做法，风险可接受。

#### 2.3 输入/输出验证与编码

- **评审意见与发现：** DSN 解析模块（`ParseDSN`）对连接字符串进行结构化解析和验证，不匹配的参数存入 `Params` map 透传。配置验证层提供 `ErrNilConfig`、`ErrNoEndpoints` 等预定义错误。TMQ ConfigMap 对 `group.id` 等必选参数进行连接前校验。`NormalizeEndpoints` 函数对端点列表进行验证和归一化处理。stmt2 二进制协议使用固定 28 字节头部结构，解析规则明确。错误信息通过统一 `Error` 类型返回，`RequestSummary` 为惰性生成，避免不必要的信息暴露。
- **状态：** 通过
- **说明/依据：** 输入验证覆盖了 DSN、Config、TMQ ConfigMap 等主要入口。二进制协议使用定长头部，降低了解析错误风险。错误信息已做脱敏处理。

#### 2.4 会话与通信安全

- **评审意见与发现：** FS 支持 WSS（WebSocket Secure）加密连接，通过 `wss://` scheme 启用 TLS 传输加密。DSN 参数示例中明确展示了 WSS 用法（如 `root:taosdata@wss(localhost:6041)/test`）。WebSocket 压缩通过 `enableCompression` 参数可选启用。Bootstrap 握手在每次连接建立时执行，包括 failover 切换后的新连接。Generation 机制和 `reconnectLock` 确保连接状态一致性，防止陈旧连接覆盖。`pendingRequests` 通过 RWMutex 保护，确保并发安全。
- **状态：** 通过
- **说明/依据：** WSS 支持为传输层加密提供了保障。会话管理通过 Generation 版本号机制实现状态一致性，是成熟的连接管理方案。`reconnectLock` 确保重连过程的互斥性。

#### 2.5 安全日志与监控

- **评审意见与发现：** 统一错误模型 `unified.Error` 提供了丰富的错误分类（8 种 ErrorType）和诊断信息。`RequestSummary` 提供失败请求的完整上下文（操作类型、目标地址、req_id），方便故障排查。`SetErrorHandler` 回调允许上层应用捕获异步错误事件。OTP 等敏感字段在日志中已做脱敏处理。
- **状态：** 通过
- **说明/依据：** 错误诊断信息充分且做了敏感数据脱敏。ErrorHandler 回调机制为上层监控提供了接入点。作为客户端 SDK，日志和监控的主要职责在使用方应用层，SDK 提供的诊断能力已满足需求。

#### 2.6 威胁缓解机制

- **评审意见与发现：** 针对威胁建模报告中识别的威胁，设计中已包含以下缓解措施：（1）凭据泄露防护（T-GOWSUNIFY-01）：密码和 OTP 脱敏处理；（2）中间人攻击防护（T-GOWSUNIFY-02）：WSS 加密连接支持；（3）重连风暴防护（T-GOWSUNIFY-04）：`reconnectIntervalMs` 和 `reconnectRetryCount` 参数限制重连频率和次数；（4）连接状态混淆防护（T-GOWSUNIFY-06）：Generation 机制和 reconnectLock 互斥锁。
- **状态：** 通过
- **说明/依据：** 主要威胁场景均有对应的缓解机制。WSS 加密、凭据脱敏、重连节流、状态版本控制等措施构成了合理的纵深防御。

#### 2.7 默认安全配置

- **评审意见与发现：** 默认配置遵循安全优先原则：`autoReconnect` 默认 `false`（需显式启用）；`readTimeout` 默认 5 分钟、`writeTimeout` 默认 10 秒（防止无限等待）；`enableCompression` 默认 `false`（减少攻击面）；`reconnectRetryCount` 默认 3 次（避免无限重试）；`reconnectIntervalMs` 默认 2000ms（避免过于频繁的重连）。
- **状态：** 通过
- **说明/依据：** 默认值选择保守且合理，高可用特性需显式启用，超时配置有明确上限，不会造成资源泄漏。

#### 2.8 依赖组件安全

- **评审意见与发现：** 设计依赖 Go 标准库和成熟的 WebSocket 库（`ws/client.Client`）。`runtime.memmove` 通过 `unsafe.Pointer` 实现高性能内存复制，使用范围限定在 stmt2 二进制帧组装（`common/stmt/mem`），属于受控的性能优化手段。依赖 taosAdapter 作为 WebSocket 网关，其安全性由服务端保障。
- **状态：** 通过
- **说明/依据：** `unsafe.Pointer` 的使用限定在明确的内存复制场景中，不涉及任意指针操作。依赖组件为 Go 生态成熟库，安全风险可控。

#### 2.9 隐私设计

- **评审意见与发现：** 本功能为客户端 SDK 连接管理层重构，不直接处理终端用户个人隐私数据。密码和认证令牌的保护已在 2.2 数据安全中评审。
- **状态：** 不适用
- **说明/依据：** 客户端 SDK 连接器不涉及个人隐私数据的收集、存储或处理，隐私设计维度不适用。

#### 2.10 其他（可扩展性、运维安全等）

- **评审意见与发现：** （1）可扩展性：`Option` 函数模式（`WithDialFunc`、`WithClientFactory`）为连接建立和 Runtime 构建提供了扩展点，便于未来接入新的安全机制。（2）运维安全：多节点 failover 和自动重连减少了运维干预需求。`RequestSummary` 诊断信息支持故障排查。（3）向后兼容：通过包装层和类型别名保持 API 兼容，降低了升级风险。（4）资源管理：Envelope 池化减少内存分配，`drainSendChan` 在连接关闭时正确清理待发送消息。
- **状态：** 通过
- **说明/依据：** 架构设计具备良好的可扩展性和运维友好性。资源管理机制合理，不存在明显的泄漏风险。

### 3. 评审结论

1. **总体安全风险等级：**
  - 低风险：安全设计完备，能有效实现安全需求，可进入开发阶段。
2. **评审结论：**
  - 通过：准予进入下一阶段（编码实现）。

本次重构将分散在多个包中的 WebSocket 连接管理统一到 `ws/unified` 包，在架构层面减少了安全实现不一致的风险。设计已覆盖凭据保护、传输加密、连接状态安全等关键维度，且默认配置保守合理。作为客户端 SDK 内部重构，未引入新的外部攻击面，主要安全边界仍由服务端（taosAdapter / taosd）保障。

无需后续行动项。所有评审维度均为"通过"或"不适用"状态，设计方案的安全性满足要求。
