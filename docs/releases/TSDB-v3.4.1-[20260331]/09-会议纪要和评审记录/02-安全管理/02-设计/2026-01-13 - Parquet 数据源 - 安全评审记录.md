### 2. 安全评审记录

评审团队对设计文档进行了审查，评估其安全机制、架构和实现细节是否足以抵御威胁。具体评审意见如下：

#### 2.1 身份认证与访问控制

- **评审意见与发现：** Parquet 数据源为 taosX 内部的文件读取模块，不独立提供网络服务或用户入口，无需设计独立的认证/授权机制。文件访问控制完全依托操作系统文件权限（§6.1.2：「遵守操作系统的文件权限控制」），taosX 进程以其自身的 OS 用户身份运行，原则上满足最小权限要求。
- **状态：** 不适用
- **说明/依据：** 本功能为数据导入插件，不引入新的认证接口；依赖操作系统权限控制，属于现有 taosX 安全框架范畴。

#### 2.2 数据安全

- **评审意见与发现：** Parquet 数据源处理本地文件系统上的列式数据文件，FS 未设计针对源文件的加密需求，符合批量数据导入工具的惯常做法。导入过程中数据以 Apache Arrow Record Batch 格式在内存中流转（§16.1.3 数据流），为非持久化中间态，无需额外加密。目标端 TDengine 连接的传输安全超出本 FS 范围。无敏感凭证存储于 Parquet DSN 配置中。数据完整性方面，§6.3.1 明确「使用 Parquet 格式内置的校验和机制」，可有效检测损坏数据。
- **状态：** 通过
- **说明/依据：** 数据导入工具对源文件加密无要求；内置校验和保障完整性；传输安全由目标端负责。

#### 2.3 输入/输出验证与编码

- **评审意见与发现：** FS 在 §6.1.1 明确要求「验证文件路径的合法性，防止路径遍历攻击」，对路径输入的安全意识良好。§4.4 定义了文件不存在、格式错误、列投影错误三类错误处理，其中列投影错误采用自动过滤不存在列的策略（§4.4.3），避免因异常输入导致崩溃。错误消息示例（§4.4.1、§11.1）包含完整文件路径，如 `/data/sensors.parquet: No such file or directory`，与 §6.1.3「不泄露敏感路径信息」的要求存在轻微不一致；但考虑到本工具面向系统管理员使用，路径信息在错误反馈中属合理范畴。数值参数 `batch_size` 和 `unprocessed_batches` 的范围校验逻辑在 FS 中未明确描述，建议实现层确保非负且合理上限。
- **状态：** 通过
- **说明/依据：** 已明确路径遍历防护要求；错误信息处理在管理员工具场景下可接受；数值参数验证为常规实现要求。

#### 2.4 会话与通信安全

- **评审意见与发现：** 本功能为本地文件批量读取模块，无需维护会话状态，无独立对外网络接口。与 TDengine 目标端的通信安全由 taosX 目标连接机制统一管理，超出本 FS 设计范围。
- **状态：** 不适用
- **说明/依据：** 无网络服务接口，无会话管理需求。

#### 2.5 安全日志与监控

- **评审意见与发现：** §4.5 定义了任务级别的日志输出，包含 INFO（任务开始/完成）和 ERROR（读取失败详情）两类，可满足基本运维溯源需求。日志格式示例（`INFO Parquet to taos, from: parquet:..., to: taos://localhost:6030/test_db`）记录了完整的目标端 DSN，若实际连接字符串含用户名和密码（如 `taos://admin:pwd@host:6030/db`），将在日志中明文暴露凭证。此问题与 taosX 其他数据源的日志行为一致，属整体平台层面需关注的模式。§8.2 补充说明支持任务状态通知机制，错误时提供详细上下文，运维友好。
- **状态：** 通过
- **说明/依据：** 日志满足基本溯源需求；DSN 凭证脱敏问题属 taosX 平台层面已知模式，非本功能新引入风险。

#### 2.6 威胁缓解机制

- **评审意见与发现：** 对照威胁建模报告（见《Parquet 数据源 - 威胁建模报告》），主要威胁的缓解措施分析如下：
  - **T-PARQUET-01（路径遍历）**：§6.1.1 明确要求路径验证，已有设计意识；
  - **T-PARQUET-02（恶意文件解析漏洞）**：采用 Rust 语言 `parquet` crate 实现，Rust 内存安全特性大幅降低解析器漏洞利用风险；
  - **T-PARQUET-03（资源耗尽）**：通过 `batch_size`（默认 1000）和 `unprocessed_batches`（默认 64）双重背压控制机制（§6.2.1/§5.1.5）有效缓解；
  - **T-PARQUET-04（DSN 凭证日志泄露）**：见 2.5 节分析；
  - **T-PARQUET-05（文件写入竞争）**：以只读方式打开文件，OS 层提供一定保护；
  - **T-PARQUET-06（列投影滥用）**：不存在列自动过滤（§4.4.3），无法访问超出文件自身定义范围的数据。
- **状态：** 通过
- **说明/依据：** 主要威胁均有相应缓解措施，Rust 语言本身为解析安全提供额外保障。

#### 2.7 默认安全配置

- **评审意见与发现：** 默认参数配置：`batch_size=1000`、`unprocessed_batches=64`（§4.1.1），在提供合理吞吐性能的同时对内存占用形成约束，属安全合理的默认值。本功能不新增网络监听端口，不引入新的对外服务，默认配置满足最小攻击面原则。
- **状态：** 通过
- **说明/依据：** 默认值在性能与资源限制间取得平衡，无不安全的默认开放项。

#### 2.8 依赖组件安全

- **评审意见与发现：** 核心依赖组件包括（§16.1）：`parquet` crate（Apache Arrow 官方 Rust 实现）、`arrow` crate（Apache Arrow 格式）、`tokio`（异步运行时）、`flume`（channel 库）。上述均为 Rust 生态中成熟且被广泛审计的库，以 Rust 语言特性保障内存安全。FS 未单独描述依赖版本固定或 CVE 扫描策略，此类管理属 taosX 工程构建体系统一负责。
- **状态：** 通过
- **说明/依据：** 所用依赖均为业界成熟 Rust 库，内存安全有语言层面保障；版本管理属项目工程实践范畴。

#### 2.9 隐私设计

- **评审意见与发现：** Parquet 数据源为通用数据导入工具，处理的时序数据内容由用户决定，FS 未声明特定个人身份信息（PII）处理场景。数据内容的隐私合规责任由上层用户的数据模型和业务流程承担。
- **状态：** 不适用
- **说明/依据：** 通用导入工具，无 PII 特定处理逻辑，隐私合规由应用层负责。

#### 2.10 其他（可扩展性、运维安全等）

- **评审意见与发现：** 任务取消机制：§6.2.3 和 §16.1.2 均明确使用 `CancellationToken` 实现优雅取消，防止任务中断后资源泄漏，设计规范。单任务文件数量建议上限 100 个（§10.2.4），提供了运维操作边界指导。不支持复杂嵌套类型（§10.2.1），有效限制了解析攻击面。无密钥/证书管理需求，无运维管理接口。
- **状态：** 通过
- **说明/依据：** 任务生命周期管理完善；操作边界明确；无额外运维安全风险。

### 3. 评审结论

1. **总体安全风险等级：** 低风险
   - 本功能为 taosX 的新增数据源插件，在现有 taosX 安全框架内运作，不引入新的网络接口、认证机制或独立服务，攻击面极为有限。核心安全关注点（路径遍历防护、资源耗尽控制）已在设计中明确覆盖，Rust 语言特性进一步降低了解析器漏洞风险。

2. **评审结论：** 通过
   - 安全设计完备，有效实现了安全需求，准予进入开发阶段。
