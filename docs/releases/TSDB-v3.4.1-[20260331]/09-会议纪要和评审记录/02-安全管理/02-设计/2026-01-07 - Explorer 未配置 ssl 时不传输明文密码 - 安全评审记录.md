### 2. 安全评审记录

评审团队对设计文档进行了审查，评估其安全机制、架构和实现细节是否足以抵御威胁。具体评审意见如下：

#### 2.1 身份认证与访问控制

- **评审意见与发现：** 本特性对 Explorer 认证机制进行了完整重构：将原有客户端可读 Token Cookie 替换为服务端会话机制。登录时后端验证 TSDB 数据库凭据（执行 `select server_version()`）后创建 session，session_id 存储于 HttpOnly Cookie，前端不再持有原始认证凭证（FS 4.1.2 节）。路由守卫通过 `/api/-/me` 接口验证会话状态，未登录用户跳转登录页（FS 4.3.3 节）。登出时服务端主动删除会话记录，会话注销有效（FS 9.3 节）。授权模型保持不变，会话与 TSDB 凭据绑定，继承现有权限体系。
- **状态：** 通过
- **说明/依据：** 服务端会话机制优于原有客户端 Token 方案，认证生命周期管理完整（创建、校验、登出、过期），无明显设计缺陷。

#### 2.2 数据安全

- **评审意见与发现：** FS 采用两层密码保护策略：(1) **传输层**：密码通过 TimeBasedXor 算法加密（16 字节硬编码前缀 `taosdataexplorer` + 8 字节时间戳构成 24 字节 XOR 密钥，60 秒有效期），替代原有 base64 明文 Basic Auth 传输（FS 4.1.1、16.1 节）；(2) **存储层**：TSDB 密码使用 AES-CBC-MAC 加密后存储于 oauth_users 表（FS 6.4 节）。litcrypt 库对硬编码密钥进行编译时混淆以增加逆向难度（FS 4.1.2 节）。需注意：`/api/-/me` 接口响应示例中包含 `tsdb_password` 字段（加密形式，FS 4.2.1 节），该字段并非前端功能所必需，如可移除则可进一步降低暴露面。
- **状态：** 通过
- **说明/依据：** 在无 SSL 的部署场景下，TimeBasedXor 相较原始 base64 明文传输有实质性改善，可有效防御被动监听。存储层 AES 加密满足凭据保护基本要求。设计文档对功能局限性（FS 10.2 节）有明确声明，符合"透明风险管理"原则。

#### 2.3 输入/输出验证与编码

- **评审意见与发现：** 登录接口使用 Rust 结构体 `LoginBody` 解析 JSON 请求体，类型系统提供基础输入校验。密码解密失败（格式错误或超过 60 秒）统一返回 401 Unauthorized，认证凭据错误返回 401（错误码 0x0357），其他错误返回 500（FS 4.1.2 节）。错误信息设计合理：不区分用户名有效性与密码错误，日志记录仅记录 username 而非密码内容（FS 12.2 节）。
- **状态：** 通过
- **说明/依据：** 错误处理策略不泄露认证枚举信息，日志记录不含敏感数据，设计合理。

#### 2.4 会话与通信安全

- **评审意见与发现：** session_id Cookie 正确配置了三项安全属性：`http_only(true)`（防 XSS 脚本读取）、`same_site(SameSite::Lax)`（缓解 CSRF 风险）、`max_age(Duration::seconds(3600))`（与服务端会话一致，1 小时超时，FS 4.1.2 节）。TimeBasedXor 60 秒有效期限制密码密文的重放窗口。FS 10.2 节已明确声明功能局限："加密仅防御被动监听，不防御主动中间人攻击（需 HTTPS）"。前后端时钟偏差超过 60 秒会导致解密失败，属于已知约束（FS 10.1 节，有排查指引）。
- **状态：** 通过
- **说明/依据：** Cookie 安全属性配置完整，会话生命周期管理合理。功能设计边界（针对无 SSL 场景的被动监听防护）在 FS 中已有明确声明，不构成设计缺陷。

#### 2.5 安全日志与监控

- **评审意见与发现：** FS 12.2 节定义了四类关键安全日志：会话创建成功（含 session_id）、会话创建失败（含 error）、认证失败（含 username）、密码解密失败（含 username）。日志包含时间、用户标识、操作结果，具备基本溯源能力，未记录密码明文。FS 8.2 节提供了配套监控建议（登录失败率分类区分密码错误与解密失败、会话创建速率、会话表大小）。
- **状态：** 通过
- **说明/依据：** 日志设计覆盖主要安全事件，兼顾可观测性与数据安全（不记录密码），与监控建议配合完整。

#### 2.6 威胁缓解机制

- **评审意见与发现：** 针对本特性新增攻击面，FS 设计了对应的缓解措施：(1) 防 XSS 窃取会话：HttpOnly Cookie（FS 6.1 节，对应 T-EXPSSL-03）；(2) 防 CSRF：SameSite=Lax（FS 6.2 节，对应 T-EXPSSL-07）；(3) 防密码密文重放：60 秒时间窗口限制（FS 6.3 节，对应 T-EXPSSL-02）；(4) 防被动监听密码明文：TimeBasedXor 加密替代 base64（FS 6.4 节，对应 T-EXPSSL-01）；(5) 防会话积压：自动过期清理（FS 8.1 节，对应 T-EXPSSL-07）。具体威胁分析详见威胁建模报告 T-EXPSSL-01 至 T-EXPSSL-07。
- **状态：** 通过
- **说明/依据：** 主要威胁均有对应的缓解措施，整体防护设计与功能定位（无 SSL 场景防被动监听）一致。

#### 2.7 默认安全配置

- **评审意见与发现：** 新版本默认启用 HttpOnly Cookie 和 SameSite=Lax（FS 4.1.2 节），默认 1 小时会话超时（FS 4.5 节），服务启动时自动配置过期会话清理定时任务（FS 8.1 节）。所有请求默认携带 Cookie（`config.withCredentials = true`，FS 4.3.4 节）。默认配置整体优于原有方案。
- **状态：** 通过
- **说明/依据：** 安全特性默认启用，无需额外配置，符合安全默认原则。

#### 2.8 依赖组件安全

- **评审意见与发现：** 新增关键依赖：(1) litcrypt crate：编译时字符串混淆，功能单一，配置语义清晰（`litcrypt::use_litcrypt!("...")` + `litcrypt::lc!(...)`，FS 4.1.2 节）；(2) actix-web Cookie builder API：HttpOnly/SameSite/max_age 属性均正确设置（FS 4.1.2 节代码示例）；(3) base64 标准编码：用于 XOR 密文传输，无安全风险。无其他新增安全敏感第三方依赖。
- **状态：** 通过
- **说明/依据：** 依赖选型合理，安全配置正确。litcrypt 为知名 Rust 混淆库，在此用途下无已知安全问题。

#### 2.9 隐私设计

- **评审意见与发现：** 产品面向 B2B 场景，本特性不涉及用户个人隐私数据的专项处理。TSDB 凭据（用户名、密码）加密存储符合基本数据保护要求。
- **状态：** 不适用
- **说明/依据：** 本特性不引入新的个人隐私数据处理场景。

#### 2.10 其他（可扩展性、运维安全等）

- **评审意见与发现：** 服务启动时自动配置过期会话清理定时任务，运维友好（FS 8.1 节）。前端删除了旧的 Token 管理函数（`removeToken`、`setLoginSign`、`isLogin` 等），清理了遗留代码攻击面（FS 4.3.1 节）。OAuth 兼容性方面，保留 `/api/-/oauth/me` 和 `/api/-/oauth/logout` 映射，保证向后兼容（FS 7.2 节）。会话依赖数据库存储，数据库不可用时无法验证会话，属于已知约束（FS 10.1 节）。
- **状态：** 通过
- **说明/依据：** 运维设计简洁，无特殊部署要求，遗留代码清理彻底，整体可维护性良好。

### 3. 评审结论

1. **总体安全风险等级：**
    - **低风险**：安全设计完备，有效提升了原有方案（客户端可读 Token Cookie + Base64 明文 Basic Auth）的安全水位，能在设计目标（无 SSL 场景防被动监听）内有效保护密码传输安全，可进入开发阶段。

2. **评审结论：**
    - **通过**：准予进入下一阶段（编码实现）。
