### 2. 安全评审记录

评审团队对设计文档进行了审查，评估其安全机制、架构和实现细节是否足以抵御威胁。具体评审意见如下：

#### 2.1 身份认证与访问控制

- **评审意见与发现：** taosgen 是本地 CLI 工具，本次优化涉及本地文件系统 CSV 读取逻辑（新增多文件 glob/目录支持和 streaming 模式），不引入任何网络认证端点或多用户访问控制逻辑。文件访问权限完全依赖操作系统文件系统权限管理，无需在应用层实现额外的认证授权机制。
- **状态：** 不适用
- **说明/依据：** 本功能为本地数据生成工具，不涉及用户身份认证或多租户权限控制，认证边界由 OS 提供。

#### 2.2 数据安全

- **评审意见与发现：** taosgen 处理的 CSV 文件为用户自行提供的测试/基准数据，通常不含密钥、个人信息等敏感数据。数据以明文方式读取并通过现有连接写入 TDengine，与工具定位（数据生成/基准测试工具）一致，无需引入额外的加密或脱敏机制。
- **状态：** 不适用
- **说明/依据：** 本工具处理用户自提供的测试数据，不存储或传输敏感信息，数据安全由调用方（用户）负责保证数据来源的安全性。

#### 2.3 输入/输出验证与编码

- **评审意见与发现：** FS 第 6.1 节明确说明使用 `std::filesystem` 进行路径解析以避免路径遍历攻击；glob 匹配仅在指定父目录内进行、不递归进入子目录（第 10.2 条约束）。第 4.4 节定义了文件不存在、目录为空/无匹配、列数不一致、配置冲突等四种错误处理场景。错误消息中包含文件路径（如 `CSV file does not exist: <path>`），这对本地 CLI 工具是合理的诊断信息，不构成敏感信息泄露风险。多文件读取时强制列数一致性校验（第 4.2.2 节），防止格式错误数据导致未定义行为。
- **状态：** 通过
- **说明/依据：** 路径遍历防护、glob 范围限制、格式校验和配置冲突检测均已在设计中明确覆盖，输入验证设计合理完整。

#### 2.4 会话与通信安全

- **评审意见与发现：** 本次优化仅涉及本地文件读取逻辑（CSV 解析库替换、多文件支持、streaming 模式），不引入任何新的网络通信端点、API 接口或会话管理逻辑。
- **状态：** 不适用
- **说明/依据：** 功能范围限于本地文件 I/O，不涉及网络层安全。

#### 2.5 安全日志与监控

- **评审意见与发现：** FS 第 15 节（可观测性）定义了 DEBUG 级别日志：多文件模式下文件列表解析结果（`Resolved <n> CSV files from path: <path>`）和文件切换记录（`Switching to next CSV file: <filename>`）。第 8.2 节补充说明 streaming 模式下内存使用量可通过系统监控观察。对于本地 CLI 工具，此粒度的运维日志足以支持故障排查，无需额外的安全审计日志。
- **状态：** 通过
- **说明/依据：** 本地数据生成工具的日志需求以运维排查为主，现有 DEBUG 日志设计满足需求。

#### 2.6 威胁缓解机制

- **评审意见与发现：** 针对威胁建模报告（TM-TSDB-CSVOPT-001）中识别的主要威胁，FS 中的设计缓解措施如下：
  - **T-CSVOPT-01（路径遍历）**：FS 6.1 通过 `std::filesystem` 规范化路径并限制 glob 范围，已有效缓解；
  - **T-CSVOPT-02（符号链接攻击）**：FS 6.1 明确依赖 OS 文件权限控制符号链接访问，在受控运行环境下风险可接受；
  - **T-CSVOPT-03（解析器漏洞）**：替换手写状态机解析器为成熟的 vincentlaucsb-csv-parser 库，降低 buffer overflow 风险；
  - **T-CSVOPT-04（内存耗尽）**：新增 streaming 模式（常量级内存占用）缓解大文件场景下的 OOM 风险；
  - **T-CSVOPT-05（数据污染）**：依赖 OS 文件权限保护，运行环境安全性由部署方保证；
  - **T-CSVOPT-06（Glob 意外扩展）**：禁止递归进入子目录、非 CSV 文件快速报错，限制了意外扩展的影响范围。
- **状态：** 通过
- **说明/依据：** 各主要威胁均有对应的设计缓解措施，整体防护设计合理。

#### 2.7 默认安全配置

- **评审意见与发现：** `loading_mode` 默认值为 `preload`（第 4.1.1 节），与原有行为完全兼容，不引入新风险；glob 和目录模式默认不递归进入子目录（第 10.2 条约束），遵循最小范围原则；本次变更无新增开放端口或后台服务。
- **状态：** 通过
- **说明/依据：** 默认配置保持原有安全基线，新功能均需用户显式启用，符合最小权限/最小攻击面原则。

#### 2.8 依赖组件安全

- **评审意见与发现：** FS 第 16.1 节新引入 `vincentlaucsb-csv-parser/2.3.0`（header-only 库，无运行时依赖）。FS 第 6.2 节指出该库"经过广泛测试，避免了手工解析器可能存在的缓冲区溢出问题"，替代手写解析器降低了整体解析风险。该依赖为 header-only，不引入动态链接库的加载风险。
- **状态：** 通过
- **说明/依据：** 引入成熟的第三方解析库替代手写解析器，安全性有所提升。该库的持续安全性应纳入常规 SCA 扫描流程（参见 `02-安全管理/新技术引入评估报告/SCA 开源工具引入评估报告.md`）。

#### 2.9 隐私设计

- **评审意见与发现：** taosgen 为数据生成/基准测试工具，处理的 CSV 数据为用户自行提供的测试数据，工具本身不收集、存储或上传任何用户个人信息。
- **状态：** 不适用
- **说明/依据：** 不涉及用户个人信息的处理，无隐私合规要求。

#### 2.10 其他（可扩展性、运维安全等）

- **评审意见与发现：** 本次变更保持完全向后兼容（第 7.1 节），原有配置无需修改；header-only 依赖不引入额外的动态链接库管理负担；构建流程无需变更（第 16.2 节）；官网文档更新需求已在 FS 第 17.1 节中列出。整体运维影响极小。
- **状态：** 通过
- **说明/依据：** 变更范围明确，兼容性保证完整，运维影响可控。

### 3. 评审结论

1. **总体安全风险等级：** 低风险
   - 本次优化为本地 CLI 工具的内部实现改进（CSV 解析库替换 + 多文件支持 + streaming 模式），攻击面有限，主要依赖 OS 文件系统权限作为安全边界。FS 已针对路径遍历、内存耗尽等关键风险设计了缓解措施，安全设计完备。

2. **评审结论：** 通过
   - 设计方案安全合理，能够有效防护已识别的主要威胁，准予进入下一阶段（编码实现）。
