### 2. 安全评审记录

评审团队对设计文档进行了审查，评估其安全机制、架构和实现细节是否足以抵御威胁。具体评审意见如下：

#### 2.1 身份认证与访问控制

- **评审意见与发现：** 该功能为 `EXPLAIN ANALYZE` 语句的诊断信息增强，属于只读查询诊断能力。FS 中未引入新的认证或授权机制，`EXPLAIN ANALYZE` 语句的执行复用现有 SQL 查询的权限校验体系，即用户需要对被分析的查询涉及的表/库具有相应的读权限才能执行。FS 第 5.5 节明确拒绝支持 DML 语句的 EXPLAIN，规避了通过诊断接口触发写操作的风险。
- **状态：** 通过
- **说明/依据：** 该功能未改变现有访问控制模型，权限校验依赖已有查询执行链路。DML 的显式拒绝设计是合理的安全边界设定。

#### 2.2 数据安全

- **评审意见与发现：** `EXPLAIN ANALYZE` 的输出新增了 I/O 代价指标（如 `file_load_blocks`、`stt_load_blocks`、`mem_load_blocks` 等）和 vgroup 拓扑信息（如 `slowest_vgroup_id`）。这些指标属于系统运行状态信息，不包含用户业务数据本身。FS 第 5.2.2.2 节删除了 `ep`（endpoint）字段的输出，避免了集群节点地址的泄露，是正向的安全改进。新增的 `vgroup_id` 信息需要从服务端通过 `explain_rsp` 消息传输，但 vgroup_id 本身不属于高敏感数据。
- **状态：** 通过
- **说明/依据：** 输出内容为性能诊断指标，不涉及用户业务数据。删除 `ep` 字段减少了信息暴露面。

#### 2.3 输入/输出验证与编码

- **评审意见与发现：** 该功能的输入为标准 SQL 语句 `EXPLAIN ANALYZE [VERBOSE TRUE/FALSE] <query>`，由现有 SQL 解析器处理。新增的 `VERBOSE` 关键字是布尔型参数，解析逻辑简单，不引入新的注入向量。FS 第 5.3.1 节对输出精度进行了明确约束（时间精确到微秒、小数保留一位、百分数保留整数），规避了异常精度导致的缓冲区溢出风险。FS 第 4.2 节提到 Ratio 参数当前会输出错误值 `0.001000`，新设计中标注"暂不支持，文档不会提及"（第 5.6 节），应确保该参数在解析层被正确拒绝或忽略，而非传入后产生非预期行为。
- **状态：** 通过
- **说明/依据：** SQL 解析复用现有链路，VERBOSE 参数类型简单。输出格式有明确精度规范，降低了格式化异常风险。

#### 2.4 会话与通信安全

- **评审意见与发现：** `EXPLAIN ANALYZE` 的执行涉及客户端与多个 vnode 之间的 RPC 通信（通过 Exchange 算子），FS 第 5.2.2.3 节新增了 Network 指标（`fetch_times`、`fetch_rows`、`fetch_cost`）。这些指标的采集基于现有 RPC 通信链路，未引入新的通信通道或协议变更。通信安全依赖 TDengine 已有的 RPC 框架安全机制。
- **状态：** 不适用
- **说明/依据：** 该功能未改变通信协议和通道，仅在现有 RPC 响应中附加诊断指标数据。

#### 2.5 安全日志与监控

- **评审意见与发现：** 该功能为诊断信息增强，本身不涉及安全事件。FS 中提到部分新增 I/O 指标（如 `file_load_elapsed`、`stt_load_elapsed`）"日志中已统计"，说明现有日志体系已覆盖相关运行指标。`EXPLAIN ANALYZE` 语句的执行会和普通查询一样被现有审计日志记录。
- **状态：** 不适用
- **说明/依据：** 该功能不产生新的安全事件类型，现有日志体系已覆盖相关指标。

#### 2.6 威胁缓解机制

- **评审意见与发现：** 针对威胁建模报告中识别的威胁，评估如下：
  - **T-EXPANA-01（执行计划信息泄露）**：FS 已删除 `ep` 字段输出，减少集群拓扑暴露；vgroup_id 和 I/O 指标属于低敏感运维信息，且受现有权限体系约束。风险可接受。
  - **T-EXPANA-02（资源消耗）**：`EXPLAIN ANALYZE` 会实际执行查询，FS 第 1 节已说明该行为，并非新引入的风险。现有查询资源管控机制适用。
  - **T-EXPANA-03（verbose 模式信息暴露）**：verbose 输出的额外指标（vgroup 拓扑、I/O 详情）为运维诊断所需，敏感度低，且受查询权限约束。
  - **T-EXPANA-04/05（统计精度与格式化）**：FS 第 5.3.1 节明确了精度规范，降低了异常值导致的格式化问题。
- **状态：** 通过
- **说明/依据：** 威胁建模中识别的风险均为低风险，现有安全机制已提供充分防护。

#### 2.7 默认安全配置

- **评审意见与发现：** FS 设计了两级输出模式：普通级别和 verbose 级别。默认输出为普通级别（`VERBOSE FALSE`），仅展示核心时间指标（`exec_first_row`、`exec_last_row`、`rows`）和基本 I/O 代价。详细的执行时间分解（`exec_elapsed`、`input_wait_elapsed`、`output_wait_elapsed`）、vgroup 偏离率、网络指标等信息仅在显式指定 `VERBOSE TRUE` 时输出。这是安全的默认配置策略——默认最小化信息暴露。
- **状态：** 通过
- **说明/依据：** 默认输出级别为非 verbose，遵循最小信息暴露原则。

#### 2.8 依赖组件安全

- **评审意见与发现：** 该功能未引入新的第三方依赖。所有新增指标的采集基于 TDengine 内部已有的算子执行框架和日志统计模块。FS 第 5.2.2.2 节提到部分指标"日志中已统计"，说明是对现有内部数据的复用。vgroup_id 的获取需要在 `explain_rsp` 消息中新增字段，属于内部协议扩展，不涉及外部组件。
- **状态：** 不适用
- **说明/依据：** 无新增外部依赖，功能基于现有内部组件实现。

#### 2.9 隐私设计

- **评审意见与发现：** `EXPLAIN ANALYZE` 输出的信息均为查询执行的性能指标和系统运行状态数据，不包含用户个人信息或业务数据内容。虽然 `total_rows`、`check_rows` 等指标间接反映数据量规模，但这属于标准数据库诊断能力，且受查询权限约束。
- **状态：** 不适用
- **说明/依据：** 输出内容为系统性能指标，不涉及个人隐私数据。

#### 2.10 其他（可扩展性、运维安全等）

- **评审意见与发现：** FS 第 5.4 节规划了未来的 `FORMAT` 选项（text/html/json/graphviz），标注"本期不做"。其中 `html` 和 `graphviz` 格式在未来实现时需要关注 XSS 和格式注入风险，建议在后续设计中加入输出编码措施。第 5.6 节的 Ratio 功能"暂不支持"，当前需确保该参数不会被误传入导致非预期行为。FS 第 6 节提到"额外统计开销应当极低"，符合诊断功能不应显著影响被诊断系统性能的原则。
- **状态：** 通过
- **说明/依据：** 当前设计范围内无运维安全问题。未来 FORMAT 扩展时需关注输出编码安全。

### 3. 评审结论

1. **总体安全风险等级：**
   - 低风险：该功能为只读诊断能力的增强，不涉及数据变更、新认证机制或新通信协议。设计中显式拒绝 DML 支持、删除 endpoint 输出、默认非 verbose 模式均为正向安全决策。安全设计完备，可进入开发阶段。
2. **评审结论：**
   - 通过：准予进入下一阶段（编码实现）。
