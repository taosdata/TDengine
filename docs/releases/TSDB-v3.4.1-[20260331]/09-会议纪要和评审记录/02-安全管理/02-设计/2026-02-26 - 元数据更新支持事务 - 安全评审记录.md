### 2. 安全评审记录

评审团队对设计文档进行了审查，评估其安全机制、架构和实现细节是否足以抵御威胁。具体评审意见如下：

#### 2.1 身份认证与访问控制

- **评审意见与发现：** FS 第 6 节"安全"为空白，未描述事务操作的权限控制机制。BEGIN/COMMIT/ROLLBACK 等事务指令是否继承现有 TDengine 用户权限模型、是否需要特定角色/权限才能发起事务，文档中均无说明。此外，事务内的元数据操作（CREATE/DROP/ALTER VTABLE）在 COMMIT 时是否进行权限二次校验也未明确——若仅在 BEGIN 时校验权限，则存在"权限已被撤销后仍可提交"的绕过风险（详见威胁 T-IDMPTX-07）。
- **状态：** 待定
- **说明/依据：** FS 未在安全章节说明事务操作的鉴权策略；COMMIT 阶段的权限二次校验机制需在设计中明确。

#### 2.2 数据安全

- **评审意见与发现：** 本功能仅涉及虚拟子表/虚拟普通表的元数据事务（CREATE/DROP/ALTER VTABLE），不直接处理时序业务数据，数据安全风险较低。PREPARED 状态的影子条目依赖 MNode 内部存储管理，沿用现有数据安全机制即可。
- **状态：** 通过
- **说明/依据：** 功能范围限于元数据层，不涉及加密、脱敏等敏感数据处理场景，现有存储安全机制可覆盖。

#### 2.3 输入/输出验证与编码

- **评审意见与发现：** 事务 SQL 语法（BEGIN/COMMIT/ROLLBACK 及事务内的 DDL 指令）经由现有 TDengine SQL 解析器处理，沿用现有输入验证逻辑。FS 4.4 节设计的冲突错误码（"Resource busy / Conflict"、"Table does not exist"）表述简洁，未在错误信息中暴露内部状态细节或路径信息，输出编码设计合理。
- **状态：** 通过
- **说明/依据：** 依赖现有 SQL 解析框架；错误信息设计不泄露内部实现细节。

#### 2.4 会话与通信安全

- **评审意见与发现：** FS 未描述事务上下文（TID）的超时/自动回滚机制。根据 FS 4.3 节，第一期全局只支持一个事务——若客户端在 BEGIN 后异常断开连接或长时间不 COMMIT/ROLLBACK，全局事务锁将持续被占用，导致所有其他用户的元数据操作被阻塞，形成拒绝服务（详见威胁 T-IDMPTX-05）。此外，TID 的生成方式（是否安全随机）亦未在设计中说明。
- **状态：** 待定
- **说明/依据：** 缺少事务超时与自动回滚机制；TID 安全生成方式需明确。

#### 2.5 安全日志与监控

- **评审意见与发现：** FS 第 12 节"可观测性"提到通过 `SHOW TRANSACTIONS` 查看事务状态（通过 `__trans__` 字段区分批事务与普通事务），但未描述事务操作的审计日志记录。"谁在何时发起了事务、事务内操作了哪些元数据对象、何时 COMMIT/ROLLBACK"等关键安全事件，若未写入审计日志，则在发生故障或安全事件时无法溯源（详见威胁 T-IDMPTX-03）。
- **状态：** 待定
- **说明/依据：** FS 可观测性设计仅覆盖运维视角的状态查询，缺少安全审计日志设计。

#### 2.6 威胁缓解机制

- **评审意见与发现：** 针对威胁建模报告（见 `元数据更新支持事务 - 威胁建模报告.md`）识别的主要威胁：
  - **T-IDMPTX-05（全局锁 DoS）**：FS 未设计超时保护，缺乏缓解措施，风险敞口高。
  - **T-IDMPTX-07（权限校验绕过）**：未明确 COMMIT 时是否重新校验权限，存在缺口。
  - **T-IDMPTX-01（TID 劫持）**：TID 生成安全性未说明。
  - FS 4.4 节对各类并发冲突场景（PREPARED_CREATE/DROP/ALTER vs. 非事务操作）给出了完整的冲突检测逻辑，是良好的防御设计。
- **状态：** 待定
- **说明/依据：** 冲突检测机制完善，但 DoS 防护和权限时序安全存在设计缺口。

#### 2.7 默认安全配置

- **评审意见与发现：** 事务功能作为 SQL 语法扩展，默认随数据库引擎启用，与现有 DDL 指令管理方式一致。全局单事务限制（FS 4.3 节）本身是一种保守的并发控制策略，在一定程度上降低了复杂并发攻击面。
- **状态：** 通过
- **说明/依据：** 默认配置策略合理，与现有架构风格一致。

#### 2.8 依赖组件安全

- **评审意见与发现：** 本功能为 MNode 元数据管理模块的内部扩展，依赖 TDengine 现有的 SQL 解析框架和元数据存储机制，未引入新的第三方库或外部服务。
- **状态：** 通过
- **说明/依据：** 无新增第三方依赖，不适用第三方组件安全评估。

#### 2.9 隐私设计

- **评审意见与发现：** 元数据事务涉及的是表结构信息（表名、列名、标签），不涉及个人隐私数据的采集、存储或处理，无隐私合规约束。
- **状态：** 不适用
- **说明/依据：** 功能范围为虚拟表元数据，不处理个人信息。

#### 2.10 其他（可扩展性、运维安全等）

- **评审意见与发现：**
  - **SHOW TRANSACTIONS 访问控制**：FS 12 节描述了通过 `SHOW TRANSACTIONS` 查看事务信息，但未明确该命令是否有权限限制。若普通用户可查看其他租户/用户的事务详情（操作的表名、操作类型等），存在业务信息泄露风险（详见威胁 T-IDMPTX-04）。
  - **二期扩展规划**：FS 16.1 节规划了并发事务、更多操作类型支持，届时应重新进行安全评审。
- **状态：** 待定
- **说明/依据：** `SHOW TRANSACTIONS` 的访问控制策略需在设计中明确。

---

### 3. 评审结论

1. **总体安全风险等级：** 中风险
   - 功能的基础冲突检测与隔离设计完善，但存在事务超时/全局锁 DoS、审计日志缺失、权限时序校验等待改进的安全设计缺口，需在编码前补充设计。

2. **评审结论：** 有条件通过
   - 需完成"后续行动项"中的所有项目，并经安全代表确认后，方可进入开发实现阶段。
