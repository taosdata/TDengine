### 2. 安全评审记录

评审团队对设计文档进行了审查，评估其安全机制、架构和实现细节是否足以抵御威胁。具体评审意见如下：

#### 2.1 身份认证与访问控制

- **评审意见与发现：** 本特性仅扩展 `PERIOD` 触发语法，不引入任何新的认证方案或授权模型。流任务的创建与删除所需权限与现有流计算特性一致，依赖 TDengine 现有的数据库写权限控制，无新增权限校验点。
- **状态：** 不适用
- **说明/依据：** FS 第6节明确指出"不涉及新的网络接口、权限模型或数据访问路径"。

#### 2.2 数据安全

- **评审意见与发现：** 本特性不引入新的数据存储路径，流计算结果写入现有输出表，数据加密和隔离方案与现有机制相同。流任务元数据中新增 `w`/`n`/`y` 单位的序列化存储（FS 第7节），但该元数据不包含敏感信息。
- **状态：** 不适用
- **说明/依据：** FS 第13节确认"不引入新的配置文件、系统表或存储格式变更（流任务元数据中新增单位的序列化需向后兼容）"，数据安全无新增风险。

#### 2.3 输入/输出验证与编码

- **评审意见与发现：** FS 第4.5节明确定义了三类参数错误的校验规则与错误信息格式：（1）offset 超出触发周期（严格小于约束）；（2）月单位 offset 静态溢出校验（以 28 天/月为基准）；（3）无效时间单位检测。错误信息仅暴露参数合法范围，不包含内部系统路径或敏感状态信息。
- **状态：** 通过
- **说明/依据：** 参数校验逻辑完整，覆盖了全部新增语法元素（interval 单位、offset 单位、offset 数值范围）。错误格式设计合理，信息最小化原则得到体现。

#### 2.4 会话与通信安全

- **评审意见与发现：** 本特性为纯 SQL 语法解析和调度逻辑扩展，不引入新的 RPC 接口、网络连接或会话管理机制。
- **状态：** 不适用
- **说明/依据：** FS 第6节明确说明不涉及新的网络接口。

#### 2.5 安全日志与监控

- **评审意见与发现：** 本特性不新增独立的可观测性要求（FS 第12节仅说明 `ins_streams` 视图以原始语法显示参数）。流任务的创建、删除等操作审计依赖现有机制，无新增安全事件类型。
- **状态：** 不适用
- **说明/依据：** 本特性为现有流计算框架的语法扩展，审计需求沿用现有流任务操作审计机制，无需单独评审。

#### 2.6 威胁缓解机制

- **评审意见与发现：** 本特性主要攻击面为 SQL 参数注入和边界条件攻击。FS 第4.5节的参数校验机制（offset 范围校验、月单位静态溢出校验、无效单位拒绝）已覆盖上述攻击向量。首次触发历史数据回溯属预期设计行为（FS 第4.4节），其资源消耗风险已在威胁建模报告（TM-TSDB-STNTM-001）中识别并记录为 T-STNTM-01。
- **状态：** 通过
- **说明/依据：** 交叉引用威胁建模报告 TM-TSDB-STNTM-001 中威胁 T-STNTM-01 至 T-STNTM-05，中低危威胁均通过现有参数校验或架构约束得到缓解，无高危未缓解威胁。

#### 2.7 默认安全配置

- **评审意见与发现：** 本特性不引入新的配置项、端口或系统服务，无默认安全配置风险。
- **状态：** 不适用
- **说明/依据：** FS 第13节明确"不引入新的配置文件、系统表或存储格式变更"，安装和卸载流程与标准版本升级一致。

#### 2.8 依赖组件安全

- **评审意见与发现：** 本特性为纯引擎内部逻辑实现，不引入新的第三方库、框架或外部服务依赖。时区和日历计算（月份天数、闰年判断）使用已有系统能力，无新依赖引入。
- **状态：** 不适用
- **说明/依据：** FS 第5节说明"新增单位的触发时间计算为纯整数运算"，无外部依赖。

#### 2.9 隐私设计

- **评审意见与发现：** 本特性不涉及个人信息的采集、处理或存储。流计算处理的时序数据（如传感器、设备数据）由现有隐私管理机制负责，本特性无新增影响。
- **状态：** 不适用
- **说明/依据：** 特性范围限于调度触发时间逻辑，不接触数据内容本身。

#### 2.10 其他（可扩展性、运维安全等）

- **评审意见与发现：** FS 第7节明确了降级注意事项：降级前须手动删除所有使用 `w`/`n`/`y` 单位的流任务，否则旧版本启动后这些任务将处于异常状态。此降级风险已在文档中明确说明，属于运维规程范畴。时区处理以服务端时区挂钟时间为准（含夏令时切换），逻辑边界清晰，无歧义风险。
- **状态：** 通过
- **说明/依据：** 运维安全注意事项完整，降级路径有明确指引。多倍数周期的 epoch 基准对齐逻辑全局一致，不依赖任务创建时间，避免了潜在的时间竞态问题。

### 3. 评审结论

1. **总体安全风险等级：**
   - **低风险**：本特性为 TDengine 流计算 `PERIOD` 语法的纯扩展，不引入新的网络接口、权限模型或数据访问路径。安全影响范围极小，参数校验设计完整，可进入开发阶段。

2. **评审结论：**
   - **通过**：准予进入下一阶段（编码实现）。本次评审未发现需在编码前解决的设计安全缺陷，无后续行动项。
