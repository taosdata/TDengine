### 2. 安全评审记录

评审团队对设计文档进行了审查，评估其安全机制、架构和实现细节是否足以抵御威胁。具体评审意见如下：

#### 2.1 身份认证与访问控制

- **评审意见与发现：** pSpace 连接采用用户名/密码认证，凭证通过 DSN（`pspace://[username]:[passwd]@[host]:[port]/...`）或 toml 配置文件传递，由 taosX 平台统一管理插件的执行与凭证传递。用户通过 taos-Explorer 输入 pSpace 连接凭证并触发连通性检查（§10.1），访问控制依赖 taosX 平台自身的用户权限体系，pSpace plugin 本身不暴露独立的外部认证端口，作为 taosX 受控子进程运行，设计层面符合最小接入原则。
- **状态：** 通过
- **说明/依据：** pSpace plugin 以 Java jar 形式受 taosX 调度，用户无法绕过 taosX 直接调用 plugin；taosX 平台对任务创建和执行有权限管控。

#### 2.2 数据安全

- **评审意见与发现：** 存在两处凭证/数据安全隐患：① pSpace 用户名/密码以明文出现于 toml 配置文件（§4.5.3 示例：`password = "admin888"`）和 DSN URL，若配置文件的文件系统权限控制不当，存在凭证泄露风险；② 当 `keep_raw_data=true` 时，原始 pSpace 工业时序数据以明文文件持久化至本地目录（默认 `./raw_data`，§4.5.6），该目录的访问权限控制未在 FS 中说明。pSpace 凭证默认不含 keep_raw_data（false），但可选启用，需说明权限防护策略。
- **状态：** 待定
- **说明/依据：** 参见威胁建模报告 T-PSPACE-01（凭证明文存储）和 T-PSPACE-04（原始数据文件暴露）。taosX 平台对凭证的实际存储方式（是否加密落盘）需进一步确认。

#### 2.3 输入/输出验证与编码

- **评审意见与发现：** 功能接受两类外部输入：① 用户通过 UI 输入的连接参数（host、port、用户名、密码、起始节点 LongName、测点名称 pattern），② 用户上传的 CSV 配置文件（§4.1.2）。CSV 中的字段（point_id、stable、tbname、tag 值等）会直接用于构造 TDengine 写入操作，若 taosX 框架对这些字段未做长度、字符集和合法性校验，存在注入风险。点位名称过滤使用 LongName 通配符，由 pSpace SDK 内部处理，路径遍历风险较低。错误输出通过 JSON 结构化返回，未见明显的敏感信息泄露设计缺陷。
- **状态：** 通过
- **说明/依据：** taosX 框架层面对表名、列名等参数有基础校验，pSpace plugin 作为受管进程，其输出经 taosX 管道处理。参见威胁建模报告 T-PSPACE-08 作为低优先级关注项。

#### 2.4 会话与通信安全

- **评审意见与发现：** pSpace plugin 与 pSpace 服务器之间的通信安全（是否使用 TLS/SSL）在 FS 中未说明，pSpace SDK 的通信协议由力控科技提供，是否支持加密传输取决于 SDK 实现。taosX 与 TDengine 之间的通信安全由 TDengine 平台层保障，不属于本功能范畴。pSpace plugin 不持有会话状态，无会话管理相关风险。
- **状态：** 待定
- **说明/依据：** 参见威胁建模报告 T-PSPACE-02（MITM 篡改数据）和 T-PSPACE-03（伪造服务器）。建议在开发阶段确认 pSpace SDK 是否支持 TLS，并在内网部署场景下评估网络隔离是否可作为等效缓解。

#### 2.5 安全日志与监控

- **评审意见与发现：** FS §4.4 说明 Metrics 复用 point message 统计指标，§13 可观测性复用 Point 类型数据源的性能指标，任务执行状态（成功/失败行数、重试次数）由 taosX 平台记录。pSpace plugin 支持通过 `advanced_options.log_level` 配置日志级别（§4.5.6 示例）。历史数据迁移的任务级审计（何时触发、迁移范围、写入数量）依托 taosX 平台任务管理功能。
- **状态：** 通过
- **说明/依据：** 参见威胁建模报告 T-PSPACE-07（抵赖风险）作为低优先级改进建议，不构成阻塞性缺陷。

#### 2.6 威胁缓解机制

- **评审意见与发现：** FS 提供了以下内置防护机制：① `max_retries`（默认10）和 `retry_interval`（默认5s）限制了失败重试行为，防止对 pSpace 服务器产生过大重连压力；② `conn_timeout` 参数防止连接无限挂起；③ `time_window` 参数将历史数据查询分批执行，天然限制单次大批量查询的资源消耗（§4.2.1、§4.2.3）；④ `min_elapsed` 参数控制实时订阅的最小间隔，防止极高频推送（§4.3）。
- **状态：** 通过
- **说明/依据：** 参见威胁建模报告 T-PSPACE-05（拒绝服务），现有参数已提供基本缓解，风险等级为低。

#### 2.7 默认安全配置

- **评审意见与发现：** 功能的默认配置整体安全：① `keep_raw_data` 默认为 `false`，原始数据不落盘；② 有合理的默认超时与重试参数；③ pSpace 默认端口 8889 为厂商标准端口，无异常开放端口。FS 中示例凭证（`password = "admin888"`）为演示占位符，不影响产品安全配置。
- **状态：** 通过
- **说明/依据：** 默认配置遵循最小暴露原则，`keep_raw_data=false` 是重要的安全默认值。

#### 2.8 依赖组件安全

- **评审意见与发现：** 本功能新增对力控科技 pSpace Java SDK 的依赖（§3 pSpace plugin、§14 安装），该 SDK 为第三方闭源组件。FS 未说明 SDK 版本锁定策略、已知安全漏洞排查方式，以及后续版本升级流程。pSpace plugin 以独立 JAR 形式部署（§4.5.1 version: 1.11.0），依赖管理由打包脚本（§14）控制。
- **状态：** 待定
- **说明/依据：** 需确认 pSpace SDK 的来源可信性（官方 Maven 仓库或厂商提供）及版本固定策略，纳入 SBOM 管理。

#### 2.9 隐私设计

- **评审意见与发现：** pSpace 为 B2B 工业实时历史数据库，接入的数据为设备传感器时序数据（温度、压力等工艺参数），不涉及自然人个人信息。tag 字段中的地理位置信息（如 `\北京\朝阳\望京`）为设施位置标识，不属于个人隐私范畴。
- **状态：** 不适用
- **说明/依据：** 工业 B2B 数据接入场景，无个人隐私数据处理需求。

#### 2.10 其他（可扩展性、运维安全等）

- **评审意见与发现：** pSpace plugin 以独立 Java jar 形式分发，通过 taosX 插件目录（`plugins/pspace`）部署（§14），更新需替换 JAR 文件，无热更新机制，运维操作可控。日志级别可按需调整（`log_level`），`keep_raw_data_days` 参数提供原始数据的自动清理机制（§4.5.6），防止磁盘无限增长。整体运维安全设计合理。
- **状态：** 通过
- **说明/依据：** `keep_raw_data_days` 的自动清理机制是良好的运维安全实践。

---

### 3. 评审结论

1. **总体安全风险等级：** 低风险
   - 安全设计基本合理，主要问题集中在凭证存储方式和第三方 SDK 管理两个方面，均为已知场景且有平台层面的兜底控制。

2. **评审结论：** 有条件通过
   - 需完成"后续行动项"中的确认事项，由安全代表确认后可进入发布阶段。
