# 20260209 关于将ISO9000体系文件汇入公司研发管理制度的专题会议纪要

会议时间： 2026年2月9日 14:00-16:00
会议地点： Stable
主 持 人： 肖波（管理者代表）
与会人员： 陶建辉（总经理）、关胜亮、郑子灵、侯哲、霍琳贺、潘魏、邝金清、鲍之骁
记 录 人： 肖波
会议主题： 评审并确定将公司ISO9001:2015质量管理体系文件（《质量手册》、《程序文件汇编》、《管理制度汇编》）内容，系统性汇入并优化公司现有研发管理规则体系。

**会议议程：**
1. 介绍ISO9000体系文件与现有研发管理制度目录的对应关系。
2. 讨论汇入与融合的具体原则、范围及方法。
3. 明确各部门职责与后续行动计划。

**会议内容与决议：**
一、 体系文件对应关系确认
会议首先由管理者代表肖波介绍了三份ISO9000体系文件的核心内容，并与现有R&D管理规则进行了初步对比分析：
1. 对应关系部分：
  - 《质量手册》第8.3章“产品和服务开发” 与研发管理规则中的 “01-管理体系/01-研发项目管理过程说明”、“02-项目管理” 全过程高度相关，为研发项目管理提供了顶层框架和要求。
  - 《程序文件汇编》中的《设计和开发控制程序》 是研发核心过程的细化，可直接对应并丰富 “02-项目管理” 下的各子过程（如项目立项、开发、测试、发布等）。
  - 《程序文件汇编》中的《文件控制程序》、《记录控制程序》 是 “01-管理体系/05-研发文档编写规范、06-研发文档编制计划” 的基础和依据。
  - 《程序文件汇编》中的《纠正和预防措施控制程序》、《不合格控制程序》 与 “03-日常制度/02-缺陷管理流程” 直接对应并提供了标准化的处理框架。
  - 《程序文件汇编》中的《人力资源管理程序》 及 《管理制度汇编》中的《人事管理制度》 为 “03-日常制度/13-绩效考核制度” 提供了人员能力与意识保障的支持性要求。
  - 《管理制度汇编》中的《设计和开发管理制度》 是研发过程的具体制度，可融入 “01-管理体系” 和 “02-项目管理” 相关环节。
  - 《质量手册》中关于“领导作用”、“策划”、“支持”、“绩效评价”、“改进”等章节 的要求，应融入研发管理的全过程，特别是在 “01-管理体系” 和项目管理决策中体现。
1. 需补充或强化部分：
  - 风险管理： 《质量手册》第6.1章及《程序文件汇编》中《风险和机遇的应对措施控制程序》明确了系统化风险管理要求。决议：在 “01-管理体系” 中增加 “风险管理指南” ，并在 “07-质量保障” 中明确与 “01-风险管理过程” 的衔接。
  - 供应商/外部供方管理： 《质量手册》第8.4章及《程序文件汇编》中《采购控制程序》对外部供方控制有明确要求。决议：将相关要求融入 “07-质量保障/02-供应商管理过程” 及 “03-采购管理制度” 。
  - 质量目标与绩效监控： 《质量手册》第6.2、9.1章明确了质量目标的制定、分解与监控。决议：在 “07-质量保障/07-度量指标制定” 中明确研发质量目标的设定、监控与分析要求，并与公司级目标（如技术开发一次合格率≥95%）挂钩。
  - 基础设施与工作环境： 《程序文件汇编》中《基础设施和工作环境控制程序》对研发环境有管理要求。决议：相关要求应补充至 “07-质量保障/08-开发环境规范”。
  - 知识管理： 《质量手册》第7.1.6章“组织的知识”要求管理经验教训。决议：在 “03-日常制度” 或 “07-质量保障” 中考虑增加知识积累与分享机制。
  - 管理评审与持续改进： 《质量手册》第9.3、10章及《程序文件汇编》中《管理评审控制程序》、《纠正和预防措施控制程序》形成了闭环改进机制。决议：在 “01-管理体系” 或 “07-质量保障” 中明确研发管理评审输入（如项目总结、度量分析、内审结果）及持续改进的要求。
二、 汇入与融合原则
经会议讨论，形成以下决议：
1. 以ISO9001为框架，以研发规则为落脚点： 保持研发管理规则现有结构（01-07大类）的清晰和实用性，将ISO9000的要求融入其中，不另起炉灶。
2. 查漏补缺，强化系统： 重点补充现有研发制度中相对薄弱或缺失的系统化管理环节，如风险、供方、知识、绩效度量与改进闭环。
3. 职责对应，流程贯通： 在融合过程中，必须明确各项活动在《质量手册》附录5（部门职责）与现有研发团队职责中的对应关系，确保流程可执行。
4. 文件层级清晰： 融合后的制度体系应保持：
  - 一级（方针/目标）： 《质量手册》相关内容。
  - 二级（过程/程序）： 《程序文件》核心过程要求 + 研发管理规则主体结构。
  - 三级（规范/指南/模板）： 具体的研发管理规范、技术规范、文档模板等。
三、 行动计划与职责分工
1. 成立融合工作组：
  - 组长： 肖波（管理者代表）
  - 执行副组长： 关胜亮
  - 核心成员： 运营部负责人、行政人事部负责人指定专员、研发部各领域骨干。
1. 阶段任务与时间节点：
  - 阶段一（梳理映射，2周内）： 由行政人事部牵头，工作组共同完成详细的《ISO9000条款与现有研发管理规则条目对照融合表》，明确每条ISO要求的落地位置和修改点。
  - 阶段二（修订起草，4周内）： 研发部主导，根据对照表，负责修订研发管理规则的01、02、03、04、07章节内容；运营部、行政人事部协助修订涉及采购、供应商、基础设施、培训等交叉部分。
  - 阶段三（评审与定稿，2周内）： 工作组内部评审修订稿，由管理者代表组织跨部门评审，报总经理批准。
  - 阶段四（发布与培训，1周内）： 行政人事部负责新体系的受控发布，并组织全员（特别是研发团队）培训。
1. 下次会议： 定于春节后召开工作组第一次进度会议，审查《对照融合表》。

**会议总结：**
陶建辉强调，此次融合工作不是简单的文件叠加，而是通过引入国际标准的管理思想，系统化提升公司研发管理的成熟度、规范性和抗风险能力，最终目标是保障产品高质量交付和客户满意。要求各部门高度重视，通力合作，确保融合后的研发管理体系既符合标准要求，又贴合公司实际，能有效指导日常工作。
