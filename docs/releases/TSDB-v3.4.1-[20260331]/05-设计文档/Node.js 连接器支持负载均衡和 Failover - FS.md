## 2. 背景

### 2.1 问题描述

当前 Node.js 连接器（taos-connector-node）在与 TDengine 数据库通信时存在以下问题：

1. 单点故障风险：连接器仅支持配置单个 taosAdapter 节点地址，当该节点故障时，整个应用将失去数据库连接能力。
2. 手动故障恢复：连接断开后需要应用层手动处理重连逻辑，增加了开发和运维复杂度。

### 2.2 目标

通过引入负载均衡和 Failover 机制，实现：

- 支持配置多个 taosAdapter 节点，自动分发连接。
- 当当前节点故障时，自动无缝切换到其他可用节点。
- 提供重试与退避参数，允许按业务可靠性目标调整行为。

## 3. 定义

- 故障转移（Failover）：当主节点或服务不可用时，自动切换到备用节点或服务的机制。
- 负载均衡（Load Balancing）：将请求或工作负载分配到多个服务器或资源上的技术，以优化资源使用、最大化吞吐量、最小化响应时间。
- 服务端点（Endpoint）：包含主机名和端口的连接目标。
- 最少连接（Least Connections）：优先选择当前活跃连接数最少的节点；并在并列时随机选择。

## 4. 行为说明

### 4.1 配置参数

#### 4.1.1 新增配置项

| 参数名               | 类型   | 默认值（毫秒） | 有效范围 | 说明                         |
| -------------------- | ------ | -------------- | -------- | ---------------------------- |
| retries              | number | 5              | >= 0     | 每个地址的最大重连尝试次数。 |
| retry_backoff_ms     | number | 200            | > 0      | 初始退避时间（毫秒）。       |
| retry_backoff_max_ms | number | 2000           | > 0      | 最大退避时间（毫秒）。       |

说明：

- 当参数缺失、非法或越界时，连接器会回退到默认值。
- 退避公式：`delay(n) = min(retry_backoff_ms * 2^n, retry_backoff_max_ms)`。

#### 4.1.2 地址与 DSN 规则

- 支持多地址：`ws://user:pass@host1:6041,host2:6042,[::1]:6043/db?...`。

#### 4.1.2 配置示例

```javascript
const dsn =
  "ws://root:taosdata@localhost:6041,localhost:6042?retries=5&retry_backoff_ms=200&retry_backoff_max_ms=2000";
const conf = new WSConfig(dsn);
const client = await WsSql.open(conf);
```

### 4.2 负载均衡行为

1. 首次连接：从候选地址中选择“当前活跃连接数最少”的地址。
2. 地址切换：重连切换时继续使用最少连接策略。
3. 并列打散：多个地址连接数相同，随机选择一个地址。
4. 连接计数：连接 `onopen` 成功后计数 `+1`，连接关闭/替换时计数 `-1`。

### 4.3 Failover 行为说明

#### 4.3.1 触发条件

- 连接关闭（非正常关闭）。
- 发送阶段出现网络相关异常（如连接已关闭、socket 写失败、超时等）。

#### 4.3.2 重连流程

- 使用重连锁收敛并发重连请求，保证同一时刻仅有一个重连流程执行。
- 对当前地址执行最多 `retries` 次重连尝试。
- 在同一地址内按指数退避等待后继续尝试。
- 当前地址耗尽后，切换到下一可选地址。

#### 4.3.3 失败处理

- 所有地址与重试都失败后，返回连接失败错误。

### 4.4 模块级行为说明

| 模块              | 行为说明                                                                 | 备注                                                                                                                                                                     |
| ----------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| SQL 写入          | 自动恢复 WebSocket 连接，并重发请求。                                    | 对于部分函数（如 NOW()）、创建用户以及各类创建语句（包括但不限于建库、建表、建 Topic 和建流等），如果语句中未包含 IF NOT EXISTS 条件判断，在执行时可能会遇到幂等性问题。 |
| SQL 查询          | 自动恢复 WebSocket 连接，并对未使用结果集的请求进行重发处理。            | 无                                                                                                                                                                       |
| 参数绑定（STMT2） | 自动恢复 WebSocket 连接与会话状态，并对未使用结果集的请求进行重发处理。  | 无                                                                                                                                                                       |
| 无模式写入        | 自动恢复 WebSocket 连接，并重发请求。                                    | 对于 InfluxDB 行协议，在执行时可能会遇到幂等性问题。                                                                                                                     |
| 数据订阅          | 自动恢复 WebSocket 连接，poll 从最后一次提交的 offset 位置继续拉取消息。 | poll 在执行时可能会遇到消息重复消费问题。                                                                                                                                |

## 5. 性能

影响分析：

| 场景     | 影响       | 说明                               |
| -------- | ---------- | ---------------------------------- |
| 连接建立 | 轻微增加   | 需要根据最少连接策略选择节点       |
| 正常运行 | 无显著影响 | 连接复用连接池中的连接             |
| 故障切换 | 增加延迟   | 需要建立新连接，延迟取决于网络状况 |

优化目标：

- 连接池获取连接的性能下降 < 5%
- 故障切换总耗时 < 30 秒（含重试）

## 6. 安全

1. 认证信息保持：Failover 切换后，新连接应使用相同的认证信息（用户名、密码、Token）。
2. TLS 支持：所有节点连接支持 wss:// 协议，加密传输数据。
3. 敏感信息脱敏：日志及连接池 key 输出不应包含明文 password/token/bearer_token。

## 7. 兼容性

向后兼容：

- 单节点配置（使用 host + port）保持完全兼容，行为不变。
- 现有 API 调用方式不变，新增功能通过可选配置启用。

协议兼容：

- 与现有 WebSocket 通信协议完全兼容。

## 8. 运维

- 日志输出：记录重连开始、重连成功、地址切换、重放中断等关键事件。

## 9. 使用场景

高可用生产环境部署：生产环境部署 3 节点 taosAdapter 集群，要求数据库连接高可用。

配置：

```javascript
const dsn =
  "ws://root:taosdata@node1:6041,node2:6041,node3:6041?retries=5&retry_backoff_ms=200&retry_backoff_max_ms=2000";
const conf = new WSConfig(dsn);
const client = await WsSql.open(conf);
```

效果：

- 任一节点故障时，连接自动切换到其他节点。
- 应用无需处理连接故障。

## 10. 约束和限制

约束：

- 至少需要配置一个有效节点地址。
- 所有配置的节点必须使用相同的认证信息。
- 所有配置的节点必须属于同一个 TDengine 集群。

限制：

- 会话状态：Failover 切换后，部分会话状态可能需要重新建立（如未完成的订阅）。
- 数据一致性：Failover 期间正在执行的查询可能返回错误，需要应用层重试。

## 11. 常见错误和排查

| 错误                | 原因                                                                        | 排查                                                                                                                                                   |
| ------------------- | --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 没有可用端点        | 1. 所有配置的 taosAdapter 节点都不可用<br>2. 网络问题导致无法连接到任何节点 | 1. 检查 taosadapter 服务状态：systemctl status taosadapter<br>2. 检查网络连通性：curl http://node:6041/rest/sql<br>3. 查看连接器日志，确认具体错误原因 |
| 频繁 Failover       | 网络不稳定                                                                  | 检查网络稳定性                                                                                                                                         |
| Failover 后认证失败 | 1. 各节点认证配置不一致<br>2. Token 过期                                    | 1. 确认所有节点使用相同的 username/password<br>2. 检查 Token 配置是否正确                                                                              |
| 重试配置未生效      | 参数非法（如负数或非数字）被回退到默认值                                    | 1. 检查 DSN 参数格式<br>2. 查看启动日志中的实际重连行为是否符合默认参数                                                                                |
