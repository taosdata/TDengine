### 4.2 人工审计

- **自顶向下**：基于威胁建模报告，定位关键安全控制点
- **自底向上**：追踪用户可控输入路径，检查危险函数使用

### 4.3 重点检查项

#### C/C++ 重点

- [ ] 缓冲区溢出：数组访问越界、字符串操作边界检查
- [ ] Use-After-Free / 双重释放：指针释放后清空、生命周期管理
- [ ] 整型溢出与回绕：内存分配、数组索引、循环计算
- [ ] 未初始化内存：malloc 分配的结构体
- [ ] 危险函数使用：strcpy、sprintf、system 等

#### Rust 重点

- [ ] `unsafe` 块审计：必要性、SAFETY 注释
- [ ] 生命周期与所有权正确性
- [ ] `panic` 安全：数据结构不变量

#### 通用逻辑

- [ ] 输入验证：类型、长度、范围、业务规则
- [ ] 身份认证与授权：操作前验证、水平越权检查
- [ ] 加密与随机数：算法强度、CSPRNG 使用
- [ ] 错误处理：信息泄露防护

### 5.2 详细发现

#### 发现 1：虚拟表列引用内存问题（高危）

- **严重等级**：高危
- **所在模块**：查询引擎
- **代码位置**：source/common/src/ttime.c（修复于2026-03-31）
- **问题描述**：虚拟表列引用过程中存在内存管理不当，可能导致堆溢出或使用已释放内存
- **修复状态**：已修复（提交：138e4c18d37）
- **修复要点**：正确管理列引用的生命周期，防止内存泄漏

#### 发现 2：Stream 操作中的堆内存使用后释放（高危）

- **严重等级**：高危
- **所在模块**：Stream（流计算）
- **代码位置**：Stream处理模块
- **问题描述**：Stream堆内存释放后仍被访问（Use-After-Free），可能导致数据损坏或任意代码执行
- **修复状态**：已修复（提交：195b7a8f5a6）
- **修复要点**：确保内存释放后不再被引用，添加适当的生命周期管理

#### 发现 3：用户认证批量响应反序列化失败时的内存泄漏（中危）

- **严重等级**：中危
- **所在模块**：认证模块
- **代码位置**：用户认证响应处理
- **问题描述**：当deserialize userAuthBatchRsp失败时，分配的内存未被正确释放
- **修复状态**：已修复（提交：9f7b3320499）
- **修复要点**：在异常路径上添加内存清理，确保资源释放

#### 发现 4：密码变更逻辑缺陷（中危）

- **严重等级**：中危
- **所在模块**：Explorer/权限管理
- **代码位置**：密码变更模块
- **问题描述**：密码变更过程中验证逻辑不完善，可能导致密码未被正确更新或权限校验绕过
- **修复状态**：已修复（提交：d3bd469c07f）
- **修复要点**：增强密码变更的验证流程，确保旧密码验证、新密码复杂度检查、日志记录

#### 发现 5：依赖项安全漏洞（中危）

- **严重等级**：中危
- **所在模块**：第三方依赖
- **问题描述**：
  - Jackson库版本过期（CVE-2024-50379）
  - quinn/reqwest审计检查失败
  - minimatch库安全漏洞
  - glog库CVE-2024-45339
- **修复状态**：已修复（多个提交）
- **修复要点**：升级依赖项到安全版本，定期执行漏洞扫描

#### 发现 6：SQL注入防护不完整（中危）

- **严重等级**：中危
- **所在模块**：Explorer、查询处理
- **问题描述**：某些查询路径中参数验证不充分，存在SQL注入风险
- **修复状态**：已修复（设计评审已通过）
- **修复要点**：实现参数化查询和输入白名单验证

#### 发现 7：明文密码传输风险（低危）

- **严重等级**：低危
- **所在模块**：Explorer
- **问题描述**：Explorer未配置SSL时，密码可能以明文形式传输
- **修复状态**：已修复（提交：bdb48870929）
- **修复要点**：
  - 实现SQL传输层混淆
  - 加强无SSL环境下的数据保护
  - 添加安全警告提示

#### 发现 8：Windows应用程序兼容性漏洞（低危）

- **严重等级**：低危
- **所在模块**：Windows安装器
- **问题描述**：
  - 缺少VC++运行时检查
  - Python进程管理不当
  - monitorFqdn配置验证不足
- **修复状态**：已修复（多个提交）
- **修复要点**：增强安装器的兼容性检查和错误处理

#### 发现 9：行结束符规范化（低危）

- **严重等级**：低危
- **所在模块**：源代码管理
- **问题描述**：代码库中存在混合的行结束符（CRLF和LF），可能导致跨平台兼容性问题
- **修复状态**：已修复（提交：9f975ce8034）
- **修复要点**：统一所有源文件为LF格式，添加.gitattributes规范化规则
