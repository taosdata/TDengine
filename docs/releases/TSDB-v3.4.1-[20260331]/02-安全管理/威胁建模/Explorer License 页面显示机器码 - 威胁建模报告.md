### 3. 分析报告

本报告针对 Explorer License 页面显示机器码功能进行了威胁建模分析。该功能旨在 Explorer 的 License 管理页面中新增机器码（Machine Code）的只读展示，使管理员无需手动执行 SQL 命令即可获取 license 激活所需信息，简化操作流程。

- 核心发现：共识别出 `4` 个潜在威胁，其中 `高危` `0` 个，`中危` `0` 个，`低危` `4` 个。
- 主要风险场景：
   - 信息泄露：机器码在网络传输过程中可能被截获，但已有 HTTPS 机制保护。
   - 未授权访问：非管理员用户可能尝试访问机器码信息，但已有权限控制机制。
   - 资源滥用：频繁刷新可能产生不必要的 SQL 查询负载，但影响极小。
- 结论：该功能设计安全风险极低。功能本身为只读信息展示，不引入新的攻击面，完全复用 Explorer 现有安全架构（管理员权限校验、HTTPS 传输、sendSQLReq API）。识别的威胁均为低危且已被现有机制有效缓解，可直接进入开发阶段。

### 4. 威胁识别与分析（STRIDE）

本功能在 Explorer License 管理页面新增机器码显示项，通过执行硬编码的 `show cluster machines` SQL 命令获取数据并以只读方式展示。数据流为：前端 Vue 组件 → sendSQLReq API → TDengine 服务端 → 返回机器码 → 前端展示。

#### 4.1 关键实体与数据

| 实体/数据 | 描述 | 敏感性 |
| --- | --- | --- |
| 机器码（Machine Code） | 通过 `show cluster machines` 返回的集群硬件指纹字符串，用于 license 激活 | 低（集群标识信息，非密钥或隐私数据） |
| sendSQLReq API 请求 | Explorer 前端向后端发送的 SQL 查询请求 | 低（使用现有认证机制保护） |
| SQL 查询响应 | 包含 cluster id、dnode_num、machine、version 等字段的 JSON 响应 | 低（集群元数据信息） |

#### 4.2 威胁评估

| 威胁ID | **威胁描述/攻击场景** | **STRIDE** | **相关组件/数据流** | **风险等级** |
| --- | --- | --- | --- | --- |
| T-EXPLMC-01 | 未授权查看机器码：非管理员用户或未认证用户尝试直接访问 License 页面或构造 API 请求以获取机器码信息。 | S (仿冒) | 前端页面 → sendSQLReq API | 低 |
| T-EXPLMC-02 | 网络传输信息泄露：攻击者在网络层截获 `show cluster machines` 的响应数据，获取机器码和集群元数据信息。 | I (信息泄露) | sendSQLReq API ↔ TDengine 服务端 | 低 |
| T-EXPLMC-03 | SQL 命令篡改：攻击者尝试篡改前端发送的 SQL 命令，将 `show cluster machines` 替换为恶意 SQL 语句以获取更多数据或执行破坏操作。 | T (篡改) | 前端 → sendSQLReq API | 低 |
| T-EXPLMC-04 | 刷新滥用导致查询负载：攻击者通过自动化脚本频繁点击刷新按钮，大量触发 `show cluster machines` 查询，增加服务端负载。 | D (拒绝服务) | 前端刷新 → sendSQLReq API → TDengine | 低 |

### 5. 安全需求与设计约束

| 威胁ID | **转化后的安全需求/设计约束** | **类型** | **优先级** |
| --- | --- | --- | --- |
| T-EXPLMC-01 | SEC-EXPLMC-001（访问控制）：License 管理页面必须保持仅管理员可访问的权限控制，`sendSQLReq` API 需验证请求者身份和权限。（已由现有机制实现） | 安全功能需求 | 低 |
| T-EXPLMC-02 | SEC-EXPLMC-002（传输加密）：Explorer 与 TDengine 之间的通信应使用 HTTPS/TLS 加密传输，防止数据在传输过程中被截获。（已由现有机制实现） | 安全设计约束 | 低 |
| T-EXPLMC-03 | SEC-EXPLMC-003（命令固化）：前端执行的 SQL 命令必须硬编码为 `show cluster machines`，不接受用户输入拼接，服务端应对 API 请求进行权限校验。（设计已满足） | 安全设计约束 | 低 |
| T-EXPLMC-04 | SEC-EXPLMC-004（请求频率）：依赖 Explorer 现有的请求频率限制机制，`show cluster machines` 为轻量级查询（10ms 内完成），即使频繁调用对服务端影响也极小。（现有机制已满足） | 非功能安全需求 | 低 |
