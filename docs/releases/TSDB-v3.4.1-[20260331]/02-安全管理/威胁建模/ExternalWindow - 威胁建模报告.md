### 3. 分析报告

本报告针对 ExternalWindow 功能进行了威胁建模分析。该功能旨在为 TDengine 引入一种基于外部查询定义的窗口作用域机制，通过 `EXTERNAL_WINDOW ((subquery) alias)` 语法，允许用户在查询中使用由子查询（而非数据集自身时间线）定义的窗口进行聚合和标量计算，支持跨表窗口关联、分组对齐、嵌套调用等能力。

- 核心发现：共识别出 `5` 个潜在威胁，其中 `高危` `0` 个，`中危` `2` 个，`低危` `3` 个。
- 主要风险场景：
  - 嵌套查询资源耗尽：多层嵌套 external window 可能产生指数级计算复杂度。
  - 大量窗口资源消耗：子查询产生海量 Window Instance 时可能耗尽内存和计算资源。
- 结论：该功能为 SQL 查询语法层面的扩展，不引入新的通信协议、持久化存储变更或外部依赖，攻击面有限。设计中已包含多项安全约束（流/订阅禁用、输入验证分层、分组对齐隔离），整体安全风险低。

### 4. 威胁识别与分析（STRIDE）

ExternalWindow 功能在现有 SQL 查询执行框架基础上，新增了基于子查询的窗口定义和窗口化计算能力。该功能不涉及数据写入（除 INSERT INTO SELECT 场景），不引入新的通信协议，执行依赖现有 SQL 解析和查询执行链路。子查询可访问与外层查询不同的表，支持多层嵌套。

#### 4.1 关键实体与数据

| 实体/数据 | 描述 | 敏感性 |
| --- | --- | --- |
| Window Relation | 子查询产生的临时结果集，每行代表一个 Window Instance | 低（查询临时数据） |
| Window Instance 时间区间 | 每个窗口的 [start_ts, end_ts] 闭区间 | 低（时间范围信息） |
| Window Instance 属性列 | 子查询中除时间列外的附加列，在外层查询中作为常量引用 | 中（可能包含业务数据） |
| groupKey | 内外分组对齐使用的分组键（字符串拼接求 hash） | 低（内部计算标识） |
| lag/lead 缓存数据 | lag/lead 函数执行时缓存的前/后行数据 | 低（查询临时数据） |

#### 4.2 威胁评估

| 威胁ID | **威胁描述/攻击场景** | **STRIDE** | **相关组件/数据流** | **风险等级** |
| --- | --- | --- | --- | --- |
| T-EXTWIN-01 | 子查询跨表权限校验绕过：ExternalWindow 的子查询可引用与外层查询不同的表（如 FS 5.1.1 节中外层查询 `alarm1`，子查询访问 `fault1`）。若查询执行引擎未对子查询中涉及的表进行独立权限校验，攻击者可能通过构造 external window 子查询读取无权访问的表中的时间戳和属性列数据。 | E (权限提升) | SQL 解析 → 子查询执行 → 表数据 | 中 |
| T-EXTWIN-02 | 嵌套 external window 资源耗尽：FS 第 4.4 节允许多层嵌套 external window（如 FS 5.1.3 节的三层嵌套示例），每层嵌套需独立执行子查询并维护 Window Relation。攻击者可构造深层嵌套查询，使计算复杂度指数增长，耗尽服务端内存和 CPU 资源，影响集群其他正常查询的执行。 | D (拒绝服务) | 客户端 → 查询引擎 → vnode | 中 |
| T-EXTWIN-03 | 大量 Window Instance 资源消耗：子查询对大表的查询可能产生海量 Window Instance（如对千万级时序数据的 event_window 输出），所有窗口实例需加载到内存中进行关联计算。若未对窗口数量设置上限，可能导致单次查询消耗过多内存，触发 OOM 或影响同节点其他查询。 | D (拒绝服务) | 子查询结果 → Window Relation → 聚合计算 | 低 |
| T-EXTWIN-04 | 运行时错误信息泄露：FS 第 7.2 节定义了多种运行时错误场景（无效窗口、乱序窗口、NULL 时间区间）。若错误消息中包含子查询的内部执行细节（如涉及的表名、数据分布信息、具体的窗口时间值），可能被攻击者利用来推断数据库结构或数据特征。 | I (信息泄露) | 查询执行 → 错误响应 → 客户端 | 低 |
| T-EXTWIN-05 | 重叠窗口导致重复数据扫描：FS 第 6.0.2 节明确重叠窗口各自独立计算。攻击者可构造大量高度重叠的窗口（如数千个几乎相同时间范围的窗口），迫使引擎对相同数据范围进行重复扫描和聚合，放大 I/O 和计算开销，实现查询级别的资源滥用。 | D (拒绝服务) | Window Relation → 聚合计算 → vnode I/O | 低 |

### 5. 安全需求与设计约束

| 威胁ID | **转化后的安全需求/设计约束** | **类型** | **优先级** |
| --- | --- | --- | --- |
| T-EXTWIN-01 | SEC-EXTWIN-001（子查询权限校验）：ExternalWindow 子查询执行时，必须对子查询中涉及的所有表进行独立的权限校验，确保用户对外层查询和子查询涉及的全部表均具有相应读权限。当前设计通过复用 SQL 执行引擎的表级权限检查机制实现此约束。 | 安全设计约束 | 中 |
| T-EXTWIN-02 | SEC-EXTWIN-002（查询资源管控复用）：ExternalWindow 查询（包括嵌套场景）的执行应受现有查询资源管控机制（查询超时 `queryTimeout`、内存限制）的约束，不应绕过任何资源限制策略。 | 非功能安全需求 | 中 |
| T-EXTWIN-04 | SEC-EXTWIN-003（错误信息规范）：ExternalWindow 相关的运行时错误消息（无效窗口、乱序窗口等）应遵循 TDengine 现有错误处理规范，仅返回错误类型和通用描述，不在错误消息中暴露子查询涉及的表名、具体数据值或内部执行细节。 | 安全设计约束 | 低 |
