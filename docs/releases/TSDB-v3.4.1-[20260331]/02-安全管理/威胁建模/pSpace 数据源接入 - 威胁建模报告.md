### 3. 分析报告

本报告针对 pSpace 数据源接入功能进行了威胁建模分析。该功能通过 taosX pSpace plugin（基于力控科技 Java SDK 封装）实现 pSpace 工业实时历史数据库与 TDengine TSDB 的数据互通，支持历史数据迁移、实时数据订阅和查询同步三种模式。

- **核心发现：** 共识别出 `8` 个潜在威胁，其中 `高危` `1` 个，`中危` `4` 个，`低危` `3` 个。
- **主要风险场景：**
   - **凭证明文泄露：** pSpace 用户名/密码以明文存在于 DSN URL 和 toml 配置文件中，是本功能最高优先级安全风险。
   - **未加密通信遭中间人攻击：** pSpace SDK 通信层是否使用 TLS 未明确，在非隔离网络中存在 MITM 风险。
   - **第三方 SDK 供应链风险：** 依赖力控科技闭源 Java SDK，版本管理和漏洞跟踪需纳入 SBOM。
- **结论：** 本功能为工业数据接入场景，架构设计合理，整体风险偏低。必须在发布前完成凭证存储方式确认及 SDK SBOM 登记，并对用户提供网络隔离部署建议。

### 4. 威胁识别与分析（STRIDE）

pSpace plugin 作为 taosX 受控子进程，通过 pSpace Java SDK 与 pSpace 服务器通信，读取工业时序数据后写入 TDengine TSDB。主要数据流：

```
用户(taos-Explorer) → taosX → pSpace plugin(JAR) → pSpace Server
                                      ↓
                               TDengine TSDB
```

#### 4.1 关键实体与数据

| 实体/数据 | 描述 | 敏感性 |
| --- | --- | --- |
| pSpace 连接凭证 | 用户名/密码，用于向 pSpace 服务器认证 | 高 |
| pSpace 时序数据 | 工业设备传感器数据点值（温度、压力等工艺参数） | 中（业务数据） |
| toml 配置文件 | 含连接参数和任务配置，可能包含明文密码 | 高 |
| CSV 配置文件 | 含数据点映射规则（point_id、表名、列名等） | 中 |
| pSpace 节点树 | pSpace 的树形数据组织结构，反映工厂/设备拓扑 | 中 |
| keep_raw_data 文件 | 可选的本地原始数据缓存文件 | 中（工业原始数据） |
| DSN URL | 含凭证的连接字符串 | 高 |

#### 4.2 威胁评估

| 威胁ID | 威胁描述/攻击场景 | STRIDE | 相关组件/数据流 | 风险等级 |
| --- | --- | --- | --- | --- |
| T-PSPACE-01 | **pSpace 凭证明文泄露：** toml 配置文件和 DSN URL 中明文存储 pSpace 用户名/密码。拥有 taosX 服务器文件系统读取权限的攻击者可直接获取凭证，进而访问 pSpace 工业历史数据库，查询或篡改工厂传感器数据。 | I（信息泄露） | toml 配置文件 → pSpace Server | 高 |
| T-PSPACE-02 | **MITM 篡改工业数据：** 若 pSpace SDK 与 pSpace 服务器之间的通信不经 TLS 加密，网络中间人可在传输过程中篡改传感器数据（如修改气温读数、质量标志位），导致 TDengine 中写入的历史数据失真。 | T（篡改） | pSpace plugin → pSpace Server 网络链路 | 中 |
| T-PSPACE-03 | **伪造 pSpace 服务器：** 攻击者通过 DNS 劫持或 ARP 欺骗将 taosX 连接引导至恶意 pSpace 服务器。若无服务器证书校验，plugin 将接收虚假数据写入 TDengine，或在认证握手过程中泄露凭证。 | S（仿冒） | pSpace plugin → 目标服务器 | 中 |
| T-PSPACE-04 | **keep_raw_data 原始数据文件暴露：** 当任务配置 `keep_raw_data=true` 时，原始 pSpace 时序数据以明文文件持久化至本地目录（默认 `./raw_data`）。若目录权限设置不当（如 world-readable），同主机的其他进程或低权限用户可读取工业传感器历史数据。 | I（信息泄露） | pSpace plugin → 本地文件系统 | 中 |
| T-PSPACE-05 | **过宽 pSpace 账号权限滥用：** taosX 使用单一 pSpace 账号执行连通检查、节点枚举、数据读取全部操作。若该账号为管理员账号，可通过调整 `root` 参数和 `point_name_pattern` 枚举并读取超出业务需要的数据点范围，违反最小权限原则。 | E（权限提升） | pSpace 账号权限 → pSpace Server | 中 |
| T-PSPACE-06 | **第三方 SDK 供应链风险：** pSpace Java SDK 为力控科技闭源组件，若 SDK 自身存在已知漏洞（如反序列化漏洞、内存溢出）未被及时修复，攻击者可利用与 pSpace 服务器通信过程中的异常响应触发 plugin 端漏洞，进而影响 taosX 主进程。 | T（篡改）/ E（权限提升） | pSpace SDK 依赖链 | 中 |
| T-PSPACE-07 | **历史数据迁移抵赖：** 历史数据批量迁移任务执行后，缺少"何时触发、由谁触发、迁移数据范围（起止时间、数据点列表）、实际写入行数"的完整审计记录，若迁移后发现数据质量问题，难以追溯操作责任和数据来源。 | R（抵赖） | 任务执行日志 | 低 |
| T-PSPACE-08 | **CSV 配置文件恶意注入：** 攻击者上传精心构造的 CSV 配置文件，注入异常表名（如超长字符串、含特殊字符的 stable/tbname 字段），可能导致 taosX 在向 TDengine 写入时产生非预期行为（如表名截断、写入错误表）。 | T（篡改） | CSV 上传 → TDengine 写入 | 低 |

### 5. 安全需求与设计约束

| 威胁ID | 转化后的安全需求/设计约束 | 类型 | 优先级 |
| --- | --- | --- | --- |
| T-PSPACE-01 | **SEC-PSPACE-001（凭证保护）：** taosX 平台对 pSpace 连接凭证的存储必须明确：若落盘，需采用加密存储（如 AES-256）或依托操作系统密钥链，而非明文写入配置文件；运行时凭证传递需通过环境变量或内存传参，避免在进程命令行参数中暴露密码。 | 安全设计约束 | 高 |
| T-PSPACE-02、T-PSPACE-03 | **SEC-PSPACE-002（通信安全）：** 调研 pSpace SDK 是否支持 TLS 加密通信及服务器证书校验。若不支持，必须在产品文档和部署指南中明确说明：pSpace Server 与 taosX 需部署于同一受信任内网区域，并通过网络隔离（VLAN/防火墙）防止 MITM 攻击。 | 安全设计约束 | 中 |
| T-PSPACE-04 | **SEC-PSPACE-003（原始数据文件权限）：** 当 `keep_raw_data=true` 时，pSpace plugin 创建的 `keep_raw_data_dir` 目录权限应设置为仅 taosX 运行用户可读写（chmod 700），并在用户手册中说明此配置的安全含义。 | 非功能安全需求 | 中 |
| T-PSPACE-05 | **SEC-PSPACE-004（最小权限建议）：** 在用户手册中建议：为 taosX 创建专用的 pSpace 只读账号，限制其可访问的节点范围，避免使用管理员账号执行数据同步任务。 | 非功能安全需求 | 中 |
| T-PSPACE-06 | **SEC-PSPACE-005（SDK SBOM 管理）：** 将 pSpace Java SDK 版本信息（GAV 坐标或 JAR 的 SHA256）纳入 TSDB v3.4.1 SBOM，建立 SDK 版本跟踪机制，确保已知 CVE 可被及时识别和响应。 | 供应链安全 | 中 |
