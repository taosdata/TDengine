### 3. 分析报告

本报告针对「taosadapter 记录 STMT 到 CSV」功能进行了威胁建模分析。该功能旨在为运维人员提供诊断能力，通过配置文件或 HTTP API 动态开启，将 taosadapter 中 STMT2 WebSocket 请求的准备（prepare）、绑定（bind）和执行（exec）操作记录到本地 CSV 文件，并复用已有日志管理机制（轮转、压缩、空间保护）进行文件生命周期管理。

- **核心发现：** 共识别出 `6` 个潜在威胁，其中 `高危` `1` 个，`中危` `3` 个，`低危` `2` 个。
- **主要风险场景：**
  - 越权数据采集：低权限用户启用录制功能，捕获全局所有用户的 SQL 语句和业务绑定数据。
  - 录制文件泄露：CSV 文件权限不当导致本地操作系统用户读取含业务数据的明文录制内容。
  - 高吞吐场景磁盘压力：TDengine 高并发 STMT2 写入时开启录制，可能在磁盘保护检查间隔内产生大量数据。
- **结论：** 该功能设计整体合理，默认关闭、按需启用、有时间边界，基本满足运维诊断场景的安全要求。但接口权限未限定为管理员角色、文件系统权限未明确规定，是需在实现和部署规范中补充落实的关键安全约束。

### 4. 威胁识别与分析（STRIDE）

该功能引入的新攻击面主要包括：新增 HTTP API 端点 `/record_stmt`（POST/DELETE/GET）、本地 CSV 录制文件（含 SQL 和 bind 数据）、以及 taosadapter 与磁盘之间的写入数据流。

#### 4.1 关键实体与数据

| 实体/数据 | 描述 | 敏感性 |
| --- | --- | --- |
| CSV 录制文件 | 存储于 taosadapter 日志目录，包含 STMT2 操作的完整上下文 | 高（含 SQL、业务数据、用户信息） |
| bind 参数数据 | STMT2 绑定的列值，序列化为 JSON，包含原始时序业务数值 | 高（含敏感业务时序数据） |
| `/record_stmt` API | 动态开启/关闭/查询录制任务的 HTTP 端点 | 中（控制平面接口） |
| 客户端元数据 | CSV 中记录的用户名、客户端 IP、端口、AppName | 中（可用于用户行为分析） |
| 准备 SQL（prepare） | STMT2 prepare 阶段的 SQL 模板，含表名、列名 | 中（含数据库结构信息） |

#### 4.2 威胁评估

| 威胁 ID | 威胁描述/攻击场景 | STRIDE | 相关组件/数据流 | 风险等级 |
| --- | --- | --- | --- | --- |
| T-STMTCSV-01 | **越权启用录制获取他人数据：** 低权限用户（非管理员）通过调用 POST `/record_stmt` 开启录制，由于录制捕获所有并发 STMT2 操作，该用户可借此获取其他用户的 SQL 语句、表名和 bind 绑定数据（如传感器读数、工业数据等敏感时序值）。 | I（信息泄露）E（权限提升） | `/record_stmt` API → CSV 录制文件 | 高 |
| T-STMTCSV-02 | **CSV 文件权限不当导致数据泄露：** CSV 录制文件存储在 taosadapter 日志目录，若文件系统权限未限制为仅 taosadapter 运行用户可读，同一服务器上的其他 OS 用户（如共享部署环境的其他服务账户）可直接读取包含 SQL 和业务数据的明文文件。 | I（信息泄露） | CSV 录制文件 → 文件系统 | 中 |
| T-STMTCSV-03 | **高并发写入场景磁盘耗尽：** TDengine 典型的高吞吐时序数据写入场景下（如大量设备并发 STMT2 写入），每个 bind/exec 操作均产生一行 CSV 记录，数据量可能在磁盘保护机制的检查间隔内迅速积累，短时间内生成大量数据，影响正常日志系统和业务写入。 | D（拒绝服务） | STMT2 WebSocket → CSV 写入 → 磁盘 | 中 |
| T-STMTCSV-04 | **录制文件被篡改破坏审计证据：** 具有文件系统访问权限的攻击者可修改已生成的 CSV 录制文件内容（如修改 SQL 语句、删除特定 QID 的记录），由于文件无完整性校验（无哈希/HMAC），篡改后无法被发现，使录制文件无法作为可信审计证据。 | T（篡改） | CSV 录制文件 | 中 |
| T-STMTCSV-05 | **录制操作本身缺乏审计：** FS 未明确说明需在安全日志中记录"哪个用户从哪个 IP 触发了录制开启/关闭"。若仅有任务启停的普通日志而无用户身份信息，则录制行为本身存在抵赖风险——无法事后证明是谁在何时开启了敏感数据的录制。 | R（抵赖） | `/record_stmt` API → 审计日志 | 低 |
| T-STMTCSV-06 | **错误响应泄露内部状态：** 部分错误信息（如 "start time xxx is after end time xxx"、"end time xxx is in the past"）会将用户提交的原始时间字符串原样回显，在某些异常情况下可能间接暴露系统当前时间或时区设置，整体风险较低。 | I（信息泄露） | `/record_stmt` API 错误响应 | 低 |

### 5. 安全需求与设计约束

| 威胁 ID | 转化后的安全需求/设计约束 | 类型 | 优先级 |
| --- | --- | --- | --- |
| T-STMTCSV-01 | **SEC-STMTCSV-001（接口权限控制）：** `/record_stmt` 接口（POST/DELETE/GET）必须限定为超级用户（TDengine root 账户或具有 sysinfo 权限的管理员账户）方可调用，普通认证用户应收到 403 响应。 | 安全功能需求 | 高 |
| T-STMTCSV-02 | **SEC-STMTCSV-002（文件权限规范）：** 部署文档/运维规范中应明确要求 CSV 录制文件的文件系统权限设置为仅 taosadapter 运行用户可读写（建议 600 或 640），禁止全局可读。 | 安全设计约束 | 中 |
| T-STMTCSV-03 | **SEC-STMTCSV-003（磁盘保护增强）：** 建议在文档中说明在高并发写入场景下开启录制的性能和磁盘风险，并建议通过 `log.reservedDiskSize` 配置足够的保留空间阈值。 | 非功能安全需求 | 中 |
| T-STMTCSV-05 | **SEC-STMTCSV-004（操作审计）：** 开启和关闭录制的操作日志应包含调用者的用户名和客户端 IP，确保录制行为可溯源。 | 审计需求 | 低 |
