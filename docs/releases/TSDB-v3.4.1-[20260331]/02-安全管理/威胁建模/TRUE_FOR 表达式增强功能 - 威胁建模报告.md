### 3. 分析报告

本报告针对 TRUE_FOR 表达式增强功能进行了威胁建模分析。该功能旨在扩展 TDengine 的 `TRUE_FOR` 表达式，使其在原有"仅基于时间长度触发"的基础上，新增基于行数（COUNT）触发以及 AND/OR 组合逻辑，适用于流计算查询（CREATE STREAM）和普通查询（SELECT）中的 STATE_WINDOW 和 EVENT_WINDOW。

- **核心发现：** 共识别出 `4` 个潜在威胁，其中 `高危` `0` 个，`中危` `1` 个，`低危` `3` 个。
- **主要风险场景：**
  - 流任务内存累积：设置极大 COUNT 阈值导致流任务窗口长期不触发，内存持续累积。
  - 信息泄露：错误消息中暴露内部数据类型边界信息。
  - 抵赖风险：流任务 TRUE_FOR 条件变更（删除重建）缺乏变更审计。
- **结论：** 该功能为纯 SQL 语法层扩展，引入的新攻击面极为有限。功能设计安全性整体良好，对已识别威胁不强制要求新增安全控制，可直接进入编码实现阶段。

### 4. 威胁识别与分析（STRIDE）

本功能在 SQL 解析层扩展 TRUE_FOR 表达式语法，在流计算引擎中新增 COUNT 计数状态管理逻辑。核心数据流为：客户端提交 SQL → 解析器解析 TRUE_FOR 参数 → 执行引擎维护窗口 COUNT 状态 → 满足触发条件后输出聚合结果。

#### 4.1 关键实体与数据

| 实体/数据 | 描述 | 敏感性 |
| --- | --- | --- |
| TRUE_FOR 表达式参数 | 用户在 SQL 中指定的 COUNT 值、duration、AND/OR 逻辑 | 低（业务配置参数）|
| 窗口 COUNT 计数器 | 流计算引擎内存中维护的每个流任务窗口行数计数状态 | 低（纯计数值）|
| 流任务定义 | 包含 TRUE_FOR 条件的 CREATE STREAM 语句元数据 | 低 |
| 窗口聚合结果 | TRUE_FOR 触发后输出的时序数据聚合结果 | 取决于业务数据本身 |

#### 4.2 威胁评估

| 威胁ID | **威胁描述/攻击场景** | **STRIDE** | **相关组件/数据流** | **风险等级** |
| --- | --- | --- | --- | --- |
| T-TRUEFOR-01 | **流任务窗口内存累积：** 拥有创建流权限的用户（或配置错误）创建使用超大 COUNT 阈值的流任务（如 `TRUE_FOR(COUNT 2147483647)`），窗口永远或极少触发，流计算引擎需长期维护该窗口的内存状态，在高吞吐写入场景下可能导致内存持续增长，影响系统稳定性。 | D（拒绝服务）| 窗口 COUNT 计数器 → 流计算引擎内存 | 中 |
| T-TRUEFOR-02 | **错误信息类型边界泄露：** 错误提示（如 `COUNT value exceeds maximum limit (2147483647)`）明确暴露了 INT32_MAX 内部数据类型上界，攻击者可利用此信息推断系统实现细节，辅助构造针对整数溢出的模糊测试用例。 | I（信息泄露）| SQL 解析器 → 错误响应 | 低 |
| T-TRUEFOR-03 | **流任务变更抵赖：** 由于 TRUE_FOR 条件不支持动态修改（须删除重建），攻击者或内部人员在删除旧流、以不同 COUNT 值重建流的过程中，若审计日志未记录前后配置差异，则操作者可抵赖变更行为，无法溯源 COUNT 阈值的实际修改历史。 | R（抵赖）| 流任务定义 → 操作审计日志 | 低 |
| T-TRUEFOR-04 | **COUNT=0 条件绕过误用：** COUNT 0 被定义为"条件始终满足（等同无 TRUE_FOR 约束）"，若开发者或用户误将此理解为"不收集任何数据"而错误配置，可能导致业务逻辑缺陷（如告警去重策略完全失效），从而引发非预期数据输出或告警风暴。 | T（篡改，配置误用）| TRUE_FOR 表达式参数 → 窗口触发逻辑 | 低 |

### 5. 安全需求与设计约束

| 威胁ID | **转化后的安全需求/设计约束** | **类型** | **优先级** |
| --- | --- | --- | --- |
| T-TRUEFOR-01 | SEC-TRUEFOR-001（流任务资源保护）：建议在流计算引擎中对单个流任务的窗口内存占用或待触发数据量设置可配置上限，当超过阈值时记录警告日志或触发告警，防止单个恶意/误配置流任务耗尽系统内存。 | 健壮性需求 | 中 |
| T-TRUEFOR-02 | 现有错误消息设计可接受，无需更改。数据库产品的类型边界信息属于公开文档内容，不构成实质安全风险。 | 不适用 | 低 |
| T-TRUEFOR-03 | SEC-TRUEFOR-002（流任务变更审计）：确认 TDengine 现有审计机制已记录 DROP STREAM 和 CREATE STREAM 操作（含 SQL 全文），以支持 TRUE_FOR 条件变更的完整溯源。 | 审计需求 | 低 |
| T-TRUEFOR-04 | SEC-TRUEFOR-003（文档说明）：在用户文档中明确标注 COUNT 0 的语义（始终满足/等同无约束），避免用户误配置。 | 文档需求 | 低 |
