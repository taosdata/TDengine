### 3. 分析报告

本报告针对「taosc 心跳消息序列化兼容性优化」功能进行威胁建模分析。该功能旨在为 `SClientHbReq` 结构体的序列化/反序列化逻辑增加 start/end encode/decode 处理，解决因缺少嵌套支持而导致的潜在 coredump 问题，并将 `userDualIp` 字段的编解码移入 `SClientHbReq` 内部，保证前后兼容性。

- **核心发现：** 共识别出 `5` 个潜在威胁，其中 `高危` `0` 个，`中危` `2` 个，`低危` `3` 个。
- **主要风险场景：**
   - 畸形序列化数据触发崩溃：恶意客户端可能利用心跳消息的边界条件触发 taosd 解析异常，已通过本次 start/end 机制得到有效缓解。
   - 心跳消息明文传输信息泄露：心跳消息携带用户名、Token 名称、IP 等信息，在未启用 TLS 场景下存在泄露风险。
   - clusterId 未序列化的潜在语义歧义：结构图中标注 `clusterId` 字段未序列化，需确认设计意图避免未来引发安全缺陷。
- **结论：** 该功能设计在修复序列化崩溃缺陷方面价值显著，整体引入的新攻击面极小。识别出的主要风险（T-HBSRC-01）已通过本次设计变更得到有效缓解，其余威胁属于既有架构层面的低风险问题。建议按后续行动项完成边界条件测试后即可进入编码实现阶段。

### 4. 威胁识别与分析（STRIDE）

本功能的核心数据流为：taosc 定期将 `SClientHbBatchReq`（含若干 `SClientHbReq`）序列化后通过网络发送给 taosd，taosd 反序列化后更新连接状态。

#### 4.1 关键实体与数据

| 实体/数据 | 描述 | 敏感性 |
| --- | --- | --- |
| SClientHbBatchReq | 心跳批次消息，包含 reqId、ipWhiteListVer 及多个 SClientHbReq | 中 |
| SClientHbReq | 单个连接的心跳消息，含 user、tokenName、userIp、clusterId、查询信息、应用统计等 | 中（含用户标识信息） |
| user / tokenName 字段 | 连接所属用户名及 Token 名称 | 高（用户身份信息） |
| SAppClusterSummary | 应用层统计信息（插入行数、查询次数、慢查询数等） | 低 |
| taosc → taosd 网络通道 | 承载心跳消息的 TCP 连接 | 高（依赖 TLS 保护） |

#### 4.2 威胁评估

| 威胁ID | **威胁描述/攻击场景** | **STRIDE** | **相关组件/数据流** | **风险等级** |
| --- | --- | --- | --- | --- |
| T-HBSRC-01 | **畸形序列化数据触发服务端崩溃**：恶意客户端发送特殊构造的 SClientHbBatchReq 消息，利用 SClientHbReq 内部序列化的边界条件（如超大结构体长度、嵌套深度异常），尝试触发 taosd 解析时内存越界，导致 taosd 进程崩溃。**本次优化已通过 start/end 机制有效缓解此威胁，但需验证边界处理的健壮性。** | D（拒绝服务） | SClientHbBatchReq 解析逻辑 → taosd 心跳处理 | 中 |
| T-HBSRC-02 | **心跳消息携带用户敏感信息未加密传输**：taosc 心跳消息中包含明文的 user 字段（用户名）、tokenName 字段及 userIp（客户端 IP）。若 taosc-taosd 连接未启用 TLS（如内网部署未强制加密），攻击者可通过网络嗅探获取用户名及连接信息，进而辅助后续攻击。 | I（信息泄露） | SClientHbReq.user / tokenName / userIp → 网络传输 | 中 |
| T-HBSRC-03 | **clusterId 未序列化导致的语义歧义**：FS 结构图中 clusterId 字段标注为"未序列化（⚠️）"，若此设计未明确文档化，后续开发者可能误以为该字段已正确传输，在依赖 clusterId 进行集群路由判断时引发逻辑错误，可能被利用篡改集群归属判断。 | T（篡改） | SClientHbReq.clusterId | 低 |
| T-HBSRC-04 | **伪造心跳消息干扰连接状态管理**：在已建立的网络连接中，被攻陷的内部节点或恶意程序注入伪造的 SClientHbReq，携带虚假的 SAppClusterSummary 统计数据（如虚高的 numOfInsertRows），干扰 taosd 对客户端连接状态的维护或监控告警阈值。 | S（仿冒） | 伪造的 SClientHbReq → taosd 连接状态 | 低 |
| T-HBSRC-05 | **心跳处理过程无审计追踪**：心跳消息的接收与处理过程无独立安全日志记录。若发生异常（如版本兼容性降级时的字段静默丢失），无法追溯具体 taosc 实例（通过 user/connType 识别）的行为，增加事后溯源难度。 | R（抵赖） | taosd 心跳处理链路 | 低 |

### 5. 安全需求与设计约束

| 威胁ID | **转化后的安全需求/设计约束** | **类型** | **优先级** |
| --- | --- | --- | --- |
| T-HBSRC-01 | SEC-HBSRC-001（边界鲁棒性验证）：必须对 start/end encode/decode 机制编写边界条件测试，覆盖字段新增、字段删除、结构体长度为零、长度超大等异常场景，确保 taosd 在任何格式的心跳输入下均不会崩溃。 | 健壮性需求 | 高 |
| T-HBSRC-02 | SEC-HBSRC-002（传输加密建议）：建议在 TDengine 部署文档中明确要求 taosc-taosd 通信启用 TLS，以保护心跳消息中的用户身份信息。此为既有架构层面建议，不要求本次变更实现。 | 非功能安全需求 | 中 |
| T-HBSRC-03 | SEC-HBSRC-003（字段设计文档化）：在代码或设计文档中明确说明 clusterId 字段不序列化的设计意图（如该字段由外层 SClientHbBatchReq 或连接上下文传递），防止后续维护者产生误解。 | 设计约束 | 低 |
