### 3. 分析报告

本报告针对「支持 ALL/ANY/SOME/[NOT]EXISTS 运算符与子查询」功能进行了威胁建模分析。该功能旨在 TDengine 查询引擎中新增对 `ALL`、`ANY`、`SOME`、`EXISTS`、`NOT EXISTS` 运算符与非相关子查询结合使用的语法支持，允许用户在 SELECT、WHERE、HAVING、JOIN ON、CASE WHEN 等子句中使用上述运算符进行复杂条件筛选，每个非相关子查询仅执行一次，EXISTS/NOT EXISTS 采用短路求值逻辑。

- **核心发现：** 共识别出 `5` 个潜在威胁，其中 `高危` `1` 个，`中危` `2` 个，`低危` `2` 个。
- **主要风险场景：**
  - ALL 大结果集内存耗尽：ALL 运算符需将子查询全量结果集载入内存逐一比较，对时序大表全量扫描时可能触发查询节点 OOM。
  - 权限越权访问：用户通过子查询访问其无权读取的表，若内外层权限校验不一致，可导致数据间接泄露。
  - 深层嵌套 DoS：恶意构造多层嵌套子查询，拖垮解析器或执行器，影响服务可用性。
- **结论：** 该功能属于纯查询语法扩展，在已有「支持 IN + 非相关子查询」功能的安全模型基础上延伸，整体攻击面与前者相当。EXISTS/NOT EXISTS 短路求值机制进一步降低了部分资源消耗风险。现有的权限校验、查询超时和内存限制机制可覆盖主要威胁，无需新增专项安全设计。建议编码阶段通过代码评审确认 ALL 运算符子查询结果集内存约束与嵌套深度上限的具体实现。

### 4. 威胁识别与分析（STRIDE）

该功能在 TDengine 查询引擎中新增 `ALL/ANY/SOME/EXISTS/NOT EXISTS + 非相关子查询` 支持。子查询在执行时独立运行，其结果集作为运算符的参数使用（ALL/ANY/SOME 进行逐一比较，EXISTS/NOT EXISTS 仅判断非空）。支持的使用场景包括普通查询、嵌套查询、UNION/UNION ALL、INSERT INTO SELECT、STMT 查询、视图，以及子查询嵌套使用（FS 第 4.2、4.3 节）。

#### 4.1 关键实体与数据

| 实体/数据 | 描述 | 敏感性 |
| --- | --- | --- |
| SQL 查询文本 | 用户提交的包含上述运算符与子查询的 SQL 语句 | 中（含表名、列名等结构信息） |
| 子查询结果集 | 内层子查询执行后的临时结果集（ALL/ANY/SOME 需全量或部分载入内存；EXISTS/NOT EXISTS 短路后仅保留存在性标记） | 高（含实际业务时序数据） |
| 被查询表 | 外层查询和内层子查询分别访问的数据表（可能跨库、跨用户） | 高（含用户时序数据） |
| 查询执行计划 | 解析后生成的查询计划树，包含嵌套运算符节点 | 低 |

#### 4.2 威胁评估

| 威胁ID | 威胁描述/攻击场景 | STRIDE | 相关组件/数据流 | 风险等级 |
| --- | --- | --- | --- | --- |
| T-AAESQ-01 | **ALL 大结果集致内存耗尽**：用户（含恶意用户）构造 ALL 子查询对时序大表全量扫描（如 `col > ALL (SELECT ts FROM huge_table)`），子查询结果集可达千万行，ALL 运算符需将全量结果载入查询节点内存逐一进行比较运算，可能触发 OOM，影响同节点其他正常查询的执行。ANY/SOME 因短路求值风险较低，EXISTS/NOT EXISTS 返回首行即终止风险最低。 | D（拒绝服务） | 内层子查询 → 子查询结果集 → ALL 比较运算 | 高 |
| T-AAESQ-02 | **权限越权访问数据**：用户 A 在其有权访问的查询外层嵌入子查询，内层访问其无权读取的表（如 `WHERE col = ANY (SELECT secret_col FROM restricted_db.sensitive_table)`）。若子查询的权限校验与外层查询不一致，可能导致未授权数据通过运算符条件匹配间接泄露（用户可通过返回结果是否为空推断数据是否存在）。 | I（信息泄露） | 子查询 → 受限数据表 | 中 |
| T-AAESQ-03 | **深层嵌套 DoS**：恶意用户构造多层递归嵌套子查询（如 20 层以上），可能导致 SQL 解析器递归调用栈溢出，或查询规划阶段指数级复杂度，消耗大量 CPU 资源，影响整体服务可用性。FS 第 4.2 节第 5 条明确支持非相关子查询嵌套使用，但未提及深度限制。 | D（拒绝服务） | SQL 解析器 / 查询规划器 | 中 |
| T-AAESQ-04 | **INSERT INTO SELECT 子查询写入放大**：FS 第 4.3 节明确支持在 INSERT INTO SELECT 中使用上述运算符+子查询。具有写入权限的用户可构造复杂子查询，使单条 INSERT 语句写入超预期数据量，或通过反复执行造成存储资源耗尽。 | T（篡改）/ D（拒绝服务） | INSERT INTO SELECT → 子查询 → 目标表 | 低 |
| T-AAESQ-05 | **错误信息泄露内部结构**：子查询语法错误或执行异常时，错误响应中若包含内部实现细节（如内存地址、函数栈信息、内部数据结构名称），可为攻击者提供进一步探测系统的线索。FS 第 11 节列举了多类错误场景（语法错误、列数错误、类型不匹配等）。 | I（信息泄露） | 错误处理 / 客户端响应 | 低 |

### 5. 安全需求与设计约束

| 威胁ID | 转化后的安全需求/设计约束 | 类型 | 优先级 |
| --- | --- | --- | --- |
| T-AAESQ-01 | SEC-AAESQ-001（结果集大小约束）：ALL 运算符对应子查询的结果集行数应受现有查询内存上限约束，超出阈值时返回明确错误而非 OOM，建议复用 `tsQueryMemoryLimit` 等现有参数控制机制；ANY/SOME 短路求值和 EXISTS/NOT EXISTS 短路求值已在实现层面降低风险。 | 健壮性需求 | 高 |
| T-AAESQ-02 | SEC-AAESQ-002（权限统一校验）：子查询中访问的每张表，必须经过与外层查询相同的权限校验流程，在查询计划生成阶段即完成所有涉及表的权限验证，不允许子查询绕过外层权限上下文。 | 安全设计约束 | 中 |
| T-AAESQ-03 | SEC-AAESQ-003（嵌套深度限制）：SQL 解析器应对子查询嵌套深度设置上限（建议与现有嵌套查询限制及「IN + 非相关子查询」功能保持一致），超过限制时返回语法错误而非崩溃，防止解析器栈溢出。 | 健壮性需求 | 中 |
