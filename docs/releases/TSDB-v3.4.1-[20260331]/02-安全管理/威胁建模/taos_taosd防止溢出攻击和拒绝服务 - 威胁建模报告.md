### 3. 分析报告

本报告针对 taos/taosd 防止溢出攻击和拒绝服务功能进行了威胁建模分析。该功能旨在通过开发约定、编译保护、运行时检测等多层机制，防止 TDengine 服务端和客户端遭受缓冲区溢出攻击及拒绝服务攻击，保障集群稳定运行。

- **核心发现：** 共识别出 `8` 个潜在威胁，其中 `高危` `2` 个，`中危` `5` 个，`低危` `1` 个。
- **主要风险场景：**
  - **缓冲区溢出导致代码执行：** 攻击者通过构造超长输入或恶意数据包，利用不安全函数触发栈/堆溢出，进而控制程序执行流。
  - **网络层连接资源耗尽：** 攻击者通过大量 TCP 连接或慢速连接攻击，耗尽服务端连接资源，导致正常用户无法连接。
  - **整数溢出导致内存越界：** 整数运算溢出引发数组索引或内存分配越界，可被利用实现越界读写。
- **结论：** FS 通过四层防护体系（静态检查、开发约定、编译保护、运行时检测）对上述风险进行了系统性覆盖，设计方案合理可行。本报告识别的安全需求已在 FS 设计中得到落实，整体安全态势良好。

### 4. 威胁识别与分析（STRIDE）

本功能覆盖 TDengine 服务端（taosd）及客户端（taos）的内存安全防护与网络层 DoS 防护，涉及对外 API 边界检查、内存安全函数封装、编译级栈保护、运行时内存检测以及连接/流量控制机制。

#### 4.1 关键实体与数据

| 实体/数据 | 描述 | 敏感性 |
| --- | --- | --- |
| 对外 API 输入参数 | 包括 dbname、tablename、colName、SQL 语句、用户名/密码等外部输入字段 | 高（直接影响执行路径） |
| 协议数据包 | 客户端与 taosd 之间的 TCP 通信数据包 | 高（可构造恶意载荷） |
| 内存缓冲区 | 服务端处理请求时使用的栈和堆内存 | 高（溢出可导致代码执行） |
| TCP 连接池 | taosd 维护的活跃连接资源集合 | 中（耗尽导致 DoS） |
| 服务端请求队列 | taosd 内部处理请求的队列 | 中（积压导致服务降级） |
| 错误信息输出 | 处理异常时向客户端返回的错误描述 | 低（可能包含内部路径信息） |

#### 4.2 威胁评估

| 威胁ID | **威胁描述/攻击场景** | **STRIDE** | **相关组件/数据流** | **风险等级** |
| --- | --- | --- | --- | --- |
| T-OVDOS-01 | **栈/堆缓冲区溢出导致任意代码执行：** 攻击者构造超长字段值（如超长 SQL 语句、超长表名）发送至 taosd，若代码使用 `strcpy` 等不安全函数处理，触发缓冲区溢出，覆盖返回地址或控制数据，从而执行任意代码。 | E（权限提升）/ T（篡改） | 对外 API 输入参数 → 内存缓冲区 | 高 |
| T-OVDOS-02 | **TCP 连接洪流耗尽服务端连接资源：** 攻击者使用大量客户端同时向 taosd 发起 TCP 连接，超出服务端最大连接数，导致合法用户连接请求被拒绝，服务不可用。 | D（拒绝服务） | 网络层 → TCP 连接池 | 中 |
| T-OVDOS-03 | **慢速连接攻击消耗连接线程资源：** 攻击者建立 TCP 连接后故意以极低速率发送数据，占用 taosd 的连接处理线程，导致线程资源耗尽，合法请求无法得到处理。 | D（拒绝服务） | TCP 连接池 → 服务端请求处理线程 | 中 |
| T-OVDOS-04 | **协议畸形数据包导致服务崩溃：** 攻击者向 taosd 发送不符合协议规范的畸形数据包（如错误的包头魔数、负长度字段），若协议解析层缺乏防御，可能导致解析逻辑崩溃或内存越界访问。 | D（拒绝服务）/ T（篡改） | 协议数据包 → taosd 协议解析模块 | 中 |
| T-OVDOS-05 | **超长字段值导致内存耗尽：** 攻击者发送包含超大字段值（如数百 MB 的数据包、极长 SQL 语句）的请求，taosd 若未在接收阶段进行长度限制，将消耗大量堆内存，导致 OOM 或服务性能严重下降。 | D（拒绝服务） | 协议数据包 → 内存缓冲区 | 中 |
| T-OVDOS-06 | **整数溢出导致缓冲区越界访问：** 在计算缓冲区大小或数组索引时，若使用的数值来自外部输入且未作类型检查，可能发生整数溢出（如 `int` 溢出为负数），导致 `malloc` 分配过小缓冲区或数组访问越界，被利用实现越界读写。 | T（篡改）/ E（权限提升） | 对外 API 输入参数 → 数值运算 → 内存缓冲区 | 高 |
| T-OVDOS-07 | **不完整请求积压请求队列：** 攻击者发送大量格式合法但内容不完整的请求（如只发送请求头不发送 body），占用 taosd 请求队列资源，导致正常请求排队等待，服务吞吐量下降。 | D（拒绝服务） | 协议数据包 → 服务端请求队列 | 中 |
| T-OVDOS-08 | **错误信息中泄露内部系统路径或函数信息：** taosd 在处理异常时，若将详细错误信息（如内部函数调用路径、内存地址、文件路径）直接返回给客户端，攻击者可利用这些信息辅助构造更精准的攻击载荷。 | I（信息泄露） | 错误处理模块 → 客户端错误信息输出 | 低 |

### 5. 安全需求与设计约束

| 威胁ID | **转化后的安全需求/设计约束** | **类型** | **优先级** |
| --- | --- | --- | --- |
| T-OVDOS-01、T-OVDOS-06 | SEC-OVDOS-001（安全函数强制使用）：所有对外 API 路径上的字符串操作必须使用 `tstrncpy`/`snprintf` 等安全函数；数组和缓冲区操作前必须验证索引有效性；所有内存分配返回值必须检查。CI 编译阶段需检测不安全函数调用。 | 安全设计约束 | 高 |
| T-OVDOS-01、T-OVDOS-06 | SEC-OVDOS-002（编译级栈保护）：编译阶段必须默认启用 `-fstack-protector`，为所有函数提供栈溢出保护。 | 安全功能需求 | 高 |
| T-OVDOS-01、T-OVDOS-05、T-OVDOS-06 | SEC-OVDOS-003（业务边界强制验证）：所有对外 API 参数（包括 dbname、tablename、colName、SQL 长度、列数量、用户名/密码长度等）必须在接入层进行上限边界校验，超限请求立即返回错误，禁止传入内部处理逻辑。 | 安全设计约束 | 高 |
| T-OVDOS-01、T-OVDOS-06 | SEC-OVDOS-004（运行时内存检测）：CI 流水线必须集成 AddressSanitizer（ASAN）并在每次 PR 合入时运行，确保运行时内存越界、UAF 等问题可被自动发现。 | 非功能安全需求 | 高 |
| T-OVDOS-02、T-OVDOS-03、T-OVDOS-07 | SEC-OVDOS-005（最大连接数与请求队列限制）：服务端必须配置最大连接数上限，超出后新连接应被拒绝并返回明确错误；请求队列应设置容量上限，防止因不完整请求积压导致资源耗尽。 | 安全功能需求 | 中 |
| T-OVDOS-04、T-OVDOS-05 | SEC-OVDOS-006（协议解析防御性设计）：协议解析层必须对所有字段的长度、类型、范围进行严格验证，畸形包、超长字段值、不完整请求应在解析层被识别并丢弃，不进入业务处理逻辑。 | 安全设计约束 | 中 |
| T-OVDOS-08 | SEC-OVDOS-007（错误信息最小化披露）：对外返回的错误信息应仅包含用户可理解的业务错误描述，禁止包含内部函数名称、内存地址、文件路径等系统内部信息。 | 安全设计约束 | 低 |
