### 3. 分析报告

本报告针对审计信息不经过 taoskeeper 记录功能进行了威胁建模分析。该功能通过新增 `AuditSaveInSelf` 配置项，允许 TDengine 集群在 `AuditSaveInSelf=1` 时将审计事件经集群内部 RPC 直接写入本集群 vnode，绕过外部 taoskeeper 服务，从而消除 taoskeeper 成为审计路径单点的风险。

- **核心发现：** 共识别出 `6` 个潜在威胁，其中 `高危` `0` 个，`中危` `3` 个，`低危` `3` 个。
- **主要风险场景：**
   - **审计库横向访问：** 拥有集群普通查询权限的用户若未被明确限制访问 IS_AUDIT 标记的审计库，可查看所有用户的操作记录。
   - **特权账户销毁审计痕迹：** 高权限管理账户可通过删除 operations 表中的记录破坏审计完整性。
   - **单 vgroup 可用性瓶颈：** 审计库限定 vgroup=1，若该 vnode 不可用，期间产生的审计记录存在丢失风险。
- **结论：** 本特性整体上通过消除外部 taoskeeper 依赖、将审计路径收敛至集群内部 RPC，主动降低了审计数据的攻击面。识别的威胁均为中低风险，且其中多项为时序数据库部署场景下的通用运维风险，在现有集群权限体系约束下实际可利用性有限。

### 4. 威胁识别与分析（STRIDE）

本特性在 TDengine 集群中新增 `AuditSaveInSelf` 开关。启用后，taosd 将审计事件通过集群内部 RPC 通道直接写入本集群 vnode 中的 operations 超级表（IS_AUDIT 标记的专用审计库），原有 taoskeeper HTTP 路径被完全绕过。

#### 4.1 关键实体与数据

| 实体/数据 | 描述 | 敏感性 |
| --- | --- | --- |
| operations 超级表 | 存储全量审计记录，包含用户名、操作、IP、影响行数等字段 | 高（含全量用户操作历史） |
| IS_AUDIT 审计库 | 以 `IS_AUDIT 1` 标记的专用数据库，vgroup=1 | 高 |
| AuditSaveInSelf 配置项 | 控制审计写入路径的开关参数，默认值为 0 | 中 |
| 集群内部 RPC 通道 | taosd 向 vnode 写入审计记录的传输通道 | 中 |
| cluster_id 标签 | 标识审计记录所属集群的超级表标签 | 低 |

#### 4.2 威胁评估

| 威胁ID | **威胁描述/攻击场景** | **STRIDE** | **相关组件/数据流** | **风险等级** |
| --- | --- | --- | --- | --- |
| T-AUDSIF-01 | **审计库横向访问：** 拥有集群 SELECT 权限的普通用户若未被明确禁止访问审计库，可通过标准 SQL 查询 operations 超级表，获取其他用户（包括管理员）的全量操作记录（user_name、operation、client_address 等），造成敏感操作信息泄露。 | I（信息泄露） | operations 超级表 / IS_AUDIT 审计库 | 中 |
| T-AUDSIF-02 | **特权账户篡改审计记录：** 持有高权限（如 root 账户或具有审计库写权限的账户）的内部攻击者，可通过 DELETE 语句删除 operations 表中的特定审计记录，或在数据库文件层面直接操作，消除其敏感操作的留痕，导致审计日志不可信。 | T（篡改） | operations 超级表 / vnode 存储 | 中 |
| T-AUDSIF-03 | **单 vgroup 审计可用性瓶颈：** 审计库限定仅一个 vgroup（vgroup=1），若该 vnode 因磁盘故障、OOM 或其他原因不可用，写入审计记录的 RPC 调用将失败，期间产生的审计事件无法落盘，造成审计记录不连续，削弱不可否认性保证。 | R（抵赖） | IS_AUDIT 审计库 / vnode 可用性 | 中 |
| T-AUDSIF-04 | **审计数据库存储耗尽：** 大规模批量操作（如导入数千张子表、批量建库）会在短时间内产生大量审计事件，持续写入单 vgroup 审计库，可能耗尽该 vnode 所在节点的磁盘空间，进而影响集群整体的数据写入可用性。 | D（拒绝服务） | IS_AUDIT 审计库 / 节点磁盘 | 低 |
| T-AUDSIF-05 | **禁用审计规避监控：** 持有配置修改权限的管理员可在执行敏感操作前将 `AuditSaveInSelf` 设置为 0（或直接停止审计库写入），使该段时间内的操作不产生审计记录，完成操作后再恢复，实现对监控的规避。配置变更本身若不被审计则无法追溯。 | E（权限提升） | AuditSaveInSelf 配置项 | 低 |
| T-AUDSIF-06 | **内部 RPC 伪造审计消息：** 在集群内部网络中拥有访问权限的攻击者，可能向 vnode 构造伪造的 RPC 审计写入消息，注入虚假的操作记录（如将某项操作归因到其他用户），干扰审计数据的准确性。此威胁要求攻击者已具备集群内部 RPC 访问能力，前提条件较高。 | S（仿冒） | 集群内部 RPC 通道 / vnode | 低 |

### 5. 安全需求与设计约束

| 威胁ID | **转化后的安全需求/设计约束** | **类型** | **优先级** | **FS 落实状态** |

| T-AUDSIF-01 | SEC-AUDSIF-001（审计库访问控制）：IS_AUDIT 标记的审计库应在权限模型中受到特殊保护，仅授权角色（如安全审计员）方可查询，普通用户无法直接访问 operations 超级表。 | 安全设计约束 | 中 | ✅ 已落实（IS_AUDIT 标记限制了审计库的访问权限） |
