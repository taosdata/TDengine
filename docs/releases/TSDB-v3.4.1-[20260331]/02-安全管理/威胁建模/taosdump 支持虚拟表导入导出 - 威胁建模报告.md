### 3. 分析报告

本报告针对 taosdump 支持虚拟表导入/导出功能进行了威胁建模分析。该功能旨在解决 taosdump 工具不支持虚拟表（Virtual Table）备份恢复的问题，在现有超级表/子表导出/导入框架上新增虚拟超级表、虚拟子表、虚拟普通表三类对象的建表语句导出与导入处理逻辑，并实现跨数据库依赖的自动排序（实体表优先于虚拟表建模）。

- **核心发现：** 共识别出 `5` 个潜在威胁，其中 `高危` `0` 个，`中危` `2` 个，`低危` `3` 个。
- **主要风险场景：**
  - **建模文件篡改：** 攻击者篡改导出的 SQL/avro 文件中的虚拟表定义，导致导入时创建非预期的跨数据库虚拟表映射关系。
  - **跨数据库引用权限绕过：** 恶意构造的导入文件引用目标系统中当前用户本不应访问的源数据库列，借助导入操作建立未授权的虚拟表视图。
- **结论：** 该功能为现有 taosdump 功能的自然扩展，主要安全边界（服务端权限校验、SQL 语法校验）由 TDengine 内建机制覆盖，整体安全风险低。以下威胁供开发及运维团队参考，无需阻塞功能交付。

### 4. 威胁识别与分析（STRIDE）

本功能核心数据流：TDengine 服务端（虚拟表元数据）→ taosdump 导出 → 本地文件系统（dbs.sql / avro-tbtags / avro-ntb）→ taosdump 导入 → 目标 TDengine 服务端（执行建表 DDL）。

#### 4.1 关键实体与数据

| 实体/数据 | 描述 | 敏感性 |
| --- | --- | --- |
| dbs.sql 文件 | 包含 `CREATE STABLE ... VIRTUAL` 语句，存储虚拟超级表的字段定义。 | 低（仅含结构元数据） |
| avro-tbtags 文件 | 包含 `CREATE VTABLE ... USING` 语句，存储虚拟子表定义及跨数据库列引用路径。 | 中（含跨数据库拓扑信息） |
| avro-ntb 文件 | 包含虚拟普通表建表语句。 | 低（仅含结构元数据） |
| 跨数据库列引用路径 | `CREATE VTABLE` 语句中 `FROM <db>.<table>.<column>` 形式的明文引用，揭示源数据库的库名、表名、列名。 | 中（可推断系统数据库拓扑） |
| taosdump 连接凭证 | 用于连接源/目标 TDengine 服务的用户名和密码（命令行参数传入）。 | 高 |

#### 4.2 威胁评估

| 威胁ID | 威胁描述/攻击场景 | STRIDE | 相关组件/数据流 | 风险等级 |
| --- | --- | --- | --- | --- |
| T-VTDUMP-01 | **建模文件篡改**：攻击者在导出目录读写权限不受控时，篡改 dbs.sql 中的 `CREATE STABLE ... VIRTUAL` 语句（如修改字段类型或标签定义），或篡改 avro-tbtags 中的跨数据库列引用（如将 `FROM db_a.t1.col` 改为 `FROM db_b.t2.col`），导致导入时在目标系统中建立错误的虚拟表映射关系，后续基于该虚拟表的查询结果将产生偏差或错误关联。 | T（篡改） | dbs.sql / avro-tbtags 文件 → taosdump 导入 → TDengine DDL | 中 |
| T-VTDUMP-02 | **跨数据库引用泄露内部结构**：导出的 avro-tbtags 文件以明文形式包含 `CREATE VTABLE ... FROM <source_db>.<source_table>.<column>` 的完整跨数据库引用路径（如 FS 第 9 节示例中的 `machine_tool_vibration_us.dp_3_virbration_04.1x`）。若导出文件被未授权人员获取（如备份存储访问控制不当），可据此推断生产环境的数据库命名规范、业务分层结构和设备命名体系。 | I（信息泄露） | avro-tbtags 文件（本地落盘） | 低 |
| T-VTDUMP-03 | **跨数据库引用权限绕过**：攻击者构造恶意的导入文件，在 `CREATE VTABLE` 语句中引用目标系统中执行账号本无查询权限的源数据库列（如其他租户的敏感数据库），通过成功建立的虚拟表实现对未授权源列的间接查询访问。此威胁依赖 TDengine 服务端在建表时是否对被引用源列执行权限校验。 | E（权限提升） | 恶意 avro-tbtags → taosdump 导入 → TDengine 权限模型 | 中 |
| T-VTDUMP-04 | **大量虚拟表定义导入耗尽 DDL 资源**：恶意构造包含数万条 `CREATE VTABLE` 语句的 avro-tbtags 文件，taosdump 执行导入时向 TDengine 服务端批量提交 DDL 请求，短时间内消耗 mnode 的 DDL 处理队列和元数据存储资源，影响其他业务的正常 DDL 操作。 | D（拒绝服务） | avro-tbtags → taosdump 批量 DDL → TDengine mnode | 低 |
| T-VTDUMP-05 | **缺乏文件完整性校验导致抵赖**：taosdump 当前未对导出文件提供完整性签名机制（与现有超级表/子表导出行为一致），导入时无法验证文件是否被篡改或替换。若导入后虚拟表行为异常，无法通过文件校验手段区分是原始导出问题还是文件被中途篡改，影响故障溯源。 | R（抵赖） | 导出目录 → 文件传输 → taosdump 导入 | 低 |

### 5. 安全需求与设计约束

| 威胁ID | 安全需求/设计约束 | 类型 | 优先级 |
| --- | --- | --- | --- |
| T-VTDUMP-01 | SEC-VTDUMP-001（建模文件访问控制）：taosdump 导出目录应通过操作系统文件系统权限限制为仅 taosdump 运行账号可读写（建议权限 700），防止其他本地用户篡改导出文件。 | 运维规范约束 | 中 |
| T-VTDUMP-03 | SEC-VTDUMP-002（源列权限校验）：TDengine 服务端执行 `CREATE VTABLE` 时，应校验当前执行账号对被引用源数据库和列的查询权限，无权访问的引用应导致建表失败。（依赖 TDengine 服务端内建权限模型，需在集成测试中验证。） | 安全设计约束 | 中 |
| T-VTDUMP-05 | SEC-VTDUMP-003（可选完整性校验）：可在 taosdump 中提供可选的导出文件 HMAC/校验和功能，导入时可对文件完整性进行验证；此为增强功能，不强制要求。 | 增强安全需求 | 低 |
