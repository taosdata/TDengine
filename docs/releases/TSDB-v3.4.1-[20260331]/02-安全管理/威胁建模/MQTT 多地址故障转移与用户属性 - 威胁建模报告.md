### 3. 分析报告

本报告针对 MQTT 多地址故障转移与用户属性功能进行了威胁建模分析。该功能旨在为 taosx 的 MQTT 数据采集连接器增加多 Broker 地址故障转移能力、MQTT v5 用户属性（连接/订阅两组）透传，以及 UI 配置区块重组（连接与认证分离）。

- **核心发现：** 共识别出 `7` 个潜在威胁，其中 `高危` `0` 个，`中危` `4` 个，`低危` `3` 个。
- **主要风险场景：**
  - **仿冒 Broker 与中间人攻击：** 默认不启用 TLS 时，攻击者可伪造 Broker 或在传输层截获 MQTT 报文，获取认证凭据及订阅数据。
  - **凭据与私钥泄露：** DSN 字符串及双向 TLS 场景下的客户端私钥若存储或日志处理不当，可导致凭据外泄。
  - **用户属性内容篡改：** 攻击者若能修改 DSN 配置，可注入特殊格式的用户属性，影响 Broker 侧对报文的解析。
- **结论：** 该功能设计在提升 MQTT 数据采集高可用性方面价值显著，整体安全基础扎实。主要风险集中于传输层安全（TLS 非默认开启）和凭据管理，属于 IoT 接入场景的典型风险，已通过现有 TLS 配置选项提供缓解手段。建议在部署文档中强调公网/高安全场景下启用 TLS 的必要性。

### 4. 威胁识别与分析（STRIDE）

本功能的核心数据流：**用户/管理员** 通过 **taos Explorer（UI）** 配置 MQTT 数据源任务 → **taosx 后端** 解析 DSN 并建立与 **MQTT Broker** 的连接 → **taosx** 订阅 Topic 并将数据写入 **TDengine**。多地址场景下，taosx 按顺序尝试 Broker 地址列表进行连接。

#### 4.1 关键实体与数据

| 实体/数据 | 描述 | 敏感性 |
| --- | --- | --- |
| MQTT Broker 地址列表 | DSN 中逗号分隔的多个 Broker host:port | 中（含网络拓扑信息） |
| MQTT 认证凭据（用户名/密码） | auth_options 中的 username/password，存储于 DSN | 高 |
| TLS 证书与私钥 | CA 证书、客户端证书、客户端私钥，双向 TLS 场景下上传至 taosx | 高 |
| 用户属性键值对 | connect_user_properties / subscribe_user_properties，为业务元数据 | 低（业务相关，不含系统凭据） |
| DSN 字符串 | 包含上述所有配置参数的序列化字符串 | 高（含凭据） |
| MQTT 订阅数据流 | taosx 从 Broker 订阅并写入 TDengine 的时序数据 | 高（含业务数据） |

#### 4.2 威胁评估

| 威胁ID | 威胁描述/攻击场景 | STRIDE | 相关组件/数据流 | 风险等级 |
| --- | --- | --- | --- | --- |
| T-MQTTFOV-01 | **仿冒 Broker**：默认不启用 TLS 时，攻击者可通过 DNS 劫持或 ARP 欺骗将 taosx 的连接重定向至恶意 Broker，诱使 taosx 发送认证凭据，并接收伪造的 MQTT 数据写入 TDengine。多地址场景下，攻击者控制列表中任意一个 Broker 即可实施。 | S（仿冒） | 多地址 DSN → taosx → MQTT Broker | 中 |
| T-MQTTFOV-02 | **凭据泄露（DSN 明文）**：DSN 字符串中包含 MQTT 用户名和密码。若 DSN 在错误日志、调试输出、任务导出或 API 响应中以明文形式暴露，攻击者可提取 Broker 认证凭据，进而直接连接 Broker 并订阅或发布消息。 | I（信息泄露） | DSN → taosx 配置存储 / 日志输出 | 中 |
| T-MQTTFOV-03 | **用户属性 DSN 注入**：攻击者构造包含特殊字符（如 `=`、`,`、`&`）的用户属性键值对，通过 UI 或直接提交 DSN，试图破坏 parse_kv_pairs 解析逻辑，使一个参数的值被解析为另一个参数的 key 或 value，干扰 MQTT 报文构造。 | T（篡改） | connect/subscribe_user_properties → rumqttc MQTT 报文 | 低 |
| T-MQTTFOV-04 | **故障转移滥用耗尽资源**：具有任务配置权限的恶意内部用户配置大量无效或超时的 Broker 地址（如不可达的公网 IP），使 taosx 在连接阶段串行等待每个地址的超时，延迟数据采集恢复，并消耗连接线程资源。 | D（拒绝服务） | Broker 地址列表 → taosx 连接管理 | 低 |
| T-MQTTFOV-05 | **连接失败信息泄露**：所有 Broker 地址连接失败时，FS 规定返回"最后一个地址的连接错误"，该错误信息可能包含内网 IP 地址、端口、Broker 版本信息等，经由 taos Explorer UI 或 API 响应暴露给未授权用户。 | I（信息泄露） | taosx 错误处理 → taos Explorer / API | 低 |
| T-MQTTFOV-06 | **明文传输中间人攻击**：默认不启用 TLS 时，taosx 与 MQTT Broker 之间的所有通信（包括 CONNECT 报文中的用户名/密码、SUBSCRIBE 报文中的用户属性、订阅的时序数据）均以明文传输，攻击者可通过网络嗅探截获完整数据流。 | T/I（篡改/信息泄露） | taosx ↔ MQTT Broker 通信链路 | 中 |
| T-MQTTFOV-07 | **客户端私钥泄露**：双向 TLS 场景下，用户上传的客户端私钥（cert_key）存储于 taosx 服务端。若 taosx 配置目录的文件系统权限配置不当，同主机上的其他进程或低权限用户可能读取私钥文件，进而伪造客户端身份连接 Broker。 | I（信息泄露） | cert_key 文件 → taosx 文件存储 | 中 |

### 5. 安全需求与设计约束

| 威胁ID | 转化后的安全需求/设计约束 | 类型 | 优先级 |
| --- | --- | --- | --- |
| T-MQTTFOV-01 | SEC-MQTTFOV-001（Broker 身份验证）：在公网或非受信网络部署场景下，应配置单向或双向 TLS 以验证 Broker 服务器证书，防止仿冒 Broker。部署文档应明确说明此建议。 | 安全配置建议 | 中 |
| T-MQTTFOV-02 | SEC-MQTTFOV-002（凭据保护）：taosx 在日志输出时应对 DSN 中的 password 字段进行脱敏处理，避免凭据明文出现在日志文件中。 | 安全设计约束 | 中 |
| T-MQTTFOV-03 | SEC-MQTTFOV-003（用户属性输入校验）：parse_kv_pairs 函数应对键值对中不允许出现的分隔符字符（逗号、等号）进行校验或转义，确保解析结果与用户意图一致。 | 安全功能需求 | 低 |
| T-MQTTFOV-06 | SEC-MQTTFOV-004（传输加密建议）：产品文档和 UI 应在 TLS 配置区块提供提示，建议非内网部署场景启用 TLS，并说明不启用 TLS 的安全风险。 | 安全配置建议 | 中 |
| T-MQTTFOV-07 | SEC-MQTTFOV-005（私钥文件权限）：taosx 存储上传证书和私钥的目录应配置严格的文件系统权限（仅 taosx 进程用户可读），防止私钥被同主机其他用户读取。 | 安全设计约束 | 中 |
