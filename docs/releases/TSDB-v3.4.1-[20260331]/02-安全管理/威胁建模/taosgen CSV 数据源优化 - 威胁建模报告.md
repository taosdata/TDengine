### 3. 分析报告

本报告针对 taosgen CSV 数据源优化功能进行了威胁建模分析。该功能旨在通过替换高性能 CSV 解析库（vincentlaucsb-csv-parser，使用 mmap I/O）、支持多文件批量加载（目录/glob 模式）以及新增 streaming 流式加载模式，解决 taosgen 原有 CSV 读取在大文件性能、多文件处理和内存占用方面的局限。

- **核心发现：** 共识别出 `6` 个潜在威胁，其中 `高危` `0` 个，`中危` `1` 个，`低危` `5` 个。
- **主要风险场景：**
  - **恶意 CSV 触发解析器漏洞：** 攻击者提供精心构造的 CSV 文件，触发第三方解析库潜在的内存安全漏洞。
  - **路径遍历攻击：** 通过恶意配置文件路径访问系统预期访问范围之外的文件。
  - **符号链接重定向：** 利用符号链接将 CSV 路径指向敏感系统文件。
- **结论：** 该功能为本地 CLI 工具的内部实现优化，攻击面有限，依赖 OS 文件系统权限作为核心安全边界。FS 已对路径遍历、内存耗尽等关键风险设计了对应的缓解措施。整体安全风险较低，设计方案通过评审。

### 4. 威胁识别与分析（STRIDE）

taosgen 是一款本地 CLI 数据生成/基准测试工具，通过读取用户配置指定的本地 CSV 文件，生成时序数据并写入 TDengine。本次优化涉及的主要数据流：用户配置（YAML 文件）→ 路径解析 → 文件系统（CSV 文件/目录/glob）→ CSV 解析器（vincentlaucsb-csv-parser）→ 内存数据行 → TDengine 写入接口。

#### 4.1 关键实体与数据

| 实体/数据 | 描述 | 敏感性 |
| --- | --- | --- |
| YAML 配置文件 | 包含 `file_path`（文件/目录/glob 路径）、`loading_mode` 等参数。 | 低（本地配置文件） |
| CSV 数据文件 | 用户提供的测试/基准时序数据，通常不含敏感业务数据。 | 低（测试数据） |
| glob/目录路径 | 由配置文件指定，用于批量匹配 CSV 文件。 | 低 |
| 解析后内存数据 | CSV 解析为内存中的行列结构，用于写入 TDengine。 | 低 |
| vincentlaucsb-csv-parser 库 | 负责 CSV 解析的第三方 header-only 库（v2.3.0）。 | 中（供应链安全） |

#### 4.2 威胁评估

| 威胁ID | 威胁描述/攻击场景 | STRIDE | 相关组件/数据流 | 风险等级 |
| --- | --- | --- | --- | --- |
| T-CSVOPT-01 | **路径遍历攻击**：攻击者通过修改 YAML 配置文件，构造包含 `../` 序列的恶意 `file_path`，使 taosgen 访问超出预期目录范围的系统文件（如 `/etc/passwd`），导致敏感信息泄露或意外解析非 CSV 文件。 | I（信息泄露）/ T（篡改） | YAML 配置 → 路径解析 → 文件系统 | 低 |
| T-CSVOPT-02 | **符号链接重定向**：攻击者在 CSV 目录下创建指向 `/etc/shadow`、`/proc/self/environ` 等敏感系统文件的符号链接，taosgen 在扫描目录或 glob 匹配时将其纳入读取列表，导致敏感文件内容被当作 CSV 解析并可能被写入 TDengine。 | I（信息泄露） | 目录/glob 扫描 → 文件系统 → CSV 解析器 | 低 |
| T-CSVOPT-03 | **恶意 CSV 触发解析器漏洞**：攻击者提供包含超长字段、嵌套引号、畸形转义序列或极端嵌套结构的 CSV 文件，触发 vincentlaucsb-csv-parser 2.3.0 中潜在的缓冲区溢出、整数溢出或内存越界漏洞，导致 taosgen 进程崩溃或执行任意代码。 | D（拒绝服务） | CSV 文件 → vincentlaucsb-csv-parser | 中 |
| T-CSVOPT-04 | **Preload 模式内存耗尽**：用户错误地在 preload 模式下加载远超可用物理内存的 CSV 文件（如 100GB+ 文件配合 8GB 内存的机器），导致系统 OOM，taosgen 进程被强制终止，影响数据导入任务的稳定性。 | D（拒绝服务） | 大 CSV 文件 → Preload 内存加载 | 低 |
| T-CSVOPT-05 | **CSV 数据污染**：在共享服务器或 CI/CD 环境中，内部人员（或恶意脚本）替换 taosgen 配置指向的 CSV 文件，将篡改后的基准数据写入 TDengine，导致测试结果失真或数据库数据受污染。 | T（篡改） | 文件系统（CSV 文件）→ TDengine | 低 |
| T-CSVOPT-06 | **Glob 通配符意外扩展**：用户误配置了过于宽泛的 glob 模式（如 `/**/*.csv`），或在高并发场景下持续扩展的目录导致 taosgen 解析海量文件，消耗大量 CPU/内存/文件句柄资源，影响同一主机上的其他进程。 | D（拒绝服务） | YAML 配置 → glob 扩展 → 文件系统 | 低 |

### 5. 安全需求与设计约束

| 威胁ID | 转化后的安全需求/设计约束 | 类型 | 优先级 |
| --- | --- | --- | --- |
| T-CSVOPT-01 | **SEC-CSVOPT-001（路径规范化）**：文件路径解析必须使用 `std::filesystem::canonical` 或等效方法进行规范化，确保路径不超出用户指定的根目录范围。 | 安全设计约束 | 高 |
| T-CSVOPT-02 | **SEC-CSVOPT-002（符号链接处理）**：目录/glob 扫描时应由操作系统文件权限控制符号链接访问，taosgen 运行账号不应具有访问系统敏感文件的权限。 | 运维安全约束 | 低 |
| T-CSVOPT-03 | **SEC-CSVOPT-003（依赖版本管控）**：vincentlaucsb-csv-parser 版本应锁定，并纳入项目 SCA 扫描流程，及时感知已知 CVE 并在出现高危漏洞时及时升级。 | 供应链安全需求 | 中 |
| T-CSVOPT-04 | **SEC-CSVOPT-004（使用指引）**：文档应明确提示大文件场景下推荐使用 streaming 模式，并说明 preload 的内存风险，帮助用户做出合理的配置选择。 | 健壮性需求 | 低 |
| T-CSVOPT-05 | **SEC-CSVOPT-005（文件完整性）**：CSV 文件所在目录应配置适当的文件系统权限，确保只有授权用户可写入，防止数据被替换篡改。 | 运维安全约束 | 低 |
| T-CSVOPT-06 | **SEC-CSVOPT-006（glob 范围限制）**：glob 匹配不递归进入子目录，防止通配符意外扩展到大量目录的 CSV 文件。 | 安全设计约束 | 低 |
