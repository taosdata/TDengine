### 3. 分析报告

本报告针对 IDMP MCP Server 功能进行了威胁建模分析。该功能旨在提供一个基于 MCP 协议的 stdio 适配层，使 MCP 客户端能够直接调用 IDMP 的 AI 对话和系统配置能力，免去手工对接 HTTP API 的工作量。

- 核心发现：共识别出 `5` 个潜在威胁，其中 `高危` `1` 个，`中危` `2` 个，`低危` `2` 个。
- 主要风险场景：
   - 凭据泄露：通过命令行参数传递密码时，可能在进程列表和 shell 历史中暴露。
   - 中间人攻击：若使用 HTTP 而非 HTTPS 的 `base_url`，通信链路可被窃听或篡改。
   - 重登录滥用：自动重登录机制若被恶意触发，可能加速账号锁定。
- 结论：该功能设计架构简洁，攻击面有限。作为无状态的 stdio 协议适配层，自身不引入重大安全风险，主要安全职责合理委托给 IDMP 服务端。FS 已针对关键风险给出安全建议（使用 HTTPS、环境变量传递密码），整体安全设计合理。

### 4. 威胁识别与分析（STRIDE）

IDMP MCP Server 是一个通过 stdio 与 MCP 客户端通信的 Go 语言 CLI 工具，启动时使用用户名/密码登录 IDMP 服务端获取 Token，随后代理 `chat` 和 `system_config` 两个 MCP 工具调用到 IDMP HTTP API。

#### 4.1 关键实体与数据

| 实体/数据 | 描述 | 敏感性 |
| --- | --- | --- |
| 登录凭据（用户名/密码） | 通过命令行参数 `--user`/`--pass` 或环境变量 `IDMP_USER`/`IDMP_PASS` 传入 | 高 |
| 认证 Token | 登录后获取，保存在进程内存中，用于后续 API 调用 | 高 |
| IDMP 服务地址 | `base_url` 参数，决定与后端的通信链路 | 中 |
| 用户 prompt 内容 | `chat` 工具的输入，可能包含业务敏感查询 | 中 |
| API 响应数据 | IDMP 返回的 AI 回答和系统配置信息 | 中 |

#### 4.2 威胁评估

| 威胁ID | **威胁描述/攻击场景** | **STRIDE** | **相关组件/数据流** | **风险等级** |
| --- | --- | --- | --- | --- |
| T-IDMPMCP-01 | 命令行凭据泄露：用户通过 `--pass` 参数传递密码时，密码明文出现在进程列表（`/proc/*/cmdline`、`ps aux`）和 shell 命令历史中，同机其他用户或恶意软件可直接读取。 | I (信息泄露) | 登录凭据、操作系统进程环境 | 高 |
| T-IDMPMCP-02 | HTTP 链路中间人攻击：若 `base_url` 配置为 HTTP 而非 HTTPS，攻击者可在网络层窃听登录凭据、Token 和业务数据，或篡改 API 响应内容。 | T (篡改) I (信息泄露) | 登录凭据、Token、IDMP HTTP API 通信链路 | 中 |
| T-IDMPMCP-03 | 重登录触发账号锁定：恶意 MCP 客户端故意发送大量无效请求触发 4xx 错误，导致 MCP Server 反复自动重登录，若 IDMP 服务端有登录失败锁定策略，可能导致合法账号被锁定。 | D (拒绝服务) | 自动重登录机制、IDMP 登录接口 | 中 |
| T-IDMPMCP-04 | 错误信息泄露内部细节：HTTP 请求失败时的错误提示（如 `request for <url> failed with status code`）可能包含 IDMP 内部 URL 路径，帮助攻击者了解后端架构。 | I (信息泄露) | 错误处理逻辑 | 低 |
| T-IDMPMCP-05 | stdio 通信被本地进程窃听：在共享主机环境下，其他具有相同用户权限的进程理论上可以通过 ptrace 或 `/proc` 文件系统读取 stdio 管道中的数据，获取 prompt 内容和 AI 回答。 | I (信息泄露) | stdio 管道、prompt 内容、API 响应 | 低 |

### 5. 安全需求与设计约束

| 威胁ID | **转化后的安全需求/设计约束** | **类型** | **优先级** |
| --- | --- | --- | --- |
| T-IDMPMCP-01 | SEC-IDMPMCP-001（凭据安全传递）：FS 已建议优先使用环境变量注入密码，避免在命令历史中明文传递 `--pass`。文档中应进一步强调此最佳实践。 | 安全设计约束 | 高 |
| T-IDMPMCP-02 | SEC-IDMPMCP-002（强制 HTTPS 建议）：FS 已建议生产使用 HTTPS `base_url`。部署文档应明确将 HTTPS 作为生产环境的强烈建议。 | 非功能安全需求 | 中 |
| T-IDMPMCP-03 | SEC-IDMPMCP-003（重登录限制）：当前设计已限制仅重试一次，有效防止无限重登录循环。该设计约束应在实现中严格遵守。 | 安全设计约束 | 中 |
| T-IDMPMCP-04 | SEC-IDMPMCP-004（错误信息最小化）：错误提示中应避免暴露完整的内部 URL 路径，仅提供必要的排查信息。 | 安全设计约束 | 低 |
