### 3. 分析报告

本报告针对 taosgen 日志路径参数配置功能进行威胁建模分析。该功能旨在通过新增命令行参数 `--log-dir` / `--log-file` 及 YAML 配置项 `log_dir` / `log_file`，允许用户自定义日志输出路径，解决容器化、多实例部署等场景下日志路径固定的问题。

- **核心发现**：共识别出 **5** 个潜在威胁，其中 **高危** **0** 个，**中危** **3** 个，**低危** **2** 个。
- **主要风险场景**：
  - **符号链接攻击**：攻击者在日志目标路径预置符号链接，指向敏感文件，借助特权运行的 taosgen 实现间接写入。
  - **磁盘耗尽**：将日志路径指向剩余空间有限的关键磁盘分区，拖慢或中断宿主系统服务。
  - **特权运行目录写入**：以提升权限（sudo）运行时，`--log-dir` 可指向 `/etc/cron.d` 等敏感目录，产生计划外文件。
- **结论**：本功能为参数扩展性改进，引入的新攻击面有限。spdlog 的日志轮转策略（5 MB × 3 文件）已有效控制磁盘占用风险；操作系统文件权限模型已覆盖主要路径控制威胁；FS 文档亦建议避免以 root/sudo 运行。整体风险可控，设计通过安全评审，无强制修改项。

### 4. 威胁识别与分析（STRIDE）

taosgen 在程序启动时按优先级解析日志路径：`--log-file`（CLI）> `--log-dir`（CLI）> `log_file`（YAML）> `log_dir`（YAML）> 默认值 `./log/taosgen.log`。确定目标路径后，程序自动创建父目录（若不存在），随后通过 spdlog 初始化异步日志文件，路径合法性通过实际 open() 调用验证，失败则输出错误消息并退出。

#### 4.1 关键实体与数据

| 实体/数据 | 描述 | 敏感性 |
| --- | --- | --- |
| 命令行参数 / YAML 配置 | 用户提供的日志目录或文件路径字符串 | 中（外部输入，路径可指向任意位置） |
| 日志文件 | taosgen 写入的运行日志（操作事件、错误信息） | 低（运营数据，无凭证或 PII） |
| 日志目录 | 日志文件所在的文件系统目录 | 中（写入权限由 OS 控制） |
| spdlog 轮转配置 | 硬编码的轮转策略（5 MB / 3 文件） | 低 |
| 错误消息 | 路径校验失败时输出到 stderr 的完整路径信息 | 低（含路径字符串） |

#### 4.2 威胁评估

| 威胁 ID | 威胁描述 / 攻击场景 | STRIDE | 相关组件 / 数据流 | 风险等级 |
| --- | --- | --- | --- | --- |
| T-LOGPATH-01 | **符号链接攻击**：攻击者在 `--log-dir` 指定的目录下预先创建名为 `taosgen.log` 的符号链接，指向目标覆写的系统文件（如 `/etc/hosts`）。若 taosgen 以足够权限运行且未检测符号链接，日志写入将覆盖目标文件内容。 | T（篡改） | 日志路径解析 -> 文件创建 -> spdlog 写入 | 中 |
| T-LOGPATH-02 | **特权运行写入敏感目录**：用户以 root/sudo 运行 taosgen 并将 `--log-dir` 设为 `/etc/cron.d`、`/etc/logrotate.d` 等系统目录，程序将在该目录自动创建 `taosgen.log` 文件，可能干扰系统定时任务或日志轮转配置（文件存在本身即为干扰）。 | E（权限提升） | 目录自动创建逻辑 -> 系统敏感目录 | 中 |
| T-LOGPATH-03 | **磁盘耗尽拒绝服务**：攻击者或误操作将日志路径指向剩余空间极小的关键磁盘分区（如 `/` 或 `/var`）。尽管 spdlog 轮转限制单次最大占用约 15 MB，但在多实例并发或日志写入频繁时，仍可能在短时间内压满分区，导致宿主机其他服务写入失败。 | D（拒绝服务） | spdlog 写入 -> 目标分区磁盘空间 | 中 |
| T-LOGPATH-04 | **错误消息路径信息泄露**：路径校验失败时，错误消息（输出到 stderr）包含完整文件系统路径（FS 第 16.1 节示例）。在多用户或远程脚本化调用场景下，泄露的路径信息可辅助攻击者了解系统目录结构。 | I（信息泄露） | 错误处理 -> stderr 输出 | 低 |
| T-LOGPATH-05 | **日志注入（路径含控制字符）**：若用户传入包含换行符（`\n`）或其他控制字符的路径字符串，且程序在初始化阶段将原始路径写入日志，可能造成日志格式污染，干扰日志分析工具的解析。 | T（篡改） | 参数解析 -> 初始化日志输出 | 低 |

### 5. 安全需求与设计约束

| 威胁 ID | 转化后的安全需求 / 设计约束 | 类型 | 优先级 |
| --- | --- | --- | --- |
| T-LOGPATH-01 | **SEC-LOGPATH-001（符号链接感知）**：在打开日志文件前，建议通过 `lstat()` 检测目标路径是否为符号链接；若是，则依据 OS 权限判断是否允许跟随，并在日志中记录一条警告。对于非 root 运行场景，OS 权限已提供足够保护。 | 安全设计建议 | 低 |
| T-LOGPATH-02 | **SEC-LOGPATH-002（最小权限运行）**：FS 第 22 节场景三已建议预先创建日志目录并授权给专属用户（`chown taosgen:taosgen`），不推荐以 root/sudo 运行 taosgen。文档层面已完成告知。 | 安全设计约束（已满足） | 中 |
| T-LOGPATH-03 | **SEC-LOGPATH-003（日志轮转策略）**：spdlog 硬编码轮转策略（5 MB × 3 文件，最大约 15 MB）已有效限制单实例磁盘占用，在多实例场景下建议将各实例日志路径分散至独立磁盘或配额受限分区。 | 运维建议 | 低 |
| T-LOGPATH-04 | **SEC-LOGPATH-004（错误信息脱敏）**：对于 stderr 输出的错误消息，当前包含完整路径属于可接受行为（CLI 工具运维场景）；无需在设计层面修改，保持现状。 | 不适用（可接受） | 低 |
| T-LOGPATH-05 | **SEC-LOGPATH-005（路径字符合法性）**：建议在参数解析阶段对路径字符串进行基础清洗，过滤换行符（`\n`、`\r`）和 null 字节，防止日志格式污染。 | 安全设计建议 | 低 |
