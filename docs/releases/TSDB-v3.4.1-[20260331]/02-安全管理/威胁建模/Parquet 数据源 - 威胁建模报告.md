### 3. 分析报告

本报告针对 Parquet 数据源功能进行了威胁建模分析。该功能旨在为 taosX 新增对 Apache Parquet 格式文件的读取支持，使用户可将存储于本地文件系统的 Parquet 文件数据高效导入 TDengine。

- **核心发现：** 共识别出 `6` 个潜在威胁，其中 `高危` `0` 个，`中危` `2` 个，`低危` `4` 个。
- **主要风险场景：**
   - **路径遍历读取：** 攻击者若能控制任务 DSN 配置，可尝试通过路径遍历访问系统敏感文件。
   - **恶意文件解析漏洞：** 精心构造的 Parquet 文件可能触发底层解析库的异常行为。
- **结论：** 该功能设计在丰富 taosX 数据接入能力方面价值显著，且作为本地文件读取插件，攻击面相当有限。FS 已明确路径验证（§6.1.1）和资源限制（§6.2）两项核心安全要求，Rust 语言内存安全特性为解析层提供了额外保障。当前设计已可满足安全上线要求。

### 4. 威胁识别与分析（STRIDE）

本功能以 DSN 方式配置本地 Parquet 文件路径，由 taosX 进程同步读取文件内容，经 Apache Arrow Record Batch 格式转换后写入 TDengine。整个数据流均在 taosX 进程内部完成，无独立网络服务接口。

#### 4.1 关键实体与数据

| 实体/数据 | 描述 | 敏感性 |
| --- | --- | --- |
| Parquet 文件 | 存储在本地文件系统的列式数据文件，包含用户时序业务数据 | 中（含时序业务数据） |
| DSN 配置字符串 | 包含文件路径、batch_size、projection、unprocessed_batches 等参数 | 低 |
| Arrow Record Batch | 内存中的中间数据格式，用于数据转换和流转 | 中（含导入数据，非持久化） |
| taosX 进程 | 宿主进程，以 OS 用户权限执行文件读取和数据写入 | 高（持有 OS 文件访问权限） |
| TDengine 目标 DSN | 包含 TDengine 连接地址（可能含凭证），用于日志记录和任务路由 | 中 |

#### 4.2 威胁评估

| 威胁ID | **威胁描述/攻击场景** | **STRIDE** | **相关组件/数据流** | **风险等级** |
| --- | --- | --- | --- | --- |
| T-PARQUET-01 | **路径遍历任意文件读取：** 攻击者若能修改 taosX 任务配置（如获取任务管理界面权限），可在 DSN 中构造路径遍历序列（如 `parquet:/../../../etc/shadow`），尝试读取系统敏感文件内容并通过导入管道写入数据库。 | I（信息泄露） | DSN 配置 → 文件读取 | 中 |
| T-PARQUET-02 | **恶意 Parquet 文件解析漏洞：** 攻击者提供一个精心构造的畸形 Parquet 文件（如异常大的行组、非法的 schema 嵌套、超长字符串），触发 `parquet` crate 的解析异常，可能导致进程崩溃（DoS）或异常内存访问。 | T（篡改）/ D（拒绝服务） | Parquet 文件 → ParquetRecordBatchReader | 中 |
| T-PARQUET-03 | **资源耗尽导致服务降级：** 操作人员配置了极大的 `batch_size`（如 1,000,000）和 `unprocessed_batches`（如 1000），在处理超大 Parquet 文件时耗尽系统可用内存，影响 taosX 其他任务或宿主系统稳定性。 | D（拒绝服务） | DSN 参数 → taosX 进程内存 | 低 |
| T-PARQUET-04 | **TDengine 连接凭证日志泄露：** 任务启动时日志记录完整 DSN（如 `to: taos://admin:password@host:6030/db`），若日志文件权限设置不当，可被低权限用户读取获取数据库凭证。 | I（信息泄露） | 日志输出 → 日志文件 | 低 |
| T-PARQUET-05 | **文件并发修改导致脏数据写入：** 在 taosX 读取 Parquet 文件期间，外部进程同时向该文件写入数据或修改文件，由于 Parquet 文件不提供行级锁，可能导致读取到不完整或损坏的数据批次被写入 TDengine。 | T（篡改） | Parquet 文件 → Arrow Record Batch → TDengine | 低 |
| T-PARQUET-06 | **列投影参数信息推断：** 攻击者通过反复尝试不同 `projection` 参数值并观察任务是否报错，推断出 Parquet 文件的列结构信息，为后续精准攻击提供情报。 | I（信息泄露） | DSN projection 参数 → 错误响应 | 低 |

### 5. 安全需求与设计约束

| 威胁ID | **转化后的安全需求/设计约束** | **类型** | **优先级** |
| --- | --- | --- | --- |
| T-PARQUET-01 | **SEC-PARQUET-001（路径遍历防护）：** 在解析 DSN 文件路径时，必须规范化路径并检测 `../`、`..\\` 等遍历序列；可选择限制允许访问的根目录范围（白名单目录）。（FS §6.1.1 已明确该要求） | 安全设计约束 | 高 |
| T-PARQUET-02 | **SEC-PARQUET-002（解析器安全更新）：** 持续跟踪 `parquet` crate 及 `arrow` crate 的安全公告，及时应用涉及解析漏洞的版本更新；利用 Rust 内存安全特性和已有的 `cargo audit` 等工具进行依赖漏洞扫描。 | 非功能安全需求 | 中 |
| T-PARQUET-03 | **SEC-PARQUET-003（参数范围文档化）：** 在文档中明确 `batch_size` 和 `unprocessed_batches` 的推荐上限值，并在实现层对超出合理范围的值给出警告或拒绝。（FS §6.2 已通过默认值提供基础控制） | 健壮性需求 | 低 |
| T-PARQUET-04 | **SEC-PARQUET-004（DSN 凭证脱敏日志）：** 日志输出 DSN 时，对凭证部分（用户名和密码）进行脱敏处理（如替换为 `***`）。此为 taosX 平台层面建议，本功能跟随平台实现。 | 审计需求 | 低 |
| T-PARQUET-05 | **SEC-PARQUET-005（文件独占读取建议）：** 建议在任务文档中说明，Parquet 文件在导入期间应避免被外部进程同时写入，以保证数据一致性。Parquet 内置校验和（§6.3.1）可检测部分损坏情形。 | 健壮性需求 | 低 |
