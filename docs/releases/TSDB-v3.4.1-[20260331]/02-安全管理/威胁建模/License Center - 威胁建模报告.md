### 3. 分析报告

本报告针对 License Center 功能进行了威胁建模分析。该功能旨在构建独立的中心化授权管理系统，包含中心侧授权服务（CLS）和客户侧授权服务（CULS），实现 TDengine / IDMP 授权的统一发放、更新、撤销和监控，支持在线和离线两种工作模式。

- **核心发现：** 共识别出 `10` 个潜在威胁，其中 `高危` `3` 个，`中危` `5` 个，`低危` `2` 个。
- **主要风险场景：**
  - **CLS 管理端越权：** CLS `taos-cls-admin` CLI 及 Web UI 缺乏明确的操作员身份认证设计，攻击者可直接发放或撤销授权。
  - **License 重放攻击：** LicensePush 消息体仅含 timestamp，缺乏 nonce 机制，已撤销的授权包存在被重放的风险。
  - **密钥泄露无吊销机制：** CLS 签名私钥一旦泄露，攻击者可伪造合法 License 包，且 FS 中缺乏密钥轮换和吊销的设计。
- **结论：** License Center 授权链路（CLS ↔ CULS ↔ Instance）的安全设计基础扎实，采用 TLS 1.3、Ed25519、三级黑名单和双侧审计日志，整体安全架构合理。上述缺陷属局部设计空白，需在进入编码实现前补充完善。

### 4. 威胁识别与分析（STRIDE）

License Center 构建了 CLS（中心侧）→ CULS（客户侧代理）→ Instance（TSDB/IDMP 实例）的三层授权分发架构，信任边界在 CLS/CULS 注册握手和 CULS/Instance 连接认证处。

#### 4.1 关键实体与数据

| 实体/数据 | 描述 | 敏感性 |
| --- | --- | --- |
| CLS 签名私钥 | 用于签发 License 包的 Ed25519 私钥，运行在服务商侧 CLS | 极高 |
| CULS 注册密钥对 | CULS 初始化时生成的 Ed25519 密钥对，公钥注册至 CLS | 高 |
| License 包（LicensePush） | 含授权维度、有效期、CLS 签名的授权数据，通过 QUIC 推送 | 高 |
| 离线授权码（Offline Token） | 存储于文件系统的离线授权凭证，有效期最长 2 年 | 高 |
| CLS PostgreSQL 数据库 | 存储客户信息、授权记录、黑名单、审计日志 | 高 |
| CULS 本地嵌入式数据库 | RocksDB/REDB，存储当前 License、实例列表、本地审计日志 | 中 |
| `taos-cls-admin` CLI/Web UI | CLS 管理界面，可执行授权发放、撤销、黑名单操作 | 极高 |
| 黑名单数据 | 三级黑名单（CULS/License/Instance），防止非法实例获取授权 | 中 |

#### 4.2 威胁评估

| 威胁ID | **威胁描述/攻击场景** | **STRIDE** | **相关组件/数据流** | **风险等级** |
| --- | --- | --- | --- | --- |
| T-LC-01 | **CLS 签名私钥泄露伪造 License：** 攻击者获取 CLS 签名私钥后，可自行构造并签发任意合法 License 包，绕过所有授权控制，向任意 CULS 分发未授权的授权内容。 | S（仿冒）/ T（篡改） | CLS 私钥 → LicensePush 签名 | 高 |
| T-LC-02 | **CLS 管理端越权操作：** 攻击者（内部人员或外部入侵者）访问 CLS 所在主机，直接执行 `taos-cls-admin issue/revoke` 命令，发放未经授权的 License 或撤销合法客户的授权。FS 未说明管理端认证机制。 | E（权限提升） | taos-cls-admin CLI / Web UI → CLS | 高 |
| T-LC-03 | **License 包重放攻击：** 攻击者截获一条历史合法的 `LicensePush` 消息（即使对应 License 已被撤销），重新发送给 CULS，试图恢复已失效的授权。当前消息体仅含 `timestamp`，缺乏 nonce 防重放机制。 | T（篡改） | LicensePush 消息 → CULS | 高 |
| T-LC-04 | **仿冒 CULS 注册：** 攻击者在 CLS 注册恶意 CULS（使用伪造的 customer_id），获取合法授权后分发给未授权实例，通过 CLS 的正规渠道间接完成授权绕过。 | S（仿冒） | CULS 注册流程 → CLS | 中 |
| T-LC-05 | **离线授权码文件被盗用：** 离线授权码以文件形式传输（U 盘、邮件），攻击者截获文件后可在另一套 CULS 上导入并激活。FS 未说明 Offline Token 是否绑定 CULS 硬件特征。 | I（信息泄露）/ S（仿冒） | Offline Token 文件 → import-offline | 中 |
| T-LC-06 | **黑名单同步延迟窗口利用：** 攻击者在 CLS 发起黑名单更新（如撤销 CULS）后、黑名单同步到实例前的时间窗口内，利用已被撤销的授权继续操作。libp2p 实时推送延迟 < 10s，但离线场景下延迟不确定。 | T（篡改）/ E（权限提升） | BlacklistUpdate 同步路径 | 中 |
| T-LC-07 | **CULS 本地数据库信息泄露：** 攻击者获得客户服务器上 CULS 进程运行账户的文件读权限，直接读取 RocksDB/REDB 数据库文件，获取当前有效 License 内容、实例列表及审计日志。 | I（信息泄露） | CULS 本地嵌入式数据库文件 | 中 |
| T-LC-08 | **CLS DoS — 恶意 CULS 注册洪泛：** 攻击者批量构造 CULS 注册请求，消耗 CLS 的注册处理资源（CPU、数据库连接），导致正常 CULS 注册或授权操作无法完成。FS 未提及注册速率限制。 | D（拒绝服务） | CULS init 注册接口 → CLS | 中 |
| T-LC-09 | **宽限期滥用 — 恶意断网延续服务：** 客户故意断开 CULS 与 CLS 的网络连接，触发宽限期（14 天），到期后重新连接再次触发，在合同到期后持续使用服务。宽限期不可配置为安全约束（§45.1）。 | E（权限提升） | 宽限期触发机制 → Instance | 低 |
| T-LC-10 | **管理操作抵赖 — CLS 操作日志不完整：** 若 `actor` 字段未与操作员账号强绑定（仅记录名义字符串），操作员可否认授权发放或撤销操作，审计日志无法提供不可抵赖的证据。 | R（抵赖） | audit_logs.actor 字段 | 低 |

### 5. 安全需求与设计约束

| 威胁ID | **转化后的安全需求/设计约束** | **类型** | **优先级** |
| --- | --- | --- | --- |
| T-LC-01 | **SEC-LC-001（CLS 私钥保护）：** CLS 签名私钥必须存储在 HSM 或加密密钥库（如 PKCS#11），不得以明文形式落盘；同时设计密钥轮换流程（建议每年轮换）和泄露应急吊销机制（更新 CULS 侧信任的公钥列表）。 | 安全功能需求 | 高 |
| T-LC-02 | **SEC-LC-002（CLS 管理端身份认证）：** `taos-cls-admin` CLI 必须通过证书或 API Key 进行操作员身份认证；Web UI 必须强制登录认证并支持会话超时；所有管理操作必须记录操作员身份至 audit_logs。 | 安全功能需求 | 高 |
| T-LC-03 | **SEC-LC-003（防 License 重放）：** `LicensePush` 消息体中增加 `nonce`（一次性随机数）字段；CULS 侧维护最近 N 条 nonce 的滑动窗口缓存（建议 24h），收到重复 nonce 的消息直接拒绝。 | 安全设计约束 | 高 |
| T-LC-04 | **SEC-LC-004（CULS 注册审核）：** CULS 注册时，CLS 应校验 `customer_id` 是否为已登记客户（与 CRM 或客户表关联），防止任意方注册 CULS；建议增加人工或 CRM 自动审核步骤。 | 安全设计约束 | 中 |
| T-LC-05 | **SEC-LC-005（离线 Token 绑定）：** Offline Token 应绑定目标 CULS ID，导入时校验 Token 中的 CULS ID 与当前 CULS ID 是否匹配，防止 Token 被盗用于其他 CULS。 | 安全设计约束 | 中 |
| T-LC-06 | **SEC-LC-006（黑名单同步监控）：** 在离线场景下，CLS 应记录黑名单推送失败的 CULS，并在 CULS 重新上线时立即同步最新黑名单，不得使用旧版黑名单授权。 | 安全设计约束 | 中 |
| T-LC-07 | **SEC-LC-007（CULS 本地存储权限）：** 文档中明确要求 CULS 进程以最小权限账号运行，数据库文件目录的 OS 权限设置为仅 CULS 进程账号可读写，防止旁路读取。 | 非功能安全需求 | 中 |
| T-LC-08 | **SEC-LC-008（注册速率限制）：** CLS 注册接口应对同一源 IP 的 CULS 注册请求实施速率限制（如每小时最多 10 次），防止注册洪泛攻击。 | 非功能安全需求 | 中 |
