### 3. 分析报告

本报告针对「Explorer 任务列表根据用户进行显示」功能进行了威胁建模分析。该功能旨在增强 Explorer 的任务列表访问控制，使非 root 用户仅能查看自己创建的任务，root 用户可查看所有任务，满足客户对多用户环境下任务数据隔离的需求。

- 核心发现：共识别出 `6` 个潜在威胁，其中 `高危` `1` 个，`中危` `3` 个，`低危` `2` 个。
- 主要风险场景：
   - 前端过滤绕过：若用户筛选逻辑仅在前端实现，攻击者可直接调用后端 API 获取全部任务列表。
   - 参数篡改越权：通过修改 API 请求参数伪造用户身份，访问其他用户的任务。
   - root 身份仿冒：伪造 root 用户身份绕过过滤逻辑，获取全量任务数据。
- 结论：该功能本质上是一项安全增强，为 Explorer 引入了用户级别的任务数据隔离。设计方案在后端实施过滤逻辑，有效控制了主要威胁。整体攻击面有限，风险可控。

### 4. 威胁识别与分析（STRIDE）

Explorer 任务列表根据用户进行显示功能涉及前端页面发起任务列表查询请求，后端根据当前登录用户身份决定返回全部任务（root）或仅当前用户的任务（非 root）。

#### 4.1 关键实体与数据

| 实体/数据 | 描述 | 敏感性 |
| --- | --- | --- |
| 任务列表数据 | Explorer 中用户创建的数据导入/导出等任务记录 | 中（含任务配置、数据源信息） |
| 用户会话身份 | 后端从会话中获取的当前登录用户名及角色信息 | 高（决定数据访问范围） |
| 任务列表 API | 前端获取任务列表的 HTTP 接口，携带 user 筛选条件 | 中（数据访问入口） |
| root 角色标识 | 后端用于判断是否为 root 用户的标识逻辑 | 高（控制权限边界） |

#### 4.2 威胁评估

| 威胁ID | **威胁描述/攻击场景** | **STRIDE** | **相关组件/数据流** | **风险等级** |
| --- | --- | --- | --- | --- |
| T-EXPTSK-01 | API 用户参数篡改：非 root 用户通过拦截并修改前端发送给后端的任务列表请求中的 user 参数，将其替换为其他用户名，尝试查看他人创建的任务。 | S (仿冒) | 任务列表 API、用户会话身份 | 中 |
| T-EXPTSK-02 | 前端过滤绕过：若任务过滤逻辑仅在前端 JavaScript 代码中实现（如仅在前端隐藏非本人任务），攻击者可直接调用后端 API 接口绕过前端限制，获取未过滤的完整任务列表。 | I (信息泄露) | 任务列表 API、任务列表数据 | 高 |
| T-EXPTSK-03 | 水平越权访问任务详情：非 root 用户虽无法在列表中看到其他用户的任务，但通过枚举或猜测任务 ID，直接访问其他用户创建的任务详情页面或 API 端点。 | E (权限提升) | 任务详情 API、任务列表数据 | 中 |
| T-EXPTSK-04 | root 身份仿冒：攻击者通过篡改请求头、Cookie 或会话标识，将自身伪装为 root 用户，触发后端的"不过滤"逻辑分支，获取所有用户的任务数据。 | S (仿冒) E (权限提升) | 用户会话身份、root 角色标识 | 中 |
| T-EXPTSK-05 | 任务元数据泄露：API 响应的错误信息或分页元数据（如总任务数、总页数）可能暴露系统中其他用户的任务数量等统计信息。 | I (信息泄露) | 任务列表 API | 低 |
| T-EXPTSK-06 | 访问行为不可追溯：缺乏针对任务列表查询的审计日志，当发生越权访问事件时，无法追溯攻击者的访问行为和时间线。 | R (抵赖) | 任务列表 API | 低 |

### 5. 安全需求与设计约束

| 威胁ID | **转化后的安全需求/设计约束** | **类型** | **优先级** |
| --- | --- | --- | --- |
| T-EXPTSK-02 | SEC-EXPTSK-001（服务端强制过滤）：任务列表的用户过滤逻辑必须在后端实施，基于服务端会话中的用户身份进行判断，不得仅依赖前端过滤。 | 安全设计约束 | 高 |
| T-EXPTSK-01 | SEC-EXPTSK-002（忽略客户端用户参数）：后端在执行任务列表查询时，必须以服务端会话中存储的用户身份为准，忽略或不信任客户端请求中携带的 user 参数。 | 安全设计约束 | 中 |
| T-EXPTSK-04 | SEC-EXPTSK-003（可靠的 root 判断）：后端判断当前用户是否为 root 的逻辑必须基于服务端认证后的会话信息，不得依赖客户端可控的请求字段。 | 安全设计约束 | 中 |
| T-EXPTSK-03 | SEC-EXPTSK-004（任务详情权限校验）：任务详情查看、编辑等接口应同样实施用户级权限校验，确保非 root 用户无法通过直接访问任务 ID 查看他人任务。 | 安全功能需求 | 中 |
| T-EXPTSK-05 | SEC-EXPTSK-005（响应数据最小化）：API 响应中的分页元数据应仅反映当前用户有权查看的任务统计信息，不应泄露全局任务数量。 | 安全设计约束 | 低 |
| T-EXPTSK-06 | SEC-EXPTSK-006（基础访问日志）：建议在 Explorer 现有日志机制中记录任务列表查询的用户身份和查询范围，便于事后审计。 | 审计需求 | 低 |
