### 3. 分析报告

本报告针对 Node.js 连接器支持负载均衡和 Failover 功能进行了威胁建模分析。该功能旨在为 `taos-connector-node` 的 WebSocket 连接场景增加多地址接入、最少连接负载均衡和自动故障转移能力，覆盖 SQL 写入/查询、STMT2 参数绑定、无模式写入和数据订阅等模块。

- **核心发现：** 共识别出 `6` 个潜在威胁，其中 `高危` `0` 个，`中危` `3` 个，`低危` `3` 个。
- **主要风险场景：**
   - **凭据随 DSN URL 明文暴露：** 用户名/密码直接嵌入 DSN 字符串，若 DSN 被记录到日志或错误信息中，可导致 TDengine 认证凭据泄露。
   - **Failover 期间的中间人攻击：** wss:// 场景下若未明确 CA 证书校验策略，攻击者可部署伪造节点在地址切换时劫持连接。
   - **写入重放导致时序数据重复：** Failover 重连后对 SQL 写入和无模式写入自动重放，可能污染时序历史数据。
- **结论：** 该功能设计为客户端侧连接管理增强，不改变认证授权模型，整体攻击面有限。FS 已在设计中包含日志脱敏、TLS 支持、重连锁和指数退避等安全缓解措施。TLS 证书校验策略和示例代码弱凭据问题需在文档层面补充完善后方可进入编码实现阶段。

### 4. 威胁识别与分析（STRIDE）

本功能在客户端侧引入候选地址列表、最少连接调度器和重连锁机制，通过 WebSocket/wss 与多个 taosAdapter 实例通信，涉及认证凭据在多个候选节点间的传递，以及 Failover 后的请求自动重放。

#### 4.1 关键实体与数据

| 实体/数据 | 描述 | 敏感性 |
| --- | --- | --- |
| DSN 连接字符串 | 包含用户名、密码、候选地址列表、重连参数等配置信息 | 高（含认证凭据） |
| 候选地址列表 | 从 DSN 解析出的 taosAdapter 地址集合（主机名/IP + 端口） | 中（反映内部网络拓扑） |
| WebSocket 连接 | 客户端与 taosAdapter 之间的 WebSocket/wss 通信通道 | 高（承载认证和时序业务数据） |
| 连接计数状态 | 进程内维护的各地址活跃连接数，用于最少连接调度 | 低 |
| 订阅消费 Offset | 数据订阅场景下最后提交的消费位点 | 中（影响消息投递语义） |

#### 4.2 威胁评估

| 威胁ID | **威胁描述/攻击场景** | **STRIDE** | **相关组件/数据流** | **风险等级** |
| --- | --- | --- | --- | --- |
| T-NODELBF-01 | **DSN 凭据明文泄露：** DSN 字符串中直接嵌入用户名/密码（如 `ws://root:taosdata@...`），若应用层代码将 DSN 写入日志、错误报告或监控系统，攻击者可直接获取 TDengine 访问凭据，并以合法用户身份访问数据库。 | I (信息泄露) | DSN 连接字符串 → 应用日志/错误信息 | 中 |
| T-NODELBF-02 | **Failover 期间中间人攻击：** wss:// 场景下若连接器未验证服务端 CA 证书（或默认跳过校验），攻击者可在 Failover 地址切换时部署伪造的 taosAdapter 节点，拦截客户端连接，获取认证凭据或注入恶意响应数据。 | S (仿冒) / T (篡改) | WebSocket 连接 | 中 |
| T-NODELBF-03 | **写入重放导致时序数据重复：** Failover 重连后，SQL 写入和 InfluxDB 行协议写入模块（第 4.4 节）自动重发上一次请求。若原始写入已在服务端部分执行，重放将导致时序数据重复插入，污染历史数据（如传感器读数翻倍、设备事件重复记录）。 | T (篡改) | 写入模块 → Failover 重连 → taosAdapter | 中 |
| T-NODELBF-04 | **持续中断连接触发重连 DoS：** 攻击者（或网络故障）持续中断所有 taosAdapter 节点的连接，使客户端反复触发重连锁、指数退避等待（最长达 retry_backoff_max_ms × retries），导致正常查询请求长时间阻塞，连接器无法服务。 | D (拒绝服务) | 重连锁 → 所有候选地址 | 低 |
| T-NODELBF-05 | **订阅消息重复消费缺乏审计：** 数据订阅场景下 Failover 后从最后提交 offset 继续拉取消息（第 4.4 节），可能导致已处理消息被重复消费。系统无法区分重复消费是 Failover 引发还是正常投递，难以追溯数据处理结果的准确性。 | R (抵赖) | 订阅消费者 → Offset 状态 → 业务系统 | 低 |
| T-NODELBF-06 | **错误信息泄露内网拓扑：** 连接失败时的错误信息（参考第 11 节错误表）若包含所有候选节点的完整地址和端口，可能向攻击者暴露内部 taosAdapter 集群的网络拓扑和节点数量，为横向渗透提供信息。 | I (信息泄露) | 错误处理 → 客户端日志/应用层 | 低 |

### 5. 安全需求与设计约束

| 威胁ID | **转化后的安全需求/设计约束** | **类型** | **优先级** | **FS 落实状态** |
| --- | --- | --- | --- | --- |
| T-NODELBF-01 | SEC-NODELBF-001（DSN 日志脱敏）：连接器内部日志及错误输出不得包含完整 DSN URL；凭据部分（密码/Token）必须被遮蔽，已由 FS 第 6.3 节要求覆盖。建议在 API 文档中提示用户避免在应用层代码中直接记录 DSN 字符串。 | 安全设计约束 | 中 | ⚠️ 连接器层已落实，应用层使用建议待补充 |
| T-NODELBF-02 | SEC-NODELBF-002（TLS 证书校验策略）：需明确 wss:// 场景下默认的 CA 证书校验行为；应提供可配置的证书校验选项（如 `rejectUnauthorized`、自定义 CA 路径），确保私有化部署自签名证书场景的安全可用性。 | 安全设计约束 | 中 | ❌ FS 未涉及，需在设计文档中补充 |
| T-NODELBF-03 | SEC-NODELBF-003（写入幂等性说明）：FS 第 4.4 节已明确写入幂等性问题，在 API 文档中应显式建议业务层对创建语句使用 `IF NOT EXISTS`，对时序数据写入设计幂等逻辑，以容忍 Failover 重放。 | 安全设计约束 | 中 | ✅ FS 中已说明，待落实到文档 |
| T-NODELBF-04 | SEC-NODELBF-004（重连防护）：重连锁 + 指数退避机制（第 4.3.2 节）已有效限制重连频率，无需额外安全需求。 | 非功能安全需求 | 低 | ✅ 已在 FS 中实现 |
| T-NODELBF-05 | SEC-NODELBF-005（订阅幂等性说明）：FS 第 4.4 节已明确订阅场景的至少一次语义，API 文档中应建议业务层基于消息内容实现幂等消费，以防止 Failover 重复消费导致的业务数据异常。 | 安全设计约束 | 低 | ✅ 已在 FS 中说明 |
| T-NODELBF-06 | SEC-NODELBF-006（错误信息分级输出）：建议连接失败的详细节点地址信息仅在调试级别日志中输出，面向上层应用的错误信息仅包含必要的错误码和简短描述，避免泄露内网拓扑。 | 安全设计约束 | 低 | ⏳ FS 未涉及，作为后续优化建议 |
