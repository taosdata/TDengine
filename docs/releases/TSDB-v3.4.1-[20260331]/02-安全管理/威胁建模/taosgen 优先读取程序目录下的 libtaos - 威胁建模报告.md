### 3. 分析报告

本报告针对 taosgen 优先加载程序目录下 libtaos 库的功能进行了威胁建模分析。该功能旨在解决 IDMP 与已安装的 TDengine 服务端库版本冲突问题，实现多版本 libtaos 共存。
- **核心发现**：共识别出 **15** 个潜在威胁，其中 **高危** **2** 个，**中危** **5** 个，**低危** **8** 个。
- **主要风险场景**：
   - **恶意库替换攻击**：攻击者替换 `./lib/libtaos` 为恶意版本，实现任意代码执行和系统完全控制。
   - **权限提升与库注入**：通过库加载机制注入恶意代码，获得更高权限，可能导致横向移动。
   - **符号链接欺骗**：利用符号链接将库路径指向恶意库，绕过正常的路径控制。
   - **TOCTOU 竞态条件**：在检查和加载库文件之间的时间窗口进行攻击。
- **结论**：该功能设计在解决多版本共存方面价值显著，但优先加载本地库引入了新的攻击面。**必须在功能详细设计与编码实现前**，将本报告提出的安全需求作为核心设计约束予以落实，特别是文件完整性校验、符号链接检测、严格的文件权限控制和详细的审计日志。

### 4. 威胁识别与分析（STRIDE）

taosgen 程序在创建 TDengine 客户端时，采用以下加载策略：
1. **优先加载**：程序所在路径下的 `./lib/libtaos` 库（使用绝对路径）
2. **回退机制**：若本地库不存在，则从系统环境路径加载 libtaos 库
3. **单次加载**：libtaos 库仅在首次创建客户端实例时加载，进程生命周期内不可更换

#### 4.2 威胁评估

| 威胁 ID | 威胁描述 / 攻击场景 | STRIDE | 相关组件 / 数据流 | 风险等级 |
| --- | --- | --- | --- | --- |
| T-LIB-01 | **恶意库替换攻击**：攻击者获得安装目录写权限，将 `./lib/libtaos.so` 替换为恶意编译的库。taosgen 启动时加载恶意库，执行任意代码，窃取数据库凭证和敏感数据，甚至完全控制系统。 | S（欺骗）/ E（权限提升） | 本地 libtaos 库文件 -> 动态加载器 | 高 |
| T-LIB-02 | **符号链接欺骗**：攻击者在 `./lib/` 目录中创建符号链接 `libtaos.so -> /tmp/malicious.so`，指向恶意库。taosgen 在不检查的情况下跟随符号链接加载恶意库。 | S（欺骗） | 本地 lib 目录 -> 符号链接 -> 恶意库 | 中 |
| T-LIB-03 | **TOCTOU 竞态条件**：攻击者利用检查库文件和实际加载之间的时间窗口，在验证通过后、加载前快速替换库文件，绕过安全检查。 | T（篡改）/ E（权限提升） | 库文件验证 -> 库加载时间窗口 | 中 |
| T-LIB-04 | **环境变量注入**：攻击者通过修改 LD_LIBRARY_PATH 等环境变量，尝试注入恶意库路径。虽然当前设计已优先使用绝对路径，但在回退到系统路径时仍存在风险。 | E（权限提升） | 环境变量 -> 库搜索路径 | 中 |
| T-LIB-05 | **运行时库篡改**：攻击者通过内存注入、进程注入等手段，在 taosgen 运行时修改内存中的 libtaos 库代码或数据，改变程序行为。 | T（篡改） | 进程内存空间 | 中 |
| T-LIB-06 | **配置文件篡改**：攻击者修改 taosgen 配置文件（如库搜索路径配置），影响库加载行为，绕过安全控制或加载错误版本的库。 | T（篡改） | 配置文件 -> 库加载逻辑 | 中 |
| T-LIB-07 | **库加载行为不可追溯**：缺乏充分的日志记录，无法追溯哪个库被加载、何时加载、加载是否成功，导致安全事件发生时难以调查和取证。 | R（抵赖） | 日志系统 | 低 |
| T-LIB-08 | **操作审计缺失**：缺乏对 `./lib/` 目录访问和修改的系统级审计，攻击者可以在不被察觉的情况下修改库文件。 | R（抵赖） | 文件系统审计 | 低 |
| T-LIB-09 | **库路径信息泄露**：错误消息或日志泄露详细的系统路径信息（如安装目录结构），帮助攻击者了解系统布局，降低攻击难度。 | I（信息泄露） | 错误处理 -> 日志输出 | 低 |
| T-LIB-10 | **调试信息泄露**：生产环境使用带调试符号的库或程序，泄露敏感的内部实现细节，帮助攻击者分析和逆向工程。 | I（信息泄露） | 二进制文件 | 低 |
| T-LIB-11 | **内存信息泄露**：库加载过程中的内存泄露或不当的内存管理可能暴露敏感数据（如配置、凭证）。 | I（信息泄露） | 内存管理 | 低 |
| T-LIB-12 | **恶意库导致拒绝服务**：攻击者替换的恶意库故意导致 taosgen 崩溃或挂起，造成服务不可用和业务中断。 | D（拒绝服务） | 库加载 -> 进程崩溃 | 中 |
| T-LIB-13 | **库依赖缺失导致服务不可用**：libtaos 依赖的其他共享库缺失或版本不兼容，导致加载失败，服务无法启动。 | D（拒绝服务） | 库依赖关系 | 低 |
| T-LIB-14 | **资源耗尽攻击**：恶意库在加载时消耗过多系统资源（CPU、内存、文件描述符），导致系统性能降低或不可用。 | D（拒绝服务） | 系统资源 | 低 |
| T-LIB-15 | **权限提升与横向移动**：攻击者通过库注入获得 taosgen 进程权限后，利用该权限访问敏感数据、横向移动到其他系统或提升到 root 权限。 | E（权限提升） | 进程权限 -> 系统访问 | 高 |

### 5. 安全需求与设计约束

| 威胁 ID | 转化后的安全需求 / 设计约束 | 类型 | 优先级 |
| --- | --- | --- | --- |
| T-LIB-01 | **SEC-LIB-001（文件权限控制）**：taosgen 安装目录、lib 子目录和库文件必须设置严格的文件权限。推荐配置：目录 750 (root:taosgen)，库文件 644。禁止普通用户写入。 | 安全设计约束 | 高（已满足） |
| T-LIB-01 | **SEC-LIB-002（文件完整性校验）**：在加载库前，必须验证库文件的完整性。推荐使用 SHA-256 哈希值验证或数字签名验证。校验失败则拒绝加载并记录告警。 | 安全功能需求 | 中（可后续优化） |
| T-LIB-01 | **SEC-LIB-003（强制访问控制）**：推荐使用 SELinux 或 AppArmor 实施强制访问控制策略，限制 taosgen 进程只能从特定路径加载库，禁止加载其他路径的库。 | 安全设计约束 | 中 |
| T-LIB-02 | **SEC-LIB-004（路径规范化）**：使用 realpath() 等函数对库路径进行规范化，并验证规范化后的路径仍在预期的安全目录内，防止路径遍历攻击。 | 安全功能需求 | 高 |
| T-LIB-03 | **SEC-LIB-005（原子操作）**：使用文件描述符的原子操作序列：open() -> fstat() 验证 -> 使用同一文件描述符加载，避免 TOCTOU 竞态条件。 | 安全功能需求 | 中 |
| T-LIB-03 | **SEC-LIB-006（文件锁定）**：在验证和加载过程中对库文件加锁，防止并发修改，或拷贝到安全路径访问。 | 安全功能需求 | 中 |
| T-LIB-04 | **SEC-LIB-007（环境变量清理）**：taosgen 启动时应清理或验证环境变量，确保 LD_LIBRARY_PATH 等不被恶意设置。优先使用绝对路径加载（已实现）。 | 安全设计约束 | 中 |
| T-LIB-05 | **SEC-LIB-008（内存保护）**：启用 ASLR（地址空间布局随机化）和 DEP/NX bit（数据执行保护），增加运行时篡改的难度。 | 非功能安全需求 | 中 |
| T-LIB-07 | **SEC-LIB-009（详细审计日志）**：必须记录详细的库加载日志，包含：加载时间戳（精确到毫秒）、库文件完整路径、库文件 SHA-256 哈希值、库文件元数据（大小、修改时间、权限）、加载结果（成功/失败）、失败详细原因。 | 安全功能需求 | 高 |
| T-LIB-09 | **SEC-LIB-010（错误信息安全）**：生产环境的错误消息不得泄露详细的路径信息、系统配置等敏感信息。详细错误仅记录到受保护的日志文件。 | 安全设计约束 | 低 |
| T-LIB-10 | **SEC-LIB-011（移除调试信息）**：生产环境的二进制文件必须移除调试符号（使用 strip 命令），防止逆向工程。 | 安全设计约束 | 高 |
| T-LIB-11 | **SEC-LIB-012（内存安全实践）**：使用内存安全的编程实践，敏感数据（如密钥、凭证）使用后必须立即清零（使用 memset_s 或 explicit_bzero）。 | 安全设计约束 | 中 |
| T-LIB-12 | **SEC-LIB-013（健康检查）**：实施进程健康检查和自动重启机制。设置库加载超时，防止恶意库导致挂起。 | 健壮性需求 | 中 |
| T-LIB-13 | **SEC-LIB-014（依赖检查）**：安装脚本必须检查所有运行时依赖项。提供依赖检查工具和清晰的错误提示。 | 安全设计约束 | 高 |
| T-LIB-14 | **SEC-LIB-015（资源限制）**：使用 ulimit、cgroups 等机制设置 taosgen 进程的资源限制（CPU、内存、文件描述符），防止资源耗尽。 | 非功能安全需求 | 中 |
| T-LIB-15 | **SEC-LIB-016（最小权限原则）**：taosgen 必须以最小权限运行，建议生产环境禁止以 root 身份运行。 | 安全设计约束 | 高 |
| T-LIB-15 | **SEC-LIB-017（能力限制）**：使用 Linux capabilities 机制，仅授予必要的能力，而非完整的 root 权限。 | 安全设计约束 | 中 |

### 7. 部署安全配置清单

#### 7.1 文件系统权限配置

```bash

## 1. 创建专用服务账户

sudo useradd -r -s /bin/false -d /opt/taosgen taosgen

## 2. 设置目录和文件权限

sudo chown -R root:taosgen /opt/taosgen
sudo chmod 750 /opt/taosgen
sudo chmod 750 /opt/taosgen/lib
sudo chmod 644 /opt/taosgen/lib/*.so
sudo chmod 750 /opt/taosgen/bin/taosgen
sudo chmod 640 /opt/taosgen/conf/*

## 3. 日志目录

sudo mkdir -p /var/log/taosgen
sudo chown taosgen:taosgen /var/log/taosgen
sudo chmod 750 /var/log/taosgen
```

#### 3.0.1 systemd 服务配置（安全加固）

```toml
[Unit]
Description=TDengine Data Generator
After=network.target

[Service]
Type=simple
User=taosgen
Group=taosgen

## 4. 安全加固

NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ProtectHome=true
ReadWritePaths=/var/log/taosgen
ReadOnlyPaths=/opt/taosgen

## 5. 资源限制

LimitNOFILE=65535
LimitNPROC=4096
MemoryLimit=2G
CPUQuota=200%

## 6. 命名空间隔离

PrivateDevices=true
ProtectKernelTunables=true
ProtectKernelModules=true
ProtectControlGroups=true

ExecStart=/opt/taosgen/bin/taosgen
Restart=on-failure
RestartSec=10

[Install]
WantedBy=multi-user.target
```
