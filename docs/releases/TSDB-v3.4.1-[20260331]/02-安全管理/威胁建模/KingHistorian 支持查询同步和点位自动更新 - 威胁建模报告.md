### 3. 分析报告

本报告针对 KingHistorian 支持查询同步和点位自动更新功能进行了威胁建模分析。该功能为 taosX 的 KingHistorian 数据源扩展了两种新采集模式：（1）查询同步模式（Query Sync），结合历史数据迁移与周期性增量查询；（2）实时点位自动更新（Point Auto-Update），通过 `KingHistPointUpdater` 组件周期性发现 KingHistorian Server 中的新增点位并追加订阅。

- **核心发现：** 共识别出 `6` 个潜在威胁，其中 `高危` `0` 个，`中危` `2` 个，`低危` `4` 个。
- **主要风险场景：**
  - **拒绝服务风险：** 点位自动更新发现大量新增点位时，短时间内对 TDengine 发起密集订阅；历史数据量远超预期导致阶段一长时间阻塞。
  - **信息泄露：** DSN 中包含明文连接凭据，若日志或错误信息中意外输出 DSN 片段，可能泄露 KingHistorian 访问凭据。
  - **数据完整性（中间人）：** 若网络路径上存在攻击者，传输中的时序数据可能被篡改。
- **结论：** 该功能为内网工业数据采集扩展，整体攻击面有限，设计合理。两个主要中危威胁的缓解措施已在参数设计中覆盖（`interval`/`update_interval` 限流），无高危威胁。

### 4. 威胁识别与分析（STRIDE）

本功能运行于客户内网，taosX 进程通过 KingHistorian Windows SDK（IPC 协议）连接 KingHistorian Server，采集时序数据后写入 TDengine。

#### 4.1 关键实体与数据

| 实体/数据 | 描述 | 敏感性 |
| --- | --- | --- |
| DSN 连接字符串 | 包含 KingHistorian 主机地址、端口及明文用户名/密码 | 高（含访问凭据） |
| KingHistorian 时序数据 | 工业设备传感器/变量读数，如温度、压力、设备状态 | 中（生产运营数据） |
| 点位元数据 | KingHistorian Server 中的点位名称、类型、变量组结构 | 低 |
| IPC 通信通道 | taosX 与 KingHistorian SDK 之间的 Windows 本地 IPC 连接 | 中 |
| 增量同步状态 | `last_sync_ts` 时间戳，记录上次同步位置 | 低 |

#### 4.2 威胁评估

| 威胁ID | 威胁描述/攻击场景 | STRIDE | 相关组件/数据流 | 风险等级 |
| --- | --- | --- | --- | --- |
| T-KHQS-01 | **DSN 凭据日志泄露：** taosX 在记录任务配置、错误堆栈或调试日志时，若未对 DSN 字符串进行脱敏处理，可能将 KingHistorian 连接凭据（用户名/密码）明文记录到日志文件，导致凭据泄露。 | I（信息泄露） | DSN 字符串 → 日志系统 | 低 |
| T-KHQS-02 | **点位爆炸导致写入 DoS：** 生产环境中 KingHistorian Server 在短时间内新增大量点位（如数千个传感器），`KingHistPointUpdater` 在一个轮询周期内发现全部新点位并触发密集的 `data_subscribe()` 调用，可能短时间内对 TDengine 产生大量写入并引发性能抖动。 | D（拒绝服务） | KingHistPointUpdater → data_subscribe() → TDengine 写入 | 中 |
| T-KHQS-03 | **历史数据量超载：** 用户将 `start` 参数设置为极早的时间（如多年前），阶段一历史追赶产生的数据量远超预期，导致 taosX 长时间阻塞、内存占用持续上升，影响同一 taosX 实例上的其他任务。 | D（拒绝服务） | collect_history() → TDengine 写入 | 中 |
| T-KHQS-04 | **时序数据被篡改：** 若客户网络存在内部攻击者（内鬼）或 KingHistorian Server 本身被入侵，推送给 taosX 的时序数据被修改（如篡改电表读数、设备状态），污染数据库中的历史记录，且功能本身无数据完整性校验机制。 | T（篡改） | KingHistorian Server → IPC SDK → TDengine | 低 |
| T-KHQS-05 | **点位订阅变更不可追溯：** 点位自动更新模式下，`KingHistPointUpdater` 静默追加订阅新增点位，若未记录变更日志，事后无法审计哪些点位是何时被自动添加的，发生数据异常时难以定位根因。 | R（抵赖） | KingHistPointUpdater → 已知点位集合 | 低 |
| T-KHQS-06 | **update_interval 过小导致 KingHistorian 轮询过载：** 用户（或错误配置）将 `update_interval` 设置为极小值（如 1 秒），`KingHistPointUpdater` 以过高频率向 KingHistorian Server 发起点位列表查询，可能导致 KingHistorian Server 负载异常，影响其他采集任务。 | D（拒绝服务） | KingHistPointUpdater → KingHistorian Server 元数据查询 | 低 |

### 5. 安全需求与设计约束

| 威胁ID | 转化后的安全需求/设计约束 | 类型 | 优先级 |
| --- | --- | --- | --- |
| T-KHQS-01 | SEC-KHQS-001（日志脱敏）：taosX 日志框架应对 DSN 字符串中的密码字段进行脱敏处理，记录日志时以 `***` 替换密码部分。此需求适用于所有数据源类型，建议在 taosX 日志公共模块统一落实。 | 安全设计约束 | 低 |
| T-KHQS-02 | SEC-KHQS-002（批量订阅限速）：点位自动更新追加订阅时，建议对单次 `data_subscribe()` 的点位数量进行限制或分批处理，避免一次性订阅大量点位引发写入突刺。可结合 `update_interval` 分批发送。 | 非功能安全需求 | 低 |
| T-KHQS-03 | SEC-KHQS-003（历史追赶保护）：建议文档和前端提示用户合理设置 `start` 时间和 `time_range` 参数，并在任务日志中输出阶段一的预估数据量或进度信息，便于用户及时发现配置错误。 | 健壮性需求 | 低 |
| T-KHQS-05 | SEC-KHQS-004（点位变更日志）：建议 `KingHistPointUpdater` 在发现并追加新增点位时，记录包含点位 ID、时间戳的操作日志，支持事后审计自动订阅的点位来源。 | 审计需求 | 低 |
| T-KHQS-06 | SEC-KHQS-005（轮询间隔下限）：建议为 `update_interval` 设置合理的最小值限制（如 10 秒），防止用户配置过小值导致 KingHistorian Server 过载。FS 已在性能章节建议根据实际场景调整，可在参数解析时进行下限校验。 | 健壮性需求 | 低 |
