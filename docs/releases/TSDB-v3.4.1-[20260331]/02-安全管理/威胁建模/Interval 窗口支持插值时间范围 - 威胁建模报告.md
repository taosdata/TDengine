### 3. 分析报告

本报告针对 Interval 窗口支持插值时间范围功能进行了威胁建模分析。该功能旨在为 Interval 窗口的 `fill` 子句新增 `surrounding_time_interval` 和 `fill_values` 参数，以及 `surround` 子句，限制插值时的数据探索范围，使用户可以控制在多大的时间范围内寻找有效值进行填充。

- 核心发现：共识别出 `5` 个潜在威胁，其中 `高危` `0` 个，`中危` `1` 个，`低危` `4` 个。
- 主要风险场景：
   - 资源消耗：用户设置超大 `surrounding_time_interval` 值可能导致查询扫描大量窗口数据，消耗过多计算资源。
   - 输入异常：畸形的 `fill_values` 参数可能触发类型转换异常。
- 结论：该功能为纯 SQL 查询语法扩展，未引入新的网络接口、数据存储或认证机制，攻击面增量极小。已识别的威胁均可由现有安全框架（SQL 解析器校验、查询超时、权限体系）有效缓解，整体安全风险低。

### 4. 威胁识别与分析（STRIDE）

本功能在 Interval 窗口查询中扩展了 `fill` 子句语法，新增 `surrounding_time_interval`（sti）参数控制数据探索范围和 `fill_values` 参数指定默认填充值，并新增 `surround` 子句。查询在现有 SQL 解析器和执行引擎中处理，数据访问受 `where` 条件和权限体系约束。

#### 4.1 关键实体与数据

| 实体/数据 | 描述 | 敏感性 |
| --- | --- | --- |
| SQL 查询语句 | 包含新增 `surrounding_time_interval`、`fill_values` 参数和 `surround` 子句的查询请求 | 低 |
| 窗口聚合结果 | Interval 窗口的聚合计算结果，作为 `fill` 操作的数据源 | 中（取决于原始数据敏感性） |
| 插值结果集 | 经过 `fill` 操作后返回给客户端的最终查询结果 | 中（取决于原始数据敏感性） |
| fill_values 参数 | 用户指定的默认填充值，在探索范围内未找到有效值时使用 | 低 |

#### 4.2 威胁评估

| 威胁ID | **威胁描述/攻击场景** | **STRIDE** | **相关组件/数据流** | **风险等级** |
| --- | --- | --- | --- | --- |
| T-ITVFILL-01 | SQL 解析器绕过：攻击者构造包含特殊字符或超长参数值的 `surrounding_time_interval` 或 `fill_values`，尝试绕过 SQL 解析器校验，触发未预期的解析路径或内存异常。 | S (仿冒) | SQL 解析器 | 低 |
| T-ITVFILL-02 | 超大探索范围导致资源耗尽：用户设置极大的 `surrounding_time_interval` 值（如数百万秒），配合小 interval 窗口，导致 `fill` 操作需要扫描大量窗口聚合数据（公式 ⌊sti/w⌋ 产生巨大值），耗尽服务器 CPU 和内存资源。 | D (拒绝服务) | 查询执行引擎、窗口聚合结果 | 中 |
| T-ITVFILL-03 | 流计算场景批量触发资源耗尽：在流计算中，大量触发窗口同时执行带有大 `surrounding_time_interval` 的 `fill` 操作，虽然 FS 说明每个触发窗口独立计算，但并发触发可能叠加资源消耗。 | D (拒绝服务) | 流计算引擎、触发窗口 | 低 |
| T-ITVFILL-04 | 通过插值行为推断数据分布：攻击者通过对比不同 `surrounding_time_interval` 值下的填充结果（是返回 `fill_values` 还是实际数据），推断特定时间范围内是否存在数据，间接获取数据分布信息。 | I (信息泄露) | 插值结果集 | 低 |
| T-ITVFILL-05 | fill_values 类型混淆导致异常：攻击者为 `fill_values` 提供与目标列类型不匹配的值（如对 INT 列传入超长字符串），尝试触发类型转换异常或内存越界。 | T (篡改) | SQL 解析器、fill_values 参数 | 低 |

### 5. 安全需求与设计约束

| 威胁ID | **转化后的安全需求/设计约束** | **类型** | **优先级** |
| --- | --- | --- | --- |
| T-ITVFILL-01 | SEC-ITVFILL-001（参数边界校验）：SQL 解析器应对 `surrounding_time_interval` 的取值范围进行严格校验（大于 0，interval 子句中需 ≥ interval），对 `fill_values` 的数量和类型进行编译期检查，拒绝不合法输入。 | 安全设计约束 | 中 |
| T-ITVFILL-02 | SEC-ITVFILL-002（查询资源限制）：复用现有查询超时机制和资源配额（如 `queryPolicy`、`maxRetentionTime`），对包含大探索范围的 `fill` 查询执行超时中断。 | 非功能安全需求 | 中 |
| T-ITVFILL-05 | SEC-ITVFILL-003（类型安全校验）：`fill_values` 参数必须在 SQL 编译阶段完成类型检查与转换，类型不匹配时返回明确错误码，不泄露内部实现细节。 | 安全设计约束 | 低 |

> 说明：T-ITVFILL-03 和 T-ITVFILL-04 风险等级为低，且现有机制（流计算资源管控、数据访问权限体系）已可覆盖，不额外提出安全需求。
