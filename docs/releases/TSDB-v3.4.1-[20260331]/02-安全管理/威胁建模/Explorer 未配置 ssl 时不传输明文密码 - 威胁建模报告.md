### 3. 分析报告

本报告针对「Explorer 未配置 ssl 时不传输明文密码」功能进行了威胁建模分析。该功能旨在将 TDengine Explorer 的认证机制从客户端可读 Token Cookie + Base64 明文 Basic Auth Header，升级为服务端 HttpOnly Cookie 会话机制 + TimeBasedXor 时间窗口加密密码传输，在无 SSL 的部署场景下防止密码明文被被动监听截获。

- **核心发现：** 共识别出 `7` 个潜在威胁，其中 `高危` `1` 个，`中危` `3` 个，`低危` `3` 个。
- **主要风险场景：**
   - **会话 Cookie 网络明文截获（高危）：** 在无 HTTPS 的目标场景下，session_id Cookie 在每次 HTTP 请求中明文传输，攻击者网络监听即可劫持会话，是本特性最主要的残余风险，在 FS 中已明确声明为已知局限。
   - **XOR 密钥可重建（中危）：** TimeBasedXor 密钥由硬编码前缀与明文时间戳（从密文中直接读取）拼接构成，攻击者截获密文后可完整重建密钥并解密密码。
   - **litcrypt 保护被逆向（中危）：** litcrypt 提供混淆而非加密，专业逆向工具可从二进制文件提取 XOR 密钥前缀，结合时间戳重建密钥。
- **结论：** 该功能设计在无 SSL 场景下相较原有 Base64 明文 Basic Auth 方案有实质性安全改善，主要威胁在设计目标范围内均有对应缓解措施，或已在 FS 中明确声明为已知局限（FS 10.2 节）。在部署了 HTTPS 的生产环境中，上述中高危威胁的实际可利用性将显著降低。

### 4. 威胁识别与分析（STRIDE）

本特性在 taos-explorer 中重构了登录流程：前端将用户密码通过 TimeBasedXor 算法加密（密钥 = 16 字节硬编码前缀 `taosdataexplorer` + 8 字节时间戳，有效期 60 秒），以 JSON Body 形式 POST 至 `/api/-/login`；后端解密并验证 TSDB 凭据后，创建服务端会话并以 HttpOnly Cookie 形式返回 session_id；后续请求携带 Cookie 进行会话验证。

#### 4.1 关键实体与数据

| 实体/数据 | 描述 | 敏感性 |
| --- | --- | --- |
| encrypted_password | TimeBasedXor 加密后的用户密码，以 `{timestamp}.{base64}` 格式在 HTTP POST body 中传输 | 高（可通过重建密钥解密） |
| TimeBasedXor 密钥 | 16 字节硬编码前缀 `taosdataexplorer`（litcrypt 混淆）+ 8 字节时间戳（明文携带于密文中） | 中（混淆而非加密保护） |
| session_id Cookie | 服务端会话标识，存储于 HttpOnly Cookie，有效期 1 小时 | 高（持有即可访问用户会话） |
| tsdb_password（AES 加密） | 用户 TSDB 密码，使用 AES-CBC-MAC 加密后存储于 oauth_users 表，同时出现于 `/api/-/me` 响应中 | 高（AES 密钥泄露则可解密） |
| oauth_sessions 表 | 服务端会话记录，含 session_id、expires_at 及关联的用户凭据 | 高 |
| /api/-/login 端点 | 接收加密密码、验证 TSDB 凭据、创建会话的登录接口 | 中（主要攻击入口点） |

#### 4.2 威胁评估

| 威胁ID | **威胁描述/攻击场景** | **STRIDE** | **相关组件/数据流** | **风险等级** |
| --- | --- | --- | --- | --- |
| T-EXPSSL-01 | **XOR 密钥可重建并解密密码：** TimeBasedXor 密文格式为 `{timestamp}.{base64encrypted}`，时间戳以明文形式嵌入密文中。XOR 密钥由已知固定前缀 `taosdataexplorer`（16 字节，litcrypt 混淆可被逆向，见 T-EXPSSL-06）与明文时间戳（8 字节大端序）拼接而成。攻击者截获登录请求后，直接从密文提取时间戳，拼接固定前缀重建完整 XOR 密钥，即可解密原始密码。 | I (信息泄露) | 前端→登录 API 数据流 / encrypted_password | 中 |
| T-EXPSSL-02 | **60 秒内密码密文重放：** 攻击者在 TimeBasedXor 60 秒有效期内截获登录请求并重放，冒充合法用户创建新会话。由于服务端只校验时间戳有效性而无一次性随机数（nonce）机制，同一加密密码在有效期内可被多次使用。 | S (仿冒) | 登录 API / TimeBasedXor 时间窗口 | 中 |
| T-EXPSSL-03 | **会话 Cookie 网络明文截获：** 在无 HTTPS 的目标部署场景中，session_id Cookie 在每次 HTTP 请求中明文传输（HttpOnly 属性仅防止 JavaScript 读取，对网络层截获无效）。攻击者通过网络监听获取 session_id，可直接劫持用户会话，完全绕过密码保护机制，在 1 小时内以受害用户身份执行任意操作。 | I (信息泄露) | session_id Cookie / HTTP 通信全程 | 高 |
| T-EXPSSL-04 | **登录接口暴力测试：** 攻击者利用 TimeBasedXor 在本地生成当前时间戳对应的密文，反复调用 `/api/-/login` 尝试不同密码组合。FS 未提及登录速率限制或账户锁定机制，数据库连接验证作为唯一节流手段，暴力攻击效率受限但可持续。 | D (拒绝服务) + S (仿冒) | 登录 API / TSDB 数据库连接池 | 低 |
| T-EXPSSL-05 | **`/api/-/me` 响应暴露加密密码：** FS 4.2.1 节响应示例显示 `/api/-/me` 接口在响应体中返回 `tsdb_password` 字段（AES-CBC-MAC 加密形式）。攻击者在劫持会话后（参见 T-EXPSSL-03）可获取该字段；若未来 AES 密钥管理出现漏洞或加密方案降级，可还原用户 TSDB 原始凭据。 | I (信息泄露) | /api/-/me API / tsdb_password 字段 | 低 |
| T-EXPSSL-06 | **litcrypt 混淆被逆向提取密钥前缀：** litcrypt 提供编译时字符串混淆而非密码学保护。攻击者使用 Ghidra、IDA 等逆向工具对 taos-explorer 二进制文件进行静态分析，可从解混淆后的字符串中提取 XOR 密钥前缀 `taosdataexplorer`，与 T-EXPSSL-01 结合可自动化解密截获的所有登录密文。 | I (信息泄露) | Explorer 后端二进制 / litcrypt 密钥前缀 | 中 |
| T-EXPSSL-07 | **会话表积压影响查询性能：** 攻击者重复登录成功后不触发登出，持续创建 1 小时有效期的会话记录。虽然 FS 8.1 节配置了过期会话定期清理，但高频登录可在短时间内积累大量待清理记录，影响 session_id 字段索引查询效率，延长正常用户的会话验证响应时间。 | D (拒绝服务) | 登录 API / oauth_sessions 数据库表 | 低 |
