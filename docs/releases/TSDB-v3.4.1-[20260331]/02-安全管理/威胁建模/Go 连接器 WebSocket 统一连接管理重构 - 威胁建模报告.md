### 3. 分析报告

本报告针对 Go 连接器 WebSocket 统一连接管理重构功能进行了威胁建模分析。该功能旨在将 driver-go 中分散在多个包（taosWS、ws/stmt、ws/schemaless、ws/tmq）的 WebSocket 连接管理统一到 `ws/unified` 包中，同时引入多节点 failover、自动重连和 stmt2 二进制协议支持。

- 核心发现：共识别出 `7` 个潜在威胁，其中 `高危` `1` 个，`中危` `3` 个，`低危` `3` 个。
- 主要风险场景：
   - 凭据泄露：DSN 字符串或日志中可能暴露数据库连接凭据。
   - 传输窃听：未启用 WSS 时 WebSocket 消息可被中间人截获。
   - 重连风暴：大规模客户端同时重连可能导致服务端过载。
- 结论：该功能作为客户端 SDK 内部重构，将分散的连接管理逻辑统一，从架构层面降低了安全实现不一致的风险。设计已包含凭据脱敏、WSS 加密支持、重连节流等安全机制。整体安全风险较低，可进入编码实现阶段。

### 4. 威胁识别与分析（STRIDE）

本次重构将 WebSocket 连接管理统一到 `ws/unified.Client`，支持多节点 failover 和自动重连，通过 Bootstrap 握手完成认证，使用 req_id 进行消息路由，并新增 stmt2 二进制协议支持。

#### 4.1 关键实体与数据

| 实体/数据 | 描述 | 敏感性 |
| --- | --- | --- |
| Config / DSN | 包含用户名、密码、Token 等认证凭据的连接配置 | 高（含明文凭据） |
| Bootstrap 握手 | 连接建立后的认证信息交换过程 | 高（传递认证凭据） |
| WebSocket 消息通道 | 客户端与 taosAdapter 之间的 WebSocket 连接 | 中（承载查询和写入数据） |
| pendingRequests | 以 req_id 为键的待响应请求注册表 | 中（含请求上下文） |
| stmt2 二进制帧 | 参数化写入的二进制编码数据 | 中（含业务时序数据） |
| RequestSummary | 失败请求的诊断上下文信息 | 低（已脱敏但含连接元数据） |
| Endpoint 列表 | 多节点 taosAdapter 的地址列表 | 低（基础设施信息） |

#### 4.2 威胁评估

| 威胁ID | **威胁描述/攻击场景** | **STRIDE** | **相关组件/数据流** | **风险等级** |
| --- | --- | --- | --- | --- |
| T-GOWSUNIFY-01 | DSN 凭据泄露：应用程序在日志、配置文件或错误信息中以明文形式记录 DSN 字符串，攻击者通过访问日志文件或监控系统获取数据库连接凭据（用户名、密码、Token）。 | I (信息泄露) | Config / DSN | 高 |
| T-GOWSUNIFY-02 | WebSocket 通信窃听：在未启用 WSS 的部署场景下，攻击者通过网络嗅探截获客户端与 taosAdapter 之间的 WebSocket 明文通信，获取 Bootstrap 握手中的认证信息及后续的查询/写入数据。 | I (信息泄露) | WebSocket 消息通道、Bootstrap 握手 | 中 |
| T-GOWSUNIFY-03 | 多节点重连风暴：在大规模部署场景下（如数百个 IoT 边缘节点），taosAdapter 节点故障后所有客户端同时触发自动重连，瞬间大量连接请求涌向存活节点，造成雪崩效应导致服务不可用。 | D (拒绝服务) | unified.Client failover 机制 | 中 |
| T-GOWSUNIFY-04 | 恶意 taosAdapter 节点：在多节点 failover 场景下，攻击者通过 DNS 劫持或网络重定向将客户端连接引导到恶意节点，窃取认证凭据或返回伪造的查询结果。 | S (仿冒) | Endpoint 列表、Bootstrap 握手 | 中 |
| T-GOWSUNIFY-05 | 连接状态混淆：在高并发场景下，由于 Runtime 替换和 Generation 递增的时序竞争，可能导致请求被发送到已关闭的旧连接，或响应被错误路由到不匹配的请求。 | T (篡改) | pendingRequests、Runtime swap | 低 |
| T-GOWSUNIFY-06 | 诊断信息泄露：RequestSummary 中包含的操作类型、目标地址、req_id 等诊断信息，虽已对 OTP 做脱敏处理，但仍可能泄露内部架构和网络拓扑信息。 | I (信息泄露) | RequestSummary、Error 模型 | 低 |
| T-GOWSUNIFY-07 | 无限重连资源耗尽：当所有候选节点均不可达时，虽然 `reconnectRetryCount` 限制了单次重连轮数，但上层应用持续重试操作可能导致客户端持续消耗 CPU 和网络资源。 | D (拒绝服务) | unified.Client 重连机制 | 低 |

### 5. 安全需求与设计约束

| 威胁ID | **转化后的安全需求/设计约束** | **类型** | **优先级** |
| --- | --- | --- | --- |
| T-GOWSUNIFY-01 | SEC-GOWSUNIFY-001（凭据脱敏）：DSN 的 `String()` 方法和所有错误日志输出中必须对密码、Token、BearerToken、TOTP 等敏感字段进行脱敏处理，确保凭据不会以明文形式出现在任何日志或错误信息中。 | 安全功能需求 | 高 |
| T-GOWSUNIFY-02 | SEC-GOWSUNIFY-002（传输加密建议）：文档中应明确推荐生产环境使用 WSS 加密连接，并在 DSN 使用说明和最佳实践中标注安全警告。 | 安全文档需求 | 中 |
| T-GOWSUNIFY-03 | SEC-GOWSUNIFY-003（重连退避）：`reconnectIntervalMs` 已提供基本的重连间隔控制。建议在后续版本中考虑引入指数退避和随机抖动（jitter），以缓解大规模客户端同时重连的风暴效应。 | 健壮性需求 | 中 |
| T-GOWSUNIFY-04 | SEC-GOWSUNIFY-004（WSS 证书校验）：使用 WSS 连接时，应依赖 Go 标准库 `crypto/tls` 的默认证书校验机制，不应提供跳过证书校验的选项，以防止连接到恶意节点。 | 安全设计约束 | 中 |
| T-GOWSUNIFY-05 | SEC-GOWSUNIFY-005（并发安全）：Generation 机制和 reconnectLock 已在设计中实现，需在编码阶段确保正确实施，并通过并发测试验证。 | 安全设计约束 | 中 |
| T-GOWSUNIFY-06 | SEC-GOWSUNIFY-006（诊断信息最小化）：RequestSummary 应仅包含故障排查必需的信息，避免暴露完整的内部网络地址和架构细节。 | 安全设计约束 | 低 |
