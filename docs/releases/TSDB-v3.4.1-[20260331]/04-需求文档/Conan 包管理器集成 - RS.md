## 2. 引言

### 2.1 术语与缩写名词

- **Conan**：C/C++ 包管理器，用于管理依赖库和构建配置
- **ConanCenter**：Conan 官方包仓库
- **CMakeDeps**：Conan 生成器，用于生成 CMake 配置文件
- **CMakeToolchain**：Conan 生成器，用于生成 CMake 工具链配置
- **ExternalProject**：CMake 模块，用于下载和构建外部依赖
- **Recipe**：Conan 包配方，描述如何构建和打包依赖库

### 2.2 相关文档资料

- Conan 官方文档：https://docs.conan.io/

### 2.3 优先级要求

- **重要程度**：高 - 改善构建系统的可维护性和可靠性
- **期望交付时间**：2026 Q1

### 2.4 版本要求

- 适用于社区版和企业版
- 计划在 TDengine 3.4 版本中引入

## 3. 需求目标

### 3.1 背景

当前 TDengine 项目使用 CMake ExternalProject 模块管理第三方依赖库，存在以下问题：
1. **构建时间长**：每次需要从源码编译所有依赖库
2. **依赖管理复杂**：手动维护依赖版本和配置
3. **跨平台兼容性差**：不同平台需要不同的构建脚本
4. **缺乏依赖解析**：无法自动处理传递依赖关系
5. **构建环境不一致**：不同开发环境可能使用不同版本的依赖库

### 3.2 目标

通过集成 Conan 包管理器，实现以下目标：
1. **提高构建效率**：使用预编译二进制包，减少编译时间
2. **简化依赖管理**：统一管理所有第三方依赖的版本和配置
3. **改善跨平台支持**：利用 Conan 的跨平台能力
4. **增强可重现性**：确保所有环境使用相同版本的依赖库
5. **降低维护成本**：减少手动维护依赖库的工作量

## 4. 功能需求

| 序号 | 功能类别 | 功能名称 | 功能描述 |
| --- | --- | --- | --- |
| 1 | 包管理 | Conan 集成 | 在 CMake 构建系统中集成 Conan，支持自动安装和配置依赖包 |
| 2 | 包管理 | 依赖声明 | 在 conanfile.py 中声明所有第三方依赖及其版本 |
| 3 | 包管理 | 自定义包配方 | 为 ConanCenter 中不存在的依赖库创建自定义 Conan 包配方 |
| 4 | 构建系统 | CMake 适配 | 更新 CMake 配置文件以支持 Conan 生成的依赖配置 |
| 5 | 构建系统 | 构建选项 | 支持通过 Conan 选项控制依赖库的构建配置（静态/动态链接等） |
| 6 | 构建脚本 | build.sh 更新 | 更新构建脚本以支持 Conan 工作流 |
| 7 | 测试支持 | 测试依赖管理 | 通过 Conan 管理测试框架依赖（gtest, cppstub） |
| 8 | 文档 | 迁移文档 | 提供详细的迁移指南和使用文档 |

### 4.1 详细功能说明

#### 4.1.1 F1：核心依赖库迁移

迁移以下核心依赖库到 Conan：
- **压缩库**：zlib, lz4, xxhash, xz_utils, fast-lzma2
- **网络库**：openssl, libcurl, libuv
- **数据库**：rocksdb
- **JSON 解析**：cjson
- **测试框架**：gtest, cppstub
- **可选依赖**：jemalloc, sqlite3, geos, pcre2

#### 4.1.2 F2：自定义包配方

为 ConanCenter 中不存在的依赖创建自定义配方：
- **cppstub** (v1.0.0)：头文件库，用于单元测试桩
- **fast-lzma2** (v1.0.1)：快速 LZMA2 压缩库
- **avro-c** (v1.11.3)：Apache Avro C 库

#### 4.1.3 F3：构建选项支持

支持以下构建选项：
- `with_test`：是否构建测试
- `with_jemalloc`：是否使用 jemalloc 内存分配器
- `with_geos`：是否包含 GEOS 几何库
- `with_pcre2`：是否包含 PCRE2 正则表达式库
- `with_uv`：是否包含 libuv
- `with_sqlite`：是否包含 SQLite
- `with_s3`：是否包含 S3 支持
- `with_taos_tools`：是否构建 taos-tools

## 5. 性能需求

1. **构建时间**：首次构建时，Conan 安装依赖的时间应在 5 分钟以内
2. **增量构建**：依赖库已缓存时，配置时间应在 30 秒以内
3. **缓存效率**：Conan 缓存应支持多项目共享，减少磁盘占用

## 6. 安全需求

1. **包完整性**：验证从 ConanCenter 下载的包的完整性和签名
2. **依赖审计**：记录所有依赖包的来源和版本，支持安全审计
3. **私有依赖**：支持使用私有 Conan 仓库管理内部依赖
4. **锁文件**：生成依赖锁文件，确保构建的可重现性

## 7. 其他需求

### 7.1 兼容性需求

- **向后兼容**：保持现有 CMake 构建系统的接口不变，开发者无需修改已有代码
- **渐进迁移**：支持逐步迁移依赖库，ExternalProject 和 Conan 可共存
- **工具链兼容**：支持 GCC 9.3+, Clang, MSVC 等主流编译器

### 7.2 接口需求

- **CMake 宏**：保持现有的依赖注入宏接口（如 `DEP_ext_*`）
- **环境变量**：支持通过环境变量控制 Conan 行为
- **IDE 集成**：支持在 IDE 中使用 Conan 管理的依赖

### 7.3 运维需求

- **离线构建**：支持预下载所有依赖，实现完全离线构建
- **CI/CD 集成**：在 CI 流水线中集成 Conan，确保自动化构建正常工作
- **错误诊断**：提供清晰的错误信息，帮助用户快速定位问题

### 7.4 易用性需求

- **文档完善**：提供详细的安装、配置和使用文档
- **示例丰富**：提供常见场景的使用示例
- **迁移指南**：提供从 ExternalProject 迁移到 Conan 的详细步骤

### 7.5 测试需求

- **单元测试**：验证 Conan 包配方的正确性
- **集成测试**：验证整个构建流程的正确性
- **跨平台测试**：在 Linux, macOS, Windows 上进行测试
- **兼容性测试**：验证与现有构建系统的兼容性
