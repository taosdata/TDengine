## 2. 引言

### 2.1 术语与缩写名词

- **Session-based Authentication**: 基于会话的认证机制，使用 HttpOnly Cookie 存储会话标识
- **Basic Authentication**: HTTP 基本认证，通过 Authorization 头传递用户名和密码
- **XOR Encryption**: 异或加密算法，用于密码在传输前的时间限制加密
- **OAuth 2.0**: 开放授权标准，用于单点登录
- **HttpOnly Cookie**: 仅限 HTTP 访问的 Cookie，JavaScript 无法读取，提高安全性

## 3. 需求目标

### 3.1 背景

当前 TDengine Explorer 使用客户端可读取的 Cookie 存储认证 Token（Basic Auth），这存在以下安全风险：
1. JavaScript 可以读取和操作认证 Cookie，容易受到 XSS 攻击
2. 密码以明文形式从前端传输到后端
3. 认证状态完全依赖客户端存储，缺乏服务端会话管理
4. OAuth 和 Basic Auth 的认证方式不统一

### 3.2 目标

实现基于服务端会话的安全认证机制，达成以下目标：
1. 使用 HttpOnly Cookie 存储会话 ID，防止 XSS 攻击
2. 实现密码的时间限制加密传输，防止密码明文泄露
3. 统一 OAuth 和 Basic Auth 的会话管理机制
4. 提高整体系统的安全性

## 4. 功能需求

| 序号 | 功能类别 | 功能名称 | 功能描述 |
| --- | --- | --- | --- |
| 1 | 认证机制 | 基于会话的认证 | 用户登录成功后，服务端创建会话并返回 HttpOnly Cookie，后续请求通过会话验证身份 |
| 2 | 密码加密 | 时间限制 XOR 加密 | 前端使用时间戳和 XOR 算法加密密码，加密结果仅在 60 秒内有效，防止重放攻击 |
| 3 | 会话管理 | 统一会话管理器 | OAuth 和 Basic Auth 使用统一的 SessionManager 管理会话生命周期 |
| 4 | API 端点 | 用户信息和登出 | 提供 `/api/-/me` 和 `/api/-/logout` 端点，支持 OAuth 和 Basic Auth |
| 5 | 前端集成 | 会话状态管理 | 前端使用 session_id Cookie 管理登录状态，移除客户端 Token 管理逻辑 |

## 5. 性能需求

- **会话创建**: 会话创建和验证操作应在 100ms 内完成
- **加密解密**: 密码加密解密操作应在 10ms 内完成
- **数据库查询**: 会话验证的数据库查询应优化索引，保持低延迟
- **内存占用**: 会话数据应合理使用内存，避免内存泄漏

## 6. 安全需求

1. **Cookie 安全性**
  - 使用 HttpOnly 标记，防止 JavaScript 访问
  - 使用 SameSite=Lax 属性，防止 CSRF 攻击
  - 设置合理的过期时间（1 小时）
1. **密码传输安全**
  - 密码在前端使用时间限制 XOR 加密
  - 加密密钥混合固定密钥和时间戳
  - 加密数据仅在 60 秒内有效，防止重放攻击
1. **会话管理**
  - 服务端验证会话有效性
  - 支持会话过期和登出
  - 敏感操作需验证会话权限
1. **密钥管理**
  - 对硬编码密钥进行混淆
  - 密钥不应明文存储在代码中
