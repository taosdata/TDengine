## 3. 需求目标

taosgen 是时序数据产品的性能基准测试工具，功能强大但配置复杂，涉及多个目标系统（TDengine、MQTT、Kafka）的复杂 YAML 配置。本需求旨在为 Claude Code 等 AI Agent 开发专用 Skill，实现：
1. **配置生成智能化**: 根据用户提供的简单参数（目标系统类型、数据规模、测试场景等），自动生成符合官方文档规范的 YAML 配置文件
2. **文档双源策略**: 优先使用 WebFetch 获取官方最新文档，失败时使用本地参考文档作为 fallback
3. **配置验证机制**: 通过临时运行测试验证配置有效性（安全检测）
4. **多目标系统支持**: 统一支持 TDengine 数据库写入、MQTT 消息发布、Kafka 消息生产三种场景
5. **最佳实践指导**: 根据性能目标（吞吐量优先/低延迟优先/可靠性优先）提供配置建议
**目标用户**:
- 需要使用时序数据库性能测试工具的开发者
- 进行 IoT 场景消息流测试的测试工程师
- 需要快速生成基准测试配置的 DevOps 人员

## 5. 性能需求

1. **文档获取响应时间**: WebFetch 获取官方文档应在 10 秒内完成；本地文档读取应在 1 秒内完成
2. **配置生成响应时间**: 简单配置（<100 行 YAML）应在 10 秒内完成；复杂配置（>500 行）应在 60 秒内完成
3. **配置验证时间**: 临时测试验证应在 15 秒内完成（包含配置创建、运行、清理）
4. **支持的最大配置规模**: 单配置文件支持生成不超过 1000 行 YAML
5. **并发处理能力**: 支持同时处理多个目标系统的配置生成请求（TDengine + MQTT + Kafka 并行）

## 6. 安全需求

### 6.1 敏感信息处理

1. **密码保护**: 数据库密码、Kafka SASL 密码、MQTT 密码等敏感信息不应在日志中明文记录
2. **密码输入建议**: Skill 应建议用户通过交互式输入提供密码，而非硬编码在配置文件中

### 6.2 配置安全

1. **风险提示**: 涉及数据删除的配置（如 `drop_if_exists: true`）必须明确提示风险并要求用户确认
2. **安全协议默认**: MQTT 和 Kafka 配置应优先推荐使用安全协议（SSL/TLS、SASL_SSL）
3. **命令安全**: 生成的命令不应包含任何破坏性 shell 操作

### 6.3 审计追溯

1. **配置版本标记**: 生成的配置应包含注释说明生成时间和 Skill 版本
2. **变更记录**: 支持用户追溯配置的历史修改版本

## 7. 其他需求

### 7.1 兼容性需求

1. **taosgen 版本兼容**: 支持 taosgen v0.8.0 及以上版本
2. **操作系统兼容**: 支持 Linux 和 macOS 系统（与 taosgen 支持的平台一致）
3. **TDengine 版本兼容**: 生成的配置应兼容 TDengine 3.x 版本
4. **Kafka 版本兼容**: 支持 Kafka 2.x 及以上版本（通过 librdkafka 兼容性实现）
5. **MQTT 版本兼容**: 支持 MQTT 3.1.1 和 MQTT 5.0 协议

### 7.2 接口需求

1. **Skill 输入接口**:
  - 自然语言描述（如"创建一个测试 10000 个智能电表的 TDengine 配置"）
  - 结构化参数（目标系统、表数量、行数量、并发数等）
1. **Skill 输出接口**:
  - 配置文件绝对路径（`OutputPath: /absolute/path/to/file`）
  - 配置摘要说明
  - 运行命令示例
  - 关键参数解释
  - 验证状态（是否通过临时测试）

### 7.3 运维需求

1. **配置管理**: 生成的配置文件应存储在用户指定目录或当前目录下
2. **日志输出**: 清晰展示配置生成步骤和验证过程

### 7.4 易用性需求

1. **智能默认值**: 为目标系统提供合理的默认参数（如默认并发数、批次大小）
2. **场景模板**: 对常见场景提供快速配置（智能电表、服务器监控、传感器网络等）
3. **渐进式配置**: 支持从简单配置开始，逐步添加高级参数
4. **错误提示友好**: 配置错误时提供清晰的错误说明和修复建议
5. **最佳实践指导**: 根据用户性能目标自动推荐最佳实践配置

### 7.5 测试需求（不含测试例）

1. **配置语法验证**: 生成的 YAML 配置必须通过 taosgen 的本地验证（通过临时运行测试）
2. **参考文档完整性**: 本地 reference 文档必须覆盖所有主要配置参数
3. **文档一致性**: 本地 reference 文档应与官方文档保持一致（参数名称、默认值、描述）
4. **示例可运行性**: 所有参考文档中的示例配置应可通过临时测试验证
