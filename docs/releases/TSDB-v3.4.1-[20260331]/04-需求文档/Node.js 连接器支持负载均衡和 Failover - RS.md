## 2. 引言

### 2.1 术语与缩写名词

- 故障转移（Failover）：当主节点或服务不可用时，自动切换到备用节点或服务的机制。
- 负载均衡（Load Balancing）：将请求或工作负载分配到多个服务器或资源上的技术，以优化资源使用、最大化吞吐量、最小化响应时间。
- 服务端点（Endpoint）：包含主机名和端口的连接目标。
- 最少连接（Least Connections）：优先选择当前活跃连接数最少的节点。

## 3. 需求目标

### 3.1 背景

当前 Node.js 连接器在与 taosAdapter 通信时，缺乏自动的负载均衡和故障转移能力。当配置的 taosAdapter 节点发生故障时，连接会中断，需要用户手动处理重连或切换节点。这在生产环境中会导致服务不可用，影响业务连续性。

### 3.2 目标

1. 多地址支持：支持在 DSN 中配置多个 taosAdapter 地址。
2. 负载均衡支持：首次连接与切换地址时采用最少连接策略，连接数相同节点随机打散。
3. Failover 支持：网络异常时自动重连，重试耗尽后自动切换到其他地址。
4. 会话恢复：重连成功后自动恢复 SQL/TMQ/STMT2 所需会话上下文。
5. 可配置性：通过 DSN 参数配置重试次数和指数退避。
6. 向后兼容：单地址配置行为与历史版本保持一致。

## 4. 功能需求

| 序号 | **功能类别** | **功能名称**    | 功能描述                                                        |
| ---- | ------------ | --------------- | --------------------------------------------------------------- |
| 1    | 地址解析     | 多地址 DSN 解析 | 支持 `host1:port1,host2:port2,[::1]:port3` 形式地址列表。       |
| 2    | 负载均衡     | 最少连接选址    | 首次连接与地址切换均以全局活跃连接数最少地址为优先。            |
| 3    | 负载均衡     | 平局随机打散    | 当多个地址连接数相同，随机选择其中一个地址。                    |
| 4    | Failover     | 异常检测        | 识别连接关闭、连接不可用和典型网络错误码/错误信息触发重连。     |
| 5    | Failover     | 地址内重试      | 每个地址按 `retries` 次数重试，重试间隔按指数退避并受上限控制。 |

## 5. 性能需求

1. 重连退避：默认参数为 `retries=5`、`retry_backoff_ms=200`、`retry_backoff_max_ms=2000`。
2. 退避函数：第 `n` 次等待时延为 `min(retry_backoff_ms * 2^n, retry_backoff_max_ms)`。
3. 参数容错：非法或越界重试参数必须回退到默认值，保证可用性。
4. 连接复用：连接池与最少连接统计共同工作，不引入额外的同步阻塞点。

## 6. 安全需求

1. 认证信息保持：Failover 切换后，新连接应使用相同的认证信息（用户名、密码、Token）。
2. TLS 支持：所有节点连接支持 wss:// 协议，加密传输数据。
3. 敏感信息保护：日志与连接池键中不得明文暴露 password/token/bearer_token。

## 7. 其他需求

### 7.1 兼容性需求

- 向后兼容：单节点配置应保持现有行为不变
- 协议兼容：与现有 WebSocket 通信协议兼容
- 版本兼容：支持与不同版本的 taosAdapter 节点通信

### 7.2 接口需求

- 配置接口：扩展现有连接配置接口，支持多节点配置
- 配置参数：支持 `retries`、`retry_backoff_ms`、`retry_backoff_max_ms`

### 7.3 运维需求

- 日志记录：记录节点切换、连接失败等关键事件
- 可观测事件：记录重连开始、重连成功、切换地址、重放请求中断等事件

### 7.4 易用性需求

- 配置简洁：多节点配置应简单直观，易于理解和使用
- 错误清晰：故障切换失败时，错误信息应清晰明确，便于排查问题
- 文档完善：提供完整的使用文档和示例代码

### 7.5 测试需求（不含测试例）

- 单元测试：覆盖地址选择、重连锁、重试参数解析、请求重放顺序。
- 集成测试：覆盖 SQL、STMT2、TMQ 在单地址和多地址下的 failover。
- 故障注入测试：覆盖代理重启、短暂断网、重连中再次断连、随机抖动场景。
