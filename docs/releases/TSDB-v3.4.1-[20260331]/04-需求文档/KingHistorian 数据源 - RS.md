## 2. 引言

### 2.1 术语与缩写名词

- KH：KingHistorian（亚控实时库）
- 点位/测点：KH 中的数据变量（tag）
- 历史迁移：按时间范围批量同步历史数据到 TDengine
- 实时同步：订阅/轮询方式持续同步实时数据
- 超级表（STable）：TDengine 超级表
- 子表（Table）：TDengine 子表
- 通配符过滤：`*`（任意长度）与 `?`（单字符）

## 3. 需求目标

为 KingHistorian 采集器提供“按点位规则过滤 + 自动更新点位”的能力，覆盖历史迁移与实时同步场景，实现：
1. 基于通配符按规则选择点位；
2. 支持新增点位的周期性发现与自动纳入任务；
3. 保障历史与实时链路的数据完整性与可运维性；
4. 提升历史迁移吞吐，缩短迁移总时长。

## 4. 功能需求

### 4.1 点位过滤与映射配置（历史/实时共用）

1. 点名称支持 `*`、`?` 过滤（与 KH 语义一致）。
2. 支持配置超级表名称，支持占位符 `{type}`。
3. 支持配置子表名称，支持占位符 `{tag_name}`。
4. 主键列默认 `datatime`，支持主键别名配置。
5. 支持“查看点位列表”，分页展示命中规则的点位集合。

### 4.2 历史迁移增强

1. 新增“选择数据点位”功能区域。
2. 支持配置开始时间、结束时间（不填默认任务创建时间）。
3. 支持查询窗口、查询时间间隔（ms）、乱序写入开关（默认 0）。
4. 点位元数据存储至少包含以下 8 个属性：
  - 变量名
  - 变量类型
  - 变量数据长度
  - 变量描述
  - 上次修改变量配置时间
  - 上次修改变量配置用户
  - 变量组名称
  - 变量组路径

### 4.3 实时同步增强

1. 支持按规则订阅实时点位。
2. 新增“点位更新模式”：`none` / `append`。
3. 新增“点位更新时间”：按周期拉取 KH 新增点位并按规则筛选。
4. `append` 模式下，符合规则的新增点位自动加入当前任务。
5. 新增点位筛选依赖亚控后续提供过滤接口。

### 4.4 历史迁移并行策略优化

1. 现状：不同数据类型共享一个 job，同步耗时差异明显，慢类型拖慢整体进度。
2. 需求：支持按不同数据类型配置独立 job 线程数（并发度）。
3. 目标：显著降低历史迁移总时长。

## 5. 性能需求

1. 大规模点位下，点位列表查询需支持分页与稳定响应。
2. 实时更新周期触发时，不应显著影响实时写入链路稳定性。
3. 历史迁移并发优化后，整体耗时需明显下降（以压测基线对比验证）。
4. 查询窗口与查询间隔应可调，以控制 KH 侧接口压力。

## 6. 安全需求

1. KH 与目标端连接凭据需安全存储与传输（加密/脱敏）。
2. 配置与任务变更需具备可审计性（操作者、时间、变更内容）。
3. 对非法配置输入进行校验，避免异常放大。
4. 点位元数据同步遵循最小必要原则，避免非必要敏感信息扩散。

## 7. 其他需求

### 7.1 兼容性需求

- 兼容 KH 原有通配符语义。
- 对已存在任务配置保持向后兼容。

### 7.2 接口需求

- 依赖亚控提供按时间/条件筛选新增点位能力。
- 需明确接口超时、重试、分页和错误码约定。

### 7.3 运维需求

- 提供任务级监控：同步速率、延迟、失败重试、点位增量统计。
- 支持任务运行状态与异常告警。

### 7.4 易用性需求

- 配置项文案清晰，关键字段提供默认值与帮助提示。
- 点位预览列表支持快速验证过滤规则。

### 7.5 测试需求（不含测试例）

- 覆盖历史/实时主流程、`none/append` 模式、周期更新、异常接口返回。
- 覆盖大规模点位和多数据类型并行迁移的性能回归。
- 覆盖占位符映射和元数据字段完整性校验。
