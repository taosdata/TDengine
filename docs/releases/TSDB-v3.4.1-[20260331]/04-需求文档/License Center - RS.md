## 2. 引言

### 2.1 术语与缩写名词

| 缩写 | 全称 | 说明 |
| --- | --- | --- |
| **ELS** | Enterprise License Server | 中心侧授权服务，运行在 TDengine 服务商侧，负责授权的统一发放、更新、查看和撤销 |
| **CLS** | Customer License Server | 客户侧授权服务，运行在客户环境，作为授权代理管理客户本地的所有 TSDB/IDMP 集群 |
| **TSDB** | TDengine | TDengine 时序数据库实例 |
| **IDMP** | Industrial Data Management Platform | 工业数据管理平台实例 |
| **DATAIN** | TDengine Data Connector | TDengine 数据连接器实例，其授权集成在 TSDB 授权中 |
| **许可证** | License | ELS 签发的授权凭证，包含 TSDB（含 DATAIN）、IDMP 两类授权项；每个 CLS 可持有多个许可证 |
| **许可证 ID** | License ID | 许可证的唯一标识符，由 ELS 分配 |
| **授权项** | Grant Item | 许可证中包含的具体授权维度，如测试点数、CPU 核数、有效期、集群个数等 |
| **槽位** | Slot | CLS 中为每个许可证按授权集群数自动创建的集群绑定位，集群先到先得占据槽位 |
| **CLS 认证字符串** | CLS Auth String | CLS 初始化时生成的身份信息，包含公钥、CLS_ID、机器码等，用于在 ELS 注册 |
| **机器码** | Machine ID | CLS 实例的唯一硬件指纹，包含在 CLS 认证字符串中 |
| **宽限期** | Grace Period | License 失效后仍可正常工作的缓冲时间，默认 14 天 |
| **授权来源** | License Source | IDMP 获取授权的途径，可选 CLS 或 TSDB，二选一互斥 |

## 3. 需求目标

### 3.1 现状问题

当前 TDengine 和 IDMP 的授权管理存在以下问题：

1. **分散管理**：每个实例独立配置 License，无法统一管理多实例、多集群授权
2. **授权更新复杂**：需要逐个实例手动更新 License 文件，运维成本高
3. **缺乏可见性**：无法集中查看所有客户、所有集群的授权状态和使用情况
4. **离线场景支持不足**：内网或离线环境下授权管理困难，缺乏机器码绑定等安全机制
5. **安全风险**：缺乏对非法实例的管控机制
6. **授权粒度不足**：无法按公司、按 CLS 进行灵活的许可证配置
7. **多组件授权割裂**：IDMP 依赖 TSDB 的授权信息，缺乏独立的授权来源配置

### 3.2 建设目标

构建**中心化授权管理系统（License Center）**，包含中心侧 Enterprise License Server（ELS）和客户侧 Customer License Server（CLS），实现：

- **统一管理**：ELS 支持按公司管理，每个公司可拥有多个 CLS，每个 CLS 可持有多个许可证
- **槽位机制**：每个许可证按授权的集群数自动创建槽位，集群先到先得占据槽位；累加型授权项默认均分到各槽位，客户可手动调整
- **授权项语义明确**：授权项分为"累加型"（如测试点数，各集群预分配配额总和不超过许可证上限）和"上界约束型"（如授权有效期，所有集群统一受限）
- **在线 + 离线**：CLS 可在线从 ELS 自动刷新许可证，也可离线导入许可证字符串
- **ELS-CLS 同步**：许可证 ID 由 ELS 分配不可修改，CLS 仅可为许可证和集群添加本地名称
- **多组件支持**：每个许可证包含 TSDB（含 DATAIN）、IDMP 两类授权，各组件只读取与自身相关的授权项
- **IDMP 双来源**：IDMP 支持从 CLS 或从 TSDB 获取授权（二选一互斥），通过配置选择授权来源

**流程说明**：

1. **交付人员在 ELS 创建客户信息**：提供公司名称等基本信息，ELS 生成客户 ID
2. **客户部署 CLS**：安装 CLS 后，通过页面或 CLI 输入离线方式获取的客户 ID 和 ELS 地址；CLS 自动生成 **CLS 认证字符串**（包含公钥、CLS_ID、机器码等），客户将认证字符串离线提供给交付人员
3. **交付人员录入 CLS 认证字符串**：在 ELS 中录入认证字符串，完成 CLS 注册，然后创建许可证
4. **许可证分发**：
   - **在线模式**：CLS 与 ELS 可通信时，CLS 自动定期刷新许可证
   - **离线模式**：CLS 与 ELS 无法通信时，交付人员在 ELS 生成离线许可证字符串，通过邮件/U盘等方式交给客户导入

### 4.7 许可证授权模型

#### 4.7.1 许可证内容结构

每个许可证包含两类授权：

| 授权类别 | 授权项 | 说明 |
| --- | --- | --- |
| **TSDB 授权（含 DATAIN）** | tsdb_clusters（TSDB 集群数） | 该许可证允许运行的 TSDB 集群个数，决定 TSDB 槽位数 |
| | timeseries, dnodes, cpu_cores, vnodes, storage_size, streams, subscriptions | 累加型资源授权项 |
| | service_expire | 上界约束型，授权有效期 |
| | audit, data_sync, backup_restore | 开关型，功能模块 |
| | datain_enabled | 开关型，是否启用 DATAIN 数据连接器 |
| **IDMP 授权** | idmp_clusters（IDMP 集群数） | 该许可证允许运行的 IDMP 集群个数，决定 IDMP 槽位数 |
| | idmp_nodes, idmp_points | 累加型资源授权项 |
| | idmp_features | 开关型，功能模块 |

#### 4.7.2 授权项分类

| 分类 | 名称 | 语义 | 示例 |
| --- | --- | --- | --- |
| **累加型** (Additive) | 资源配额类 | 各槽位预分配配额之和不超过许可证总量 | timeseries、cpu_cores、dnodes、vnodes、storage_size、streams、subscriptions、idmp_nodes、idmp_points |
| **上界约束型** (Capped) | 约束类 | 所有集群统一受限于同一约束值 | 授权有效期（service_expire） |
| **开关型** (Toggle) | 功能模块类 | 有/无，全局统一 | audit、data_sync、backup_restore、idmp_features |

#### 4.7.3 槽位机制详解

**槽位创建**：

- 每个许可证的 `tsdb_clusters=N` 自动创建 N 个 TSDB 槽位
- 每个许可证的 `idmp_clusters=M` 自动创建 M 个 IDMP 槽位

**默认分配**：

- 累加型授权项默认均分到各槽位
- 例：许可证总量 timeseries=1,000,000，tsdb_clusters=2 → 每个 TSDB 槽位默认分配 500,000

**集群绑定**：

- TSDB 集群配置许可证 ID 和 CLS 地址后，向 CLS 注册，**先到先得**占据一个 TSDB 槽位
- IDMP 集群同理

**示例**：

```
许可证 A（tsdb_clusters=2, timeseries=1,000,000, cpu_cores=128）

  TSDB 槽位 1（默认均分）        TSDB 槽位 2（默认均分）
  ┌─────────────────────┐      ┌─────────────────────┐
  │ timeseries: 500,000 │      │ timeseries: 500,000 │
  │ cpu_cores:  64      │      │ cpu_cores:  64      │
  │                     │      │                     │
  │ → 集群 1 已绑定     │      │ → 集群 2 已绑定     │
  └─────────────────────┘      └─────────────────────┘

  客户手动调整后：
  ┌─────────────────────┐      ┌─────────────────────┐
  │ timeseries: 700,000 │      │ timeseries: 300,000 │
  │ cpu_cores:  80      │      │ cpu_cores:  48      │
  │                     │      │                     │
  │ → 集群 1 已绑定     │      │ → 集群 2 已绑定     │
  └─────────────────────┘      └─────────────────────┘
  总和: 1,000,000 ≤ 1,000,000 ✅   总和: 128 ≤ 128 ✅
```

**槽位满时**：

- 当所有 TSDB 槽位已被占满，新的 TSDB 集群尝试注册时，CLS 拒绝并提示"槽位已满"
- 需要在 ELS 更新许可证的 `tsdb_clusters` 值，增加槽位数后 CLS 同步，新集群才可注册

**集群删除**：

- 客户可删除某个已授权集群，释放其槽位
- 被删除的集群加入黑名单，无法再占据槽位

### 4.8 TSDB 组件接入详细流程

```
TSDB 实例                                    CLS
    │                                         │
    │ 1. SQL: 配置 CLS 连接参数和许可证 ID       │
    │    ALTER LOCAL 'cls_enabled' '1';         │
    │    ALTER LOCAL 'cls_url'                   │
    │      'http://192.168.1.100:7443';        │
    │    ALTER LOCAL 'cls_license_id'           │
    │      'lic-abc123';                       │
    │    ALTER LOCAL 'cls_refresh_interval'     │
    │      '3600';                             │
    │                                         │
    │ 2. 向 CLS 注册，先到先得占据 TSDB 槽位     │
    │─────── 注册请求（许可证ID+集群信息）────>│
    │<────── 返回槽位分配结果 ────────────────│
    │                                         │
    │ 3. 从 CLS 读取 TSDB 相关授权项             │
    │─────── 请求 TSDB 授权 ─────────────────>│
    │<────── 返回 TSDB 授权项（按槽位配额）───│
    │        （仅 TSDB 相关，忽略 IDMP 授权项）  │
    │                                         │
    │ 4. 持久化授权信息到本地存储                  │
    │                                         │
    │ 5. 按配置的读取频率定期刷新                  │
    │─────── 定期刷新 ───────────────────────>│
    │<────── 返回最新授权 ───────────────────│
```

**TSDB 配置方式**：通过 ALTER LOCAL 语句配置，无需修改配置文件重启：

```sql
-- 是否启用 CLS（0=禁用，1=启用，默认 0）
ALTER LOCAL 'cls_enabled' '1';

-- 配置 CLS 服务地址（包括端口号）
ALTER LOCAL 'cls_url' 'http://192.168.1.100:7443';

-- 配置许可证 ID
ALTER LOCAL 'cls_license_id' 'lic-abc123';

-- 配置读取频率（秒）
ALTER LOCAL 'cls_refresh_interval' '3600';
```

| 配置项 | 说明 | 默认值 |
| --- | --- | --- |
| cls_enabled | 是否启用 CLS 授权模式 | 0（禁用） |
| cls_url | CLS 服务地址（IP/域名 + 端口号） | 空 |
| cls_license_id | 许可证 ID，用于绑定到指定许可证的 TSDB 槽位 | 空 |
| cls_refresh_interval | 授权信息读取频率（秒） | 3600 |

**TSDB Explorer 页面改造**：
- 在已有授权管理页面增加配置区域：
  - 是否启用 CLS（开关）
  - CLS 服务地址（IP/域名 + 端口号）
  - 许可证 ID
  - 读取频率（秒）
  - 连接状态显示（已连接/断开/未配置）
  - 槽位绑定状态（已绑定/未绑定/槽位已满）
  - "手动刷新"按钮
- 原有授权项显示不变（`show grants full` 结果展示）

| timeseries | TSDB | 仅 TSDB 读取 |
| dnodes | TSDB | 仅 TSDB 读取 |
| cpu_cores | TSDB | 仅 TSDB 读取 |
| vnodes | TSDB | 仅 TSDB 读取 |
| storage_size | TSDB | 仅 TSDB 读取 |
| streams | TSDB | 仅 TSDB 读取 |
| subscriptions | TSDB | 仅 TSDB 读取 |
| audit | TSDB | 仅 TSDB 读取 |
| data_sync | TSDB | 仅 TSDB 读取 |
| backup_restore | TSDB | 仅 TSDB 读取 |
| idmp_clusters | IDMP | IDMP 集群个数上限（决定 IDMP 槽位数） |
| idmp_nodes | IDMP | 仅 IDMP 读取 |
| idmp_points | IDMP | 仅 IDMP 读取 |
| idmp_features | IDMP | 仅 IDMP 读取 |

## 5. 通信需求

| 序号 | 功能名称 | 描述 |
| --- | --- | --- |
| 1 | ELS ↔ CLS 安全通信 | 加密传输，支持 TLS 1.3 或更高版本 |
| 2 | CLS ↔ 实例安全通信 | TSDB/IDMP 与 CLS 之间建立加密通信通道 |
| 3 | 身份认证 | CLS 向 ELS 认证：基于 CLS 认证字符串中的公钥（Ed25519）；实例向 CLS 认证：基于许可证 ID 绑定 |
| 4 | 授权数据签名 | 许可证数据必须签名，防止篡改 |
| 5 | CLS 拉取模式 | CLS 按配置频率主动从 ELS 拉取许可证更新（Pull 模式） |
| 6 | CLS 向实例推送 | CLS 获取许可证更新后，主动向已注册的 TSDB/IDMP 实例推送授权变更；实例也可按配置频率主动拉取 |

## 6. 审计与监控需求

| 序号 | 功能名称 | 描述 |
| --- | --- | --- |
| 1 | ELS 操作审计 | 记录所有敏感操作（客户创建、CLS 注册、许可证创建/修改/撤销、黑名单变更），包含操作人、时间、对象、结果 |
| 2 | CLS 操作审计 | 记录许可证导入/刷新、槽位配额调整、集群删除/拉黑等操作，包含操作人、时间、对象、结果 |
| 3 | 审计日志保留 | 审计日志保留至少 1 年 |
| 4 | 授权使用监控 | CLS 实时汇聚各许可证下各槽位的授权资源使用情况，与许可证总量和槽位配额对比 |
| 5 | ELS 全局监控 | ELS 可查看所有公司、所有 CLS 的授权状态、到期时间、资源使用率 |
| 6 | 告警 | 授权即将到期（30 天提醒）、槽位资源使用率超阈值、CLS 连接异常等场景触发告警 |
| 7 | 监控指标导出 | 提供 Prometheus 格式的 metrics 供外部监控系统采集 |

## 7. 性能需求

1. **授权验证性能**：TSDB/IDMP 实例启动时的授权验证应在 1 秒内完成
2. **授权同步延迟**：ELS 侧许可证更新后，CLS 下次拉取时应在 10 秒内完成同步（网络正常情况）
3. **CLS 到实例延迟**：CLS 许可证更新后，应在 5 秒内分发到所管理的实例
4. **并发管理能力**：
   - ELS 应支持管理至少 10,000 个 CLS 实例
   - 每个 CLS 应支持管理至少 100 个集群（含 TSDB 和 IDMP）
5. **离线许可证生成**：离线许可证字符串生成应在 1 秒内完成
6. **状态查询响应**：授权状态查询（含所有集群）应在 3 秒内返回结果
7. **TSDB/IDMP 定期读取**：按配置的读取频率从 CLS 拉取授权，单次请求响应时间 < 500ms

## 8. 安全需求

1. **通信安全**：
   - ELS 与 CLS 之间、CLS 与 TSDB/IDMP 之间的所有通信必须加密传输
   - 支持 TLS 1.3 或更高版本
2. **身份认证**：
   - CLS 向 ELS 认证：基于 CLS 认证字符串中的非对称密钥对（建议 Ed25519）
   - TSDB/IDMP 向 CLS 认证：基于许可证 ID 绑定
3. **离线许可证安全**：
   - 离线许可证字符串必须绑定 CLS 机器码（包含在 CLS 认证字符串中），防止许可证被复制到其他机器使用
   - 许可证必须包含数字签名和有效期
4. **授权完整性**：许可证数据必须签名，防止篡改
5. **权限控制**：
   - 实例侧的参数配置仅限安全员角色执行
   - ELS 侧的许可证撤销操作需要管理员权限
6. **审计要求**：所有敏感操作必须记录审计日志，保留至少 1 年
7. **黑名单机制**：
   - CLS 级黑名单：ELS 维护，防止被撤销的客户继续使用
   - 集群级黑名单：CLS 维护，被删除的集群无法再占据槽位

## 9. 其他需求

### 9.1 兼容性需求

- **向后兼容**：现有单机 License 文件机制应继续支持，作为降级方案
- **平滑升级**：支持从单机 License 模式迁移到 License Center 模式
- **多版本支持**：ELS 应兼容不同版本的 TSDB/IDMP 实例
- **IDMP 兼容**：IDMP 从 TSDB 读取授权的原有逻辑保留，新增 CLS 作为可选授权来源（二选一互斥）

### 9.2 接口需求

- **ELS 管理接口**：RESTful API，用于客户管理、CLS 注册、许可证创建和撤销
- **CLS 对外接口**：供 TSDB/IDMP 调用的授权查询和槽位注册接口（REST 或 gRPC）
- **CRM 集成接口**：（未来版本）用于查询客户合同和订单信息
- **管理界面**：ELS 和 CLS 均提供 Web UI 或 CLI 工具

### 9.3 运维需求

- **部署方式**：
  - ELS：支持容器化部署（Docker/K8s）
  - CLS：支持二进制、Docker、系统服务等多种部署方式
- **高可用**：ELS 应支持多副本部署，保证服务可用性
- **数据备份**：ELS 和 CLS 的数据均需支持备份和恢复
- **日志管理**：结构化日志输出，支持日志级别配置和轮转
- **配置管理**：支持配置文件和环境变量两种方式

### 9.4 易用性需求

- **TSDB 配置简单**：通过 ALTER LOCAL 语句即可完成 CLS 配置（含许可证 ID），无需修改配置文件重启
- **IDMP 配置直观**：在 IDMP 授权页面通过 UI 选择授权来源并配置（含许可证 ID），操作直观
- **槽位管理直观**：CLS 提供清晰的槽位可视化，展示各槽位的占用状态、绑定集群和配额分配
- **错误提示**：授权失败、槽位已满、连通性失败时提供明确的错误信息和解决建议
- **文档完善**：提供部署文档、API 文档、故障排查手册
