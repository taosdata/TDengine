## 2. 引言

### 2.1 术语与缩写名词

- **License Center**：授权中心系统，包含中心侧和客户侧两个组件
- **中心侧授权服务（Central License Server, CLS）**：运行在 TDengine 服务商侧的授权管理服务
- **客户侧授权服务（Customer License Server, CULS）**：运行在客户环境的授权代理服务
- **TSDB**：TDengine 时序数据库实例
- **IDMP**：Industrial Data Management Platform，工业数据管理平台实例
- **License ID**：授权证书的唯一标识符
- **Instance ID**：TSDB/IDMP 实例的唯一标识符
- **离线授权码**：用于离线环境的授权凭证，包含有效期信息
- **宽限期**：License 失效后仍可正常工作的缓冲时间，默认 2 周

## 3. 需求目标

当前 TDengine 和 IDMP 的授权管理存在以下问题：
1. **分散管理**：每个实例独立配置 License，无法统一管理多实例授权
2. **授权更新复杂**：需要逐个实例手动更新 License 文件，运维成本高
3. **缺乏可见性**：无法集中查看所有实例的授权状态和使用情况
4. **离线场景支持不足**：内网或离线环境下授权管理困难
5. **安全风险**：缺乏对非法实例的管控机制
本需求旨在构建独立于 TSDB 的**中心化授权管理系统**，实现：
- 统一的授权发放、更新、查看和撤销
- 多实例集中管理和监控
- 离线环境支持
- 黑名单机制防止非法使用
- 与 CRM 系统集成实现自动化授权流程

## 4. 功能需求

| 序号 | 功能类别 | 功能名称 | 功能描述 |
| --- | --- | --- | --- |
| 1 | 中心侧授权服务 | 授权发放 | 中心侧可为客户创建和发放 License，支持在线推送和离线授权码生成 |
| 2 | 中心侧授权服务 | 授权查看 | 中心侧可查看所有客户的授权状态、实例使用情况、License 剩余量等 |
| 3 | 中心侧授权服务 | 授权撤销 | 中心侧可撤销指定客户或实例的授权，将其加入黑名单 |
| 4 | 中心侧授权服务 | CRM 集成 | 与 CRM 系统对接，查询客户合同信息，研究自动发放 License 机制 |
| 5 | 中心侧授权服务 | 黑名单管理 | 维护客户侧授权服务（CULS）的黑名单，被列入黑名单的 CULS 无法获取授权 |
| 6 | 客户侧授权服务 | 授权接收 | 从中心侧接收在线推送的 License 或导入离线授权码 |
| 7 | 客户侧授权服务 | 授权更新 | 自动或手动更新 License，并向所有注册实例分发最新授权 |
| 8 | 客户侧授权服务 | 授权解除 | 执行 `drop license` 命令，将当前 License ID 加入黑名单并上报中心侧 |
| 9 | 客户侧授权服务 | 授权状态查看 | 查看当前管理的所有 TSDB/IDMP 实例的授权状态和资源使用情况 |
| 10 | 客户侧授权服务 | 实例注册管理 | TSDB/IDMP 实例向 CULS 注册，CULS 集中管理所有实例的授权 |
| 11 | 客户侧授权服务 | 实例黑名单 | 维护实例级黑名单，阻止非法 Instance ID 获取授权 |
| 12 | 客户侧授权服务 | 离线运行支持 | 使用离线授权码在无网络环境下独立运行，授权有效期由离线码决定 |
| 13 | 实例侧改造 | License Server 认证 | TSDB/IDMP 实例验证 CULS 的身份（基于密钥对），拒绝黑名单中的 CULS |
| 14 | 实例侧改造 | 宽限期机制 | License 失效或无法连接 CULS 时，仍可全功能运行 2 周 |
| 15 | 实例侧改造 | drop license 命令 | 仅安全员角色可执行，执行后将当前 License ID 加入黑名单 |
| 16 | 通信层 | 安全通信 | CLS 与 CULS、CULS 与实例之间建立加密通信通道 |
| 17 | 通信层 | 主动推送机制 | 中心侧可主动向客户侧推送授权更新，客户侧可主动向实例推送授权 |
| 18 | 审计与监控 | 操作审计日志 | 记录所有敏感操作（授权发放/撤销/解除等），包含操作人、时间、对象 |
| 19 | 审计与监控 | 授权使用监控 | 实时监控各实例的授权资源使用情况（timeseries、cpu_cores 等） |
| 20 | 授权维度支持 | 多维度授权 | 支持 `show grants full` 中的所有维度：时间、timeseries、dnodes、cpu_cores、vnodes、storage_size、功能模块等 |

## 5. 性能需求

1. **授权验证性能**：实例启动时的授权验证应在 1 秒内完成
2. **授权更新延迟**：中心侧发起的授权更新应在 10 秒内到达客户侧（网络正常情况）
3. **并发管理能力**：
  - 中心侧应支持管理至少 10,000 个客户侧授权服务
  - 客户侧应支持管理至少 1,000 个 TSDB/IDMP 实例
1. **离线授权码生成**：离线授权码生成应在 1 秒内完成
2. **状态查询响应**：授权状态查询（包含所有实例）应在 3 秒内返回结果

## 6. 安全需求

1. **通信安全**：
  - 所有网络通信必须使用加密传输
  - 支持 TLS 1.3 或更高版本的加密标准
1. **身份认证**:
  - CULS 向 CLS 认证：基于非对称密钥对（建议 Ed25519）
  - 实例向 CULS 认证：基于密钥对，并验证 CULS 是否在黑名单中
1. **授权完整性**：License 数据必须签名，防止篡改
2. **权限控制**:
  - `drop license` 命令仅限安全员（security officer）角色执行
  - 中心侧的授权撤销操作需要管理员权限
1. **审计要求**：所有敏感操作必须记录审计日志，保留至少 1 年
2. **黑名单机制**:
  - 实例级黑名单：防止非法 Instance ID 获取授权
  - CULS 级黑名单：中心侧维护，防止被撤销的客户继续使用
  - License ID 黑名单：执行 `drop license` 后的 License 不可复用
1. **离线授权安全**：离线授权码应包含签名和有效期，防止被复制滥用

## 7. 其他需求

### 7.1 兼容性需求

- **向后兼容**：现有单机 License 文件机制应继续支持，作为降级方案
- **平滑升级**：支持从单机 License 模式迁移到 License Center 模式
- **多版本支持**：CLS 应兼容不同版本的 TSDB/IDMP 实例

### 7.2 接口需求

- **CRM 集成接口**：RESTful API 或 gRPC，用于查询客户合同和订单信息
- **管理界面**：提供 Web UI 或 CLI 工具管理授权
- **监控接口**：提供 Prometheus 格式的 metrics 供监控系统采集

### 7.3 运维需求

- **部署方式**：
  - 中心侧：支持容器化部署（Docker/K8s）
  - 客户侧：支持二进制、Docker、系统服务等多种部署方式
- **高可用**：中心侧应支持多副本部署，保证服务可用性
- **数据备份**：
  - 中心侧 PostgreSQL 数据库需定期备份
  - 客户侧 Embedded DB 支持导出/导入
- **日志管理**：结构化日志输出，支持日志级别配置和轮转
- **配置管理**：支持配置文件和环境变量两种方式

### 7.4 易用性需求

- **自动发现**：实例应能自动发现本地网络中的 CULS
- **可视化**：提供清晰的 Web 界面展示授权状态和使用情况
- **错误提示**：授权失败时提供明确的错误信息和解决建议
- **文档完善**：提供部署文档、API 文档、故障排查手册

### 5. 测试需求（不含测试例）

- **功能测试**：覆盖所有授权操作场景（发放、更新、撤销、解除等）
- **安全测试**：
  - 渗透测试验证通信加密和认证机制
  - 黑名单机制有效性测试
- **性能测试**：
  - 大规模并发场景（10,000+ 客户侧，每个管理 100+ 实例）
  - 授权更新延迟测试
- **容错测试**:
  - 网络中断恢复测试
  - 宽限期机制测试
  - 离线授权码测试
- **兼容性测试**：不同版本 TSDB/IDMP 实例的兼容性验证
