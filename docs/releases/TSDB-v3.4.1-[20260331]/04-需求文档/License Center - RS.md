## 2. 引言

### 2.1 术语与缩写名词

| 缩写 | 全称 | 说明 |
| --- | --- | --- |
| **ELS** | Enterprise License Server | 中心侧授权服务，运行在 TDengine 服务商侧，负责授权的统一发放、更新、查看和撤销 |
| **CLS** | Customer License Server | 客户侧授权服务，运行在客户环境，作为授权代理管理客户本地的所有 TSDB/IDMP 集群 |
| **TSDB** | TDengine | TDengine 时序数据库实例 |
| **IDMP** | Industrial Data Management Platform | 工业数据管理平台实例 |
| **授权策略** | License Policy | ELS 上按公司配置的授权方案，一个公司可拥有多套授权策略 |
| **授权码** | License Key | 授权策略的具体凭证，与策略一一对应；在线模式下 CLS 从 ELS 自动获取，离线模式下由人工导入 |
| **集群组** | Cluster Group | 共享同一授权码的一组集群（1~N 个集群） |
| **授权项** | License Grant Item | 授权码中包含的具体授权维度，如测试点数、CPU 核数、有效期等 |
| **机器码** | Machine ID | CLS 实例的唯一硬件指纹，用于离线授权码绑定 |
| **宽限期** | Grace Period | License 失效后仍可正常工作的缓冲时间，默认 14 天 |
| **授权来源** | License Source | IDMP 获取授权的途径，可选 CLS 或 TSDB，二选一互斥 |

### 2.2 业界方案参考

在设计本系统时，参考了业界主流的 License Server 方案：

| 方案 | 关键特性 | 本系统借鉴点 |
| --- | --- | --- |
| **FlexNet Publisher (Flexera)** | 浮动授权池（Floating License Pool）、License 借用（Borrowing）、Node-Locked 绑定、三冗余 License Server、vendor daemon 架构 | 集群组共享授权池的"浮动授权"思想；离线授权码绑定机器码类似 Node-Locked 模式 |
| **Reprise License Manager (RLM)** | 轻量 License Server、ISV daemon、roaming license、named user / host-based 许可 | 轻量化 CLS 部署；按公司/按组灵活授权模型 |
| **LicenseSpring** | 云端 License 管理、离线激活（hardware-bound activation）、消耗型（Consumption-based）授权、API-first 设计 | 离线激活绑定机器码流程；授权项可为"可累加数值型"和"上界约束型"两类 |
| **IBM License Metric Tool (ILMT)** | 按 PVU（Processor Value Unit）计量、子容量授权（Sub-Capacity Licensing）、多产品聚合报告 | 多组件（TSDB/IDMP）分别读取各自授权项的设计 |

## 3. 需求目标

### 3.1 现状问题

当前 TDengine 和 IDMP 的授权管理存在以下问题：

1. **分散管理**：每个实例独立配置 License，无法统一管理多实例、多集群授权
2. **授权更新复杂**：需要逐个实例手动更新 License 文件，运维成本高
3. **缺乏可见性**：无法集中查看所有客户、所有集群的授权状态和使用情况
4. **离线场景支持不足**：内网或离线环境下授权管理困难，缺乏机器码绑定等安全机制
5. **安全风险**：缺乏对非法实例的管控机制
6. **授权粒度不足**：无法按公司、按集群组进行灵活的授权策略配置
7. **多组件授权割裂**：IDMP 依赖 TSDB 的授权信息，缺乏独立的授权来源配置

### 3.2 建设目标

构建**中心化授权管理系统（License Center）**，包含中心侧 Enterprise License Server（ELS）和客户侧 Customer License Server（CLS），实现：

- **统一管理**：ELS 支持按公司管理，每个公司可配置多套授权策略
- **灵活分组**：每套授权策略对应一个授权码，每个授权码绑定一个集群组
- **授权项语义明确**：授权项分为"累加型"（如测试点数，各集群总量相加不超过授权上限）和"上界约束型"（如授权有效期，所有集群统一受限）
- **在线 + 离线**：CLS 可在线从 ELS 读取授权，也可离线导入授权码；离线获取授权码时需上传 CLS 机器码
- **ELS-CLS 同步**：CLS 中的授权策略与 ELS 一一对应，策略 ID 由 ELS 分配不可修改，CLS 仅可修改本地显示名称；在线/离线只是同步通道不同，数据模型完全一致
- **多组件支持**：TSDB 和 IDMP 各自从 CLS 读取与自身相关的授权项，互不干扰
- **IDMP 双来源**：IDMP 支持从 CLS 或从 TSDB 获取授权（二选一互斥），通过配置选择授权来源

### 4.5 授权模型详细说明

#### 4.5.1 层级结构

```
ELS (Enterprise License Server)
 └── 公司 (Company)
      └── 授权策略 (License Policy)   ← 一个公司可有多套
           └── 授权码 (License Key)   ← 一个策略对应一个授权码
                └── 集群组 (Cluster Group) ← 每个授权码绑定一个集群组
                     └── 集群 (Cluster)    ← 1~N 个集群
                          └── TSDB / IDMP 实例
```

#### 4.5.2 授权项分类

| 分类 | 名称 | 语义 | 示例 |
| --- | --- | --- | --- |
| **累加型** (Additive) | 资源配额类授权项 | 集群组内所有集群的使用量**总和**不得超过授权上限 | timeseries 数、cpu_cores、dnodes、vnodes、storage_size、streams、subscriptions |
| **上界约束型** (Capped) | 约束类授权项 | 所有集群**统一受限**于同一个约束值，不能超过 | 授权有效期（service_expire） |
| **开关型** (Toggle) | 功能模块类 | 有/无，全组统一 | audit、data_sync、backup_restore |

**示例**：授权码 A 绑定集群组 A（含集群 1、集群 2），授权项如下：

| 授权项 | 类型 | 授权值 | 集群 1 使用 | 集群 2 使用 | 合规判断 |
| --- | --- | --- | --- | --- | --- |
| timeseries | 累加型 | 1,000,000 | 400,000 | 500,000 | ✅ 总和 900,000 ≤ 1,000,000 |
| cpu_cores | 累加型 | 128 | 64 | 48 | ✅ 总和 112 ≤ 128 |
| 授权有效期 | 上界约束型 | 2027-01-01 | 2027-01-01 | 2027-01-01 | ✅ 均不超过 |
| 审计功能 | 开关型 | 启用 | 启用 | 启用 | ✅ |

    CLS                                        ELS（或线下渠道）
     │                                              │

**TSDB 配置方式**：通过 ALTER LOCAL 语句配置，无需修改配置文件重启：

```sql
-- 是否启用 CLS（0=禁用，1=启用，默认 0）
ALTER LOCAL 'cls_enabled' '1';

-- 配置 CLS 服务地址（包括端口号）
ALTER LOCAL 'cls_url' 'http://192.168.1.100:7443';

-- 配置读取频率（秒）
ALTER LOCAL 'cls_refresh_interval' '3600';
```

| 配置项 | 说明 | 默认值 |
| --- | --- | --- |
| cls_enabled | 是否启用 CLS 授权模式 | 0（禁用） |
| cls_url | CLS 服务地址（IP/域名 + 端口号） | 空 |
| cls_refresh_interval | 授权信息读取频率（秒） | 3600 |

**TSDB Explorer 页面改造**：

### 4.8 授权项与组件的对应关系

CLS 存储的授权信息中，每个授权项标记所属组件类型：

| 授权项 | 所属组件 | 说明 |
| --- | --- | --- |
| service (授权有效期) | TSDB + IDMP | 通用，两个组件均读取 |
| timeseries | TSDB | 仅 TSDB 读取 |
| dnodes | TSDB | 仅 TSDB 读取 |
| cpu_cores | TSDB | 仅 TSDB 读取 |
| vnodes | TSDB | 仅 TSDB 读取 |
| storage_size | TSDB | 仅 TSDB 读取 |
| streams | TSDB | 仅 TSDB 读取 |
| subscriptions | TSDB | 仅 TSDB 读取 |
| audit | TSDB | 仅 TSDB 读取 |
| data_sync | TSDB | 仅 TSDB 读取 |
| backup_restore | TSDB | 仅 TSDB 读取 |

## 5. 通信需求

| 序号 | 功能名称 | 描述 |
| --- | --- | --- |
| 1 | ELS ↔ CLS 安全通信 | 加密传输，支持 TLS 1.3 或更高版本 |
| 2 | CLS ↔ 实例安全通信 | TSDB/IDMP 与 CLS 之间建立加密通信通道 |
| 3 | 身份认证 | CLS 向 ELS 认证：基于非对称密钥对（Ed25519）；实例向 CLS 认证：基于密钥对，并验证 CLS 是否在黑名单中 |
| 4 | 授权数据签名 | 授权码和授权数据必须签名，防止篡改 |
| 5 | CLS 拉取模式 | CLS 按配置频率主动从 ELS 拉取授权策略更新（Pull 模式） |
| 6 | CLS 向实例推送 | CLS 获取授权更新后，主动向已注册的 TSDB/IDMP 实例推送授权变更；实例也可按配置频率主动拉取 |

## 6. 审计与监控需求

| 序号 | 功能名称 | 描述 |
| --- | --- | --- |
| 1 | ELS 操作审计 | 记录所有敏感操作（策略创建/修改/撤销、授权码签发/解除、黑名单变更），包含操作人、时间、对象、结果 |
| 2 | CLS 操作审计 | 记录授权码导入/更新/解除、集群组变更、黑名单操作等，包含操作人、时间、对象、结果 |
| 3 | 审计日志保留 | 审计日志保留至少 1 年 |
| 4 | 授权使用监控 | CLS 实时汇聚集群组内各集群的授权资源使用情况（timeseries、cpu_cores、storage_size 等），与授权总量对比 |
| 5 | ELS 全局监控 | ELS 可查看所有公司、所有 CLS 的授权状态、到期时间、资源使用率 |
| 6 | 告警 | 授权即将到期（30 天提醒）、集群组资源使用率超阈值、CLS 连接异常等场景触发告警 |
| 7 | 监控指标导出 | 提供 Prometheus 格式的 metrics 供外部监控系统采集 |

## 7. 性能需求

1. **授权验证性能**：TSDB/IDMP 实例启动时的授权验证应在 1 秒内完成
2. **授权同步延迟**：ELS 侧授权更新后，CLS 下次拉取时应在 10 秒内完成同步（网络正常情况）
3. **CLS 到实例延迟**：CLS 授权更新后，应在 5 秒内分发到所管理的实例
4. **并发管理能力**：
   - ELS 应支持管理至少 10,000 个 CLS 实例
   - 每个 CLS 应支持管理至少 100 个集群（含 TSDB 和 IDMP）
5. **离线授权码生成**：离线授权码生成应在 1 秒内完成
6. **状态查询响应**：授权状态查询（含所有集群）应在 3 秒内返回结果
7. **TSDB/IDMP 定期读取**：按配置的读取频率从 CLS 拉取授权，单次请求响应时间 < 500ms

## 8. 安全需求

1. **通信安全**：
   - ELS 与 CLS 之间、CLS 与 TSDB/IDMP 之间的所有通信必须加密传输
   - 支持 TLS 1.3 或更高版本
2. **身份认证**：
   - CLS 向 ELS 认证：基于非对称密钥对（建议 Ed25519）
   - TSDB/IDMP 向 CLS 认证：基于密钥对或预共享密钥
3. **离线授权码安全**：
   - 离线授权码必须绑定 CLS 机器码，防止授权码被复制到其他机器使用
   - 授权码必须包含数字签名和有效期
4. **授权完整性**：License 数据必须签名，防止篡改
5. **权限控制**：
   - 实例侧的参数配置仅限安全员角色执行
   - ELS 侧的授权撤销操作需要管理员权限
6. **审计要求**：所有敏感操作必须记录审计日志，保留至少 1 年
7. **黑名单机制**：
   - CLS 级黑名单：ELS 维护，防止被撤销的客户继续使用
   - 实例级黑名单：CLS 维护，防止非法实例获取授权
   - License ID 黑名单：执行 `drop license` 后的 License 不可复用

## 9. 其他需求

### 9.1 兼容性需求

- **向后兼容**：现有单机 License 文件机制应继续支持，作为降级方案
- **平滑升级**：支持从单机 License 模式迁移到 License Center 模式
- **多版本支持**：ELS 应兼容不同版本的 TSDB/IDMP 实例
- **IDMP 兼容**：IDMP 从 TSDB 读取授权的原有逻辑保留，新增 CLS 作为可选授权来源（二选一互斥）

### 9.2 接口需求

- **ELS 管理接口**：RESTful API，用于公司管理、授权策略配置、授权发放和撤销
- **CLS 对外接口**：供 TSDB/IDMP 调用的授权查询接口（REST 或 gRPC）
- **CRM 集成接口**：（未来版本）用于查询客户合同和订单信息
- **管理界面**：ELS 和 CLS 均提供 Web UI 或 CLI 工具

### 9.3 运维需求

- **部署方式**：
  - ELS：支持容器化部署（Docker/K8s）
  - CLS：支持二进制、Docker、系统服务等多种部署方式
- **高可用**：ELS 应支持多副本部署，保证服务可用性
- **数据备份**：ELS 和 CLS 的数据均需支持备份和恢复
- **日志管理**：结构化日志输出，支持日志级别配置和轮转
- **配置管理**：支持配置文件和环境变量两种方式

### 9.4 易用性需求

- **TSDB 配置简单**：通过 ALTER LOCAL 语句即可完成 CLS 配置，无需修改配置文件重启
- **IDMP 配置直观**：在 IDMP 授权页面通过 UI 选择授权来源并配置，操作直观
- **错误提示**：授权失败、连通性失败时提供明确的错误信息和解决建议
- **文档完善**：提供部署文档、API 文档、故障排查手册

### 9.5 测试需求（不含测试例）

- **功能测试**：覆盖所有授权操作场景（策略配置、发放、更新、撤销、离线导入等）
- **集群组测试**：验证累加型和上界约束型授权项在多集群场景下的正确性
- **TSDB 接入测试**：ALTER LOCAL 配置 → 联通性检查 → 授权读取 → 持久化 → Explorer 展示 全流程
- **IDMP 接入测试**：双来源切换（CLS/TSDB）、授权读取、持久化 全流程
- **安全测试**：渗透测试、机器码绑定有效性、黑名单机制
- **性能测试**：大规模并发场景（多公司、多 CLS、多集群组）
- **容错测试**：网络中断恢复、宽限期机制、离线授权码
- **兼容性测试**：不同版本 TSDB/IDMP 实例的兼容性验证
