# 子查询功能增强

## 一、功能背景与问题来源

### 1.1 业务痛点

在实际工业数据分析中，用户经常需要执行复杂的条件筛选和数据对比，但之前版本的 TDengine 对子查询的支持有限，导致用户在处理以下场景时面临挑战：

**查询复杂度高：**
- **无法使用计算结果作为条件** - 需要先查询平均值、最大值等统计指标，再手动构造第二次查询
- **多表关联条件受限** - 无法在 JOIN 条件中使用子查询动态获取阈值
- **集合运算不灵活** - 缺少 IN、EXISTS 等标准 SQL 运算符与子查询的结合

**业务场景受限：**
- **异常检测困难** - 无法一次查询找出超过平均值的异常设备
- **动态阈值判断不便** - 无法根据历史数据动态确定告警阈值
- **存在性判断繁琐** - 需要多次查询才能判断某个条件是否存在

### 1.2 典型场景示例

**场景一：电表异常用电检测**
- 问题：需要找出当天用电量超过本月平均值 1.5 倍的电表，但无法在单条 SQL 中完成
- 现状：需要先查询月平均值，再手动构造第二条 SQL 查询
- 影响：实时监控延迟，无法快速响应异常

**场景二：设备状态关联分析**
- 问题：需要查询"存在告警记录"的设备的运行数据，但缺少 EXISTS 运算符
- 现状：需要先查询告警表获取设备列表，再通过 IN 子句手动拼接查询
- 影响：SQL 构造复杂，难以维护，性能较差

**场景三：生产指标对比**
- 问题：需要筛选出产量高于所有同类设备的优秀设备，但缺少 ALL 运算符支持
- 现状：需要通过多次嵌套查询或应用层处理
- 影响：查询效率低，业务逻辑复杂

### 1.3 为什么需要子查询增强？

子查询是 SQL 标准的重要组成部分，允许在查询中嵌入另一个查询，实现复杂的业务逻辑。之前版本的 TDengine 对子查询的支持有限，缺少：

1. **标量子查询** - 无法将单值子查询结果用作常量或表达式
2. **IN 子查询** - 无法使用 `IN (SELECT ...)` 进行集合匹配
3. **比较运算符子查询** - 缺少 ALL、ANY、SOME 等标准运算符
4. **存在性判断子查询** - 缺少 EXISTS、NOT EXISTS 运算符

**TDengine 3.4.0 和 3.4.1** 通过增强子查询功能，全面支持标准 SQL 子查询语法，大幅提升查询表达能力。

## 二、功能介绍与核心特性

### 2.1 非相关标量子查询

#### 2.1.1 功能定义

**标量子查询（Scalar Subquery）**：返回**单行单列**数据的子查询，可以作为查询中的一个常量使用。

**非相关子查询**：子查询中不引用父查询的列，每个子查询只执行一次。

#### 2.1.2 使用场景

标量子查询可以在几乎所有需要表达式的地方使用：
- SELECT 列表
- WHERE 条件
- JOIN ON 条件
- GROUP BY 分组列
- HAVING 过滤条件
- ORDER BY 排序条件
- 函数参数
- CASE 表达式

#### 2.1.3 基础示例

**示例一：SELECT 列表中使用标量子查询**

```sql
-- 查询每个电表的用电量，并显示全局平均用电量
SELECT tbname, 
       current, 
       voltage,
       (SELECT AVG(current) FROM meters) AS avg_current
FROM meters
WHERE ts >= NOW - 1h;
```

**功能说明：**
- 子查询 `(SELECT AVG(current) FROM meters)` 返回全局平均电流值
- 该子查询只执行一次，结果作为常量在每行中显示
- 便于对比单个电表与平均水平的差距

**示例二：WHERE 条件中使用标量子查询**

```sql
-- 查询电流超过平均值的电表
SELECT tbname, ts, current, voltage
FROM meters
WHERE current > (SELECT AVG(current) FROM meters WHERE ts >= NOW - 1d)
  AND ts >= NOW - 1h;
```

**功能说明：**
- 子查询计算过去 24 小时的平均电流
- 主查询筛选出最近 1 小时内超过平均值的记录
- 一条 SQL 完成异常检测，无需应用层二次处理

**示例三：JOIN 条件中使用标量子查询**

```sql
-- 关联电表和告警表，使用动态阈值
SELECT m.tbname, m.ts, m.current, a.alarm_type
FROM meters m 
JOIN alarms a 
  ON m.tbname = a.device_id 
  AND m.ts = a.ts
  AND m.current > (SELECT AVG(current) * 1.5 FROM meters WHERE ts >= NOW - 1d);
```

### 2.2 IN 子查询

#### 2.2.1 功能定义

**IN 子查询**：判断表达式是否在子查询返回的集合中，子查询必须返回**单列**数据。

**语法格式：**
```sql
expr IN (subquery)
-- 或
expr IN ((subquery))
```

#### 2.2.2 基础示例

**示例一：WHERE 条件中使用 IN 子查询**

```sql
-- 查询有告警记录的电表的实时数据
SELECT tbname, ts, current, voltage, power
FROM meters
WHERE tbname IN (
  SELECT DISTINCT device_id 
  FROM alarms 
  WHERE ts >= NOW - 1d 
    AND alarm_level = 'critical'
)
AND ts >= NOW - 1h;
```

**功能说明：**
- 子查询返回过去 24 小时内有严重告警的设备列表
- 主查询筛选这些设备最近 1 小时的运行数据
- 避免手动拼接设备 ID 列表

**示例二：HAVING 条件中使用 IN 子查询**

```sql
-- 按电表分组统计，筛选出产量在TOP 10的电表
SELECT tbname, 
       COUNT(*) AS record_count,
       AVG(current) AS avg_current,
       SUM(power) AS total_power
FROM meters
WHERE ts >= NOW - 1d
GROUP BY tbname
HAVING tbname IN (
  SELECT tbname 
  FROM production_stats 
  ORDER BY daily_output DESC 
  LIMIT 10
);
```

### 2.3 ALL/ANY/SOME 运算符

#### 2.3.1 功能定义

**ALL 运算符**：判断表达式是否满足子查询返回的**所有**结果。

**ANY/SOME 运算符**：判断表达式是否满足子查询返回的**任意一个**结果（两者功能等价）。

**语法格式：**
```sql
expr [=|>|<|>=|<=|<>] ALL (subquery)
expr [=|>|<|>=|<=|<>] ANY (subquery)
expr [=|>|<|>=|<=|<>] SOME (subquery)
```

#### 2.3.2 基础示例

**示例一：使用 ALL 运算符**

```sql
-- 查询电流高于所有同车间电表平均值的设备
SELECT tbname, ts, current, voltage
FROM meters m
WHERE workshop = '车间A'
  AND current > ALL (
    SELECT AVG(current) 
    FROM meters 
    WHERE workshop != '车间A'
      AND ts >= NOW - 1h
    GROUP BY workshop
  )
  AND ts >= NOW - 1h;
```

**功能说明：**
- 子查询返回其他车间的平均电流值（多行单列）
- ALL 运算符要求当前电流高于所有其他车间
- 找出表现最优秀的设备

**示例二：使用 ANY 运算符**

```sql
-- 查询电压波动超过任一历史异常阈值的记录
SELECT tbname, ts, voltage, current
FROM meters
WHERE voltage < ANY (
  SELECT min_voltage 
  FROM voltage_thresholds 
  WHERE alarm_level IN ('warning', 'critical')
)
AND ts >= NOW - 1h;
```

**功能说明：**
- 子查询返回多个告警阈值
- ANY 运算符判断是否低于任一阈值
- 实现多级告警检测

**示例三：使用 SOME 运算符（与 ANY 等价）**

```sql
-- 查询功率超过同类设备任一峰值的电表
SELECT tbname, ts, power, current
FROM meters m
WHERE device_type = 'A型'
  AND power >= SOME (
    SELECT MAX(power) 
    FROM meters 
    WHERE device_type = 'B型'
      AND ts >= NOW - 1d
    GROUP BY tbname
  )
  AND ts >= NOW - 1h;
```

### 2.4 EXISTS/NOT EXISTS 运算符

#### 2.4.1 功能定义

**EXISTS 运算符**：判断子查询是否返回**至少一行数据**，返回则为 TRUE，否则为 FALSE。

**NOT EXISTS 运算符**：判断子查询是否**无数据返回**，为空则为 TRUE，否则为 FALSE。

**语法格式：**
```sql
EXISTS (subquery)
NOT EXISTS (subquery)
```

**性能优化：** EXISTS/NOT EXISTS 采用短路求值，子查询返回第一行后立即终止，性能优异。

#### 2.4.2 基础示例

**示例一：使用 EXISTS 运算符**

```sql
-- 查询存在过载告警的电表的实时数据
SELECT m.tbname, m.ts, m.current, m.voltage, m.power
FROM meters m
WHERE EXISTS (
  SELECT 1 
  FROM alarms a 
  WHERE a.device_id = m.tbname 
    AND a.alarm_type = 'overload'
    AND a.ts >= NOW - 1d
)
AND m.ts >= NOW - 1h
ORDER BY m.ts DESC;
```

**功能说明：**
- 子查询检查是否存在过载告警记录
- EXISTS 只关心是否有数据，不关心具体内容
- 子查询返回第一行即停止，性能优异

**示例二：使用 NOT EXISTS 运算符**

```sql
-- 查询正常运行（无任何告警记录）的电表
SELECT tbname, ts, current, voltage
FROM meters m
WHERE NOT EXISTS (
  SELECT 1 
  FROM alarms a 
  WHERE a.device_id = m.tbname 
    AND a.ts >= NOW - 7d
)
AND ts >= NOW - 1h;
```

**功能说明：**
- 筛选出过去 7 天内无告警记录的电表
- NOT EXISTS 用于排除性查询
- 便于找出稳定运行的设备

**示例三：CASE 表达式中使用 EXISTS**

```sql
-- 为每个电表标记告警状态
SELECT tbname,
       ts,
       current,
       voltage,
       CASE 
         WHEN EXISTS (
           SELECT 1 FROM alarms 
           WHERE device_id = meters.tbname 
             AND alarm_level = 'critical'
             AND ts >= NOW - 1h
         ) THEN '严重告警'
         WHEN EXISTS (
           SELECT 1 FROM alarms 
           WHERE device_id = meters.tbname 
             AND alarm_level = 'warning'
             AND ts >= NOW - 1h
         ) THEN '预警'
         ELSE '正常'
       END AS status
FROM meters
WHERE ts >= NOW - 1h;
```

## 三、典型应用场景与价值

### 3.1 场景一：智能电表异常用电检测

**业务需求：**
电力公司需要实时监控用电异常，找出当天用电量超过本月平均值 1.5 倍的电表，及时进行用电安全检查或计费核查。

**客户价值：**
- ✅ 一条 SQL 实现异常检测，无需应用层二次查询
- ✅ 实时动态阈值，自动适应用电变化趋势
- ✅ 提升异常响应速度，降低用电安全风险

**实现方案：**

```sql
-- 使用标量子查询计算动态阈值
SELECT tbname AS meter_id,
       ts,
       current,
       voltage,
       power,
       daily_kwh,
       (SELECT AVG(daily_kwh) 
        FROM meter_daily_stats 
        WHERE ts >= NOW - 30d) AS monthly_avg,
       daily_kwh / (SELECT AVG(daily_kwh) 
                    FROM meter_daily_stats 
                    WHERE ts >= NOW - 30d) AS usage_ratio
FROM meter_daily_stats
WHERE daily_kwh > (
  SELECT AVG(daily_kwh) * 1.5 
  FROM meter_daily_stats 
  WHERE ts >= NOW - 30d
)
AND ts >= NOW - 1d
ORDER BY usage_ratio DESC;
-- 自动找出用电异常的电表，无需手动计算阈值
```

### 3.2 场景二：生产效率对标分析

**业务需求：**
制造企业需要找出生产效率高于所有同类设备的优秀设备，作为标杆进行经验推广，并对低效设备进行改进。

**客户价值：**
- ✅ 使用 ALL 运算符实现"超过所有"的严格对比
- ✅ 自动识别标杆设备，无需人工筛选
- ✅ 为设备优化和管理决策提供数据支撑

**实现方案：**

```sql
-- 使用 ALL 运算符找出最优设备
SELECT m.tbname AS device_id,
       m.device_type,
       m.workshop,
       AVG(m.oee) AS avg_oee,
       SUM(m.output_count) AS total_output,
       COUNT(*) AS working_hours
FROM production_metrics m
WHERE m.ts >= NOW - 7d
  AND m.device_type = '注塑机A型'
PARTITION BY m.tbname, m.device_type, m.workshop
HAVING AVG(m.oee) > ALL (
  SELECT AVG(oee)
  FROM production_metrics
  WHERE device_type = '注塑机B型'
    AND ts >= NOW - 7d
  PARTITION BY tbname
)
ORDER BY avg_oee DESC;
-- 找出OEE高于所有B型设备的A型设备，作为标杆
```

### 3.3 场景三：设备健康状态监控

**业务需求：**
需要实时监控设备健康状态，将设备分为"正常"、"预警"、"故障"三类，并为每个设备提供状态标签，便于监控大屏展示。

**客户价值：**
- ✅ 使用 EXISTS 高效判断告警存在性
- ✅ 一条 SQL 生成设备状态标签，无需多次查询
- ✅ 支持实时监控大屏，提升可视化效果

**实现方案：**

```sql
-- 使用 EXISTS/NOT EXISTS 判断设备状态
SELECT m.tbname AS device_id,
       m.device_type,
       m.workshop,
       LAST(m.ts) AS last_update,
       LAST(m.current) AS current_value,
       LAST(m.temperature) AS current_temp,
       CASE
         -- 存在严重告警
         WHEN EXISTS (
           SELECT 1 FROM alarms 
           WHERE device_id = m.tbname 
             AND alarm_level = 'critical'
             AND ts >= NOW - 1h
         ) THEN '故障'
         -- 存在预警但无严重告警
         WHEN EXISTS (
           SELECT 1 FROM alarms 
           WHERE device_id = m.tbname 
             AND alarm_level = 'warning'
             AND ts >= NOW - 1h
         ) THEN '预警'
         -- 无任何告警
         ELSE '正常'
       END AS health_status,
       CASE
         -- 判断是否有维护计划
         WHEN EXISTS (
           SELECT 1 FROM maintenance_plan 
           WHERE device_id = m.tbname 
             AND plan_date >= NOW 
             AND plan_date <= NOW + 7d
         ) THEN '已计划'
         ELSE '无计划'
       END AS maintenance_status
FROM meters m
PARTITION BY m.tbname
ORDER BY health_status DESC, m.tbname;
-- 一条SQL生成设备健康看板数据
```

### 3.4 场景四：无故障设备筛选与奖励

**业务需求：**
企业需要找出连续 30 天无任何故障告警的设备，作为优秀设备进行表彰，并分析这些设备的运行特征。

**客户价值：**
- ✅ 使用 NOT EXISTS 高效筛选无故障设备
- ✅ 激励设备操作规范，提升设备管理水平
- ✅ 分析优秀设备特征，推广最佳实践

**实现方案：**

```sql
-- 使用 NOT EXISTS 筛选无故障设备
SELECT m.tbname AS device_id,
       m.device_type,
       m.workshop,
       COUNT(*) AS operating_hours,
       AVG(m.oee) AS avg_oee,
       AVG(m.temperature) AS avg_temp,
       SUM(m.output_count) AS total_output
FROM production_metrics m
WHERE NOT EXISTS (
  SELECT 1 
  FROM alarms a 
  WHERE a.device_id = m.tbname 
    AND a.ts >= NOW - 30d
)
AND m.ts >= NOW - 30d
PARTITION BY m.tbname, m.device_type, m.workshop
HAVING COUNT(*) > 600  -- 至少600小时运行记录
ORDER BY avg_oee DESC
LIMIT 20;
-- 找出30天无故障且表现优秀的Top 20设备
```

## 四、运维最佳实践

### 4.1 子查询性能优化建议

**尽量使用非相关子查询：**
- 非相关子查询只执行一次，性能优于相关子查询
- 当前版本暂不支持相关子查询

**合理使用 EXISTS/NOT EXISTS：**
- EXISTS 采用短路求值，返回第一行即停止，性能优异
- 优先使用 EXISTS 而非 IN，特别是子查询结果集较大时

**避免子查询返回大量数据：**
- IN 子查询应通过 WHERE 条件减少返回行数
- ALL/ANY 子查询同样应控制结果集大小

### 4.2 常见错误排查

**错误一：子查询返回多行多列**
```sql
-- 错误示例：标量子查询返回多行
SELECT * FROM meters 
WHERE current > (SELECT current FROM meters);  -- 报错

-- 正确写法：确保返回单行单列
SELECT * FROM meters 
WHERE current > (SELECT AVG(current) FROM meters);
```

**错误二：IN 子查询返回多列**
```sql
-- 错误示例：IN 子查询返回多列
SELECT * FROM meters 
WHERE tbname IN (SELECT tbname, ts FROM alarms);  -- 报错

-- 正确写法：确保返回单列
SELECT * FROM meters 
WHERE tbname IN (SELECT device_id FROM alarms);
```

**错误三：数据类型不匹配**
```sql
-- 错误示例：类型不兼容
SELECT * FROM meters 
WHERE current > (SELECT tbname FROM meters);  -- 报错

-- 正确写法：确保类型兼容
SELECT * FROM meters 
WHERE current > (SELECT AVG(current) FROM meters);
```

### 4.3 使用限制说明

**当前版本限制：**
1. ❌ DDL、DML 语句中暂不支持子查询
2. ❌ Query policy 4 暂不支持子查询
3. ❌ 相关子查询暂不支持

**支持的场景：**
1. ✅ 普通查询
2. ✅ 嵌套查询
3. ✅ UNION/UNION ALL
4. ✅ INSERT INTO SELECT
5. ✅ STMT 查询
6. ✅ 视图

## 五、总结

### 核心价值

TDengine 3.4.0 和 3.4.1 的子查询增强为工业数据分析带来了**强大的 SQL 表达能力**：

1. **简化复杂查询** - 一条 SQL 实现多步骤数据分析，减少应用层代码
2. **动态条件判断** - 支持基于历史数据的动态阈值和条件
3. **标准 SQL 兼容** - 支持 IN、ALL、ANY、EXISTS 等标准运算符
4. **性能优异** - 非相关子查询只执行一次，EXISTS 短路求值
5. **降低使用门槛** - 符合 SQL 标准，易于学习和使用

### 功能清单

| 功能 | 版本 | 说明 |
| --- | --- | --- |
| 非相关标量子查询 | 3.4.0 | 返回单行单列，可用作常量 |
| IN 子查询 | 3.4.1 | 集合匹配，子查询返回单列 |
| ALL 运算符 | 3.4.1 | 满足所有结果的比较 |
| ANY/SOME 运算符 | 3.4.1 | 满足任一结果的比较 |
| EXISTS 运算符 | 3.4.1 | 判断是否存在数据 |
| NOT EXISTS 运算符 | 3.4.1 | 判断是否无数据 |

### 快速上手建议

1. **从标量子查询入手** - 先熟悉在 WHERE、SELECT 中使用标量子查询
2. **掌握 IN 和 EXISTS** - 这两个是最常用的子查询运算符
3. **理解运算符差异** - 区分 ALL（所有）、ANY（任一）、EXISTS（存在）的语义
4. **注意性能优化** - 优先使用 EXISTS，控制子查询结果集大小
5. **遵循使用限制** - 了解当前版本的限制，避免在不支持的场景中使用
