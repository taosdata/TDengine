# 数据订阅功能增强

## 一、功能背景与问题来源

### 1.1 业务痛点

在实际多集群架构和数据同步场景中,用户在使用数据订阅时经常遇到以下挑战:

**虚拟表元数据不支持订阅:**
- **虚拟表创建无法同步** - 虚拟超级表、虚拟子表的创建、修改等操作无法通过数据订阅同步
- **跨集群迁移受限** - 虚拟表相关的业务无法完整迁移到测试集群或灾备集群
- **数据迁移不完整** - 数据库订阅只能同步物理表,虚拟表元数据丢失

**Token 认证不支持:**
- **只支持用户名密码** - 数据订阅只支持传统的用户名密码认证,无法使用 Token
- **不符合现代应用要求** - 微服务架构下,Token 认证是标准做法
- **安全审计困难** - 用户名密码分散在代码中,集中管理和审计困难

**订阅性能问题:**
- **大宽表订阅慢** - 订阅包含大量列的超级表时,性能严重下降
- **频繁数据拷贝** - 每个表单独一个 block,频繁分配拷贝对齐数据
- **拼装逻辑复杂** - slotId、colId 处理逻辑混乱,效率低下

### 1.2 典型场景示例

**场景一:多集群数据同步**
- 问题:需要将包含虚拟表的数据库从生产集群同步到测试集群,但数据订阅不支持虚拟表元数据
- 影响:虚拟表相关的业务无法完整迁移,测试环境不完整

**场景二:微服务架构订阅**
- 问题:微服务架构下,多个订阅消费者需要使用统一的 Token 进行认证,但数据订阅不支持 Token
- 影响:只能使用用户名密码,集中管理困难,安全审计不便

**场景三:大宽表订阅**
- 问题:订阅单个 VNode、30000 子表、每表 1000 列的超级表,订阅速度只有 150 条/秒
- 影响:数据同步延迟大,业务实时性差

### 1.3 为什么需要数据订阅增强?

**数据订阅是多集群架构的关键:**
- 虚拟表作为重要特性,需要完整的订阅和迁移支持
- Token 认证符合现代应用的安全要求
- 订阅性能直接影响数据同步的实时性

**TDengine 3.4.1** 通过全面增强数据订阅功能,支持虚拟表元数据订阅、Token 认证,并大幅优化订阅性能,提升多集群架构能力。

## 二、功能介绍与核心特性

### 2.1 虚拟表元数据订阅支持

#### 2.1.1 功能概述

数据订阅现在全面支持虚拟表的元数据变更,包括虚拟超级表的创建、修改、删除,以及虚拟子表的创建、修改、删除等操作。

#### 2.1.2 核心行为

**1. 虚拟超级表订阅:**
- 必须使用 `WITH META` 参数,否则订阅不到内容
- 订阅到的是虚拟表的元数据消息 (二进制格式)
- 可通过 `tmq_get_json_meta` 接口获取 JSON 格式元数据

```sql
-- 订阅虚拟超级表元数据
CREATE TOPIC topic_virtual_meters AS 
SELECT * FROM virtual_meters WITH META;
```

**2. 数据库订阅:**
- 使用 `WITH META` 参数时,可订阅虚拟表的元数据信息
- 仅订阅元数据,不包含虚拟表的实际数据 (虚拟表本身不存储数据)

```sql
-- 订阅数据库,包含虚拟表元数据
CREATE TOPIC topic_test_db AS 
DATABASE test WITH META;
```

**3. 订阅消息格式:**
- 虚拟表的订阅结果都是 meta 数据
- 具体内容为相应消息的二进制编码:
  - 创建虚拟超级表: SVCreateStbReq 结构的 encode msg
  - 修改虚拟子表: SVAlterTbReq 结构的 encode msg
- 通过 `tmq_get_json_meta` 接口可获取 JSON 格式描述

**4. 数据迁移写入:**
- `tmq_get_json_meta` 接口返回的 JSON 结构包含虚拟表相关内容
- 支持 `tmq_write_raw` 接口自动化迁移虚拟表元数据

#### 2.1.3 跨集群迁移配置

**新增配置参数:**

| 参数 | 说明 | 默认值 | 使用建议 |
| --- | --- | --- | --- |
| tmqWriteRefDB | 写入目标集群时,替换虚拟表 REF 信息中的数据库名 | 空 (不替换) | 数据迁移场景设置为目标数据库名 |
| tmqWriteCheckRef | 写入时是否校验虚拟表 REF 引用的有效性 | false | 数据迁移场景建议 false,生产环境同步建议 true |

**配置示例:**

```ini
# 数据迁移场景推荐配置
tmqWriteRefDB=target_db           # 替换 REF 数据库为 target_db
tmqWriteCheckRef=false            # 不校验 REF 有效性 (允许源表缺失)

# 生产环境同步推荐配置
tmqWriteCheckRef=true             # 校验 REF 有效性 (保证数据完整性)
```

**为什么默认不校验 REF:**
- 源库 REF 的数据可能已经不存在
- 即使不存在,虚拟表依然有效,只是查询时 REF 的列返回 NULL
- 数据迁移时,保留虚拟表结构比校验 REF 更重要

#### 2.1.4 使用示例

**跨集群迁移虚拟表:**

```python
# Python 示例:从源集群迁移虚拟表到目标集群
import taos

# 源集群:创建订阅
source_conn = taos.connect(host='source-host', user='root', password='taosdata')
source_cursor = source_conn.cursor()
source_cursor.execute("CREATE TOPIC topic_test_db AS DATABASE test WITH META")

# 配置消费者
conf = {
    'group.id': 'migration_group',
    'td.connect.ip': 'source-host',
    'td.connect.user': 'root',
    'td.connect.pass': 'taosdata',
}
consumer = taos.Consumer(conf)
consumer.subscribe(['topic_test_db'])

# 目标集群:配置迁移参数
target_conn = taos.connect(host='target-host', user='root', password='taosdata')
target_conn.execute("SET tmqWriteRefDB='production_db'")     # 替换 REF 数据库
target_conn.execute("SET tmqWriteCheckRef=false")            # 不校验 REF

# 迁移数据和元数据
while True:
    msg = consumer.poll(timeout=1.0)
    if msg is None:
        continue
    
    # 写入目标集群 (自动处理虚拟表元数据)
    target_conn.write_raw(msg)
    consumer.commit(msg)

consumer.close()
source_conn.close()
target_conn.close()
```

### 2.2 Token 认证支持

#### 2.2.1 功能概述

数据订阅现在支持使用 Token 进行身份认证,符合现代应用的安全要求。

#### 2.2.2 核心行为

**1. Token 优先级:**
- Token 优先级高于用户名密码
- 同时设置 Token 和用户名密码时,优先使用 Token

**2. Token 有效性检测:**
- 创建 Consumer 时校验 Token 是否有效
- Poll 数据过程中定期检测 Token 有效性 (通过心跳)
- Token 失效、过期或被删除时,poll 返回 NULL
- 错误信息通过 `taos_errstr(NULL)` 获取

**3. Token 恢复:**
- 如果 Token 从失效变为有效 (如重新启用),可继续获取数据
- 无需重建 Consumer

**4. 实现逻辑:**
- `tmq_consumer_new` 时,如果指定 Token,优先使用 Token 创建连接
- `tmq_t` 结构新增 tokenCode 字段,记录 Token 是否有效
- Consumer 心跳中定期检测 Token 有效性 (发送给 mnode 的消息自动检测)
- `tmq_consumer_poll` 检测 tokenCode,如果无效则设置 terrno 并返回 NULL

#### 2.2.3 使用示例

**C 代码示例:**

```c
// 使用 Token 创建 Consumer
tmq_conf_t* conf = tmq_conf_new();
tmq_conf_set(conf, "group.id", "consumer_group_1");

// 方式一:仅使用 Token
tmq_conf_set(conf, "td.connect.token", "your_token_value");

// 方式二:同时设置 Token 和用户名密码 (优先使用 Token)
tmq_conf_set(conf, "td.connect.user", "root");
tmq_conf_set(conf, "td.connect.pass", "taosdata");
tmq_conf_set(conf, "td.connect.token", "your_token_value");  // 优先使用 Token

tmq_t* tmq = tmq_consumer_new(conf, NULL, 0);
tmq_subscribe(tmq, topics);

// Poll 数据,自动检测 Token 有效性
while (running) {
    TAOS_RES* msg = tmq_consumer_poll(tmq, 1000);
    if (msg == NULL) {
        // 检查是否 Token 失效
        const char* err = taos_errstr(NULL);
        if (err != NULL && strstr(err, "token") != NULL) {
            // 告警:Token 失效,通知管理员
            send_alert("Subscription token expired or disabled");
        }
    } else {
        // 处理数据
        process_message(msg);
    }
}

tmq_consumer_close(tmq);
```

**Python 代码示例:**

```python
import taos

# 创建 Token
conn = taos.connect(host='localhost', user='root', password='taosdata')
conn.execute("CREATE TOKEN subscribe_token FOR USER subscribe_user EXPIRE_TIME 7d")

# 使用 Token 创建 Consumer
conf = {
    'group.id': 'consumer_group_1',
    'td.connect.token': 'subscribe_token_value',
}
consumer = taos.Consumer(conf)
consumer.subscribe(['topic_meters'])

# Poll 数据
while True:
    msg = consumer.poll(timeout=1.0)
    if msg is None:
        # 检查 Token 是否失效
        error = taos.get_last_error()
        if error and 'token' in error.lower():
            print(f"Token 失效: {error}")
            send_alert(f"Subscription token error: {error}")
    else:
        # 处理数据
        process_message(msg)
        consumer.commit(msg)

consumer.close()
```

**Token 管理:**

```sql
-- 创建 Token
CREATE TOKEN subscribe_token FOR USER subscribe_user EXPIRE_TIME 7d;

-- 查看 Token 状态
SHOW TOKENS;

-- Token 即将过期时续期
ALTER TOKEN subscribe_token EXPIRE_TIME 7d;

-- 安全事件发生时禁用 Token
ALTER TOKEN subscribe_token DISABLE;

-- 问题解决后恢复 Token
ALTER TOKEN subscribe_token ENABLE;
-- Consumer 无需重建,自动恢复数据订阅

-- 删除 Token
DROP TOKEN subscribe_token;
```

### 2.3 订阅性能优化

#### 2.3.1 性能问题分析

**优化前的性能问题:**

测试场景:
- 单个 VNode
- 30000 子表
- 每表 1000 列数据,10 列 tag
- 每表 10 条数据
- 订阅 `SELECT * FROM stb`

性能表现:
- **订阅速度:150 条/秒**

通过火焰图分析,发现性能瓶颈:
1. 每个表单独一个 block,需要频繁分配拷贝对齐数据
2. 拼装 slotId、colId 逻辑复杂混乱,每个表处理很慢
3. 每个 block 都要 set tag、filter 等逻辑,且要拷贝到最终结果 block

#### 2.3.2 优化措施

**主要优化点:**

1. **统一 block 复用**
   - Query 固定,结果 block 类型固定
   - 不同表使用同一个 block,避免频繁创建拷贝
   - 性能极大提升

2. **优化 colId 和 slotId 处理**
   - 初始化时建立好结果,解析数据时直接使用
   - 避免复杂的处理逻辑

3. **优化 filter 逻辑**
   - 对最终的 block 做一次 filter
   - 减少重复的 filter 操作

4. **优化 query 类型 topic**
   - Query 里有 tag 时,优化获取 tag 的缓存逻辑
   - 之前使用 LRU Cache,与查询共用,问题较多
   - 优化后使用 topic 独立的只有需要的 tag 的缓存

5. **优化 operator**
   - 之前使用 StreamOperator,混杂了旧流的大量字段和逻辑
   - 新的 TmqOperator,清除大量旧 stream 相关内容
   - 逻辑清晰明朗,便于维护

#### 2.3.3 性能提升效果

**测试结果:**

| 优化前 | 优化后 | 性能提升 |
| --- | --- | --- |
| 150 条/秒 | 4000 条/秒 | **27 倍** |

**其他优化:**

1. **增加单次最大返回时长**
   - 通过 `fetch.max.wait.ms` 参数控制,默认 1s
   - 含义:如果 `tmq_consumer_poll` 调用服务端超过该时间,即使没到需要的条数也返回

2. **tmq_consumer_poll 处理逻辑**
   - 超过 `fetch.max.wait.ms` 时间,返回
   - 超过 `min.poll.rows` 设置的条数,返回
   - 如果没有数据,超过 poll 接口本身设置的 timeout,返回
   - 返回 NULL 时,通过 `taos_errstr(NULL)` 获取原因 (出错或真的没数据)

## 三、典型应用场景与价值

### 3.1 场景一:虚拟表跨集群数据迁移

**业务需求:**
需要将包含虚拟表的测试数据库完整同步到生产集群,虚拟表引用的源表可能部分不存在,但虚拟表本身结构需要保留。

**客户价值:**
- ✅ 数据订阅支持虚拟表元数据,实现完整迁移
- ✅ 自动替换 REF 数据库名,适应目标集群环境
- ✅ 可选跳过 REF 校验,允许部分源表缺失
- ✅ 使用 `tmq_write_raw` 实现自动化迁移

**实现方案:**

**源集群:创建订阅**

```sql
-- 订阅测试数据库,包含虚拟表元数据
CREATE TOPIC topic_test_db AS 
DATABASE test WITH META;
```

**目标集群:配置迁移参数**

```ini
# 配置文件或运行时设置
tmqWriteRefDB=production_db      # 替换 REF 数据库为 production_db
tmqWriteCheckRef=false            # 不校验 REF 有效性 (允许源表缺失)
```

**迁移代码:**

```c
// 从源集群订阅数据和元数据
tmq_t* source_tmq = tmq_consumer_new(source_conf, NULL, 0);
tmq_subscribe(source_tmq, topics);

// 创建目标集群连接
TAOS* target_conn = taos_connect("target_host", "root", "password", NULL, 0);

while (running) {
    // 从源集群 poll 数据
    TAOS_RES* msg = tmq_consumer_poll(source_tmq, 1000);
    if (msg != NULL) {
        // 写入目标集群 (自动处理虚拟表元数据)
        tmq_write_raw(target_conn, msg);
        tmq_commit(source_tmq, msg, 0);
    }
}
```

**迁移效果:**
- 虚拟表结构完整迁移到目标集群
- REF 数据库名自动替换为 `production_db`
- 即使源表部分缺失,虚拟表也能创建成功 (查询时 REF 列返回 NULL)

**灾备集群:配置同步服务**

```python
import taos
import time

# 生产集群消费者
prod_conf = {
    'group.id': 'disaster_recovery',
    'td.connect.ip': 'prod-cluster',
    'td.connect.token': 'dr_token_value',
    'fetch.max.wait.ms': '1000',

    dr_conn.write_raw(msg)
    prod_consumer.commit(msg)

    if total_synced % 10000 == 0:
        print(f"已同步 {total_synced} 行数据")
```

## 四、运维最佳实践

### 4.1 虚拟表订阅注意事项

**必须使用 WITH META:**
```sql
-- 错误:虚拟表订阅不使用 WITH META,订阅不到内容
CREATE TOPIC topic_virtual AS SELECT * FROM v_meters;

-- 正确:虚拟表订阅必须使用 WITH META
CREATE TOPIC topic_virtual AS SELECT * FROM v_meters WITH META;
```

**虚拟表不订阅实际数据:**
- 虚拟表本身不存储数据
- 订阅到的只有虚拟表的元数据 (创建、修改、删除)
- 虚拟表引用的源表数据需要单独订阅

**跨集群迁移配置:**

```ini
# 数据迁移场景推荐配置
tmqWriteRefDB=target_db           # 替换 REF 数据库名
tmqWriteCheckRef=false            # 不校验 REF 有效性 (允许源表缺失)

# 生产环境同步推荐配置
tmqWriteCheckRef=true             # 校验 REF 有效性 (保证数据完整性)
```

### 4.2 Token 认证最佳实践

**Token 生命周期管理:**

```sql
-- 创建 Token 时设置合理的过期时间
CREATE TOKEN subscribe_token FOR USER subscribe_user EXPIRE_TIME 7d;
```

**Token 失效监控:**

```python
def monitor_token_status(consumer):
    """监控 Token 状态,失效时告警"""
    msg = consumer.poll(timeout=1.0)
    if msg is None:
        error = taos.get_last_error()
        if error and 'token' in error.lower():
            # Token 失效
            send_alert(f"Subscription token error: {error}")
            return False
    return True

# 在订阅循环中使用
while True:
    if not monitor_token_status(consumer):
        # Token 失效,等待管理员处理
        time.sleep(10)
        continue
    # 正常处理数据...
```

```sql
-- Consumer 无需重建,会自动恢复订阅
```

### 4.3 订阅性能优化

**合理设置参数:**

```python
conf = {
    'group.id': 'consumer_group',
    # 单次最大等待时间:1 秒
    'fetch.max.wait.ms': '1000',
    # 最少返回行数:10000
    'min.poll.rows': '10000',
}
```

**参数说明:**
- `fetch.max.wait.ms`:超过该时间即使没到 `min.poll.rows` 也返回,默认 1s
- `min.poll.rows`:达到该行数立即返回
- poll timeout:如果没有数据,超过 timeout 返回 NULL

**批量处理数据:**

```python
def batch_process(msg):
    """批量处理订阅数据,提升效率"""
    rows = []
    for record in msg:
        rows.append(record)
        
        # 每 1000 行批量插入
        if len(rows) >= 1000:
            insert_batch(rows)
            rows.clear()
    
    # 处理剩余数据
    if rows:
        insert_batch(rows)
```
