# 批量标签修改功能

## 一、功能背景与问题来源

### 1.1 业务痛点

在实际工业场景中,用户在进行元数据维护时经常遇到以下挑战:

**标签批量修改困难:**
- **子表数量巨大** - 千万级子表场景下,逐个修改标签耗时极长
- **无法批量清空标签** - 定期清理或重置标签值需要大量 SQL 语句
- **数据迁移工作量大** - 需要根据外部系统台账批量更新标签,人工操作容易出错
- **网络往返次数多** - 逐个修改子表需要大量网络往返,效率低下

### 1.2 典型场景示例

**场景一:设备标签定期更新**
- 问题:河北电力有 3000 万电表子表,需要每月根据外部台账批量更新设备标签 (区域、状态、用户等),逐个修改耗时数小时
- 影响:运维效率低,数据更新延迟影响业务

**场景二:数据清理和重置**
- 问题:设备维护记录标签需要每月初批量清空,3000 万条 SQL 语句难以管理
- 影响:脚本复杂,容易出错,运维成本高

**场景三:虚拟表标签批量修改**
- 问题:IDMP 项目需要批量更新、增加、删除虚拟子表的标签,逐个处理效率低
- 影响:业务自动化程度低,人工干预多

### 1.3 为什么需要批量标签修改?

**元数据批量操作是大规模应用的必备:**
- 千万级子表场景下,批量操作是刚需而非优化
- 与外部系统集成时,批量修改标签能大幅提升自动化水平
- 减少网络往返次数,提升修改效率

**TDengine 3.4.1** 通过支持一条 SQL 批量修改多个子表标签,大幅提升元数据维护效率。

## 二、功能介绍与核心特性

### 2.1 功能概述

支持一条 SQL 语句批量修改多个子表的标签,大幅提升大规模场景下的元数据维护效率。同时支持标签值设置为 NULL,实现标签清空功能。

### 2.2 语法格式

**语法一:多表逐个指定标签值**

```sql
ALTER TABLE tb1 SET TAG tag_11 = tag_val_11, tag_12 = NULL 
            tb2 SET TAG tag_21 = NULL, tag_22 = tag_val_22 
            ...;
```

**适用场景:**
- 每个子表的新标签值不同,需要逐个指定
- 典型场景:根据外部台账批量更新标签

**示例:**
```sql
ALTER TABLE 
  meter_d001 SET TAG region = '石家庄', status = 'active'
  meter_d002 SET TAG region = '保定', status = 'active'
  meter_d003 SET TAG region = '唐山', status = 'inactive';
```

**语法二:基于条件统一修改标签 (内部使用)**

```sql
ALTER TABLE USING stb 
SET tag1 = REGEXP_REPLACE(tag1, regexp, replacement), tag2 = NULL 
WHERE condition;
```

**适用场景:**
- 标签值可通过表达式统一计算或修改
- 典型场景:批量清空标签、批量替换标签值中的子串
- **注意:此语法仅供内部使用,不对外公开**

**示例 (内部使用):**
```sql
-- 批量替换虚拟表标签值中的特定子串
ALTER TABLE USING v_meters
SET region = REGEXP_REPLACE(region, '石家庄市', '石家庄')
WHERE region LIKE '%石家庄市%';
```

### 2.3 核心行为说明

**支持标签值设置为 NULL:**
- 标签值可以设置为 NULL,实现标签清空功能
- 清空后标签列依然存在,只是值为 NULL
- 适用于定期清理或重置标签值的场景

**批量修改事务性:**
- 批量修改过程中,某个子表修改失败会导致整个操作失败
- 已经修改成功的子表无法回滚
- 建议先在小范围测试,确认无误后批量执行

**性能特点:**
- 批量修改性能与逐个修改相当,主要优势在于操作便捷性
- 显著减少 SQL 语句数量和网络往返次数
- 千万级子表场景下,可将 3000 万条 SQL 优化为 3 万条 (每批 1000 表)

### 2.4 兼容性说明

**消息格式变更:**
- ALTER TABLE 消息格式有变更,需要客户端和服务端同时升级
- 新版客户端不支持旧版服务端,新版服务端也不支持旧版客户端

**版本升级:**
- 可从旧版本升级到 3.4.1,享受批量修改功能
- 也可从 3.4.1 降级为旧版,不影响已有数据

### 2.5 数据订阅和流计算支持

**数据订阅修改:**
1. VNode 修改标签时,会更新数据订阅的 tablelist
2. 订阅 meta 数据时,会根据新的 WAL 数据结构进行过滤
3. 数据迁移接口 `tmq_get_json_meta` 支持获取批量修改的 meta 消息 JSON 结构
4. 数据迁移写入目标数据库时,`taosAlterTable` 支持批量修改逻辑

**流计算支持:**
- 流计算读取 WAL meta 消息时,会处理 ALTER TAG 操作
- 支持批量标签修改的元数据同步

## 三、典型应用场景与价值

### 3.1 场景一:千万级子表标签批量更新

**业务需求:**
河北电力有 3000 万电表子表,每月需要根据外部台账系统批量更新电表的区域、状态、用户等标签信息。

**客户价值:**
- ✅ 一条 SQL 批量修改多个子表,大幅减少语句数量
- ✅ 支持标签值设置为 NULL,实现批量清空
- ✅ 降低网络往返次数,提升更新效率
- ✅ 简化批量操作脚本,降低运维复杂度

**实现方案:**

```sql
-- 批量更新电表标签 (每批 1000 个子表)
ALTER TABLE
  meter_d000001 SET TAG region = '石家庄', status = 'active', customer_name = '张三'
  meter_d000002 SET TAG region = '保定', status = 'active', customer_name = '李四'
  meter_d000003 SET TAG region = '唐山', status = 'inactive', customer_name = NULL
  ...
  meter_d001000 SET TAG region = '邯郸', status = 'active', customer_name = '王五';
-- 重复执行直到完成 3000 万子表更新
```

**批量脚本示例:**

```python
# Python 脚本示例:从外部台账读取数据并批量更新
import taos

# 连接数据库
conn = taos.connect(host='localhost', user='root', password='taosdata', database='power')
cursor = conn.cursor()

# 从外部台账读取更新数据 (假设为 CSV 文件)
import csv
with open('meter_updates.csv', 'r', encoding='utf-8') as f:
    reader = csv.DictReader(f)
    updates = list(reader)

# 每批 1000 个子表
batch_size = 1000
total = len(updates)

for i in range(0, total, batch_size):
    batch = updates[i:i+batch_size]
    
    # 构造批量修改 SQL
    sql_parts = []
    for row in batch:
        meter_id = row['meter_id']
        region = row['region']
        status = row['status']
        customer = row['customer_name'] if row['customer_name'] else 'NULL'
        
        part = f"{meter_id} SET TAG region = '{region}', status = '{status}', customer_name = {customer}"
        sql_parts.append(part)
    
    sql = "ALTER TABLE " + " ".join(sql_parts) + ";"
    
    # 执行批量修改
    try:
        cursor.execute(sql)
        print(f"已完成 {i+len(batch)}/{total} 个子表的更新")
    except Exception as e:
        print(f"批次 {i//batch_size + 1} 失败: {e}")
        # 记录失败批次,稍后重试
        with open('failed_batches.log', 'a') as log:
            log.write(f"Batch {i//batch_size + 1}: {e}\n")

cursor.close()
conn.close()
print("批量更新完成!")
```

**性能对比:**
- **优化前:逐个子表修改**
  - 3000 万条 SQL 语句
  - 需要数小时完成
  - 网络往返 3000 万次
- **优化后:批量修改**
  - 3 万条 SQL 语句 (每批 1000 表)
  - 显著减少网络往返和操作复杂度
  - 运维效率大幅提升

### 3.2 场景二:定期标签清理和重置

**业务需求:**
设备维护系统需要每月初批量清空所有设备的维护记录标签 (last_maintenance_date、last_maintenance_person),为新一月的维护记录做准备。

**客户价值:**
- ✅ 使用 NULL 值批量清空标签
- ✅ 一条 SQL 完成大量设备的标签重置
- ✅ 简化定期清理脚本

**实现方案:**

```sql
-- 每月初清空所有设备的维护记录标签 (每批 1000 个设备)
ALTER TABLE
  device_d000001 SET TAG last_maintenance_date = NULL, last_maintenance_person = NULL
  device_d000002 SET TAG last_maintenance_date = NULL, last_maintenance_person = NULL
  device_d000003 SET TAG last_maintenance_date = NULL, last_maintenance_person = NULL
  ...
  device_d001000 SET TAG last_maintenance_date = NULL, last_maintenance_person = NULL;
-- 重复执行直到完成所有设备
```

**自动化脚本示例:**

```bash
#!/bin/bash
# Shell 脚本示例:每月1号自动清空维护记录标签

# 配置
DB_HOST="localhost"
DB_USER="root"
DB_PASS="taosdata"
DB_NAME="iot"
BATCH_SIZE=1000

# 获取所有设备子表
taos -h $DB_HOST -u $DB_USER -p$DB_PASS -d $DB_NAME -s "SELECT tbname FROM devices" | tail -n +3 > device_list.txt

# 统计设备总数
TOTAL=$(wc -l < device_list.txt)
echo "总共 $TOTAL 个设备需要清空维护记录"

# 分批处理
BATCH_NUM=1
while read -r batch; do
    # 构造批量修改 SQL
    SQL="ALTER TABLE "
    for device in $batch; do
        SQL="$SQL $device SET TAG last_maintenance_date = NULL, last_maintenance_person = NULL"
    done
    SQL="$SQL;"
    
    # 执行
    echo "执行批次 $BATCH_NUM..."
    echo "$SQL" | taos -h $DB_HOST -u $DB_USER -p$DB_PASS -d $DB_NAME
    
    BATCH_NUM=$((BATCH_NUM + 1))
done < <(split -l $BATCH_SIZE - < device_list.txt)

echo "标签清空完成!"
rm device_list.txt
```

**业务价值:**
- 自动化定期清理,无需人工干预
- 减少运维脚本复杂度
- 提升数据管理规范性

### 3.3 场景三:虚拟表标签批量修改

**业务需求:**
IDMP 项目需要批量更新、增加、删除虚拟子表的标签。由于虚拟子表必须包含超级表的所有标签,删除标签等价于将标签值置为 NULL,增加标签等价于将标签值置为非 NULL 值。

**客户价值:**
- ✅ 支持虚拟表标签批量修改
- ✅ 通过 NULL 值实现标签"删除"
- ✅ 简化虚拟表元数据管理

**实现方案:**

```sql
-- 批量修改虚拟子表标签
ALTER TABLE
  v_device_001 SET TAG location = 'Building A', status = 'active', priority = 1
  v_device_002 SET TAG location = 'Building B', status = 'inactive', priority = NULL
  v_device_003 SET TAG location = 'Building C', status = 'active', priority = 2
  ...;
-- priority = NULL 相当于"删除"该标签
```

### 3.4 场景四:外部系统集成批量同步

**业务需求:**
ERP 系统每天凌晨推送设备基础信息变更数据,需要同步更新 TDengine 中的设备标签,包括设备名称、所属车间、负责人等。

**客户价值:**
- ✅ 自动化数据同步,无需人工干预
- ✅ 批量处理大幅提升同步效率
- ✅ 与外部系统无缝集成

**实现方案:**

```python
# Python 脚本示例:从 ERP API 获取变更数据并同步
import taos
import requests

# 连接数据库
conn = taos.connect(host='localhost', user='root', password='taosdata', database='manufacturing')
cursor = conn.cursor()

# 从 ERP API 获取设备变更数据
response = requests.get('http://erp-api.company.com/device-updates')
updates = response.json()['data']

# 每批 500 个子表
batch_size = 500

for i in range(0, len(updates), batch_size):
    batch = updates[i:i+batch_size]
    
    # 构造批量修改 SQL
    sql_parts = []
    for device in batch:
        device_id = device['device_id']
        name = device['name']
        workshop = device['workshop']
        owner = device['owner'] if device['owner'] else 'NULL'
        
        part = f"{device_id} SET TAG name = '{name}', workshop = '{workshop}', owner = {owner}"
        sql_parts.append(part)
    
    sql = "ALTER TABLE " + " ".join(sql_parts) + ";"
    
    # 执行批量修改
    try:
        cursor.execute(sql)
        print(f"同步完成 {i+len(batch)}/{len(updates)} 个设备")
    except Exception as e:
        print(f"同步失败: {e}")

cursor.close()
conn.close()
print("ERP 数据同步完成!")
```

**业务价值:**
- 实现 ERP 与 TDengine 的数据一致性
- 自动化同步,降低人工维护成本
- 提升数据准确性和时效性

## 四、运维最佳实践

### 4.1 批量操作建议

**分批操作:**
- 大规模修改建议每批 500-1000 个子表
- 避免单条 SQL 过大导致超时或内存溢出
- 示例:3000 万子表分 30000 批执行,每批 1000 表

**失败处理:**
- 单个子表修改失败会导致整批回滚
- 建议先在小范围测试 (如 10 个子表),确认无误后批量执行
- 记录已成功的批次号,失败后从断点继续
- 将失败批次记录到日志文件,稍后重试

**测试流程:**
```sql
-- 第一步:小范围测试
ALTER TABLE
  test_device_001 SET TAG region = '测试区域', status = 'test'
  test_device_002 SET TAG region = '测试区域', status = 'test';

-- 第二步:验证结果
SELECT * FROM test_device_001;
SELECT * FROM test_device_002;

-- 第三步:确认无误后批量执行
ALTER TABLE
  device_d000001 SET TAG region = '石家庄', status = 'active'
  device_d000002 SET TAG region = '保定', status = 'active'
  ...;
```

### 4.2 标签清空注意事项

**标签清空 vs 标签删除:**
- `SET TAG tag_name = NULL`:清空标签值,标签列依然存在
- 无法删除标签列本身 (需要修改超级表 schema)
- 清空后查询该标签返回 NULL

**清空标签的场景:**
- 定期清理临时标签 (如维护记录、备注信息)
- 重置标签为初始状态
- 删除不再需要的标签值 (但保留标签列)

**示例:**
```sql
-- 清空设备维护记录标签
ALTER TABLE
  device_d001 SET TAG last_maintenance_date = NULL, last_maintenance_person = NULL
  device_d002 SET TAG last_maintenance_date = NULL, last_maintenance_person = NULL;

-- 查询结果:标签值为 NULL
SELECT * FROM device_d001;
-- last_maintenance_date: NULL
-- last_maintenance_person: NULL
```

### 4.3 脚本编写建议

**使用参数化查询:**
```python
# 推荐:使用参数化查询,避免 SQL 注入
def batch_update_tags(cursor, updates, batch_size=1000):
    for i in range(0, len(updates), batch_size):
        batch = updates[i:i+batch_size]
        sql_parts = []
        
        for device_id, tags in batch:
            # 转义特殊字符
            tags_str = ", ".join([f"{k} = '{v}'" if v else f"{k} = NULL" 
                                  for k, v in tags.items()])
            sql_parts.append(f"{device_id} SET TAG {tags_str}")
        
        sql = "ALTER TABLE " + " ".join(sql_parts) + ";"
        cursor.execute(sql)
```

### 4.4 性能优化建议

**合理设置批次大小:**
- 批次过小:网络往返次数多,总耗时长
- 批次过大:单条 SQL 过大,可能超时或内存溢出
- 推荐:500-1000 个子表/批次
- 根据网络延迟和服务器性能动态调整

**并发执行:**
```python
# 多线程并发执行批量修改 (注意控制并发度)
from concurrent.futures import ThreadPoolExecutor
import taos

def execute_batch(batch_sql):
    conn = taos.connect(...)
    cursor = conn.cursor()
    try:
        cursor.execute(batch_sql)
        return True, None
    except Exception as e:
        return False, str(e)
    finally:
        cursor.close()
        conn.close()

# 最多 4 个并发连接
with ThreadPoolExecutor(max_workers=4) as executor:
    futures = []
    for i in range(0, len(updates), batch_size):
        batch = updates[i:i+batch_size]
        sql = construct_batch_sql(batch)
        futures.append(executor.submit(execute_batch, sql))
    
    # 等待所有批次完成
    for future in futures:
        success, error = future.result()
        if not success:
            print(f"批次失败: {error}")
```

**优化网络传输:**
- 批量修改主要减少网络往返次数
- 在高延迟网络环境下收益更明显
- 建议在业务低峰期执行大规模批量修改

## 五、总结

### 核心价值

TDengine 3.4.1 的批量标签修改为元数据管理带来了**显著效率提升**:

1. **大幅减少 SQL 语句数量** - 3000 万条优化为 3 万条,减少 99.9%
2. **降低网络往返次数** - 显著提升大规模场景下的修改效率
3. **支持标签清空** - 使用 NULL 值实现标签重置功能
4. **简化运维脚本** - 批量操作逻辑清晰,易于维护
5. **与外部系统无缝集成** - 支持自动化数据同步

### 功能清单

| 功能 | 核心特性 | 主要价值 |
| --- | --- | --- |
| 批量标签修改 | 一条 SQL 修改多表 | 大幅减少语句数量 |
|  | 支持标签值设置 NULL | 实现批量清空功能 |
|  | 支持虚拟表 | 虚拟表元数据管理 |
