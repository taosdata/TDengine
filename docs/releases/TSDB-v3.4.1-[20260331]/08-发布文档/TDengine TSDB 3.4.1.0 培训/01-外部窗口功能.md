# 外部窗口功能

## 一、功能背景与问题来源

### 1.1 业务痛点

在实际业务场景中，我们经常遇到这样的需求：**需要基于外部定义的时间窗口对数据进行聚合分析**，而这些窗口并不是基于当前数据自身产生的（如 session、state、event 窗口），而是来自于：

- **另一条时间线的事件** - 例如基于故障事件的时间窗口，分析告警事件的响应情况
- **外部系统提供的窗口** - 例如来自 MES/ERP 系统的生产计划时间段
- **业务规则定义的窗口** - 例如生产班次、设备维护窗口等特定时间范围

### 1.2 典型场景示例

**场景一：故障告警关联分析**
- 问题：当设备发生故障（fault 事件）后，需要分析 60 秒内是否收到告警（alarm 事件）
- 挑战：故障事件和告警事件来自不同的数据流，无法用传统的窗口函数处理

**场景二：电梯响应分析**
- 问题：按下电梯按钮（button 事件）后，需要找到第一次对应楼层的电梯门开启（door 事件）
- 挑战：需要在动态时间窗口内查找满足条件的事件

**场景三：能耗异常分析**
- 问题：识别设备能耗持续超标的异常窗口，并分析窗口内的工艺参数
- 挑战：需要基于事件窗口（能耗超标）关联分析其他传感器数据

### 1.3 为什么需要外部窗口？

传统的窗口函数（interval、session、event_window）都是基于**查询数据自身的时间线**生成窗口，无法满足"基于其他表或外部系统定义的窗口进行计算"的需求。**外部窗口**正是为了解决这一问题而设计的。

## 二、功能语法与基本使用

### 2.1 核心语法

```sql
SELECT select_list
FROM from_clause
[WHERE where_condition]
[PARTITION BY partition_list]
[EXTERNAL_WINDOW ((subquery) alias_name) [FILL(fill_mod)]]
[HAVING having_condition]
```

**关键要素：**
- **子查询（subquery）**：定义窗口的数据源，前两列必须是窗口的开始时间和结束时间（TIMESTAMP 类型）
- **alias_name**：窗口别名，用于在外部查询中引用窗口的列
- **FILL(fill_mod)**：可选，指定无数据窗口是否输出（当前版本仅支持 NONE）

### 2.2 窗口定义规则

1. **时间闭区间**：窗口默认为闭区间 `[start_ts, end_ts]`，即 `ts >= start_ts AND ts <= end_ts`
2. **窗口可重叠**：多个窗口的时间范围可以有交集，每个窗口独立计算
3. **窗口需有序**：窗口按 `start_ts` 递增排列（允许相同）
4. **窗口属性列**：子查询除前两列时间列外，其他列可在外部查询中引用

### 2.3 基础使用示例

**示例一：查找 60 秒内未响应的故障**

```sql
SELECT w.ts, w.event, w.val, COUNT(a.*), AVG(a.val)
FROM alarm1 a 
WHERE event = 6 
EXTERNAL_WINDOW (
  (
    SELECT ts, ts + 60s, event, val 
    FROM fault1
    WHERE event = 1
  ) w
)
HAVING COUNT(a.*) <= 0;
```

**功能说明：**
- 内部查询定义窗口：每个故障事件产生一个 60 秒的时间窗口
- 外部查询在窗口内统计：统计每个窗口内的告警事件数量
- HAVING 过滤：只保留没有告警响应的故障

**示例二：列出所有故障及其告警响应（含无告警故障）**

```sql
SELECT w.ts, w.event, w.val, a.ts, a.event, a.val
FROM alarm1 a 
WHERE event = 6 
EXTERNAL_WINDOW (
  (
    SELECT ts, ts + 60s, event, val 
    FROM fault1
    WHERE event = 1
  ) w
)
FILL(NONE);
```

**功能说明：**
- 使用 `FILL(NONE)` 后，即使窗口内没有匹配数据，窗口仍会输出
- 未匹配的列值显示为 `NULL`

### 2.4 伪列使用

外部窗口支持使用标准窗口伪列：

- `_WSTART`：窗口开始时间
- `_WEND`：窗口结束时间
- `_WDURATION`：窗口持续时间

```sql
SELECT _WSTART, _WEND, _WDURATION, COUNT(*)
FROM alarm1 a 
EXTERNAL_WINDOW (
  (SELECT ts, ts + 60s FROM fault1) w
);
```

### 2.5 使用限制

**本版本不支持：**
1. ❌ 在流计算（stream）中使用
2. ❌ 在订阅（subscribe）中使用
3. ❌ 窗口内使用不定行函数（如 `diff`、`interp`）
4. ❌ FILL 子句仅支持 `NONE`，不支持其他填充模式
5. ❌ WHERE 子句中引用窗口属性列

**支持的功能：**
1. ✅ `INSERT INTO ... SELECT` 语句
2. ✅ 窗口内聚合函数（COUNT、AVG、SUM、MIN、MAX、FIRST、LAST 等）
3. ✅ 窗口内标量计算
4. ✅ 嵌套使用外部窗口

## 三、典型应用场景与价值

### 3.1 场景一：设备故障响应监控

**业务需求：**
运维团队需要监控设备故障后的告警响应速度，识别未及时响应的故障。

**客户价值：**
- ✅ 实时发现故障响应延迟，降低设备停机时间
- ✅ 量化运维团队响应效率，支持 SLA 考核
- ✅ 识别高风险设备，优化运维资源分配

**实现方案：**

```sql
-- 统计每小时内故障的平均响应时间
SELECT deviceId, _WSTART, AVG(response_time) avg_response
FROM (
  SELECT w.ts, w.deviceId, 
         CASE WHEN FIRST(a.ts) IS NULL THEN 60 ELSE FIRST(a.ts) - w.ts END AS response_time
  FROM alarm a 
  WHERE event = 6 
  PARTITION BY deviceId
  EXTERNAL_WINDOW (
    (
      SELECT ts, ts + 60s, event, deviceId 
      FROM fault
      WHERE event = 1
      PARTITION BY deviceId
    ) w
  )
  ON a.deviceId = w.deviceId
)
PARTITION BY deviceId
INTERVAL(1h);
```

### 3.2 场景二：复杂事件序列识别

**业务需求：**
在工业控制场景中，需要识别"故障发生后 10 分钟内未恢复，且期间无车辆经过，且故障后 1 分钟内有两次告警"的异常模式。

**客户价值：**
- ✅ 识别复杂故障模式，提前预警潜在风险
- ✅ 减少误报，提高告警准确性
- ✅ 支持多维度事件关联分析

**实现方案（嵌套窗口）：**

```sql
SELECT w3.t1, w3.event, COUNT(a.*) 
FROM alarm1 a
EXTERNAL_WINDOW (
  (
    SELECT w2.t1, w2.t1 + 1m, w2.event, COUNT(c.*) 
    FROM car1 c
    EXTERNAL_WINDOW (
      (
        SELECT w1.t1, w1.t2, w1.event, COUNT(f2.*)
        FROM fault1 f2 
        WHERE event = 2 
        EXTERNAL_WINDOW (
          (
            SELECT ts t1, ts + 10m t2, event 
            FROM fault1 f1
            WHERE event = 1
          ) w1
        )
        HAVING COUNT(f2.*) <= 0
      ) w2
    )
    HAVING COUNT(c.*) <= 0
  ) w3
)
HAVING COUNT(a.*) = 2;
```

### 3.3 场景三：电梯响应时间分析

**业务需求：**
分析用户按下电梯按钮后，电梯到达对应楼层的响应时间。

**客户价值：**
- ✅ 评估电梯系统服务质量
- ✅ 识别响应慢的时段和楼层，优化调度算法
- ✅ 支持设备维护计划制定

**实现方案：**

```sql
-- 找到按钮事件后第一次对应楼层的电梯门开启时间
SELECT w.t1 AS button_time, 
       FIRST(d.ts) AS door_time,
       FIRST(d.ts) - w.t1 AS response_time
FROM door d
PARTITION BY deviceId
WHERE (w.event = 1 AND w.targetFloor = d.floor) 
   OR (w.event = 2 AND w.landingFloor = d.floor)
EXTERNAL_WINDOW (
  (
    SELECT ts t1, ts + 10m t2, event, targetFloor, landingFloor, deviceId
    FROM button
    PARTITION BY deviceId
  ) w
)
ON w.deviceId = d.deviceId
HAVING COUNT(d.*) > 0;
```

### 3.4 场景四：能耗异常窗口分析

**业务需求：**
在智能工厂中，需要识别"设备启动后能耗持续超标 5 分钟以上"的异常窗口，并统计异常窗口内的温度、压力等工艺参数，分析能耗异常的原因。

**客户价值：**
- ✅ 实时发现能耗异常，降低能源浪费
- ✅ 关联工艺参数，快速定位异常原因
- ✅ 为节能优化提供数据支撑

**实现方案：**

```sql
-- 使用 EVENT_WINDOW 生成能耗异常窗口，再分析窗口内的工艺参数
SELECT w.device_id,
       w.window_start,
       w.window_end,
       AVG(process.temperature) AS avg_temp,
       AVG(process.pressure) AS avg_pressure,
       MAX(process.power_consumption) AS max_power
FROM process_data process
PARTITION BY device_id
EXTERNAL_WINDOW (
  (
    SELECT device_id,
           _WSTART AS window_start,
           _WEND AS window_end,
           AVG(power_consumption) AS avg_power
    FROM energy_monitor
    PARTITION BY device_id
    EVENT_WINDOW
    START WITH power_consumption > power_threshold * 1.2
    END WITH power_consumption <= power_threshold * 1.1
    HAVING _WDURATION >= 5m
  ) w
)
ON process.device_id = w.device_id;
```

### 3.5 场景五：跨班次连续生产分析

**业务需求：**
生产线 24 小时连续运行，需要按照班次时间窗口（如早班、中班、夜班）统计各班次的产量、良品率、设备利用率等指标。

**客户价值：**
- ✅ 对比不同班次的生产效率，优化人员排班
- ✅ 识别特定班次的质量问题，加强培训
- ✅ 支持绩效考核和激励机制

**实现方案：**

```sql
-- 使用外部班次表定义窗口，统计各班次生产指标
SELECT w.shift_type,
       w.shift_start,
       COUNT(*) AS total_products,
       SUM(CASE WHEN quality = 'pass' THEN 1 ELSE 0 END) AS pass_count,
       SUM(CASE WHEN quality = 'pass' THEN 1 ELSE 0 END) * 100.0 / COUNT(*) AS pass_rate
FROM production_log p
PARTITION BY production_line
EXTERNAL_WINDOW (
  (
    SELECT production_line,
           shift_type,
           shift_start,
           shift_end
    FROM shift_schedule
    WHERE schedule_date >= '2026-04-01'
    PARTITION BY production_line
  ) w
)
ON p.production_line = w.production_line;
```

## 四、新增辅助函数

为配合外部窗口使用，TDengine 3.4.1 新增以下函数：

### 4.1 lag() 函数

**语法：** `lag(expr, offset[, default_value])`

**功能：** 在排序后取前第 N 行指定列的值

**参数说明：**
- `expr`：列名或表达式
- `offset`：偏移行数（只允许正值）
- `default_value`：可选，偏移行不存在时的默认值

**使用说明：**
- 本版本仅支持 offset = 1（即前一行）

**示例：**
```sql
-- 获取前一次告警事件的时间
SELECT ts, lag(ts, 1) AS prev_ts
FROM alarm;
```

### 4.2 lead() 函数

**语法：** `lead(expr, offset[, default_value])`

**功能：** 在排序后取后第 N 行指定列的值

**参数说明：**
- `expr`：列名或表达式
- `offset`：偏移行数（只允许正值）
- `default_value`：可选，偏移行不存在时的默认值

**使用说明：**
- 本版本仅支持 offset = 1（即后一行）

**示例：**
```sql
-- 获取下一次告警事件的时间
SELECT ts, lead(ts, 1) AS next_ts
FROM alarm;
```

## 五、总结

### 核心价值

外部窗口为 TDengine 带来了**跨时间线的窗口计算能力**，使工业场景的时序数据分析更加灵活强大：

1. **解决复杂关联分析** - 支持基于事件驱动的窗口定义，满足故障诊断、质量追溯等工业场景需求
2. **支持外部数据集成** - 可与 MES、ERP 等外部系统的业务数据协同工作
3. **提升分析灵活性** - 嵌套窗口支持复杂业务逻辑的多层过滤和聚合
4. **保持查询语义清晰** - 声明式语法，易于理解和维护
5. **适配工业实际需求** - 支持班次、批次、维护窗口等工业场景特有的时间维度

### 快速上手建议

1. **从简单场景入手** - 先尝试单表单窗口的基础用例
2. **理解窗口语义** - 明确窗口的时间闭区间和有序性要求
3. **善用伪列和辅助函数** - _WSTART、_WEND、lag()、lead() 等可简化查询
4. **注意使用限制** - 了解本版本暂不支持的场景，避免踩坑
