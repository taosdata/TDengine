# TDengine TSDB v3.4.1 考试答案

#### 1. 第一部分,笔试题目,所有人回答

1. **安全功能在哪几个维度有提升？**
   - 身份鉴别：强口令、多因素认证、登录控制
   - 访问控制：RBAC 权限模型、细粒度权限管控、强制访问控制
   - 传输安全：TLS+SASL 分层加密
   - 存储安全：全量透明存储加密、敏感数据安全删除
   - 安全审计：五级粒度审计、审计日志安全存储、审计日志直接记录到本集群
   - 防破解：防 SQL 注入、防溢出攻击和拒绝服务攻击

2. **虚拟表性能优化主要体现在哪些查询场景？**
   - 虚拟表投影查询
   - 虚拟表聚合函数和选择函数查询
   - 虚拟表窗口查询（Interval、Session、Event、State Window）
   - 虚拟表多列多表场景查询
   - 虚拟表单表引用场景查询
   - 虚拟表聚合查询 + GROUP BY

3. **数据订阅在哪些方面有提升？**
   - 在数据订阅时通过 enable.wal.marker 选项**延长 WAL 的保留时间**
   - 支持通过执行 RELOAD TOPIC 命令，使数据订阅无需重建即生效
   - 支持虚拟表元数据订阅（虚拟超级表和虚拟子表的创建、修改、删除）
   - 支持 Token 认证方式
   - 大幅优化订阅性能（大宽表场景提升显著）
   - 新增跨集群迁移配置参数（tmqWriteRefDB、tmqWriteCheckRef）

4. **流计算的事件窗口支持子事件窗口后，可以用于哪些场景？**
   
   适用于需要精细化监控复杂事件的场景，例如：
   - 工业设备故障分级监控（设备振动值≥60开启预警子窗口，≥90开启告警子窗口，振动值＜70关闭窗口）
   - 电力负荷波动监控（负荷≥80%开启常规波动子窗口，≥95%开启过载子窗口，负荷＜60%关闭窗口）
   - 环境监测多阈值预警（PM2.5≥75开启轻度污染子窗口，≥150开启重度污染子窗口，PM2.5＜50关闭窗口）

5. **流计算的 TRUE_FOR 表达式是什么含义？**
   
   TRUE_FOR 表达式用于 STATE_WINDOW 和 EVENT_WINDOW 窗口类型，定义窗口触发条件：
   - **基于时间触发**：TRUE_FOR(duration) - 条件持续满足指定时长后触发
   - **基于行数触发**：TRUE_FOR(COUNT n) - 累积 n 行数据后触发
   - **AND 逻辑**：TRUE_FOR(duration AND COUNT n) - 时间和行数都满足才触发
   - **OR 逻辑**：TRUE_FOR(duration OR COUNT n) - 时间或行数任一满足即触发

6. **流计算的分组空闲检测是什么含义？**
   
   分组空闲检测用于监控流计算中每个分组（如每个设备）是否长时间无数据上报：
   - 通过 `STREAM_OPTIONS(IDLE_TIMEOUT(duration))` 配置空闲阈值
   - 当某个分组超过指定时间未收到新数据时，触发 IDLE 事件
   - 当分组恢复上报数据时，触发 RESUME 事件
   - 适用于设备离线监控、数据链路故障检测等场景

7. **流计算定时触发 PERIOD 支持哪些自然时间单位，有什么用途？**
   
   **支持的自然时间单位：**
   - **w (周)**：PERIOD(1w) - 每周触发一次，默认每周一 00:00:00
   - **n (月)**：PERIOD(1n) - 每月触发一次，默认每月 1 日 00:00:00
   - **y (年)**：PERIOD(1y) - 每年触发一次，默认每年 1 月 1 日 00:00:00
   
   **主要用途：**
   - 周报表：统计上周的业务数据
   - 月报表：生成月度汇总、账单、财务对账等
   - 年度归档：年度数据统计、历史数据归档
   - 自然周期对齐：无需应用层计算时间对齐，直接使用自然日历周期

8. **解释一下非相关标量子查询？**
   
   非相关标量子查询是一种特殊的子查询：
   - **非相关**：子查询不依赖父查询的任何字段，可独立执行
   - **标量**：子查询返回单行单列的结果（一个标量值）
   - **用途**：可在 SELECT 列表、WHERE 条件、JOIN ON 条件、HAVING、ORDER BY 等位置使用，作为常量表达式
   - **执行次数**：每个子查询只执行一次，结果在父查询中重复使用

9. **外部窗口功能适用于哪些典型场景？**
   
   外部窗口适用于需要基于外部定义的时间窗口进行数据聚合的场景，例如：
   - **故障告警关联分析**：基于故障事件时间窗口，分析窗口内是否收到告警响应
   - **电梯响应分析**：基于按钮按下事件，查找窗口内第一次电梯门开启事件
   - **能耗异常分析**：基于能耗超标事件窗口，分析窗口内的工艺参数
   - **MES 系统集成**：基于外部生产计划时间段，统计设备运行数据
   - **跨数据流关联**：基于一个时间线的事件，分析另一个时间线的数据

10. **INTERVAL 窗口查询的 SURROUND 子句的作用是什么？**
    
    SURROUND 子句用于限制 FILL(PREV/NEXT/NEAR) 插值模式的数据探索范围：
    - **限制探索范围**：通过 surrounding_time_interval 参数指定数据探索的时间范围
    - **设置默认值**：当探索范围内未找到有效数据时，使用 fill_values 指定的默认值填充
    - **避免远距离填充**：防止使用过远的历史数据进行插值，保证数据合理性
    - **业务场景**：如只使用最近 2 小时数据填充，超过 2 小时则填充为 0

#### 2. 第二部分,笔试题目,售前交付回答

1. **外部窗口的子查询定义窗口时，前两列必须是什么类型？窗口是闭区间还是开区间？**
   
   - **前两列类型**：必须是 TIMESTAMP 类型，分别表示窗口的开始时间和结束时间
   - **窗口区间**：闭区间 [start_ts, end_ts]，即 `ts >= start_ts AND ts <= end_ts`
   - **排序要求**：窗口按 start_ts 递增排列（允许相同）
   - **可重叠**：多个窗口的时间范围可以有交集，每个窗口独立计算

2. **状态窗口零状态功能中，zeroth_state 过滤与 where 条件过滤的核心区别是什么？**
   
   - **zeroth_state 过滤**：先计算完整的状态窗口，再过滤掉零状态窗口，不影响窗口划分
   - **where 条件过滤**：先过滤数据，再基于剩余数据计算状态窗口，会改变窗口划分结果
   - **执行顺序不同**：zeroth_state 是窗口计算后过滤，where 是窗口计算前过滤
   - **应用场景**：zeroth_state 适用于需要基于完整窗口判断零状态的场景

3. **流计算中事件窗口触发支持子事件窗口的语法格式是什么？**
   
   ```sql
   EVENT_WINDOW(START WITH (start_cond_1, start_cond_2 [,...]) [END WITH end_cond])
   ```
   
   - **START WITH**：使用括号包含多个开始条件，每个条件独立判断
   - **子窗口触发**：当满足任一 start_cond 时，开启对应的子窗口
   - **END WITH**：所有子窗口共享同一个结束条件
   - **示例**：`START WITH (payload≥60, payload≥90) END WITH temperature<70`

4. **流计算的 TRUE_FOR 表达式增强后的语法格式是什么？**
   
   ```sql
   -- 仅基于时间
   TRUE_FOR(duration)
   
   -- 仅基于行数
   TRUE_FOR(COUNT n)
   
   -- AND 逻辑（时间和行数都满足）
   TRUE_FOR(duration AND COUNT n)
   
   -- OR 逻辑（时间或行数任一满足）
   TRUE_FOR(duration OR COUNT n)
   ```
   
   - **duration**：时间长度，如 10s、1m、1h
   - **COUNT n**：行数阈值，n 为非负整数（0 表示立即触发）
   - **AND/OR**：逻辑组合运算符

5. **流计算分组空闲检测中，IDLE 和 RESUME 事件的触发时机分别是什么？**
   
   - **IDLE 事件触发时机**：当某个分组超过 IDLE_TIMEOUT 指定的时间未收到新数据时触发
   - **RESUME 事件触发时机**：当处于空闲状态的分组重新收到数据时触发
   - **示例**：`STREAM_OPTIONS(IDLE_TIMEOUT(10m))` - 10 分钟无数据触发 IDLE，恢复数据时触发 RESUME
   - **应用**：IDLE 用于发送离线告警，RESUME 用于发送恢复通知

6. **INTERVAL 窗口查询的 SURROUND 子句的作用是什么？其参数 surrounding_time_interval 与 interval 的关系是什么？**
   
   **SURROUND 子句的作用：**
   - 限制 FILL(PREV/NEXT/NEAR) 插值的数据探索时间范围
   - 设置未找到有效数据时的默认填充值
   - 防止使用过远的历史数据进行插值
   
   **surrounding_time_interval 与 interval 的关系：**
   - **约束**：surrounding_time_interval 必须 ≥ interval
   - **计算**：实际探索窗口数 = floor(surrounding_time_interval / interval)
   - **示例**：INTERVAL(1h) SURROUND(80m, ...) → 探索 1 个窗口（floor(80/60)=1）
   - **示例**：INTERVAL(1h) SURROUND(59m, ...) → 探索 0 个窗口，直接使用默认值

7. **虚拟表引用校验功能提供了哪些新增系统表？各自的作用是什么？**
   
   **新增系统表：**
   - `INFORMATION_SCHEMA.INS_VIRTUAL_TABLES_REFERENCING`
   
   **作用：**
   - 记录虚拟表与源表之间的完整引用关系
   - 包含虚拟表的数据库名、表名、列名
   - 包含源表的数据库名、表名、列名
   - 提供错误码和错误信息，用于检测引用是否有效
   - 支持通过 `SHOW VTABLE VALIDATE FOR table_name` 命令验证虚拟表可用性

8. **EXPLAIN ANALYZE 中 exec_elapsed 和 input_wait_elapsed 指标的区别是什么？**
   
   - **exec_elapsed（算子执行时间）**：
     - 算子自身的实际计算时间
     - 不包含等待时间，只统计 CPU 计算开销
     - 用于判断算子计算是否是瓶颈
   
   - **input_wait_elapsed（等待下游数据时间）**：
     - 算子等待下游算子提供数据的时间
     - 表示算子处于空闲等待状态的时间
     - 用于判断下游算子是否是瓶颈
   
   **诊断价值：**
   - exec_elapsed 高 → 算子自身计算慢，需优化算法或数据量
   - input_wait_elapsed 高 → 下游算子慢，需优化下游算子

9. **批量标签修改功能支持哪两种语法格式？各自适用于什么场景？是否支持将标签值设置为 NULL？**
   
   **语法格式一：多表逐个指定标签值**
   ```sql
   ALTER TABLE tb1 SET TAG tag_11 = tag_val_11, tag_12 = NULL 
               tb2 SET TAG tag_21 = NULL, tag_22 = tag_val_22 
               ...;
   ```
   - **适用场景**：每个子表的新标签值不同，需要逐个指定
   - **典型场景**：根据外部台账批量更新标签
   
   **语法格式二：基于条件统一修改标签（内部使用）**
   ```sql
   ALTER TABLE USING stb 
   SET tag1 = REGEXP_REPLACE(tag1, regexp, replacement), tag2 = NULL 
   WHERE condition;
   ```
   - **适用场景**：标签值可通过表达式统一计算或修改
   - **典型场景**：批量清空标签、批量替换标签值中的子串
   - **注意**：此语法仅供内部使用，不对外公开
   
   **是否支持 NULL：**
   - ✅ 支持将标签值设置为 NULL
   - 实现标签清空功能（标签列仍存在，值为 NULL）
   - 适用于定期清理或重置标签值的场景

10. **解释一下 TLS 和 SASL 的作用？**
    
    - **TLS（Transport Layer Security）**：
      - 通用的加密传输机制
      - 保证数据在网络传输过程中的安全性与完整性
      - 防止数据被窃听、篡改或伪造
      - 适用于所有网络通信场景
    
    - **SASL（Simple Authentication and Security Layer）**：
      - 通过挑战-响应机制进行身份认证
      - 对于密码、密钥等关键信息，进行额外的加密传输
      - 在 TLS 基础上提供更强的认证安全性
      - 适用于需要双重加密保护的敏感信息传输
