| 项目 | 内容 |

| 变更申请编号 | BCR-3410-001 |

| 影响基线 | BL-3410-002（设计基线） |
| 变更类型 | 设计变更（安全漏洞修复） |

**变更原因：**

Risk-341-01（TDengine SQL 注入安全漏洞）修复方案确定后，需在 AST 级别引入危险函数白名单机制、强化 UDF 脚本函数调用权限管控、新增危险函数审计告警模块。上述变更涉及多处底层逻辑改动，超出初版设计文档（CI-3410-DS-001 v1.0）的描述范围，需通过基线变更正式纳入设计基线。

**变更内容：**

| 序号 | 变更项 | 变更前 | 变更后 |
| --- | --- | --- | --- |
| 1 | 危险函数管控机制 | 无专项管控 | 新增危险函数白名单机制，仅允许业务必需的系统函数调用 |
| 2 | UDF 权限管控 | 基础权限校验 | 强化 UDF 脚本函数调用权限管控，禁止调用危险系统函数 |
| 3 | AST 检测逻辑 | 基础函数调用检查 | 优化为异常函数调用精准识别，增强 AST 级别检测精度 |
| 4 | 审计告警 | 无 | 新增危险函数调用审计告警模块 |
| 5 | 危险函数规则库 | 无 | 建立危险函数黑名单规则库，支持定期更新维护 |

**影响分析：**

| 需求文档 | 无需变更需求基线（修复内容在原安全加固需求范围内） |

### 2.2 BCR-3410-002：Parquet 列投影行为变更（strict_projection 参数）

| 项目 | 内容 |
| --- | --- |
| 变更申请编号 | BCR-3410-002 |
| 申请日期 | 2026-02-25 |
| 申请人 | 霍琳贺 |
| 所属部门 | 研发部 |
| 影响基线 | BL-3410-001（需求基线）、BL-3410-002（设计基线） |
| 变更类型 | 功能增强变更 |

**变更原因：**

Risk-341-02（Parquet 数据源列投影静默过滤）应对措施确定后，需在现有 Parquet 查询接口中增加 `strict_projection` 参数，允许用户选择严格模式（指定列不存在时任务失败并报错，而非静默过滤）。同时需完善数据导入摘要报告，输出实际导入列数和被过滤列信息。上述改动涉及需求新增和接口设计变更，需通过基线变更正式纳入。

**变更内容：**

| 序号 | 变更项 | 变更前 | 变更后 |
| --- | --- | --- | --- |
| 1 | Parquet 列投影行为 | 列不存在时静默过滤并继续执行 | 默认行为不变；增加 strict_projection=true 选项，启用时列不存在则任务失败 |
| 2 | 导入摘要报告 | 无 | 任务完成后输出实际导入列数及被过滤列信息 |
| 3 | 文档说明 | 未说明静默过滤行为 | 在用户手册中明确列投影行为及最佳实践建议 |

**影响分析：**

| 影响范围 | 说明 |
| --- | --- |
| 需求文档 | CI-3410-FS-001 更新，新增 strict_projection 参数需求条目 |
| 设计文档 | CI-3410-DS-003 更新至 v1.1，补充参数设计及摘要报告输出逻辑 |
| 接口文档 | CI-3410-IF-001 补充 strict_projection 参数定义 |
| 测试用例 | 需新增列不存在的严格模式和默认模式对比测试（约 6 条用例） |
| 向后兼容 | 默认行为不变，严格模式为可选参数，不影响现有用户 |
