# S3 对象存储用户手册

TDengine 当前实现基于通用 S3 SDK，对各个 S3 平台的访问参数进行了兼容适配，可以访问如 minio, 腾讯云 COS等对象存储服务。

#### 1. 功能说明

TDengine 如果在配置文件 taos.cfg 中配置了合法的 S3 相关参数，那么在多级存储系统中，会把最后一级存储中存放时序数据的 data 文件上传到 S3 存储 ；即，只会对第二级或第三级进行处理，如果只有一级存储，数据均会存储在本地。主要流程有：
1，数据迁移，当最后一级某个数据文件一天（可配置）没有修改更新时，data 文件会被上传到 S3；
2，数据查询，涉及 S3 部分的数据会按需下载到内存，并在内存中缓存，后续查询可以直接读取 LRU 缓存中的数据。
3，数据写入，数据文件上传到 S3 后，写入对应文件相关的数据会在 TSDB 落盘的过程中忽略（相当于过期数据），如果存在 stt 文件则不会触发 merge 流程。
4，数据过期，当数据过期需要删除时，S3 上过期的 data 文件会同步删除；
5，数据删除，由于 TSDB 数据删除命令的实现是逻辑删除，相关信息均记录在本地，所以可以对所有级使用删除命令，与是否配置 S3 无关；当删除某个 DB 时，相关 vnode 的 S3 数据会一同被物理删除。
6，vgroup 操作, split 暂不支持。支持 redistribute 命令对 vnode 在 dnode 之间进行迁移操作；支持 DB 的副本变更，增加或减少副本数量。compact 操作需要在 data 文件上传到 s3 之前进行，或将文件下载到本地再操作。

#### 2. 配置参数

##### 2.1 访问控制参数：

| # | 参数 | 示例值 | 描述 |
| --- | --- | --- | --- |
| 1 | s3EndPoint | http://cos.ap-beijing.myqcloud.com | 用户所在地域的 COS 服务域名 |
| 2 | s3AccessKey | AKIDsQmwsfKxTo2A6nGVXZN0UlofKn6JRRSJ:lIdoy99ygEacU7iHfogaN2Xq0yumSm1E | 冒号分隔的用户 SecretId:SecretKey |
| 3 | s3BucketName | test0711-1309024725 | 存储桶名称，减号后面是用户注册 COS 服务的 AppId |

s3EndPoint 支持 http 和 https，bucket 的区域需要与 endpoint 的保持一致，否则无法访问。
其中 AppId 是 COS 特有，AWS 和阿里云都没有，配置时需要作为 bucket name 的一部分，使用减号分隔。参数值均为字符串类型，但不需要引号。多副本情况下，不同的 dnode 需要配置不同的 s3BucketName。

##### 2.2 数据上传及缓存参数：

| # | 参数 | 默认值 | 最小值 | 最大值 | 描述 |
| --- | --- | --- | --- | --- | --- |
| 1 | s3UploadDelaySec | 86400 | 600 | 2592000 (30天） | 默认最后一级存储 data 文件 1 天不再变动后上传至 s3，单位：秒 |
| 2 | s3PageCacheSize | 4096 | 4 | 1024*1024*1024 | s3 page cache 缓存页数目，单位：页 |

为保持兼容，之前的 s3BlockSize 及 s3BlockCacheSize 参数依然可以使用。

#### 3. 历史数据导入

当历史数据较多，导入时间较长，最后一级本地存储空间有限等情况下，可以按时间段分批次写入到最后一级，默认情况下，data 文件一天不再变动后将上传至 S3；如果按一个 duration 的时间完成一组文件的写入后，需要尽快腾出存储空间，可以 flush database 将内存中数据落盘，然后如有必要可以进行 compact 操作。
之后，可以将 s3UploadDelaySec 参数动态修改到最小值:
`alter dnode <dnodeId> 's3UploadDelaySec' '600';`
十分钟后（从 data 文件的最后修改时间开始）进行 trim database 操作（默认情况下，mnode 会每小时下发一次 trim 命令），data 文件将开始上传到 S3。
上传操作完成后，TSDB 会将本地已上传的 data 文件删除，释放存储空间，然后可以进行下一个批次的数据导入。
Data 文件上传到 S3 之后，继续写入对应时间段的数据，会在落盘时作为过期数据处理，所以为避免数据丢失，需要在 data 文件上传之前，flush database 或写入下一个时间段足够的数据，保证当前时间段的数据均已落盘（上传 S3 之前）。
如果要补写历史数据或进行 compact 操作，目前的版本则需要手动将文件下载到本地之后进行。

#### 4. 资源规划

最后一级的磁盘的空间需要考虑 head, tomb, sma，stt 文件及同时存在的 data 文件大小。具体预留空间的大小可以基于上一级存储进行估算，例如：
上一级和最后一级的 keep 分别是 10 天和 100 天，duration 是 1 天；
上一级最大 data 文件 10G，其它文件大小 100M；
则最后一级时序数据至少需要 100M * （100天/10天）+ 10G ～ 11G。

#### 5. 平台特性

文件大小：
COS 
- 简单上传：单个对象最大5GB。
- 分块上传：单个对象最大48.82TB（50，000GB），块大小1MB – 5GB，最后一个块可小于1MB，分块数1 – 10000。
阿里云基本类似，S3 单个对象最大5TB。
AWS S3 的相关规格可以参考相关链接。

#### 6. 通用 SDK 环境依赖

1. openssl
2. curl
3. libxml2

#### 7. COS SDK 环境依赖

1. cos-c-sdk
2. apr
3. apr-util
4. curl
5. Minixml
上述依赖已作为静态库依赖，无需安装。~~Ubuntu 平台可以通过下面命令安装:~~
```plaintext
sudo apt install libapr1-dev libaprutil1-dev libcurl4-openssl-dev libmxml-dev -y
```

apr-util 在编译时必须依赖 expat，编译环境可能需要安装：
```plaintext
sudo apt install -y libexpat1-dev
sudo yum install -y expat-devel
```
