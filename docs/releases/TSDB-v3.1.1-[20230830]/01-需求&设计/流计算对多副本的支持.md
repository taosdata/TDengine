# 流计算对多副本的支持

## 1. 设计目标

1. 流计算能够支持多副本 DB
2. 在多副本DB中能够支持 fill_history， pause/resume stream 等已经具备的能力
3. 在多副本DB中能够达到和单副本下相同水平的资源控制
4. 在多副本集群中一个 dnode 宕机导致部分 vgroup  发生切主时流计算能够无感知自适应 vgroup 切主
5. 流计算节点 snode 宕机重启后能够无感知继续进行流的计算
6. 能够人工或用脚本定时备份流计算状态存储相关文件
7. 如果出现磁盘损坏的情况，能够使用备份文件人工恢复流计算到上一次备份时的状态，并能够从此状态继续进行流的计算 （6/7 两点可以总结为以运维手段解决磁盘损坏丢失流计算状态数据的情况）
8. 极端情况下，如果无法从备份的文件恢复，或者没有备份文件，可以重新建流并从头开始计算。此种情况下性能无法保证，取决于存量数据大小，但要保证正确性。

## 2. 设计建议

本建议不做强制，供流计算小组参考。
为了能够适应 vgroup 切主，并且不使方案过于复杂，建议设计方案如下：
1. 单副本模式下保持现状，不使用独立的 snode 。无论从行为和实现上都不做任何变化。
2. 多副本模式下强制使用独立的 snode，可以从建流语句上就予以限定 create stream xxxxxx on snode yyyy。如果该 snode 不存在或不可用则报错拒绝建流。
3. snode 从 vgroup leader 拉取数据。如果 vgroup 发生切主， snode 能够自动适应。
4. snode 具备重启后自动恢复计算的能力
5. snode 具备从备份的 snapshot 自动恢复计算的能力
