### 9.2 异常场景

| case | 预期结果 | 测试结果 |
| --- | --- | --- |
| MQTT broker 宕机并重启 | MQTT broker 宕机无法连接时会报错 MQTT polling connection error: I/O: connection closed by peer，每隔一段时间重新连接超过 10 次任务报错退出，会由 taosx scheduler 重复调度重启任务，重新连接成功后消息正常消费，任务重启后如果连接失败会**立即失败退出**，再次由调度器重启 | ok |
| MQTT 带宽限制，连接超时 | 当网络带宽太小导致连接超时，会报错 MQTT polling connection error: Network timeout ， 断开连接，并每隔一段时间重新连接，超过10次后任务退出，会由 taosx scheduler 重复调度重启任务，重新连接成功后消息正常消费，任务重启后如果连接失败会**立即失败退出**，再次由调度器重启 | ok |
| MQTT 数据量远大于带宽 | MQTT 所在主机网卡上下行速度为 100 Kbps，发送数据大小为 409600 字节 数据量太大占满带宽会报错 MQTT polling connection error: Mqtt state: Last pingreq isn't acked MQTT polling connection error: Mqtt state: Io error: Custom { kind: ConnectionAborted, error: "connection closed by peer" } MQTT polling connection error: Mqtt state: Io error: Custom { kind: ConnectionReset, error: "connection reset by peer" } 现象： MQTT 无法消费，反复断开连接并重连 | 带宽限制恢复后，自动重新连接成功并继续消费 |
| client_id 相同导致客户端被踢下线 | v3: MQTT polling connection error: Mqtt state: Io error: Custom { kind: ConnectionAborted, error: "connection closed by peer" } v5: MQTT polling connection error: Mqtt state: Server sent disconnect with reason `None` and code 'SessionTakenOver' 任务自动重新连接成功，会把对方客户端下线，如果双方客户端都有自动重连机制，会互相踢 | ok |

### 9.4 可靠性

- MQTT 同步任务至少稳定运行 N 天
- 同步过程中制造 taosd 故障，检查故障恢复后同步任务是否可以自动恢复，是否会补救故障过程中的数据
- 同步过程中制造 taosd 长时间故障，检查 taosX 会缓存多少数据
- 同步过程中制造 taosapapter 故障，检查故障恢复后同步任务是否可以自动恢复，是否会补救故障过程中的数据
