# 需求说明：慢查询日志

## 1. 引言

### 1.1 优先级要求

有用户与 Jeff 单独沟通，需要尽快排期。

### 1.2 版本要求

企业版支持，社区版待与 Jeff 确认。

## 2. 需求目标

慢查询日志是一项关键的性能监控工具，其主要作用在于协助数据库管理员追踪执行时间较长的 SQL 查询语句。通过记录超过设定阈值的查询，为性能优化提供关键的线索，有助于发现潜在的性能瓶颈并重构查询语句，提升数据库的整体性能。
1. 在每条 SQL 执行结束，并且执行时间超过慢日志阈值时，会把 SQL 执行相关信息记录到慢日志中，同样的 SQL 多次执行都会记录。
2. 日志记录过程从客户端发起，有几种记录方式，建议采用方式一（可复用现有框架）。
   - 客户端将日志发送给 mnode，由 mnode 发送给 taoskeeper，再记录到其他集群（也可以是本集群）。
   - 客户端将日志发送给 taoskeeper，再记录到其他集群（也可以是本集群）。
   - 客户端将日志记录到本集群中。

## 3. 功能需求

### 3.1 配置参数

在服务端提供如下配置参数，客户端从服务端拉取这些参数的具体值。
1. enable_slow_log ：用于控制是否开启慢日志功能。默认值为 0，表示不打开。
2. slow_log_threshold：设置慢日志的阈值，执行时间超过阈值的 SQL 语句将被记录到慢日志中。默认值是 3000 ms。取值为 0 时表示记录所有语句。
3. slow_log_max_len：设置慢日志记录 SQL 语句的最大长度。默认值是 4096 byte。
4. enable_collect_detail_info：设置是否记录执行计划以及其他调试信息，默认值是 1。
5. only_record_failed_query：记录错误语句，无论是否达到时间阈值。默认值是 1。

### 3.2 记录字段

1. StartTs：表示该语句开始执行的时间。
2. QueryTime：表示执行该语句花费的时间。
3. Succ：表示该语句是否执行成功。
4. ErrorInfo：当语句执行失败时，记录错误信息。
5. Db：所属数据库。
6. User：执行 SQL 语句的用户。
7. IP：如有可能，记录执行 SQL 语句的 IP 地址。（通过 taosadapter 执行的 SQL 其 IP 相同，设计时看有无办法特殊处理）
8. Type：表示该 SQL 语句的类型。
9. RowsNum：结果集中的记录数目。
10. Query：表示该 SQL 语句的字符串。
11. Plan：表示该语句的执行计划。
12. Detail：表示该语句的其他关键执行信息。
13. ClientInfo：能够获取到的客户端信息，例如进程 ID 或者程序名称。
说明：建议把 Db、User、Succ、集群 ID、执行时间（分等级）作为标签，拼接起来作为子表名。

### 3.3 界面要求

1. 支持在 TDinsight 中展示。
2. 支持在 taosExplorer 中查看明细日志。

### 3.4 运维要求

1. 通过 SQL 语句查看当前慢日志配置参数的取值。
2. 通过 SQL 语句修改当前各慢日志配置参数的取值，在几秒钟之内生效。

## 4. 其他说明

1. 不记录数据写入语句 
2. 其他有助于分析性能的信息也应记录到慢日志中（需查询组进行确认），例如
   - 查询类型
   - 涉及节点数目
   - 是否用到预计算
   - 是否有普通列过滤
   - 扫描的磁盘大小
   - 占用内存
   - 嵌套层数
