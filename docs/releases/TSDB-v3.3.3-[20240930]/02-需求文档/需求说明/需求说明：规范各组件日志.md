# 需求说明：规范各组件日志

## 1. 需求背景

在 [撰写日志的基本要求](https://taosdata.feishu.cn/wiki/XgJDwCEf8iMEW2kA9mMcVqCinke) 中，明确描述了 TDengine 日志的具体要求，需将此文档落实到各个组件，包括
1. taos-explorer
2. taoskeeper
3. taosadapter
4. taosx
5. taosx-agent

## 2. 需求说明

1. 日志文件命名
   - 组件名称_YYYYMMDDHHMM.log
   - taoskeeper_2024_08_12_00_00.log -> taoskeeper_202408120000.log
2. 日志记录要求
   - 进程启动时，打印编译信息、GIT、版本号、配置信息、系统参数，连接的组件信息
   - 日志区分 trace、debug、info、warning、error 五个级别
   - 记录所有 SQL，包括 SQL 本身、执行 SQL 的 QID、执行开始时间、执行结束时间、执行结果、结果集数目
   - 记录对其他组件的调用，包括消息请求、对应的 URL、执行参数、执行开始时间、执行结束时间、执行结果
   - 记录来自其他组件的调用
   - 记录所有出错信息，包括内部错误、外部接口的异常、定时器超时等
   - 如果有资源的异步释放、任务的异步调度，需要打印日志
   - 记录文件打开、文件关闭，以及过程中的错误
   - 记录影响关键的判断分支的变量，并在合适的地方打印出来
   - 在 FS 中清晰描述 QID 的生成算法
3. 日志格式要求
   - 日志风格应该和 taosd 基本相同，包括线程 ID、模块简写（三个字母）、时间精确到微秒
   - 各关键字的分隔符为逗号（不是空格）
   - 不要采用双引号、中括号包围日志字符串
   - QID 在日志中用 qid 打印
   - 打印变量时采用 qid:0x23f422（不是qid=0x23f422）
4. 日志配置参数
   - 相同含义的参数与 taosd 保持一致，采用驼峰命名，已有的参数增加 alias
   - debugFlag：配置为 trace、debug、info、warning、error，而不是 131/135 这样的数字
   - logDir：日志文件夹，与 taosd 含义和默认值相同
   - minimalLogDirGB：日志文件夹所在磁盘可用空间达到一定阈值时停止写入，与 taosd 含义和默认值相同
   - rotationCount：同时保留的日志文件个数，默认 30 个
   - rotationTime：日志切分的时间，默认 24 小时
   - rotationSize：日志切分的大小，默认 1000 MB；rotationTime 和 rotationSize 任一条件满足则切分文件
   - logCompress：0-不压缩，1-压缩，默认不压缩
   - taosd 的历史配置参数（logKeepDays、numOfLogLines） 保持不变
