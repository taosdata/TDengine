# 删除事务的运维工具

## 1. 背景

当一个事务卡住，无法恢复时，为了恢复集群需要删除掉这个事务，但是这时可能因为这个事务导致，mnode无法启动。出现这种情况的场景应该是事务本身的bug。这时无法使用kill transaction删除事务，只能采用挂gdb的方式，删除这个事务。这种方法费时费力，并且出问题的原因不同，gdb的挂载点也不一样，执行的脚本也不一样，leader和follower角色也要考虑在内，每次都要重新想方案。
提供一个运维工具，在任何场景下都可以删除所有事务。该工具不对用户开放，也不对交付同学开放。因为强行删除事务，会导致mnode中元数据与vnode的状态不一致，导致不可逆的后果。

## 2. 实现原理

从sdb.data文件中读取出所有mnode对象，然后重新写入到sdb.data文件，在写入的过程中，如果发现对象是transaction类型则跳过，这样就相当与删除了所有事务。

## 3. 使用方法

1.退出所有mnode节点
2.备份sdb.data文件
3.在每个mnode节点上分别执行 taosd -dTxn
4.备份mnode wal目录，并且删除mnode wal中的所有文件
5.重启所有mnode节点
