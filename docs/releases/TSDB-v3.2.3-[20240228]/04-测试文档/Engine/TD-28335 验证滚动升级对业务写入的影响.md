# TD-28335 验证滚动升级对业务写入的影响

### 1. 概述：

测试需求：[集群滚动升级标准操作流程（暂行）](https://taosdata.feishu.cn/wiki/KejrwbnWPi5OhtkXqz4cafKXnKn) 
测试目的主要是验证集群（尤其是多副本）滚动升级过程中，对线上业务的影响时间。

### 2. 测试环境：

192.168.1.176(taosd)主：
CPU: 4核
Mem: 8 GB
Disk: 300GB
192.168.1.54(taosd)：
CPU: Intel(R) Xeon(R) CPU E5-2650 v3 @ 2.30GHz （2）40核
Mem：250G
Disk:  874GB
192.168.1.228(taosd)：
CPU: Intel Core Processor (Haswell, no TSX, IBRS) 32核
Mem：64G
Disk:  200GB

### 3. 测试步骤：

1. 搭建3节点，启动集群所有dnode节点为ready状态
2. 开始使用taosBenchmark工具创建数据库及表
   - vgroup 10
   - replica  3
   - buffer 512
   - childtable_count 1000
   - insert_interval 500 ms
3. 开始写入，持续10分钟
4. 停止228的dnode，准备升级到3.2.2.2
5. 5分钟后启动228的dnode，发现cpu会到356%持续3秒后恢复
6. 停止54节点，准备升级到3.2.2.2，查看show vnodes到达restored状态是true
7. 启动54节点，cpu会到70%持续2秒后恢复
8. 停止176节点，准备升级到3.2.2.2，查看show vnodes到达restored状态是true
9. 启动176节点，cpu会到70%持续2秒后恢复

### 4. 总结：

1. 滚动升级过程中未发现cpu长时间处于飙高的情况
2. 整个升级过程符合预期
