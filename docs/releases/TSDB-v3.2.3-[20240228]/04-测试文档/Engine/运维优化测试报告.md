## 2. 测试结论

-  Redistribute vgroup 在单副本情况下阻塞写入的时间大幅缩短，写入相同数据量的时间，优化前需要 100s 以上，优化后只需要 70s 左右，测试通过；
- Split vgoup 在单副本情况下阻塞写入的时间大幅缩短，写入相同数据量的时间，优化前需要 160s 到 180s，优化后只需要 60s 到 80s，测试通过
-  在 dnode 为空并且 offline 的情况下，drop dnode 命令可以直接删除掉空的 dnode，测试通过

## 3. 测试方法

**功能测试**：执行 redistribute vgroup， split vgroup， drop dnode 指令可以成功完成指定的操作并正常结束退出
**性能测试**步骤如下：
1. 三节点集群写入 150G 原始数据 (vgroups: 20, tables: 1000000, rows per table: 15000)
2. 使用 taosBenchmark 写入 1一条记录，建表成功后，执行 redistribute / split vgroup 操作
3. 记录写入数据的时间以及 redistribute / split vgroup 命令的执行时间
4. 在 3.0 分支和 main 分支分别执行步骤上述步骤（1~3），对比数据写入时间以及命令执行时间
5. 在 3.1 分支和 优化后的 3.1 分支分别执行步骤上述步骤（1~3），对比数据写入时间以及命令执行时间
