# 若干运维管理命令优化-功能说明

## 1. 背景

优化若干运维管理的命令或软件行为方式；涉及单副本库redistribute和split的读写阻塞时间优化，以及空dnode删除调整等。

## 3. 定义

| **名词** | **说明** |
| --- | --- |
| 空dnode | 不含vnode、mnode、qnode、及snode等的dnode节点 |
| 成员变更 | 虚拟组（vgroup）增加或减少虚拟节点（vnode）的配置变化过程，我们称之为成员变更。 |

## 4. 行为说明

涉及运维管理命令的用户使用方式和基本功能逻辑，均未发生变化；仅对在特定场景下的行为方式，做了调整优化。
**注意**：
1. 由于这些管理命令均是现有功能，不熟悉的读者，需首先阅读相关用户手册。
2. 相关功能用户使用方式和基本功能逻辑描述，请参考官网用户手册（https://docs.taosdata.com/）。

### 4.1 副本节点迁移 - redistribute vgroup

多副本库，redistribute vgroup 已经不会长时间阻塞读写；故本次优化只涉及单副本库。
**参考命令**
```c
redistribute vgroup <vgId> dnode <did>;
```

**优化前**
单副本库vgroup，副本节点迁移时，尤其是在快照复制阶段，在迁移完成之前，读写全程阻塞。
**优化后**
单副本库vgroup，副本节点迁移时，通过 learner 机制，把读写阻塞时间，缩短到副本数 1->2->1 过程中的成员变更时间。
**注意**：当前优化，不涉及副本迁移效率以及成员变更等时间。

### 4.2 虚拟组分裂 - split vgroup

多副本库，split vgroup 已经不会长时间阻塞读写；故本次优化只涉及单副本库。
**参考命令**
```c
split vgroup <vgId>;
```

**优化前**
单副本库 vgroup，分裂时，在副本1->2阶段，尤其是在快照复制阶段，读写全程阻塞。
**优化后**
单副本库 group，副本数 1->2 过程中副本复制阶段，通过 learner 机制，从而把读写阻塞时间，缩短到子表等元数据重整以及成员变更时间。
**注意**：本次优化，不涉及副本迁移效率、子表等元数据重整、以及成员变更等时间。

### 4.3 空 dnode 删除 - drop dnode

存在数据的 dnode（例如存在mnode、vnode、qnode、或snode等），删除逻辑保持不变；本次优化只涉及空 dnode （即不存在 mnode, vnode, qnode, snode）的删除。
**参考命令**
```c
drop dnode <dnode_id>;
```

**优化前**
空 dnode，如果离线，将不能删除。
**优化后**
空 dnode，无论是否在线，均可正常删除。
**注意**：本次优化，主要为解决dnode被误添加场景的问题。
