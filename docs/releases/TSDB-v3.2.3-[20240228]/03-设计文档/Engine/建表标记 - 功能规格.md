# 建表标记 - 功能规格

## 1. 背景

如果一个子表或普通表创建之后没有写入数据，那么在第一次查询缓存 last/last_row 后，会在缓存中做一个标记，这样在后续查询中便不需要再次从原始数据中扫描加载目标 last/last_row 值，可以加快后续的查询速度。
然而，第一次查询时仍然需要从原始数据扫描，造成第一次查询速度慢，故在创建表时需要在缓存中做一个标记，这样第一次查询速度也会很快。
类似的，当给表增加列时，标记新增加的列为空列，这样在查询此列时，就不需要去扫描原始数据，而可以直接返回空列。

## 3. 定义

缓存 last/last_row 查询： 指 DB 参数 cachemodel 为 'both', 'last_value' 或 'last_row' 三种情况下，查询计划指定部分 last/last_row 语句通过 tsdb 缓存进行查询。

## 4. 行为说明

原有行为逻辑不受影响，主要对两个方面改进优化，增加表或列时，在缓存中做一个标记，提升查询速度；另一方面，删除表或列时，把缓存中的相应数据删除，这里的缓存包括内存缓存和 rocks 持久化的缓存。涉及需要调整的行为包括：
1. 创建子表，此时在缓存中做空表标记。
2. 删除子表，删除缓存中此表的数据。
3. 创建普通表，此时在缓存中做空表标记。
4. 删除普通表，删除缓存中此表的数据。
5. 普通表添加列或删除列，添加时在缓存中做空列标记，删除时把缓存中此列的数据删除。
6. 超级表添加列或删除列，添加时在缓存中把其对应的所有子表做空列标记，删除时把缓存中把其对应的所有子表此列的数据删除。
优化前，对于空表的查询会在第一次查询后，在缓存中做个空表标记，后续查询使用此标记，不再需要从原始数据中重新加载。
优化后，如果缓存被打开（'both', 'last_value' 或 'last_row'），当创建子表或普通表时，就会在缓存中做个空表标记，这样第一次查询时就会使用此标记，不需要扫描原始数据。这样可以避免新建表对查询性能的影响，也会缩短内存缓存的预热时间。

## 5. 性能

这个优化主要是解决空表情况下第一次缓存 last/last_row 查询速度问题，通过在建表时对缓存做一个标记，避免空表情况下从原始数据中扫描。
