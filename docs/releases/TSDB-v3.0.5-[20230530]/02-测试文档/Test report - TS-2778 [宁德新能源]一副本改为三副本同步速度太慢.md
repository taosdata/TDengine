# Test report - TS-2778 [宁德新能源]一副本改为三副本同步速度太慢

**概述**：
客户问题是通过命令“alter database replica 3” 实现从单副本转成3副本时, 数据同步时间太慢，16G的数据同步十几个小时，目的是单副本转多副本场景下的数据同步时间优化。

环境信息：
192.168.1.61：
CPU: Intel(R) Xeon(R) CPU E5-2650 v3 @ 2.30GHz （2）40核
Mem：DDR4 16GB * 16
Disk:  893GB
192.168.1.35：
CPU: Intel(R) Xeon(R) CPU E5-2630 v2 @ 2.60GHz （2）24核
Mem: DDR3  32 GB * 2
Disk: 2792GB
102.168.1.63：
CPU: Intel(R) Xeon(R) CPU E5-2650 v3 @ 2.30GHz（2）40核
Mem: DDR4 16GB* 16
Disk: 895GB
**测试用例：**
场景1（在非写入场景）：
1. 搭建三节点测试环境
2. 通过taosBenchmark创建单副本db并写入一亿条数据
3. 在任一节点执行select count（*）统计写入的数据条数
4. 在任一节点随机选择三个子表的数据，导出csv数据文件
5. 执行命令alter database replica 3；
6. 通过show vgroups命令查看每个dnode节点添加vnode的角色变化，通过show transactions查看3副本转换过程是否完成
7. 3副本转换完成后，停掉任一dnode节点，在另一个dnode节点执行select count（*）命令，数据条数与单副本下的数据条数一致
8. 导出step d中的三个子表的数据，导出csv数据文件，并与step d中的数据文件对比，数据一致
9. 统计每秒数据同步数（MB) (注：3副本数据同步过程中会按表进行扫描，合并，磁盘占用空间小于单副本interlace写入的磁盘占用，以实际同步数据除以总时间计算结果)

场景2（在持续写入场景下）：
1. 搭建三节点测试环境
2. 修改taosBenchmark 参数trying_interval 为1秒，通过taosBenchmark创建单副本db持续写入数据，数据总量一亿
3. 数据写入超过2000万时，执行命令alter database replica 3；
4. 通过show vgroups命令查看每个dnode节点添加vnode的角色变化，通过show transactions查看3副本转换过程是否完成
5. 3副本转换完成后，停掉任一dnode节点，在另一个dnode节点执行select count（*）命令，在不同dnode上数据条数一致
6. 随机导出三个子表的数据，导出csv数据文件
7. 打开停掉的dnode节点，关闭另一个dnode节点，导出以上三个子表的数据，与step f中的数据文件对比，数据一致
8. 统计每秒数据同步数（MB) (注：3副本数据同步过程中会按表进行扫描，合并，磁盘占用空间小于单副本interlace写入的磁盘占用，以实际同步数据除以总时间计算结果)

**测试结果：**

|  | 结果描述 |
| --- | --- |
| 功能 | 1. 两种场景下，单副本转多副本都能完成 1. 在持续写入场景下，在增加vnode节点时，写入过程会有短暂block，添加vnode后，能够继续写入 1. 在持续写入场景下，如果写入数据量较大或vnode数较多，可能会出现选主时间较长（目前看大于2000w的写入数据量，选主时间会在2-4分钟） 1. 两种场景下，保证数据一致 |
| 性能 | 场景1： 同步数据量7G 单副本变3副本完成时间11 分钟 每秒同步数据量：~~10.9 M/S ~~21.8 MB/S 场景2： 同步数据量7G 单副本变3副本完成时间22 分钟 每秒同步数据量：~~5.4 M/S ~~10.8 MB/S 注：以上性能数据计算应乘以2，从单副本变3副本，同步数据量是2倍的单副本数据量。 |

**测试总结：**
1. 单副本转换多副本顺序是根据每个dnode节点，分别增加副本vnode；每个dnode在添加第一个vnode时，vnode角色会变成learner，当wal追平当前的leader节点时，增加的vnode节点角色为follower，原leader vnode角色变为candidate；直到数据落盘后，选主完成，继续增加下一个vnode，从增加第三个vnode开始，增加的vnode不会进入learner角色
2. 在多副本数据同步过程中，会按表进行数据扫描、同步，所以在磁盘占用上会比通过taosBenchmark 以interlace_rows写入的数据占用磁盘空间小
3. 数据一致性验证使用数据总条数及随机子表数据对比方式验证，建议有一个工具对数据一致性做有效校验
