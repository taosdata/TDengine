# last\last_row性能优化

## 1. 需求来源

3.0.5.0中客户对last、last_row查询性能提升的诉求

## 2. 测试重点

功能测试为辅，性能测试为主
1、last支持缓存所有列，同时支持按各种列缓存（并考虑搭配上tag的过滤）。
2、大宽表部分列的测试（尤其是长庆场景中4K以上的 bianry 列）。
3、NULL/NONE 值较多时的验证。
4、写入性能、读取性能会由浩然的tsbs进行第一轮的性能对比，看看各个指标下降了多少。
5、对各子表的查询验证，包括group by tbname或者partition by tbname。
6、主从切换后last缓存及数据验证。
7、插入乱序数据等。
8、删除已缓存过last数据的时间段数据。
9、边删除边插入测试。
10、单副本三副本切换测试。
11、schema 修改。
12、重启后查询性能（对比首次加载速度）。
