## 1. 优化目标

针对流计算中暴露出来的突出问题：
1) 算子状态量持久化消耗 IO 资源过多
2） task 的 input queue 大小不可控，如果流计算的性能低于写入的性能，会导致数据在 task 的 input queue 中堆积，从而导致内存持续上涨
3）input queue 中的数据堆积，导致无法快速停止vnode.
上述的这些问题涉及以下的 10 个 Jira：
[TS-2964](https://jira.taosdata.com:18080/browse/TS-2964) - [nevados] tq 目录占用大量空间 **BLOCKED**
[TS-3088](https://jira.taosdata.com:18080/browse/TS-3088) - macOS taosd 无法停止服务 **BLOCKED**
[TD-21457](https://jira.taosdata.com:18080/browse/TD-21457) - [TSma] tsma 结果推送过慢 **BLOCKED**
[TD-21497](https://jira.taosdata.com:18080/browse/TD-21497) - [TSma] tsma cpu 和内存占用过高 **BLOCKED**
[TD-22198](https://jira.taosdata.com:18080/browse/TD-22198) - in cloud service platform, memory grows up very fast after creating stream **BLOCKED**
[TD-22834](https://jira.taosdata.com:18080/browse/TD-22834) - stream 磁盘占用过高 **BLOCKED**
[TD-22961](https://jira.taosdata.com:18080/browse/TD-22961) - taosd exit stream object leak memory streamExec.c:92 **BLOCKED**
[TS-2633](https://jira.taosdata.com:18080/browse/TS-2633) - [nevados] the specified stream will lead the TDengine OOM at once **BLOCKED**
[TS-3057](https://jira.taosdata.com:18080/browse/TS-3057) - instance first OOM then crash after restarting **BLOCKED**
[TD-22431](https://jira.taosdata.com:18080/browse/TD-22431) - 当写入的时候，与流计算同时运行，出现磁盘IO瓶颈的时候，流计算仍然会累积消息，占用内存，导致OOM **PENDING**

期望的到的优化效果如下：
1. 在流计算运行的情况下，不论写入频率如何，taosd 不会出现内存占用失控
2. 流计算能够在taosd crash以后， taosd 重启以后，继续正常运行并返回正确的结果
3. 流任务占用的磁盘空间（用于存储算子状态量）显著缩小，一般意义上，应该是远小于原始数据，当然这个结论与聚合窗口的大小有关系。
4. 流任务运行过程中消耗的 IO 资源显著缩小，不会由于（单个）流计算任务导致的磁盘 IO 资源被完全占据。
5. taosd 能够快速停机，不会出现由于流计算任务没有完成执行，导致 taosd 长时间执行无法停机
此外，上述的 10 个 Jira 应该是不会再出现。
