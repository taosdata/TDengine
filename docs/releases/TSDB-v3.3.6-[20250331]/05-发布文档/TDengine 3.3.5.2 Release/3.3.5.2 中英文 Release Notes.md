# 3.3.5.2 中英文 Release Notes

### 1. 中文

```markdown

### 2. 特性

   - TD-33044 特性：taosX MQTT 数据源支持根据模板创建多个超级表

### 3. 优化

   - TD-33259 优化：改进 taosX 数据库不可用时的错误信息
   - TD-33409 优化：使用 Poetry 标准管理依赖项并减少 Python 连接器安装依赖项
   - TD-33422 优化：taosX 增量备份和恢复优化
   - TS-5651  优化：在多级存储数据迁移过程中，如果迁移时间过长，可能会导致 Vnode 切主
   - TS-5879  优化：调整 systemctl 守护 taosd 进程的策略，如果 60 秒内连续三次重启失败，下次重启将推迟至 900 秒后

### 4. 修复

   - TS-5836  修复：maxRetryWaitTime 参数用于控制当集群无法提供服务时客户端的最大重连超时时间，但在遇到 Sync timeout 错误时，该参数不生效
   - TS-5906  修复：支持在修改子表的 tag 值后，即时订阅到更新后的 tag 值。
   - TD-32471 修复：数据订阅的 tmq_consumer_poll 函数调用失败时没有返回错误码
   - TD-33390 修复：当创建超过 100 个视图并执行 show views 命令时，taosd 可能会发生崩溃
   - TD-33417 修复：当使用 stmt2 写入数据时，如果未绑定所有的数据列，写入操作将会失败
   - TD-33419 修复：当使用 stmt2 写入数据时，如果数据库名或表名使用了反引号，写入操作将会失败。
   - TD-33435 修复：关闭 vnode 时如果有正在进行的文件合并任务，taosd 可能会崩溃
   - TD-33440 修复：频繁执行 drop table with `tb_uid` 语句可能导致 taosd 死锁
   - TD-33444 修复：日志文件切换过程中可能出现的死锁问题
   - TD-33450 修复：禁止创建与系统库（information_schema, performance_schema）同名的数据库
   - TD-33465 修复：当嵌套查询的内层查询来源于超级表时，排序信息无法被上推
   - TD-33470 修复：通过 STMT 接口尝试写入不符合拓扑规范的 Geometry 数据类型时误报错误
   - TD-33473 修复：在查询语句中使用 percentile 函数和会话窗口时，如果出现错误，taosd 可能会崩溃
   - TD-33475 修复：无法动态修改系统参数的问题
   - TD-33484 修复：订阅同步偶发 Translict transaction 错误
   - TD-33498 修复：同一消费者在执行取消订阅操作后，立即尝试订阅其他不同的主题时，会返回错误
   - TD-33502 修复：Go 连接器安全修复 CVE-2022-28948
   - TS-5869  修复：当视图中的子查询包含带别名的 ORDER BY 子句，并且查询函数自身也带有别名时，查询该视图会引发错误
   - TS-5872  修复：在将数据库从单副本修改为多副本时，如果存在一些由较早版本生成且在新版本中已不再使用的元数据，会导致修改操作失败。
   - TS-5878  修复：在使用 SELECT * FROM 子查询时，列名未能正确复制到外层查询
   - TS-5900  修复：对字符串类型数据执行 max/min 函数时，结果不准确且 taosd 可能会崩溃
   - TS-5862  修复：流式计算不支持使用 HAVING 语句，但在创建时未报告错误
   - TS-5861  修复：taos shell 显示的服务端版本信息不准确，例如无法正确区分社区版和企业版。
   - TS-5863  修复：在某些特定的查询场景下，当 JOIN 和 CAST 联合使用时，taosd 可能会崩溃。


```

### 5. English

```markdown

### 6. Features

   - TD-33044 feat: taosX now support multiple stables with template for MQTT

### 7. Enhancements

   - TD-33259 enh: improve taosX error message if database is invalid
   - TD-33409 enh: use poetry group depencencies and reduce dep when install
   - TD-33422 enh: improve backup restore using taosX
   - TS-5651  enh: during the multi-level storage data migration, if the migration time is too long, it may cause the Vnode to switch leader
   - TS-5879  enh: adjust the systemctl strategy for managing the taosd process, if three consecutive restarts fail within 60 seconds, the next restart will be delayed until 900 seconds later.

### 8. Fixes

   - TS-5836  fix: the maxRetryWaitTime parameter is used to control the maximum reconnection timeout time for the client when the cluster is unable to provide services, but it does not take effect when encountering a Sync timeout error
   - TS-5906  fix: supports immediate subscription to the new tag value after modifying the tag value of the sub-table
   - TD-32471 fix: the tmq_consumer_poll function for data subscription does not return an error code when the call fails.
   - TD-33390 fix: taosd may crash when more than 100 views are created and the show views command is executed.
   - TD-33417 fix: when using stmt2 to insert data, if not all data columns are bound, the insertion operation will fail.
   - TD-33419 fix: when using stmt2 to insert data, if the database name or table name is enclosed in backticks, the insertion operation will fail.
   - TD-33435 fix: when closing a vnode, if there are ongoing file merge tasks, taosd may crash.
   - TD-33440 fix: frequent execution of the “drop table with tb_uid” statement may lead to a deadlock in taosd
   - TD-33444 fix: the potential deadlock during the switching of log files
   - TD-33450 fix: prohibit the creation of databases with the same names as system databases (information_schema, performance_schema).
   - TD-33465 fix: when the inner query of a nested query come from a super table, the sorting information cannot be pushed up.
   - TD-33470 fix: incorrect error reporting when attempting to write Geometry data types that do not conform to topological specifications through the STMT interface
   - TD-33473 fix: when using the percentile function and session window in a query statement, if an error occurs, taosd may crash
   - TD-33475 fix: the issue of being unable to dynamically modify system parameters
   - TD-33484 fix: random error of tranlict transaction in replication
   - TD-33498 fix: the same consumer executes the unsubscribe operation and immediately attempts to subscribe to other different topics, the subscription API will return an error
   - TD-33502 fix: fix CVE-2022-28948 security issue in go connector
   - TS-5869  fix: when a subquery in a view contains an ORDER BY clause with an alias, and the query function itself also has an alias, querying the view will result in an error.
   - TS-5872  fix: when changing the database from a single replica to a mulit replica, if there are some metadata generated by earlier versions that are no longer used in the new version, the modification operation will fail
   - TS-5878  fix: column names were not correctly copied when using SELECT * FROM subqueries.
   - TS-5900  fix: when performing max/min function on string type data, the results are inaccurate and taosd will crash
   - TS-5862  fix: stream computing does not support the use of the HAVING clause, but no error is reported during creation
   - TS-5861  fix: the version information displayed by taos shell for the server is inaccurate, such as being unable to correctly distinguish between the community edition and the enterprise edition.
   - TS-5863  fix: in certain specific query scenarios, when JOIN and CAST are used together, taosd may crash


```
