# 窗口最小持续时长限制 FS

## 1. 背景

对于事件窗口和状态窗口，在数据偶尔波动的情况下，往往会生成许多持续时间极短的窗口。从业务角度来看，这些窗口通常会被视为误报。在判断是否构成一个新的窗口时，以往的方法是一旦满足条件即视为窗口开启。本功能可以要求窗口必须持续一段时间之后，才被认定为真正开启。

## 4. 行为说明

为 `STATE_WINDOW`、`EVENT_WINDOW` 窗口新增关键字 `TRUE_FOR`，用于指定窗口的最小持续时长。
```sql
window_clause: {
  | STATE_WINDOW(col) [TRUE_FOR(true_for_duration)]
  | EVENT_WINDOW START WITH …… END WITH …… [TRUE_FOR(true_for_duration)]
}
```

其中，true_for_duration 可以是：
1. 自带时间单位的形式，如 1a, 2b, 3d
2. 不带时间单位的形式，将使用查询库的时间精度作为默认时间单位，当存在多个库时默认采用精度更高的库
3. 自带时间单位的字符串形式，字符串内部不能有任何空格等其他字符
相关算子在计算时，当有数据满足开窗条件后，会一直接收数据直到满足关窗条件。此时，如果窗口的宽度不小于 true_for_duration，则正常计算；否则丢弃该窗口及其包含的数据。之后开始下一窗口条件的判断。
补充：流计算和批查询都将支持本功能。

## 5. 性能

与目前不指定 TRUE_FOR 的查询场景相比，性能无明显下降(即下降程度不大于 3%)。

## 8. 使用场景

| 场景分类 | 场景描述 | SQL 示例 |
| --- | --- | --- |
| 正常 | 自带时间单位 | STATE_WINDOW(c1) TRUE_FOR (1m) |
| 正常 | 不带时间单位 | STATE_WINDOW(c1) TRUE_FOR (60000) |
| 正常 | 自带时间单位的字符串 | STATE_WINDOW(c1) TRUE_FOR ('1m') |
| 异常 | Duration 小于0 | STATE_WINDOW(c1) TRUE_FOR (-10) |
| 异常 | 时间单位为 n(月)或y(年) | STATE_WINDOW(c1) TRUE_FOR (1n) |

## 9. 约束和限制

1. true_for_duration 不能小于 0
2. true_for_duration 的时间单位不支持 n(月), y(年)
