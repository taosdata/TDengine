# 3.3.5.0 中英文 Release Notes

### 1. 中文

```markdown

### 2. 特性

   - TD-31253 特性：MQTT 稳定性和性能提升
   - TD-31475 特性：taosX 增量备份与恢复

### 3. 优化

   - TD-32951 优化：调整 telemerty 的上报机制
   - TS-4713 优化：支持通过 SQL 统计指定 DB 的磁盘空间
   - TS-4743 优化：在服务端增加查询内存管控

   - TD-32558 优化：taosX 支持可配置的异常数据处理
   - TD-32642 优化：支持为客户端连接设置选项，包括时区、字符集、用户 IP、用户名称
   - TD-32823 优化：taosdump 支持查询超时或连接端开时自动重连
   - TD-33225 优化：允许为已经订阅的 tag 列创建索引

   - TS-5560 优化：JDBC 支持多表批量写入
   - TS-5649 优化：支持对多级存储中的 dataDir 参数进行动态调整。
   - TS-5699 优化：taosX 数据库文件默认使用 data_dir 
   - TS-5742 优化：强制要求用户设置强密码，密码长度必须为 8 到 16 位，并且至少包含大写字母、小写字母、数字、特殊字符中的三类
   - TD-32614 优化：提高客户端获取新 Leader 的速度
   - TS-5566 优化：OPC 点位正则匹配支持 “非”

   - TD-33123 修复：taosX 迁移支持列压缩的超宽超级表时报语法错误

   - TD-33271 修复：通过 SQL 语句将数据写入一个表名长度为192个字符的子表时，如果表名被反引号（`）包围，可能会导致错误
```

### 5. English

```markdown

### 6. Features

   - TD-31253 feat: refactor MQTT to improve stability and performance
   - TD-31475 feat:  refactor taosX incremental backup-restore
   - TD-32222 feat: add stmt2 apis in JDBC via websocket connection
   - TD-32234 feat: add stmt2 api in Rust connector
   - TD-33054 feat: Adding error codes in error prompts in taos-CLI
   - TD-33062 feat: SuperSet can connect TDengine with python connector
   - TS-5583 feat: configurable grafana dashboards in explorer management
   - TS-5737 feat: add taosX-agent in-memory cache queu capacity option

### 7. Enhancements

   - TD-32951 enh: adjust the reporting mechanism of telemetry.
   - TS-4713 enh: support for SQL-based statistics of disk space for a specified DB.
   - TS-4743 enh: add memory management for SQL queries on the server side
   - TS-5058 enh: INTERVAL clause allows the use of the AUTO keyword to specify the window offset.
   - TS-5749 enh: reduce the impact on data write performance during data migration across multi-level storage
   - TD-28816 enh: migrate from angular to react for grafana 11.3+
   - TD-30186 enh: refactor taosAdapter websocket  api for a slightly better perf
   - TD-31906 enh: add health state in taosX task status
   - TD-32558 enh: taosX add configurations to handle exceptions
   - TD-32642 enh: support setting options for client connections, including time zone, character set, user IP, and user name.
   - TD-32823 enh: taosdump support retry after connection timeout or broken
   - TD-33225 enh: allow creating index for tags that already subscribed
   - TD-33256 enh: taosX now support literal special chars in password
   - TS-4937 enh: improve data write performance when Last Cache is activated.
   - TS-4994 enh: COMPACT command supports automatic execution, concurrency setting, and progress observation.
   - TS-5007 enh: support update global configuration parameters through SQL statements and persisting them.
   - TS-5035 enh: update the default compression method for all data types to improve the compression ratio in most scenarios.
   - TS-5234 enh: taosBenchmark --nodrop fix for mac/window
   - TS-5251 enh: prohibit the simultaneous execution of DB compaction and replica change operations (Enterpris).
   - TS-5325 enh: taosdump support primary key tables
   - TS-5385 enh: display user IP and name in the results of the SHOW QUERIES and SHOW CONNECTIONS statements.
   - TS-5560 enh: (JDBC)support batch insertion into multiple tables
   - TS-5649 enh: support for dynamically modifying the dataDir parameter for multi-level storage.
   - TS-5699 enh: prefer db file under data_dir
   - TS-5742 enh: enforce users to set strong passwords, which must be 8 to 16 characters in length and include at least three types of characters from the following: uppercase letters, lowercase letters, numbers, and special characters.
   - TD-32614 enh: improve the speed at which clients acquire the new Leader.
   - TS-5566 enh: support negative regex pattern in opc point selector

### 8. Fixes

   - TD-33136 fix: the potential for deadlocks when updating checkpoints in stream computing under high-load scenarios.
   - TS-5789 fix: write tmq data into target error when terrno already set
   - TS-5812 fix: taosd cannot start when there is data corruption in a block within the WAL
   - TS-5835 fix: taosBenchmark fails when taosd disconnected in replica 2/3
   - TD-30933 fix: log files being lost when they are switched frequently.
   - TD-32799 fix: he stream computing stops due to the data update within the window.
   - TD-32930 fix: libtaosws.so sets an incorrect error code when the connection is terminated while fetch data.
   - TD-33066 fix: taosX opc error in case of @-prefixed name
   - TD-33101 fix: fix permission denied with show vgroups sql in cloud
   - TD-33123 fix: fix sql syntax error when migrating from large stables with compress options
   - TD-33133 fix: incorrect memory estimation for vnode usage
   - TD-33137 fix: failed to perform UNION ALL query on constant strings of the varchar type.
   - TD-33139 fix: leader transfer during the execution of transaction may cause deadlock.
   - TD-33140 fix: rust connector invliad pointer addr in ws_stmt_get_tag_fields
   - TD-33223 fix: UNION statement fails when executing with subqueries containing multiple NULLs.
   - TD-33230 fix: the pause operation of stream computing might fail.
   - TD-33271 fix: when writing data into a sub-table with a table name length of 192 characters using an SQL statement, errors may occur if the table name is enclosed in backticks (`).
   - TD-33331 fix: when performing a join query on super tables across different databases, if each database contains only one vnode, the query will return an error.
   - TD-33343 fix: no enough disk space cause taosX panic
   - TD-33353 fix: when write data to a super table, using both bound and unbound simultaneously will trigger an exception.
   - TS-5764 fix: metrics non-exist cause panic when connect with agent
   - TS-5777 fix: when creating indexes for tag with a large character length, taosd may crash.
   - TS-5798 fix: when the input parameters for the functions first, last, last_row, and char exceed 127, the taosd may crash.
   - TS-5803 fix: when the number of rows in the result set of the LIMIT statement exceeds the size of a single data block, the returned count does not match the expectation.
   - TS-5826 fix: when synchronizing data between clusters, if the target task is deleted, the source cluster may run out of memory
   - TS-5827 fix: metadata read-write lock misconfiguration leads to a very small chance of blocking writes.
   - TS-5828 fix: when importing CSV files using the INSERT INTO statement on the Windows platform, the absence of a newline character at the end of the file may lead to an issue of infinite loop reading.
   - TS-5829 fix: after the tags of the table are updated, the stream computing fails to recognize and apply the ne values.
   - TS-5599 fix: fix kafka timeout issue and improve performance and stability
   - TS-5757 fix: in SQL queries, when both 'is null' and invalid 'in' filter conditions are included simultaneously, the query results are incorrect.
   - TS-5758 fix: SQL queries containing both 'IN' and 'BETWEEN' filter conditions result in incorrect query results.
   - TS-5760 fix: when performing multiplication or division operations between timestamp and numeric types, the results are incorrect.
   - TS-5761 fix: data type conversion error in the IN statement leads to incorrect query results.
   - TS-5706 fix: the error in filtering results when constant conditions are combined with OR operators.
   - TS-5712 fix: when performing subtraction operation on timestamp type, the negative value is not considered.
   - TS-5732 fix: tag values may display incorrectly when using GROUP BY tag synatix
   - TS-5779 fix: gcc < 10 bug cause taosX compile error
```
