# 流计算处理时间推送结果、支持新函数

## 1. 背景

目前电力行业 SCADA 场景中，需要经常计算发电量、耗电量，一般都是基于瞬时功率对时间求积分。
河北电力调度中心期望在其新一代调度云中，在 SCADA 场景利用 TDengine 中的 twa 时间加权函数和断面函数实现该功能。
流计算不支持使用 interp 和 twa 的函数执行，需要开发。
当前的流计算框架不支持按照处理时间生成 sink 结果，需要增加相关的语法和操作逻辑支持。

## 3. 定义

事件时间：时序数据自身所带的主键时间戳。
处理时间：流计算运行的服务器的当前时间。
写入时间：时序数据写入到系统中的时间，目前写入时间在 TDengine 流计算系统中没有实际意义。
历史数据：在创建流之前，就已经写入并存储在 TDengine 中的数据。

## 4. 行为说明

### 4.1 处理时间驱动设置

如果需要每个要求的时间间隔返回结果，与流计算当前的事件驱动运行模式不同。因此，引入 trigger 的新选项`force_window_close` 来描述处理时间驱动的计算结果推送。`force_window_close` 表示在机器处理时间时刻判定的窗口结束时刻，强制生成该窗口的聚合结果，开启 `force_window_close `选项以后，需要 SQL 语句中强制搭配 `FILL `选项，并且 `FILL `选项不能是`LINEAR`和 `NEXT`。
用户可以指定 watermark，此时按照机器时间 + watermark，开始计算并向下游算子推送计算结果。
在 `force_window_close` 模式下运行，设置 `ignore expired`为0, `ignore update`为0，`max_delay`， `fill_history `为1 会触发语法错误。
```sql {wrap}
CREATE STREAM sample_stream TRIGGER force_window_close WATERMARK 20s INTO dst_table
    AS 
        SELECT INTERP(col_name)
        FROM src_stable 
        PARTITION BY tbname
        EVERY(10s)
        FILL(Prev);
```

### 4.2 时间驱动行为表现

即按照机器时间定时拉起计算流程，从 TSDB 中读取数据进行计算，并向下游返回结果，其行为与 fill-history 对历史数据的处理方式类似。

#### 4.2.1 定时从 TSDB 中读取数据进行计算

1. 每隔 SQL 语句指定的时间间隔（使用 interval 或 every 定义）+ `water_mark`，从计算存储在 tsdb 中的该时间段范围内的数据，计算结果并写入目标表中（如果没有结果，则使按照 fill 设置填充数据）。
2. 对于推送完成的时间区间，**如果数据晚到，计算引擎直接忽略该部分数据**。
3. 由于计算拉起的时间是基于计算时间来进行，数据写入到 tsdb 中得到确认与事件时间之间存在不确定性。采用这种计算模式得到的结果具有**不确定性**。

#### 4.2.2 `force_window_close `模式下 TWA 计算方式

采用**间断区间**模式计算 TWA 结果，不针对前一个区间的原始数据获取其最后一个有效值与本时间区间中第一个有效值进行插值生成本时间窗口起始值的插值。

**本需求不处理 历史数据、不进行重算、不针对历史数据进行插值。**

### 4.3 INTERP 与  TWA 使用规则

创建流的 SQL 语句中可以使用新增加两个函数  TWA 和 interp 函数。TWA 函数与 interp 函数的使用限制与适用的数据类型与 批查询中的限制相同。

#### 4.3.1 TWA

```sql {wrap}
TWA
TWA(expr)
功能说明：时间加权平均函数。统计表中某列在一段时间内的时间加权平均。对于存在复合主键的表的查询，若时间戳相同的数据存在多条，则只有对应的复合主键最小的数据参与运算。
返回数据类型：DOUBLE。
适用数据类型：数值类型。
适用于：表和超级表。
```

TWA 在流计算中，如果应用在超级表中需要强制搭配 `partition by tbname` 限制每个时间线生成各自的结果。使用的示例如下：
```sql {wrap}
CREATE STREAM sample_stream INTO dst_table 
    AS 
        SELECT TWA(col_name) 
        FROM src_stable 
        INTERVAL(10s)
        PARTITION BY tbname;
```

TWA 可以应用在流计算支持的窗口模式中，包括：interval 窗口（翻转窗口与滑动窗口）。 只支持force window close模式
本期项目中确保完成 interval（翻转和滑动窗口）中  TWA 的计算功能需求。搭配其他的窗口时候，SQL 解析报错。

#### 4.3.2 INTERP

```sql {wrap}
INTERP
INTERP(expr [, ignore_null_values])

ignore_null_values: {
    0 | 1
}
返回数据类型：同字段类型。
适用数据类型：数值类型。
适用于：表和超级表。
功能说明：生成指定时刻的断面数据。不能使用 range 指定范围。需要强制搭配 partition by tbname 限制每个时间线生成独立的断面结果。同时要求使用 every 指定生成 interp 的时间间隔。
```

Interp 在流计算中，不能搭配 range 关键字使用，因为不再限制执行的时间范围, 需要强制搭配 `partition by tbname`限制每个时间线生成独立的断面结果。同时要求使用 `every `指定生成 interp 的时间间隔，`fill `指定缺失数据的情况下 interp 的插值方法。使用 interp 创建流计算示例如下：
```sql
CREATE STREAM sample_stream INTO dst_table 
    AS 
        SELECT INTERP(col_name) 
        FROM src_stable
        PARTITION BY tbname 
        EVERY(10s)
        FILL(Prev);
```

Interp 不支持window close模式。

#### 4.3.3 Fill 规则

1.对于force window close模式，从第一条数据开始，按时间填充空隙。
2.对其他模式，只填充第一条数据和最后一条数据之间的空隙。

<quote-container>
流计算支持一种新的 trigger 模式`force_time_window`，按照处理时间计，如果 source 节点的时间窗口关闭，则将当前关闭窗口的结果推送出去。
1. 开启 `force_window_close `选项以后，需要创建流的 SQL 语句中强制搭配 `FILL `选项，并且 `FILL `选项只能是 `PREV `、`NULL`、 `NONE`、`VALUE`。
2. 不支持`ignore expired`, `ignore update`，`max_delay` `fill_history `选项，设置上述选项会出现语法错误。
3. 用户可以使用 `watermark `设置在（按照`source task`所在机器时间计算）时间窗口关闭多长时间以后开始向下游推送结果。
4. 运行在 `force_window_close `模式下，不能够针对历史数据进行计算。只开始从创建流时刻机器时间开始计算窗口范围内写入数据库的数据结果。
5. 由于计算时刻和写入数据时刻的不确定性，最后生成的计算结果具有**不确定性**。

此外，流计算新增支持两个计算函数 `twa `和 `interp`。
在流计算中，interp 禁止设置 range 关键字。
在针对超级表的查询中，twa 和 interp 均需要强制搭配 `partition by tbname` 使用。
TWA 在流计算中只支持 interval （翻转窗口），暂不支持滑动窗口、会话窗口、事件窗口、状态窗口、计数窗口。
此外，twa 与 interp 的使用限制与在批查询中完全相同。
