# Explorer 数据写入任务重构

## 1. 背景

目前 explorer 是基于配置数据生成各个数据源写入任务的配置页面，这种方式的设计初衷是考虑数据源存在很大的共性，所以通过一套低代码的方式来生成配置页面以加快开发。但是随着数据源的不断加入个性化配置越来越多，为了实现这些个性化的配置，在原有前端开发框架加了很多特殊实现。这些特殊实现实现代价大，难以维护；而且为了提升用户体验，在原有框架中做实现难度很高。本版本(20241231) explorer 整体会重构底层为 vue3，借此机会重写数据写入任务前端代码以达到以下目标：
1. 降低数据源数据写入的前端开发难度
2. 提高可维护性
3. 提升代码的可读性

## 2. 重构措施

重构措施有以下几方面：
1. 每个数据源配置都有自己的页面代码，各个数据源共享一些通用的输入控件
2. 减少前端部分职责：前端只处理 json 配置数据，不再有任何 DSN 的组装逻辑存在，后端负责转换为 DSN

### 3.2 各个数据源任务配置页面开发

为每个数据源开发独立的配置页面，在此过程中，要充分发现各个数据源的共享，提取共享组件和方法，加强代码复用性。

### 3.3 taosX 接口适配

1. 保证现有 taosX 的 tasks 数据存储模型不变；
2. 重新开发一套前后端交互接口，新开发的接口其实是旧接口的适配接口
   - POST 接口：获取 json 数据，组装 json 数据为 dsn，调用旧接口底层方法；
   - GET 接口：从底层数据库拿到 ‘from’ dsn 数据，转成前端需要的 json 格式，返回给前端。
3. 具体接口
   - 连通性检查接口
   - Opc 上传点位 csv 文件校验接口
   - 提交任务接口
   - 获取任务列表接口

## 4. 兼容性

1. 底层数据模型不变，对任务调度没有任何影响
2. taosX 保留现有接口，完全兼容旧版 explorer
