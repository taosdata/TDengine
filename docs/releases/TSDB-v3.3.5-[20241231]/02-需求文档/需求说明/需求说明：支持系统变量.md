# 需求说明：支持系统变量

## 一、需求背景

近期优化白名单（TS-4971）、慢日志（TS-4921）功能时，存在两个典型的配置参数
1. 白名单参数 enableWhiteList，标识是否启用白名单，在服务端配置，通过心跳传递给 taosadapter
2. 慢日志参数 slowlogSwitch，标识是否启用慢日志，在服务端配置，通过心跳传递给 taosc 
这两个参数的特点
1. 集群所有 dnode 该参数的取值必须一致，当某 dnode 取值与 mnode leader 所在 dnode 不同时，该 dnode 离线
2. 参数的取值支持动态变更，但变更后不能确认是否成功保存到各 dnode 的配置文件中
在 [TDengine 可运维观测需求](https://taosdata.feishu.cn/wiki/OrX7woLVbiGy0ekld25c141VnPf) 的第 14 项，李珲提出
<quote-container>
show dnode <id> variables; 命令输出的结果显示乱七八糟，没有任何规律，现在参数越来越多，查找某个参数时太费劲了。希望能有一个分类
</quote-container>

## 二、需求概述

将全局配置项转化为系统变量，支持持久化，支持在线变更。
1. 转化为系统变量后，原有配置项将被废弃
2. 集群初始化时，各系统变量被设置为默认取值
3. 提供设置系统变量的语法，原有的 `alter dnode` 系列语句只修改非全局配置参数
4. 各 dnode 首次启动时，从 mnode 拉取系统变量的取值，存储在 dnode.cfg 文件中
5. 各 dnode 再次启动时，先从 dnode.cfg 中获取系统变量的取值，然后在和 mnode 心跳过程中更新值
6. 如果部分系统变量必须在 dnode 重启后才能生效，需要运维人员手动重启 dnode

## 三、兼容性

全局配置参数转化为系统变量的过程，仅在升级过程中发生一次，升级完成之后，被废弃的全局配置项不再有任何效果。系统变量可保存在 mnode 的 object 中，通过编程技巧保证升降级兼容。
1. 升级时，读取配置文件中的全局配置参数，并存储为系统变量
2. 降级时，mnode 发现  object 存在多余的数据，直接丢弃，并继续启动
