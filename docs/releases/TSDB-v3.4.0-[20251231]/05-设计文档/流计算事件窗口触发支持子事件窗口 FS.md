## 2. 背景

对于事件窗口触发，IDMP 希望能够指定多个开始条件：当任何一个开始条件满足时，事件窗口开启；当所有开始条件都不满足，或者结束条件满足时，事件窗口关闭。在事件窗口开启期间，如果满足的开始条件发生变化，能够切分对应的子事件窗口。
此功能旨在增强流计算引擎的能力，使其能够支持基于多个触发条件生成子事件。这对于需要精细化事件分析和监控的场景至关重要。通过引入父子事件窗口的概念，可以更清晰地呈现复杂的事件关系和演变过程。

## 3. 定义

1. **有效触发条件**：对于给定的若干个开始条件，从前到后，第一个满足的条件就是有效触发条件。
2. **子窗口**：当某一个具体的开始条件满足时子窗口开启， 当有效触发条件发生变化，或结束条件满足时，子窗口关闭。子窗口的时间范围由其对应的有效触发条件决定。子窗口的开始时间为有效触发条件首次满足的时间点，结束时间为以下两者中的较早者：(1) 有效触发条件发生变化的时间点；(2) 结束条件满足的时间点。子窗口之间不存在交叉重叠。如果有效触发条件没有变化，那么只有一个窗口，不存在父/子窗口。
3. **父窗口**：任何一个开始条件满足时产生的总窗口，包含两个或两个以上的子窗口。它的时间范围从第一个子窗口的开始时间，直到最后一个子窗口的结束时间。

## 4. 行为说明

### 4.1 功能语法

在现有流计算的事件窗口触发基础上，扩充其用法，允许指定多个开始条件（大于1个），允许不指定结束条件，新增语法如下：
```sql
EVENT_WINDOW(START WITH (start_cond_1, start_cond_2 [,...]) [END WITH end_cond])
```

要求实现以下功能：
1. 在事件窗口开启期间，如果有效触发条件没有变化，那么只产生一个子窗口，没有父窗口；
2. 在事件窗口开启期间，如果有效触发条件发生变化，那么：
   - 在变化时，开启新的子窗口，之前的子窗口关闭；
   - 仅在第二个子窗口开启时，才开启父窗口，父窗口的起始时间为第一个子窗口的起始时间；
   - 最后，这个父窗口和所有的子窗口都需要触发各自的通知和计算；
3. 当所有开始条件都不满足，或者结束条件(允许不指定)满足时，最后一个子窗口和父窗口(如果有)关闭；
4. 在窗口开启的通知消息中，需要添加两个字段：
   - conditionIndex: 触发当前窗口开启的开始条件的序号，从0开始计数；对于父窗口， 它的值与第一个子窗口的值相同；
   - windowIndex: 子事件窗口在父窗口中的序号，从 0 开始计数；如果不是子窗口，这个字段为 -1；
5. 现有事件窗口触发的语法、功能和行为没有任何变化；

待讨论问题：
1. 所有开始条件都不满足时触发父窗口关闭，这个行为是否必须？理论上用户可以在 END WITH 中显式指定。如果是必须的，那么 END WITH 指定额外的结束条件，是否还有实际应用场景？
  解答：
   - 所有开始条件都不满足时触发父窗口关闭，这个行为是必须的；
   - END WITH 指定额外的结束条件是有意义的；
1. 如果指定了 TRUE_FOR 选项，是否需要对子窗口生效？如果生效，对父窗口和其他子窗口的影响是什么？
  解答：需要，一律同样对待。TRUE_FOR 选项对子窗口和父窗口均生效，即：小于该时间长度限制的窗口直接忽略。补充说明：
   - 如果父窗口下有部分子窗口不满足 TRUE_FOR 条件，则有效的子窗口可能不是连续的；
   - 如果父窗口下仅有1个子窗口满足 TRUE_FOR 条件，仍保留父/子窗口，触发各自的通知和计算；
1. 计算语句是否需要额外的占位符，功能类似通知消息中新增的字段？
  
  
### 4.2 示例说明

```sql
create table t (ts timestamp, payload int, temperature int);

-- 负载高于 60 时告警，高于 90 时再次告警；负载下降到 60 以下时结束告警
create stream s_warning_1 (start with (payload >= 90, payload >= 60)) from t
    notify("ws://localhost:8080/notify") on (window_open | window_close)
    into warn_1 as select _twstart, _twend, _trownum;

-- 负载高于 60 时告警，高于 90 时再次告警；负载下降到 60 以下或者温度下降到 70 以下时结束告警
create stream s_warning_2 (start with (payload >= 90, payload >= 60) end with (temperature < 70)) from t
    notify("ws://localhost:8080/notify") on (window_open | window_close)
    into warn_2 as select _twstart, _twend, _trownum;
    
-- 流任务 ready 之后写入实时数据
insert into t values
    ('2025-10-01 00:00:00', 90, 90),
    ('2025-10-01 00:01:00', 95, 95),
    ('2025-10-01 00:02:00', 50, 70),

    ('2025-10-01 00:03:00', 70, 70),
    ('2025-10-01 00:04:00', 80, 80),
    ('2025-10-01 00:05:00', 90, 90),
    ('2025-10-01 00:06:00', 95, 95),
    ('2025-10-01 00:07:00', 50, 50),

    ('2025-10-01 00:08:00', 70, 70),
    ('2025-10-01 00:09:00', 80, 80),
    ('2025-10-01 00:10:00', 60, 60);

```

接下来，我们以 `s_warning_2` 为例，对通知和计算行为进行说明：
1. 第一个窗口的时间范围是 `['2025-10-01 00:00:00', '2025-10-01 00:02:00']`：
   - 有效触发条件始终是 `payload >= 90`，没有发生变化，所以没有父/子窗口；
   - 共触发2次通知：窗口的窗口开启、窗口关闭，在窗口开启的通知中，conditionIndex = 0, winIndex = -1；
   - 共触发1次计算，计算结果为：`{'2025-10-01 00:00:00', '2025-10-01 00:02:00', 3}`
2. 第二个窗口的时间范围是 `['2025-10-01 00:03:00', '2025-10-01 00:07:00']`：
   - 有效触发条件在 '2025-10-01 00:05:00' 时发生了变化，所以它是父窗口，有2个子窗口：
      - 第一个子窗口时间范围是 `['2025-10-01 00:03:00', '2025-10-01 00:04:00']`；
      - 第二个子窗口时间范围是 `['2025-10-01 00:05:00', ``'2025-10-01 00:07:00'``]`；
   - 共触发6次通知，分别是：
      - 第一个子窗口的窗口开启、窗口关闭，在窗口开启的通知中，conditionIndex = 1, winIndex = 0；
      - 第二个子窗口的窗口开启、窗口关闭，在窗口开启的通知中，conditionIndex = 0, winIndex = 1；
      - 父窗口的窗口开启、窗口关闭，在窗口开启的通知中，conditionIndex = 1, winIndex = -1；
   - 共触发3次计算，计算结果为：
      - `{'2025-10-01 00:03:00', '2025-10-01 00:04:00', 2}`
      - `{'2025-10-01 00:05:00', '2025-10-01 00:07:00', 3}`
      - `{'2025-10-01 00:03:00', '2025-10-01 00:07:00', 5}`
3. 第三个窗口的时间范围是 `['2025-10-01 00:08:00', '2025-10-01 00:10:00']`：
   - 有效触发条件始终是 `payload >= 60`，没有发生变化，所以没有父/子窗口；
   - 共触发2次通知：窗口的窗口开启、窗口关闭，在窗口开启的通知中，conditionINdex = 1, windowIndex = -1；
   - 共触发1次计算，计算结果为：`{'2025-10-01 00:08:00', '2025-10-01 00:10:00', 3}`

## 5. 性能

1. 不影响现有流计算的事件窗口触发的性能；
2. 与基础版本的事件窗口触发相比，指定多个开始条件(5个以内)的事件窗口触发，性能差距不超过 15%；
