## 2. 背景

**JIRA**：[TD-32977](https://jira.taosdata.com:18080/browse/TD-32977)    
**基本描述**：切分窗口条件满足后，数据已完成分组，此时查询中使用的 _wstart、_wend 伪列已具备明确语义。是否执行聚合运算应根据业务需求灵活选择，无需强制要求携带聚合函数。
**场景示例**：对于如下查询语句，业务侧可能仅需输出各子表满足条件的时间范围，无需执行 last、max 等聚合操作：
```plaintext
select _wstart, _wend, tbname 
from stable_1 
partition by tbname  
event_window start with q_int>0 end with q_int < 0;
```

**功能价值**：
1. 去除不必要的语法约束，提升查询灵活性与易用性；
2. 统一各窗口查询行为——此前 state window 无需强制聚合函数，其他窗口则有强制要求，修改后该规则保持一致。

## 4. 行为说明

核心规则：所有切分窗口（含时间窗口、状态窗口、会话窗口、事件窗口、计数窗口）的 SELECT 列表，均不再强制要求包含聚合函数（此规则将同步更新至官方文档）。
SELECT 列表支持的表达式类型包括：
1. 常量；
2. 窗口伪列（_wstart、_wend、_wduration）；
3. 聚集函数（含选择函数及可通过参数确定输出行数的时序特有函数）；
4. 由上述表达式组合而成的复杂表达式。
补充说明：
1. 表标识相关字段支持：查询普通表时可使用 tbname；查询子表时支持 tbname 与 tag 字段。此类字段与 now() 函数统一归为“常量”范畴；
2. 规则对比：此前执行如下查询会报错**“DB error: No valid function in window query”**，修改后可正常执行并输出结果：
```plaintext
select _wstart, _wend, tbname 
from stable_1 
partition by tbname  
event_window start with q_int>0 end with q_int < 0;
```

## 13. 文档

原有规则描述：

窗口子句将数据按窗口进行切分，对每个窗口进行 SELECT 列表中的表达式的计算，SELECT 列表中的表达式只能包含：
</quote-container>

新规则：窗口子句将数据按窗口进行切分，对每个窗口进行 SELECT 列表中的表达式的计算，SELECT 列表中的表达式只能包含：
1. 常量。
2. _wstart 伪列、_wend 伪列和_wduration 伪列。
3. 聚集函数（包括选择函数和可以由参数确定输出行数的时序特有函数）。
4. 包含上面表达式的表达式。
5. 且至少包含一个聚集函数**(3.4.0.0之后不再有该限制)。**
