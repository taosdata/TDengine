## 3. 需求目标

支持重要数据在存储
1. 配置文件加密存储
2. 权限和密码相关的数据文件加密存储
3. 时序数据相关的数据文件加密存储
4. 支持国密算法，包括 SM2、SM3、SM4
5. 秘钥生命周期管理

## 4. 功能要求

### 4.1 密钥生成与管理

#### 4.1.1 密钥定义

采用分级加密方式进行存储加密和密钥管理。
1. 服务器主密钥 SVR_KEY：用于加密数据库主密钥
2. 数据库主密钥 DB_KEY：用于加密其他库内秘钥
3. 库内秘钥
   - 配置加密秘钥 CFG_KEY：加密配置文件、其他明文文件
   - 元数据加密密钥：META_KEY：加密 mnode、snode 中的数据文件，如库表信息、权限和密码相关信息
   - 时序数据加密密钥：DATA_KEY：加密时序数据相关的数据文件，时序数据自身的元数据、预写日志文件

#### 4.1.2 密钥生成

密钥存储在 dnode/config/encrypt.bin 中。开发 taosk 可执行程序，负责生成和管理密钥，主要功能如下
1. 选择配置文件路径：例如 taosk -c /etc/taos
2. 设定加密算法和范围：支持对配置数据、元数据、时序数据进行分别设置
3. 设置加密算法属性，例如数据页大小：支持对三类数据进行分别配置，页大小影响某些加密算法的可用性
4. 设置主密钥：包括 SVR_KEY、DB_KEY，如不设置，则使用默认的符合安全要求的密钥

#### 4.1.3 密钥存储

密钥文件的保存格式如下
1. 密文保存的信息
   - 使用当前机器的机器码作为密钥，通过一个不公开的对称加密算法对 SVR_KEY 进行加密
   - 使用 SVR_KEY 对 DB_KEY 进行加密
   - 使用 SVR_KEY 对其他必要的信息进行加密，例如上次修改时间、加密算法
   - 使用 DB_KEY，对 CFG_KEY、META_KEY、DATA_KEY 进行加密
2. 明文保存的信息：
   - “不公开的对称加密算法” 类型，通过一个整型数标识，以便后续扩展
   - 密钥文件本身的版本信息

#### 4.1.4 密钥变更

1. CFG_KEY、META_KEY、DATA_KEY 在生成后不可更改
2. SVR_KEY、DB_KEY 可以更改
   - 支持通过命令行更改 taosk --update-svrkey --update-dbkey 
   - 支持通过 SQL 语句更改
   - 支持通过 SQL 语句查看当前值和上次修改时间

#### 4.1.5 密钥到期

支持通过 SQL 语句设置密钥到期时间和到期策略
1. 策略一：通过监控接口发送告警，写入监控库，在 TDinsight 中配置告警策略
2. 策略二：停止数据查询服务。（暂不实现）
3. 策略三：停止数据写入服务。（暂不实现）

#### 4.1.6 密钥分发

1. 通过安全可靠的内部加密通信机制（SASL），由 mnode 分发至其他经过认证的 dnode 节点，在 “[传输安全](https://taosdata.feishu.cn/wiki/ACKtwrzpbi4T62kXk79cC3Ixndb)” 中实现
2. 将密钥文件拷贝到其他数据节点时，由于机器码不对应，密钥文件无法被打开

#### 4.1.7 密钥备份与恢复

1. 备份：输入原节点机器码、SVR_KEY，生成不包含机器码加密信息的 encrypt.bin 文件
2. 恢复：通过 taosk 程序，基于以上文件，当输入目标节点机器码、SVR_KEY 时，为该节点生成可用的秘钥文件

### 4.2 透明加密

在透明加密中，加解密过程由数据库管理系统自动完成，用户不可见。

#### 4.2.1 配置文件加密

使用 CFG_KEY 加密，不支持修改密钥。开启后，对 dnode、mnode、vnode、snode 文件夹中的所有非数据文件进行加密，具体指：
1. dnode：包括 dnode.info  dnode.json
2. mnode：包括 mnode.json、raft_config.json、raft_store.json
3. vnode：包括 vnodes.json、vnode.json、raft_config.json、raft_store.json 等所有非数据文件
4. snode：包括 snode.json
简化 taos.cfg 文件内容
1. taos.cfg SA仅保留必要的配置参数，例如 firstEp、secondEp、fqdn、serverPort、debugFlag、dataDir
2. 在 taos.cfg 文件本身以及用户手册中，声明 taos.cfg 中的配置仅在系统第一次启动时有效
可以通过 taosk 程序查看密文文件
1. taosk --encrypt-file
2. taosk --decrypt-file
3. 进行以上操作时，需要提供 SVR_KEY 和 DB_KEY，如 taosk --svr-key --db_key
配置文件展示改造
1. 查看配置参数时，读取 全局变量、局部变量 时的方式不统一，可以在 ins_variables 中增加一列，可以同时看到全局和局部变量的信息。
2. 需要给配置参数增加一个修改时间字段，当通过 SQL 语句修改时，记录此时间

#### 4.2.2 元数据文件加密

使用 META_KEY 加密，不支持修改密钥。开启后，对 snode、mnode 中的所有数据文件进行加密
1. mnode： SDB 和 WAL 文件
2. snode：checkpoint 等文件

#### 4.2.3 数据文件加密

使用 DATA_KEY 加密，不支持修改密钥。
1. 创建数据库时，通过指定 ENCRYPT_ALGORITHM 选项开启，不支持修改
2. 加密范围包括 TSDB、WAL、STT、TDB、BSE 等文件

### 4.3 加密状态查看

#### 4.3.1 查看当前加密状态

增加系统表 ins_encrypt_status，各列定义如下
1. 加密范围：元数据加密、配置文件加密、时序数据文件加密
2. 加密算法：名称
3. 加密状态：开启、关闭

#### 4.3.2 查看特定数据库的加密状态

系统表 ins_databases 的 "encrypt_algorithm" 可查看各个数据库的加密算法配置。
```bash
select name, encrypt_algorithm from ins_databases;
              name              | encrypt_algorithm |
=====================================================
 power1                         | none              |
 power                          | sm4               |
```

## 5. 性能需求

存储加密在保证数据文件安全性的同时，也会带来一定的性能影响，不同的加密算法对性能的影响各有不同，用户需要根据自己的需求来决定是否进行加密以及加密算法的选择。在测试过程中，对如下指标进行测试，如果性能不达预期，需优化代码。
1. **启动性能**
   - 加密实现不应显著影响 TDengine 启动性能。
2. **写入性能**：
   - 加密实现影响数据写入性能，写入延迟增加不得超过 100%。
3. **查询性能**：
   - 加密实现影响数据查询性能，查询延迟增加不得超过 100%。
4. **资源消耗**：
   - 加密功能的内存占用需可控。

## 6. 安全需求

1. 通过 SQL 语句进行的操作，例如密钥变更、密钥到期策略设置
2. 密钥变更、密钥到期策略设置的语法，将在“权限管理”相关功能中表述

## 7. 兼容性需求

1. 需向后兼容，自 3.3.8 版本升级至本版本时，不需要手工干预
2. 当前需求不新增语法，不影响写入、查询
3. 使用新版本加密数据后，不能退回到旧版本。
