## 3. 需求目标

在“[存储安全](https://taosdata.feishu.cn/wiki/UYAqwU3GqiBsjCkT6BccKqLmnGh)”和“[身份鉴别](https://taosdata.feishu.cn/wiki/GZNPwH62SiiRtQkQHTvcM73YnDh)”功能开发过程中，涉及到很多加密算法。本需求的目标是集成这些算法
1. 国密系列加密算法
2. 标准安全加密算法

## 4. 功能需求

### 4.1 算法列表展示

通过 SQL 语法查看系统当前的加密算法，增加系统表 ins_encrypt_algorithems，各列定义如下
1. 算法名称：简称，例如 sm2、sm3 等
2. 算法描述：完整的字符串
3. 算法类型：如 1-散列算法、2-对称加密、3-非对称加密、4-编码方法
4. 算法来源：内置算法、UKEY、用户自定义
5. 其他信息：如算法库路径等

### 4.2 自定义加密算法

除内置加密算法外，系统还支持用户自定义的加密算法。增加名为“自定义加密算法路径”的配置项，字符串类型，可配置多个路径。自定义加密算法以动态链接库方式已提供，需实现“算法标准接口”。接口规范在设计时给出，以满足“[存储安全](https://taosdata.feishu.cn/wiki/UYAqwU3GqiBsjCkT6BccKqLmnGh)”功能对接口的要求为准，需要包括：
1. 基本信息获取：算法名称、描述、类型等
2. 加解密接口：输入信息、输出信息、密钥信息等
3. 创建和销毁接口等

### 4.3 新增加密算法

改造现有加密算法，按照 “算法标准接口” 进行封装、使用、展示，如下算法为参考，实现中根据调研结果确定
1. 国密算法：SM2 (非对称), SM4 (对称), SM3 (哈希), SM9 (标识密码)
2. 国标算法：RSA-2048+/ECC-256+ (非对称), AES-128+ (对称), SHA-256+ (哈希），根据开源许可证要求引用
3. 不需实现不安全的算法：MD5, SHA-1, DES, 3DES, RC4, RSA-1024 及以下
