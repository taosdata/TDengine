## 3. 需求背景

### 3.1 现有数据计算痛点

以典型时序数据模型为例
```sql
create table tb (ts timestamp , v1 int, v2 int);
insert into tb values('2025-12-02 10:28:08', 1, 2);
insert into tb values('2025-12-02 10:28:18', NULL, 3);
insert into tb values('2025-12-02 10:28:21', 4, NULL);
insert into tb values('2025-12-02 10:28:27', 5, 6);

taos> select * from tb;
           ts            |     v1      |     v2      |
======================================================
 2025-12-02 10:28:08.000 |           1 |           2 |
 2025-12-02 10:28:18.000 | NULL        |           3 |
 2025-12-02 10:28:21.000 |           4 | NULL        |
 2025-12-02 10:28:27.000 |           5 |           6 |
```

常规计算中，含 NULL 值的列会直接导致计算结果为 NULL
```sql
taos> select ts, v1*v2 from tb;
           ts            |           v1*v2           |
======================================================
 2025-12-02 10:28:08.000 |                         2 |
 2025-12-02 10:28:18.000 | NULL                      |
 2025-12-02 10:28:21.000 | NULL                      |
 2025-12-02 10:28:27.000 |                        30 |
```

### 3.2 用户期望效果

用户希望当列数据为空时，自动向前查找最近的非空值参与计算，预期结果如下：
```sql
taos> select ts, v1*v2 from tb;
           ts            |           v1*v2           |
======================================================
 2025-12-02 10:28:08.000 |                         2 |
 2025-12-02 10:28:18.000 | NULL  -> 3 （1*3）        |
 2025-12-02 10:28:21.000 | NULL  -> 12 （4*3）       |
 2025-12-02 10:28:27.000 |                        30 |
```

### 3.3 **窗口函数方案**

```sql
taos> select ts, LAG(v1) * LAG(v2) AS v1_v2 FROM tb;
```

### 3.4 **Interp 函数方案**

结果与期望不符，且多列联合使用时配置受限（ignore_null_values 参数无法设为 1），操作复杂度高
```sql
taos> select _irowts, interp(v1), interp(v2) from tb range('2025-12-02 10:28:05', '2025-12-02 10:28:30') every(5s) fill(near);

         _irowts         | interp(v1)  | interp(v2)  |
======================================================
 2025-12-02 10:28:05.000 |           1 |           2 |
 2025-12-02 10:28:10.000 |           1 |           2 |
 2025-12-02 10:28:15.000 | NULL        |           3 |
 2025-12-02 10:28:20.000 |           4 | NULL        |
 2025-12-02 10:28:25.000 |           5 |           6 |
 2025-12-02 10:28:30.000 |           5 |           6 |
Query OK, 6 row(s) in set (0.003692s)

taos > select ts, vv1, vv2 from (
          select _irowts, interp(v1) vv1, interp(v2) vv2 from ……
       );
```

## 4. 需求目标

限于开发周期，本期实现简化版本的 Lag 函数，具体要求：
1. **行为逻辑**：LAG 函数默认在当前查询结果集时间线内，向前查找所有历史数据中的最近非 NULL 值填充。
2. **易用性：**无需配置函数参数及 OVER 子句，降低用户操作成本。

## 5. 功能需求

### 5.1 语法定义

简化 LAG 函数调用方式，无需参数及 OVER 子句，语法格式如下：
```sql
SELECT [列名/ LAG(列名) / 计算表达式]
FROM [表名/虚拟表]
[WHERE 时间范围条件]
[PARTITION BY [列名]][其他聚合/排序子句];
```

### 5.2 填充规则

1. 对查询中使用 LAG 函数的列，自动向前追溯最近的非 NULL 值填充；
2. 若当前行之前无数据（如首行 NULL 值），保持 NULL 值；
3. 填充逻辑优先于列运算执行（如先填充 v1、v2，再计算 LAG (v1)*LAG (v2)）。

### 5.3 场景适配

1. **超级表**：按子表维度分别执行 LAG 函数插值逻辑；
2. **虚拟表**：适配虚拟表数据源映射后的 NULL 值填充；
3. **PARTITION BY**：按分区维度独立执行插值逻辑。

## 6. 性能需求

1. 虚拟表 / 超级表场景下，填充性能应该和 Interp 函数类似

## 7. 兼容性需求

1. 与现有 SQL 语法兼容，不影响未使用简化 LAG 函数的查询逻辑
2. 后续扩展参数配置时，需与窗口函数体系兼容，无功能冲突
