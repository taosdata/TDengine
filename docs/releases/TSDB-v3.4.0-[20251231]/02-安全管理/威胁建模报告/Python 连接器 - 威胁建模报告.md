### 3. 分析报告

本报告针对 Python 连接器进行了威胁建模分析。该连接器旨在为 Python 开发者提供访问 TDengine 数据库的能力，支持原生连接、WebSocket 连接和 REST 连接三种方式。
- **核心发现**： 共识别出 `15` 个潜在威胁，其中 `高危` `5` 个，`中危` `7` 个，`低危` `3` 个。
- **主要风险场景**：
   - **认证凭证泄露**：用户名、密码、Token 在内存、日志或网络传输中可能被窃取。
   - **SQL 注入攻击**：未经验证的用户输入直接拼接到 SQL 语句中，可能导致数据泄露或篡改。
   - **中间人攻击**：未加密或加密配置不当的连接可能被拦截和篡改。
   - **数据泄露**：查询结果、错误信息可能泄露敏感数据或系统信息。
   - **拒绝服务攻击**：恶意客户端可能通过大量请求、慢查询等方式耗尽服务器资源。
**结论**： Python 连接器作为数据库访问的关键组件，其安全性直接影响整个应用的安全态势。当前设计已考虑参数绑定防 SQL 注入、SSL/TLS 加密连接等基本安全措施，但在凭证管理、输入验证、错误处理、审计日志等方面仍需加强。必须在功能详细设计与编码实现中，将本报告提出的安全需求作为核心设计约束予以落实。

### 4. **威胁识别与分析（STRIDE）**

Python 连接器提供三种连接方式（原生、WebSocket、REST），支持 SQL 执行、参数绑定、无模式写入、数据订阅等功能。主要涉及到的组件包括：
1. **客户端 SDK**：taospy（原生+REST）、taos-ws-py（WebSocket）
2. **通信通道**：TCP（原生）、WebSocket、HTTP/HTTPS
3. **中间组件**：taosAdapter（WebSocket/REST 连接的代理）
4. **后端服务**：TDengine 数据库服务器

#### 4.1 **关键实体与数据**

| 实体/数据 | 描述 | 敏感性 |
| --- | --- | --- |
| 用户凭证 | 用户名、密码用于身份认证 | 高 |
| Token | TDengine 云服务的身份验证令牌 | 高 |
| SQL 语句 | 包含业务逻辑和可能的敏感数据 | 中-高 |
| 查询结果集 | 从数据库返回的数据，可能包含敏感信息 | 中-高 |
| 连接字符串 | 包含主机地址、端口、数据库名等配置信息 | 中 |
| 客户端驱动 | libtaos.so/taos.dll 本地库文件 | 中 |
| 错误信息 | 可能包含系统内部信息、堆栈跟踪等 | 中 |
| 审计日志 | 记录操作历史的日志信息 | 中 |

#### 4.2 **威胁评估**

| 威胁 ID | 威胁描述 / 攻击场景 | STRIDE | 相关组件 / 数据流 | 风险等级 |
| --- | --- | --- | --- | --- |
| T-PYCONN-01 | **凭证明文存储**：用户在代码中硬编码用户名密码或以明文形式存储在配置文件中，攻击者通过代码泄露、文件系统访问获取凭证。 | I（信息泄露） | 用户凭证 | 高 |
| T-PYCONN-02 | **凭证内存泄露**：密码在内存中以明文形式存在时间过长，可能被内存转储、调试工具或恶意软件读取。 | I（信息泄露） | 用户凭证 | 中 |
| T-PYCONN-03 | **日志凭证泄露**：连接字符串、SQL 语句被记录到日志文件中，包含密码或敏感数据，日志文件权限配置不当导致泄露。 | I（信息泄露） | 用户凭证、SQL 语句 | 高 |
| T-PYCONN-04 | **SQL 注入攻击**：应用未使用参数绑定，直接拼接用户输入到 SQL 语句，攻击者构造恶意 SQL 代码执行未授权操作。 | T（篡改）/ E（权限提升） | SQL 语句 | 高 |
| T-PYCONN-05 | **中间人攻击（原生连接）**：原生连接默认不加密，网络攻击者可拦截、窃听或篡改客户端与服务器之间的通信。 | I（信息泄露）/ T（篡改） | 原生连接通信通道 | 高 |
| T-PYCONN-06 | **中间人攻击（WebSocket/REST）**：使用 ws:// 或 http:// 而非 wss:// 或 https://，导致通信未加密，易受中间人攻击。 | I（信息泄露）/ T（篡改） | WebSocket/REST 通信通道 | 高 |
| T-PYCONN-07 | **SSL/TLS 证书验证绕过**：客户端禁用证书验证或接受自签名证书而不进行严格验证，攻击者可伪造服务器。 | S（仿冒） | WebSocket/REST SSL 连接 | 中 |
| T-PYCONN-08 | **查询结果数据泄露**：应用未正确处理查询结果的权限，敏感数据被未授权用户访问或记录到不安全的位置。 | I（信息泄露） | 查询结果集 | 中 |
| T-PYCONN-09 | **错误信息泄露**：详细的错误信息（堆栈跟踪、SQL 语句、内部路径）被返回给客户端或记录到日志，暴露系统内部实现细节。 | I（信息泄露） | 错误信息 | 中 |
| T-PYCONN-10 | **连接耗尽攻击**：恶意客户端创建大量连接但不关闭，耗尽数据库连接池，导致合法用户无法连接。 | D（拒绝服务） | 连接管理 | 中 |
| T-PYCONN-11 | **慢查询攻击**：攻击者提交资源密集型查询（如全表扫描、复杂聚合），占用大量服务器资源，影响其他用户。 | D（拒绝服务） | SQL 执行 | 中 |
| T-PYCONN-12 | **批量写入攻击**：攻击者通过参数绑定或无模式写入接口提交大量数据，快速填满磁盘或耗尽内存。 | D（拒绝服务） | 参数绑定、无模式写入 | 中 |
| T-PYCONN-13 | **客户端库篡改**：本地安装的 [libtaos.so/taos.dll](http://libtaos.so/taos.dll) 被恶意软件替换为木马版本，窃取数据或执行恶意操作。 | T（篡改）/ S（仿冒） | 客户端驱动库 | 中 |
| T-PYCONN-14 | **依赖库漏洞**：Python 连接器依赖的第三方库（如 requests、websocket-client）存在已知安全漏洞，攻击者利用漏洞攻击应用。 | 多种 | 第三方依赖 | 低-中 |
| T-PYCONN-15 | **审计日志不足**：缺少关键操作的审计日志（连接、查询、数据修改），无法追溯安全事件或检测异常行为。 | R（抵赖） | 审计日志 | 低 |

### 5. **安全需求与设计约束**

| 威胁 ID | 转化后的安全需求 / 设计约束 | 类型 | 优先级 |
| --- | --- | --- | --- |
| T-PYCONN-01 | **SEC-PYCONN-001（凭证安全存储）**：文档必须明确警告不要硬编码凭证，推荐使用环境变量、密钥管理服务（如 HashiCorp Vault、AWS Secrets Manager）或加密配置文件。示例代码应展示安全的凭证获取方式。 | 文档/最佳实践 | 高 |
| T-PYCONN-02 | **SEC-PYCONN-002（凭证内存保护）**：连接器实现应在使用后尽快清除内存中的密码，避免长时间保留明文凭证。考虑使用安全内存擦除技术。 | 安全设计约束 | 中 |
| T-PYCONN-03 | **SEC-PYCONN-003（日志脱敏）**：连接器的日志输出必须对敏感信息（密码、Token、个人身份信息）进行脱敏或掩码处理。SQL 语句日志应可配置开关。 | 安全功能需求 | 高 |
| T-PYCONN-04 | **SEC-PYCONN-004（参数绑定）**：文档必须强调参数绑定（Prepared Statement）是防止 SQL 注入的最佳实践，并提供清晰示例。对于不支持参数绑定的场景，必须提供输入验证和转义指南。 | 文档/最佳实践 | 高 |
| T-PYCONN-05 | **SEC-PYCONN-005（原生连接加密）**：若 TDengine 原生协议支持 TLS，文档应说明如何启用加密。如不支持，必须在文档中明确说明风险，建议在安全敏感环境使用 VPN 或其他网络层加密。 | 文档/配置指南 | 高 |
| T-PYCONN-06 | **SEC-PYCONN-006（支持 HTTPS/WSS）**：文档和示例代码应默认使用 wss:// 和 https://。连接器可添加配置选项，在生产环境禁止非加密连接。 | 安全设计约束 | 中 |
| T-PYCONN-07 | **SEC-PYCONN-007（证书验证）**：WebSocket 和 REST 连接默认不接受自签名证书。提供配置选项但需明确警告风险。 | 安全设计约束 | 中 |
| T-PYCONN-08 | **SEC-PYCONN-008（结果集访问控制）**：文档应指导开发者在应用层实现适当的访问控制，确保查询结果仅对授权用户可见。 | 文档/最佳实践 | 中 |
| T-PYCONN-09 | **SEC-PYCONN-009（错误处理）**：生产环境的错误信息应简化，避免暴露内部实现细节。详细错误仅记录到安全的日志系统，不返回给最终用户。提供调试模式开关。 | 安全设计约束 | 中 |
| T-PYCONN-010 | **SEC-PYCONN-010（连接池管理）**：实现或文档说明连接池最佳实践，包括最大连接数、连接超时、空闲连接回收等，防止连接耗尽。 | 非功能安全需求 | 中 |
| T-PYCONN-011 | **SEC-PYCONN-011（查询超时）**：连接器应提供查询超时配置，防止慢查询长时间占用资源。文档应建议合理的超时值。 | 安全设计约束 | 中 |
| T-PYCONN-012 | **SEC-PYCONN-012（写入限流）**：文档应建议在应用层或数据库层实现写入速率限制，防止批量写入攻击。参数绑定和无模式写入接口应有数据量限制。 | 非功能安全需求 | 中 |
| T-PYCONN-013 | **SEC-PYCONN-013（库文件完整性）**：提供客户端库文件的哈希值或数字签名，供用户验证下载文件的完整性。使用官方 PyPI 仓库分发，利用其签名机制。 | 发布流程安全 | 中 |
| T-PYCONN-014 | **SEC-PYCONN-014（依赖管理）**：定期扫描和更新第三方依赖库，修复已知安全漏洞。在 CI/CD 流程中集成依赖安全检查工具（如 Safety、Snyk）。 | 开发流程安全 | 低-中 |
| T-PYCONN-015 | **SEC-PYCONN-015（审计日志）**：连接器应提供可选的审计日志功能，记录关键操作（连接建立/断开、执行的 SQL 语句、数据修改）。日志应包含时间戳、用户标识、操作类型等信息。 | 安全功能需求 | 低 |

### 7. **当前实现的安全措施评估**

#### 7.1 **已实现的安全措施**

1. **参数绑定（Prepared Statement）**：
  - 原生连接和 WebSocket 连接支持 STMT 和 STMT2 参数绑定
  - 有效防止 SQL 注入攻击
  - 状态：✅已实现
1. **SSL/TLS 加密支持**：
  - WebSocket 连接支持 wss:// 协议
  - REST 连接支持 https:// 协议
  - 状态：✅ 已实现，需加强配置指导
1. **Token 认证**：
  - 支持 TDengine 云服务的 Token 认证
  - 状态：✅ 已实现
1. **连接池：**
   - 支持 sqlalchemy 连接池
   - 状态：✅ 已实现

#### 7.2 **待改进的安全措施**

1. **凭证管理指导**：缺少安全存储凭证的最佳实践文档
2. **日志脱敏**：当前实现未明确说明日志脱敏机制
3. **原生连接加密**：原生连接是否支持加密需要明确
4. **证书验证配置**：需要明确默认行为和配置选项
5. **审计日志**：缺少统一的审计日志框架
6. **错误处理**：需要规范化错误信息的返回，避免信息泄露
