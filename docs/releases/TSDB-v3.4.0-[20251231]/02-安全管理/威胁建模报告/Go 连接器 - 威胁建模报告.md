### 3. **分析报告**

本报告针对 GO 连接器功能进行了威胁建模分析。该功能旨在为 Go 语言开发者提供连接 TDengine 数据库的能力，支持原生连接（CGO）、RESTful 连接和 WebSocket 连接三种方式，实现数据库的连接、查询、插入、参数绑定、schemaless 写入和消息订阅等操作。
- 核心发现： 共识别出 `15` 个潜在威胁，其中 `高危` `6` 个，`中危` `7` 个，`低危` `2` 个。
- 主要风险场景：
   - 凭证泄露与传输安全： DSN 字符串包含明文密码，可能在日志、错误信息或内存转储中泄露；非加密连接（HTTP、WS）可被中间人攻击。
   - 注入攻击： SQL 注入、schemaless 数据注入可能导致数据篡改或未授权访问。
   - 身份认证与授权缺陷： Token 认证缺乏刷新机制、证书验证可被绕过、缺少细粒度权限控制。
   - 数据完整性风险： 缺少传输层完整性校验，压缩数据可能被篡改。
   - 资源耗尽攻击： WebSocket 长连接、订阅功能、参数绑定可能被滥用导致资源耗尽。
- 结论： 该 GO 连接器在提供多种连接方式和丰富功能的同时，引入了多个安全风险点。必须在详细设计与编码实现前，将本报告提出的安全需求作为核心设计约束予以落实，特别是凭证管理、传输加密、输入验证和资源限制方面。

### 4. **威胁识别与分析（STRIDE）**

GO 连接器提供三种连接方式（原生连接、RESTful 连接、WebSocket 连接），支持 SQL 查询、写入、参数绑定（STMT/STMT2）、schemaless 写入和 TMQ 订阅功能。

#### 4.1 **关键实体与数据**

| 实体/数据 | 描述 | 敏感性 |
| --- | --- | --- |
| DSN 连接字符串 | 包含用户名、密码、主机地址、端口等连接信息 | 高（含明文凭证） |
| 认证 Token | 连接云服务时使用的 token（RESTful/WebSocket） | 高 |
| TLS 证书 | HTTPS/WSS 连接的 SSL/TLS 证书 | 高 |
| SQL 查询语句 | 用户提供的 SQL 语句和参数 | 中（可能包含业务敏感数据） |
| Schemaless 数据 | InfluxDB、OpenTSDB 格式的时序数据 | 中 |
| TMQ 订阅数据 | 消息队列中的时序数据流 | 中到高（取决于业务） |
| CGO 内存缓冲区 | 原生连接使用的 C 语言内存空间 | 中（可能包含敏感数据残留） |
| WebSocket 会话 | 持久化的 WebSocket 连接状态 | 中 |
| 配置参数 | cgoThread、readTimeout、enableCompression 等 | 低到中 |

#### 4.2 **威胁评估**

| 威胁 ID | 威胁描述 / 攻击场景 | STRIDE | 相关组件 / 数据流 | 风险等级 |
| --- | --- | --- | --- | --- |
| T-GO-01 | DSN 明文密码泄露：DSN 字符串中的明文密码可能在日志、错误消息、内存转储、进程列表或代码仓库中泄露，导致数据库凭证被攻击者获取。 | I（信息泄露） | DSN 连接字符串、所有连接类型 | 高 |
| T-GO-02 | 非加密传输窃听：使用 HTTP 或 WS 协议时，数据在传输过程中未加密，攻击者可通过网络嗅探获取敏感数据（包括凭证、查询数据、业务数据）。 | I（信息泄露）/ T（篡改） | RESTful HTTP、WebSocket WS | 高 |
| T-GO-03 | SQL 注入攻击：应用未正确验证或转义用户输入，直接拼接到 SQL 语句中，攻击者可注入恶意 SQL 代码，导致未授权数据访问、数据篡改或删除。 | T（篡改）/ I（信息泄露）/ E（权限提升） | SQL 查询接口（Exec、Query） | 高 |
| T-GO-04 | Schemaless 数据注入：攻击者通过 schemaless 写入接口注入恶意格式的数据（超长字符串、特殊字符、畸形 JSON），可能导致服务器解析错误、资源耗尽或绕过验证。 | T（篡改）/ D（拒绝服务） | Schemaless 写入接口 | 高 |
| T-GO-05 | TLS 证书验证绕过：RESTful 连接的 `skipVerify` 参数允许跳过 TLS 证书验证，攻击者可通过中间人攻击伪造服务器，窃取凭证或篡改数据。 | S（仿冒）/ T（篡改）/ I（信息泄露） | RESTful HTTPS 连接 | 高 |
| T-GO-06 | Token 认证缺陷：云服务 token 可能缺乏过期时间、刷新机制或安全存储，攻击者获取 token 后可长期冒充合法客户端访问数据库。 | S（仿冒）/ E（权限提升） | Token 参数（RESTful/WebSocket） | 高 |
| T-GO-07 | WebSocket 连接劫持：WebSocket 连接建立后缺少会话验证机制，攻击者可能通过网络劫持或中间人攻击接管已建立的连接，执行未授权操作。 | S（仿冒）/ T（篡改） | WebSocket 连接 | 中 |
| T-GO-08 | CGO 内存安全问题：原生连接使用 CGO 调用 C 库，可能存在缓冲区溢出、内存泄漏或 use-after-free 漏洞，导致程序崩溃或被攻击者利用执行任意代码。 | E（权限提升）/ D（拒绝服务） | 原生连接（taosSql）、CGO 接口 | 中 |
| T-GO-09 | 参数绑定类型混淆：STMT/STMT2 参数绑定时类型不匹配可能导致数据精度丢失、类型转换错误或意外的数据库行为，影响数据完整性。 | T（篡改）/ I（信息泄露） | STMT/STMT2 参数绑定 | 中 |
| T-GO-10 | TMQ 订阅未授权访问：缺少细粒度的订阅权限控制，攻击者可能订阅未授权的主题，获取敏感的业务数据流。 | I（信息泄露）/ E（权限提升） | TMQ 订阅功能 | 中 |
| T-GO-11 | 资源耗尽攻击 - 连接池：攻击者创建大量数据库连接但不关闭，耗尽服务器连接池资源，导致合法用户无法连接数据库。 | D（拒绝服务） | 连接管理（Open/Close） | 中 |
| T-GO-12 | 资源耗尽攻击 - 查询：攻击者提交复杂或大数据量的查询语句，消耗服务器 CPU、内存和 I/O 资源，影响服务可用性。 | D（拒绝服务） | 查询接口（Query） | 中 |
| T-GO-13 | WebSocket 消息泛洪：攻击者向 WebSocket 连接发送大量消息或超大消息，耗尽客户端或服务器资源。 | D（拒绝服务） | WebSocket 连接 | 中 |
| T-GO-14 | 配置参数滥用：错误或恶意配置（如 cgoThread 设置过大、readTimeout 设置为 0）可能导致资源耗尽或功能异常。 | D（拒绝服务） | DSN 配置参数 | 低 |
| T-GO-15 | 错误信息泄露：详细的错误消息可能泄露数据库版本、内部路径、表结构等敏感信息，帮助攻击者进行进一步攻击。 | I（信息泄露） | 错误处理机制 | 低 |

### 5. **安全需求与设计约束**

| 威胁 ID | 转化后的安全需求 / 设计约束 | 类型 | 优先级 |
| --- | --- | --- | --- |
| T-GO-01 | SEC-GO-001（凭证保护）：禁止在日志中记录完整 DSN 字符串，错误消息中应脱敏密码和 token。应用层应使用环境变量或密钥管理系统存储凭证，避免硬编码。SDK 文档必须明确说明 DSN 安全最佳实践。 | 安全设计约束 | 高 |
| T-GO-02 | SEC-GO-002（强制加密传输）：生产环境必须使用 HTTPS 和 WSS 协议，禁止使用 HTTP 和 WS。SDK 应在文档中明确警告非加密连接的风险，并建议默认使用加密连接。 | 安全设计约束 | 高 |
| T-GO-03 | SEC-GO-003（防 SQL 注入）：SDK 文档必须强调使用参数化查询（PreparedStatement/STMT）的重要性。所有示例代码应使用参数绑定而非字符串拼接。考虑在 SDK 中提供输入验证辅助函数。 | 安全功能需求 | 高 |
| T-GO-04 | SEC-GO-004（Schemaless 输入验证）：Schemaless 写入接口必须在客户端和服务器端进行严格的格式验证和长度限制。限制单次写入的数据行数和总大小。对特殊字符进行适当转义或拒绝。 | 安全功能需求 | 高 |
| T-GO-05 | SEC-GO-005（证书验证）：禁止在生产环境使用 `skipVerify=true` 参数。SDK 应在运行时检测到 skipVerify 时输出安全警告日志。文档必须明确说明该参数仅用于测试环境。 | 安全设计约束 | 高 |
| T-GO-06 | SEC-GO-006（Token 安全管理）：Token 必须支持过期时间和刷新机制。Token 应使用安全的存储方式（环境变量、密钥管理系统），禁止硬编码或记录到日志。实现 Token 轮换机制。 | 安全功能需求 | 高 |
| T-GO-07 | SEC-GO-007（WebSocket 会话安全）：WebSocket 连接应实现会话令牌验证机制。支持定期重新认证。实现空闲超时和最大连接时长限制。记录连接建立、断开和异常事件的审计日志。 | 安全功能需求 | 中 |
| T-GO-08 | SEC-GO-008（CGO 内存安全）：对 CGO 代码进行定期安全审计和静态分析。实现严格的边界检查和内存管理。使用内存安全工具（如 AddressSanitizer）进行测试。建立 CVE 响应流程。 | 安全设计约束 | 中 |
| T-GO-09 | SEC-GO-009（类型安全）：STMT/STMT2 绑定时进行严格的类型检查和转换验证。文档应明确列出类型对应关系和精度损失风险。提供类型安全的辅助函数。在运行时检测类型不匹配并返回明确错误。 | 健壮性需求 | 中 |
| T-GO-10 | SEC-GO-010（订阅权限控制）：TMQ 订阅必须在服务器端实现基于用户的主题访问控制。客户端应在订阅前验证用户权限。记录所有订阅操作的审计日志（用户、主题、时间）。 | 安全功能需求 | 中 |
| T-GO-11 | SEC-GO-011（连接池管理）：实现客户端连接池大小限制和超时机制。提供连接健康检查（Ping）功能。实现连接泄漏检测和自动清理。文档应说明连接管理最佳实践。 | 健壮性需求 | 中 |
| T-GO-12 | SEC-GO-012（查询限制）：实现查询超时机制（通过 Context）。服务器端应限制单次查询返回的数据量。提供慢查询日志功能。考虑实现查询复杂度评估和限制。 | 非功能安全需求 | 中 |
| T-GO-13 | SEC-GO-013（WebSocket 流控）：实现 WebSocket 消息大小限制和速率限制。提供消息队列深度限制（chanLength）。实现背压机制，防止消息堆积。 | 非功能安全需求 | 中 |
| T-GO-14 | SEC-GO-014（配置验证）：对所有 DSN 参数进行合法性验证和范围检查。为关键参数设置安全默认值。文档应说明每个参数的安全影响。在检测到不安全配置时输出警告。 | 健壮性需求 | 低 |
| T-GO-15 | SEC-GO-015（错误信息脱敏）：错误消息应避免泄露敏感信息（数据库版本、内部路径、表结构、SQL 语句）。提供详细错误信息和脱敏错误信息两个级别，生产环境默认使用脱敏版本。 | 安全设计约束 | 低 |
