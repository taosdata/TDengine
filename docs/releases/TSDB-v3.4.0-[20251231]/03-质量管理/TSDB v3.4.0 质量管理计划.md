## 2. 文档概述

### 2.1 目的

本文档旨在明确 TDengine TSDB v3.4.0（安全版）项目的质量管理目标、质量活动安排、角色职责划分及质量验收标准，确保质量保证工作系统化地融入项目全生命周期，保障产品质量、过程规范性和交付可靠性。

### 2.2 适用范围

本计划适用于 TSDB v3.4.0 的全部开发活动，涵盖引擎安全加固、虚拟表增强、流计算改进、工具链安全加固等模块，覆盖从项目立项到版本发布的全过程，时间范围为 2025-10-01 至 2025-12-31。

## 3. 项目质量目标

### 3.1 整体质量目标

1. **过程合规性**：各开发阶段严格遵循质量保证制度要求，不符合项关闭率达到 100%。
2. **文档完整性**：需求、设计、测试等关键文档按计划编写并完成评审，文档完整率达到 95% 以上。
3. **缺陷管理**：系统测试阶段结束时，严重缺陷（P0/P1）全部关闭，P2 缺陷关闭率达到 90% 以上。
4. **安全质量**：所有安全功能（身份鉴别、访问控制、存储安全、传输安全）均通过安全测试验证。
5. **测试覆盖率**：新增功能的测试用例覆盖率达到 90% 以上，核心安全功能测试用例覆盖率达到 100%。

### 3.2 分阶段质量目标

| 阶段 | 时间范围 | 质量目标 |
| --- | --- | --- |
| 需求与设计阶段 | 2025-10-01 ~ 2025-11-30 | 需求文档评审通过率 100%；设计文档评审通过率 100% |
| 开发及功能测试阶段 | 2025-12-01 ~ 2025-12-15 | 功能测试缺陷提交规范率 ≥ 90%；代码评审覆盖率 ≥ 80% |
| 系统测试与验收阶段 | 2025-12-16 ~ 2025-12-31 | P0/P1 缺陷全部关闭；系统测试通过率 ≥ 95% |

## 7. 质量度量指标

参照《[度量指标规范](https://taosdata.feishu.cn/wiki/L50dwsyiciOW8TkkbFZcZEpnn9e)》，本项目重点关注以下质量度量指标，在每个自然月的第三个周四进行度量：

| 指标名称 | 度量方法 | 目标值 |
| --- | --- | --- |
| 缺陷关闭周期 | 缺陷从发现到关闭的平均天数 | P0/P1 ≤ 3 天；P2 ≤ 7 天 |
| 各类缺陷数目 | 按优先级（P0~P3）统计缺陷数量及趋势 | 持续跟踪 |
| 需求增加率 | 新增需求数 / 初始需求总数 | ≤ 15% |
| 文档评审通过率 | 一次评审通过文档数 / 总评审文档数 | ≥ 85% |
| 不符合项关闭率 | 已关闭 NCR 数 / 发现 NCR 总数 | 100%（项目结束时） |

## 8. 不符合项（NCR）管理

### 8.1 不符合项类别

| 等级 | 定义 |
| --- | --- |
| 严重（Critical） | 违反关键制度要求，可能导致产品质量重大缺陷或项目重大风险的问题 |
| 一般（Major） | 违反过程规范要求，可能影响产品质量或交付效率的问题 |

### 8.2 不符合项处理流程

1. **发现**：QA 在审计过程中记录不符合项，填写 NCR 记录（含问题描述、发现日期、严重等级）。
2. **确认**：与被审计方确认问题事实，避免误判。
3. **整改**：责任人制定整改措施，明确整改截止日期。
4. **跟踪**：质量组长跟踪整改进度，必要时上报项目经理。
5. **关闭**：QA 验证整改效果，确认整改完成后关闭 NCR。
6. **汇总**：在质量保证报告中汇总所有 NCR 的统计和分析结果。

## 9. 质量风险识别

以下为项目立项时识别的质量相关风险，详细信息见《TSDB v3.4.0 风险登记册》：

| 风险 ID | 风险描述 | 质量影响 | 应对措施 |
| --- | --- | --- | --- |
| Risk-3400-01 | 研发部组织架构调整 | 可能导致质量活动责任人变动 | 根据调整及时更新任务分配 |
| Risk-3400-02 | 权限控制、存储安全进度延迟 | 安全功能测试覆盖不足 | 安排加班推进，确保测试时间 |
| Risk-3400-03 | 测试用例未覆盖特定场景 | 安全功能缺陷可能泄露 | 完成全部用例后针对新特性补充测试 |
| Risk-3400-04 | 用户鉴权实现进度低于预期 | 相关功能测试延迟 | 减少下游依赖，仅提交可实现部分 |
| Risk-3400-05 | OAuth 2.0 需求变更，TOKEN 实现进度慢 | 变更导致测试需重新设计 | 安排相关人员加班推进 |

## 10. 质量验收标准

在 TSDB v3.4.0 系统测试结束、申请版本发布前，须满足以下质量验收标准：

| 验收条件 | 验收标准 | 验收人 |
| --- | --- | --- |
| 功能完整性 | 所有 P0/P1 级别功能全部实现并通过测试 | 肖波 |
| 缺陷状态 | P0/P1 缺陷全部关闭；P2 缺陷关闭率 ≥ 90% | 肖波 |
| 安全功能验证 | 身份鉴别、访问控制、存储安全、传输安全、安全审计等核心安全功能通过验证 | 霍琳贺、肖波 |
| 文档完整性 | Release Notes、用户手册、部署说明等发布文档已完成并经过评审 | 王旭 |
| QA 不符合项 | 所有审计发现的不符合项已关闭或有书面批准的豁免说明 | 王旭 |
| 配置与基线管理 | 四个基线（需求/设计/功能冻结/发布）均已建立并登记，基线审计报告完成，所有配置管理问题已关闭 | 王旭 |
| 风险登记册 | 所有高优先级风险已关闭或有明确应对措施 | 关胜亮 |
