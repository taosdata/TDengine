# 20251113 消费端可控的 WAL 保留机制设计评审记录

## 1. 评审信息

1. 评审目的：评估 “状态窗口零状态功能” 设计的合理性、安全性、性能、兼容性及可维护性
2. 评审文档：[消费端可控的 WAL 保留机制 FS](https://taosdata.feishu.cn/wiki/PMk8wmGSRiEe9qkVTVNcC2KKnuf)

## 2. 评审记录

评审团队对设计文档进行了全面审查，认为所有设计合理，具体评审意见如下：
1. 机制完整性设计：
   - 设计引入了`enable.wal.marker`参数和WAL Keep Version机制，全面解决了订阅进度缓慢导致的WAL文件被过早删除的问题，机制设计完整。
   - 通过消费者进度控制WAL保留，确保数据至少被消费一次，可靠性高。
   - 新增的`TRIM DATABASE`命令提供了管理灵活性，兼顾了自动保留与手动干预的需求
2. 性能影响评估：设计明确评估了对写入、查询和订阅性能无显著影响，WAL版本号提交采用异步方式，避免阻塞主要流程
3. 安全性设计：设计指出不涉及新的安全风险，复用现有安全机制，这一点合理
4. 兼容性与可维护性：向后兼容性良好，新参数默认关闭，现有应用程序无需修改即可保持原有行为
5. 运维可行性：提供了磁盘空间不足时的应对措施（使用`TRIM DATABASE`命令），运维指导清晰

## 3. 评审结论

通过
