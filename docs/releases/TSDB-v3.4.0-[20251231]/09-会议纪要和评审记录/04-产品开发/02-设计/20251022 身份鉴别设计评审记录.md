## 2. 评审记录

设计文档架构清晰，存在如下修改建议
1. TOTP 多因素认证
   - 启用 TOTP 后，用户必须同时输入密码和 TOTP 验证码才能登录，仅凭密码将无法通过认证。
   - 需对 taos shell 和 taosExplorer 的登录界面进行改造，增加 TOTP 输入支持。
   - 新增以下 C API 函数以支持 TOTP 登录
      - `taos_connect_token_totp`
      - `taos_connect_totp`
   - 关于执行 `UPDATE TOTP`命令后如何安全地获取 TOTP 密钥值，其具体实现方式在开发阶段根据实现复杂度进一步评估确定。
2. 登录行为
   - 清晰描述不同客户端的登录流程，需为 taos shell、taosExplorer 及 C API 绘制登录流程图，明确包括普通密码登录、TOTP 双因素登录及 Token 登录在内的认证路径。
   - 增加 taos_connect_token，支持 token 登录
3. TOKEN 管理
   - 在 token 创建机制中，假定 `client_code`具备唯一性。
   - 用户通过 token 连接时，不能刷新 token 的过期时间。  
4. 传输安全
   - 为杜绝密码明文传输，taosc 与服务端之间将采用 libsasl 库实现认证安全（如使用 SCRAM 机制）。
   - JDBC 等连接器与 taosAdapter 之间的连接则通过 TLS 加密 保证传输安全。
5. 连接管理
   - 连接池管理及可能的连接强制断开需求，是否需要增加新的控制 API 在线下讨论具体场景后确定。
   - Show Connection 语句支持连接方式字段，包括 “TOKEN 连接” 还是 “密码连接”。
