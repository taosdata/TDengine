# 安全相关功能兼容现存行为

## 1. 背景

我们在 3.4.0.0 的版本上，为了提升产品的安全能力，我们陆续完善了权限校验和身份鉴别的功能，并努力让这些功能变成业内标准实现。在功能设计初期我们就决定不兼容一部分过去的语法并增加了许多使用的限制（禁止使用默认密码，密码自动过期等等），这导致了现有客户的一系列兼容问题以及产品的易用性下降。
为了解决这些问题，并同时保证产品的安全能力，顺利通过安全相关测试。我们决定做一次兼容性的改造，增加一个 CMAKE 编译选项 `BUILD_ADVANCED_SECURITY`，**默认关闭**。此选项打开时（设置为 `true`），代码中会定义宏 `TD_ENABLE_ADVANCED_SECURITY`，关闭时不会定义。**理论上这个编译选项仅在安可送测版本才会打开**。

## 2. 权限相关

最主要的问题是一个授权语法的语义变化。
```plaintext
grant all on db.* to u1;
```

这个语法在 3.4.0.0 之前的版本代表授予数据库 db 下的**全部对象**的全部权限给 u1；
这个语法在 3.4.0.0 之后的版本代表授予数据库 db 下的**全部 table **的全部权限给 u1;
这导致了云服务的一系列问题。
在  `BUILD_ADVANCED_SECURITY` 关闭时，把这个语法的语义恢复和 3.4.0.0 之前一致。

| SQL | 3.4.0.0 之前版本 | 3.4.0.0 现状 | 3.4.0.0 兼容性修改后 |
| --- | --- | --- | --- |
| grant all on db.* to u1; | 授予数据库 db 下的**全部对象**的全部权限给 u1 | 授予数据库 db 下的**全部 table **的全部权限给 u1 | 同 3.4.0.0 之前版本行为 |
| grant read on db.* to u1; | 授予数据库 db 下的**全部对象**的读权限给 u1 | 不支持 | 同 3.4.0.0 之前版本行为 |
| grant write on db.* to u1; | 授予数据库 db 下的**全部对象**的写权限给 u1 | 不支持 | 同 3.4.0.0 之前版本行为 |

## 3. 身份鉴别

在  `BUILD_ADVANCED_SECURITY` 关闭时：
1. Root & 普通用户可以使用 taosdata 密码
2. Root & 普通用户默认密码不会过期
3. 除 `ALLOW_TOKEN_NUM `外，其他 3.4 新增用户属性默认不生效
