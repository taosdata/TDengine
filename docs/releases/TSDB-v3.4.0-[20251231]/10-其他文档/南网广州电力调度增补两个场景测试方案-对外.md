# 南网广州电力调度增补两个场景测试方案-对外

### 1. 需求概述

业主希望在之前测试基础上，增加两项查询测试：
- CIM树查询
- 配变重载/过载、三相不平衡及负载率分区统计查询

#### 1.1 **CIM树查询**

针对四种常见查询场景进行并发查询性能验证
- 主网接线图界面模糊查询厂站名称
- GIS单线图界面模糊查询馈线名称
- 添加配网故障简报弹窗模糊搜索所有设备名称
- GIS台区图界面模糊搜索台区名称
目前CIM表结构【该表记录数约178万】

#### 1.2 **配变重载/过载查询、三相不平衡查询以及配变负载率分区统计查询**

业主方关注的查询核心需求分三类：配变重载/过载界面查询，三相不平衡查询，以及配变负载率分区统计查询
其中配变界面查询是重点。其基本逻辑是，从原始数据计算得到中间表，存放重载、一般过载、严重过载的详情；所有界面都从中间表筛选、计算得出。
<quote-container>
重载：负载率大于80%到100%，持续时间2小时
一般过载：负载率大于100%到120%，持续时间2小时
严重过载：负载率大于120%，持续时间2小时
</quote-container>

- 重载/过载中间结果表：存储三类过载的每次重载、过载区间对应的起始、终止时间、时长、最大负载率、最高负载率发生时间、最大三相电流。
- TX6_TJFZL_UNBALANCE_DAY表：存储每个配变每天最大电流值，最大电流时间，最小电流值，最大三相不平衡。
- TX6_TJFZL_FZLLJ_PB_DAY表：存储每个配变每天各个负载率层级的时间（0%，10%，20%，30%，......）单位分钟，配变类型。
- 查询示例：根据给定的区局（无，则默认全局，精确匹配）、配变名称（无则默认全部，模糊匹配）、时间范围，负载率范围，单日累计时间四个条件，计算查询出符合条件的配变负载率，并统计对应配变处于负载率范围的累计时长，日均时长；时间范围内的三相最大电流，最高负载率，最高负载率发生时间。
目前表结构

###### 4.1.3.2 查询**pbdata计算写入 **overload 

```sql {wrap}
insert into sta.overload (tbname, gis_code, rated_cap, pbattr, flag, tss, tse, dur, max_loadrate, max_ts, max_current, sum_loadrate, cnt)
select 
concat('ol0_',tbname) as `tbname`,
gis_code, rated_cap, classify_id as pbattr, 0 as flag, 
_wstart as tss, _wend as tse, _wduration/60000 as dur, 
max(greatest(a_current,b_current,c_current)*ct_ratio*0.4*1.732/rated_cap) as max_loadrate, 
cols(max(greatest(a_current,b_current,c_current)),ts) as max_ts, 
max(greatest(a_current,b_current,c_current)) as max_current, 
sum(greatest(a_current,b_current,c_current)*ct_ratio*0.4*1.732/rated_cap) as sum_loadrate,
count(*) as cnt  
from df8600.pbdata 
where ts between '2025-1-1' and '2025-11-1' 
partition by tbname
event_window
start with 
greatest(a_current,b_current,c_current)*ct_ratio*0.4*1.732/rated_cap >= 0.8 and 
greatest(a_current,b_current,c_current)*ct_ratio*0.4*1.732/rated_cap < 1 
end with 
greatest(a_current,b_current,c_current)*ct_ratio*0.4*1.732/rated_cap < 0.8 or 
greatest(a_current,b_current,c_current)*ct_ratio*0.4*1.732/rated_cap >= 1 
having _wduration >= 2h
```

##### 4.1.4 tx6_tjfzl_fzllj_pb_day 负载率分区统计表初始化

###### 4.1.4.1 **设计思路与建表**

- 创建超级表 sta.tx6_tjfzl_fzllj_pb_day
- 从pbdata计算每台配变每天负载率各区间时长(分钟)、日最大负载率等信息，写入tx6_tjfzl_fzllj_pb_day表
```sql {wrap}
create stable sta.tx6_tjfzl_fzllj_pb_day (ts TIMESTAMP, ymd INT COMPOSITE KEY, insertdate TIMESTAMP, fzl0 INT, fzlless10 INT, fzl10 INT, fzl20 INT, fzl30 INT, fzl40 INT, fzl50 INT, fzl60 INT, fzl70 INT, fzl80 INT, fzl85 INT, fzl90 INT, fzl95 INT, fzl100 INT, fzl110 INT, fzl120 INT, fzl130 INT, fzl140 INT, fzl150 INT, fzlover200 INT, max_lr DOUBLE, max_ts TIMESTAMP, sum_lr DOUBLE, cnt INT) tags (name varchar(32), typedesc varchar(200), bureau nchar(16), pbname nchar(50), rated float))
```

###### 4.1.4.2 **查询pbdata计算后写入 tx6_tjfzl_fzllj_pb_day**

```sql {wrap}
insert into sta.tx6_tjfzl_fzllj_pb_day (tbname, name, ts, ymd, insertdate, fzl0, fzlless10, fzl10, fzl20, fzl30, fzl40, fzl50, fzl60, fzl70, fzl80, fzl85, fzl90, fzl95, fzl100, fzl110, fzl120, fzl130,fzl140, fzl150, fzlover200, max_lr, max_ts, sum_lr, cnt)
select
concat('fzllj_',tname) as `tbname`,
last(gis_code) as name,
_wstart as ts,
cast(to_char(_wstart,'YYYYMMDD') as INT) as ymd,
now as insertdate, 
sum(fzl0) as fzl0,
sum(fzlless10) as fzlless10, 
sum(fzl10) as fzl10, 
sum(fzl20) as fzl20, 
sum(fzl30) as fzl30, 
sum(fzl40) as fzl40, 
sum(fzl50) as fzl50, 
sum(fzl60) as fzl60, 
sum(fzl70) as fzl70, 
sum(fzl80) as fzl80, 
sum(fzl85) as fzl85, 
sum(fzl90) as fzl90, 
sum(fzl95) as fzl95, 
sum(fzl100) as fzl100, 
sum(fzl110) as fzl110, 
sum(fzl120) as fzl120, 
sum(fzl130) as fzl130, 
sum(fzl140) as fzl140, 
sum(fzl150) as fzl150, 
sum(fzlover200) as fzlover200,
max(lr) as max_lr, cols(max(lr), ts as max_ts), 
sum(lr) as sum_lr, count(*) as cnt 
from (
select 
ts, tname, gis_code, 
case when lr < 0 then dur end as fzl0,
case when lr >=0 and lr <0.1 then dur end as fzlless10, 
case when lr >=0.1 and lr <0.2 then dur end as fzl10, 
case when lr >=0.2 and lr <0.3 then dur end as fzl20, 
case when lr >=0.3 and lr <0.4 then dur end as fzl30, 
case when lr >=0.4 and lr <0.5 then dur end as fzl40, 
case when lr >=0.5 and lr <0.6 then dur end as fzl50, 
case when lr >=0.6 and lr <0.7 then dur end as fzl60, 
case when lr >=0.7 and lr <0.8 then dur end as fzl70, 
case when lr >=0.8 and lr <0.85 then dur end as fzl80, 
case when lr >=0.85 and lr <0.9 then dur end as fzl85, 
case when lr >=0.9 and lr <0.95 then dur end as fzl90, 
case when lr >=0.95 and lr <1 then dur end as fzl95, 
case when lr >=1 and lr <1.1 then dur end as fzl100, 
case when lr >=1.1 and lr <1.2 then dur end as fzl110, 
case when lr >=1.2 and lr <1.3 then dur end as fzl120, 
case when lr >=1.3 and lr <1.4 then dur end as fzl130, 
case when lr >=1.4 and lr <1.5 then dur end as fzl140, 
case when lr >=1.5 and lr <2 then dur end as fzl150, 
case when lr >=2  then dur end as fzlover200,
lr
from 
(select _wstart as ts, tbname as tname, _wduration/60000 as dur, gis_code,
first(greatest(a_current,b_current,c_current)*ct_ratio*0.4*1.732/rated_cap) as lr
from df8600.pbdata
```
