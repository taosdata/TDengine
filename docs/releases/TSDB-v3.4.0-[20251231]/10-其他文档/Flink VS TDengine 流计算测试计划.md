# Flink VS TDengine 流计算测试计划

### 1. 测试指标设计

#### 1.1 主要指标

本次测试将主要关注吞吐量和资源利用率指标。
1. 吞吐量​：单位时间内系统处理的记录数量
   - 测试方法：通过开始时间和结束时间即可计算
2. 资源利用率​：系统在处理过程中的资源消耗情况
   - 测试方法：监控测试期间的 CPU、内存使用情况

#### 1.2 次要指标

当主要指标测试工作结束后，再考虑选取和观测次要指标。
1. 延迟指标​：包括端到端延迟和处理延迟
   - 定义统一和测量准确性面临挑战，参考 Nexmark 框架的经验，延迟测量面临两个核心挑战：
      - 定义不统一​：在窗口聚合等复杂流计算操作中，"结果产生时间点"难以明确定义。不同计算方法（如output_system_time - window_end 与 output_system_time - max(ingest_time)）会产生不同含义的延迟指标
      - 反压影响​：系统反压会显著增加数据在管道中的停留时间，使观测到的延迟包含处理时间和排队等待时间，难以纯粹衡量引擎处理效率
2. 可扩展性​：资源增加与性能提升的比例关系
   - 测试复杂度：需要多机部署环境，测试成本较高
3. 容错能力​：系统从故障中恢复的时间
   - 测试重点：非本次性能对比的核心关注点

### 2. Flink 测试方案

#### 2.1 自定义数据源设计

开发专用数据源 `tsbs-datasource`，其工作流程如下：
1. 打开指定数据文件
2. 逐行读取数据内容
3. 按照 TSBS 字段规范解析为多列数据
4. 将解析后的数据传递给 Flink 源算子
5. 循环执行 2-4 步 直至数据读取完成

#### 2.2 单流计算测试流程

1. 数据表定义
   - 表结构设计与 TSBS 字段完全对应
   - 数据源类型指定为 TSBS
   - 输入数据来自预生成的 TSBS 数据文件
2. 流计算测试执行
   - 定义测试 SQL 语句、数据读取并发度、计算并发度
   - 启动计时器
   - 执行 SQL 语句
   - 等待语句执行完成
   - 停止计时器
   - 按 b-e 步骤执行其他测试（覆盖预设的流计算场景）
   - 统一生成测试结果报表
3. 结果统计
   - 吞吐量计算：处理数据条数/(结束时间-开始时间)
   - 资源消耗：通过外部工具统计测试期间的 CPU 和内存使用情况

#### 2.4 整体测试方法

1. 数据准备​：使用 TSBS 数据生成器预先生成 CSV 格式测试数据
2. 测试环境​：
   - 采用单机部署模式（数据读取与计算在同一节点）
   - 选择理由：
      - 与 TDengine 测试架构一致（客户端/服务端分离）
      - Flink 客户端开销可忽略不计
      - 简化测试代码复杂度
3. Flink 配置​：
   - 104 核机器，配置 104 个 SLOT
   - 数据读取并发度：52
   - 流计算并发度：52
4. 测试执行​：
   - 依据预设流计算场景设计等效 Flink SQL 语句
   - 按单流计算测试流程统计吞吐量和资源占用
   - 生成文本格式测试结果
   - 基于结果数据生成图表和测试报告

### 3. TDengine 测试方案

1. 数据准备​：使用 TSBS 数据生成器准备数据文件
2. 测试环境​：
   - 双节点部署：
      - 客户端：24 核机器，负责数据写入
      - 服务端：104 核机器，负责数据处理和计算
3. 测试流程​：
   - 启动数据库实例
   - 创建数据表结构
   - 创建流计算任务
   - 启动计时器
   - 执行数据写入操作
   - 启动/监控流计算任务
   - 等待流计算完成
   - 停止计时器
   - 删除之前的流计算任务
   - 按 c-i 步骤执行其他测试（覆盖预设的流计算场景）
   - 统一生成测试结果报表

### 4. 测试计划说明

本方案只关注吞吐量和资源利用率这两个可测量且对比性强的核心指标。后续工作安排
1. 测试环境准备（郭向阳）
   - 准备客户端和服务端的机器
   - 准备 TSBS 测试数据，CSV 格式、不同时长和设备数量（见[tsbs 生成 csv](https://taosdata.feishu.cn/wiki/Xebww0OhDiqOJekhAr2cC8henVf)）
2. Flink 测试（关胜亮）
   - 准备 Flink 测试环境
   - 开发 Flink 测试数据源
   - 在 Flink 中改写  TDengine 的流语句
   - 执行测试，确保这些语句通过
   - 调研加 Flink 中可能用到的调优参数，并加速计算
3. TDengine 测试（郭向阳）
   - 创建流
   - 使用 taosBenchmark（或者 taosX）读取 CSV 格式的 TSBS 数据并写入服务端
   - 检查数据写入和流计算结束
   - 记录计算时间
   - 记录资源消耗
   - 删除流
   - 生成测试结果
   - 编写脚本，以上步骤一键执行
4. 测试报告（潘魏）
   - 编写测试报告模版，先编写 TDengine 部分，预留填空（数字和图）
   - 调整 TDengine 的测试参数或程序代码，结果达到最优
