### 2.测试用例

```plaintext
trim database {dbName} [max_speed {speedValue}] // 单位: MB/s
```

**目前采用的观测方法，是在taosd日志中查看trim database操作起始和终止时打印的日志，来计算该操作的时间差。通过时间差，以及在trim操作之后，在下一级存储路径上获取计算得到的数据文件大小，来计算出越级迁移的速度。**
**ps：这里的max_speed之前和****@徐开礼讨论，目前的实现是给每个vnode的限速，所以日志中应该计算对应vgroupID执行的时间。 ****讨论，目前的实现是给每个vnode的限速，所以日志中应该计算对应vgroupID执行的时间。**
举个简单的例子：
设置多级存储为3级，每级一个目录，即：
```bash
dataDir /mnt/data1  0 1     # /mnt/data1为第0级存储
dataDir /mnt/data2  1 0    # /mnt/data2为第1级存储
dataDir /mnt/data2  2 0    # /mnt/data2为第2级存储
```

建库时设置keep0，keep1，keep2为（10d，20d，30d），1个vgroup，通过taosBenchmark写入一批数据（写入近30天的数据，时间戳间隔为1ms，每天8640w条，一共2.592亿条），执行trim database后，所以数据应该平均分布在3个目录下。此时计算1、2级目录下vnode文件夹的总大小（rom），以及日志中打印的trim操作时间（time），可以得到speed=rom/time
