## 2. 引言

### 2.1 背景

TDengine 当前的时区处理存在以下问题：

1. **语义分散**：时区在不同场景（写入、读取、函数、INTERVAL）的来源和行为各不相同，没有统一文档规范。
2. **连接级时区未全面生效**：部分场景（普通列读取展示、SHOW/EXPLAIN 时间显示）使用系统时区而非连接级时区，导致同一连接内读写时区不一致。
3. **已有函数时区参数不支持 IANA**：`TO_ISO8601` 的时区参数仅支持偏移量格式，不支持 IANA 名称，无法处理 DST 场景。
4. **一周起始日硬编码**：周级窗口/截断固定以周一为起始日，周日起始的国家/地区无法使用。
5. **文档错误**：TIMETRUNCATE `1w` 的文档描述与实际代码行为不一致。
6. **自然单位支持不完整**：查询侧 `INTERVAL` 不支持周（`w`）/月（`n`）/年（`y`）/季（`q`）；TIMETRUNCATE 缺少月/季/年级截断能力。

### 2.2 目标版本

**v3.4.2**，开源版与企业版均支持。

### 2.3 优先级

高优先级。时区语义不一致是跨国部署场景的核心阻塞问题，影响日报、周报、月报等定时统计业务的正确性。

### 2.4 术语

| 术语 | 定义 |
| --- | --- |
| UTC | 协调世界时，TDengine 内部时间戳的存储基准 |
| IANA 时区名称 | 由 IANA 时区数据库维护的地理时区标识，如 `Asia/Shanghai`，自动包含夏令时规则 |
| 固定偏移 | 以 UTC 为基准的恒定偏移量，如 `+08:00`，不包含夏令时信息 |
| DST | 夏令时（Daylight Saving Time） |
| 挂钟时间 | 当地时钟显示的时间，DST 切换时会出现跳跃或重叠 |
| 自然时间单位 | 长度不固定的日历单位：天（`d`）、周（`w`）、月（`n`）、季度（`q`）、年（`y`） |
| 固定时间单位 | 长度恒定的单位：毫秒（`a`）、秒（`s`）、分钟（`m`）、小时（`h`） |
| L1-L5 | 本文定义的五层时区优先级层级，详见第 4 章 |
| firstDayOfWeek | 一周起始日配置，0=周日、1=周一（默认）、...、6=周六 |

## 4. 时区层级体系

建立五层时区优先级体系：

| 层级 | 名称 | 设定方式 | 生命周期 | 影响范围 |
| --- | --- | --- | --- | --- |
| L1 | SQL 级 | 函数时区参数 | 单条 SQL | 该 SQL 语句内的时区计算 |
| L2 | 连接级 | C API `taos_options_connection` / SQL `SET TIMEZONE` | 单个连接 | 该连接上所有 SQL 的时间解释与服务端计算 |
| L3 | 客户端全局 | 客户端侧 `taos.cfg timezone` | 客户端进程 | 客户端本地行为（时间戳格式化展示） |
| L4 | 服务端全局 | 服务端侧 `taos.cfg timezone` | 服务端进程 | 连接未设时区时服务端计算的回退 |
| L5 | 系统默认 | OS 自动检测 | 永久 | L3/L4 未配置时的最终回退 |

**各场景的回退链**：

| 场景类型 | 回退链 | 说明 |
| --- | --- | --- |
| 客户端本地展示（②⑦） | L2 → L3 → L5 | 回退到客户端全局时区 |
| 服务端计算（①③④⑤⑥） | L1 → L2 → L4 → L5 | 回退到服务端全局时区 |

时区值支持两种格式：IANA 名称（如 `'Asia/Shanghai'`，DST 感知）和固定偏移（如 `'+08:00'`，不感知 DST）。

## 5. 各场景详细行为

### 5.1 场景 ① 写入（INSERT）

**时区来源**：L2→L3→L5（不变）

将不带时区后缀的时间字符串按连接时区转为 UTC。带显式时区后缀的字符串不受连接时区影响。

**DST 行为**：
- 春跳：写入不存在的时刻时自动调整为跳后时刻
- 秋退：写入重叠时刻时由系统选择标准时间解释

**本次改造**：不变

### 5.2 场景 ② 普通列读取

**时区来源**：当前 L3->L5，**改为 L2→L3→L5**

服务端返回 UTC int64，客户端驱动使用连接级时区格式化。

```sql
SET TIMEZONE 'Asia/Shanghai';
SELECT ts FROM t;  -- 2026-03-15 00:00:00.000

SET TIMEZONE 'America/New_York';
SELECT ts FROM t;  -- 2026-03-14 11:00:00.000
```

**本次改造**：F1

### 5.3 场景 ③ 函数读取（TO_ISO8601、TO_CHAR 等）

**时区来源**：有 L1 参数时用 L1，否则 L2→L3→L5

```sql
SELECT TO_ISO8601(ts, 'America/New_York') FROM t;  -- L1: IANA（新增支持）
SELECT TO_ISO8601(ts) FROM t;                       -- 回退 L2
```

**DST 行为**：IANA 时区时，输出偏移量随目标时刻的 DST 状态变化。

**本次改造**：F5

### 5.4 场景 ④ 时刻计算（NOW、TODAY、TIMETRUNCATE）

**时区来源**：L2→L3→L5

| 函数 | 行为 | 时区角色 |
| --- | --- | --- |
| `NOW()` | 返回当前 UTC 纪元值 | 不需要时区 |
| `TODAY()` | 返回连接时区当天 00:00:00 的 UTC 值 | 需要时区确定"今天" |
| `TIMETRUNCATE(ts, unit)` | 截断到指定单位边界 | `d`/`w`/`n`/`q`/`y` 需要时区 |

**TIMETRUNCATE 调整拆分**：

| 类型 | 内容 | 影响范围 |
| --- | --- | --- |
| 行为改造（口径统一） | `1w` 按 `firstDayOfWeek` 对齐到本地周起始日 00:00:00 | 现有 `1w` 行为与文档统一 |
| 行为改造（DST 语义） | `1d/1w` 在 DST 区域按本地挂钟边界截断 | DST 切换日结果可预测 |
| 能力新增（单位扩展） | 新增 `n/q/y` 截断，对齐月首/季首/年首 00:00:00 | 不影响旧 SQL 语义 |

**TIMETRUNCATE 月/季/年截断行为**：

| 单位 | 截断规则 | 示例 |
| --- | --- | --- |
| `n` | 对齐到当月 1 日 00:00:00 | `TIMETRUNCATE('2026-03-15', 1n)` → `2026-03-01 00:00:00` |
| `q` | 对齐到当季首月 1 日 00:00:00 | `TIMETRUNCATE('2026-05-15', 1q)` → `2026-04-01 00:00:00` |
| `y` | 对齐到当年 1 月 1 日 00:00:00 | `TIMETRUNCATE('2026-08-15', 1y)` → `2026-01-01 00:00:00` |
| 多倍数 `2q` | 按 epoch 季度计数整除 | `TIMETRUNCATE('2026-05-15', 2q)` → `2026-01-01 00:00:00` |
| 多倍数 `3n` | 按 epoch 月份计数整除 | `TIMETRUNCATE('2026-05-15', 3n)` → `2026-04-01 00:00:00` |

**本次改造**：F6、F7、F9、F10

### 5.5 场景 ⑤ INTERVAL 时间窗口切分

**时区来源**：L2→L4→L5（已有，不变）

**各单位窗口切分规则**：

| 单位 | 窗口边界 | 多倍数对齐基准 |
| --- | --- | --- |
| `a`/`s`/`m`/`h` | 固定时长整除 | UTC epoch 整除 |
| `d` | 本地时区 00:00:00 | 本地时区 epoch 整除 |
| `w` | 本地时区一周起始日 00:00:00 | 本地时区 epoch 后第一个一周起始日整除 |
| `n` | 本地时区每月 1 日 00:00:00 | epoch 起月份计数整除 |
| `q` | 本地时区每季度首月 1 日 00:00:00 | epoch 起季度计数整除（Q1=1月, Q2=4月, Q3=7月, Q4=10月） |
| `y` | 本地时区每年 1 月 1 日 00:00:00 | epoch 起年份计数整除 |

**DST 行为**：
- `d`/`w` 单位：DST 切换日窗口物理时长变化（春跳日 23h，秋退日 25h），系统按挂钟边界正确处理
- `n`/`y` 单位：月/年边界 UTC 值受 DST 影响，系统在本地时间坐标系计算后换回 UTC

**闰年/变长月处理**：

| 场景 | 行为 |
| --- | --- |
| `INTERVAL(1n)` 经过二月 | 窗口 [2月1日, 3月1日)，28 或 29 天 |
| `INTERVAL(1y)` 跨闰年 | 365 或 366 天 |
| `INTERVAL(1q)` 季度窗口 | Q1=90/91天, Q2=91天, Q3=92天, Q4=92天 |

**FILL 与自然单位**：`INTERVAL(1n) FILL(PREV)` 填充边界逐月推进，自适应实际天数。

**本次改造**：F7（`w` 尊重 firstDayOfWeek）、F11（新增 `w`/`n`/`q`/`y`）

### 5.6 场景 ⑥ WHERE / CAST / JOIN

WHERE 条件中的时间字符串字面量按连接级时区解析为 UTC 进行比较；CAST 在时间戳与字符串之间转换时使用连接级时区；JOIN 条件中涉及时间字符串的比较同理。

**时区来源**：L2→L3→L5（已有，不变）

**本次改造**：不变

### 5.7 场景 ⑦ SHOW / EXPLAIN 时间显示

`SHOW` 命令返回的元数据时间戳（如表创建时间、vnode 状态时间等）和 `EXPLAIN` 输出中的时间信息，当前使用系统时区格式化显示，改为使用连接级时区。

**时区来源**：当前 L3->L5，**改为 L2→L3→L5**

**本次改造**：F2

## 6. 新增 SQL 语法

### 6.1 SET TIMEZONE

```sql
SET TIMEZONE '<timezone_string>';
```

支持 IANA 名称或固定偏移。

### 6.2 SET FIRST_DAY_OF_WEEK

```sql
SET FIRST_DAY_OF_WEEK <value>;
```

`<value>` 为 0-6 整数，0=周日，1=周一（默认），6=周六。

### 6.3 TIMEZONE() 函数增强

同时返回连接级、客户端、服务端三个时区，便于用户排查时区配置问题：

- **连接级时区**（L2）：通过 `SET TIMEZONE` 或 `taos_options_connection` 设置的值，未设置时为空
- **客户端时区**（L3→L5）：客户端 `taos.cfg` 配置或系统检测值
- **服务端时区**（L4→L5）：服务端 `taos.cfg` 配置或系统检测值

## 7. 新增配置参数

### 7.1 firstDayOfWeek

| 属性 | 值 |
| --- | --- |
| 配置文件 | 服务端侧 `taos.cfg` |
| 参数名 | `firstDayOfWeek` |
| 类型 | 整数 |
| 取值范围 | 0-6 |
| 默认值 | 1（周一） |
| 影响范围 | 所有 `w` 单位的边界对齐 |

`firstDayOfWeek` 不提供客户端全局配置——客户端时间戳展示格式 `YYYY-MM-DD HH:MM:SS.mmm` 不涉及周起始日。回退链：L2 → L4 → 默认值 1。

## 8. 错误处理

| 错误场景 | 错误信息 |
| --- | --- |
| 无效时区字符串 | `[0x2600] Invalid timezone: '<value>'` |
| firstDayOfWeek 超出范围 | `[0x2601] Invalid firstDayOfWeek: <value>, must be 0-6` |
| TIMETRUNCATE 第三参数类型错误 | 向后兼容：整数按旧语义（0=UTC, 1=连接时区），字符串按新语义 |

## 9. 兼容性

- 所有默认行为不变（时区回退链不变，`firstDayOfWeek` 默认 1=周一）
- `TIMETRUNCATE` 第三参数传 `0`/`1` 保持旧语义
- 不使用新语法的用户无任何行为变化
