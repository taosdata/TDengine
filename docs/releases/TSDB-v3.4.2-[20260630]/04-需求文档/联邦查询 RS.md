## 2. 引言

### 2.1 术语与缩写名词

| 缩写 | 全称 | 说明 |
| --- | --- | --- |
| **联邦查询** | Federated Query | 在查询执行期访问外部数据源，并与 TDengine 本地数据在同一查询链路中完成过滤、聚合、排序、关联、窗口等计算 |
| **外部数据源** | External Source | 由系统管理的外部访问入口对象，通过 `CREATE EXTERNAL SOURCE` 定义，包含连接器实现和连接配置 |
| **外部连接器** | External Connector | 按数据库类型实现的适配层，负责元数据获取、能力声明、读取执行和结果转换 |
| **外部连接** | External Connection | 访问外部系统的一组配置，包括连接地址、目标库表信息等 |

## 3. 需求目标

当前 TDengine 和 IDMP 在多数据源场景下存在以下痛点：

1. **数据分散**：时序数据分布在 MySQL、PostgreSQL、InfluxDB 与 TDengine 本地集群等多类系统中，需先做数据同步再统一分析，链路长、成本高、交付周期长
2. **缺乏统一入口**：IDMP 作为语义与智能层，无法在不搬迁数据的前提下统一访问多数据源并联合分析
3. **功能适配复杂**：若 IDMP 直接查询第三方数据库，需要针对每种数据库进行额外查询功能适配，无法复用 TSDB 的特色窗口计算、流计算等能力

为解决上述问题，需要让 TSDB 具备联邦查询能力，在不强制迁移数据的前提下提供统一查询入口，支持 TSDB 的全部查询功能，使 IDMP 的建模、可视化、分析、事件和 AI 问数可透明访问第三方时序数据。

## 4. 功能需求

### 4.1 外部数据源管理

1. 支持创建、查看、修改、删除外部数据源对象（`CREATE/SHOW/DESCRIBE/ALTER/DROP EXTERNAL SOURCE`）
2. 支持刷新外部源元数据（`REFRESH EXTERNAL SOURCE`）
3. 外部数据源类型支持 MySQL、PostgreSQL、InfluxDB，其中 MySQL 和 InfluxDB 为高优先级
4. TDengine 外部集群类型预留扩展，首版不交付

### 4.2 外部对象映射

1. MySQL：Database → TDengine 数据库；Table/View → 普通表
2. PostgreSQL：Database + Schema → TDengine 数据库；Table/View/FDW/继承表 → 普通表
3. InfluxDB v3：Database → TDengine 数据库；Measurement → 超级表；Tag → 标签列；Field → 数据列；Tag Set → 子表
4. 索引、存储过程、触发器等非数据对象不参与联邦查询

### 4.3 类型映射

1. 可精确对应的类型直接映射（如 MySQL `INT` → TDengine `INT`）
2. 可降级转换的类型允许映射，但记录日志提示精度或语义损失
3. 完全无法表达的类型拒绝映射，报错 `TSDB_CODE_EXT_TYPE_MISMATCH`
4. 带时区类型统一转换为 UTC，丢弃时区信息

### 4.4 外部路径解析

1. 查询 FROM 子句支持二段式（`source.table`）和三段式（`source.{database|schema}.table`）
2. 虚拟表 DDL 列引用支持三段式（`source.table.column`）和四段式（`source.{database|schema}.table.column`）
3. 短路径使用外部数据源创建时的默认 DATABASE/SCHEMA，未指定默认值时必须使用完整路径
4. 三段式消歧规则：查询 FROM 子句无歧义；虚拟表 DDL 上下文按首段名称区分外部与内部引用

### 4.5 联邦查询

1. 支持单外部源查询、本地与外部联合查询、多外部源联合查询
2. 所有查询语句遵循 TDengine 语义
3. 支持 TSDB 除极少数无概念或类型映射外的全部查询功能，虚拟表相关查询功能为高优先级
4. 不支持的功能：MySQL/PostgreSQL 外部表上的 `TBNAME` 伪列和 `TAGS` 关键字查询（InfluxDB 有例外）

### 4.6 虚拟表引用外部数据源

1. 虚拟表的列引用 FROM 子句扩展为支持外部路径引用
2. 虚拟表必须创建在 TDengine 内部库中
3. 被引用的外部表必须具备时间戳语义的主键或索引列
4. 含外部引用的虚拟表支持所有标准 TDengine 查询语法

### 4.7 查询优化

1. 支持谓词下推、列裁剪、聚合下推
2. 优先源端执行，不可源端执行时本地执行
3. 执行位置仅影响性能，不影响正确性

### 4.8 元数据

1. 新增系统表 `information_schema.ins_ext_sources`，存储所有外部数据源定义信息
2. 普通用户可查询该表，但 `user` 和 `password` 列对非管理员返回 NULL

## 5. 性能需求

1. 默认关闭时对本地查询性能无影响
2. 在可下推场景下显著减少远端读取量
3. TDengine 专有时序功能（窗口计算、FILL、INTERP、TWA 等）、跨源 JOIN、UDF 等无法下推的场景会产生性能退化，用户可通过缩小时间范围和增加过滤条件改善

## 6. 安全需求

1. 密码和敏感凭据必须加密存储，`SHOW`/`DESCRIBE` 与日志中脱敏显示
2. 权限校验覆盖外部数据源对象管理与查询执行全过程
3. 外部通信支持 TLS 加密传输与证书校验
4. 错误路径必须避免敏感信息泄露
5. 对异常返回数据做边界校验，避免崩溃和资源泄漏

## 7. 兼容性需求

1. 默认关闭时，现有行为不变
2. 开启后仅新增对象与行为，不改变原有对象语义
3. 不支持的语义必须显式报错，禁止返回不确定结果
4. 升级脚本需处理外部数据源元数据迁移

## 8. 其他需求

1. 外部数据源名称不允许与 TSDB 中本地库名同名
2. 首批支持 1 种第三方时序源（InfluxDB v3 优先）
3. 需更新企业版文档和官网文档，包括功能介绍、语法规则、权限安全、常见错误排查和运维建议
