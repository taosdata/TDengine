## 3. 需求目标

当前虚拟表在复杂工业场景中存在以下痛点
1. 模型复用性差：公共字段（如设备基础参数）需重复定义，增加建模复杂度
2. 个性化能力缺失：设备特有采集点（如定制传感器）无法动态扩展，导致跨表查询频繁
3. 层级聚合低效：需手动合并多个虚拟超级表（VST）数据，无法实现“父模型自动包含子模型”的聚合逻辑
为了让 TDengine 在物联网建模上变得极为灵活，需开发如下功能
1. 虚拟超级表支持继承，参考语法
```sql {wrap}
CREATE VIRTUAL STABLE vst2 BASE ON vst1;
```

1. 虚拟子表支持私有数据列，参考语法
```sql {wrap}
CREATE VIRTUAL TABLE v_child USING vst2 TAGS (...) 
    PRIVATE (
        col1 FROM …… 
        col2 FROM …… 
    );
```

## 4. 功能需求

### 4.1 虚拟超级表继承机制

1. 多级继承
   - 继承深度最少支持 10 级，形成树状结构
   - 禁止循环继承（如 `vst1 → vst2 → vst1`），创建时自动检测 DAG 依赖
2. 聚合范围动态控制
   - 聚合子 VST（例如 `vst2`） ：只处理直接基于`vst2`创建的虚拟子表
   - 聚合父 VST（例如 `vst1`）：包含`vst1`直接子表 + 所有继承自`vst1`的子表（如`vst2`、`vst3`）
3. 元数据修改联动
   - 修改父 VST 结构（如新增列），自动同步至所有子 VST
   - 删除父 VST 时级联检查依赖关系，禁止直接删除被继承的 VST

### 4.2 虚拟子表私有数据列扩展

数据列可见规则如下

| 查询对象 | 返回列范围 | 示例 |
| --- | --- | --- |
| 虚拟超级表 | 仅基础列，不含子表私有列 | `select * from `<text color="red">`vst`</text>` where tbname= vct` |
| 虚拟子表 | 基础列 + 子表私有列 | `select * from `<text color="red">`vct`</text> |

### 4.3 元数据

1. 新增系统表 `INFORMATION_SCHEMA.INS_INHERITS`，记录 `parent_vst`、`child_vst` 关系
2. 子表的 describe 结果相应调整
3. 系统表 ins_columns、ins_tables、ins_stables 等相应调整

## 6. 安全需求

权限控制需求
1. 子 VST 在创建后，自动继承父 VST 的权限
2. 子 VST 可以自定义权限
3. 父 VCT 修改权限后，自动同步至所有子 VST，覆盖子 VST 的原有权限
审计需求
1. 虚拟超级表的增删改操作，需要记录审计日志

## 7. 兼容性需求

1. 兼容低版本虚拟表存储，不需重新创建
