## 1. 当前问题

### 1.1 同一功能多处出现，维护困难

"数据订阅"在 `06-advanced/01-subscription/` 讲概念，在 `07-develop/07-tmq.md`
讲编程，两处内容重叠且容易不同步。类似的还有写入（basic vs develop/stmt/schemaless）、
查询、流计算等功能。

### 1.2 语法手册缺场景，用户不知何时使用

当前 SQL 手册是纯语法参考，只告诉用户"怎么写"，不告诉"什么场景下用"。
每项功能都是为了给用户带来价值的，这个价值必须在文档中明确传达。

### 1.3 "基础/高级/开发"三区划分模糊

`05-basic`（建模、写入、查询）、`06-advanced`（订阅、流计算、数据接入）、
`07-develop`（连接、SQL、参数绑定）的边界不清晰，用户不确定该在哪里找内容。

### 1.4 SQL 参考埋藏过深

SQL 手册作为最高频查阅内容，路径为
`14-reference/03-taos-sql/`，需 3 次点击才能到达。

### 1.5 连接器信息分散

连接器教程在 `07-develop/01-connect/`，API 详情在 `14-reference/05-connector/`，
用户需在两处间反复跳转。

### 1.6 编号断层与资源管理不统一

章节编号跳跃（缺 09, 11-13, 15-24），暗示历史删改痕迹。图片管理不统一，
部分目录有 `pic/`，部分使用 `assets/`、`img/` 或直接混放。

### 1.7 竞品对标

主流时序/分析数据库均采用任务导向或认知阶段式组织，TDengine 当前采用书籍章节式。

### 1.8 安全能力缺少统一汇总入口

当前安全相关内容分散在运维、开发、连接器配置和 SQL 权限语法中，
用户难以快速回答“TDengine 提供了哪些安全能力、分别在什么层面生效”。
需要在目录与导航层明确“安全能力总览 + 分层入口”，降低安全治理认知成本。

## 2. 优化目标

| 目标 | 说明 |
|------|------|
| **内容不重复** | 每个知识点只在一处详述，其他处以链接引用 |
| **场景与语法合一** | 语法手册中直接告诉用户"什么场景下用 + 怎么写"，不再分散 |
| **消除三区混乱** | 取消 basic/advanced/develop 的划分，按内容本质组织 |
| **SQL 手册提升为顶层** | `04-taos-sql/` 作为一级目录，1 跳直达 |
| **运维与组件工具一体化** | 运行维护与组件/工具按一个章节组织，减少用户跨章节跳转 |
| **连接器信息合一** | 教程与 API 统一在开发指南，消除跳转 |
| **安全能力汇总** | 提供统一安全能力导航，覆盖认证授权、传输安全、数据安全、审计合规 |
| **编号连续** | 00-18 连续编号，无断层 |
