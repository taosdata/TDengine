## 2. 背景

当前状态窗口只支持单列状态键，不支持以多个状态列联合定义窗口边界。该能力计划解决单列状态窗口只能描述单一状态维度的问题，能够覆盖以下业务场景：

- 设备状态由多个离散字段共同决定，例如 `run_state` 与 `mode`；
- 告警状态由 `level` 与 `source` 联合定义；
- 流式任务需要在多个状态字段任一变化时关闭当前窗口并触发通知。

## 3. 定义

- 状态窗口：按状态键连续不变的数据片段划分出的窗口。
- 状态键：用于判断窗口是否延续的一组值。单列状态窗口对应一个状态键，多列状态窗口对应一个按顺序排列的状态键列表。
- 多列状态键：由两个及以上列组成的状态键，例如 `STATE_WINDOW(s1, s2)`。
- 切窗：当前行状态键与上一条有效状态键不一致时，关闭旧窗口并开启新窗口。
- 有效记录：参与状态键比较的记录。多列状态窗口按列独立判定：若某列为 `NULL`，该列对本行不参与切窗判定；当且仅当当前行**所有**状态键列均为 `NULL` 时，整行才走与单列状态窗口一致的空值路径，详见 4.5 节。
- 上一有效状态键：当前窗口内每个状态键列最近一次出现的非 `NULL` 值，按列独立维护；若窗口内某列从未出现过非 `NULL` 值，则该列视为「未定义」。
- 部分 `NULL` 候选段：由连续的部分 `NULL` 行（可能夹杂全 `NULL` 行）组成的极大数据段。段内维护一个**累积状态**（每列取该段内最近一次出现的非 `NULL` 值），每当新的部分 `NULL` 行到达时，将其非 `NULL` 列与累积状态中已定义的对应列比较——若任一列值不同则触发切窗，终止当前候选段。该段作为一个整体参与归属决策（详见 4.5.2 节）。
- `EXTEND(n)`：状态窗口边界扩展选项。当前实现支持 `0`、`1`、`2`，分别对应默认、backward、forward 扩展，语义与现有单列状态窗口一致。
- `ZEROTH_STATE(...)`：零状态配置。用于在窗口结果中过滤零状态窗口。
- `NO_ZEROTH`：`ZEROTH_STATE` 中的占位值，表示对应位置的状态列不配置零状态。

## 4. 行为说明

### 4.1 总体原则

状态窗口的核心语义没有变化：状态键不变则继续累积到当前窗口，状态键变化则关闭当前窗口并从当前记录开启新窗口。多列支持只是把“单值比较”扩展为“按顺序逐列比较”。

### 4.2 SQL 语法

`STATE_WINDOW` 在支持多列状态键的同时，**必须与历史版本单列写法保持语法兼容**。**单列**时，历史写法仍可将扩展模式与零状态配置放在 `STATE_WINDOW(...)` **圆括号内、且位于该唯一状态键之后**：括号内只使用**位置参数**（字面量 / 常量），不出现 `EXTEND`、`ZEROTH_STATE` 关键字，语义分别对应 `EXTEND(n)` 与 `ZEROTH_STATE(...)`。

**多列**（两个及以上状态键）时，圆括号内**仅**允许状态键表达式，**不允许**在括号内再写扩展模式字面量、零状态位置参数，也**不允许**在括号内写 `EXTEND(...)` / `ZEROTH_STATE(...)`；若需要扩展或零状态，**必须**使用**形式二**，将 `EXTEND(...)`、`ZEROTH_STATE(...)` 写在右括号之外。这样可避免多列时尾随字面量与状态键表达式在解析上产生歧义。

**形式一：仅单列——兼容历史（括号内位置参数，无 `EXTEND`/`ZEROTH_STATE` 关键字）**

在**唯一**状态键参数之后，解析器按固定后缀解析（与历史单列约定一致）：

1. 可选：**扩展模式** `n`，为字面量 `0`、`1` 或 `2`，语义同 `EXTEND(n)`。
2. 可选：**零状态参数** `z`（单列仅一个），仅支持常量，语义同 `ZEROTH_STATE(z)`。若需要配置零状态而省略扩展模式，须先写出默认扩展 `0` 再写零状态参数（例如 `STATE_WINDOW(c1, 0, 0)`），或改用形式二。

```sql
STATE_WINDOW(state_key [, n [, z]])
[TRUE_FOR(...)]
```

**形式二：子句写法（单列与多列均可；多列若需扩展/零状态时必须使用本形式）**

```sql
STATE_WINDOW(state_key_1 [, state_key_2, ...])
  [EXTEND(n)]
  [ZEROTH_STATE(z1 [, z2, ...])]
[TRUE_FOR(...)]
```

说明如下：

- `STATE_WINDOW(...)` 可以写 1 个或多个状态键；状态键可以是列引用或 `case when`、`if` 表达式。
- **单列**：可选用形式一或形式二；**同一语句不得混用**（例如 `STATE_WINDOW(c1, 0) ZEROTH_STATE(...)` 非法）。**单列**圆括号内**不得**书写 `EXTEND(...)` 或 `ZEROTH_STATE(...)` 关键字。
- **多列**：多个状态键通过逗号分隔，例如 `STATE_WINDOW(k1, k2, ...)`；一旦需要扩展或零状态，**只能**在右括号后接 `EXTEND`/`ZEROTH_STATE` 子句。
- 零状态子句（或形式一末尾的 `z`）参数个数须与状态键个数一致。

示例（形式一，仅单列）：

```sql
-- c1 为整数类型
STATE_WINDOW(c1)
STATE_WINDOW(c1, 0)
STATE_WINDOW(c1, 0, 0)
STATE_WINDOW(CASE WHEN c1 < 0 THEN c1 ELSE c2 END, 0)
STATE_WINDOW(c1) EXTEND(0) ZEROTH_STATE(0)
```

示例（多列：必须使用形式二配置扩展/零状态）：

```sql
STATE_WINDOW(s1, s2)
STATE_WINDOW(CASE WHEN s1 < 0 THEN 0 ELSE s1 END, CASE WHEN s2 = 'OFF' THEN 'idle' ELSE s2 END)
STATE_WINDOW(s1, s2) EXTEND(0)
STATE_WINDOW(s1, s2) EXTEND(0) ZEROTH_STATE(1, NO_ZEROTH)
STATE_WINDOW(s1, s2) EXTEND(0) ZEROTH_STATE(1, 'OFF') TRUE_FOR(10s)
```

### 4.3 状态键比较规则

多列状态键的切窗规则与单列状态窗口一致，即：当状态键中的任意一列变化时，切窗。

示例：

- `(1, 'a') -> (1, 'a')`：不切窗；
- `(1, 'a') -> (2, 'a')`：切窗；
- `(1, 'a') -> (1, 'b')`：切窗；
- `(1, 'a') -> (2, 'b')`：切窗。

### 4.4 状态键输入限制

多列输出时每个状态键的要求与单列状态窗口一致：

- 支持的状态键类型仍沿用现有状态窗口限制，只支持整数类型、布尔类型和变长字符串类型；
- 支持 `case when` 和 `if` 表达式作为状态键，但返回值类型必须为整数、布尔或变长字符串；
- 单独 tag 列不能作为状态键，但可在表达式中使用；

因此：

- `STATE_WINDOW(c1)` 合法；
- `STATE_WINDOW(CAST(c1 AS VARCHAR(8)))` 合法；
- `STATE_WINDOW(c1, c2)` 合法；
- `STATE_WINDOW(c1, CASE WHEN c2 > 0 THEN 1 ELSE 0 END)` 合法；
- `STATE_WINDOW(CASE WHEN c1 > 0 THEN c1 ELSE 0 END, CASE WHEN c2 > tag2 THEN 1 ELSE 0 END)` 合法；
- `STATE_WINDOW(tag1, c1)` 非法。

### 4.5 `NULL` 处理

多列状态窗口在现有单列空值语义基础上扩展为「按列独立判定 + 归属决策」。判定基准是：

- 前一窗口的「上一有效状态键」P = (p1, ..., pn)：pi 记录列 i 在前一窗口内最近一次出现的非 `NULL` 值；
- 后一候选窗口首行对应状态键 N = (n1, ..., nn)（若存在）。

对当前行 r = (r1, ..., rn) 按是否为全 `NULL` 分两类处理。

#### 4.5.1 全 `NULL` 行（所有状态键列均为 `NULL`）

全 `NULL` 行处理逻辑保持不变：

- 不参与按列切窗判定；
- 归属规则与单列状态窗口一致；
- `EXTEND(...)` 对全 `NULL` 段的影响保持不变。

#### 4.5.2 部分 `NULL` 候选段

当连续若干行均为部分 `NULL`（至少一列非 `NULL`）或全 `NULL` 时，段内按**累积状态**逐行判定是否延续：每个部分 `NULL` 行的非 `NULL` 列与累积状态中已定义的对应列比较，若值相同或对应列尚未定义则继续累积（并将未定义列初始化为当前值），否则触发切窗、终止当前候选段。未被切窗终止的连续行构成一个**部分 `NULL` 候选段**。候选段作为整体参与归属决策，必须归属到前一窗口、后一窗口，或独立成窗，**不可丢弃**。候选段内夹杂的全 `NULL` 行随段整体归属，不再单独按 4.5.1 处理。

定义兼容性（基于候选段的累积状态与前/后窗口状态的比较）：

- 前兼容：候选段累积状态中所有已定义列与前一窗口 P 对应列相等；
- 后兼容：候选段累积状态中所有已定义列与后一候选窗口首行 N 对应列相等。

开头或结尾位置的候选段，默认最多只可能与一侧兼容（因为另一侧窗口不存在）。

候选段归属决策如下表：

| 兼容性 | `EXTEND(0)` | `EXTEND(1)` | `EXTEND(2)` |
| --- | --- | --- | --- |
| 前后都兼容 | 向前合并 | 向前合并 | 向后合并 |
| 仅前兼容   | 向前合并 | 向前合并 | 独立成窗 |
| 仅后兼容   | 向后合并 | 独立成窗 | 向后合并 |
| 前后都不兼容 | 独立成窗 | 独立成窗 | 独立成窗 |

示例（状态键为 `(c1, c2)`，按时间顺序）：

基础四类（与决策表一一对应）：

- 前后都兼容：`(1, 10) -> (1, NULL) -> (1, 20)`，候选段为部分 `NULL`；`EXTEND(0|1)` 向前合并，`EXTEND(2)` 向后合并；
- 仅前兼容：`(1, 'a') -> (1, NULL) -> (2, 'a')`，候选段仅与前窗兼容；`EXTEND(0|1)` 向前合并，`EXTEND(2)` 独立成窗；
- 仅后兼容：`(1, 'a') -> (NULL, 'b') -> (1, 'b')`，候选段仅与后窗兼容；`EXTEND(0|2)` 向后合并，`EXTEND(1)` 独立成窗；
- 前后都不兼容：`(1, 'a') -> (NULL, 'b') -> (2, 'a')`，候选段与前后均不兼容；三种 `EXTEND` 均独立成窗。

边界位置（开头/结尾最多单侧兼容）：

- 开头仅后兼容：`(NULL, 'b') -> (1, 'b') -> (1, 'b')`，候选段无法前兼容，仅可后兼容；`EXTEND(0|2)` 向后合并，`EXTEND(1)` 独立成窗；
- 开头后不兼容：`(NULL, 'b') -> (1, 'a') -> (1, 'a')`，候选段既无前窗又与后窗不兼容；三种 `EXTEND` 均独立成窗；
- 结尾仅前兼容：`(1, 'a') -> (1, 'a') -> (1, NULL)`，候选段无法后兼容，仅可前兼容；`EXTEND(0|1)` 向前合并，`EXTEND(2)` 独立成窗；
- 结尾前不兼容：`(1, 'a') -> (1, 'a') -> (NULL, 'b')`，候选段与前窗不兼容且无后窗；三种 `EXTEND` 均独立成窗。

多行候选段：

- 双行仅后兼容：`(1, 'a') -> (NULL, 'b') -> (NULL, 'b') -> (1, 'b')`，两行候选段整体仅后兼容；`EXTEND(0|2)` 向后合并，`EXTEND(1)` 独立成窗；
- 双行仅前兼容：`(1, 'a') -> (1, NULL) -> (1, NULL) -> (2, 'a')`，两行候选段整体仅前兼容；`EXTEND(0|1)` 向前合并，`EXTEND(2)` 独立成窗；
- 夹杂全 `NULL`：`(1, 'a') -> (1, NULL) -> (NULL, NULL) -> (1, NULL) -> (2, 'a')`，中间三行（含一行全 `NULL`）构成候选段，整体仅前兼容；`EXTEND(0|1)` 向前合并，`EXTEND(2)` 独立成窗；
- 独立全 `NULL` 段：`(NULL, NULL) -> (NULL, NULL)`，不含部分 `NULL` 行，不构成候选段，按 4.5.1 全 `NULL` 路径处理。

### 4.6 `EXTEND(...)`

`EXTEND(...)` 的行为没有因为多列状态键而改变，只是比较对象从单个状态值变成了多个状态列。

当前实现支持的取值为：

- `EXTEND(0)`：默认行为；
- `EXTEND(1)`：向后扩展；
- `EXTEND(2)`：向前扩展。

语义保持与现有单列状态窗口一致。`EXTEND(...)` 在多列场景下作用于「归属决策」，不改变“任一非 `NULL` 列变化即切窗”的基本判定。具体而言：

- 对全 `NULL` 行：处理逻辑不变，`EXTEND(...)` 影响保持与单列一致；
- 对部分 `NULL` 候选段：按 4.5.2 决策表归属。可概括为：
  - 前后都兼容时：`EXTEND(0|1)` 向前，`EXTEND(2)` 向后；
  - 仅前兼容时：`EXTEND(0|1)` 向前，`EXTEND(2)` 独立；
  - 仅后兼容时：`EXTEND(0|2)` 向后，`EXTEND(1)` 独立；
  - 前后都不兼容时：三种 `EXTEND` 均独立。

`EXTEND(...)` 不影响以下规则：

- 全非 `NULL` 行按 4.3 逐列比较，任一列变化即切窗；
- 「上一有效状态键」按列独立维护、`NULL` 列不参与比较且不更新对应槽位；
- `ZEROTH_STATE(...)` 的过滤判定。

### 4.7 `ZEROTH_STATE(...)` 和 `NO_ZEROTH`

#### 4.7.1 配置规则

当前实现支持多列 `ZEROTH_STATE(...)`，并要求其参数个数与状态键个数完全一致。

例如：

```sql
STATE_WINDOW(s1, s2) EXTEND(0) ZEROTH_STATE(1, NO_ZEROTH)
STATE_WINDOW(s1, s2, s3) EXTEND(0) ZEROTH_STATE(0, NO_ZEROTH, 'IDLE')
```

规则如下：

- 每个位置的零状态与对应位置的状态列一一对应；
- `NO_ZEROTH` 表示该列不参与零状态判断；
- 若配置了 `ZEROTH_STATE(...)`，其参数个数必须与状态键个数一致，否则直接报错；
- 非 `NO_ZEROTH` 的零状态值必须是常量，且可被转换为对应状态列的数据类型。

#### 4.7.2 过滤语义

当前实现会把 `ZEROTH_STATE(...)` 翻译为“至少有一个受约束状态列不等于对应零状态值”的过滤条件。

等价地说：

- 只有当所有已配置零状态的列都等于各自的零状态值时，该窗口才会被视为零状态窗口并被过滤；
- `NO_ZEROTH` 对应的位置不参与该判断；
- 如果所有位置都是 `NO_ZEROTH`，则等价于未配置 `ZEROTH_STATE(...)`。

#### 4.7.3 示例

```sql
SELECT _wstart, _wend, count(*), s1, s2
FROM ntb
STATE_WINDOW(s1, s2) EXTEND(0) ZEROTH_STATE(1, NO_ZEROTH)
ORDER BY _wstart;
```

该 SQL 的含义是：

- `s1`、`s2` 共同定义窗口；
- 只要 `s1` 或 `s2` 任一变化就切窗；
- 零状态只约束 `s1 = 1`，`s2` 不参与零状态判断；
- 因此 `s1 = 1` 的窗口会被过滤，无论 `s2` 的值是什么。

### 4.8 `TRUE_FOR(...)`

`TRUE_FOR(...)` 的行为保持不变。

### 4.9 查询行为示例

由于现有官网智能电表示例表中缺少两个同时满足“非 tag 且类型可用于状态窗口”的离散状态列，本节示例使用普通表演示多列状态窗口语义。

#### 4.9.1 多列切窗

```sql
SELECT _wstart, _wend, count(*), s1, s2
FROM ntb
STATE_WINDOW(s1, s2)
ORDER BY _wstart;
```

对如下数据：

```sql
-- (ts, s1, s2)
(10:00:00, 1, 'a')
(10:00:01, 1, 'a')
(10:00:02, 2, 'a')
(10:00:03, 2, 'b')
(10:00:04, 2, 'b')
```

结果会切成 3 个窗口：

- `(1, 'a')` 对应 `[10:00:00, 10:00:01]`；
- `(2, 'a')` 对应 `[10:00:02, 10:00:02]`；
- `(2, 'b')` 对应 `[10:00:03, 10:00:04]`。

#### 4.9.2 多列零状态过滤

```sql
SELECT _wstart, _wend, count(*), s1, s2
FROM ntb
STATE_WINDOW(s1, s2) EXTEND(0) ZEROTH_STATE(1, NO_ZEROTH)
ORDER BY _wstart;
```

对于如下窗口序列：

- `(1, 'a')`
- `(2, 'a')`
- `(2, 'b')`
- `(1, 'b')`
- `(3, 'c')`

结果会过滤掉 `s1 = 1` 的窗口，仅保留：

- `(2, 'a')`
- `(2, 'b')`
- `(3, 'c')`

### 4.10 流计算与通知行为

#### 4.10.1 流计算触发

- **建流解析与校验**：触发类型与查询一致，支持多列状态键；**单列**时扩展与零状态可选用括号内位置参数或括号外子句（不得混用）；**多列**时若需扩展或零状态，**仅允许**括号外 `EXTEND`/`ZEROTH_STATE` 子句。并可携带 `TRUE_FOR(...)`。状态键个数、零状态参数个数及类型限制与「状态键输入限制」「`ZEROTH_STATE`」各节相同，在 `CREATE STREAM` 阶段即校验，避免运行期才发现配置错误。
- **触发器元数据与部署消息**：状态窗口触发描述从单槽位扩展为**有序多槽位**（列或表达式在槽位中的顺序与 SQL 中 `STATE_WINDOW` 参数顺序一致），持久化与 mnode → vnode / snode 的下发格式需采用兼容演进（见本文「兼容性」中「流触发器部署消息」）；解码后各执行节点按同一顺序维护「上一有效状态键」，避免多节点对列顺序理解不一致。
- **触发事件语义**：流计算仍是在**窗口打开、窗口关闭**等窗口生命周期事件上触发子查询执行与通知发送，事件类型集合不与单列场景冲突；**变化**在于判定「当前是否发生关窗 / 开窗」时，比较对象由单值变为多列状态键——**任一状态列**相对上一有效状态发生变化即关闭当前窗口并自当前数据行开启新窗口（与查询路径切窗规则一致）。因此在写入节奏不变的前提下，多列状态键可能比单列更易因多维度抖动而增加切窗与触发次数。

#### 4.10.2 流计算切窗

流计算状态窗口的切窗规则与查询一致。需要在实时计算和历史回放两条路径中统一支持多列状态键。

示例：

```sql
CREATE STREAM s_multi_state
INTO result_table
AS
SELECT _wstart, _wend, count(*), avg(v)
FROM ntb
STATE_WINDOW(s1, s2) EXTEND(0);
```

当 `s1` 或 `s2` 任一变化时：

- 当前窗口关闭；
- 从当前行开启新窗口；
- 聚合结果按现有状态窗口语义输出。

### 4.11 `window_open/window_close` 通知内容

对单列状态窗口，通知 JSON 保持现有标量字段形式。

对多列状态窗口，需要实现的通知 JSON 改为数组字段：

- `window_open`：

```json
{"prevState":[1,"a"],"curState":[2,"a"]}
```

- `window_close`：

```json
{"curState":[2,"a"],"nextState":[2,"b"]}
```

这意味着：

- 多列状态窗口的通知消费者需要按数组顺序解析状态值；
- 数组元素顺序与 `STATE_WINDOW(c1, c2, ...)` 中的列顺序完全一致；
- 单列状态窗口通知格式不变。

### 4.12 Explain 输出

当前实现中，`EXPLAIN` 对多列状态窗口的展示也已更新为列列表，例如：

```text
StateWindow on Columns s1,s2
```

### 4.13 错误处理

以下是当前实现下的重要报错场景：

- `STATE_WINDOW()`
  - 语法错误，至少需要一个状态键。
- `STATE_WINDOW(tag1, c1)`
  - 报错：状态窗口不支持 tag 列。
- `STATE_WINDOW(c1, c2) ZEROTH_STATE(0)`
  - 报错：零状态参数个数必须与状态键个数一致。
- `STATE_WINDOW(c1, c2) ZEROTH_STATE(c1, 0)`
  - 报错：零状态只接受常量或 `NO_ZEROTH`。
- `STATE_WINDOW(c1, c2) EXTEND(3)`
  - 报错：扩展模式仅支持 `0`、`1`、`2`。
- `STATE_WINDOW(c1, c2, 0)`、`STATE_WINDOW(c1, c2, 0, 1, NO_ZEROTH)`、`STATE_WINDOW(c1, c2, 3)` 等（**多列**时在括号内尾随扩展字面量或零状态参数）
  - 报错：语法错误；多列状态窗口不得在圆括号内配置 `EXTEND`/`ZEROTH_STATE`（含位置参数形式），应写为 `STATE_WINDOW(c1, c2) EXTEND(...)` / `ZEROTH_STATE(...)`。
- `STATE_WINDOW(c1, c2, EXTEND(0), ZEROTH_STATE(1, NO_ZEROTH))` 或 `STATE_WINDOW(c1, c2, ZEROTH_STATE(1, NO_ZEROTH))`
  - 报错：语法错误；圆括号内不得出现 `EXTEND`/`ZEROTH_STATE` 关键字，多列时须整组使用子句形式。
- `STATE_WINDOW(c1, 0) ZEROTH_STATE(0)`（**单列**括号内已有位置参数后缀，括号外再写子句）
  - 报错：语法错误；单列须**只采用**括号内位置参数形式或**只采用**括号外子句形式，不得拆分混用。
- `STATE_WINDOW(cfloat, c1)`
  - 报错：状态窗口只支持整数、布尔和变长字符串类型。

## 5. 性能

多列状态窗口的主要性能变化如下：

- 单行状态比较从单值比较变为逐列比较，复杂度从 $O(1)$ 增加为 $O(n)$，其中 $n$ 为状态键列数；
- `NULL` 检查也变为逐列检查；
- 查询执行器需要缓存多个上一行状态键，而不是一个状态值；
- 流计算在多列场景下需要维护状态值数组，并在通知场景下构造数组型 JSON。

影响评估：

- 对常见的 2 到 4 列状态键场景，性能影响可控；
- 对高频切窗场景，额外开销主要来自逐列比较和通知 JSON 构造；
- 当前虚拟表窗口优化路径仍主要针对单列列引用场景，多列状态窗口会走通用路径，因此多列状态窗口在特定优化场景下可能略慢于单列窗口，遗留TODO。

## 6. 安全

本需求不引入新的权限模型、认证机制或跨组件访问控制逻辑。

安全影响主要体现在：

- 需要保证状态键顺序稳定，避免不同节点对多列顺序理解不一致导致错误切窗；
- 需要保证流式通知内容中的状态数组顺序与 SQL 定义顺序一致，避免通知消费者误读；
- 对非法 SQL 需要返回明确错误，避免进入不确定执行路径。

## 7. 兼容性

### 7.1 向前兼容

- 现有单列状态窗口 SQL 保持兼容；
- 单列表达式状态窗口保持兼容；
- 单列下**历史写法** `STATE_WINDOW(col [, n [, z]])`（扩展模式 `n` 与零状态 `z` 为圆括号内的位置参数，**无** `EXTEND`/`ZEROTH_STATE` 关键字）保持兼容；
- 单列 `TRUE_FOR(...)` 及与子句形式 `STATE_WINDOW(col) EXTEND(n) ZEROTH_STATE(z)` 的等价组合保持兼容；
- 多列为本需求新增路径：凡需 `EXTEND`/`ZEROTH_STATE` 的，统一采用子句形式，与「多列不得使用括号内扩展/零状态」规则一致，不涉及旧脚本迁移；
- 单列流通知 JSON 保持兼容。

### 7.2 向后兼容

流触发器部署消息需要兼容旧单列状态窗口的序列化格式：

- 新实现对多列状态窗口使用槽位数组编码；
- 解码端仍可读取旧的单槽位格式；
- 旧的单列状态窗口流定义不需要因为本功能而重建。

### 7.3 兼容性注意事项

- 多列状态窗口是新增能力，旧客户端在不使用该语法时不受影响；
- 如果业务为多列状态窗口配置了 `window_open/window_close` 通知，通知接收方需要支持数组型状态字段；
- 多列状态窗口不会放宽现有状态窗口对 tag、类型和非法表达式的限制。

## 8. 运维

本功能不引入新的部署组件、配置文件或安装脚本要求。

运维与支持侧需要关注：

- 回归验证单列状态窗口行为未变化；
- 验证多列状态窗口在查询、实时流、历史回放三条路径上结果一致；
- 如果使用流通知，需要确认消费端已经适配数组型状态字段；
- 升级后如需排查执行计划，可通过 `EXPLAIN` 观察多列状态键展示是否符合预期。

## 9. 使用场景

- 工业设备运行分析：`run_state` 与 `mode` 联合定义运行窗口；
- 告警压缩：`alarm_level` 与 `alarm_source` 共同决定告警窗口边界；
- 生产状态切换分析：`status_code` 与 `recipe_id` 共同定义工单窗口；
- 流式通知：当任一关键状态字段变化时发送 `window_open/window_close`；
- 零状态过滤：仅过滤“全部受约束状态列同时命中零状态”的窗口。

## 10. 约束和限制

约束：

- 多列状态窗口中每个状态键都必须来自当前输入记录；
- 多列状态窗口支持列引用和表达式列表；
- `ZEROTH_STATE(...)` 参数个数必须与状态键个数一致；
- `NO_ZEROTH` 只能作为零状态占位值使用；
- **单列**：扩展与零状态须**整组**采用「圆括号内位置参数」或**整组**采用「右括号后 `EXTEND`/`ZEROTH_STATE` 子句」，不得拆分混用；圆括号内**不得**书写 `EXTEND`/`ZEROTH_STATE` 关键字。
- **多列**：圆括号内**仅**状态键；若需扩展或零状态，**仅允许**右括号后的 `EXTEND`/`ZEROTH_STATE` 子句（见「SQL 语法」「错误处理」）。

限制：

- 状态键类型仍限制为整数、布尔和变长字符串；
- tag 列仍不能作为状态键；
- 多列场景下 `NULL` 按「全 `NULL` / 部分 `NULL`」分治（详见 4.5）：全 `NULL` 行沿用单列一致路径；连续的部分 `NULL` 行（可能夹杂全 `NULL` 行）构成候选段，候选段作为整体必须归属于前窗、后窗或独立窗，不可丢弃，具体由前/后兼容性与 `EXTEND(0|1|2)` 共同决定；
- 多列状态窗口当前没有单列列引用路径那样的全部优化机会，在部分场景下性能会弱于单列状态窗口；
- 多列状态窗口若需配置扩展或零状态，**仅**支持 `EXTEND`/`ZEROTH_STATE` 子句，**不支持**在 `STATE_WINDOW(...)` 圆括号内尾随字面量或关键字形式。

## 11. 常见错误和排查

- 语法错误
  - **单列**：检查是否混用括号内位置参数与括号外子句，或在圆括号内误写了 `EXTEND`/`ZEROTH_STATE` 关键字。
  - **多列**：检查是否把扩展字面量或零状态参数写在 `STATE_WINDOW(...)` 圆括号内；若需扩展/零状态，应全部放在右括号后的子句中。
- `ZEROTH_STATE argument count must match STATE_WINDOW key count`
  - 检查 `ZEROTH_STATE(...)` 参数个数是否与状态键个数一致。
- `Only support STATE_WINDOW on integer/bool/varchar column`
  - 检查状态键表达式的返回类型是否为整数、布尔或变长字符串。
- `Not support STATE_WINDOW on tag column`
  - 检查是否误用了 tag 列。
- 多列流通知消费失败
  - 检查通知接收方是否仍按单值 `curState/nextState` 解析，而没有适配数组。
- 切窗次数比预期多
  - 检查多个状态列中是否有高频抖动列；任一列变化都会切窗。
