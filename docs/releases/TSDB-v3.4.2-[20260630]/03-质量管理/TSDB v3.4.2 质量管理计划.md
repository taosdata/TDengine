## 2. 文档概述

### 2.1 目的

本文档旨在明确 TDengine TSDB v3.4.2 项目的质量管理目标、质量活动安排、角色职责划分及质量验收标准。v3.4.2 重点推进窗口函数与 OVER 子句支持、虚拟表继承、联邦查询演示、元数据变更事务及集群稳定性提升，同时完成 Explorer 数据导出（Parquet/Kafka/MQTT）、taosX 高可用、连接器高可用以及 License Server 正式发布等工具链建设，并持续推进安全漏洞修复和平台基础设施改进（日志监控、崩溃模拟生成、GitLab 迁移）。本文档在 v3.4.1 质量管理改进成果的基础上进一步深化过程改进。

### 2.2 适用范围

本计划适用于 TSDB v3.4.2 全部开发活动，时间范围为 2026-04-01 至 2026-06-30（发布日期）；含系统测试延伸至 2026-07-25，项目总结至 2026-07-30。

## 3. 项目质量目标

### 3.1 整体质量目标

1. **过程合规性**：各开发阶段严格遵循质量保证制度要求，不符合项关闭率达到 100%。
2. **文档完整性**：需求、设计、测试等关键文档按计划编写并完成评审，文档完整率达到 95% 以上。
3. **缺陷管理**：系统测试阶段结束时，P0/P1 缺陷全部关闭，P2 缺陷关闭率达到 90% 以上。
4. **安全漏洞修复**：本版本识别的高优先级安全漏洞全部完成修复并通过安全验证；漏洞扫描服务器投入使用。
5. **缺陷报告规范率**：延续 v3.4.1 改进成果，缺陷报告规范率 ≥ 95%。
6. **需求追踪及时率**：延续 v3.4.1 改进成果，RTM 每周更新及时率 100%。
7. **集群稳定性**：集群稳定性测试（IDMP 稳定性测试框架）通过，无复现率 > 50% 的崩溃问题。

### 3.2 分阶段质量目标

| 阶段 | 时间范围 | 质量目标 |
| --- | --- | --- |
| 需求与设计阶段 | 2026-04-01 ~ 2026-04-30 | 需求文档评审通过率 100%；设计文档评审通过率 100% |
| 开发及功能测试阶段 | 2026-05-01 ~ 2026-06-30 | 功能测试缺陷报告规范率 ≥ 95%；代码评审覆盖率 ≥ 80% |
| 系统测试与验收阶段 | 2026-07-01 ~ 2026-07-25 | P0/P1 缺陷全部关闭；系统测试通过率 ≥ 95% |
| 项目总结阶段 | 2026-07-25 ~ 2026-07-30 | 质量保证报告完成；过程改进建议归档 |

## 7. 质量度量指标

参照《[度量指标规范](https://taosdata.feishu.cn/wiki/L50dwsyiciOW8TkkbFZcZEpnn9e)》，本项目重点关注以下质量度量指标，在每个自然月的第三个周四进行度量：

| 指标名称 | 度量方法 | 目标值 |
| --- | --- | --- |
| 缺陷关闭周期 | 缺陷从发现到关闭的平均天数 | P0/P1 ≤ 3 天；P2 ≤ 7 天 |
| 各类缺陷数目 | 按优先级（P0~P3）统计缺陷数量及趋势 | 持续跟踪 |
| 缺陷报告规范率 | 规范缺陷数 / 总缺陷数 | ≥ 95% |
| 需求追踪矩阵更新及时率 | 每周更新次数 / 计划更新次数 | 100% |
| 不符合项关闭率 | 已关闭 NCR 数 / 发现 NCR 总数 | 100%（项目结束时） |
| 文档评审通过率 | 一次评审通过文档数 / 总评审文档数 | ≥ 85% |
| 集群稳定性崩溃复现率 | crash-gen/IDMP 测试中高复现率崩溃数 | 0 个（复现率 > 50%） |

## 8. 不符合项（NCR）管理

### 8.1 不符合项类别

| 等级 | 定义 |
| --- | --- |
| 严重（Critical） | 违反关键制度要求，可能导致产品质量重大缺陷或项目重大风险的问题 |
| 一般（Major） | 违反过程规范要求，可能影响产品质量或交付效率的问题 |

### 8.2 不符合项处理流程

1. **发现**：QA 在审计过程中记录 NCR（含问题描述、发现日期、严重等级）。
2. **确认**：与被审计方确认问题事实。
3. **整改**：责任人制定整改措施，明确整改截止日期。
4. **跟踪**：质量组长跟踪整改进度，必要时上报项目经理。
5. **关闭**：QA 验证整改效果后关闭 NCR。
6. **汇总**：在质量保证报告中汇总 NCR 统计和分析结果。

以下为本项目识别的质量相关风险，详细信息见《TSDB v3.4.2 风险登记册》（待维护）：

| 风险 ID | 风险描述 | 质量影响 | 优先级 | 应对措施 |
| --- | --- | --- | --- | --- |
| — | 安全漏洞修复工作量超过 2 人周 | 开发进度压缩，测试周期不足 | 中 | 识别高优先级漏洞优先修复；必要时调整范围 |
| — | 漏洞扫描服务器采购/投产延迟 | 安全扫描无法按时执行，安全验证覆盖不足 | 高 | 持续跟进采购进度；协调临时替代手段 |
| — | GitLab 迁移导致 CI/CD 流水线中断 | 自动化测试无法执行，测试覆盖下降 | 中 | 提前验证 GitLab 流水线配置；制定回滚预案 |
| — | 窗口函数/OVER 子句实现复杂度高 | 功能缺陷率偏高，测试周期超预期 | 中 | 分阶段实现，优先覆盖核心场景测试 |
