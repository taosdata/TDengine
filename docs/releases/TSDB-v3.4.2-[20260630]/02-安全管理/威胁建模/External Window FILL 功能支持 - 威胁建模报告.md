### 3. 分析报告

本报告针对 External Window FILL 功能进行了威胁建模分析。该功能通过空窗口补行提升查询语义完整性，但同时扩大了执行器输入与状态管理攻击面。  
- 核心发现：共识别出 `8` 个潜在威胁，其中 `高危` `3` 个，`中危` `4` 个，`低危` `1` 个。  
- 主要风险场景：  
  - 大规模空窗口 + 强制补行导致查询资源耗尽。  
  - `PREV/NEXT` 状态隔离不严导致分区间数据污染。  
  - planner 跨节点字段传递不一致导致结果漂移或拒绝服务。  
- 结论：该功能可推进，但必须先落实第 5 节中的关键安全约束，并以分布式回归和压力回归验证后再进入全量发布。

### 4. 威胁识别与分析（STRIDE）

功能在 parser/translater/planner/executor 全链路新增 fill 语义处理，风险主要集中在参数可控输入、执行状态缓存、跨节点一致性与审计可追溯性。

#### 4.1 关键实体与数据

| 实体/数据 | 描述 | 敏感性 |
| --- | --- | --- |
| 窗口定义数组 | external_window 子查询产生的 skey/ekey 列表与窗口属性列。 | 中 |
| fill 参数与 VALUE 常量 | 用户可控参数，直接影响结果行与填充值。 | 中 |
| PREV/NEXT 状态缓存 | 维护相邻窗口结果，用于空窗口回填。 | 高 |
| partition 上下文 | 控制分组隔离，决定是否会跨组污染。 | 高 |
| planner fill 字段 | 通过 clone/code/msg 传递到分布式节点。 | 高 |
| explain 与错误日志 | 用于排障和审计，含模式、参数与错误信息。 | 中 |

#### 4.2 威胁评估

| 威胁ID | **威胁描述/攻击场景** | **STRIDE** | **相关组件/数据流** | **风险等级** |
| --- | --- | --- | --- | --- |
| T-EXTFILL-01 | 构造超大窗口集合并使用 `NULL_F/VALUE_F` 强制补行，触发结果行暴涨和 CPU/内存耗尽，影响同节点其他查询。 | D（拒绝服务） | SQL 输入 -> executor 输出 | 高 |
| T-EXTFILL-02 | 通过异常 VALUE 常量（数量、类型、长度）触发高成本转换或执行异常，造成服务不稳定。 | T（篡改）/D（拒绝服务） | parser/translater -> executor | 中 |
| T-EXTFILL-03 | `PREV/NEXT` 缓存未按 partition 隔离时，前一分区结果泄露到后一分区，造成数据污染。 | I（信息泄露）/T（篡改） | partition 上下文 -> 回填逻辑 | 高 |
| T-EXTFILL-04 | planner 的 fill 字段在 clone/code/msg 任一路径缺失，导致分布式执行节点语义不一致。 | T（篡改）/D（拒绝服务） | planner -> 远端节点 | 高 |
| T-EXTFILL-05 | 不支持模式在不同阶段报错不一致，暴露内部实现细节并增加探测面。 | I（信息泄露） | parser/translater 错误分支 | 低 |
| T-EXTFILL-06 | 审计字段不足时，无法区分恶意探测与普通误用，出现异常后难以归因。 | R（抵赖） | 日志与监控链路 | 中 |
| T-EXTFILL-07 | 高频提交 `NEXT` 两遍扫描查询造成资源竞争，形成慢查询放大和可用性下降。 | D（拒绝服务） | 查询入口 -> 执行器 | 中 |
| T-EXTFILL-08 | 窗口定义对象权限检查不严时，低权限用户可能间接读取不应访问的窗口属性。 | E（权限提升）/S（仿冒） | 访问控制 -> 子查询对象 | 中 |

### 5. 安全需求与设计约束

| 威胁ID | **转化后的安全需求/设计约束** | **类型** | **优先级** |
| --- | --- | --- | --- |
| T-EXTFILL-01 | SEC-EXTFILL-001：必须配置窗口数量与补行总量阈值，超限拒绝执行并返回统一错误码。 | 非功能安全需求 | 高 |
| T-EXTFILL-02 | SEC-EXTFILL-002：`VALUE/VALUE_F` 必须在语义层完成数量、类型和长度联合校验，禁止执行期兜底。 | 安全设计约束 | 中 |
| T-EXTFILL-03 | SEC-EXTFILL-003：`PREV/NEXT` 缓存必须按 partition 独立维护，并在分组切换和异常分支强制清空。 | 安全功能需求 | 高 |
| T-EXTFILL-04 | SEC-EXTFILL-004：fill 字段在 clone/code/msg 链路必须做一致性校验，发布前完成分布式一致性回归。 | 安全设计约束 | 高 |
| T-EXTFILL-05 | SEC-EXTFILL-005：不支持模式统一在语义层返回固定错误码与文案。 | 健壮性需求 | 低 |
| T-EXTFILL-06 | SEC-EXTFILL-006：日志必须记录用户、对象、fill 模式、窗口规模、错误码和耗时。 | 审计需求 | 中 |
| T-EXTFILL-07 | SEC-EXTFILL-007：对高成本 fill 查询启用速率限制和慢查询告警。 | 非功能安全需求 | 中 |
| T-EXTFILL-08 | SEC-EXTFILL-008：补充窗口定义对象与源表的联合权限校验，落地最小权限原则。 | 安全功能需求 | 中 |
