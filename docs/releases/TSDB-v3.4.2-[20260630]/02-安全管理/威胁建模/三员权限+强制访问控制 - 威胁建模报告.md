### 3. 分析报告

本特性引入安全等级模型（TS-SEC-LEVEL-1~3）和强制访问控制（MAC），是 TDengine 安全体系的核心升级。设计质量较高，但 MAC 激活路径存在竞态窗口，SQL 启用 SoD 时的事务保护在 MAC 激活路径中缺失。

核心发现：共识别出 `5` 个潜在威胁，其中 `高危` `1` 个，`中危` `2` 个，`低危` `2` 个。

### 5. 风险评估与应对措施

#### 5.1 高危威胁应对

##### T-MAC-01：MAC 激活竞态条件

| 项目 | 内容 |
| --- | --- |
| 威胁 | MAC 激活预检查与实际激活之间的竞态窗口 |
| 影响 | 激活后安全等级约束被违反，低等级用户可访问高等级数据 |
| 现有防护 | SQL 启用 SoD 时有事务保护（§4.1.3.2），MAC 激活路径未提及类似保护 |
| 残余风险 | 预检查完成后用户配置可能被并发修改 |
| 应对措施 | ① MAC 激活在一个事务内完成（预检查 + 写入标记 + 再次校验）；② 激活期间对 SSecurityPolicyObj 和用户表加排他锁 |
| 安全需求编号 | SEC-MAC-001 |
| 优先级 | 高 |
| 验证方式 | 并发竞态测试 |

### 7. 总结

三员权限+MAC 设计质量较高，安全等级不可变设计和 SoD 冲突矩阵体现了纵深防御原则。主要风险在于 MAC 激活的竞态窗口，需在编码阶段修复。
