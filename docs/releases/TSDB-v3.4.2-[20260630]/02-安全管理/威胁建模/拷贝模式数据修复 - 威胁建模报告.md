### 3. 分析报告

本特性引入 `taosrepair` 工具进行副本拷贝模式下的数据修复，支持本地和远程模式。远程模式通过 SSH/SCP 执行命令，引入命令注入风险。

核心发现：共识别出 `4` 个潜在威胁，其中 `高危` `1` 个，`中危` `2` 个，`低危` `1` 个。

### 4. 威胁识别与分析（STRIDE）

#### 4.1 威胁评估

| 威胁ID | 威胁描述/攻击场景 | STRIDE | 风险等级 |
| --- | --- | --- | --- |
| T-REPAIR-01 | --source-host 参数格式为 user@host，host 部分含 shell 特殊字符（如 `;rm -rf /`）时通过 `ssh <host> cat <cfg_path>` 执行导致命令注入 | T（篡改）/E（权限提升） | 高 |
| T-REPAIR-02 | --source-cfg 路径含 shell 元字符时同样存在注入风险 | T（篡改） | 中 |
| T-REPAIR-03 | taosrepair 以 taosd 进程权限运行，如果被入侵可访问 taosd 所有数据 | E（权限提升） | 中 |
| T-REPAIR-04 | 命令白名单机制（isCommandAllowed()）如果实现不严格，可能被绕过 | E（权限提升） | 低 |

### 5. 风险评估与应对措施

| 威胁ID | 应对措施 | 安全需求编号 | 优先级 |
| --- | --- | --- | --- |
| T-REPAIR-01 | 使用 execvp 直接执行 ssh/scp 避免 shell 解析，--source-host 增加严格正则校验（仅允许 user@hostname_or_ip） | SEC-REPAIR-001 | 高 |
| T-REPAIR-02 | --source-cfg 路径做严格字符白名单校验 | SEC-REPAIR-002 | 中 |
| T-REPAIR-03 | taosrepair 以最小权限运行，不使用 root 权限 | SEC-REPAIR-003 | 中 |
| T-REPAIR-04 | isCommandAllowed() 实现需通过安全审查 | SEC-REPAIR-004 | 低 |

### 7. 总结

远程模式的 SSH 命令注入是本特性的核心安全风险，必须使用 execvp 替代 shell 解析。
