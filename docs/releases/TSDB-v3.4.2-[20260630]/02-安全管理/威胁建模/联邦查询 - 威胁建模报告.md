### 3. 分析报告

联邦查询引入外部数据源访问能力，是 v3.4.2 攻击面新增最大的特性。核心风险集中在凭据管理、SQL 注入和认证边界三个维度。

核心发现：共识别出 `7` 个潜在威胁，其中 `高危` `2` 个，`中危` `3` 个，`低危` `2` 个。

### 4. 威胁识别与分析（STRIDE）

#### 4.1 关键实体与数据

| 实体/数据 | 描述 | 敏感性 |
| --- | --- | --- |
| 外部源连接凭据（密码、Token、私钥） | CREATE EXTERNAL SOURCE 语句中的 PASSWORD、api_token、tls_client_key | 极高 |
| 外部表元数据 | SExtTableMeta，含列名、类型、表结构 | 中 |
| 远端子计划 pRemotePlan | 物理计划子树，含用户查询的过滤条件、聚合函数等 | 中 |
| 下推 SQL 文本 | Connector 生成的目标库 SQL 字符串 | 高 |
| 外部源能力画像 | SExtSourceCapability，决定下推策略 | 中 |
| ins_ext_sources 系统表 | 含 host、port、user、password、options | 高 |
| TLS 证书 PEM 内容 | OPTIONS 中的 tls_ca_cert、tls_client_cert、tls_client_key | 极高 |

#### 4.2 威胁评估

| 威胁ID | 威胁描述/攻击场景 | STRIDE | 相关组件/数据流 | 风险等级 |
| --- | --- | --- | --- | --- |
| T-FEDQ-01 | 外部源密码/api_token/tls_client_key 在 SQL 审计日志中以明文记录，攻击者通过日志获取凭据横向渗透 | I（信息泄露） | Parser -> 审计日志 | 高 |

### 5. 风险评估与应对措施

#### 5.1 高危威胁应对

##### T-FEDQ-01：外部源凭据泄露

| 项目 | 内容 |
| --- | --- |
| 威胁 | 外部源密码在审计日志和系统表中明文暴露 |
| 影响 | 外部数据库被入侵，横向渗透 |
| 现有防护 | SHOW/DESCRIBE 脱敏显示 |
| 残余风险 | 审计日志未脱敏、mnode 持久化加密方案不明确 |
| 应对措施 | ① DDL 执行前从审计日志中过滤 PASSWORD/api_token/tls_client_key；② mnode 持久化使用主密钥加密凭据字段；③ 明确 SExtSource.password 序列化加密方式 |
| 安全需求编号 | SEC-FEDQ-001 |
| 优先级 | 高 |
| 验证方式 | 凭据加密单元测试 + 审计日志脱敏验证 |

##### T-FEDQ-02：External Connector SQL 注入

| 项目 | 内容 |
| --- | --- |
| 威胁 | Connector SQL 生成时字面量值直接嵌入 SQL 字符串 |
| 影响 | 外部数据库数据泄露/篡改 |
| 现有防护 | 文档提及使用参数化方式，但实现细节不明确 |
| 残余风险 | 字面量拼接、标识符未转义、VALUE FILL 参数未验证 |
| 应对措施 | ① Connector 使用参数化查询或严格转义所有字面量；② 外部表名/列名按目标库规则做标识符引用；③ 添加 SQL 注入 fuzz 测试 |
| 安全需求编号 | SEC-FEDQ-002 |
| 优先级 | 高 |
| 验证方式 | SQL 注入 fuzz 测试 + 参数化查询代码审查 |

### 7. 总结

联邦查询是 v3.4.2 攻击面新增最大的特性，引入凭据管理、SQL 生成、跨源认证等全新路径。2 个高危问题（凭据泄露、SQL 注入）必须在编码阶段落实并通过安全测试验证。
