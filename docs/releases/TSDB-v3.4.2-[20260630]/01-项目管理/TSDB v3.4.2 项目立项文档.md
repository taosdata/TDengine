## 2. 项目目标

本项目聚焦于开发与发布 TDengine v3.4.2，致力于达成以下核心目标：

1. 窗口函数和 OVER 子句
2. 虚拟表继承机制
3. 联邦查询
4. 元数据变更支持事务

## 3. 项目范围

### 3.1 引擎

1. 窗口函数和 OVER 子句
2. 虚拟表继承机制
3. 联邦查询演示版本
4. 元数据变更支持事务
5. 集群切主、同步等的稳定性提升

### 3.2 工具

1. TSDB Explorer 支持 Data Out 到 Parquet/Kafka/MQTT 的导出能力
2. taosX 高可用与负载均衡完善和增强（基于河北电力场景测试）
3. 各个连接器的高可用与负载均衡
4. License Server 正式发布

### 3.3 平台
  
1. 建立日志周期性检查机制
2. crash-gen 优化及增强
3. GitHub Internal/Private 仓库迁移至 GitLab
4. IDMP稳定性测试框架

## 4. 项目工期

项目总工期为 4 个月，自 2026-04-01 至 2026-07-30。项目进度计划遵循经典的"设计-开发-测试"瀑布模型，但各子功能的开发可以敏捷迭代，确保在紧凑的工期内高效交付。

1. 需求与设计阶段：2026-04-01 ~ 2026-04-31，完成需求分析和功能设计。
2. 开发及功能测试阶段：2026-05-01 ~ 2026-06-30，完成代码开发和功能测试，发布可测试的软件版本。
3. 系统测试与验收阶段：2026-07-01 ~ 2026-07-25，完成系统测试和缺陷修复，完成软件版本的验收。
4. 项目总结阶段：2026-07-25 ~ 2026-07-30，项目成果评审、文档归档、经验总结与复盘。

## 8. 项目成功标准与验收条件

1. 功能完成与文档就绪：规划的所有核心功能均已实现，并通过功能测试；用户手册已编写完成；已发布可供测试的版本。
2. 通过系统测试：通过测试部门组织的系统测试，并获取了正式的系统测试报告。
3. 通过性能基准测试：和 3.4.1 版本比较，性能衰减低于 10%。
4. 通过系统兼容性测试：从 3.4.1 版本可以升级至 3.4.2 版本，数据文件向上兼容。
5. 通过交付验收：通过交付部门的验收审核，确认其质量与稳定性满足向客户升级发布的要求。
6. 过程符合规范：本次开发过程遵循了既定的研发体系与规范，各项实践应用有效。
