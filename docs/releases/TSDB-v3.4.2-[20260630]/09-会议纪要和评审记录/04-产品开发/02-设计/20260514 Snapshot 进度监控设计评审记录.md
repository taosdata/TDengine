## 2. 评审记录

评审团队对设计文档（Snapshot 进度监控 FS）进行了全面审查，认为整体设计贴合 snapshot 传输过程可观测性与运维诊断需求、逻辑严谨、可落地性强，具体评审意见如下：
1. 设计目标清晰精准，核心痛点定位明确，紧扣当前 Raft snapshot 复制流程（RAW 全量/ROW 增量）可能持续数分钟甚至更长但完全没有可观测手段、用户无法得知传输进度/是否卡住/卡在哪个 fileset 的痛点，明确核心目标为在 `information_schema` 下新增 `ins_snap_send_vnodes`（vnode 级整体进度）和 `ins_snap_send_filesets`（fileset 级细粒度进度）两张只读系统表，提供实时的 snapshot 发送进度监控能力，目标聚焦、指引明确。
2. 功能设计全面细致，可落地性强，覆盖核心业务场景：两张系统表列定义完整（vnodes 表含 vgroup_id/dnode_id/total_file_sets/finished_file_sets/start_time/elapsed，filesets 表含 vgroup_id/fid/file_count/finished_file_count/total_size/read_size/start_time/elapsed/start_index/end_index/transfer_type）、新增配置项设计简洁（`tsSnapSendPullupInterval` 默认 10s 范围 1-10000 控制采集频率）、数据生命周期清晰（reader 打开时出现/正常关闭或异常中止后消失/最多延迟一个拉取周期）、进度字段语义区分 RAW 与 ROW 两种传输模式差异（RAW 下 finished_file_count 实时递增且 read_size/total_size 可直接计算百分比、ROW 下 fileset 完成时才跳变且 read_size 仅供趋势参考）、错误处理覆盖 dnode 离线/消息不识别/OOM 三类场景、数据采集链路完整（mnode 定时器→扫描 snapRestoring=1 的 SVgObj→RPC 请求 dnode→dnode 遍历 vnode 加读锁深拷贝→RSP 序列化→mnode 更新内存哈希表→系统表查询时实时计算 elapsed）、关键数据结构和新增消息类型定义清晰、涉及修改文件清单列出 25+ 个文件的修改内容摘要，使用场景覆盖日常监控/卡死诊断/进度估算/告警集成/restore dnode 追踪五类典型场景，设计闭环完整。
3. 设计文档结构规范，版本与修订记录清晰：文档包含两版修订记录（0.1 初稿→1.0 根据 review 意见修改）、背景（现状问题与目标）、定义（9 项术语含 RAW/ROW 传输/snapRestoring/mnode 定时拉取/VGROUP_VER_NUMBER）、行为说明（系统表定义/配置项/数据生命周期/进度字段语义/访问权限/错误处理六大子节）、性能、安全、兼容性、运维（含卡住判断方法和 leader 切换说明）、使用场景（5 项）、约束和限制（约束 4 项/限制 3 项）、常见错误和排查（5 类场景）、可观测性、安装和卸载、文档（含已完成 4 项和待处理 1 项）、参考文档、附录（进度采集数据链路/关键数据结构/新增消息类型/涉及文件清单）共 16 大章节，层次分明、约束与限制界定清晰，逻辑清晰、无歧义，符合 TDengine 设计文档规范要求。
4. 安全性、兼容性与性能考虑周全，风险可控：安全方面系统表为只读视图、进度数据仅含文件大小/时间戳/版本号等元数据不含用户数据、遵循现有 `information_schema` 访问控制机制；兼容性方面 `VGROUP_VER_NUMBER` 从 2 升为 3 但 `snapRestoring` 重启后始终置 0 不影响历史数据读取、`mndVgroupActionUpdate` 中正确保留内存状态（pNew←pOld 方向）、新消息类型旧版本 dnode 返回错误 mnode 忽略等待下次重试不影响集群功能、`syncSnapshotRecving` 移出 BUILD_NO_CALL 保护所有构建类型可链接、不修改任何现有 SQL/API/配置；性能方面 mnode 仅向有活跃 snapshot 的 leader 发轻量 RPC（通常并发 0-3）、tsdb 层进度统计仅在已有 rwlock 下做整数累加开销可忽略、系统表查询从内存哈希表读取不触发额外 RPC。

## 3. 评审结论

设计文档整体设计合理、逻辑清晰，功能覆盖全面，Snapshot 进度监控通过新增 `ins_snap_send_vnodes` 和 `ins_snap_send_filesets` 两张 information_schema 系统表实现了 vnode 级与 fileset 级的 snapshot 发送进度实时可观测，mnode 定时拉取 + 内存缓存 + elapsed 实时计算的架构轻量高效，RAW/ROW 两种传输模式的进度语义区分明确，性能、安全、兼容性设计符合系统规范，精准解决了 snapshot 复制过程完全不可观测导致无法判断进度和卡住位置的核心痛点。
