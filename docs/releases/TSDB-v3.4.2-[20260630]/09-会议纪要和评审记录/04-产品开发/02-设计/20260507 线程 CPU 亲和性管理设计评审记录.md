## 2. 评审记录

评审团队对设计文档（线程 CPU 亲和性管理 FS、DS）进行了全面审查，认为整体设计贴合高并发混合负载场景下线程资源隔离需求、架构分层清晰、可落地性强，具体评审意见如下：
1. 设计目标清晰精准，核心痛点定位明确，紧扣 taosd 服务进程中管理类、写入类、读取类线程共享所有 CPU 核心导致写入密集 I/O 或查询大量计算时线程间 CPU 竞争和缓存污染（cache pollution）引起关键管理操作（集群协调、元数据管理等）出现延迟抖动的实际业务痛点，明确核心目标为通过 CPU 核心亲和性机制将 taosd 所有线程分三类绑定到独立 CPU 核心集合运行，实现隔离关键管理操作、减少缓存污染提升 L1/L2 命中率、管理员可按负载模式灵活调整分配比例三大收益，主开关默认关闭确保零影响升级，目标聚焦、指引明确。
2. 功能设计全面细致，可落地性强，覆盖核心业务场景：FS 层面——配置参数设计完整（`enableCpuAffinity` 主开关 + `managementCpuCores`/`readCpuCores`/`otherCpuCores` 三组核心数），核心分配算法按顺序从核心 0 开始分配（管理→写入→读取）规则清晰，`SHOW CPU_ALLOCATION` SQL 命令和 `ins_cpu_allocation` 系统表提供实时可观测能力，主开关行为覆盖默认关闭/显式开启≥3 核/显式开启<3 核自动降级/关闭但保留参数四种场景，出错处理覆盖总核心数超出/参数范围非法/核心数<3/非 Linux 平台/主开关关闭六种异常场景，线程分类将所有 taosd 线程无遗漏地归入管理/写入/读取三类，使用场景覆盖写入密集/查询密集/混合负载/大规模集群/容器化部署/安全回滚六个典型配置示例；DS 层面——四层架构（用户层→配置层→核心分配层→线程绑定层→OS 层）职责清晰，核心数据结构 `EThreadCategory`/`SCpuCoreSet`/`SCpuAllocStatus` 设计精练，`taosInitCpuAllocation()`/`taosSetCpuAffinity()`/`taosGetCpuAllocStatus()`/`taosGetAvailableCpuSet()` 四个 API 边界清晰，配置注册组件通过 `cfgAddBool`/`cfgAddInt32` 标准注册（CFG_SCOPE_SERVER/CFG_DYN_NONE），数据流图和消息序列图完整展示从配置加载到线程绑定到 SQL 查询的全链路数据流转，`ins_cpu_allocation` 表通过 `sysTableFromDnode()` 路由各 dnode 汇总结果，设计闭环完整。
3. 设计文档结构规范，版本与修订记录清晰：FS 文档明确修订记录（1.0 初稿 dmchen），16 个章节从背景、定义、行为说明（含配置参数、核心分配算法、SQL 命令、主开关行为、出错处理、线程分类）、性能、安全、兼容性、运维、使用场景（6 类）、约束限制、常见错误排查、可观测性到安装卸载/文档/参考文档/附录分层呈现；DS 文档修订记录同步（1.0 dmchen），涵盖引言（目的/范围/受众）、术语、概述（架构/技术/依赖项）、设计考虑（假设限制/设计模式/风险缓解）、详细设计（组件设计/关键数据结构/数据库设计/设计图含数据流图+消息序列图+流程图+状态转换图）、接口规范（OS API/SQL 接口/线程绑定调用点），FS+DS 联合覆盖从用户视角到实现细节完整闭合，逻辑清晰、无歧义，符合 TDengine 设计文档规范要求。
4. 安全性、兼容性与性能考虑周全，风险可控：安全方面明确 CPU 亲和性为操作系统级线程调度特性不涉及数据机密性完整性可用性、所有配置通过标准 `taos.cfg` 管理；兼容性设计稳妥，主开关默认关闭升级不改变任何运行行为、三组核心参数在主开关关闭时不生效、线程数量不变仅控制在哪些核心运行与现有线程数配置参数完全独立；性能方面 CPU 亲和性设置仅在线程创建时执行一次后续零运行时开销、同类线程共享核心提升缓存命中率、管理线程专用核心保障低延迟、主开关关闭时与未引入特性完全一致；DS 层面设计模式合理（单例模式保证全局状态一致、策略模式解耦分配算法、关注点分离配置/算法/绑定三层独立），风险缓解措施覆盖配置错误拒绝启动、<3 核自动降级、非 Linux 空操作提示、CPU 热插拔要求重启刷新四项。

## 3. 评审结论

设计文档整体设计合理、逻辑清晰，功能覆盖全面，CPU 亲和性主开关与三类线程核心分配机制、`SHOW CPU_ALLOCATION` 可观测能力、四层架构设计、核心数据结构与 API 规范、六类使用场景配置示例等核心设计规范严谨，使用场景贴合高并发混合负载下 CPU 竞争与缓存污染导致管理操作延迟抖动的实际业务需求，性能、安全、兼容性设计符合系统规范，精准解决了 taosd 多类线程共享 CPU 核心导致关键管理操作延迟抖动和缓存命中率下降的核心痛点。
