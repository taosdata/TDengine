## 2. 评审记录

评审团队对设计文档（TEXT 外部行集数据源查询支持 FS）进行了全面审查，认为整体设计贴合用户轻量级内联数据查询需求、逻辑严谨、可落地性强，具体评审意见如下：
1. 设计目标清晰精准，核心痛点定位明确，紧扣用户在 SQL 中直接内嵌结构化行值并构造可查询结果集的需求，明确核心目标为让 `TEXT (column_list) VALUES row_value ...` 成为 FROM 子句中的内联行集表源，支持独立查询、JOIN 任意一侧、UNION/UNION ALL 任意一侧以及 INSERT INTO ... SELECT 场景，无需创建持久化表即可参与完整 SQL 查询能力，目标聚焦、指引明确。
2. 功能设计全面细致，可落地性强，覆盖核心业务场景：语法定义清晰（TEXT 作为 table_expr 与 table_name/view_name/subquery 同级）、schema 声明规则完整（列名显式定义不可重复/不支持自动类型推断/不支持 JSON/GEOMETRY/BLOB 三种类型/类型转换失败直接报错）、支持范围清晰划分为直接支持（独立查询/JOIN/UNION/INSERT INTO SELECT）和间接支持（通过子查询包裹进入派生表/EXTERNAL_WINDOW/标量子查询等已有入口）、无 TIMESTAMP 列时的能力限制明确列出（支持投影/WHERE/GROUP BY/PARTITION BY/ORDER BY，不支持 JOIN/INTERVAL/SESSION/EVENT_WINDOW/INTERP/EXTERNAL_WINDOW/INSERT INTO SELECT 七类场景）、数据量限制三层约束（10,000 行/1,000,000 单元格/8 MB）取最先触达者、常见错误与排查覆盖 9 类场景含解决方法，提供独立查询/派生表/JOIN 真实表/EXTERNAL_WINDOW 四个语法示例，设计闭环完整。
3. 设计文档结构规范，版本与修订记录清晰：文档包含三版修订记录（0.1 初稿→0.2 补充限制去除实现细节→0.3 去除首列强制 TIMESTAMP 与 FILE 约束对齐）、背景与定义、行为说明（功能目标/语法定义/行输入规则/schema 声明/支持范围/无 timestamp 限制七大子节）、数据量限制、安全、兼容性、运维、使用场景、约束和限制（8 项）、常见错误和排查（9 类）、可观测性、安装和卸载、文档、参考文档、附录（含 10 项验收要求）共 16 大章节，层次分明、约束与限制界定清晰，逻辑清晰、无歧义，符合 TDengine 设计文档规范要求。
4. 安全性、兼容性与性能考虑周全，风险可控：安全方面通过三层数据量限制（行数/单元格/字节）在 SQL 解析阶段拦截超大输入、审计日志可区分 TEXT 数据源使用行为；兼容性方面现有查询语法完全不变、TEXT 为纯增量新增表源类型、错误码和错误文案能区分语法错误/schema 错误/数据解析错误/执行错误；性能方面 TEXT 数据在 parser 阶段一次性构建为内存数据块无磁盘 I/O、明确定位为轻量级临时数据源非大规模导入替代方案。

## 3. 评审结论

设计文档整体设计合理、逻辑清晰，功能覆盖全面，TEXT 内联行集数据源通过显式 schema 声明和 VALUES 语法实现了无需建表即可参与完整 SQL 查询的能力，直接/间接支持范围划分清晰、无 TIMESTAMP 列时的能力降级设计合理，性能、安全、兼容性设计符合系统规范，精准解决了用户在 SQL 中内嵌结构化数据进行临时查询和窗口定义的核心痛点。
