## 2. 评审记录

### 2.1 架构安全性

- 安全等级模型（TS-SEC-LEVEL-1/2/3）设计清晰，与国标 BLP 模型对齐。
- MAC 激活前的预检查机制（全量扫描角色持有者 security_level）体现了"检查先于执行"的安全原则。
- SQL 语句启用路径的双通道设计（传统命令 vs SQL 语句）兼容性好。
- **不足**：MAC 激活路径缺少 SQL 启用路径中已有的事务保护机制。

### 2.2 身份认证与授权

- SoD（职责分离）冲突矩阵设计合理：sysinfo+audit 角色冲突防止同一个人既管理又审计。
- 三员角色分配后不可撤销，安全等级不可变——这两个"不可逆"设计是正确的安全决策。
- MAC 激活不可逆（只可关闭），关闭后安全等级属性保留在系统表中——审计可追溯性好。
- **不足**：MAC 激活的 TOCTOU 竞态窗口需要事务保护。

### 2.3 密码学设计

- 安全等级模型本身不涉及密码学，依赖现有 TDengine 认证体系。

### 2.4 数据流与隐私保护

- sysinfo 用户不能读取非 sysinfo 用户的数据——读隔离设计清晰。
- 无安全等级的用户不能访问有安全等级的数据库——"无等级=无权限"原则正确。
- 审计字段（MAC 状态变更历史）设计合理，支持审计追溯。

### 2.5 输入验证与防御

- 安全等级值（TS-SEC-LEVEL-1/2/3）为枚举类型，Parser 层强制校验，不存在注入风险。
- MAC 激活的预检查覆盖了所有角色持有者，不存在遗漏。

### 2.6 错误处理与日志

- 错误码设计合理：0x80005000~0x80005006 覆盖了 MAC 激活失败、SoD 冲突、安全等级缺失等场景。
- 错误信息具体且不泄露内部实现细节（如 SSecurityPolicyObj 结构）。
