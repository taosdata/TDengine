### 2.2 高危问题详细记录

#### H1. 联邦查询：外部源密码明文暴露风险

- **涉及文档**: `联邦查询 FS.md` §3.4.1, §6.2.5; `联邦查询 DS.md` §6.2.1
- **问题分类**: 数据流与隐私保护 / 密码学设计
- **STRIDE 分类**: I（信息泄露）
- **问题描述**: `CREATE EXTERNAL SOURCE` 语句要求用户在 SQL 中直接写入明文 `PASSWORD`。虽然 `SHOW`/`DESCRIBE` 时脱敏显示，但 SQL 审计日志会完整记录含密码的 DDL 语句。`SExtSource` 结构体中 `password` 字段为 `char*`，文档对 mnode 持久化时是否加密表述不一致（FS §5.3.10.1.2 提及 'mnode 加密存储'，但 DS §6.2.1 结构体无加密标记）。OPTIONS 中的 `api_token`（InfluxDB）和 `tls_client_key` 同样面临审计日志泄露风险。
- **威胁**: 攻击者通过审计日志或系统表直接获取外部数据库凭据，横向渗透。
- **建议**: (1) DDL 执行前从审计日志中过滤 PASSWORD/api_token/tls_client_key 字段；(2) mnode 持久化时使用主密钥加密凭据字段；(3) 明确 SExtSource.password 在序列化到 mnode 存储时的加密方式。
- **评审结论**: 条件通过——必须在编码阶段明确凭据加密方案并通过安全测试验证。

#### H2. MCP 代理：Authorization 头无条件透传

- **涉及文档**: `IDMP MCP 代理 FS.md` §4.2, §6
- **问题分类**: 身份认证与授权
- **STRIDE 分类**: S（仿冒）/E（权限提升）
- **问题描述**: MCP 代理入口 `/api/v1/mcp/stream` 将调用方的 `Authorization` 头原样透传给上游 MCP 服务，代理层自身不做任何鉴权。如果 IDMP 的 REST 层和 MCP 层使用不同的认证体系，攻击者可构造 IDMP 无法识别但 MCP 可接受的 Token。`X-Forwarded-For` 可被伪造（§4.2 明确说'若调用方已提供则沿用'）。hop-by-hop 头过滤列表缺少 `cookie` 头。
- **威胁**: 内网攻击者通过伪造 Authorization 头或 X-Forwarded-For 绕过访问控制或污染审计。
- **建议**: (1) 代理层增加可选的 Token 校验（至少验证格式和签名）；(2) X-Forwarded-For 仅在可信代理链中追加；(3) 补充 cookie 到不转发列表。
- **评审结论**: 条件通过——代理层应增加至少一层 Token 格式校验。

#### H3. 联邦查询 External Connector：SQL 注入风险

- **涉及文档**: `联邦查询 DS.md` §5.3.10.3, §6.1.2.4
- **问题分类**: 输入验证与防御
- **STRIDE 分类**: T（篡改）
- **问题描述**: External Connector 在 Executor 阶段将远端子计划（pRemotePlan）转换为目标库 SQL。子计划中的字面量值（如 `WHERE col = 'user_input'`）可能直接嵌入生成的 SQL 字符串。外部表名/列名如果包含特殊字符未正确转义会导致注入。`FILL(VALUE, 'input')` 传入的值如果直接拼接到 SQL 中同样存在注入风险。
- **威胁**: 恶意用户通过精心构造的查询参数，在联邦查询下推 SQL 中注入任意 SQL 语句。
- **建议**: (1) Connector 生成 SQL 时必须使用参数化查询或对所有字面量值做严格转义；(2) 外部表名/列名必须按目标库标识符规则做引用；(3) 添加 SQL 注入 fuzz 测试用例。
- **评审结论**: 不通过——必须在编码阶段确认参数化查询方案并通过 SQL 注入测试验证。

### 2.3 中危问题详细记录

#### M1. 三员权限：MAC 激活预检查存在 TOCTOU 竞态

- **涉及文档**: `三员权限+强制访问控制 FS.md` §4.2.1.3
- **STRIDE 分类**: T（篡改）/E（权限提升）
- **问题描述**: MAC 激活前执行'全量扫描'检查所有角色持有者的 security_level。但检查完成后、ALTER CLUSTER 实际执行前，管理员可能通过并发连接修改用户 security_level 或撤销角色。SQL 启用 SoD 时有事务保护（§4.1.3.2），但 MAC 激活路径未提及类似保护。
- **建议**: MAC 激活应在一个事务内完成（预检查 + 写入标记 + 再次校验），激活期间对 SSecurityPolicyObj 和用户表加排他锁。

#### M2. SLEEP 函数：无并发限制导致线程池耗尽 DoS

- **涉及文档**: `Sleep 函数 FS.md` §4.6, §6
- **STRIDE 分类**: D（拒绝服务）
- **问题描述**: SLEEP 以 OS 级 sleep 实现，持续占用连接线程槽位，无内置并发数量限制。`queryNoFetchTimeoutSec` 对首包前阻塞的 SLEEP 查询不适用（§4.5），`SELECT SLEEP(3600)` 可阻塞线程 1 小时不被服务端超时终止。
- **建议**: (1) 增加 SLEEP 最大时长配置（默认 60 秒）；(2) 增加全局并发 SLEEP 计数限制；(3) 将 SLEEP 计入 queryNoFetchTimeoutSec 检测范围。

#### M3. 联邦查询：TLS 私钥通过 OPTIONS 传递的安全风险

- **涉及文档**: `联邦查询 FS.md` §3.4.1.4, §6.2.5
- **STRIDE 分类**: I（信息泄露）
- **问题描述**: TLS 证书通过 OPTIONS 子句传入 PEM 文本内容。`tls_client_key` 是私钥，与 password 同等敏感，但文档未将其纳入 sysInfo=true 保护。`ins_ext_sources.options` 列以 JSON 格式存储全部 OPTIONS，敏感字段脱敏策略未明确。
- **建议**: (1) tls_client_key 和 tls_client_cert 在系统表中应设为 sysInfo=true；(2) 明确 options JSON 中敏感字段的脱敏规则。

#### M4. 拷贝模式数据修复：SSH 命令注入防护不完整

- **涉及文档**: `拷贝模式数据修复 FS.md` §6.2
- **STRIDE 分类**: T（篡改）/E（权限提升）
- **问题描述**: --source-host 参数格式为 user@host，host 部分包含 shell 特殊字符时可导致命令注入。--source-cfg 远程模式下通过 `ssh <host> cat <cfg_path>` 读取，cfg_path 含 shell 元字符同样存在注入风险。命令白名单机制（isCommandAllowed()）实现细节未在文档中说明。
- **建议**: (1) 使用 execvp 系列函数直接执行 ssh/scp，避免 shell 解析；(2) 对 --source-host 做严格正则校验；(3) 将转义实现纳入安全评审。

#### M5. Explorer XNode 管理：SQL 拼接依赖前端转义

- **涉及文档**: `Explorer XNode 管理页面 FS.md` §6.1
- **STRIDE 分类**: T（篡改）
- **问题描述**: Endpoint 和 Password 中的 SQL 特殊字符由前端转义后拼接 SQL，SQL 注入防护不应依赖前端转义。Token 字段未提及任何转义或校验。
- **建议**: 依赖服务端 SQL 解析器的参数化/预编译机制，或在 Explorer SQL 代理层增加参数化查询支持。

### 2.4 低危问题详细记录

#### L1. 联邦查询能力探测可被用于端口扫描

- **涉及文档**: `联邦查询 FS.md` §5.3.10.1.2
- **问题描述**: 管理员创建指向内网任意 IP 的 EXTERNAL SOURCE，能力探测可被用作端口扫描工具。
- **建议**: 限制外部源地址不可为内网地址（可配置），或在审计日志中记录所有探测请求。

#### L2. RegexpExtract 函数：ReDoS 无内置防护

- **涉及文档**: `RegexpExtract 函数 FS.md` §6
- **问题描述**: POSIX ERE 引擎不支持超时中断匹配，恶意正则可阻塞查询线程数分钟。
- **建议**: 增加正则编译时的复杂度检测（嵌套量词检测），或在匹配执行时增加行级超时。

#### L3. Event Window 通知泄露内部实现细节

- **涉及文档**: `Event Window 多级子事件 FS.md` §4.3
- **问题描述**: 事件通知 payload 中的 conditionPath 暴露 SQL 语句内部结构，通知发送到外部系统时可推断业务规则。
- **建议**: 文档中明确提醒用户确保通知通道的安全性。
