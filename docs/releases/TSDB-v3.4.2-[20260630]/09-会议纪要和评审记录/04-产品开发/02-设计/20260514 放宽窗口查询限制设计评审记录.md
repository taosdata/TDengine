## 2. 评审记录

评审团队对设计文档（放宽窗口查询限制 FS）进行了全面审查，认为整体设计贴合用户窗口查询场景的实际使用痛点、逻辑严谨、可落地性强，具体评审意见如下：
1. 设计目标清晰精准，核心痛点定位明确，紧扣窗口查询 SELECT 列表限制过严（无法输出原始数据列/标签列/表名/标量表达式）和不定行函数（csum/diff/derivative/mavg/statecount/stateduration/lag/lead/fill_forward）被完全禁止在窗口查询中使用两大痛点，明确核心目标为：扩展窗口查询支持的表达式类型（允许原始列/标签列/标量函数/不定行函数在窗口查询中使用），并在 INTERVAL 查询中为不定行函数场景提供受限但实用的 FILL 子句支持（NONE/NULL/NULL_F/VALUE/VALUE_F），目标聚焦、指引明确。
2. 功能设计全面细致，可落地性强，覆盖核心业务场景：SELECT 列表规则变化按是否包含聚集函数分两种情况清晰定义（包含时与改动前一致/不包含时允许任意运算）、查询模式自动推断规则覆盖四种场景（聚集函数→聚合模式/原始列或标量→投影模式/不定行函数→投影模式/仅伪列和标签→歧义场景默认聚合）、新增 SCALAR/AGG 关键字解决歧义场景、FILL 子句行为按三种函数组合场景分别定义并详细列出五种 FILL 模式在有数据窗口/空窗口/全空范围下的行为矩阵、仍然禁止的组合清晰列出（不定行与聚合混用/输出行数不同的不定行混用/unique/tail/interp/forecast 不支持窗口/GROUP BY 不支持不定行）、错误码设计精确区分 FILL 模式不支持场景（新增 0x2657），提供多个 SQL 示例和两个 IoT 使用场景，设计闭环完整。
3. 设计文档结构规范，版本与修订记录清晰：文档包含修订记录、背景与痛点分析、术语定义（8 个专业术语含不定行函数/窗口查询/FILL 子句/窗口内独立计算/强制填充/聚合模式/投影模式/SCALAR-AGG 关键字）、行为说明（SELECT 列表规则/查询模式与关键字/FILL 子句行为/禁止组合/错误码五大子节）、性能、安全、兼容性、运维、使用场景、约束和限制（4 约束+2 限制）、常见错误和排查（6 类错误含解决方法）、可观测性、安装和卸载、文档修改说明共 14 大章节，层次分明、约束与限制界定清晰，逻辑清晰、无歧义，符合 TDengine 设计文档规范要求。
4. 安全性、兼容性与性能考虑周全，风险可控：安全方面不涉及认证/授权/加密/数据访问控制，无安全风险引入；兼容性方面设计为完全向后兼容（此前报错的 SQL 现可执行为功能扩展、此前可执行的 SQL 行为不变、序列化新增 `indefRowsMode` 字段通过 `tDecodeIsEnd()` 兼容旧版本反序列化默认 false）；性能方面不定行函数模式仅额外窗口边界检测和状态重置开销可忽略不计、FILL 算子 peek 下一行时间戳为一次数组索引操作无显著开销、不涉及不定行函数时执行路径与原来完全一致无回归风险、写入性能无影响。

## 3. 评审结论

设计文档整体设计合理、逻辑清晰，功能覆盖全面，窗口查询 SELECT 列表扩展通过聚合/投影双模式自动推断机制和 SCALAR/AGG 消歧关键字实现了灵活且向后兼容的查询能力提升，FILL 子句按函数类型精确分级支持确保语义明确，性能、安全、兼容性设计符合系统规范，精准解决了窗口查询表达式类型受限和不定行函数无法按窗口重置计算两大核心痛点。
