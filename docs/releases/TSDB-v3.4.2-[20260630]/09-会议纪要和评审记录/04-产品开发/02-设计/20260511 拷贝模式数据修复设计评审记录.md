## 2. 评审记录

评审团队对设计文档（拷贝模式数据修复 FS）进行了全面审查，认为整体设计贴合多副本集群大规模数据损坏恢复需求、逻辑严谨、可落地性强，具体评审意见如下：
1. 设计目标清晰精准，核心痛点定位明确，紧扣多副本集群中损坏数据量巨大时 `restore` 命令逐行解析重放性能不足、手工拷贝文件效率低且易出错两大痛点，明确核心目标为通过 `taosd -r --mode copy` 命令实现文件级拷贝修复（跳过编解码开销，预期恢复速度提升一个数量级以上），支持本地模式和远程 SCP 模式、多 vnode 批量修复、TFS 多级存储磁盘 ID 重映射，目标聚焦、指引明确。
2. 功能设计全面细致，可落地性强，覆盖核心业务场景：命令行语法设计清晰（`-r --mode copy --node-type vnode --source-host --source-cfg --vnode` 六个参数各有明确语义）、vnode ID 列表支持逗号分隔和减号范围两种格式、配置文件解析通过 `cfgInit()/cfgLoad()` API 独立完成不依赖 dnode 初始化；12 步执行流程形成完整事务语义（备份→拷贝→替换→清理，失败时自动回滚恢复 vnodeN.bak）、磁盘 ID 重映射规则覆盖同层级映射/层级折叠/单盘全映射三种场景、出错处理覆盖 8 类异常场景并定义 5 个退出码（0/1/2/3/4）、提供本地单盘/本地多级存储/远程 SCP 三个使用示例和完整操作步骤，设计闭环完整。
3. 设计文档结构规范，版本与修订记录清晰：文档包含修订记录（三版迭代：初稿→评审修改→恢复流程事务化）、背景与痛点分析、术语定义（TFS/磁盘 ID 重映射/主磁盘/SCP）、行为说明（命令行语法/使用示例/执行流程/磁盘 ID 重映射/出错处理/退出码）、性能、安全、兼容性、运维、使用场景、约束和限制、可观测性、安装和卸载、文档、参考文档、附录共 16 大章节，模块分层清晰、约束与限制（6 项约束 + 4 项限制）明确标注，参考文档链接到数据修复工具 RS 和 FS，逻辑清晰、无歧义，符合 TDengine 设计文档规范要求。
4. 安全性、兼容性与性能考虑周全，风险可控：安全方面远程模式仅支持 SSH 密钥认证并使用 `BatchMode=yes` 确保非交互式执行、所有 SSH/SCP 路径参数严格 shell 转义防止命令注入、通过 `isCommandAllowed()` 白名单机制仅在修复模式临时允许 ssh/scp 命令执行、源数据始终只读访问、建议使用专用只读 SSH 账户；兼容性方面 `--mode copy` 为纯新增模式不影响现有 `--mode force` 行为、不修改任何配置参数/SQL/API、修复后数据格式与正常运行完全一致；性能方面文件级拷贝跳过行级解析和 Raft 重放开销、不启用传输压缩（TSDB 数据已压缩）、修复在 taosd 进入正常服务前完成不影响运行时。

## 3. 评审结论

设计文档整体设计合理、逻辑清晰，功能覆盖全面，文件级拷贝修复模式通过事务化执行流程（备份→拷贝→替换→清理→失败回滚）和 TFS 磁盘 ID 重映射机制实现了安全可靠的多副本数据恢复，安全防护（SSH 密钥认证/命令注入防护/白名单机制/源端只读）、兼容性（纯新增模式无破坏性变更）和性能设计（文件级拷贝跳过编解码、免传输压缩）符合系统规范，精准解决了大规模数据损坏场景下恢复效率低和手工操作易出错两大核心痛点。
