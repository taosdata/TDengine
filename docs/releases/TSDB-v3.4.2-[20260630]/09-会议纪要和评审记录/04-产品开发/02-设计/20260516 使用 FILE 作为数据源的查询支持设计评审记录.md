## 2. 评审记录

评审团队对设计文档（FILE 外部行集数据源查询支持 FS）进行了全面审查，认为整体设计贴合用户 CSV 文件作为查询数据源的实际需求、逻辑严谨、可落地性强，具体评审意见如下：
1. 设计目标清晰精准，核心痛点定位明确，紧扣当前 `FILE 'path'` 仅作为 `INSERT INTO ... FILE ...` 专用输入语法、无法独立成为查询数据源的限制，明确核心目标为让 `FILE(file_path, column_list [, option ...])` 成为真正的查询表源，支持独立 SELECT、JOIN 任意一侧、UNION/UNION ALL 任意一侧以及 INSERT INTO ... SELECT 场景，使 CSV 文件能够像普通表或子查询一样参与完整 SQL 查询，目标聚焦、指引明确。
2. 功能设计全面细致，可落地性强，覆盖核心业务场景：语法定义清晰（FILE 作为 table_expr 与 table_name/view_name/subquery 同级，三个参数 file_path/column_list/options）、选项设计实用（header=true/false 控制首行列名映射支持部分列读取、delimiter 自定义分隔符默认逗号）、schema 声明规则完整（column_list 显式定义/不支持 JSON/GEOMETRY/BLOB/列数可少于文件实际列数实现部分列读取/列数多于实际列数报错/header=true 时按列名映射/header=false 时按顺序映射）、路径语义明确（客户端本地路径/支持绝对和相对路径/相对于发起查询进程当前工作目录/无法访问直接报错）、支持范围清晰划分直接支持四类和间接支持（子查询包裹进入 EXTERNAL_WINDOW 等入口）、无 TIMESTAMP 列时能力限制与 TEXT 对齐（不支持 JOIN/INTERVAL/SESSION/EVENT_WINDOW/INTERP/EXTERNAL_WINDOW/INSERT INTO SELECT）、数据量限制三层约束（10,000 行/1,000,000 单元格/8 MB）、常见错误与排查覆盖 11 类场景，提供基本查询/header/部分列读取/自定义分隔符/别名/派生表/JOIN 真实表七个语法示例，设计闭环完整。
3. 设计文档结构规范，版本与修订记录清晰：文档包含四版修订记录（0.1 初版→0.2 FILE/TEXT 拆分→0.3 补充限制去除实现细节→1.0 修正无 timestamp 时 JOIN 不支持与 TEXT 对齐）、背景与定义、行为说明（功能目标/语法定义/选项说明/schema 声明/路径说明/支持范围/无 timestamp 限制七大子节）、数据量限制、安全、兼容性（三个子节含向后兼容/风险/目标）、运维、使用场景、约束和限制（12 项）、常见错误和排查（11 类）、可观测性、安装和卸载、文档（5 项修改点）、参考文档、附录（含 12 项验收要求）共 16 大章节，层次分明、约束与限制界定清晰，逻辑清晰、无歧义，符合 TDengine 设计文档规范要求。
4. 安全性、兼容性与性能考虑周全，风险可控：安全方面明确要求限制可访问路径范围防止任意读取宿主机敏感文件、权限模型与现有文件导入能力保持一致、审计日志可区分 FILE 数据源访问行为、客户端路径不可访问与服务端执行错误有清晰区分；兼容性方面现有查询语法不变、现有 `INSERT INTO ... FILE ...` 语义不变、EXTERNAL_WINDOW 语义不变仅扩展子查询来源、文档明确路径按客户端解释避免误解、错误码区分语法/schema/文件访问/数据解析/执行五类错误；性能方面 CSV 解析在客户端完成后二进制数据块通过 plan 序列化传输至服务端、服务端无磁盘 I/O、数据量上限 8 MB 定位为轻量级临时数据源。

## 3. 评审结论

设计文档整体设计合理、逻辑清晰，功能覆盖全面，FILE 外部行集数据源通过 `FILE(path, column_list, options)` 语法将 CSV 文件提升为完整的查询表源，header/delimiter 选项和部分列读取设计实用灵活，路径语义（客户端本地读取）和安全防护（路径限制/权限模型/审计日志）设计清晰，性能、安全、兼容性设计符合系统规范，精准解决了 FILE 仅能用于 INSERT 导入而无法参与查询的核心痛点。
