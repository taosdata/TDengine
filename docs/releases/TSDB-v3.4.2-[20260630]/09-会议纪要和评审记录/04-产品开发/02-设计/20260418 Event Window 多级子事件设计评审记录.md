## 2. 评审记录

评审团队对设计文档（Event Window 多级子事件 FS）进行了全面审查，认为整体设计精准解决了开始事件嵌套表达与通知语义不足的核心问题、逻辑严谨、可落地性强，具体评审意见如下：
1. 设计目标清晰精准，核心痛点定位明确，紧扣现有 EVENT_WINDOW 开始事件硬编码为一层兄弟节点导致无法表达嵌套父子关系、事件通知只能给出一层 conditionIndex 语义不足以描述命中的嵌套节点、windowIndex 对多级子事件语义错误且关闭事件存在硬编码逻辑三大实际问题，明确核心目标为提供多级 START WITH 子事件能力并将通知语义从扁平索引升级为静态条件树路径 + triggerId 模型，目标聚焦、指引明确。
2. 功能设计全面细致，可落地性强，覆盖核心业务场景：START WITH 从单条件或一层列表扩展为递归条件树，支持任意层级括号分组嵌套，现有单条件和一层子事件语法保持兼容；静态条件树路径 conditionPath 按 SQL 书写顺序生成、兄弟节点从 0 编号，路径稳定可预测便于下游消费端精确分流；事件通知 payload 新增 conditionPath、重定义 conditionIndex 为父节点下本地索引、删除语义错误的 windowIndex，嵌套分支切换时通知顺序严格遵守先关闭叶子→关闭祖先→打开新祖先→打开新叶子的四步规则保证父子语义正确；_event_condition_path 占位符设计巧妙，不仅输出路径还解决了祖父/父/子窗口共享 _twstart 导致结果表主键冲突互相覆盖的实际问题，合法性约束明确（仅 event-window 且有子事件结构时可用，其他场景报错），五个使用场景（分层告警、通知精确分流、分支切换追踪、流结果回查、兼容一层子事件）覆盖典型业务需求。
3. 设计文档结构规范，版本与修订记录清晰：明确修订记录两个版本（1.0 初稿邝金清、1.1 根据评审意见修改），术语定义完整准确涵盖开始事件树、子事件结构、conditionPath、conditionIndex、triggerId、_event_condition_path 六个核心概念，从背景、定义、行为说明、性能、安全、兼容性、运维、使用场景、约束限制分层呈现，正向和错误示例均有 SQL 代码示意，约束和限制分别记录清晰（END WITH 不支持多级、fieldValues 不按路径裁剪、windowIndex 必须移除无零成本兼容），逻辑清晰无歧义。
4. 安全性、兼容性与性能考虑周全，风险可控：安全方面 _event_condition_path 只暴露条件树路径不暴露额外业务数据，conditionPath 来自用户自定义 START WITH 结构不含敏感信息，非法使用必须被 parser/translator 拦截；兼容性设计坦诚区分保留项（单条件/一层语法、triggerId/fieldValues 语义不变）和破坏项（删除 windowIndex、conditionIndex 语义重定义），明确依赖旧行为的消费端必须同步调整，运维侧给出灰度环境通知 payload 兼容性回归建议；性能方面不引入新持久化结构和网络往返，单层/单条件开销接近现状，多级子事件额外成本随节点数线性增长，通知 payload 新增短字符串字段体积增长可控。

## 3. 评审结论

设计文档整体设计合理、逻辑清晰，功能覆盖全面，递归条件树语法扩展、静态条件树路径 conditionPath、通知 payload 语义升级、嵌套分支切换四步通知顺序、_event_condition_path 占位符及复合主键语义等核心设计规范严谨，使用场景贴合分层告警和通知精确分流的实际业务需求，性能、安全、兼容性设计符合系统规范，精准解决了开始事件无法表达嵌套父子关系、通知语义不足以描述多级命中节点的核心痛点。
