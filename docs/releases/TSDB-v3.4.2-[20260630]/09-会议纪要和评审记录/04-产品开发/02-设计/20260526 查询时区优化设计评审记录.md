## 2. 评审记录

评审团队对设计文档（时区与查询改造 FS/DS）进行了全面审查，认为整体设计贴合连接级时区统一管理与自然时间单位扩展需求、逻辑严谨、可落地性强，具体评审意见如下：
1. 设计目标清晰精准，核心痛点定位明确，紧扣当前客户端时区无法在连接级灵活切换（仅有 C API 无 SQL 语法）、函数时区参数仅支持固定偏移不支持 IANA、TIMETRUNCATE 单位受限且 1w 对齐基于 epoch 取模无法自定义一周起始日、INTERVAL 不支持季度单位的痛点，明确核心目标为建立 L1-L5 五层时区优先级体系统一连接时区在客户端展示与服务端计算中的生效规则、新增 `SET TIMEZONE`/`SET FIRST_DAY_OF_WEEK` 语法、扩展 TO_ISO8601/TO_CHAR/TIMETRUNCATE 的 IANA 时区参数与自然单位、修正 1w 对齐为按 firstDayOfWeek、新增 INTERVAL 季度单位，目标聚焦、指引明确。
2. 功能设计全面细致，可落地性强，覆盖核心业务场景：FS 功能规格覆盖 11 项功能点（F1-F11）——时区层级体系设计完整（L1 SQL 级→L2 连接级→L3 客户端全局→L4 服务端全局→L5 系统默认，各场景回退链明确区分客户端展示/格式化函数/服务端计算/时间字面量解析四类路径）、`SET TIMEZONE` 语法定义完整（支持 IANA 名称和固定偏移四种写法/范围 ±14:00/保持 legacy ISO 解释/与 ALTER LOCAL 层级关系清晰）、`SET FIRST_DAY_OF_WEEK` 与 `firstDayOfWeek` 配置设计完整（0-6 范围默认 4 与 epoch 旧行为兼容/客户端 scope/ALTER LOCAL 动态修改/回退链 SET→客户端→默认 4）、函数扩展覆盖 TO_ISO8601/TO_CHAR/TIMETRUNCATE 的 IANA 时区参数及无参回退行为变更、TIMETRUNCATE 新增 n/q/y 单位与 1w firstDayOfWeek 对齐修正、INTERVAL 新增 q 季度单位等价于 3n、DST 春跳/秋退的写入与查询处理规则明确（gap 归一化到跳后时刻/overlap 取第一次出现）、JOIN ON TIMETRUNCATE 的 merge join 与 hash join 一致性要求、固定偏移兼容语义区分（SET TIMEZONE/TO_ISO8601 保持 legacy ISO 解释 vs ALTER LOCAL/TO_CHAR/TIMETRUNCATE 通用校验路径按 POSIX 符号解释）、新增错误码 0x26B2/0x26B3 定义清晰；DS 实现方案细致——代码基线差距分析明确（6 项未落地能力）、Parser/Client/Function/Scalar/Planner/Executor 各模块改动方案完整、hash join 对 TIMETRUNCATE 主键表达式的 planner slot 物化与 executor timezone_t 补齐设计合理、参数校验抽成共享 helper 供多入口复用、实施顺序分 5 个优先级清晰可执行、验收要点覆盖语法/回退链/函数/周季度/执行路径五大类，设计闭环完整。
3. 设计文档结构规范，版本与修订记录清晰：FS 文档包含四版修订记录（0.1 初稿→0.2 firstDayOfWeek 改为客户端参数→0.3 补充 JOIN ON TIMETRUNCATE 一致性→1.0 补充固定偏移兼容语义与 GMT 拒绝）、引言（目的/需求来源含 RS 勘误/术语 9 项）、功能总览与现状对照（11 项）、时区层级体系（五层优先级/各场景回退链/日期时间函数回退链/firstDayOfWeek 回退链）、SET TIMEZONE 语法（含与 ALTER LOCAL 关系/TIMEZONE() 增强）、firstDayOfWeek 配置与覆盖（含 SET 语法/ALTER LOCAL 关系/回退链）、查询行为（含 WHERE/CAST/JOIN 回退链/DST 春跳秋退处理）、写入行为与 DST、TO_ISO8601/TO_CHAR 扩展、TIMETRUNCATE 扩展、INTERVAL 扩展等章节；DS 文档包含两版修订记录（0.1 初稿→0.2 补充 hash join planner/executor 设计）、引言/代码基线/总体设计/F1-F11 功能点设计/数据结构与接口变更/错误码设计/兼容性与风险/实施顺序/验收要点/参考文件共 11 大章节，两份文档互为补充、FS 聚焦行为规格 DS 聚焦实现路径，逻辑清晰、无歧义，符合 TDengine 设计文档规范要求。
4. 安全性、兼容性与性能考虑周全，风险可控：安全方面 SET TIMEZONE/SET FIRST_DAY_OF_WEEK 仅影响当前连接不持久化、ALTER DNODE 操作需管理员权限、不涉及敏感数据处理；兼容性方面完全向后兼容（旧 SQL 不变/仅显式使用新语法时行为改变/TIMEZONE() 未设置 L2 时行为与原版本一致/TIMETRUNCATE 1w 默认 firstDayOfWeek=4 与 epoch 旧行为结果一致/INTERVAL 1w 默认兼容/TIMETRUNCATE 保持整数 0/1 兼容）、固定偏移兼容语义按入口区分避免 breaking change（SET TIMEZONE 保持 legacy/ALTER LOCAL 按 POSIX）、通信协议和数据格式均无变更；性能方面不影响正常查询写入路径、时区转换复用现有 timezone_t/localtime_rz/mktime_z 体系、hash join TIMETRUNCATE 主键表达式物化不引入额外 RPC。

## 3. 评审结论

设计文档整体设计合理、逻辑清晰，功能覆盖全面，时区与查询改造通过 L1-L5 五层优先级体系统一了连接时区在展示/函数/计算/字面量解析中的生效规则，新增 SET TIMEZONE/SET FIRST_DAY_OF_WEEK 语法提供了灵活的连接级时区与周起始日控制，TO_ISO8601/TO_CHAR/TIMETRUNCATE 的 IANA 时区扩展与自然单位扩展（n/q/y）覆盖了完整的日历时间计算需求，DST 感知的 JOIN ON TIMETRUNCATE 保证 merge join 与 hash join 一致性，性能、安全、兼容性设计符合系统规范，精准解决了连接级时区无法灵活管理、函数不支持 IANA 时区、自然时间单位不完整的核心痛点。
