## 2. 评审记录

评审团队对设计文档（超级表订阅表列表变更优化 DS）进行了全面审查，认为整体设计紧扣 TMQ 超级表订阅场景下子表动态变化导致的正确性缺陷、逻辑严谨、可落地性强，具体评审意见如下：
1. 设计目标清晰精准，核心痛点定位明确，紧扣超级表订阅在子表 Tag 修改或子表删除后表列表过滤结果不正确、已删除表 WAL 历史写操作无法解析导致消费中断的实际业务痛点，通过根因分析清晰揭示 `pCtbIdx` 始终读取最新 Tag 和 `pUidIdx` 查询已删除表直接报错两个核心问题，明确版本化 Tag 读取与 Schema 容错两条修复路径，目标聚焦、指引明确。
2. 功能设计全面细致，可落地性强，覆盖核心业务场景：版本化 Tag 读取机制通过 `version` 参数沿 `tqUpdateTableList → qFilterTableList → doFilterByTagCond → getTableTagsByUidVersion → metaGetTableTagByUidVersion` 完整调用链向下透传，`version = -1` 哨兵值保证非订阅场景零改动，设计简洁可靠；已删除表 Schema 容错通过 `ignoreExist` 参数控制降级路径，从 `pTbDb` 历史条目回溯 suid 和 Schema，避免消费中断；代码拆分方案将 `clientTmq.c`（约 6000 行）按职责拆分为 poll 主循环、commit、conf、offset 四个模块，服务端 TQ 模块同步梳理，新增 `tqInterface.c` 统一 RPC 处理函数，拆分后文件依赖关系清晰，各文件行数控制在合理范围；附带清理死代码 `SMqSeekReq`、移除冗余 `STqExecDb` 结构体、修正枚举命名 `WITH_DATA → ONLY_DATA`，整体改动边界清晰。
3. 设计文档结构规范，版本与修订记录清晰：明确修订记录（1.0 初稿 wangmm0220），术语定义完整准确（TMQ、STB、CTB、WAL、TQ、Tag、table list、ctbIdx、pTbDb、pSkmDb、WAL version），从引言、术语、概述、设计考虑、详细设计、接口规范、安全考虑、性能分析、部署配置、监控维护到参考资料分层呈现，Mermaid 架构图与流程图直观展示调用链与容错流程，接口变更规范列出 Storage API、Executor、executil、Meta 四层接口的新增与重命名，删除接口及原因明确记录，符合 TDengine 设计文档的规范要求。
4. 安全性、兼容性与性能考虑周全，风险可控：安全方面 `version` 参数为 `int64_t` 内部传递，不接受用户直接输入，无注入风险，不涉及认证授权变更；兼容性设计稳妥，`version = -1` 保持原有语义使普通查询路径零改动，`SMqSeekReq` 枚举值保留避免消息序号兼容性问题，不修改持久化格式无需数据迁移，滚动升级无需特殊处理；性能影响评估详尽，版本化读取路径仅在子表动态变化时触发，已删除表容错路径频率极低，普通查询无任何性能影响；风险识别覆盖 version 漏传、pTbDb 扫描性能、代码拆分编译错误等五项，每项均有明确缓解措施。

## 3. 评审结论

设计文档整体设计合理、逻辑清晰，功能覆盖全面，版本化 Tag 读取机制、已删除表 Schema 容错、模块代码拆分、冗余代码清理等核心设计规范严谨，调用链版本透传与哨兵值兼容策略简洁可靠，接口变更与风险缓解措施完备，性能、安全、兼容性设计符合系统规范，精准解决了超级表订阅场景下子表 Tag 修改或删除导致表列表过滤错误、历史 WAL 消费中断的核心痛点。
