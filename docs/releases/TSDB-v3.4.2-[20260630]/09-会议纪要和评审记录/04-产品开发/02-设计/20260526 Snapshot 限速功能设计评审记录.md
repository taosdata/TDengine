## 2. 评审记录

评审团队对设计文档（Snapshot 限速功能 FS/DS）进行了全面审查，认为整体设计贴合快照复制场景下 IO 带宽保护需求、逻辑严谨、可落地性强，具体评审意见如下：
1. 设计目标清晰精准，核心痛点定位明确，紧扣多 vgroup 同时进行快照复制时磁盘写入量叠加在 follower 节点产生严重 IO 瓶颈、影响正常业务读写性能的痛点，明确核心目标为引入 dnode 级别的快照发送限速机制（令牌桶算法），通过全局带宽控制避免快照复制过程对系统正常 IO 造成过大冲击，适用于集群扩容/节点故障恢复/混合部署环境三类典型场景，目标聚焦、指引明确。
2. 功能设计全面细致，可落地性强，覆盖核心业务场景：FS 功能规格完整——新增配置参数 `snapshotRateLimit`（int32/MB·s⁻¹/默认 0 不限速/范围 0-10240/服务端作用域/支持 ALTER DNODE 动态修改立即生效）、行为规则清晰（0 不限速/发送端 leader 控制/令牌耗尽非阻塞退出本轮等待 ack 触发下轮/快照 resend 不受限速/精度为 block 粒度偏差 ±1 block）、错误处理覆盖参数超范围和类型错误两类场景；DS 技术实现方案细致——全局单例 `SSnapshotRateLimiter`（mutex + tokens + lastFillMs）、非阻塞惰性填充设计（不使用定时器线程/在每次消费调用时根据时间差补充令牌/上限为 1 秒配额防 burst）、后置扣减策略（先发送再扣减因 block 大小需发送后才知道）、API 接口清晰（init/cleanup/tryConsume/deduct 四个函数）、发送路径集成方案明确（在 syncSnapBufferSend 循环中插入限速检查）、涉及 5 个核心文件变更，设计闭环完整。
3. 设计文档结构规范，版本与修订记录清晰：FS 文档包含一版修订记录（1.0 初稿）、背景、定义（4 项术语）、行为说明（配置参数/SQL 示例/行为规则/错误处理四大子节）、性能、安全、兼容性、运维、使用场景（3 项）、约束和限制、常见错误和排查（3 类）、可观测性、安装和卸载、文档、参考文档、附录共 16 大章节；DS 文档包含引言（目的/范围/受众）、术语、概述（架构图/技术栈/依赖项）、设计考虑（假设限制/设计模式/风险缓解）、详细设计（组件设计含配置注册/令牌桶/发送路径集成、关键数据结构、设计图含数据流/消息序列/流程图）、接口规范（API/UI）、安全考虑、性能和可扩展性、部署和配置、监控和维护、参考资料、文件变更清单共 12 大章节，两份文档互为补充、层次分明，逻辑清晰、无歧义，符合 TDengine 设计文档规范要求。
4. 安全性、兼容性与性能考虑周全，风险可控：安全方面 `ALTER DNODE` 需管理员权限符合现有权限模型、限速器内部 mutex 保护无竞态条件、不涉及敏感数据；兼容性方面完全向后兼容（默认值 0 与未引入功能前行为一致）、不涉及通信协议变更和数据格式变更、升级无需特殊处理降级后参数被忽略无副作用；性能方面默认不限速时零额外开销（TryConsume 直接判断全局变量返回 true/Deduct 为空操作）、启用限速时每次发送仅增加一次 mutex lock/unlock 和时间戳获取（纳秒级开销可忽略）、非阻塞设计对正常 Raft 消息处理无影响、多线程并发通过 mutex 保护安全、令牌上限 1 秒配额防止长时间无快照后突发。

## 3. 评审结论

设计文档整体设计合理、逻辑清晰，功能覆盖全面，Snapshot 限速功能通过 dnode 级全局令牌桶单例实现了非阻塞、惰性填充、后置扣减的快照发送带宽控制，配置参数支持动态修改立即生效，默认不限速保持完全向后兼容，性能、安全、兼容性设计符合系统规范，精准解决了多 vgroup 快照复制叠加导致 follower 节点 IO 瓶颈影响正常业务的核心痛点。
