## 2. 评审记录

评审团队对设计文档（Sleep 函数 FS、DS）进行了全面审查，认为整体设计对齐 MySQL 生态使用习惯、语义清晰、可落地性强，具体评审意见如下：
1. 设计目标清晰精准，核心痛点定位明确，紧扣 TSDB 缺少 SQL 层面可控等待能力导致查询超时配置验证依赖外部工具、慢查询日志触发无法通过 SQL 内部手段模拟、功能测试中延迟注入只能借助应用层 sleep 三大实际痛点，明确核心目标为引入与 MySQL 兼容的 SLEEP(duration) 标量函数，为测试能力增强和后续 SQL 级流量控制预留入口，目标聚焦、指引明确。
2. 功能设计全面细致，可落地性强，覆盖核心业务场景：FS 文档从核心语义、适用范围、参数规则、返回值语义、超时交互、并发安全、边界场景七个维度系统定义 SLEEP 函数行为，NULL 和负数立即返回 0、表查询每行各执行一次（MySQL 兼容）、与 readTimeout 和 queryNoFetchTimeoutSec 的交互关系明确无歧义；DS 文档按 Function 层、Parser 层、Planner 层、Executor 层、Scalar 层五层清晰列出改动清单，新增 FUNC_MGT_VOLATILE_FUNC 和 FUNC_MGT_NO_PUSHDOWN_FUNC 两个分类标志位分别阻止常量折叠和 vnode 下推，translateSleep() 翻译阶段设置返回类型，hasVolatileFunc 标记阻止无表查询走 LOCAL 短路路径，sleepFunction() 通过 threadlocal gTaskScalarExtra 感知查询取消状态实现 WHERE 子句中 SLEEP 的正确中断，实现路径完整可追溯。
3. 设计文档结构规范，版本与修订记录清晰：FS 文档从背景、定义、行为说明、性能、安全、兼容性、运维、使用场景、约束限制、常见错误排查、可观测性到参考文档分层呈现，修订记录明确（0.1 初稿 Stephen）；DS 文档修订记录两个版本（0.1 初稿、0.2 更正表查询每行执行一次语义），关联 FS 文档引用清晰，测试覆盖规划涵盖正向基本、NULL、负数、超时交互、无表查询、表查询多行、负向非数值参数七项，风险回滚策略完备（仅需从注册表移除条目、无数据格式变更），符合设计文档规范要求。
4. 安全性、兼容性与性能考虑周全，风险可控：安全方面明确 DoS 风险（大量并发 SLEEP 耗尽线程池）并给出缓解措施（现有连接数限制 + readTimeout 配置），SLEEP 仅允许具有 SELECT 权限的用户调用无需单独授权；兼容性设计稳妥，SLEEP 为全新函数不影响已有查询行为，无历史数据格式变更无需升级迁移，旧版本降级后报解析错误符合预期；性能方面 SLEEP 以 OS 级 sleep 实现 CPU 开销接近零，FUNC_MGT_NO_PUSHDOWN_FUNC 确保仅在协调层执行不扩散到 vnode 限制影响范围，回滚策略简洁（移除注册表条目即可，新增分类位对其他函数无影响）。

## 3. 评审结论

设计文档整体设计合理、逻辑清晰，功能覆盖全面，SLEEP 函数核心语义、参数规则、超时交互、五层改动清单、分类标志位设计、查询取消感知机制等核心设计规范严谨，使用场景贴合 MySQL 生态兼容需求，测试覆盖与风险回滚策略完备，性能、安全、兼容性设计符合系统规范，精准解决了 SQL 层面缺少可控等待能力导致超时验证和延迟注入依赖外部工具的核心痛点。
