## 2. 评审记录

### 2.1 架构安全性

- 代理层嵌入在 IDMP REST 服务内，复用现有端口和 TLS 配置，架构简洁。
- 只有 `/api/v1/mcp/stream` 一个入口，路径固定，攻击面小。
- 代理层职责清晰：路由、转发、映射错误——不做业务逻辑处理。
- **不足**：代理层不做独立鉴权，完全依赖上游 MCP Server 的认证。

### 2.2 身份认证与授权

- Authorization 头无条件透传到上游 MCP Server，代理层不做任何校验。
- 这意味着代理层对 MCP 流量是"透明"的——安全责任完全在上游 MCP Server。
- **不足**：如果 IDMP REST 层和 MCP 层使用不同的认证体系，存在认证绕过风险。
- **不足**：信任边界未在文档中明确定义。

### 2.3 数据流与隐私保护

- hop-by-hop 头过滤列表（Host、Connection、Keep-Alive、Transfer-Encoding、TE、Trailer、Upgrade、Content-Length、Content-Encoding）基本完整。
- **不足**：cookie 头未在过滤列表中。
- **不足**：X-Forwarded-For 可被客户端伪造。

### 2.4 输入验证与防御

- 代理层对请求体不做解析（§4.1 明确'不过度解析 body'），仅转发。
- 这是合理的安全决策——减少代理层的复杂度和攻击面。
- 但意味着所有输入验证责任在上游 MCP Server。

## 3. 评审结论

**条件通过。**

代理层设计简洁，职责清晰。主要风险在于认证边界模糊，建议增加至少一层 Token 格式校验，并明确信任边界文档。
