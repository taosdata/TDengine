## 2. 评审记录

评审团队对设计文档（taosAdapter 连接与订阅返回实例列表 FS）进行了全面审查，认为整体设计贴合 adapter 集群服务发现与高可用需求、逻辑严谨、可落地性强，具体评审意见如下：
1. 设计目标清晰精准，核心痛点定位明确，紧扣当前 WebSocket SQL 连接和 TMQ 订阅接口仅完成连接/订阅建立、不返回 adapter 实例列表导致调用方无法在连接时同步感知集群拓扑的痛点，明确核心目标为在不改变默认协议行为的前提下为 `/ws` conn 和 `/rest/tmq` subscribe 两个 WebSocket 入口增加可选 `list_instances` 请求字段、成功时在响应中返回 adapter 实例访问地址列表（`host:port` 格式），目标聚焦、指引明确。
2. 功能设计全面细致，可落地性强，覆盖核心业务场景：两个接口（SQL conn/TMQ subscribe）的请求字段定义完整（bool 类型、可选、默认 false）、响应字段语义清晰（字符串数组、仅 true 且查询成功时返回）、行为约束严谨（SQL 路径先完成认证白名单校验再查询实例列表/TMQ 路径持锁后先查询实例列表再创建 consumer/查询失败则连接或订阅失败/空列表返回空数组）、实例列表查询规则明确（使用 `taos_list_instances(filter_type)` 过滤仅返回 adapter 类型实例/地址必须携带端口号）、错误码与错误处理覆盖 5 种场景（旧版本忽略/未设置不返回/空列表/SQL 查询失败关闭连接/TMQ 查询失败不创建 consumer），请求和响应均提供完整 JSON 示例，设计闭环完整。
3. 设计文档结构规范，版本与修订记录清晰：文档包含两版修订记录（0.1 初稿→1.0 明确返回值为带端口号的实例访问地址）、背景、定义（5 项术语）、行为说明（SQL 连接/TMQ 订阅/实例列表查询规则/错误码四大子节）、性能、安全、兼容性（含降级兼容）、运维、使用场景（4 项）、约束和限制（4 项）、常见错误和排查（5 类场景）、可观测性、安装和卸载、文档（3 项修改点）、参考文档、附录共 16 大章节，层次分明、约束与限制界定清晰，逻辑清晰、无歧义，符合 TDengine 设计文档规范要求。
4. 安全性、兼容性与性能考虑周全，风险可控：安全方面不新增认证方式、不绕过现有校验、返回数据仅含实例地址不含用户数据或凭据、响应是否返回由调用方显式请求控制默认不返回避免意外暴露；兼容性方面默认值 false 使旧客户端行为不变、旧 adapter Go JSON 反序列化忽略未知字段不报错、新客户端将缺失字段视为服务端未返回而非协议错误、降级后核心连接订阅能力不受影响；性能方面默认路径无额外开销、请求 true 时仅在初始化阶段额外调用一次本地客户端实例查询、不影响后续查询/写入/poll/fetch/commit 的正常执行路径。

## 3. 评审结论

设计文档整体设计合理、逻辑清晰，功能覆盖全面，taosAdapter 通过在 WebSocket SQL 连接和 TMQ 订阅接口中新增可选 `list_instances` 字段实现了按需返回 adapter 实例访问地址列表的能力，协议扩展保守（默认不返回/旧版本忽略）、错误处理语义明确（查询失败即连接或订阅失败），性能、安全、兼容性设计符合系统规范，精准解决了调用方无法在连接或订阅建立时同步感知 adapter 集群拓扑的核心痛点。
