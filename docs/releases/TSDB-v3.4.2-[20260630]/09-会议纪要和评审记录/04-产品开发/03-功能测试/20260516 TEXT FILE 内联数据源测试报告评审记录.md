## 2. 评审记录

评审团队对测试文档（TEXT/FILE 内联数据源功能测试相关）进行了全面审查，认为所有设计合理、内容详实、流程规范，具体评审意见如下：
1. 测试目标明确：针对 TEXT/FILE 内联数据源功能开展专项测试，目标聚焦基础查询（SELECT/WHERE/ORDER BY/子查询/JOIN）、窗口查询（INTERVAL/SESSION/STATE_WINDOW/时序函数）、列类型覆盖（含 DECIMAL/VARBINARY/不支持类型拒绝）、数据量边界限制（行数/列数/单元格数/字节数的达标与超限拒绝）、首列 TIMESTAMP 约束（无 ts/非首列 ts 拒绝）、乱序与重复时间戳处理、UNION/UNION ALL 组合、FILE 专属特性（header/delimiter/部分列读取/类型转换容错），同时覆盖反例测试（超限数据/非法类型/无主键列/不存在列名），定位清晰、重点突出。
2. 测试用例设计全面：15 个测试函数（TEXT 7 个 + FILE 8 个）覆盖十五大模块，合计 330+ 条测试点（186 条 `.in` 文件 SQL + 144 条内联断言）——TEXT 基础查询（SELECT/WHERE/ORDER BY/子查询/聚合/NULL/JOIN/LEFT JOIN/INSERT INTO SELECT，9 条）、TEXT 窗口查询（INTERVAL/SESSION/STATE_WINDOW/CSUM/DIFF/LAG/LAST，5 条）、TEXT 列类型覆盖（DECIMAL/VARBINARY/不支持类型拒绝，8 条）、TEXT 大数据量与边界限制（10,000 行达标/超限/1,000,000 单元格/8 MB/聚合校验，7 条）、TEXT GROUP BY（分组/HAVING/多列聚合，3 条）、TEXT 首列约束与乱序重复（无 ts 拒绝/非首列拒绝/乱序排序/重复 ts 保留/组合场景，14 条）、TEXT UNION（TEXT+TEXT/去重/+实表/子查询包裹/GROUP BY/无 ts 反例，10 条）、FILE 基础查询（CSV 读取/WHERE/ORDER BY/NULL/乱序/JOIN/header/delimiter/INSERT/LEFT JOIN，10 条）、FILE 大数据量（10,000 行/超限/聚合校验，3 条）、FILE 边缘场景（Schema 窄于 CSV/类型容错/宽列/header 子集/不存在列名，5 条）、FILE GROUP BY（分组/聚合，2 条）、FILE 首列约束（无 ts/INTERVAL/JOIN/非首列反例，6 条）、FILE 重复时间戳（保留/COUNT/GROUP BY，3 条）、FILE UNION（FILE+TEXT/TEXT+FILE/FILE+FILE/去重/+实表/无 ts 反例，9 条）、FILE 列类型全覆盖（VARBINARY/NCHAR 中文/整数类型/NULL 表示/BOOL/FLOAT/部分列/DECIMAL，8 条），用例设计科学合理、覆盖全面。
3. 测试覆盖维度完整：涵盖功能覆盖（TEXT 和 FILE 各自独立覆盖基础查询/窗口/聚合/UNION/JOIN/INSERT INTO SELECT 全路径）、类型覆盖（INT/BIGINT/FLOAT/DOUBLE/BOOL/VARCHAR/NCHAR/VARBINARY/DECIMAL/TIMESTAMP 及 SMALLINT/TINYINT/UNSIGNED 变体）、边界覆盖（10,000 行/1,000,000 单元格/8 MB 三层限制的达标与超限）、反例覆盖（无 TIMESTAMP 首列/非首列 TIMESTAMP/不支持类型 JSON/GEOMETRY/BLOB/超限数据/不存在列名）、组合覆盖（TEXT+TEXT/FILE+FILE/TEXT+FILE/FILE+TEXT/+实表的 UNION/JOIN 全组合）、兼容性覆盖（INSERT INTO SELECT/JOIN/UNION/窗口查询/时序函数五个维度与已有功能的组合验证），测试严谨性强。
4. 测试方法规范：明确各功能模块测试要点，详细列出用例编号、测试描述及测试结果，清晰区分正常场景（基础查询/窗口/聚合/JOIN/UNION）和反例场景（无 ts 拒绝/非首列拒绝/超限拒绝/不支持类型拒绝），采用 `.in/.ans` 文件对比验证全部输出（含列头/数据行/错误信息）和内联 `tdSql.checkRows/checkData/error` 逐条校验双重验证机制，测试流程规范，结果可验证、可追溯。
