## 2. 评审记录

评审团队对需求文档（新 taosdump 相关）进行了全面审查，认为所有设计合理，具体评审意见如下：

### 2.1 功能

- 需求精准切中大数据量场景下备份速度慢、文件体积大、恢复低效三大痛点，采用列存储（zstd 逐列压缩）替代 Avro 行存储的核心设计方向明确，功能覆盖全量/指定库表/时间范围/Schema-only 四种备份模式以及断点续传、数据库重命名恢复等高级场景

- 功能范围定义清晰，29 项功能需求覆盖备份（13 项）、恢复（8 项）、连接（5 项）、其他（3 项）四个类别，支持 TDengine 全部数据类型（含 DECIMAL）、全部时间精度（ms/us/ns）、全部表类型（STB/CTB/NTB/VTAB/VSTB），二进制与 Parquet 双格式、STMT1/STMT2 双写入模式设计合理

- 里程碑和优先级划分合理，定位为 P0 级核心工具随主版本同步发布，开源与企业版同步支持

### 2.2 性能

- 性能需求有明确基准数据支撑（1 亿行实测），binary T8 备份 28s/恢复 29s、文件体积仅为 taosdump Avro 格式的 42%，性能目标量化、可验证

- 多线程并行设计（数据线程 T + 标签线程 m）充分利用多核资源，连接池（dataThread×2 + tagThread + 4）大小与线程数匹配，资源管理合理

### 2.3 安全

- 安全需求边界清晰：凭证仅通过命令行参数传入不写入备份文件，备份文件访问控制依赖操作系统文件权限，不引入额外攻击面

### 2.4 兼容性

- 兼容性设计稳妥，支持 TDengine v3.0.0.0+ 版本（STMT2 需 v3.3+），平台覆盖 Linux（x86_64/x86/ARM64/ARMv7l/MIPS64/LoongArch64）和 macOS（Apple Silicon），Parquet 通过编译宏在 Windows 上优雅禁用

- Schema 变更适配（ColMapping 部分列写入）保证不同版本间备份数据的恢复兼容性，断点续传机制保证大规模数据备份的可靠性

## 3. 评审结论

需求文档整体设计合理、逻辑清晰，可用于指导后续开发工作。
