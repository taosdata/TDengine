## 2. 评审记录

评审团队对需求文档（License Center 相关）进行了全面审查，认为所有设计合理，具体评审意见如下：

### 2.1 功能

- 需求精准定位了当前 TDengine/IDMP 授权管理分散、更新复杂、缺乏可见性等核心痛点，明确了 ELS（中心侧授权服务）和 CLS（客户侧授权服务）的分层架构设计，职责划分清晰，符合业界 License Server 最佳实践。

- 许可证体系设计完整，涵盖 TSDB（含 DATAIN）和 IDMP 两类授权，授权项维度（测试点数、CPU 核数、有效期、集群个数等）覆盖全面；槽位机制实现集群先到先得的灵活绑定，简洁高效。

- 里程碑计划合理，分四阶段推进（CLS+IDMP 上线 → TSDB 改造 → ELS 全流程 → 测试验收），节奏清晰，便于项目跟踪和风险管控。

### 2.2 性能

- CLS 作为客户侧轻量化授权代理，本地缓存授权信息，避免频繁远程校验，对 TSDB/IDMP 集群正常运行无性能影响；宽限期（默认 14 天）机制保障网络中断场景下业务连续性，设计合理。

### 2.3 安全

- 许可证签发采用公钥体系，CLS 认证字符串包含公钥、CLS_ID 和机器码，授权绑定硬件指纹可有效防止非法复制和滥用；离线激活绑定机器码的流程参考了业界 Node-Locked 模式，安全性可靠。

### 2.4 兼容性

- 版本兼容性需求描述到位，明确为企业版专属功能，发布版本为 TDengine 3.4.1，且需兼容现有单机 License 验证机制保证平滑升级，符合项目迭代原则，可保障现有客户业务场景不受影响。

## 3. 评审结论

需求文档整体设计合理、逻辑清晰，可用于指导后续开发工作。
