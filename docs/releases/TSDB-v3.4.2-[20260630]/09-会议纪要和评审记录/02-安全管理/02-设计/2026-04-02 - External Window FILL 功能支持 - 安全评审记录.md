# External Window FILL 功能支持 - 设计安全评审记录

### 1. 评审信息

1. **评审目的：** 评估「External Window FILL 功能支持 FS」的技术设计方案是否有效、合理地实现了安全需求，识别架构与详细设计中的安全缺陷，并提出改进建议。
2. **评审文档：** `external_window FILL 功能支持 FS.md`

### 2. 安全评审记录

评审团队对设计文档进行了审查，重点覆盖 external_window FILL 在 parser/translater/planner/executor 链路上的安全影响，并结合时序数据库高并发查询、分区执行与窗口补行场景进行分析。

#### 2.1 身份认证与访问控制

- **评审意见与发现：** FS 明确 FILL 仅支持聚合模式（`4.2`），减少误用；但未定义窗口定义子查询对象与源表对象的联合授权策略，缺少最小权限矩阵与失败路径定义。
- **状态：** 待定
- **说明/依据：** `4.2` 与 `16.2.2` 只描述语义和实现，不包含对象级访问控制规则。

#### 2.2 数据安全

- **评审意见与发现：** 功能仅影响查询结果，不涉及落盘数据结构（`16.5.3`）；但 `PREV/NEXT` 缓存、窗口数组、空窗口聚合中间态的生命周期和异常清理未明确，存在残留状态污染风险。
- **状态：** 待定
- **说明/依据：** `5`、`16.2.3` 给出缓存策略但未给出安全清理约束。

#### 2.3 输入/输出验证与编码

- **评审意见与发现：** 已定义 `VALUE/VALUE_F` 参数个数与类型校验，以及 `LINEAR/NEAR/SURROUND` 的语义层拒绝（`11`、`16.4.1`）；但未定义窗口数量和 VALUE 常量规模上限，仍可能被构造为资源放大型查询。
- **状态：** 待定
- **说明/依据：** 现有控制偏语义正确性，缺少抗滥用边界。

#### 2.4 会话与通信安全

- **评审意见与发现：** 本次不新增会话机制、认证令牌或网络协议，未引入新的通信链路风险。
- **状态：** 不适用
- **说明/依据：** 设计范围集中在查询解析、计划和执行器内部逻辑。

#### 2.5 安全日志与监控

- **评审意见与发现：** 文档要求 explain/错误码/日志区分三类失败（`12`、`16.6.2`），具备基础可观测性；但缺少安全审计字段基线（用户、对象、fill 模式、窗口规模、错误码、耗时）和告警阈值。
- **状态：** 待定
- **说明/依据：** 可观测性目标已提出，安全追溯深度不足。

#### 2.6 威胁缓解机制

- **评审意见与发现：** FS 已识别分区串组、字段漏传、参数错误等风险（`11`、`16.5`），但尚未形成“威胁—控制”强绑定。建议绑定 `T-EXTFILL-01`→`SEC-EXTFILL-001`、`T-EXTFILL-03`→`SEC-EXTFILL-003`、`T-EXTFILL-04`→`SEC-EXTFILL-004`。
- **状态：** 待定
- **说明/依据：** 见威胁建模报告 `4.2`、`5` 节。

#### 2.7 默认安全配置

- **评审意见与发现：** 默认不开启 FILL 时行为不变（`7`），兼容性基线较好；但强制模式在全空窗口场景会主动补行（`4.7`），若没有阈值限制，可能放大资源消耗。
- **状态：** 待定
- **说明/依据：** `4.7`、`16.6.1` 明确语义差异，未定义默认护栏。

#### 2.8 依赖组件安全

- **评审意见与发现：** 改动跨 parser、planner、nodes clone/code/msg、executor 多组件，任何链路漏改都可能引发分布式语义不一致。
- **状态：** 待定
- **说明/依据：** `16.2.2`、`16.5.1` 已将该问题列为主要工程风险。

#### 2.9 隐私设计

- **评审意见与发现：** 本功能不新增个人信息处理链路，无新增隐私合规接口变更。
- **状态：** 不适用
- **说明/依据：** FS 未涉及隐私数据收集和对外共享。

#### 2.10 其他（可扩展性、运维安全等）

- **评审意见与发现：** 已提供快速回滚策略（`16.5.3`）；但灰度发布缺少明确自动降级指标（结果行放大倍数、错误码激增、慢查询比例）。
- **状态：** 待定
- **说明/依据：** 回滚路径可行，运维触发门槛尚未量化。

### 3. 评审结论

1. **总体安全风险等级：**
  - 中风险
    - 风险集中在资源耗尽、跨分区状态隔离和分布式一致性。
1. **评审结论：**
  - 有条件通过
    - 完成关键安全约束后可进入编码实现与回归。
