## 2. 会议决定事项

1. **审阅通过**《TSDB v3.4.2 质量管理计划》（v1.0），确认文档内容已覆盖 v3.4.1 质量保证报告中提出的过程改进建议，并体现以下延续与提升：
   - 缺陷报告规范率目标延续 ≥ 95%，由肖波继续执行缺陷报告质量门禁，并新增对连接器高可用（taosX HA / 连接器 HA）等复杂模块的缺陷质量关注。
   - 需求追踪矩阵（RTM）每周更新机制延续，王旭每月审计执行情况；GitLab 迁移期间，各功能负责人须同步在新平台维护 RTM。
   - NCR 整改时限延续（严重 3 天 / 一般 7 天），度量频率保持每月第三个周四。

2. **验收角色确认**：本版本新增验收组长张心治（交付中心），负责从交付方视角参与系统测试阶段的产品验收与质量评审，王旭将在系统测试审计计划中纳入与张心治的协同节点。

3. **GitLab 迁移质量风险**：会议识别 GitLab 迁移过程中 CI/CD 流水线及代码评审流程存在中断风险（Risk-342-04）。决定由关胜亮负责组织制定迁移期间的过渡方案，王旭将该风险纳入质量风险跟踪，并在 4 月需求与设计阶段审计中专项核查迁移进展。

4. **漏洞扫描服务器投产**：确认本版本计划将漏洞扫描服务器正式投入使用，霍琳贺负责与平台组协调投产时间表，目标于系统测试阶段开始前（2026-07-01）前完成部署，王旭跟踪进度作为安全质量门禁验证项。

5. **集群稳定性测试覆盖**：肖波确认在系统测试阶段使用 IDMP 稳定性测试框架（crash-gen）覆盖集群稳定性场景，测试计划须在系统测试开始前提交评审；王旭将集群稳定性测试覆盖情况纳入系统测试审计检查项。

6. **质量度量周期**：延续每月第三个周四进行度量指标采集，本版本新增对"漏洞扫描服务器投产进度"的跟踪，并继续跟踪"需求追踪矩阵更新及时率"。
