Release Date: **2026-11-02**

## Features

  1. Add a port-declaration consistency gate that parses the planning document's port tables and statically scans the codebase, blocking MRs and raising Feishu alerts on undeclared ports or semantic conflicts.
  2. Add aggregate function BIT_DURATION to measure how long an integer or boolean point stays in a masked bit state, including windows and stream processing.
  3. Add the subscription parameter msg.consume.start.ts so table and database subscriptions can consume only rows whose primary timestamp is at or after a Unix time in milliseconds, with 0 meaning no filter.
  4. Add triggerTableName to every stream notification event, using the trigger child-table name without a database prefix for PARTITION BY tbname, the virtual child-table name for a virtual table, and an empty string otherwise.
  5. After a taosX node fails, the Agent confirms the previous task has exited before the new node starts the same task, and stale start, stop, and cancel commands cannot take the task back.
  6. Federated query can register on-premises SQL Server 2019 and 2022 as an external source, query its tables and views, and reference them from virtual tables.
  7. Let taosExplorer write data collected by Neuron or NeuronEX into TDengine through eKuiper, with onboarding, refresh, and monitoring under Data In on the Data Collection Agents page.
  8. Let the self-hosted taosExplorer SQL editor set the frontend timeout for the current execution, defaulting to 60 seconds with a range of 1 to 3600 seconds, and show a yellow warning on request timeout without cancelling a query that is still running on the server.
  9. Linux can run federated queries against Oracle, including external tables and virtual-table external sources.
 10. OPC DA point tasks accept a PI-compatible quality mode and digital-state value map, and migration tools can rebuild a PI archive on a PI server, then replay and map the points onto existing TDengine tables through OPC DA.
 11. Support FULL on SHOW CREATE TABLE, STABLE, VTABLE, and RSMA, returning the complete DDL as a BLOB instead of truncating it at 65535 bytes.
 12. Support SQL Server external sources in stream processing, so virtual tables can mix those columns with local columns, short and explicit database or schema references identify the same remote table, and completed window results are kept after a reference is rebound.
 13. Support recording native client workloads at the public API boundary, including connections, SQL, STMT, and schemaless calls, and replaying them with taosreplay using the original connection and thread timing.
 14. TDgpt adds PCA (principal component analysis), PLS (partial least squares), and clustering analysis (KMeans, DBSCAN, GMM).
 15. TaosExplorer and taosX can connect to Kepware Server 7.1, scan OPC UA points, and ingest them by subscription or polling into a selected database.
 16. Windows can run federated queries against MySQL, PostgreSQL, and InfluxDB, including external tables and virtual tables with external sources.
 17. Windows can run federated queries against SQL Server, including external tables and virtual tables with external sources.

## Enhancements

  1. A stream fetching calculation data from an external table uses the time expressions in the calculation statement, clips only the window-join side that references those columns, and no longer skips a due PERIOD window because of idle throttling.
  2. Automatically recover Agent tasks that should keep running after an XNode failure or Agent reconnect.
  3. Creating or querying a virtual table with a very large number of columns now resolves column references by column id, so SQL analysis no longer spends a long time repeatedly scanning every column.
  4. Federated query is now tested with PostgreSQL 18.6, while supported versions remain 14 and above.
  5. Libtaos.so no longer depends on libtaosnative.so, so a WebSocket-only deployment can load the client by itself.
  6. Query and stream processing WALk node lists in order, so the cost grows linearly with the node count instead of with its square. Rewriting parameters for 16,000 nodes dropped from about 232 ms to about 0.21 ms.
  7. Reduce the client memory used to hold column and tag references when querying a virtual super table.
  8. Single-table tag SUM, AVG and COUNT, and interval queries partitioned by tags, run faster, and a super-table interval query with LIMIT can use the INTERVAL_LIMIT() hint to scan less.
  9. Skip the full vgroup scan when information_schema.ins_databases does not need ntables.
 10. Speed up information_schema.ins_tables queries that filter table_name with equality or IN by looking up the name index instead of scanning every table in the vnode.
 11. Speed up most BLOB column queries so eligible count(blob) queries use block-level precomputed statistics again, while some medium-length select blob queries may slow down and use more memory.
 12. Support SQL changes to xnodeDsnProtection, xnodeDsnPublicKeyFile, and xnodedDsnPrivateKeyFile, persisting the values and applying them after taosd restarts.
 13. TaosExplorer no longer bundles the user manual. Chinese and English manuals are installed separately, and a missing language opens the official website instead of returning 404.
 14. TaosX data-source plugins are installed separately. A host without the plugin cannot run that data-source task, while taosExplorer still lists the data source and names the missing plugin and package.
 15. Use the official documentation favicon for the Explorer browser tab.
 16. When an interval query uses only the table name or a single tag as its group key, each scan block keeps one copy instead of copying the key into every row, and query results stay the same. On warm-cache Debug runs, 24 million rows across 400 child tables with long names fell from 0.711 s to 0.160 s, and 10 million rows across 100 child tables with a long VARCHAR tag fell from 0.362 s to 0.0678 s.

## Fixes

  1. 3.4.3.5 failing to restart streams because it rejects checkpoints written by 3.4.3.0 through 3.4.3.4 with Invalid message.
  2. A C/C++ client no longer leaks memory when writing with STMT2 parameter binding, and the next successful write on a fixed table without interlace keeps its bound fixed tags after an execution error.
  3. A delete recalculation staying pending and leaving result rows missing when it arrives after real-time progress advances with an empty recalculation queue and no further writes.
  4. A failed decode of a super table heartbeat response or table metadata releases the partially decoded data, so this error path no longer leaks memory.
  5. A last_row query on a super table grouped by child table no longer waits for the whole cache scan before producing output, so the query is faster when there are many child tables.
  6. A partitioned window stream fails when some groups have no valid input on a vgroup but still emit an empty aggregate, because those rows leave the required group order.
  7. A schemaless create of an existing super table can no longer change the type of an existing column or tag, shrink its width, or drop it, while a taosX create still cannot change a type or shrink a width but can drop a column or tag for cross-cluster replication.
  8. A single-start EVENT_WINDOW with TRUE_FOR now sends the historical OPEN notification when the duration is met, even if the window is still open at the end of the history scan.
  9. A stream that uses %%trows no longer crashes taosd with an out-of-bounds access when a window contains variable-length columns.
 10. A stream with a standalone SLIDING and IGNORE_NODATA_TRIGGER generated every empty window across a large time gap, delaying results for that group and other groups.
 11. ALTER statements for a virtual-table SERIES leaked the alias, external source name, and tag condition after parsing, so repeated execution kept growing client memory.
 12. After SPLIT on a double-replica database with an arbitrator, SHOW ARBGROUPS drops the source vgroup's arbgroup and creates one for each of the two resulting vgroups.
 13. After SQL Server stops, a federated query fails at the configured connect timeout and is no longer held by the driver's internal retries.
 14. After a stream is dropped and recreated with the same name, a stale deployment action no longer keeps the deployment state, and unfinished management state is released when deployment fails or a runner task is undeployed, so taosd memory no longer keeps growing.
 15. After a virtual-table column rebind, a stream redeploy that does not finish within 60 seconds no longer retries forever and fails the stream with an explicit error.
 16. Allocating a TDB free page rewrote the page before the rollback log, so an unexpected restart corrupted the free-page chain and the next allocation exited on an invalid page number.
 17. An ONLY META or WITH META super-table subscription now filters child tables by the WHERE condition in the metadata snapshot, so a child-table name condition no longer delivers create events for every child table.
 18. An encrypted backup left the buffer length set after writing a full cipher block, so a later write could emit the old block again and restore failed with Invalid message.
 19. An ordinary inner join whose inputs are already ordered by the primary timestamp, with an extra equality on a column or tag, defaults to Merge Join again instead of Hash Join.
 20. Arbitrator assignment of a vnode leader always checks the member token, so the force flag can no longer skip the check and an unmatched request cannot make the vnode an assigned leader.
 21. BALANCE VGROUP LEADER now logs the vgroup, database, and error when it cannot add a vgroup to the balance transaction.
 22. Building Arrow from source on non-Windows platforms could pick an incompatible OpenSSL 4 for its bundled Thrift and fail the macOS build; it now uses the project's OpenSSL 3.1.3.
 23. Casting DECIMAL to VARCHAR, BINARY, or BLOB reading past the buffer when the target width cannot hold the full text.
 24. Client crash when a virtual supertable aggregation groups by a source-table tag and the time filter can be pushed down.
 25. Correct the unclear description in the user manual of which row or column privilege applies, stating that a user privilege takes priority over a role privilege of the same type, and that the later-updated role privilege is used when the user has none.
 26. Correct the unclear description of FIRST and LAST on a non-primary timestamp, stating that both follow the effective timeline and are not equivalent to ORDER BY the argument column with LIMIT 1.
 27. Destroying a stream task freed its data cache before the cache iterators still in use, so taosd accessed freed memory during shutdown.
 28. During a slow taosd startup, the stream heartbeat no longer runs before the message callbacks are registered, so startup no longer crashes on that path.
 29. During an AVRO restore, taosdump no longer reports a just-created table as missing, stops the restore when CREATE DATABASE fails, and shows progress while creating child tables.
 30. Fix TDgpt models getting stuck in the 'started' state after a container restart or a killed worker, which kept the model-load API returning 500; model state is now reconciled from live processes and installed files at startup and before each request, so manual database edits are no longer required.
 31. Fixed an issue where a stream on a virtual table with referenced TAGs produced no data when PRE_FILTER was configured, because all source tables were pruned.
 32. Grouped last() queries slowed down because a reused scan block kept a false null flag, and the per-query reader timing log is now DEBUG instead of INFO.
 33. IDMP repeatedly querying information_schema.ins_tables by UID for virtual child-table names during a burst of events and saturating taosd.
 34. In taosExplorer data ingestion with a pSpace source, an empty point list showed a blank error toast, and on Chrome or Edge 86 the metrics dialog after a task started was offset and could not scroll.
 35. OPC DA fixed-length strings now keep only the text before the first NUL by default, so the NUL and the characters after it are no longer written to TDengine.
 36. On Windows, taosd, taosAdapter, taosKeeper, taosX, and taosExplorer restart 10, 30, 90, 180, and 300 seconds after an abnormal exit, for at most five times, and then stop restarting automatically.
 37. On Windows, the xnoded readiness probe waits up to 3 seconds per attempt instead of 100 milliseconds, so a started xnoded is no longer treated as unreachable and stopped during XNODE creation or restart.
 38. Queries without a BLOB column no longer check the BLOB length on every row, so 16 MB BLOB support no longer slows large reads of ordinary tables.
 39. Querying information_schema.ins_tags by table name reads that child table's tags directly, and equality filters on database, super table, and table name are applied before the scan, so a database with many child tables no longer WALks all metadata.

 44. SPLIT VGROUP on a vgroup_id that does not exist now reports that the vgroup is missing instead of returning success.
 45. Snapshot restore, including REDISTRIBUTE VGROUP, now places data files on the storage tier selected from file time and the KEEP configuration, instead of writing them all to tier 0.
 46. Stream calculations that use only some virtual-table columns adding a Reader and retrying after an unused column is rebound, while rebinding a column used by the calculation or in WHERE still deploys a Reader when needed.
 47. Streams restarting or redeploying and then repeatedly reporting WAL log does not exist and redeploying with no output when the requested WAL has been reclaimed, so they continue from the WAL that is still retained.
 48. Streams sourced from a virtual super table repeatedly fetching database routing from the mnode and resolving unused column references while parsing tag references, causing excessive metadata requests and high memory use.
 49. Streams that read a data column added directly on a virtual child table missing the reference or returning empty or NULL results, so dropping an unused owned source no longer fails calculations on inherited columns.

 51. TaosX OPC UA collection leaving sessions open after a subscription failure, reconnect, or task exit, so sessions no longer accumulate until later connections are rejected and the task restarts repeatedly.
 52. TaosX queried the target database KEEP and precision before every Point write batch, which piled up metadata queries on taosd and made them intermittently slow. Each task now caches that result and reuses it for 1 hour by default.
 53. TaosX-opc remaining in the running state with no data written after an abnormal exit and restart, when metric reporting or the OPC DA initial connection blocks.
 54. Taosd and taos no longer fail to start when an existing writable log file cannot be changed to mode 0666; they keep the current permissions and print a warning.
 55. Taosd crashing while formatting a taoskeeper report when a monitor metric label contains a comma, equals sign, quote, or brace, with those characters replaced by underscores when the label is written.
 56. Taosdump import failing with row length exceeds max length after the CREATE statement was truncated. Backups now use SHOW CREATE ... FULL and keep the full statement.
 57. Taosdump omitting virtual tables with many columns because SHOW CREATE was truncated. Backups now use SHOW CREATE ... FULL and keep the full statement.
 58. Tasks run through a taosX Agent staying queued after a start attempt while the agent is disconnected, and not starting automatically after the agent reconnects.
 59. The InfluxDB connector exited before its readers started, so a migration task was reported successful with no data written.
 60. The outer filter of a state-window stream is applied before results are written, so windows that do not match are no longer emitted, and a trailing history window that has not reached TRUE_FOR no longer triggers calculation.
 61. Trigger thread CPU staying at 100% after creating a virtual-table stream without FILL_HISTORY, caused by eager history-context setup that matched every virtual table in each group.
 62. Upgrade zstd-sys to 2.1.2 and backport the RUSTSEC-2026-0403 fix to zstd-safe 5.0.2/7.2.4.
 63. Virtual table queries with ORDER BY ts and LIMIT scanning all rows and sorting the full merge result when the sort direction and row limit are not pushed down.
 64. Virtual table streams getting stuck retrying the virtual table patch and reporting Invalid parameters after runtime virtual table changes.
 65. Virtual-table stream history processing crashing taosd when a condition compares an empty filtered column.
 66. Virtual-table streams with NODELAY_CREATE_SUBTABLE stopping on Retry needed or Internal error when initialization responses arrive out of order, while still creating output child tables early.
 67. WAL retention and rollback not deleting WAL files on non-primary mount points when level 0 has multiple disks, causing disk usage to keep growing.
 68. When CREATE STREAM inside an explicit transaction creates an output super table or a NODELAY table, that table is visible in the same transaction once the statement succeeds.
 69. When a consumer unsubscribes while a rebalance is being committed, a stale rebalance result no longer sets the consumer back to ready, so the topic can be dropped immediately instead of staying subscribed.
 70. When a virtual table column is narrower than its source column, UNION and UNION ALL use the wider column and no longer report invalid input.
 71. When monitor protocol logging is enabled, taosd estimates the line count of a multi-line JSON message from its size, so log files rotate and compress at numOfLogLines.
 72. With DEBUG logging enabled, scalar evaluation no longer writes a high-frequency debug line per column argument, so JOIN queries are not slowed by log output.

## Security

  1. A JSON tag index rejects an overlong column name, and a filter result shared by a nested condition is released only once.
  2. A dnode rejects invalid management messages and forged responses, configuration outside the dynamic scope is no longer applied, and the object-storage access string no longer appears in configuration output.
  3. A leader counts a replica only up to the log it actually sent, so a forged acknowledgement can no longer invent a quorum and commit unreplicated entries. TD-SEC-2026-044.
  4. A request that assigns an arbitrator group leader now requires a privilege check, so an unauthorized peer can no longer force a vnode leader change.
  5. A vote request that claims to come from the node itself, or from the current leader in the same term, is dropped, so it can no longer depose the leader or consume the vote.
  6. An append-entries frame must contain the full header, and its declared data length cannot exceed the bytes left in the frame. A short or oversized frame is rejected and no longer causes an out-of-bounds read that crashes taosd. GHSA-q86r-32wm-qwpg.
  7. An unauthenticated connection can no longer fetch the full global configuration, and the community edition no longer shows secrets such as the object-storage access string in clear text in SHOW VARIABLES.
  8. Before forwarding monitor statistics, mnode checks that the claimed user exists and rejects invalid JSON, so unverified content is no longer sent to taoskeeper.
  9. Bound TMQ ask-ep response decoding so an overlong topic, database name, or FQDN is rejected instead of overflowing the client stack (CWE-121).
 10. CREATE STREAM now checks the client-supplied execution plan and rejects a plan with the wrong node type or a missing required child, instead of crashing the mnode.
 11. Client sync requests are no longer accepted from the network, so an unauthenticated peer can no longer use them to write a Raft log. If one still reaches the internal path, its declared data length cannot exceed the frame.
 12. Correct the minimum length of sync snapshot requests and responses so a complete fixed header with a truncated payload header stops the sender session and resets replication, instead of requiring struct trailing padding (GHSA-xg67-9f8r-64v5, TD-SEC-2026-042).
 13. Creating a stream now requires the name, database, and table, and a request that omits them is rejected instead of dereferencing a null pointer during creation or reload.
 14. Creating a super table now rejects a fixed-width column whose length is outside the type's allowed range, so an out-of-range width is no longer copied into subscription and stream blocks.
 15. Creating a super table now requires precision and scale for DECIMAL and DECIMAL64 columns, and a column without them is rejected so querying information_schema.ins_columns no longer crashes mnode.
 16. Decoding a transaction raw record now checks field lengths with an unsigned range, so an oversized length no longer wraps and makes mnode allocate a huge buffer and crash.
