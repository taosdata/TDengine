Release date: **2026-04-30**

| Release type | Recommended for |
| --- | --- |
| Maintenance release | Users of stream processing, virtual tables, taosX, timezone functions, or two replicas |

## 1. Highlights

- `TO_ISO8601` accepts timezones from `-14:00` to `+14:00`, including minute offsets.
- `TO_CHAR` and `TO_TIMESTAMP` add `TZ` for a full timezone. `TZH` still means the timezone hour.
- Virtual tables support `DECIMAL`.
- `INTERVAL` can split windows by the client timezone.
- `information_schema.ins_disk_usage` is added for viewing how table data is distributed.
- A table that is being subscribed can be dropped. After it is dropped and recreated, run `RELOAD TOPIC` to resume the subscription.

## 2. Features

- taosExplorer adds an XNode management page. Creating a taosX task with no available XNode guides the user to create one.
- taosX can import and export configuration files through taosExplorer. AVEVA Historian reconnects automatically after a disconnect.
- The Rust connector can subscribe to batch tag changes. Parameter binding supports `DECIMAL` and `BLOB`.
- taos shell adds `-H`. It is off by default. When it is on, `BINARY` values that contain non-printable characters are shown as `0x` hexadecimal.
- `TO_ISO8601` supports daylight-saving conversion.
- `ins_disk_usage` and `ins_security_policies` are added.
- `syncAssignedCheckAppliedGap` is added. When a node is assigned as the assigned leader under two replicas, it limits how far the follower's applied index may lag the commit index, so the follower does not enter restoring before it has caught up. The default is `20`. `0` means this check is off.
- Virtual tables support `DECIMAL` columns.
- A connector security development guide and examples are provided.

## 3. Enhancements

- When DataIn creates a super table and a data column is moved to a tag column, the default empty tag column is removed.
- Cross-origin handling in taosExplorer is tighter.
- Communication logs between taosX and `xnoded` are easier to read.
- SQLAlchemy support in the Python WebSocket connector is more complete.
- During `STMT2` writes, a child-table metadata change no longer returns an error that asks for a retry.
- `INTERVAL` splits windows by the timezone brought by the client.
- The return format of `SHOW TABLE DISTRIBUTED` is easier to read.
- Truncation is more reliable when the last WAL log file is damaged.
- A table that is being used by a subscription can be dropped.

## 4. Fixes

### 4.1 Severe issues

- Some functions crashed when they ran without `FROM`. Affected versions: all versions.
- A conversion expression such as `NOT (CAST(NULL AS VARBINARY) BETWEEN NOW() AND ts)` crashed. Affected versions: all versions.
- `GROUP_CONCAT` crashed and returned the wrong result. Affected versions: all versions. Queries that already used the result of this function need to be checked again.
- While replaying WAL, stream processing did not cap the number of sliding windows, so memory was exhausted and the process crashed. Affected versions: `v3.3.7.0` through `v3.4.1.0`.
- Using `DIFF` together with a notification in the outer stream query crashed. Affected versions: `v3.3.7.0` through `v3.4.1.0`.
- A stream query that used `%%tbname` released memory incorrectly under heavy writes and exhausted memory. Affected versions: `v3.3.7.0` through `v3.4.1.0`.
- Expired-data deletion conflicted with shared-storage migration. Shared storage was released in `v3.3.7.0`. Affected versions: `v3.3.7.0` through `v3.4.1.0`.
- When taosdump read data through WebSocket, a server failure returned empty data without an error, so the backup was missing data. Affected versions: all versions. Backups produced by an affected version need to be checked for completeness.
- During database compaction, if some nodes stayed offline for a long time, the mnode message queue could fill up and connections failed. Affected versions: all versions.

### 4.2 Stream processing, timezones, and tools

- In a nanosecond-precision database, creating a stream failed when an output-table tag used a fixed value.
- Writing the calculation result failed when the stream result table was an existing ordinary table.
- A count-window trigger used too much memory while reading historical data.
- When `CASE WHEN` filtered on the primary key, the execution plan did not match the actual execution.
- The `USE` prompt on macOS differed from Linux. It is now `Database changed.` on both.
- `queryTableNotExistAsEmpty` did not take effect through taosAdapter.
- `taos_cleanup` leaked memory on exit.
- The Windows installer could not stop processes cleanly. An `xnoded` child process on Windows could fail to stop.
- taosk used the wrong path while generating a key. taosdump slowed down while exporting a large number of child tables. Writing monitoring information to the log database failed.
- The column count of a virtual child table did not match the virtual super table.
- taosX: the backup point was abnormal when there was no data; a filter did not take effect; OPC ingestion failed on Windows when port 6051 was bound; Pulsar custom authentication had no parameter input; a Pulsar task stayed in creating when split was unsupported; Kafka used an auto-increment value by mistake for a composite primary-key timestamp; SparkPlugB gave no prompt and could not retry after pulling sample data failed.
- taosExplorer: the page loaded slowly when there were many write tasks; SQL elapsed time was inaccurate.

## 5. Security

### 5.1 Vulnerability fixes

None.

### 5.2 Hardening

- Cross-origin handling in taosExplorer is tighter.
- `SECURITY_LEVEL`, `SECURITY_POLICIES`, and the system table `ins_security_policies` are added.
- Connectors add a security development guide and examples.

## 6. Upgrade notes

### 6.1 Upgrade path

Direct upgrade, rolling upgrade, downgrade, and the minimum client version are not stated separately on this page.

### 6.2 Behavior changes

- The timezone accepted by `TO_ISO8601` expands from `-12:00` through `+12:00` to `-14:00` through `+14:00`, and minutes are supported. Offsets that used to report an error are now accepted, including offsets that do not exist in practice, such as `+08:01`.
- In `TO_CHAR` and `TO_TIMESTAMP`, `TZH` means the timezone hour. A full timezone uses `TZ`.
- The `USE` output on macOS changes to `Database changed.`.
- A table that is being subscribed can be dropped. The subscriber must run `RELOAD TOPIC` to continue after the table is recreated.
- `STMT2` no longer returns a retry error code when child-table metadata changes. Writes that retry on that error code need another check.

### 6.3 Configuration changes

| Parameter | Purpose |
| --- | --- |
| syncAssignedCheckAppliedGap | Under two replicas, when a node is the assigned leader, the allowed gap between the follower's applied index and the commit index. Default `20`. `0` means no check. |

### 6.4 Keyword changes

When one of these words is used as a database, table, super table, child table, column, or tag name, quote it with backticks regardless of case.

`SECURITY_LEVEL`, `SECURITY_POLICIES`.

### 6.5 System table changes

`information_schema.ins_disk_usage` is added for viewing how table data is distributed.

`information_schema.ins_security_policies` is added.

No system table is removed in this release.

### 6.6 Dependency changes

Dependency versions did not change.

### 6.7 Before you upgrade

An upgrade from `v3.3.6` cannot keep the old stream processing. See [Compatibility Notes](../../07-stream-processing/02-instructions.md#compatibility-notes).

A cluster that already runs the new stream processing on `v3.4.0.0` or later does not repeat those steps when it rolls to this release.
