Release date: **2026-01-03**

| Release type | Recommended for |
| --- | --- |
| Feature release | Users of stream processing, virtual tables, data subscription, privileges, or encryption |

## 1. Highlights

- Data transfer supports SASL and resource control. Data storage supports transparent encryption.
- Multi-factor authentication, several login security policies, RBAC privileges, and tiered audit are supported.
- `SM4_ENCRYPT`, `SM4_DECRYPT`, `AES_ENCRYPT`, `AES_DECRYPT`, digest, masking, and Base64 functions are added.
- Event windows in stream processing support child event windows. A window query can select only pseudo columns such as `_wstart` and `tbname`.
- JSON can be parsed and written into the database. taosExplorer supports OAuth 2.0 / OIDC. taosAdapter can be configured with SQL interception rules.
- The maximum number of columns on a virtual table is raised to 32767. `STMT2` can query virtual tables.

## 2. Features

### 2.1 Security and privileges

- Data transfer supports SASL and resource control. Data storage supports full transparent encryption and encryption-algorithm management.
- Multi-factor authentication and several login security policies are supported, including a policy for failed logins.
- An RBAC privilege model is supported, with tiered audit and privilege control.
- The audit log can record operations such as query and delete.
- Identity verification functions are added.
- `SM4_ENCRYPT`, `SM4_DECRYPT`, `AES_ENCRYPT`, `AES_DECRYPT`, `MD5`, `SHA`, `SHA1`, `SHA2`, `MASK_FULL`, `MASK_PARTIAL`, `MASK_NONE`, `FROM_BASE64`, and `TO_BASE64` are added.

### 2.2 Stream processing and query

- An event-window trigger in stream processing supports child event windows. An event window emits an open notification only when `true_for` is satisfied.
- Stream processing supports `INTERP` and `PERCENTILE`.
- A window query does not have to contain an aggregate. It can select only pseudo columns such as `_wstart` and `tbname`.
- A state window can name a zero state with `zeroth_state`. Windows in that state skip calculation and output.
- TDgpt supports row-correlation functions such as `DTW`, `DTW_PATH`, and `TLCC`.

### 2.3 Ingestion, connections, and installation

- JSON can be parsed and written into the database.
- taosX supports high availability and Kafka load balancing.
- taosAdapter can register and query instances. A connection carries the connector type and version. Custom SQL interception rules are supported.
- The C WebSocket connector supports extra TLS parameters.
- taosExplorer supports OAuth 2.0 / OIDC single sign-on.
- The Linux tar package can be installed by a non-root user, and the install path can be chosen.
- A Rust connector performance tool is added.

## 3. Enhancements

- The maximum number of columns on a virtual table is raised to 32767. Aggregate and selection queries on a virtual super table are faster.
- `WIN_OPTIMIZE_BATCH` and `WIN_OPTIMIZE_SINGLE` are added for state windows on virtual tables.
- `STMT2` can query virtual tables. Boolean values are checked on write.
- `COMPACT` supports `FORCE`.
- After a tag column changes, `RELOAD TOPIC` makes the subscription use the new tag. The topic does not have to be recreated. Updating a child-table tag returns immediately when the tag value did not change.
- `SHOW CONNECTIONS` adds the client version. `SHOW VGROUPS` adds `is_ready`.
- `ins_anodes_full` in TDgpt adds status and description, so model and algorithm status can be viewed.
- An execution plan can show a tag index.
- A global time zone reduces lock contention during concurrent time conversion for queries and writes.
- Stream processing uses less resource while reading trigger data and calculation data.
- Communication between cluster nodes checks the clock.
- When taosc cannot write the log directory, the initialization failure is reported more clearly.
- taosmqtt releases resources on exit. OPC DA collection and reconnect are more stable.
- A non-aggregate query can no longer be ordered by an aggregate function. `STATE_WINDOW`, `COUNT_WINDOW`, and `EVENT_WINDOW` on a super table cannot use duplicate timestamps.

## 4. Fixes

### 4.1 Severe issues

- Stream recalculation of trigger data did not use the latest WAL version, so the result was wrong. The new stream processing was released in `v3.3.7.0`. Affected versions: `v3.3.7.0` through the version before this release.
- `FILL_HISTORY` failed to calculate historical data. Affected versions: `v3.3.7.0` through the version before this release.
- After a stream read failed, later calculation tasks waited indefinitely. Affected versions: `v3.3.7.0` through the version before this release.
- Creating a table from a stream trigger crashed the process when the trigger carried no written data. Affected versions: `v3.3.7.0` through the version before this release.
- A stream subquery crashed when a correlated condition such as `tag == %%n` was used. Affected versions: `v3.3.7.0` through the version before this release.
- `STMT2` crashed when the auto-created table name was too long. `STMT2` was released in `v3.3.3.0`. Affected versions: `v3.3.3.0` through the version before this release.
- A `STMT2` query hung when both `dbname` and `tbname` were placeholders. Affected versions: `v3.3.3.0` through the version before this release.
- The callback was not invoked after a stmt query returned, and taosAdapter crashed. Affected versions: all versions.
- A query crashed when a virtual table referenced columns of the same name but different types in child tables. Virtual tables were released in `v3.3.6.0`. Affected versions: `v3.3.6.0` through the version before this release.
- The result was wrong when columns of several virtual tables used the same source column. Affected versions: `v3.3.6.0` through the version before this release.
- Querying a virtual super table reported Invalid value in client. Affected versions: `v3.3.6.0` through the version before this release.
- With the cache enabled, flushing a `DECIMAL` value of `NULL` crashed occasionally. Affected versions: all versions.
- `INSERT INTO ... SELECT` wrote rows to the wrong dnode and reported Vnode is closed. Affected versions: all versions.
- A nested query returned the wrong result in reverse order, with no order, or ordered by a key other than the primary timestamp. Affected versions: all versions.
- `STATE_WINDOW` used with `PARTITION BY` returned the wrong result. Affected versions: all versions.
- Loading data failed when upgrading from `v3.3.6.32` through `v3.3.6.36` to `v3.3.8.6` through `v3.3.8.10`.
- Query memory control could crash the process. Affected versions: all versions.

### 4.2 Query, subscription, and writes

- `ORDER BY ABS(col)` reported an error when `col` appeared in the result but not in the table.
- On a JSON tag, `SHOW CREATE TABLE` and `SELECT DISTINCT tbname, json_tag_name` did not return the expected result.
- The outer `COLS` of a nested query failed.
- When the child-table timestamp primary key in a `JOIN` was a constant, an extra sort is no longer added.
- Creating a stream counted backticks into an output-table tag name, so the table did not match one created by hand and the statement reported Out table tag type mismatch.
- When the stream result table already existed, schema and tag synchronization failed.
- A stream event notification sent over WebSocket could fail.
- A stream that used anomaly detection read the wrong data source.
- A concurrent problem occurred when a subscription ran at the same time as a tdb change. A rawdata subscription failed.
- A client could not see a table-schema change made by another client. A concurrent internal schema change during schemaless write failed.
- `tbname` was handled incorrectly in `INSERT INTO` a super table.
- `cache_load` in `ins_vgroups` was shown as a negative number when it exceeded the 32-bit integer limit.
- A transaction that modified a global variable could not finish.
- `taos_stmt2_get_fields` in the C WebSocket connector returned the wrong type. The Node.js connector did not set a time zone by default.

### 4.3 taosX and taosExplorer

- After an OPC UA task was modified, downloading point data failed. Writes became slow when there were many points.
- InfluxDB rows without tags could not be written. A PI or PI Backfill source whose name contained a period failed. Creating a PI task reported Not found model in DSN.
- The depth in a Kafka extract or split configuration was wrong. A column split did not match the expected result. A single message larger than 100 KB could make the SQL too long.
- A KingHistorian live subscription received no data. The AVEVA Historian write-task configuration page was abnormal.
- taosgen exited abnormally while importing a special CSV.
- taosExplorer login failed. An alert panel can be imported into Grafana 12. Explorer reports monitoring information by default.

## 6. Upgrade notes

### 6.1 Upgrade path

Direct upgrade, rolling upgrade, downgrade, and the minimum client version are not stated separately on this page.

### 6.2 Behavior changes

- taosX and taosX-Agent cannot keep an old configuration across the upgrade. Configure them again for the new version.
- The community edition and the enterprise edition cannot connect to each other.
- `SHOW TABLE DISTRIBUTED` does not support a virtual super table.
- The maximum number of columns on a virtual table is raised to 32767.
- `STATE_WINDOW`, `COUNT_WINDOW`, and `EVENT_WINDOW` on a super table no longer accept duplicate timestamps. A statement that uses duplicate timestamps fails.

### 6.4 Keyword changes

When one of these words is used as a database, table, super table, child table, column, or tag name, quote it with backticks regardless of case.

`ALGR_NAME`, `ALGR_TYPE`, `DB_KEY`, `ENCRYPT_STATUS`, `ENCRYPT_ALGORITHMS`, `ENCRYPT_ALGR`, `IS_AUDIT`, `OSSL_ALGR_NAME`, `RELOAD`, `ROLE`, `ROLES`, `SVR_KEY`, `TOKEN`, `TOKENS`, `DRAIN`, `REBALANCE`, `XNODE`, `XNODES`.

### 6.5 System table changes

`SHOW CONNECTIONS` adds the client version. `SHOW VGROUPS` adds `is_ready`. `ins_anodes_full` adds status and description fields.

No system table is removed in this release.

### 6.6 Dependency changes

| Component | Dependency | v3.3.8.8 | v3.4.0.0 |
| --- | --- | --- | --- |
| taosKeeper | driver-go | 3.7.1 | 3.7.8 |

### 6.7 Before you upgrade

An upgrade from `v3.3.6` cannot keep the old stream processing. If the old streams, TSMA, snode, and their data directories are not removed, taosd fails to start. See [Compatibility Notes](../../07-stream-processing/02-instructions.md#compatibility-notes).

When upgrading from a version before `v3.4` to this release, taosX does not migrate existing tasks automatically. Before `v3.4`, tasks were stored in SQLite. From `v3.4` on, they are stored in mnode. Export the tasks in taosExplorer before the upgrade, import them afterward, and start the tasks that should run. If the tasks were not exported before the upgrade, they do not appear in taosExplorer afterward. See [Migrate Tasks When Upgrading from a Version Before v3.4 to v3.4.x](../../12-operations-and-tooling/03-components/06-taosx.md#migrate-tasks-when-upgrading-from-a-version-before-v34-to-v34x).
