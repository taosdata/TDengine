Release date: **2026-04-01**

| Release type | Recommended for |
| --- | --- |
| Feature release | Users of subqueries, stream processing, virtual tables, data subscription, or privilege upgrades from `v3.3` |

## 1. Highlights

- External windows are supported. The time range comes from a subquery. Scalar subqueries are supported, as are `ANY`, `SOME`, `ALL`, `EXISTS`, and `NOT EXISTS`.
- `LAG`, `LEAD`, and `FILL_FORWARD` are added. `FILL` of `INTERVAL` and `INTERP` can set the interpolation time range.
- Stream processing can calculate on calendar weeks, months, quarters, and years, and can send a timeout notification when a source table has no new data.
- Child-table tags can be modified in batches. Virtual tables add reference checks.
- Data subscription supports token login and notices virtual-table metadata changes.
- taosX, TDgpt, and stream processing can run on Windows.

## 2. Features

### 2.1 Query

- [External windows](../../05-tdengine-sql/04-data-query/04-distinguished.md#external-window) are supported. The time range is set explicitly by a subquery.
- Non-correlated scalar subqueries are supported, as are scalar subqueries without `FROM`. `IN` can use a non-correlated subquery.
- `ANY`, `SOME`, `ALL`, `EXISTS`, and `NOT EXISTS` are supported.
- `LAG`, `LEAD`, and `FILL_FORWARD` are supported.
- `FILL` of `INTERVAL` and `INTERP` supports an interpolation time range. `FILL(PREV/NEXT/NEAR/LINEAR)` can fill the preceding and following non-NULL values.
- `BLOB` supports `CAST` and `SUBSTR`.
- Child-table tag values can be modified in batches.
- taosd adds a data-repair mode. `RESTORE DNODE` can specify `VGROUP ID`.
- TDgpt supports multivariate anomaly detection.

### 2.2 Stream processing and subscription

- Stream processing can calculate on a calendar week, month, quarter, or year.
- A timeout notification can be sent when a source child table or virtual child table has no new data for a long time.
- Stream processing supports `NODELAY_CREATE_SUBTABLE`. The result table can be created before any data is written.
- Stream processing supports multi-group batch calculation and batch deletion. A virtual-super-table trigger notices child-table creation and deletion, tag changes, and column-mapping changes.
- Stream subqueries support `IN`, `ANY`, `SOME`, `ALL`, `EXISTS`, and `NOT EXISTS`.
- Data subscription notices virtual-table metadata changes and supports token login.
- Go, Rust, and C WebSocket subscriptions support tokens. The Go REST connector supports `TOKEN`. taos shell can log in with a token.

### 2.3 Platform, privileges, and tools

- Windows supports taosX, TDgpt, and stream processing.
- taosX adds visibility privileges, plus system and object privileges. A pSpace data source from ForceControl is added. OPC-UA connectivity checks support failover. Kafka collection can write to several super tables by filter.
- Points can be updated automatically during KingHistorian synchronization. When the end time is empty, migration can continue.
- MQTT can be configured with several brokers.
- taosdump can import and export `DECIMAL` and `BLOB`, and can write with `STMT2`.
- taosgen supports Windows, and the log directory can be set in the configuration file.
- taosKeeper can export all current metrics.
- taosExplorer supports password login to obtain a token, TOTP, and Bearer Token. A session can renew itself. Login can require a verification code.

## 3. Enhancements

- Aggregate, `GROUP BY`, time-window, event-window, session-window, and state-window queries on a virtual super table are faster. Queries that reference many columns are faster. When creation fails, the mismatched column is named.
- Virtual tables check references against source tables, including saving the reference, checking source-table changes, querying the reference, and verifying availability. The limit on the number of source tables is removed. `WIN_OPTIMIZE_BATCH` and `WIN_OPTIMIZE_SINGLE` are removed.
- `LAST_ROW` queries are faster. The number of LRU shards can be adjusted at runtime to speed up `LAST`.
- Subscription is faster during interleaved writes.
- A subquery used as a primary-key filter is faster.
- `JOIN` and window joins can compute on the result of a selection function.
- `SHOW QUERIES` shows execution progress. `EXPLAIN ANALYZE` corrects operator elapsed time and adds operator metrics. Slow-query logs are reported sooner.
- SQL errors are clearer.
- root can change `PASSWORD_LIFE_TIME`, `PASSWORD_REUSE_TIME`, `PASSWORD_REUSE_MAX`, and `ALLOW_TOKEN_NUM`. The minimum password lifetime defaults to 1 day.
- When a subscription password is wrong, the error is Authentication failure, the same as a failed connection.
- A taosX backup still creates a backup point when fetching the offset fails. Custom OPC tag properties support character replacement.
- Explorer adjusts the data-source and Transform pages, the license page, the JSON rule input, and the activation-code display.
- The TDgpt server uses Gunicorn. The taos-ws example in the JDBC documentation sets `varcharAsString=true`.

## 4. Fixes

### 4.1 Severe issues

- An aggregate on a virtual table with `PARTITION BY` on a tag crashed. A parameter-bound query on a virtual table crashed. Querying a virtual super table crashed occasionally. Affected versions: `v3.3.6.0` through `v3.4.0.9`.
- A query failed when a virtual child-table column type did not match the mapped source table, usually after a same-name column was added or dropped. Affected versions: `v3.3.6.0` through `v3.4.0.9`.
- Querying the timestamp column and a data column of a virtual child table reported Planner slot key not found when the data column did not reference a source table. Affected versions: `v3.3.6.0` through `v3.4.0.9`.
- Querying a virtual super table reported Invalid value in client. Affected versions: `v3.3.6.0` through `v3.4.0.9`.
- A session window on a virtual super table returned the wrong result. Affected versions: `v3.3.6.0` through `v3.4.0.9`.
- `LAST` crashed while reading `BLOB`. Affected versions: all versions.
- Calling `TRIM` inside an expression or function crashed. Affected versions: all versions.
- `SAMPLE` could crash when the data volume exceeded the 32-bit integer range. Affected versions: all versions.
- Merging two aggregate queries with `UNION ALL` could crash. Affected versions: all versions.
- Comparing two tag columns and using an index crashed taosd. Affected versions: all versions.
- High concurrency of subscription and stream processing together crashed with very low probability. Affected versions: `v3.3.7.0` through `v3.4.0.9`.
- Stream `FILL_HISTORY` failed. Schema and tag synchronization failed when the result table already existed. Affected versions: `v3.3.7.0` through `v3.4.0.9`.
- A filter on a stream aggregate result did not take effect. A constant used as the start-time filter returned the wrong result. A result set that contained `JOIN` and was empty still produced output. Affected versions: `v3.3.7.0` through `v3.4.0.9`.
- Stream temporary files were not released, so disk usage kept growing. Affected versions: `v3.3.7.0` through `v3.4.0.9`. After the upgrade, new runs no longer keep accumulating; disk space that is already full still needs the temporary files cleaned up.
- Stream `SLIDING(0s)` was created successfully by mistake. Affected versions: `v3.3.7.0` through `v3.4.0.9`.
- When a subscription had no data for a long time, some vnodes stopped consuming. A rawdata subscription failed. Affected versions: all versions.
- After an upgrade from `v3.3.8` to `v3.4.0.0` or `v3.4.0.1`, and then to `v3.4.0.2` or later, some root operations reported insufficient privilege. Affected versions: `v3.4.0.0` through `v3.4.0.9`. Check root privileges after upgrading to this release.

### 4.2 Query, storage, and privileges

- The SQL shown in `ins_streams` was incomplete.
- `EXPLAIN` returned no result while parsing a subquery. `DROP TSMA IF EXISTS` did not take effect.
- With drop-table privilege, `DROP TABLE IF EXISTS db.not_exist_table` still reported insufficient privilege.
- A user with read-only `sysinfo` privilege who reads an unauthorized field gets an error, and no longer gets NULL. This matches `v3.3.8`.
- The dynamic modification range of `ssEnabled` was wrong. The default of `SS_CHUNKPAGES` did not take effect. `COMPACT` during a shared-storage upload reported Operation not supported.
- With every debug log enabled, the log volume kept taosd CPU high.
- In taos shell, a subquery with `LIMIT` no longer ignored the limit of showing only the first 100 rows.
- Generating a dmp file on Windows was abnormal.
- The TDgpt Docker image lacked gcc-related components, so PyTorch inference could not run.

### 4.3 taosX, taosdump, and taosExplorer

- taosdump did not include VGroups information when restoring a database.
- taosX: checkpoint lock contention when many CSV files were processed together; synchronizing `VARBINARY` / `BLOB` reported an error; migration-task status was unexpected when taosd was unhealthy; tasks did not migrate after taosX stopped; an XNode data-replication task could not enter the running state.
- Kafka array writes are unified as JSON. OPC-DA collection stopped occasionally, or points could not be enumerated.
- The taosX panel in TDinsight showed the wrong task information. A database could not be selected while importing a task. The error was unclear when a Parser parameter was too long. `SHOW XNODE TASKS` sorts by ID.
- taosExplorer: the preview did not match expectations when the write configuration was wrong; an error was reported after a split rule was deleted; an error was reported when subscription privilege was left empty; task filtering dropped field values; some requests failed when the password contained special characters; changing `xor_allowed_duration_secs` had no effect; reverse proxy with a relative path is supported; a data-replication task reported Bad Request.

## 5. Security

### 5.1 Vulnerability fixes

- taosExplorer fixes one SQL injection. The work item has no vulnerability ID or CVE number.
- See the [security advisories](https://docs.taosdata.com/security-guide/security-advisories/).

### 5.2 Hardening

- Protection against SQL injection, denial of service, and overflow is added. Sensitive data is overwritten after deletion.
- taosAdapter and taosKeeper add `readHeaderTimeout`, default 10 seconds, to reduce the chance that a slow request holds a connection.
- The C and Rust WebSocket connectors are hardened.
- `enableAdvancedSecurity` is added. When the advanced-security compile option is off, the default is `0`: password expiration, strong passwords, and password rotation are off, and the default password is allowed. The default behavior matches `v3.3`. When the advanced-security compile option is on, the default is `1`.
- `enableGrantLegacySyntax` is added. When it is `1`, the `v3.4` grant syntax is compatible with `v3.3`.
- `forceReadConfig` is removed.

## 6. Upgrade notes

### 6.1 Upgrade path

Direct upgrade, rolling upgrade, downgrade, and the minimum client version are not stated separately on this page.

### 6.2 Behavior changes

- When the cluster is not licensed, a machine-code change no longer triggers repeated checks. The license state stays ungranted.
- When counting licensed measurement points, child tables of known system super tables in the log database and the audit database are excluded. Another 1000 measurement points are reserved and used only when deciding whether the license is exceeded. `SHOW GRANTS` still shows the actual measurement-point count. Virtual tables are not counted. If the log database or the audit database already exists, the upgrade does not recount measurement points automatically. To correct the count, set `vndStats.timeseries` in the vnode's `vnode.json` to 0 and restart. Do not change `vndStats.ntimeseries`.
- A comparison that includes `NULL` returns NULL. The NULL comparison rules inside `IN` / `NOT IN` have changed, so existing statements may return a different result.
- The community edition and the enterprise edition cannot connect to each other.
- A user with read-only `sysinfo` privilege who reads an unauthorized field gets an error, and no longer gets NULL.
- taosdump includes VGroups information when restoring a database, so the restored database may have different VGroups from an older backup.
- root can change the password lifetime, reuse count, and allowed token count. The minimum password lifetime is 1 day.
- From `v3.3.7.0` through `v3.4.0.9`, do not change `ssEnabled` with `ALTER DNODES`.
- From `v3.3.8.20` through `v3.3.8.22`, and from `v3.4.0.10` through `v3.4.0.14`, the default `SS_CHUNKPAGES` of a new database is not the split that corresponds to 512 MB. If S3 may be used later, set it explicitly when creating the database, for example `CREATE DATABASE d1 SS_CHUNKPAGES 131072`. Existing databases are unchanged.

### 6.3 Configuration changes

| Parameter | Purpose |
| --- | --- |
| enableAdvancedSecurity | Whether password expiration, strong passwords, and password rotation are enabled. The default is `0` when the advanced-security compile option is off. |
| enableGrantLegacySyntax | When it is `1`, grant syntax is compatible with `v3.3`. |
| auditSaveInSelf | When enabled, audit information no longer goes through taosKeeper, and creating the audit database also creates the operations super table. The default is on when the advanced-security compile option is on. |
| tmqWriteRefDB | Whether a subscription writes reference-database data. |
| tmqWriteCheckRef | Whether a subscription checks references on write. |
| readHeaderTimeout | Timeout for taosAdapter and taosKeeper to read a request header. Default 10 seconds. |

`forceReadConfig` is removed. Hints `WIN_OPTIMIZE_BATCH` and `WIN_OPTIMIZE_SINGLE` are removed.

### 6.4 Keyword changes

When one of these words is used as a database, table, super table, child table, column, or tag name, quote it with backticks regardless of case.

`ANY`, `SOME`, `EXTERNAL_WINDOW`, `CACHESHARDBITS`.

### 6.5 System table changes

`SHOW QUERIES` adds query progress.

No system table is removed in this release.

### 6.6 Dependency changes

Dependency versions did not change.

### 6.7 Before you upgrade

An upgrade from `v3.3.6` cannot keep the old stream processing. See [Compatibility Notes](../../07-stream-processing/02-instructions.md#compatibility-notes). A cluster that already runs the new stream processing on `v3.4.0.0` or later does not repeat those steps when it rolls to this release.

When upgrading from a version before `v3.4` to this release, taosX does not migrate existing tasks automatically. Before `v3.4`, tasks were stored in SQLite. From `v3.4` on, they are stored in mnode. Export the tasks in taosExplorer before the upgrade, import them afterward, and start the tasks that should run. If the tasks were not exported before the upgrade, they do not appear in taosExplorer afterward. See [Migrate Tasks When Upgrading from a Version Before v3.4 to v3.4.x](../../12-operations-and-tooling/03-components/06-taosx.md#migrate-tasks-when-upgrading-from-a-version-before-v34-to-v34x). A cluster already running on `v3.4.0.0` or later, with tasks stored in mnode, does not need to repeat those steps when rolling to this release.
