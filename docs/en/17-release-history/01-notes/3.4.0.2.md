Release date: **2026-02-02**

| Release type | Recommended for |
| --- | --- |
| Maintenance release | Users of XNode, stream processing, or virtual tables, and users upgrading privileges or encryption from `v3.3` |

## 1. Highlights

- An XNode is created during initialization. taosX-Agent works with XNode high availability.
- taosX can import Parquet files.
- The Rust native connection supports `STMT2`.
- For event windows and state windows in stream processing and batch queries, `true_for` supports both a duration and a row count.
- `LAG` is renamed to `FILL_FORWARD`. Existing SQL must be renamed.
- root must change the password after login when the default password is still in use. `allowDefaultPassword` keeps the old behavior.

## 2. Features

- An XNode is created when the service is initialized. taosX-Agent works with XNode high availability. An XNode task adds `created_by` and `labels`.
- taosX can import Parquet. An MQTT topic can use any character.
- taosAdapter records SQL for STMT. The Rust native connection supports `STMT2`. `INTERVAL` in a STMT query can be bound as a parameter.
- `true_for` of an event window and a state window can test both a duration and a row count.
- `CREATE TOTP_SECRET` creates a TOTP secret.
- The taosExplorer license page shows the machine code so it can be copied.
- IPv4 and IPv6 are supported at the same time.

## 3. Enhancements

- SQL error messages are clearer.
- Login requires root to change the password when the default password is still in use.
- Notifications related to user tokens are added. The expiration time and expiration policy of a data-encryption key can be updated.
- A cluster that already uses data encryption can be upgraded from an older version. Encryption covers files such as bse. After encryption takes effect, changing the configuration file can no longer bypass it.
- Privilege compatibility from `v3.3` to `v3.4` is handled, and privilege control for views and audit is completed. A user can change privilege control.
- A notification from a scheduled stream trigger adds the start time and end time. The field names remain `windowStart` and `windowEnd`.
- In a stream query, a placeholder such as `_twstart` can appear in `ORDER BY`. The delay of a virtual-table tag filter is lower.
- The upper limit of source tables a virtual table can reference is changed from 1000 to 2000. `COLS` and `LAST` are faster when only one source table is referenced.

## 4. Fixes

### 4.1 Severe issues

- After an mnode leader change, stream heartbeat handling crashed the process. Affected versions: `v3.4.0.0`.
- The `xnoded` shutdown path could leave `taosd` stuck while stopping. XNode was released in `v3.4.0.0`. Affected versions: `v3.4.0.0`.
- When a state window processed several groups, a group whose window was entirely `NULL` produced the wrong result. Affected versions: all versions.
- After a stream result child table was dropped and recreated, the calculation result was wrong. Affected versions: `v3.3.7.0` through `v3.4.0.0`.
- `true_for` used the wrong trigger logic when out-of-order rows were written. Affected versions: `v3.3.7.0` through `v3.4.0.0`.
- A stream that called `CONCAT` returned the wrong result. Affected versions: `v3.3.7.0` through `v3.4.0.0`.
- A client could crash when many STMT writes ran concurrently. Affected versions: all versions.
- Using `GROUP_CONCAT` with `COUNT_WINDOW` crashed the process. Affected versions: all versions.
- `SHOW CREATE TABLE` of a virtual table returned the wrong result. Affected versions: `v3.3.6.0` through `v3.4.0.0`.

### 4.2 Query, privileges, and other issues

- A `JOIN` whose subquery had no `FROM` returned an error.
- `LIMIT` on the outermost correlated query did not take effect when there was no `ORDER BY`.
- The scheduled time of a multi-level storage migration was inaccurate.
- The default duration of the password-reuse limit was wrong.
- After a user was deleted, a subscription that user had created could not be cancelled.
- Memory leaked when UDF initialization failed. Duplicate error details are removed.
- An InfluxDB migration hit a null pointer in a special case. A backslash in a migration statement was treated as invalid syntax.
- taosKeeper did not accept a password that contained special characters.
- Collecting AVEVA Historian as a migration failed. A MySQL task could block when there was very little data.
- Creating an OPC data-source task reported an error. The TMQ error text on the taosX native interface was incompatible.
- Setting user privileges in taosExplorer of `v3.4.0.0` failed.

## 5. Security

### 5.1 Vulnerability fixes

None.

### 5.2 Hardening

- root must change the password after login when the default password is still in use. `allowDefaultPassword` can allow the default password on the first start.
- The expiration time and expiration policy of a data-encryption key can be set. After encryption takes effect, changing the configuration file can no longer change the encryption state.

## 6. Upgrade notes

### 6.1 Upgrade path

Direct upgrade, rolling upgrade, downgrade, and the minimum client version are not stated separately on this page.

### 6.2 Behavior changes

- `LAG` is renamed to `FILL_FORWARD`. The arguments and behavior are unchanged. Existing statements must change `LAG` to `FILL_FORWARD`.
- `allowDefaultPassword` takes effect only the first time the server starts. When it is `1`, the default user can use the default password. Otherwise the default user must change the password after login.

### 6.3 Configuration changes

| Parameter | Purpose |
| --- | --- |
| allowDefaultPassword | Effective only on the first start. When it is `1`, the default user can use the default password. Otherwise the password must be changed after login. |

### 6.4 Keyword changes

None.

### 6.5 System table changes

None.

### 6.6 Dependency changes

Dependency versions did not change.

### 6.7 Before you upgrade

An upgrade from `v3.3.6` cannot keep the old stream processing. If the old streams, TSMA, snode, and their data directories are not removed, taosd fails to start. See [Compatibility Notes](../../07-stream-processing/02-instructions.md#compatibility-notes).

A cluster that already runs the new stream processing on `v3.4.0.0` does not repeat those steps when it rolls to this release.
