## Introduction

This section describes how to integrate S3 with TDengine Enterprise. The current implementation is based on the generic S3 SDK, which is compatible with the parameters of most S3 platforms, and can access object storage services such as minio, Tencent Cloud COS, Amazon S3 and so on. With appropriate parameter configuration, most cold time-series data can be stored in the S3 service.

## Configuration

The S3 object storage is configured like the following  (in the configuration file /etc/taos/taos.cfg):

```
s3EndPoint   http://cos.ap-beijing.myqcloud.com
s3AccessKey  AKIDsQmwsfKxTo2A6nGVXZN0UlofKn6JRRSJ:lIdoy99ygEacU7iHfogaN2Xq0yumSm1E
s3BucketName test0711-1309024725
```

- s3EndPoint: domain name of the user's region, supports http and https, the bucket's zone needs to be the same as the endpoint's, otherwise it can't be accessed.
- s3AccessKey: colon-separated user's SecretId:SecretKey.
- s3BucketName: bucket name, followed by a minus sign is the AppId registered for COS service. AppId is unique to COS, not available in AWS and Aliyun, and needs to be part of the bucket name when configuring, separated by a minus sign. The parameter values are all of string type, but do not require quotes.

In the configuration file, you can also set parameters such as data upload delay time and cache size. For example, you can use the following configuration:

```
s3UploadDelaySec     60
s3PageCacheSize      4096
s3MigrateIntervalSec 3600
s3MigrateEnabled     1
```

- s3UploadDelaySec: seconds after which data files will be uploaded to s3 if no more touched, unit: second. Minimum: 1; maximum: 2592000 (30 days).
- s3PageCacheSize: number of pages in s3 page cache, unit: page. Minimum: 4; Maximum: 1024*1024\*1024.
- s3MigrateIntervalSec: period for trigger data uploading to S3, unit: second. Minimum value: 600; Maximum value: 100000.
- s3MigrateEnabled: whether to enable automatic S3 migration. Default value is 1. Can be configured as 0 to disable it.

### Configuration Parameters Checking

You can check the correctness of the configured parameters by using the `checks3` parameter of the `taosd` command:

```
css
Copy code
taosd --checks3
```

If the configured S3 service is inaccessible, this command will output the corresponding error messages during runtime.

### Creating Databases that Utilize S3

After completing the configuration, you can start the TDengine cluster and create databases that utilize S3. For example:

```
taos> create database demo_db duration 1d s3_keeplocal 3d;
Create OK, 0 row(s) affected (1.232775s)
```

In the `demo_db` database, time-series data written will automatically be chunked and stored in S3 three days after being retained locally.

By default, the `mnode` issues S3 data migration check commands every hour. If time-series data needs to be uploaded, it will be automatically chunked and stored in S3. Users can also manually trigger this operation using the SQL command, as follows:

```
s3migrate database <db_name>;
```

The detailed database options are shown in the table below:

| #    | Parameter    | Default Value | Minimum Value | Maximum Value | Description                                                  |
| ---- | ------------ | ------------- | ------------- | ------------- | :----------------------------------------------------------- |
| 1    | s3_keeplocal | 3650          | 1             | 365000        | Number of days the data is retained locally, i.e., how long data files remain on local disk before being uploaded to S3. Default unit: days, supports three units: m (minutes), h (hours), and d (days). |
| 2    | s3_chunksize | 262144        | 131072        | 1048576       | Threshold size for uploading objects, same as the `TSDB_PAGESIZE` option, cannot be modified, unit is TSDB page. |
| 3    | s3_compact   | 0             | 0             | 1             | Whether to automatically perform a compact operation when the TSDB file group is first uploaded to S3. |
