发布时间：**2026-11-02**

## 特性

  1. Linux 上可以联邦查询 Oracle，外部表和虚拟表外部源都支持。
  2. OPC DA 点位任务支持 PI 兼容的质量码和数字状态映射，并可用迁移工具把 PI 归档复刻到 PI 服务器，再按 OPC DA 回放并映射到已有 TDengine 表。
  3. SHOW CREATE TABLE、STABLE、VTABLE 和 RSMA 支持 FULL，用 BLOB 返回完整建表语句，不再按 65535 字节截断。
  4. Windows 上可以联邦查询 MySQL、PostgreSQL 和 InfluxDB，外部表和虚拟表外部源都支持。
  5. Windows 上可以联邦查询 SQL Server，外部表和虚拟表外部源都支持。
  6. feat: TDgpt 新增 PCA 主成分分析、PLS 偏最小二乘与聚类分析（KMeans/DBSCAN/GMM）能力。
  7. feat: 新增端口声明一致性审查门禁：解析计划文档端口表并静态扫描代码，发现未声明端口或文档语义冲突时阻断 MR 并推送飞书告警。
  8. taosExplorer 可将 Neuron 或 NeuronEX 采集的数据经 eKuiper 写入 TDengine，并在数据写入的数据采集代理中完成接入、刷新和监控。
  9. taosExplorer 和 taosX 支持接入 Kepware Server 7.1，可扫描 OPC UA 点位，并以订阅或轮询写入选定数据库。
 10. taosX 节点故障后，Agent 先确认旧任务已经退出，再由接管节点启动同一任务，过期的启动、停止和取消不能把任务抢回去。
 11. 支持在 native 客户端公开 API 边界录制连接、SQL、STMT 与 schemaless 调用时序，并可通过 taosreplay 按原连接和线程节奏回放，用于复现并发问题。
 12. 新增聚合函数 BIT_DURATION，统计整型或布尔测点按位掩码处于指定状态的持续时长，并支持窗口与流计算。
 13. 流计算支持 SQL Server 外部源，虚拟表可引用其列并与本地列混合计算，短引用与显式 database/schema 引用指向同一远端表，动态重绑定后保留已完成窗口的结果。
 14. 流计算通知的每个事件增加 triggerTableName，按 PARTITION BY tbname 分组时为不带库名前缀的触发子表名，虚拟子表使用虚拟子表名，其余情况为空字符串。
 15. 联邦查询可将本地部署的 SQL Server 2019 和 2022 登记为外部数据源，查询其表和视图，并在虚拟表中引用。
 16. 自部署 taosExplorer 的 SQL 编辑器可设置本次执行的前端超时，默认 60 秒，范围为 1 至 3600 秒，请求超时会显示黄色警告，且不取消服务端仍在执行的查询。
 17. 订阅新增参数 msg.consume.start.ts，表订阅和库订阅可按主键时间只消费不早于该 Unix 毫秒时间戳的数据，默认 0 表示不过滤。

## 优化

  1. Explorer 浏览器标签页改用与官方文档一致的 favicon.ico。
  2. XNode 异常或 Agent 重连后，自动恢复仍应继续运行的 Agent 任务。
  3. libtaos.so 不再依赖 libtaosnative.so，只使用 WebSocket 时也可以单独加载客户端。
  4. taosExplorer 不再内置用户手册，中文和英文手册分别安装。未安装对应语言手册时，帮助入口打开官网，不再返回 404。
  5. taosX 的数据源插件改为单独安装。主机没有对应插件时不能在该主机运行该数据源任务，taosExplorer 仍列出该数据源，并提示缺少的插件和安装包。
  6. 列数很大的虚拟表在建表和查询时按列号定位引用列，不再因逐列反复扫描而长时间停留在 SQL 分析阶段。
  7. 区间查询的分组键只是表名或单个标签时，扫描块只保留一份分组键，不再逐行复制，查询结果不变。热缓存 Debug 对照中，400 张长表名子表共 2400 万行从 0.711 秒降到 0.160 秒，100 张子表共 1000 万行的长 VARCHAR 标签从 0.362 秒降到 0.0678 秒。
  8. 单表标签上的 SUM、AVG、COUNT 以及按标签分区的 INTERVAL 查询执行更快，超级表上同时带 INTERVAL 和 LIMIT 的查询可使用 INTERVAL_LIMIT() 提示减少扫描。
  9. 提升多数 BLOB 列查询的性能，使满足条件的 count(blob) 重新使用块级预计算结果；部分中等长度 select blob 可能变慢，内存占用也会增加。
 10. 支持通过 SQL 修改 xnodeDsnProtection、xnodeDsnPublicKeyFile 和 xnodedDsnPrivateKeyFile，修改结果持久化保存，重启 taosd 后生效。
 11. 查询 information_schema.ins_databases 时，未请求 ntables 不再全量扫描 vgroup。
 12. 查询 information_schema.ins_tables 并用 table_name 等值或 IN 过滤时，按表名索引定位目标表，不再扫描 vnode 中的全部表。
 13. 查询和流计算遍历节点列表改为顺序前进，节点很多时开销从按节点数平方增长降为线性。16000 个节点的参数改写从约 232 毫秒降到约 0.21 毫秒。
 14. 流计算从外部表取计算数据时按计算语句的时间表达式确定范围，窗口连接只裁剪引用该时间列的一侧，到期的 PERIOD 窗口不再被空闲节流跳过。
 15. 联邦查询已用 PostgreSQL 18.6 做测试验证，支持范围仍是 14 及以上。
 16. 降低虚拟超级表查询时，客户端保存列引用和标签引用的内存占用。

## 修复

  1. 0 级挂载多块磁盘时，WAL 保留策略与回滚未删除非主挂载盘上的 WAL 文件，导致磁盘空间持续增长的问题。
  2. BALANCE VGROUP LEADER 未能把某个 vgroup 加入平衡事务时，会记录该 vgroup、数据库和失败原因。
  3. C/C++ 客户端使用 STMT2 参数绑定写入时不再泄漏内存；固定表且未开启 interlace 时，执行失败后的下一次成功写入仍保留已绑定的固定标签。
  4. InfluxDB 连接器在读线程启动前退出，迁移任务被报为成功但实际没有写入数据的问题。
  5. ONLY META 或 WITH META 的超级表订阅在元数据快照中按 WHERE 条件过滤子表，指定子表名时不再把全部子表的建表事件推给消费者。
  6. OPC DA 采集的固定长度字符串默认只保留首个 NUL 之前的内容，不再把 NUL 及其后的字符写入 TDengine。
  7. Rust WebSocket 文档示例在 tokio 1.54 及以上版本创建数据库时因零容量缓冲区断言而 panic 的问题。
  8. SQL Server 停服后，联邦查询按配置的连接超时返回失败，不再被驱动内部重试拖过这个时间。
  9. Windows 上 taosd、taosAdapter、taosKeeper、taosX 和 taosExplorer 异常退出后，会按 10 秒、30 秒、90 秒、180 秒和 300 秒自动重启，最多五次，之后不再自动重启。
 10. Windows 创建或重启 XNODE 时，xnoded 就绪探测的单次超时由 100 毫秒改为 3 秒，避免服务已启动仍被判为不可访问并被停止。
 11. fix: 修复 TDgpt 模型在运行中因容器重启或 worker 被 kill 后 model_state 卡死在 started、加载模型接口持续 500 的问题；启动时与请求前会按实际进程/已安装文件自动校正状态，无需再手工改库恢复。
 12. last() 分组查询因扫描块空值标志未复位而变慢，并把每条查询的 reader timing 日志从 INFO 降为 DEBUG。
 13. schemaless 在超级表已存在时再次创建，不能再修改已有列和标签的类型、缩短其宽度或删除它们；taosX 同样不能改类型或缩短宽度，但仍可删除列和标签以回放跨集群复制。
 14. taosExplorer 使用 pSpace 数据源写入时，点位列表为空会弹出无文字的错误提示；Chrome、Edge 86 上任务运行后的指标弹窗还会偏移且无法滚动。
 15. taosX 写入每批 Point 数据前都会查询目标库的 KEEP 和 precision，导致 taosd 元数据查询堆积并偶发变慢。现按任务缓存该结果，默认 1 小时内复用。
 16. taosd 启动较慢时，流心跳不再在消息回调注册前发出，启动过程不再因此崩溃。
 17. taosdump 导入 AVRO 时，表结构预检查不再把刚创建的表误报为不存在，创建数据库失败会中止后续导入，子表创建也会显示进度。
 18. taosdump 导入时因建表语句被截断而报 Row length exceeds max length 的问题。备份改为使用 SHOW CREATE ... FULL，完整保留超长建表语句。
 19. taosdump 导出列数很多的虚拟表时，因 SHOW CREATE 被截断而漏表的问题。备份改为使用 SHOW CREATE ... FULL，完整保留建表语句。
 20. 不含 BLOB 列的查询不再逐行检查 BLOB 长度，避免 16 MB BLOB 支持拖慢普通表的大数据量读取。
 21. 两侧已按主键时间有序、另有普通列或标签等值条件的普通 Inner Join，默认改回 Merge Join，不再因附加等值条件改走 Hash Join。
 22. 以虚拟表为数据源的流计算，在引用 TAG 为空、短于类型头，或定长 TAG 为 NULL 时，不再因此中断分组，结果表可以继续产出。
 23. 仲裁器指派 vnode leader 时始终校验成员令牌，force 不能再跳过校验，未通过校验的请求不能把 vnode 设为指定 leader。
 24. 修复 3.4.3.5 在重启时无法读取 3.4.3.0 至 3.4.3.4 写出的流 checkpoint、报 Invalid message 并进入 failed 的问题。
 25. 修复 DECIMAL 转为 VARCHAR、BINARY 或 BLOB 时，目标宽度不足以容纳完整文本而越界读取内存的问题。
 26. 修复 IDMP 在短时间产生大量事件时按 UID 反复查询 information_schema.ins_tables 获取虚拟子表名，导致 taosd 资源被打满的问题。
 27. 修复 taosX OPC UA 采集在订阅失败、重连或任务退出时未关闭会话，导致会话累积、后续连接被拒绝且任务反复启动失败的问题。
 28. 修复 taosX-opc 异常退出并重启后，监控指标上报或 OPC DA 初始连接阻塞导致任务一直处于 running、没有数据写入的问题。
 29. 修复以虚拟超级表为源的流在解析标签引用时，重复向 mnode 获取库路由并展开无用列引用，导致元数据请求过多和内存升高的问题。
 30. 修复流计算只使用虚拟表部分列时，改绑未使用列仍补充计算 Reader 并引发不必要重试的问题，参与计算或出现在 WHERE 中的列改绑仍会按需部署。
 31. 修复流计算读取虚拟子表直接添加的数据列时引用缺失、结果为空或为 NULL 的问题，未使用的自有源表删除后不再导致继承列计算失败。
 32. 修复流重启或重新部署后，读取位置对应的 WAL 已被回收时反复报 WAL log does not exist 并重新部署、持续无输出的问题，改为从仍保留的 WAL 继续处理。
 33. 修复监控指标标签值含逗号、等号、引号或大括号时，taoskeeper 报告格式化导致 taosd 崩溃的问题，这些字符在写出标签时替换为下划线。
 34. 修复经 taosX Agent 执行的任务在 Agent 尚未连上时启动失败后一直停在排队中、Agent 恢复连接后也不会自动启动的问题。
 35. 修复虚拟表 TAG 使用引用写法时，流任务设置 PRE_FILTER 后源表清单被全部裁剪、流状态 RUNNING 但不出数的问题。
 36. 修复虚拟表在 ORDER BY ts 且带 LIMIT 时未下推排序方向和行数上限，从而全量扫描并额外排序，导致查询变慢、taosd 资源占用高的问题。
 37. 修复虚拟表流在历史计算中过滤后没有数据行时，条件比较空指针导致 taosd 崩溃的问题。
 38. 修复虚拟表流在运行时虚拟表变更后反复重试虚拟表补丁、trigger 卡死并报 Invalid parameters 的问题。
 39. 修复虚拟表流开启 NODELAY_CREATE_SUBTABLE 时，初始化响应交错导致 Retry needed 或 Internal error 并停流的问题，结果子表仍会提前创建。
 40. 修正用户手册中 FIRST、LAST 对非主键时间戳描述不清晰的问题，明确二者按有效时间线取值，不等价于按参数列 ORDER BY ... LIMIT 1。
 41. 修正用户手册对行、列权限生效规则描述不清晰的问题，明确用户和角色同时拥有同一类型权限时优先使用用户权限，用户未设置时多个角色取更新时间较晚的权限。
 42. 分配 TDB 空闲页时先改写页面再写入回滚日志，意外重启后空闲页链被写坏，再次分配时 taosd 因非法页号退出。
 43. 创建未配置 FILL_HISTORY 的虚拟表流后，Trigger 线程因立即初始化历史上下文并按分组全量匹配虚拟表而 CPU 占满的问题。
 44. 加密备份写满一个加密块后没有清空缓冲长度，后续写入可能重复输出旧数据，恢复时报 Invalid message。
 45. 升级 taosX 的 zstd-sys 至 2.1.2，并回补 zstd-safe 5.0.2/7.2.4 的 RUSTSEC-2026-0403 修复。
 46. 单起始条件的 EVENT_WINDOW 配置 TRUE_FOR 后，历史窗口尚未关闭但时长已满足时，也会发送历史 OPEN 通知。
 47. 对不存在的 vgroup_id 执行 SPLIT VGROUP 时不再返回成功，而是报 vgroup 不存在。
 48. 将未显式设置的订阅参数 session.timeout.ms 默认值从 12 秒提高到 45 秒，避免心跳处理延迟时消费者被移出消费组而无法继续消费。
 49. 带仲裁的双副本库执行 SPLIT 后，SHOW ARBGROUPS 去掉被拆分 vgroup 的仲裁组，并为拆出的两个 vgroup 各建一个新的仲裁组。
 50. 开启 DEBUG 日志时，标量计算不再为每个列参数写高频调试日志，避免 JOIN 查询因日志量过大而明显变慢。
 51. 开启监控协议日志时，taosd 按内容大小估算多行 JSON 的行数，日志文件会按 numOfLogLines 正常切换并压缩。
 52. 快照恢复 vnode（包括 REDISTRIBUTE VGROUP）会按文件时间和 KEEP 配置选择存储级别，不再把数据全部写到 0 级目录。
 53. 按表名查询 information_schema.ins_tags 时直接读取该子表的标签，库名、超级表名和表名上的等值条件也会提前筛选，子表很多时不再遍历全部元数据。
 54. 日志文件已可写但无法把权限改为 0666 时，taosd 和 taos 不再因此启动失败，而是沿用现有权限并给出警告。
 55. 显式事务中 CREATE STREAM 新建输出超级表或 NODELAY 普通表时，语句成功返回后当前事务即可看到该表。
 56. 查询计划解码时复用已解析的时区句柄，修复重复加载时区数据导致的查询性能回退。
 57. 流被删除后用同名重建时，过期的部署动作不再继续占用部署状态；部署失败和计算任务卸载时也会释放尚未完成的管理状态，避免 taosd 内存持续增长。
 58. 流计算任务销毁时先释放数据缓存、再释放仍在使用的读取迭代器，taosd 在关闭阶段访问已释放内存。
 59. 流计算使用 %%trows 且窗口含变长列时，taosd 不再因行序与写入顺序不一致而越界崩溃。
 60. 流计算使用独立 SLIDING 并设置 IGNORE_NODATA_TRIGGER 时，大段时间空档会逐个生成空窗口，同组和其他分组的结果被推迟。
 61. 流计算分组窗口聚合时，部分分组在某些 vgroup 没有有效输入但仍产生空结果，输出顺序错乱，流任务进入 Failed。
 62. 流计算外部数据源（联邦查询）外部拉取请求句柄在响应被丢弃时未释放导致的内存泄漏。
 63. 流计算实时进度推进且自动重算队列为空后，再删除数据且没有后续写入时，删除重算一直挂起、结果表缺行的问题。
 64. 消费者退订与再均衡提交交错时，过期的再均衡结果不再把消费者改回就绪，刚退订的主题可以立即删除，不再持续报已被订阅。
 65. 状态窗口流的外层过滤条件会在结果写入前生效，不满足条件的窗口不再输出；历史回填结束时，未达到 TRUE_FOR 时长的尾窗也不再触发计算。
 66. 虚拟表 SERIES 的 ALTER 语句解析结束后未释放别名、外部源名称和标签条件，重复执行会持续占用客户端内存。
 67. 虚拟表列改绑后，流计算重新部署若在 60 秒内没有完成，不再无限重试，而是返回明确错误并使流进入 Failed。
 68. 虚拟表列比源列窄时，UNION 和 UNION ALL 按较宽的列输出，不再报输入无效。
 69. 虚拟超级表按源表标签分组聚合，且时间条件可下推时，客户端崩溃的问题。
 70. 超级表上按子表分组的 last_row 查询不再等全部缓存扫描完成才输出，子表很多时查询更快。
 71. 超级表心跳响应或表元数据解码失败时释放已经解析的部分数据，这条异常路径不再泄漏内存。
 72. 非 Windows 平台从源码构建 Arrow 时，内置 Thrift 可能选中不兼容的 OpenSSL 4，导致 macOS 编译失败；现在固定使用项目自带的 OpenSSL 3.1.3。

## 安全

  1. DROP XNODE JOB 和 REBALANCE XNODE JOB 的 WHERE 条件会检查表达式形状，空值或缺少操作数的条件会被拒绝，不再导致 mnode 崩溃。
  2. JSON 标签索引遇到超长列名时拒绝这次索引过滤，嵌套条件共用的过滤结果也只释放一次。
  3. Node.js 连接器将开发依赖 brace-expansion 固定到已修复版本，避免 `{a},b}` 形式展开的平方级耗时造成拒绝服务；该依赖不随发布的连接器包分发（CVE-2026-102277, GHSA-q2hr-2g5m-vwhr）。
  4. SHOW VARIABLES 不再返回对象存储访问串等敏感配置。
  5. TMQ 客户端解码 ask-ep 响应时校验字段长度和剩余报文，拒绝超长 topic、数据库名和 FQDN，修复恶意服务端导致的客户端栈溢出（CWE-121）。
  6. dnode 拒绝非法管理消息和伪造的响应，超出动态范围的配置不再被应用，对象存储访问串也不再出现在配置输出中。
  7. mnode 应用已提交的元数据记录时会校验记录头的长度和类型，长度越界或绕过事务的直接写入会被拒绝。
  8. mnode 转发监控统计前会确认所声称的用户存在，并拒绝非法 JSON，未通过校验的内容不再发给 taoskeeper。
