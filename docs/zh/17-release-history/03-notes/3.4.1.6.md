## 1. 版本亮点

- `TO_ISO8601` 接受 `-14:00` 至 `+14:00` 的时区，并支持分钟偏移。
- `TO_CHAR`、`TO_TIMESTAMP` 增加 `TZ`，用于完整时区。`TZH` 仍表示时区小时。
- 虚拟表支持 `DECIMAL`。
- `INTERVAL` 可以按客户端时区划分窗口。
- 新增 `information_schema.ins_disk_usage`，用于查看表的数据分布。
- 可以删除正在被订阅的表。删除并重建后，执行 `RELOAD TOPIC` 恢复订阅。

## 2. 新特性

- taosExplorer 增加 XNode 管理页。创建 taosX 任务时如果没有可用 XNode，会引导去创建。
- taosX 可以通过 taosExplorer 导入和导出配置文件。AVEVA Historian 断线后自动重连。
- Rust 连接器可以订阅批量标签修改，参数绑定支持 `DECIMAL` 和 `BLOB`。
- taos shell 新增 `-H`。默认关闭。打开后，含不可打印字符的 `BINARY` 以 `0x` 十六进制显示。
- `TO_ISO8601` 支持夏令时转换。
- 新增 `ins_disk_usage` 和 `ins_security_policies`。
- 新增 `syncAssignedCheckAppliedGap`。双副本下节点被指定为 assigned leader 时，用它限制 follower 的 applied index 与 commit index 的差距，避免 follower 还没追上就进入 restoring。默认 `20`。`0` 表示不做这项检查。
- 虚拟表支持 `DECIMAL` 列。
- 提供连接器安全开发指南和示例。

## 3. 优化

- DataIn 创建超级表时，如果把数据列移成标签列，会去掉默认的空标签列。
- taosExplorer 的跨域处理收紧。
- taosX 与 `xnoded` 之间的通信日志更易读。
- Python WebSocket 连接器的 SQLAlchemy 适配更完善。
- `STMT2` 写入时，子表元数据变化不再返回需要重试的错误。
- `INTERVAL` 按客户端带来的时区划分窗口。
- `SHOW TABLE DISTRIBUTED` 的返回格式更易读。
- WAL 最后一个日志文件损坏时，截断处理更可靠。
- 可以删除正在被订阅使用的表。

## 4. 问题修复

### 4.1 严重问题

- 部分函数在没有 `FROM` 时执行会导致崩溃。影响版本：所有版本。
- `NOT (CAST(NULL AS VARBINARY) BETWEEN NOW() AND ts)` 这类转换表达式会导致崩溃。影响版本：所有版本。
- `GROUP_CONCAT` 崩溃，并且结果错误。影响版本：所有版本。已经使用该函数结果的查询需要重新核对。
- 流计算回放 WAL 时，滑动窗口数量没有上限，导致内存耗尽并崩溃。影响版本：`v3.3.7.0` 至 `v3.4.1.0`。
- 流计算外层查询里 `DIFF` 与通知一起使用时崩溃。影响版本：`v3.3.7.0` 至 `v3.4.1.0`。
- 流计算查询使用 `%%tbname` 时，大量写入下内存释放错误并导致内存耗尽。影响版本：`v3.3.7.0` 至 `v3.4.1.0`。
- 过期数据删除与共享存储迁移冲突。共享存储自 `v3.3.7.0` 发布。影响版本：`v3.3.7.0` 至 `v3.4.1.0`。
- taosdump 通过 WebSocket 读数据时，服务异常后返回空数据且不报错，备份会缺数据。影响版本：所有版本。用受影响版本生成的备份需要核对是否完整。
- 数据库重整时，部分节点长时间离线，mnode 消息队列可能被占满，连接异常。影响版本：所有版本。

### 4.2 流计算、时区与工具

- 纳秒精度库中，流计算输出表的标签使用固定值时，建流失败。
- 流计算结果表是已经存在的普通表时，写入计算结果报错。
- 计数窗口触发在读历史数据时内存占用过高。
- `CASE WHEN` 用主键做过滤时，执行计划与实际执行不一致。
- macOS 上 `USE` 的提示与 Linux 不一致，现统一为 `Database changed.`。
- `queryTableNotExistAsEmpty` 经 taosAdapter 访问时不生效。
- `taos_cleanup` 退出时内存泄漏。
- Windows 安装包不能优雅停止进程。`xnoded` 子进程在 Windows 上有概率停不掉。
- taosk 生成密钥时路径错误。taosdump 导出大量子表时变慢。监控信息写入日志库失败。
- 虚拟子表与虚拟超级表的列数不一致。
- taosX：无数据时备份点异常；过滤条件不生效；Windows 上绑定 6051 端口时 OPC 接入失败；Pulsar 自定义认证没有参数输入框；Pulsar 不支持切分时任务一直处于创建中；Kafka 为复合主键时间戳错误地使用自增；SparkPlugB 拉示例数据失败后没有提示且不能重试。
- taosExplorer：写入任务多时页面加载慢；SQL 执行时间不准确。

## 6. 升级须知

### 6.1 升级路径

直接升级、滚动升级、降级和客户端配套版本未在本页另写。

### 6.2 行为变更

- `TO_ISO8601` 接受的时区从 `-12:00` 至 `+12:00` 扩大到 `-14:00` 至 `+14:00`，并支持分钟。以前报错的偏移现在会被接受，包括现实中不存在的偏移，例如 `+08:01`。
- `TO_CHAR`、`TO_TIMESTAMP` 中，`TZH` 表示时区小时。完整时区使用 `TZ`。
- macOS 上 `USE` 的输出改为 `Database changed.`。
- 可以删除正在被订阅的表。订阅方需要执行 `RELOAD TOPIC` 才能在表重建后继续。
- `STMT2` 在子表元数据变化时不再返回需要重试的错误码。依赖该错误码重试的写入需要改成其他判断。

### 6.3 配置参数变更

| 参数 | 作用 |
| --- | --- |
| syncAssignedCheckAppliedGap | 双副本下，节点被指定为 assigned leader 时，follower 的 applied index 与 commit index 允许的差距。默认 `20`。`0` 表示不检查。 |

### 6.4 关键字变更

下列词用作库名、表名、超级表名、子表名、列名或标签名时，不论大小写都要用反引号。

`SECURITY_LEVEL`、`SECURITY_POLICIES`。

### 6.5 系统表变更

新增 `information_schema.ins_disk_usage`，用于查看表的数据分布。

新增 `information_schema.ins_security_policies`。

本版本没有移除系统表。

### 6.6 升级前操作

从 `v3.3.6` 升级到本版本时，旧流计算不能直接沿用。步骤见 [流计算兼容性说明](../../07-stream-processing/02-instructions.md#兼容性说明)。

已经在 `v3.4.0.0` 及之后按新流计算运行的集群，滚动到本版本时不必重复。
