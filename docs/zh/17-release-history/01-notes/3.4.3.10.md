## 1. 版本亮点

- **联邦查询支持 Oracle**：Windows 上也可以联邦查询 Oracle，外部表和虚拟表的外部源都可以使用。流计算可以把 Oracle 外部表作为单层窗口的触发表，也可以从列来自 Oracle 外部表的虚拟表取数。
- **taosX 支持资源控制**：taosX 和 taosX-Agent 可以按进程限制内存、写入带宽和 CPU。内存达到预算时暂停读取新数据，已经进入管道的批次继续写入。未配置时不启用，现有任务行为不变。
- **Windows 平台**：修复 30 余项 Windows 平台问题，涉及时区与夏令时、CPU 绑核、日志压缩、`CREATE TSMA`、加密库、备份路径、嵌套窗口流计算，以及 taos 命令行、taosBenchmark 和 taosdump。
- **流计算稳定性**：修复客户现场发现的多项流计算问题，包括窗口结果漏算或重复计算、周期长于 WAL 留存的 `PERIOD` 流在重启后停止输出、虚拟表流崩溃或反复重新部署，以及手动重算后 `STOP STREAM` 卡住。

## 2. 新特性

### 2.1 联邦查询与流计算

- Windows 上可以联邦查询 Oracle，外部表和虚拟表的外部源都支持，行为与 Linux 一致。说明见 [联邦查询](../../05-tdengine-sql/04-data-query/06-federated-query.md)。
- `CREATE STREAM` 可以引用 Oracle 外部表。触发器只支持单层窗口，包括 `INTERVAL`、`SLIDING`、`SESSION`、`STATE`、`EVENT` 和 `COUNT`。也可以用列来自 Oracle 外部表的虚拟表作为取数来源。多层嵌套窗口触发器、对 Oracle 外部表执行 `CREATE TOPIC`，以及向 Oracle 外部表写入，仍会被拒绝并返回明确错误。
- Linux 上可以联邦查询 InfluxDB OSS 1.8。外部源类型仍为 `influxdb`，`OPTIONS` 中须把 `version` 设为 `1.8`，使用 `USER` 和 `PASSWORD` 认证，可用 `retention_policy` 指定保留策略，省略时使用目标 database 的默认保留策略。支持原始列投影和虚拟表 `SERIES` 引用，筛选、聚合、排序和 `LIMIT` 在 TDengine 侧计算。Windows 和流计算暂不支持 InfluxDB 1.8。未指定 `version` 的已有 InfluxDB 外部源仍按 3.x 处理。说明见 [InfluxDB 参数](../../05-tdengine-sql/04-data-query/06-federated-query.md#influxdb-参数)。
- 联邦查询支持使用 `caching_sha2_password` 认证的 MySQL 账号，不必再把账号改成 `mysql_native_password`。

### 2.2 taosX 与 taosExplorer

- taosX 和 taosX-Agent 可以通过 `[resource]` 配置按进程限制内存、写入带宽和 CPU。内存达到预算时暂停读取新数据，已经进入管道的批次继续写入。未配置时不启用，现有任务行为不变。说明见 [资源占用控制](../../08-data-ingest-and-delivery/06-resource-control.md)。
- taosExplorer 为 SQL Server 同步任务创建超级表时，按查询元数据预填字段类型、长度和 `DECIMAL` 精度，不再默认使用 `VARCHAR(128)`。查询没有返回行时仍可得到表结构。长度未知或没有上限的字段需要手工确认。

### 2.3 集群运维

- 全部节点停止后，可以用 taosd 离线修改 dnode 的 FQDN 和端口。先在每个节点用 `--rewrite-endpoints-precheck` 和 `--map` 预检，再用 `--rewrite-endpoints-apply` 改写配置和数据目录中的旧地址。命令不修改数据，执行成功后不能回退。说明见 [修改节点地址](../../12-operations-and-tooling/02-operations/09-network.md#修改节点地址)。

## 3. 优化

### 3.1 查询与虚拟表

- `LIMIT 0` 的查询在客户端直接返回空结果，列名和类型不变，不再发到服务端执行。预编译语句中 `LIMIT` 绑定为 0 时同样生效。
- 虚拟表列引用内容没有变化时，重复执行 `ALTER COLUMN REF` 不再写入元数据，也不再递增引用版本。

### 3.2 集群与工具

- `BALANCE VGROUP LEADER` 遇到单副本库时跳过该库，继续均衡双副本和三副本库。
- taos 命令行以文本显示可打印的 BLOB，包括 `SHOW XNODE TASKS` 的 parser 和 `SHOW XNODE JOBS` 的 config。不可打印的 BLOB 仍以十六进制显示。
- 用户手册补充了使用 taosX 备份和恢复指定表的说明。见 [使用 taosX 备份和恢复指定表](../../12-operations-and-tooling/02-operations/10-backup.md#使用-taosx-备份和恢复指定表)。

### 3.3 taosX

- taosX-Agent 统一交付协议：批次在写入完成或按配置处理异常数据后才确认。断流或交付超时时保留未确认的数据，自动重连后重放。明确的写入、认证、协议或配置错误会停止任务。交付窗口和超时可以通过环境变量调整，说明见 [交付窗口与超时](../../12-operations-and-tooling/03-components/07-taosx-agent/01-configuration.md#交付窗口与超时)。

## 4. 问题修复

### 4.1 严重问题

- 自 `v3.4.3.8` 起，dnode 状态心跳中的机器标识与已登记值不一致时，mnode 返回认证失败，节点一直离线。Windows 上从旧版原地升级、机器码来源改变后也会触发。本版本不再因此拒绝心跳，节点保持在线。影响版本：`v3.4.3.8` 至 `v3.4.3.9`。
- `COUNT_WINDOW`、`INTERVAL`、`STATE_WINDOW` 和 `PERIOD` 的流计算可能因读取顺序漏掉窗口结果，同一窗口也可能被计算两次。影响版本：`v3.3.7` 至 `v3.4.3.9`。
- Windows 上，嵌套窗口流计算用整个结构体构造外层窗口缓存键，填充字节使同一窗口被当成不同范围。嵌套 `COUNT_WINDOW`、`INTERVAL` 和 `SLIDING` 的 `%%trows` 聚合可能为空、丢行，`count` 和 `sum` 不正确。影响版本：`v3.4.2.7` 至 `v3.4.3.9` 的 Windows 版本。
- 普通表和超级表上，不同字符串 `IN` 集合与时间或数值范围组成的 `OR` 条件可能互相串用，重叠区间里的行被丢掉。影响版本：所有版本。
- 查询线程池在执行名额空闲后可能丢失唤醒。只有一个查询线程时，关联查询或取消后的重试一直不返回。影响版本：所有版本。
- 多 mnode 集群在显式事务尚未结束时切换 leader 或整体重启，`COMMIT` 和 `ROLLBACK` 可能漏掉事务里的 `DROP STREAM` 等操作。影响版本：`v3.4.3.0` 至 `v3.4.3.9`。
- 流计算用虚拟表的标签引用读取配置表标签作为阈值时，首次写入数据会导致 taosd 崩溃。影响版本：`v3.4.2.0` 至 `v3.4.3.9`。
- 联邦查询的扫描列名累计达到 512 字节时，规划阶段写穿栈导致进程崩溃。宽表 `SELECT *` 会触发，单列查询不会。影响版本：`v3.4.3.0` 至 `v3.4.3.9`。
- 手动重算之后执行 `STOP STREAM`，重算事务和运行态锁互相等待，语句一直不返回。影响版本：`v3.4.2.7` 至 `v3.4.3.9`。
- 周期长于 WAL 留存的 `PERIOD` 流在周期结束前不采集输入，重启后不再输出结果。本版本持续采集输入，仍按原来的周期边界输出。WAL 中已经回收且未缓存的数据不会被补回。影响版本：`v3.3.7` 至 `v3.4.3.9`。
- Windows 上数据目录路径较长时，停止后再启动会因文件名被截断而崩溃。影响版本：所有版本。

### 4.2 流计算

- 虚拟超级表上的流同时聚合存储标签和源数据列时，不再失败并反复重新部署，也不再报 `No exchange source for vgId`。历史计算和后续窗口不再越界读取。
- 流重算扫描远端虚拟表时，已消费的数据块在下一批响应前释放，宽表长时间扫描不再占满内存、拖慢查询。部署尚未完成时，虚拟表计算的重试改为退避。
- 流计算重复使用 `ANOMALY_WINDOW` 时，算子重置会释放上一轮的表达式和函数上下文，内存不再随重置次数增长。
- 异常检测窗口在表达式、空值和非有限浮点数上不再生成非法分析请求，结果可以正常写出。
- 不带 `TO` 的手动重算在历史结果写出且执行结束后，显示 Finished 和 100%，不再停在 Running 和 0%。

### 4.3 查询、虚拟表与联邦查询

- 虚拟超级表上的 `STATE_WINDOW`、`SESSION` 或 `EVENT_WINDOW` 只查询 `_wstart`、`_wend` 或 `_wduration` 时，taosd 不再崩溃。
- 联邦查询虚拟超级表时，时间轴恢复为主键时间。被错放并截断为空值的时间类型副列恢复为原值。
- `ALTER EXTERNAL SOURCE` 恢复 `database` 后，`DESCRIBE` 不再被过期的心跳快照写回旧值。
- `FILL(NEXT)` 的插值查询在前一个窗口被裁空后，不再从错误位置继续扫描，单行结果也不再读入大量多余的行。
- 虚拟普通表和虚拟子表上，不分组的主时间戳 `LAST` 连同同行的列和标量表达式，读到第一条完整结果即停止，不再扫描整张表。同时取出引用标签或外部源列时也是如此。
- 虚拟表上 `DIFF`、`DERIVATIVE`、`MAVG`、`LAG` 和 `LEAD` 按时间戳排序并带 `LIMIT` 时，只读取计算结果所需的行，不再扫描整张虚拟表。
- `ALTER VTABLE` 修改虚拟超级表时不再返回成功却不改结构，该语句改为被拒绝。
- 虚拟表自有列执行 `ALTER VTABLE ... ALTER COLUMN ... SET` 或 `SET NULL` 时，不再报 Table column does not exist，改绑和解绑可以成功。`CREATE VTABLE` 可以声明不带 `FROM` 的自有列，`SHOW CREATE` 也会输出这类未绑定的自有列，导出再导入不再丢列。
- 虚拟超级表 `ALTER STABLE` 加列与子表自有列重名时，错误信息会指出冲突的子表和列名。删列时会提示该名可能是某个虚拟子表的自有列。错误码不变。

### 4.4 集群、授权与运维

- `REDISTRIBUTE VGROUP` 会同时更新仲裁组的节点映射，仲裁不再指向迁移前的节点。
- 创建数据库期间，`SHOW CLUSTER ALIVE` 不再因为新 vgroup 尚未上报 leader 而短暂返回 2。
- 只设置 `readCpuCores` 或 `otherCpuCores` 其中一项时，另一项按剩余核数取动态默认值，不再回退为 1。
- 基础授权到期后，可以查询由 vnode 扫描的系统表，例如 `ins_tables`、`ins_tags` 和 `ins_columns`。用户表查询仍返回授权到期。这项修复在客户端生效，需要升级 taosc 以及内置 taosc 的组件，例如 taosAdapter。
- 基础授权或 TDgpt 授权到期后，仍可以创建、查看和更新 ANode，个数限制不变。时序分析函数查询仍受基础授权到期限制。

### 4.5 Windows 平台

- 带夏令时的时区按该时刻的实际偏移换算本地时间，自然月、自然季度窗口和 `TO_ISO8601` 不再按固定的标准时偏移错位。
- 新建连接采用客户端配置的时区，配置为 UTC 时窗口边界不再按默认时区计算。
- 可以执行 `SET TIMEZONE`，会话时区按设置生效，不再返回 0x0237。
- 系统时间改为精确时钟，同一批流计算窗口各自得到可区分的时间戳，不再因时间相同而互相覆盖。
- taosd 在流通知 WebSocket 发送受阻时，不再停在 Stop Pending、无法完成关闭。
- 可以执行 `CREATE TSMA`，不再返回平台不支持。
- 可以创建 AES-128-CBC 加密库，不再报算法不存在。
- 启用 CPU 绑核后，线程按配置使用指定的核。
- `logKeepDays` 不为 0 时，写满的日志按日期保存并压缩。
- `KILL QUERY` 按连接标识的原始 32 位值查找连接，高位为 1 时不再被截成 7fffffff。
- `NCHAR` 的 `MATCH` 按字符匹配，四个字符的模式可以匹配四个字符的字符串。
- `REGEXP_IN_SET` 的模式为空时返回不匹配，空 `NCHAR` 模式不再对非空集合返回 1。
- `CREATE TABLE ... FILE` 拒绝无效 CSV 后会关闭文件，不再留下文件句柄。
- 全量备份会为混用正斜杠和反斜杠的路径创建父目录，mnode 元数据可以写入。
- 共享存储迁移清理垃圾文件时，保留刚上传的 manifest 和数据分片，不再把反斜杠路径全部删掉。
- taosX 开启实时缓存的采集在浮点数回放失败时任务报错结束，不再停住并让源端一直等待。
- taos 命令行在标准输入被重定向时会读取并执行命令，不再一直等待。执行 CRLF 换行的脚本时，反斜杠续行仍然有效。
- taosBenchmark 在标准输出被重定向时仍会输出提示和汇总。按 64 位解析 CSV 中的原始时间戳。REST 查询读完 chunked 响应后再解析，大结果不再报 JSON 解析失败。telnet TCP 写入在结束前读完对端响应，成功条数与实际写入行数一致。
- taosdump 在标准输出被重定向时会输出结束汇总，并把 `restore.log` 写到当前工作目录。系统编码为 GBK 时，可以为中文库名创建备份目录。

### 4.6 taosX 与 taosExplorer

- taosX 的 OPC UA 采集断连后不再显示运行中并继续写出缓存的旧值。持续不可用超过恢复窗口后上报采集失败，并按原有策略重试。
- taosX 复用导出的 OPC UA 点位 CSV 时，不再把没有 Value 属性的 Object 行加入采集而导致任务启动失败。浏览点位失败时返回错误，不再把不完整的点位列表当作成功。
- taosX 的 CSV 监听文件夹导入在大量文件场景下停止写入时，不再仍显示运行中、需要手动重启。
- taosX 的 CSV 监听文件夹导入在任务完成后按配置删除已处理的文件，重启后进度指标准确。
- taosExplorer 的 `explorer.toml` 中的 `monitor.port` 和 `monitor.interval` 在重启后生效，不再回退为 6043 和 10。

## 5. 安全

### 5.1 漏洞修复

见 [安全公告](https://docs.taosdata.com/security-guide/security-advisories/)。

- Windows 上 TOTP 会校验验证码。错误的验证码和轮换前的旧密钥不能再登录。
- vnode 解码写入请求、快照和数据文件时，在使用前校验长度、个数和类型。异常输入返回错误，不再越界、超大分配或崩溃，损坏的数据也不再写入或返回给客户端。磁盘格式和 RPC 格式不变。
- taosd 上报监控指标时，在锁内拷贝样本快照后再使用，避免并发 rehash 时访问已释放的内存。
- taosX 将 zstd-safe 升级到 7.4.0，并不再使用 5.0.2，修复 RUSTSEC-2026-0399、RUSTSEC-2026-0401 和 RUSTSEC-2026-0406。actix 系列依赖升级，修复 RUSTSEC-2026-0443、RUSTSEC-2026-0446、RUSTSEC-2026-0447、RUSTSEC-2026-0448 和 RUSTSEC-2026-0455。不再使用 scc 2.4.0，修复 RUSTSEC-2026-0205。
- Java 连接器将 guava 从 33.5.0-jre 升级到 33.7.2-jre，修复 CVE-2026-102554（GHSA-xxph-c9ww-hj94）。jackson 从 2.22.1 升级到 2.22.3，修复 CVE-2026-89407（GHSA-p6pp-m3f8-5c89）、CVE-2026-89425（GHSA-7hhh-6rmp-j9qf）、CVE-2026-91776（GHSA-wv8q-qhhj-9h54）、CVE-2026-91777（GHSA-cxp5-3px4-pw24）和 CVE-2026-68497（GHSA-q4xh-88c3-wmh7）。
- taos-insight 将 follow-redirects 升级到 1.16.2，修复 CVE-2026-116689（GHSA-mrwp-f3q8-3g9p）。minimatch 升级到 11.0.1，修复 CVE-2026-118764（GHSA-g3hv-75wg-m249）。qs 升级到 6.16.1，修复 CVE-2026-110816（GHSA-6pq8-jhm2-2vcw）。serialize-javascript 升级到 7.1.3，修复 CVE-2026-115897（GHSA-m5mm-p8h7-m29v）。zod 升级到 4.6.6，修复 CVE-2023-54404（GHSA-mrhx-c7xc-m3w5）。

### 5.2 安全加固

无。

## 6. 升级须知

### 6.1 升级路径

- 支持直接升级的源版本：`v3.3.7` 及后续版本。
- 是否支持滚动升级：支持，范围为 `v3.4.3.0` 至 `v3.4.3.9`。
- 是否支持降级或回滚：支持，范围为 `v3.4.3.0` 至 `v3.4.3.9`。
- 客户端与连接器的最低配套版本：`v3.4.3.0`。

### 6.2 行为变更

- taosX-Agent 改用统一交付协议 v2。taosX 与所有 taosX-Agent 必须一起升级，旧版 Agent 或协议不匹配时明确报错，不回退旧协议。结果未知的批次会重放，下游可能收到重复数据。
- taosX 的 CSV 监听文件夹导入任务升级后，无法按新断点校验的旧任务会从文件开头重新导入。升级前已经完成、但无法按新断点校验的 CSV 文件不会自动删除，需要手动清理。
- taosX 的 OPC UA 采集在断连或读取失败期间不再输出缓存的旧值，下游看到的是数据缺口。
- 带夏令时的时区下，Windows 上自然月、自然季度窗口边界和 `TO_ISO8601` 的本地偏移由偏差 1 小时变为正确值。不使用夏令时的时区不受影响。
- 只显式配置 `readCpuCores` 或 `otherCpuCores` 其中一项时，另一项按 `(totalCores - managementCpuCores)` 取动态默认值，不再是 1。`SHOW CPU_ALLOCATION` 的显示和实际绑核随之变化。两项都配置或都不配置时不受影响。
- 周期长于 WAL 留存的 `PERIOD` 流计算落后时，已经到点的多个周期合并成一轮结果，不再为每个错过的周期单独输出。
- 修改虚拟超级表结构请使用 `ALTER STABLE`。`ALTER VTABLE` 作用于虚拟超级表时改为报错。
- `SHOW CREATE TABLE`、`SHOW CREATE VTABLE` 及其 `FULL` 形式会输出虚拟子表中未绑定的自有列，写成 `name TYPE`。
- 预编译语句中 `LIMIT` 绑定为负数时报错 limit cannot be less than 0。
- 使用 `caching_sha2_password` 的 MySQL 外部源在客户端认证插件缺失时，返回 External source client authentication plugin is missing [0x8000642E]，不再报认证失败 [0x80006401]。密码错误仍报认证失败。
- taos 命令行中可打印的 BLOB 由十六进制改为原文显示，列类型仍为 BLOB。
- taosd 不再读取 `ep.json`，遗留的文件会被忽略。
- taosExplorer 重启后使用 `explorer.toml` 中 `monitor.port` 和 `monitor.interval` 的值。命令行参数和环境变量仍然优先。

### 6.3 配置参数变更

taosX 和 taosX-Agent 新增 `[resource]` 配置段，taosX-Agent 新增三个交付相关的环境变量。taosd 没有新增或移除配置参数。

#### 6.3.1 taosX 与 taosX-Agent 的 `[resource]` 配置段

未配置 `[resource]` 时不启用资源限制。修改后需要重启对应进程。

| 参数 | 作用 |
| --- | --- |
| `enabled` | 是否启用资源限制。存在 `[resource]` 时默认 `true`，设为 `false` 可完整关闭。 |
| `maxWriteMBps` | 数据写入带宽上限，单位 MB/s。默认 `0`，表示不限制。 |
| `maxMemoryMB` | 进程及已注册子进程的内存软预算，单位 MiB。默认 `0`，表示读取 cgroup 内存限制；没有 cgroup 限制时不启用。 |
| `maxPauseSecs` | 任意资源限制单次暂停的上限，单位秒。默认 `10`。 |
| `maxCpuPercent` | CPU 高水位，占全部核数的百分比，超过后暂停数据写入。默认 `0`，表示不限制。 |
| `cpuResumePercent` | CPU 恢复水位。默认 `0`，表示取 `maxCpuPercent` 的 80%。 |
| `maxCpuCores` | 运行时 worker 线程数上限。默认 `0`，表示不限制。 |
| `cgroupPath` | 可选的 cgroup 目录。默认从 `/proc/self/cgroup` 解析。 |
| `cpuPriority` | Linux 上可选的 nice 值，范围为 1 至 19。默认 `0`，其他平台忽略。 |

#### 6.3.2 taosX-Agent 环境变量

设置在 taosX-Agent 服务进程的环境中，不是 `agent.toml` 或任务 DSN 参数。修改后需要重启对应进程。

| 参数 | 作用 |
| --- | --- |
| `TAOSX_AGENT_DELIVERY_MAX_BATCHES` | 未确认批次的数量上限。默认沿用 `in_memory_cache_capacity`，未修改时为 `64`。 |
| `TAOSX_AGENT_DELIVERY_MAX_BYTES` | 未确认数据的估算字节上限。默认 `67108864`（64 MiB）。 |
| `TAOSX_AGENT_DELIVERY_TIMEOUT_SECS` | 已发送但未完成批次的交付期限，单位秒。默认 `120`。 |

### 6.7 升级前操作

taosX 与所有 taosX-Agent 需要一起升级到本版本。只升级其中一方时，交付协议不匹配，任务会报错。

从 `v3.3.6` 升级到本版本时，旧流计算不能直接沿用。未删除旧流、TSMA、snode 及其数据目录时，taosd 会启动失败。步骤见 [流计算兼容性说明](../../07-stream-processing/02-instructions.md#兼容性说明)。已经在 `v3.4.2.0` 及之后按新流计算重建过的集群，滚动到本版本时不必重复上述步骤。

从 `v3.4` 以前的版本升级到本版本时，taosX 不会自动迁移已有任务。此前任务存在 SQLite 中，`v3.4` 起存在 mnode 中。升级前在 taosExplorer 中导出任务；升级后导入，再启动需要运行的任务。没有在升级前导出时，升级后的 taosExplorer 中看不到这些任务。步骤见 [从 v3.4 以前的版本升级到 v3.4.x 时迁移任务](../../12-operations-and-tooling/03-components/06-taosx.md#从-v34-以前的版本升级到-v34x-时迁移任务)。已经在 `v3.4.0.0` 及之后运行、任务已在 mnode 中的集群，滚动到本版本时不必重复上述步骤。
