| 维护版本 | 使用流计算、taosX 备份与同步，或从 `v3.3` 升级多副本 mnode 的用户 |

## 1. 版本亮点

- 流计算增加可观测性。`information_schema` 中的系统表展示延迟、吞吐、历史填充和重算进度。
- 流计算支持外部源联邦查询，包括 InfluxDB。
- taosExplorer 可以在页面上启动、停止和重算流任务。
- taosdump 可以按内容选择备份范围。默认只处理基础数据，虚拟表、流和订阅需要显式选择。
- 流计算 Runner 的部署组数和副本数可以配置。
- RPC 增加 CRC 校验开关。x86 客户端启用硬件 CRC，需要降低开销时可以关闭校验。

## 2. 新特性

### 2.1 流计算

- 通过 [`information_schema.ins_streams`](../../07-stream-processing/04-observability.md)、`information_schema.ins_stream_tasks` 和 `information_schema.ins_stream_recalculates` 查看实时延迟、吞吐、历史填充与重算进度。
- 支持对外部源做联邦查询，包括 InfluxDB，并完善触发模式、stream options 和 `SHOW` 中的可观测字段。
- 新增 `numOfStreamRunnerDeploys` 和 `numOfStreamRunnerReplicas`。前者默认 `3`，范围 1–64，表示 Runner 部署组数；后者默认 `5`，范围 1–1024，表示每组副本数。二者均可动态修改。

### 2.2 taosExplorer

- 流计算页面可以启动、停止和重算流任务，不必手写 SQL。
- 可以通过 `allowedOrigins` 配置跨域 HTTP 和 WebSocket，使 IDMP 等跨源场景下的数据写入可用。

### 2.3 taosdump、taosgen 与连接器

- taosdump 新增 `-M` / `--content`，取值为 `basic`、`ext-meta` 或 `all`。默认 `basic`，只处理超级表、子表、普通表及其标签与时序数据。`ext-meta` 包含虚拟表、流和订阅，并分阶段恢复，避免跨库虚拟表依赖导致恢复失败。
- taosX 增量备份可以借助 schema snapshot 从任意备份点恢复，并恢复虚拟表和流计算任务的 schema。
- taosX Kafka 数据接入支持解析 zstd 压缩消息。
- XNode 任务的 parser 上限提高到 960 KiB，JOB config 上限提高到 1 MiB，可以创建 400 个以上字段的导入任务。
- taosgen 的普通测量列可以使用 `TIMESTAMP`，并支持把时间字符串转成时间戳。
- Python WebSocket 连接器新增 `user_app`，用于标识应用程序名称。
- 新增 [`rpcCrcEnable`](../../12-operations-and-tooling/03-components/01-taosd.md#rpccrcenable)。默认 `1`，对 RPC 消息做 CRC32C 校验。可通过 `ALTER` 修改，重启后生效。

## 3. 优化

- 提升大时间范围内 `LAST` 查询的性能。查询会跳过全为 NULL 的数据块。
- 提升 taosX Kafka Connector 的消费能力。
- 外层派生表带过滤时，流计算可以继续使用 external window，降低 `INTERVAL` 窗口的资源占用。
- WebSocket STMT2 在 close 时释放关联查询结果集，与 native STMT2 一致。
- `STMT2` 自动建表写入不再重复解析 tag，写入性能接近提前建表。
- taosdump 备份和恢复时写入 `backup.log` 和 `restore.log`，记录版本、参数和完整 SQL。
- taosExplorer 数据订阅示例代码页的步骤条跟随滚动并定位当前步骤。
- InfluxDB 同步在只选择少量 measurement 时，不再全量加载 bucket 元数据。
- taosX 指定表备份缩短备份前检查时间。单表失败时继续备份其他表。
- 不适合走 tag index 的场景不再以错误级别输出 IDX 日志。
- snapshot 限速到达上限后不再降为 0，传输速度按设定值执行。

## 4. 问题修复

### 4.1 严重问题

- 多副本 mnode 从 `v3.3` 升级到 `v3.4.2.0` 至 `v3.4.2.2` 时，角色升级可能没有执行，系统默认角色和用户权限丢失。影响版本：`v3.4.2.0` 至 `v3.4.2.2`。升级到本版本后，请核对默认角色和用户权限是否完整。
- 开启共享存储但未配置默认访问串时，`DROP DATABASE` 会导致 taosd 崩溃。影响版本：`v3.3.7.0` 至 `v3.4.2.2`。
- 流计算外部窗口复用结果块时可能越界写入，导致 taosd 崩溃。影响版本：`v3.3.7.0` 至 `v3.4.2.2`。
- 流计算扫描 WAL metadata 时越界写入，节点掉线。影响版本：`v3.3.7.0` 至 `v3.4.2.2`。
- 仅通知、没有计算内容的流配置 `MAX_DELAY` 时，WAL 没有数据会触发空指针并导致 taosd 崩溃。影响版本：`v3.3.7.0` 至 `v3.4.2.2`。
- `SHOW SUBSCRIPTIONS` 在 vnode 恢复时因结果块容量不足导致进程崩溃。影响版本：所有版本。
- `STMT2` interlace 模式关闭时重复释放列信息，进程崩溃。`STMT2` 自 `v3.3.3.0` 发布。影响版本：`v3.3.3.0` 至 `v3.4.2.2`。
- `STMT2` 多表交替绑定，以及 taosdump 恢复时大小表交替，会导致提交失败和小表数据丢失。影响版本：`v3.3.3.0` 至 `v3.4.2.2`。已经用受影响版本恢复过的备份，需要核对小表数据是否完整。
- 客户端在连接关闭过程中收到服务端响应时进程中止。影响版本：所有版本。
- Python 原生连接器异步查询未保留回调，进程崩溃。影响版本：所有版本。
- TMQ 同步流计算自动创建的普通表时，taosAdapter 因元数据解析错误崩溃。影响版本：`v3.3.7.0` 至 `v3.4.2.2`。
- Windows 版 taosdump 在不支持相应指令集的旧 CPU 上启动即崩溃。影响版本：所有版本。
- Windows 下 taos 客户端关闭连接时可能卡住。影响版本：所有版本。
- PI Connector 列名超长时任务反复重启并丢失数据。影响版本：所有版本。已经接入的数据需要与源端核对。
- OPC 采集在连接断开且存在异常节点时可能异常退出，任务无法正常启动。影响版本：所有版本。
- InfluxDB 1.x 高基数同步可能漏读数据，目标端与源端不一致。影响版本：所有版本。升级后需要核对已同步数据，必要时重跑同步。
- taosX 任务级备份做异地恢复时，未识别 `-1` 子目录，命令成功但数据没有恢复。影响版本：所有版本。用受影响版本做过恢复的环境，需要重新恢复并核对数据。
- taosdump 在备份过程中服务不可用时，可能把中断当成取数完成，备份数据缺失。影响版本：所有版本。
- `IMPUTATION` 补值结果不正确。该函数自 `v3.3.7.7` 引入，`v3.3.6` 没有该函数。影响版本：`v3.3.7.7` 至 `v3.4.2.2`。使用补值结果的查询需要重新核对。
- `LAST` / `LAST_ROW` 在重叠 `INTERVAL` + `SLIDING` 窗口下，直接查询和子查询结果不一致，多周滑动窗口的相位也不稳定。影响版本：所有版本。
- 虚拟子表 `SELECT TAGS` 按源表数据行错误展开结果。`EXPLAIN SELECT TAGS` 在扫描列链表为空时进程崩溃。虚拟表自 `v3.3.6.0` 发布。影响版本：`v3.3.6.0` 至 `v3.4.2.2`。
- 虚拟表 `ALTER TAG` 后，`SELECT TAGS` 报 Planner slot key not found。影响版本：`v3.3.6.0` 至 `v3.4.2.2`。
- 单节点首次部署中途中断后，默认元数据没有建全，连接报 Invalid user。启动时会补建缺失对象。影响版本：所有版本。
- 部分平台上 taosX 默认只监听 IPv6，用 `127.0.0.1` 创建的 XNode 显示 offline。XNode 自 `v3.4.0.0` 发布。影响版本：`v3.4.0.0` 至 `v3.4.2.2`。

### 4.2 查询

- `INTERVAL` 查询因时区日界字段遗漏报 Executor internal error。
- `TIMETRUNCATE` 对固定时区偏移的解析不一致。join、子查询等标量路径上，隐式会话时区与显式固定偏移（如 `+0800`）对 `1d`、`1w` 的截断结果不一致。
- Windows 上 `TIMETRUNCATE` 等函数因时区偏移符号不一致，转换结果错误。
- `TO_TIMESTAMP` 解析合法日期时，可能因线程遗留错误随机报 format mismatch。
- 同一条 SQL 中多个 `MAVG`、`STATECOUNT`、`STATEDURATION` 与 `ts` 或普通列共存时报错。
- 超级表先 `DROP TAG` 再 `ADD TAG` 后，对已有子表执行 `SHOW CREATE TABLE` 报 Unexpected generic error。
- `v3.4.1.0` 至 `v3.4.2.2` 在 root 下执行 `taosd -k`，生成的机器码与更早版本不一致。
- `v3.4.2.0` 至 `v3.4.2.2` 引入 RPC CRC 后，部分查询变慢。x86 客户端改为硬件 CRC，并可通过 `rpcCrcEnable` 关闭校验。

### 4.3 流计算

- `FILL_HISTORY` 在 `PARTITION BY` 下，部分子表在历史起点之后没有数据时触发 Internal error，历史结果无法生成。
- WebSocket 通知帧超过 1 MiB 时，远端接收失败。
- `nodelay_create_subtable` 在还没有真实窗口时，不再用占位窗口进入执行器，避免虚拟表扫描报 Invalid parameters、输出子表没有结果。
- 处理自动建表数据时，无效时间戳把计算范围拉得过大，CPU 占用过高。
- 除 `INTERVAL` 以外的窗口暂不支持聚合 `DISTINCT`，解析阶段直接报错。

### 4.4 写入与订阅

- `STMT2` 或 WebSocket 自动建表写入时，bind 之后、exec 之前删除子表会报 Table does not exist，并且不能按已绑定 tag 重建后再写入。
- `STMT2` 查询绑定后丢失会话时区，`TO_CHAR` 等时间函数的时区结果错误。
- 普通用户 `CREATE DATABASE` 后立刻自动建表写入，客户端权限缓存尚未刷新，报 Permission denied。
- 状态心跳未释放嵌套数组，造成内存泄漏。
- VGroup 在还没有收到有效心跳时被误判为 offline。

### 4.5 taosX、taosdump 与 taosExplorer

- taosX 在 taos 到 taos 同步时无法迁移虚拟子表。
- 目标端不可用（例如 taosd 宕机）时，taosX 把可恢复错误当成致命错误并退出，目标恢复后无法继续同步。
- 创建 TMQ 备份任务时，校验阶段创建 Topic 形成循环等待，首次提交超时。
- 经 TMQ WebSocket 持续拉取大量数据时，心跳没有刷新 taosAdapter 读超时，大约每 2 分钟断开一次。
- 周期备份的周期参数没有生效，备份无法按计划停止。
- 备份到阿里云对象存储时 Path-style 访问失败。新增 S3 URI style，可选 `path` 或 `virtualhost`。
- 备份无法处理含特殊字符的表名。
- 删除 XNode 后，备份或 ETL 任务仍可能被分配到已删除的 XNode。
- 创建 XNode CSV 写入任务时，默认字段引用符导致提交失败。
- 启用 SQL 标签缓存后，已缓存子表被删除，Kafka 同步任务因表不存在而停止。
- taosdump 按时间范围备份时，主键时间列不叫 `ts` 会报 Invalid column name。
- taosdump 断点续传（`-C`）更换备份格式（`-F`）时未校验一致性，目录里混入不同格式，恢复失败。
- taosBenchmark 并行混合查询没有按 SQL 的 result 配置写出结果文件。
- taosExplorer：OPC CSV 上传因响应格式变化解析失败；PI/OPC 配置页拼写和标签样式导致 path filter 显示异常；创建备份任务时超时连点会重复创建；慢 SQL 分页导致内存升高、切换页大小后无数据，查询失败后按钮不可再点；授权页错误展示 IDMP 授权项；数据接入活动明细不显示失败原因；S3 备份在取消 dumper 时误取消整任务。
- Windows All-in-One 安装后 taosKeeper 无法启动。崩溃转储文件名改为按崩溃模块命名，不再固定使用 taosd 前缀。

本版本无安全相关修复。

## 6. 升级须知

### 6.1 升级路径

- 支持直接升级的源版本：`v3.3.7` 及后续版本。
- 是否支持滚动升级：支持，范围为 `v3.4.2.0` 至 `v3.4.2.5`。
- 是否支持降级或回滚：支持，范围为 `v3.4.2.0` 至 `v3.4.2.5`。
- 客户端与连接器的最低配套版本：`v3.4.2.0`。

### 6.2 行为变更

- `rpcCrcEnable` 默认 `1`。全集群和全部客户端必须一致。一端开启 CRC 时，会拒绝另一端关闭 CRC 的消息。改为 `0` 后需要重启才生效，可以降低校验开销，同时不再做 CRC32C 校验。
- taosdump 的 `-M` / `--content` 默认是 `basic`。虚拟表、流和订阅不再进入默认备份和恢复。需要这些对象时指定 `ext-meta` 或 `all`。
- 除 `INTERVAL` 以外的窗口中使用聚合 `DISTINCT`，语句在解析阶段失败。
- `information_schema.ins_streams`、`information_schema.ins_stream_tasks` 和 `information_schema.ins_stream_recalculates` 新增运行和进度相关列，例如 `realtime_lag_ms`、`input_rows_per_sec_1m`、`output_rows_per_sec_1m`、`history_progress_pct` 以及重算 `status`。按列名读取的应用不需要修改。

### 6.3 配置参数变更

#### 6.3.1 流计算

| 参数 | 作用 |
| --- | --- |
| numOfStreamRunnerDeploys | Runner 部署组数。默认 `3`，范围 1–64，可动态修改。 |
| numOfStreamRunnerReplicas | 每组 Runner 副本数。默认 `5`，范围 1–1024，可动态修改。 |

#### 6.3.2 连接

| 参数 | 作用 |
| --- | --- |
| rpcCrcEnable | 是否对 RPC 消息做 CRC32C 校验。默认 `1`。可通过 `ALTER` 修改，重启后生效。全集群和客户端必须一致。自 `v3.4.2.4` 引入。 |

#### 6.3.3 taosExplorer 与 taosX

| 参数 | 作用 |
| --- | --- |
| allowedOrigins | taosExplorer 允许的跨域 HTTP / WebSocket 来源。 |
| S3 URI style | taosX 备份访问对象存储的方式，取值为 `path` 或 `virtualhost`。 |

### 6.4 关键字变更

无。

### 6.5 系统表变更

`information_schema.ins_streams`、`information_schema.ins_stream_tasks` 和 `information_schema.ins_stream_recalculates` 新增运行与进度列。说明见 [流计算可观测性](../../07-stream-processing/04-observability.md)。

本版本没有移除系统表。

### 6.6 依赖库变更

| 组件 | 依赖库 | v3.4.2.2 | v3.4.2.5 |
| --- | --- | --- | --- |

### 6.7 升级前操作

从 `v3.3.6` 升级到本版本时，旧流计算不能直接沿用。未删除旧流、TSMA、snode 及其数据目录时，taosd 会启动失败。步骤见 [流计算兼容性说明](../../07-stream-processing/02-instructions.md#兼容性说明)。

从 `v3.4` 以前的版本升级到本版本时，taosX 不会自动迁移已有任务。此前任务存在 SQLite 中，`v3.4` 起存在 mnode 中。升级前在 taosExplorer 中导出任务；升级后导入，再启动需要运行的任务。没有在升级前导出时，升级后的 taosExplorer 中看不到这些任务。步骤见 [从 v3.4 以前的版本升级到 v3.4.x 时迁移任务](../../12-operations-and-tooling/03-components/06-taosx.md#从-v34-以前的版本升级到-v34x-时迁移任务)。已经在 `v3.4.0.0` 及之后运行、任务已在 mnode 中的集群，滚动到本版本时不必重复上述步骤。
