| --- | --- |
| 功能版本 | 使用流计算、虚拟表、数据订阅、权限与加密的用户 |

## 1. 版本亮点

- 数据传输支持 SASL 和资源管控，数据存储支持透明加密。
- 支持多因素认证、多种登录安全策略、基于 RBAC 的权限，以及分级审计。
- 新增 `SM4_ENCRYPT`、`SM4_DECRYPT`、`AES_ENCRYPT`、`AES_DECRYPT`、摘要、脱敏和 Base64 函数。
- 流计算的事件窗口支持子事件窗口。窗口查询可以只选择 `_wstart`、`tbname` 等伪列。
- 支持把 JSON 解析后入库。taosExplorer 支持 OAuth 2.0 / OIDC。taosAdapter 可以配置 SQL 拦截规则。
- 虚拟表最大列数提高到 32767。`STMT2` 可以查询虚拟表。

## 2. 新特性

### 2.1 安全与权限

- 数据传输支持 SASL 和资源管控。数据存储支持全量透明加密，并支持加密算法管理。
- 支持多因素认证和多种登录安全策略，包括登录失败策略。
- 支持基于 RBAC 的权限架构，以及分级审计和权限管控。
- 审计日志可以记录查询、删除等操作。
- 新增身份鉴别函数。
- 新增 `SM4_ENCRYPT`、`SM4_DECRYPT`、`AES_ENCRYPT`、`AES_DECRYPT`、`MD5`、`SHA`、`SHA1`、`SHA2`、`MASK_FULL`、`MASK_PARTIAL`、`MASK_NONE`、`FROM_BASE64`、`TO_BASE64`。

### 2.2 流计算与查询

- 流计算事件窗口触发支持子事件窗口。事件窗口只在满足 `true_for` 时生成窗口开启通知。
- 流计算支持 `INTERP` 和 `PERCENTILE`。
- 窗口查询不必包含聚合函数，可以只选择 `_wstart`、`tbname` 等伪列。
- 状态窗口可以用 `zeroth_state` 指定零状态。处于该状态的窗口跳过计算和输出。
- TDgpt 支持 `DTW`、`DTW_PATH`、`TLCC` 等行相关性分析函数。

### 2.3 接入、连接与安装

- 支持解析 JSON 并入库。
- taosX 支持高可用和 Kafka 负载均衡。
- taosAdapter 可以注册和查询实例，连接中带有连接器类型和版本，并支持自定义 SQL 拦截规则。
- C WebSocket 支持 TLS 扩展参数。
- taosExplorer 支持 OAuth 2.0 / OIDC 单点登录。
- Linux tar 包支持非 root 用户安装，并可指定安装路径。
- 新增 Rust 连接器性能测试工具。

## 3. 优化

- 虚拟表最大列数提高到 32767。虚拟超级表上聚合函数和选择函数的查询更快。
- 新增 `WIN_OPTIMIZE_BATCH`、`WIN_OPTIMIZE_SINGLE`，用于虚拟表状态窗口。
- `STMT2` 可以查询虚拟表。写入时增加布尔类型校验。
- `COMPACT` 支持 `FORCE`。
- 修改标签列后，执行 `RELOAD TOPIC` 即可让订阅按新标签生效，不必重建 topic。标签值没有变化时，更新子表标签立即返回。
- `SHOW CONNECTIONS` 增加客户端版本。`SHOW VGROUPS` 增加 `is_ready`。
- TDgpt 的 `ins_anodes_full` 增加状态和说明，用于查看模型和算法状态。
- 执行计划可以显示标签索引。
- 设定全局时区，降低并发查询和写入时的时间转换锁竞争。
- 降低流计算读取触发数据和计算数据的资源消耗。
- 集群间通信增加时钟检查。
- taosc 在日志目录没有写权限时，初始化失败的错误信息更明确。
- taosmqtt 退出时释放资源。OPC-DA 采集和重连更稳定。
- 非聚合查询不能再按聚合函数排序。超级表的 `STATE_WINDOW`、`COUNT_WINDOW`、`EVENT_WINDOW` 不能使用重复时间戳。

## 4. 问题修复

### 4.1 严重问题

- 流计算重算触发数据时没有使用最新的 WAL 版本，计算结果错误。新版流计算自 `v3.3.7.0` 发布。影响版本：`v3.3.7.0` 至本版本之前。
- 流计算 `FILL_HISTORY` 计算历史数据失败。影响版本：`v3.3.7.0` 至本版本之前。
- 流计算读取失败后，后续计算任务一直等待。影响版本：`v3.3.7.0` 至本版本之前。
- 流计算触发建表时如果没有携带写入数据，进程崩溃。影响版本：`v3.3.7.0` 至本版本之前。
- 流计算子查询中，关联查询包含 `tag == %%n` 一类条件时进程崩溃。影响版本：`v3.3.7.0` 至本版本之前。
- `STMT2` 自动建表时表名过长导致崩溃。`STMT2` 自 `v3.3.3.0` 发布。影响版本：`v3.3.3.0` 至本版本之前。
- 通过 `STMT2` 查询时，`dbname` 和 `tbname` 都是占位符会导致查询卡住。影响版本：`v3.3.3.0` 至本版本之前。
- stmt 查询返回后回调没有被调用，taosAdapter 崩溃。影响版本：所有版本。
- 虚拟表引用子表中同名但类型不同的列时，查询崩溃。虚拟表自 `v3.3.6.0` 发布。影响版本：`v3.3.6.0` 至本版本之前。
- 多个虚拟表的列使用同一原始表列时，结果不正确。影响版本：`v3.3.6.0` 至本版本之前。
- 查询虚拟超级表报 Invalid value in client。影响版本：`v3.3.6.0` 至本版本之前。
- 开启缓存时，值为 NULL 的 `DECIMAL` 落盘偶发崩溃。影响版本：所有版本。
- `INSERT INTO ... SELECT` 把数据写到错误的 dnode，并报 Vnode is closed。影响版本：所有版本。
- 嵌套查询在逆序、无排序或非时间主键排序时，结果错误。影响版本：所有版本。
- `STATE_WINDOW` 与 `PARTITION BY` 一起使用时结果错误。影响版本：所有版本。
- 从 `v3.3.6.32` 至 `v3.3.6.36` 升级到 `v3.3.8.6` 至 `v3.3.8.10` 时，数据加载异常。
- 查询内存管控存在崩溃隐患。影响版本：所有版本。

### 4.2 查询、订阅与写入

- `ORDER BY ABS(col)` 中，`col` 出现在结果里而不是表中时报错。
- JSON 类型标签上，`SHOW CREATE TABLE` 和 `SELECT DISTINCT tbname, json_tag_name` 的结果不符合预期。
- 嵌套查询外层 `COLS` 执行出错。
- `JOIN` 中子表时间主键为常量时，不再额外排序。
- 创建流时，输出表标签名误把反引号算进列名，与手工建的表不一致，报 Out table tag type mismatch。
- 流计算结果表已存在时，schema 和 tag 同步失败。
- 流计算通过 WebSocket 发送事件通知时可能失败。
- 流计算使用异常检测时读了错误的数据源。
- 数据订阅与 tdb 修改同时进行时出现并发问题。订阅 rawdata 失败。
- 客户端不能看到其他客户端对表结构的修改。schemaless 写入时并发改内部表结构会出错。
- `INSERT INTO` 超级表时，`tbname` 处理错误。
- `ins_vgroups` 的 `cache_load` 超过 32 位整数上限时显示为负数。
- 修改全局变量时事务不能结束。
- C WebSocket 的 `taos_stmt2_get_fields` 返回类型错误。Node.js 连接器默认不设置时区。

### 4.3 taosX 与 taosExplorer

- OPC UA 修改任务后，下载点位数据失效。点位很多时写入变慢。
- InfluxDB 没有 tag 的数据不能入库。PI 和 PI Backfill 的数据源名称含句号时失败。PI 创建任务报 Not found model in DSN。
- Kafka 提取或拆分配置里 depth 错误。列拆分结果与预期不符。单条消息超过 100 KB 时 SQL 可能超长。
- KingHistorian 实时订阅收不到数据。AVEVA Historian 写入任务配置页异常。
- taosgen 导入特殊 CSV 时异常退出。
- taosExplorer 登录错误。Grafana 12 可以导入告警面板。Explorer 默认上报监控信息。

## 5. 安全

本版本的认证、加密、权限和审计能力写在第 2 章。本版本没有单独的漏洞编号。

## 6. 升级须知

### 6.1 升级路径

直接升级、滚动升级、降级和客户端配套版本未在本页另写。

### 6.2 行为变更

- taosX 与 taosX-Agent 不能沿用旧版本配置直接升级，需要按新版本重新配置。
- 社区版与企业版不能互连。
- `SHOW TABLE DISTRIBUTED` 不支持虚拟超级表。
- 虚拟表最大列数提高到 32767。
- 超级表的 `STATE_WINDOW`、`COUNT_WINDOW`、`EVENT_WINDOW` 不再接受重复时间戳。使用重复时间戳的语句会失败。

### 6.4 关键字变更

`ALGR_NAME`、`ALGR_TYPE`、`DB_KEY`、`ENCRYPT_STATUS`、`ENCRYPT_ALGORITHMS`、`ENCRYPT_ALGR`、`IS_AUDIT`、`OSSL_ALGR_NAME`、`RELOAD`、`ROLE`、`ROLES`、`SVR_KEY`、`TOKEN`、`TOKENS`、`DRAIN`、`REBALANCE`、`XNODE`、`XNODES`。

### 6.5 系统表变更

`SHOW CONNECTIONS` 增加客户端版本。`SHOW VGROUPS` 增加 `is_ready`。`ins_anodes_full` 增加状态和说明字段。

本版本没有移除系统表。

### 6.6 依赖库变更

依赖库版本没有变化。

| 组件 | 依赖库 | v3.3.8.8 | v3.4.0.0 |
| --- | --- | --- | --- |

### 6.7 升级前操作

从 `v3.3.6` 升级到本版本时，旧流计算不能直接沿用。未删除旧流、TSMA、snode 及其数据目录时，taosd 会启动失败。步骤见 [流计算兼容性说明](../../07-stream-processing/02-instructions.md#兼容性说明)。

从 `v3.4` 以前的版本升级到本版本时，taosX 不会自动迁移已有任务。此前任务存在 SQLite 中，`v3.4` 起存在 mnode 中。升级前在 taosExplorer 中导出任务；升级后导入，再启动需要运行的任务。没有在升级前导出时，升级后的 taosExplorer 中看不到这些任务。步骤见 [从 v3.4 以前的版本升级到 v3.4.x 时迁移任务](../../12-operations-and-tooling/03-components/06-taosx.md#从-v34-以前的版本升级到-v34x-时迁移任务)。
