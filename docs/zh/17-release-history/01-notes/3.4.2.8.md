| 维护版本 | 使用流计算、虚拟表、taosX 同步与备份，或 0 级多挂载点的用户 |

## 1. 版本亮点

- taosExplorer 可以在流计算页面查看延迟、输入输出速率、历史进度、失败原因和重算记录。
- TDinsight 增加流计算观测面板，并预置流失败与重算失败告警。需要 TDengine `v3.4.2.7` 或更高版本。
- 流计算触发支持[嵌套窗口](../../07-stream-processing/01-syntax.md#嵌套窗口触发)。
- 可以用一条语句批量创建或删除虚拟表，虚拟普通表和普通表支持自有标签。
- `ALTER DATABASE` 可以动态修改 `MAXROWS`。
- 0 级配置了多个挂载点时，新建 WAL 段可以在这些挂载点之间轮询分配。

## 2. 新特性

### 2.1 流计算

- taosExplorer 流计算页面展示流任务的延迟、输入输出速率、历史进度、失败原因和重算记录。
- TDinsight 新增流计算观测面板，并预置流失败与重算失败告警。告警可经通知策略转发到钉钉等渠道。需要 TDengine `v3.4.2.7` 或更高版本。
- 流计算触发支持嵌套窗口。`WINDOW` 中可以组合 2 至 8 层窗口，外层上下文变量驱动内层计算。说明见 [嵌套窗口触发](../../07-stream-processing/01-syntax.md#嵌套窗口触发)。
- 流计算任务第一次因错误停止时，向 taosKeeper 上报失败指标。

### 2.2 虚拟表

- `DROP VTABLE` 可以一次删除多张虚拟普通表或虚拟子表，包括跨库对象。
- 一条 `CREATE VTABLE` 可以创建多个虚拟子表。
- 虚拟普通表和普通表支持自有标签列，可以用 `CREATE`、`ALTER` 定义和维护，并出现在 `SHOW CREATE TABLE`、`SHOW TAGS` 和 `ins_tags` 中。说明见 [虚拟表](../../05-tdengine-sql/02-ddl/04-virtualtable.md)。

### 2.3 存储与运维

- `ALTER DATABASE` 可以动态修改 `MAXROWS`。之后执行 `COMPACT FORCE`，已有 fileset 按新的块大小生效。
- 新增 [`walMultiMountEnable`](../../12-operations-and-tooling/03-components/01-taosd.md#walmultimountenable)。0 级配置多个挂载点时，新建 WAL 段在挂载点之间轮询分配。默认 `1`。可通过 `ALTER ALL DNODES` 动态修改，只影响之后新建的段。该参数自 `v3.4.2.7` 引入。
- 新增 `FLUSH MNODE` 和 `taosd -fMnode`。sdb 的 JSON 导出和导入可以在故障场景下离线修改全局参数等元数据。

## 3. 优化

- taosX TMQ 同步在重建 consumer 时，对 subscribe 做有限次重试，降低源端短时重启导致整次任务失败的可能。
- taosX 导入数十万个 CSV 文件时，可以配置解析和建任务过程，降低超时和随文件数下降的导入速度。
- taosX-Agent 可靠写入 ACK 增加协议和 UUID v7 身份基础。本版本仍走原写入路径，Kafka offset 行为不变。
- 流计算手动重算失败时不再让整条流停止。未完成的重算请求可以在重启后恢复。
- 数据订阅在心跳定时器超过两个周期没有上报时，由 poll 线程补发心跳，降低消费者被误判离线的可能。
- 改进 `PARTITION BY` 分组缓存和落盘策略，降低高基数、小分组场景下因内存页不足造成的磁盘读写。
- taosX 强化 Kafka 消费和下游写入的超时处理，并补充连接池与连接器观测指标。
- taosX 接入 MySQL 时，示例查询和历史同步不再发出超过查询间隔的大窗口 SQL。

## 4. 问题修复

### 4.1 严重问题

- taosX 从 MySQL 实时同步时，delay 会同时回拨窗口起点，查询窗口重叠，数据重复写入。影响版本：所有版本。已经同步的数据需要核对是否重复。
- taosX OPC UA 在「选择数据点位」模式下，点位 id 含 `::` 或 `,` 时被截断，部分点位没有数据。影响版本：所有版本。已经采集的点位需要与源端核对。
- taosX 备份任务在完成判定时查询非属主 vgroup 的位点，任务一直不结束。影响版本：所有版本。
- 流计算外部窗口复用结果块时可能越界写入，taosd 崩溃。新版流计算自 `v3.3.7.0` 发布。影响版本：`v3.3.7.0` 至 `v3.4.2.5`。
- 流计算启用 `nodelay_create_subtable` 时，分组结果子表在 `information_schema` 和 `SHOW TABLES` 中可见，但 `SELECT` 报表不存在。影响版本：`v3.3.7.0` 至 `v3.4.2.5`。
- `RECALCULATE STREAM` 时，用户指定的 `FROM` / `TO` 被运行时边界裁剪，部分数据没有参与重算。影响版本：`v3.3.7.0` 至 `v3.4.2.5`。需要重算的流请在升级后重新执行。
- 集群 balance 期间 reader 任务短暂不存在时，流计算任务失败。影响版本：`v3.3.7.0` 至 `v3.4.2.5`。
- `STMT2` 或 WebSocket 查询使用 `tbname = ?` 或 `tbname IN (?)` 时读到占位符而不是绑定的表名，路由到错误的 vgroup，结果为空。`STMT2` 自 `v3.3.3.0` 发布。影响版本：`v3.3.3.0` 至 `v3.4.2.5`。
- 含转义字符的 XNode 任务按反转义前的长度落库，升级后尾部空字节导致 JSON 解析失败，任务无法加载。XNode 自 `v3.4.0.0` 发布。影响版本：`v3.4.0.0` 至 `v3.4.2.5`。
- 离线副本通过 snapshot 恢复后没有应用 leader 的 `KEEP`，保留策略不一致，过期数据不能按新策略清理。影响版本：所有版本。
- `LEASTSQUARES` 跨多个 vgroup 时，斜率和截距不稳定。影响版本：所有版本。
- `REGEXP_IN_SET` 用 `NCHAR` 列做分隔符，或传入空 `NCHAR` 时，结果不正确。影响版本：所有版本。
- RESTful 接口上的 `TO_CHAR` 等时区函数把 `+0800` 这类 ISO 8601 偏移按 POSIX 解析，时区结果偏差。影响版本：所有版本。
- 虚拟超级表在引用关系变化后，查询偶发 Invalid parameters。虚拟表自 `v3.3.6.0` 发布。影响版本：`v3.3.6.0` 至 `v3.4.2.5`。
- 虚拟超级表在源表 VGroup 路由过期时，重试没有刷新源库元数据，偶发 No valid epSet。影响版本：`v3.3.6.0` 至 `v3.4.2.5`。
- 存在未完成事务时执行 `SHOW TRANSACTIONS`，taosd 可能崩溃。影响版本：所有版本。
- 数据库 `minRows` 与 `maxRows` 相等时，`SHOW DISK_INFO` 或 `SHOW TABLE DISTRIBUTED` 可能导致 taosd 崩溃。影响版本：所有版本。

### 4.2 查询与时区

- `INTERP` 等语句通过视图或预处理语句执行时，误报函数冲突。
- 时区错误不再返回未替换的 `Invalid timezone: '%s'`。文件描述符耗尽等系统错误不再被报成非法时区。
- `UTC0`、`UTC8` 这类省略正号的 POSIX 偏移可以被接受。`UTC0` 表示 `UTC+0`。

### 4.3 流计算与写入

- `STMT2` 在删除并用同名重建超级表后仍使用旧缓存，写入报 Table does not exist。
- `STMT2` 绑定 `DECIMAL` 时，只绑定部分列或列 ID 不连续会误用其他列的精度，报 Decimal value overflow。
- XNode 任务的创建用户被删除后，root 或有权限的用户无法删除或更新该任务。
- WebSocket TMQ 客户端收到错误应答时反序列化失败，请求挂起或报错。
- Rust WebSocket 连接器关闭连接时未清理通道中尚未处理的请求。

### 4.4 taosX、taosdump 与 taosExplorer

- taosX MySQL 任务停止后再启动时，不能从断点继续，而是从配置的起始时间重新同步。
- taosdump 只恢复 ext-meta 时，没有先创建全部数据库再执行流和 Topic 的 DDL，跨库依赖恢复会随机失败。该能力自 `v3.4.2.5` 提供。影响版本：`v3.4.2.5`。
- taosExplorer：编辑普通表时不显示字段；普通表详情把复合主键显示成标签，并错误展示超级表和标签区域；数据写入预览里，子表名模板列被 cast 为空时丢掉前后缀；按指定备份点恢复时因任务名缺失或 DSN 编码错误而失败；跨域策略过严，导致 IDMP 等不同源的 HTTP 预检失败、WebSocket 握手被拒绝。

## 6. 升级须知

### 6.1 升级路径

- 支持直接升级的源版本：`v3.3.7` 及后续版本。
- 是否支持滚动升级：支持，范围为 `v3.4.2.0` 至 `v3.4.2.8`。
- 是否支持降级或回滚：支持，范围为 `v3.4.2.0` 至 `v3.4.2.8`。
- 客户端与连接器的最低配套版本：`v3.4.2.0`。

### 6.2 行为变更

- 流计算手动重算失败时，不再让整条流停止。
- `UTC0` 表示 `UTC+0`。`UTC0`、`UTC8` 这类省略正号的写法不再被拒绝。
- 时区错误会返回格式化后的信息，不再把未替换的 `Invalid timezone: '%s'` 交给应用。文件描述符耗尽不再报成非法时区。
- taosExplorer 的 `cors` 控制 HTTP 跨域。`cors` 为 true 时允许任意 Origin，默认 false。`allowedOrigins` 只约束跨主机的 WebSocket 握手，不再影响 HTTP。`cors` 为 false 时，默认同主机（任意端口）和 loopback 可以访问。
- `information_schema.ins_stream_recalculates` 新增 `request_time`、`message` 列。按列名读取的应用不需要修改。

### 6.3 配置参数变更

| 参数 | 作用 |
| --- | --- |
| walMultiMountEnable | 0 级多个挂载点时，新建 WAL 段是否在挂载点间轮询。默认 `1`。可动态修改，只影响之后新建的段。自 `v3.4.2.7` 引入。 |
| cors | taosExplorer 的 HTTP 跨域开关。默认 false。为 true 时允许任意 Origin。 |
| allowedOrigins | 只约束 taosExplorer 的跨主机 WebSocket 握手，不再影响 HTTP。 |

### 6.7 升级前操作

从 `v3.3.6` 升级到本版本时，旧流计算不能直接沿用。未删除旧流、TSMA、snode 及其数据目录时，taosd 会启动失败。步骤见 [流计算兼容性说明](../../07-stream-processing/02-instructions.md#兼容性说明)。已经在 `v3.4.2.0` 及之后按新流计算重建过的集群，滚动到本版本时不必重复上述步骤。

从 `v3.4` 以前的版本升级到本版本时，taosX 不会自动迁移已有任务。此前任务存在 SQLite 中，`v3.4` 起存在 mnode 中。升级前在 taosExplorer 中导出任务；升级后导入，再启动需要运行的任务。没有在升级前导出时，升级后的 taosExplorer 中看不到这些任务。步骤见 [从 v3.4 以前的版本升级到 v3.4.x 时迁移任务](../../12-operations-and-tooling/03-components/06-taosx.md#从-v34-以前的版本升级到-v34x-时迁移任务)。已经在 `v3.4.0.0` 及之后运行、任务已在 mnode 中的集群，滚动到本版本时不必重复上述步骤。
