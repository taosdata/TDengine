发布时间：**2026-02-02**

| 版本类型 | 推荐升级对象 |
| --- | --- |
| 维护版本 | 使用 XNode、流计算、虚拟表，或从 `v3.3` 升级权限与加密的用户 |

## 1. 版本亮点

- 初始化时创建 XNode。taosX-Agent 适配 XNode 高可用。
- taosX 可以导入 Parquet 文件。
- Rust 原生连接支持 `STMT2`。
- 流计算和批查询的事件窗口、状态窗口，`true_for` 同时支持持续时间和持续条数。
- `LAG` 更名为 `FILL_FORWARD`。已有 SQL 需要改名。
- 使用默认密码的 root 在登录后必须修改密码。可用 `allowDefaultPassword` 保留旧行为。

## 2. 新特性

- 服务初始化时创建 XNode。taosX-Agent 适配 XNode 高可用。XNode 任务增加 `created_by` 和 `labels`。
- taosX 支持导入 Parquet。MQTT Topic 可以使用任意字符。
- taosAdapter 为 STMT 记录 SQL。Rust 原生连接支持 `STMT2`。STMT 查询的 `INTERVAL` 可以参数绑定。
- 事件窗口和状态窗口的 `true_for` 可以同时判断持续时间和持续条数。
- 可以用 `CREATE TOTP_SECRET` 创建 TOTP 密钥。
- taosExplorer 许可证页展示机器码，便于复制。
- 同时支持 IPv4 和 IPv6。

## 3. 优化

- SQL 报错信息更明确。
- 登录校验要求仍使用默认密码的 root 修改密码。
- 增加用户令牌相关通知。可以更新数据加密密钥的过期时间和过期策略。
- 支持从旧版本数据加密集群升级到新版本。加密覆盖 bse 等文件。加密生效后，不能再通过改配置文件绕过。
- 处理从 `v3.3` 到 `v3.4` 的权限兼容，并完善视图和审计的权限控制。用户可以修改权限控制。
- 流计算定时触发的通知增加开始时间和结束时间，字段名仍是 `windowStart`、`windowEnd`。
- 流计算查询里，`_twstart` 等占位符可以出现在 `ORDER BY` 中。虚拟表标签过滤的计算延迟降低。
- 虚拟表可引用的原始表数量上限从 1000 调整为 2000。只引用一张原始表时，`COLS` 与 `LAST` 的查询更快。

## 4. 问题修复

### 4.1 严重问题

- 流计算在 mnode 切主后，心跳处理不当导致进程崩溃。影响版本：`v3.4.0.0`。
- `xnoded` 关闭逻辑导致停止 taosd 时偶发卡住。XNode 自 `v3.4.0.0` 发布。影响版本：`v3.4.0.0`。
- 状态窗口处理多分组时，个别分组窗口内全是 NULL，计算结果错误。影响版本：所有版本。
- 删除流计算结果子表并重建后，计算结果异常。影响版本：`v3.3.7.0` 至 `v3.4.0.0`。
- 流计算 `true_for` 在乱序写入时触发逻辑错误。影响版本：`v3.3.7.0` 至 `v3.4.0.0`。
- 流计算调用 `CONCAT` 的结果错误。影响版本：`v3.3.7.0` 至 `v3.4.0.0`。
- STMT 大量并发写入时，客户端可能崩溃。影响版本：所有版本。
- `GROUP_CONCAT` 与 `COUNT_WINDOW` 一起使用时崩溃。影响版本：所有版本。
- 虚拟表 `SHOW CREATE TABLE` 的结果错误。影响版本：`v3.3.6.0` 至 `v3.4.0.0`。

### 4.2 查询、权限与其他

- 不带 `FROM` 的子查询做 `JOIN` 时返回错误。
- 最外层关联查询带 `LIMIT` 但没有 `ORDER BY` 时，`LIMIT` 不生效。
- 多级存储迁移任务的定时执行时间不准确。
- 密码重用限制的默认时间配置错误。
- 删除用户后，该用户已经创建的订阅无法取消。
- UDF 初始化失败时内存泄漏。重复的报错信息已去掉。
- InfluxDB 迁移在特殊情况下出现空指针。迁移语句中的反斜杠被当成错误语法。
- taosKeeper 不支持含特殊字符的密码。
- AVEVA Historian 按迁移方式采集异常。MySQL 任务在数据很少时可能阻塞。
- 创建 OPC 数据源任务报错。taosX 原生接口上的 TMQ 错误信息不兼容。
- `v3.4.0.0` 的 taosExplorer 设置用户权限失败。

## 5. 安全

### 5.1 漏洞修复

无。

### 5.2 安全加固

- 仍使用默认密码的 root 登录后必须修改密码。首次启动时可以用 `allowDefaultPassword` 允许默认密码。
- 可以设置数据加密密钥的过期时间和过期策略。加密生效后，不能再靠修改配置文件改变加密状态。

## 6. 升级须知

### 6.1 升级路径

直接升级、滚动升级、降级和客户端配套版本未在本页另写。

### 6.2 行为变更

- `LAG` 更名为 `FILL_FORWARD`。参数和行为不变。已有语句里的 `LAG` 需要改为 `FILL_FORWARD`。
- `allowDefaultPassword` 只在服务端第一次启动时起作用。为 `1` 时，默认用户可以使用默认密码。否则默认用户登录后必须修改密码。

### 6.3 配置参数变更

| 参数 | 作用 |
| --- | --- |
| allowDefaultPassword | 仅首次启动生效。为 `1` 时默认用户可以使用默认密码，否则登录后必须修改密码。 |

### 6.4 关键字变更

无。

### 6.5 系统表变更

无。

### 6.6 依赖库变更

依赖库版本没有变化。

### 6.7 升级前操作

从 `v3.3.6` 升级到本版本时，旧流计算不能直接沿用。未删除旧流、TSMA、snode 及其数据目录时，taosd 会启动失败。步骤见 [流计算兼容性说明](../../07-stream-processing/02-instructions.md#兼容性说明)。已经在 `v3.4.0.0` 按新流计算运行的集群，滚动到本版本时不必重复上述步骤。

从 `v3.4` 以前的版本升级到本版本时，taosX 不会自动迁移已有任务。此前任务存在 SQLite 中，`v3.4` 起存在 mnode 中。升级前在 taosExplorer 中导出任务；升级后导入，再启动需要运行的任务。没有在升级前导出时，升级后的 taosExplorer 中看不到这些任务。步骤见 [从 v3.4 以前的版本升级到 v3.4.x 时迁移任务](../../12-operations-and-tooling/03-components/06-taosx.md#从-v34-以前的版本升级到-v34x-时迁移任务)。已经在 `v3.4.0.0` 及之后运行、任务已在 mnode 中的集群，滚动到本版本时不必重复上述步骤。
