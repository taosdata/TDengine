## 1. 版本亮点

- **流计算分层规则与跨源闭环**：一条流按设备路径同时汇总产线、车间和工厂。事件窗口支持多级开始条件和嵌套窗口，并按流自己的时区做自然月、季、年结算。外部工单和质检表可以直接驱动流。运行状态可在系统表、taosExplorer 和 TDinsight 中查看；告警通知异步发送，切主或虚拟表引用变更后流继续输出。
- **虚拟表继承与跨层引用**：虚拟超级表可以从父模型继承列和标签，列和标签也可以逐层引用其他虚拟表。虚拟子表可以带自有列和标签，并支持批量创建和删除。外部列可以先过滤再按时间戳对齐，一张表可以同时引用不同时间精度的库。引用失效时，报错点名失效对象和完整引用链。
- **查询关联与子查询**：普通 `JOIN` 可以按业务列、范围或组合条件关联，不必强制主时间戳等值。它可以和 `ASOF JOIN`、`WINDOW JOIN` 写在同一条 SQL 里，两侧可以是子查询或虚拟表。标量子查询可以引用外层当前行，窗口查询可以输出原始列和序列结果。`TEXT` 和 `FILE` 可以直接参与查询。
- **联邦查询**：同一条 SQL 可以联合查询 MySQL、PostgreSQL、InfluxDB 和本地数据，窗口、聚合和 `INTERVAL` 可以下推到外部数据源。该能力默认关闭，使用前需要显式开启。
- **安全修复**：拒绝会导致服务崩溃或越界读写的畸形输入，并修复同步模块中的已知漏洞。Grafana 数据源插件修复 30 项依赖漏洞，XNode 任务和作业中的 DSN 可以加密后再展示。

## 2. 新特性

### 2.1 查询

- `ASOF JOIN` 和 `WINDOW JOIN` 可以使用虚拟表或子查询作为输入。`WINDOW JOIN` 可用 `WINDOW_TIME` 指定两侧时间列。
- 普通 `JOIN` 可以按 SQL 括号和结合顺序与 `ASOF JOIN`、`WINDOW JOIN` 嵌套。流计算查询同样支持。
- 等值 `JOIN` 在输入无序时使用 Hash Join。已经按连接键有序的输入仍使用 Merge Join。需要稳定顺序时必须写 `ORDER BY`。
- 支持标量相关子查询。没有匹配行时结果为 `NULL`，返回多行或多列时报错。
- `DELETE` 的 `WHERE` 支持按普通列过滤，可与时间范围和标签条件用 `AND` 组合。复合主键表、`SECURE_DELETE`，以及时间、标签与普通列之间的 `OR` 仍不支持。
- 新增 `BIT_CHANGES`、`VALUE_CHANGES`，以及时间加权聚合 `TWAVG`、`TWSUM`、`TWVAR`。它们可用于查询和流计算。
- 支持 `CSUM(expr) OVER (PARTITION BY ... ORDER BY ...)`，按分区和指定顺序保留每一行的累计和。
- 单数据源虚拟子表和虚拟普通表支持精确 `PERCENTILE`。
- 外部窗口支持 `DIFF`、`CSUM`、`MAVG`、`LAG`、`LEAD`，以及 `TOP`、`BOTTOM`、`SAMPLE`、`HISTOGRAM`。规则与其他时间窗口一致。说明见 [外部窗口](../../05-tdengine-sql/04-data-query/04-distinguished.md#外部窗口)。
- `SHOW TABLE DISTRIBUTED` 指定超级表时，汇总其全部子表在各 vnode 上的压缩数据块大小。同一结果也可从 `INS_TABLE_FIXED_DISTRIBUTED` 查询。统计只含 data 文件中的数据块。
- 支持通过 `CREATE EXTERNAL SOURCE` 注册外部数据源。说明见 [联邦查询](../../05-tdengine-sql/04-data-query/06-federated-query.md)。
- 提供 Spark JDBC 方言 `com.taosdata.spark:TDengine-spark-dialect:1.0.0`。PySpark 注册后可通过 WebSocket 访问 TDengine。

### 2.2 流计算与虚拟表

- 流计算支持 `INNER JOIN` 与 `LEFT JOIN` 多层嵌套。
- 流计算可以用引用 MySQL、PostgreSQL、InfluxDB 列的虚拟表作为触发表，并与本地列混合、按时间戳合并。此类流暂不支持 `FILL_HISTORY` 和 `FILL_HISTORY_FIRST`。
- `STREAM_OPTIONS(CONFIG)` 可以固化时区和一周起始日，并支持含季度的自然时间单位。
- 流计算支持多级嵌套子事件。
- 虚拟子表可以通过 `CREATE VTABLE` 和 `ALTER VTABLE` 增加自有列和自有标签。
- 普通表和虚拟普通表的标签可以作为虚拟表 tag-ref 源，并支持链式引用。
- 虚拟表引用 MySQL、PostgreSQL 外部列时可以加 `WHERE` 过滤。
- 虚拟表可以引用不同时间精度（毫秒、微秒、纳秒）数据库中的表，查询时自动转换时间戳。
- `ALTER STABLE RENAME COLUMN` 可以修改超级表和虚拟超级表的数据列名。`ALTER TABLE ... RENAME TAG` 可以修改普通表和虚拟普通表的标签列名。

### 2.3 备份、XNode 与写入

- 支持集群和数据库级全量备份及离线恢复，覆盖 mnode、snode 和 vnode（含流检查点）。新增 `CREATE FULL BACKUP`、`SHOW BACKUPS`、`KILL BACKUP`，以及 `taosd --restore`。增量备份和只备份指定库在本版本尚未实现。
- 新增 `RESTART XNODE`，重启当前 mnode leader 所在节点上的 xnoded。
- 可以开启 XNode DSN 保护。`SHOW XNODE TASKS` 和 `SHOW XNODE JOBS` 中的敏感字段显示为 `******`，运行时下发使用信封加密。`ALTER` 提交 `******` 表示保留原值。
- taosX 新增 `archive` 子命令，用于查看和导出 archive、cache 文件。
- taosX 的 MySQL 数据源支持任务级 Job（`job_id=-1`）使用持久化 checkpoint。关闭「双竖线字符串连接」和「禁止存储引擎替换」后，可以通过 MySQL 协议从 Apache Doris 同步数据。
- taosExplorer 可以配置 taosX 的 `-T` 转换动作，例如超级表和子表重命名与映射。
- JDBC WebSocket 连接新增 `stmtCacheSize`，缓存 PreparedStatement。默认 5，高效写入模式默认 2，`0` 表示关闭。
- taosAdapter 支持 InfluxDB 1.x 的 ping 接口。兼容客户端可以通过 `GET` 或 `HEAD /influxdb/v1/ping` 检查服务是否可用。
- taosgen 提供 gRPC ingress 写入接口，外部程序推送标准化数据后由 STMT2 拼批写入。
- 二级压缩可以通过环境变量挂载可插拔的硬件加速 zlib、zstd、lz4 库。

## 3. 优化

### 3.1 查询

- `HAVING` 可以在没有 `GROUP BY`、`PARTITION BY` 或窗口时使用。
- 关联查询的 `ON` 条件支持单侧表达式等值、有限的整数与时间偏移、范围比较和组合条件。
- 子查询排序与 `JOIN` 时间条件不一致时，按实际时间条件返回结果。
- 按 tbname 分组的 `INTERVAL` 查询走快速路径。分组 last 查询批量读取缓存。符合条件的普通查询可以从副本读取。
- 超级表 `INTERP` 覆盖按标签或普通列分区的场景，并减少按子表输出时的数据传输，提升大规模断面插值性能。
- 分区状态窗口减少大量小分区的切换开销，并保持多 vnode 下分区内的时间顺序。
- 超级表查询中 `tbname` 等值条件走名称索引。
- 增加 `FAST_INTERVAL` 和 `EX_INTERVAL` 两个 Hint，用于符合条件的固定窗口 `INTERVAL`。
- NCHAR 与字符串常量比较按客户端字符集解析。
- `CREATE SMA INDEX` 不再支持。已有 SMA 对象仍可查询和删除。
- Linux 上联邦查询在已有目录找不到三方库时，再从 `/usr/local/lib` 加载。随安装包提供的库仍优先。

### 3.2 流计算与虚拟表

- 流计算在源 vnode 切主或 vgroup 重新分布后继续输出正确结果。虚拟表流在切主后重新加载表信息。未映射源列的虚拟表流不再反复重新部署。
- 流运行期间虚拟表元数据变更时，触发器在线更新引用和子表列表，流保持运行。
- 流计算写入已有超级表时，只校验输出列与保存列的顺序、名称和类型。
- 非 `ON_FAILURE_PAUSE` 的事件通知改为异步批量发送。
- 新增 `streamTriggerMaxPendingParams`，限制触发器积压的待计算参数。
- external window 的多分组批处理支持 `JOIN` 和嵌套窗口。`COUNT_WINDOW` 等触发下，含派生聚合的计算子查询可以走 external window。
- 关联维表的嵌套窗口流按批读取维表，并在预算内用等值键过滤连接数据。
- 元数据事务可以包含创建流、删除流和更多表结构变更。
- 虚拟表引用的源表或源列失效时，查询和 `SHOW VTABLE VALIDATE` 点名失效对象和引用链。源列已删除的虚拟超级表不再静默返回空结果。
- 虚拟表上的联邦查询可以把窗口、聚合和 `INTERVAL` 下推到外部数据源。

### 3.3 存储与集群

- 提升 split vgroup 执行效率，降低对在线写入的阻塞。
- 改进 `REDISTRIBUTE VGROUP` 与写入、流计算、订阅、虚拟表查询并发时的处理。
- `CREATE DATABASE` 在全部 vgroup 选出主之后才返回，避免随后 `SHOW CLUSTER ALIVE` 误报部分可用。
- `BALANCE VGROUP LEADER` 拆成默认的随机再平衡和 `FORCE` 强制均匀。强制方式在副本落后过多时可能暂时选不出主。
- 强制均衡增加约 2 分钟的超时回退，避免落后副本长期无法选出主。
- 多副本切主后的集群恢复时间缩短。
- 修改数据库副本数时可以用 `PARALLEL` 控制并发。`restore dnode` 新增 `parallel`。
- 新增 `compactSpeedLimitMB`，限制 `COMPACT` 写盘速度。`0` 表示不限制。
- 新增 `snapshotMediumOnLag`。默认关闭。打开后，已有数据但落后的副本用文件级增量快照追赶。
- BLOB 单值上限从 4MB 提升到 16MB。Python、Node.js 连接器和 taosX 支持该上限，并修复 Python 读取超过 64KB、Node.js 绑定较大 BLOB 失败的问题。
- 复合主键支持 `TIMESTAMP` 列。
- Last Cache 的 RocksDB 参数可通过 `taos.cfg` 中的 `sLastCache*` 配置，并新增 `information_schema.ins_last_cache_stats`。
- `SHOW VARIABLES` 和 `SHOW LOCAL VARIABLES` 增加 `reboot` 列，表示该项已修改、需要重启才生效。
- 慢查询、UDF、MQTT 和 XNode 日志文件名统一为 `taos` 前缀。`logKeepDays` 可以清理过期慢查询日志。
- taosd 为迁移、compact、选主、流计算、订阅和虚拟表 DDL 输出 `[KEYOP]` 日志。
- 支持免费许可，并新增系统变量 `registerEmail`。
- 社区版启动时按操作系统白名单做交叉校验，并支持 Rocky Linux 和 AlmaLinux。执行专有功能时返回带功能名的错误。

### 3.4 写入、订阅与客户端

- STMT2 在服务端执行错误后可以继续复用同一语句。`taos_stmt2` 支持 `UPDATE` 参数绑定。
- CSV 建表和导入支持 UTF-8 BOM。非 UTF-8 BOM 会被拒绝。
- 表不存在等重试只刷新表元数据，不再频繁执行 `USE`。
- 错误码、SQL 提示、客户端日志和命令行工具修正英文拼写与语法，错误码数值不变。
- Windows 上 `taos` 支持 Tab 补全。`libtaos` 优先加载同目录的 `taosnative.dll` 和 `taosws.dll`。
- JDBC WebSocket 支持 `setTimezone` 和 `getTimezone`。参数绑定支持数值类型自动转换。
- Rust 连接器在 `adapter_ha` 模式下按连接选择 taosAdapter，并随集群注册表刷新故障转移地址。
- 数据订阅在 vnode 重分布时自动 rebalance。
- TMQ 消费宽表时，只在表结构变化后刷新投影列宽。

### 3.5 taosX、XNode 与 taosExplorer

- 已注册到一个集群的 taosX 不能再被另一个集群接管。
- taosX 的 MSSQL、Oracle 和 MongoDB 数据源使用与 MySQL、PostgreSQL 相同的写入确认流程。任务取消时不推进检查点。
- taosX 任务启动时，若绑定的 XNode 不存在或不可用，会改试其他可调度节点。
- XNode 任务和作业在 xnoded、taosd 或 Agent 重连后按期望状态恢复。默认开启，可用 `--auto-resume` 或 `XNODED_AUTO_RESUME` 关闭。
- taosX 和 XNode 增加 CPU、RPC、队列、下游写入和持久化缓冲等指标。
- archive 和 cache 改为带版本号的帧格式，并按失败原因去重。旧文件仍可读。
- taosExplorer 支持备份页的 S3 连通性测试、taosX-Agent 地址保存，以及超长文本的单行截断提示。
- taosExplorer 的 Tools 页面与 Programming 卡片对齐，并补充工具说明。SQL 结果区的 Export 与 Run、Format 一样使用文本按钮。
- TDgpt 镜像把 `model` 和 `model_venvs` 挂到宿主机，升级镜像不再覆盖已经添加的模型。
- taosX 和 Java 插件的默认安装包不再包含 OpenTelemetry 与 Swagger UI，需要时再启用。
- taosgen 的 WebSocket 写入支持断线重连，并输出重试和恢复日志。

## 4. 问题修复

### 4.1 严重问题

- `COUNT(DISTINCT)` 与普通聚合混用时结果不稳定，该问题在 `v3.4.2.10` 和 `v3.4.3.0` 已修复。`PARTITION BY` 加 `INTERVAL` 仍把各分区折成一行；按分区去重的修复不在 `v3.4.3.3` 中。聚合 `DISTINCT` 自 `v3.4.2.0` 起。影响版本：`v3.4.2.0` 至 `v3.4.3.3`。（[#35495](https://github.com/taosdata/TDengine/issues/35495)）
- `COUNT(DISTINCT)` 误用按标签计数优化，`GROUP BY` 结果混入时间过滤范围外的数据。影响版本：`v3.4.2.0` 至 `v3.4.2.11`。（[#35508](https://github.com/taosdata/TDengine/issues/35508)）
- 内存池 session 空闲链表并发异常时，同一 session 被重复分配并销毁，taosd 崩溃。影响版本：`v3.3.5.0` 至 `v3.4.2.8`。（[#35485](https://github.com/taosdata/TDengine/issues/35485)）
- 动态超级表 Join 补列按行数而不是块容量分配，导致堆损坏和 taosd 崩溃。影响版本：`v3.3.6.0` 至 `v3.4.2.10`。（[#35509](https://github.com/taosdata/TDengine/issues/35509)）
- 查询内存分配失败时，清理空的子任务上下文导致 taosd 崩溃（[#35468](https://github.com/taosdata/TDengine/issues/35468)、[#35559](https://github.com/taosdata/TDengine/issues/35559)）。影响版本：`v3.4.0.0` 至 `v3.4.3.2`。
- 整数列上 `FILL_FORWARD` 按 8 字节写入，超出列宽并破坏相邻内存。影响版本：`v3.4.1.0` 至 `v3.4.3.2`。（[#35550](https://github.com/taosdata/TDengine/issues/35550)）
- 将列压缩改为 TSZ 后写入再查询，taosd 崩溃。TSZ 列的编码必须为 `DISABLED`。影响版本：`v3.3.0.0` 至 `v3.4.2.9`。（[#35475](https://github.com/taosdata/TDengine/issues/35475)）
- 普通表和虚拟普通表执行 `SET TAG` 时可能崩溃，标签值未提交，查询返回 `NULL`。影响版本：`v3.4.2.12`。（[#35505](https://github.com/taosdata/TDengine/issues/35505)）
- 虚拟表列声明宽度小于源列时越界写入，taosd 崩溃。现在按源列实际宽度分配缓冲；无法放宽的超宽值返回 `Query buffer limit has reached`。影响版本：`v3.3.6.0` 至 `v3.4.3.0`。（[#35570](https://github.com/taosdata/TDengine/issues/35570)）
- 虚拟表上带时间范围的 `LAST` 可能报 `Table schema is old`，或返回错误列值。影响版本：`v3.4.2.3` 至 `v3.4.3.0`。（[#35568](https://github.com/taosdata/TDengine/issues/35568)）
- 对没有精度扩展的联邦 MySQL `DECIMAL` 列执行 `DESCRIBE` 时，taos 和 taosAdapter 崩溃。影响版本：`v3.4.2.0` 至 `v3.4.2.13`。（[#35534](https://github.com/taosdata/TDengine/issues/35534)）
- 流计算读取虚拟表时，重复的空心跳回复可能导致 taosd 崩溃。影响版本：`v3.4.0.0` 至 `v3.4.2.12`。（[#35502](https://github.com/taosdata/TDengine/issues/35502)）
- 流计算在外部窗口零行结算时，组别名丢失并导致空指针崩溃，全过滤组的结算也可能漏发。影响版本：`v3.4.1.0` 至 `v3.4.2.12`。（[#35537](https://github.com/taosdata/TDengine/issues/35537)）
- 关闭低延迟计算时，实时触发批次的截止时间被新数据反复推迟，`COUNT_WINDOW` 子查询流没有输出。影响版本：`v3.4.1.0` 至 `v3.4.2.8`。（[#35490](https://github.com/taosdata/TDengine/issues/35490)）
- 流计算语句同一侧有多个时间条件时，点窗口的扫描区间被算空，流不产出数据。影响版本：`v3.3.7.0` 至 `v3.4.3.1`。（[#35566](https://github.com/taosdata/TDengine/issues/35566)）
- 分组流在历史补算时被按单组处理，流变为 Failed 并报 `Stream internal error`。影响版本：`v3.4.2.7` 至 `v3.4.2.13`。（[#35474](https://github.com/taosdata/TDengine/issues/35474)）
- 版本升级后，已保存的流计划因节点编号变化无法恢复，重新启动仍然失败。节点编号自 `v3.4.2.0` 起变化。影响版本：`v3.4.2.0` 至 `v3.4.3.1`。（[#35556](https://github.com/taosdata/TDengine/issues/35556)）
- 流计算继续使用虚拟表 tag-ref 的旧缓存，配置表标签变更后仍按旧阈值计算。影响版本：`v3.4.2.13` 至 `v3.4.3.1`。（[#35491](https://github.com/taosdata/TDengine/issues/35491)）
- Rust 连接器的 Native TMQ 在接收超时与消息到达重叠时静默丢消息，订阅或 taosX 同步缺数据。影响版本：`v3.4.2.0` 至 `v3.4.3.0`。（[#35528](https://github.com/taosdata/TDengine/issues/35528)）
- 数据订阅 `tmq_write_raw` 在目标表不存在时吞掉错误并跳过，依赖该错误自动建表的调用方失效。影响版本：`v3.4.2.0` 至 `v3.4.2.8`。（[#35523](https://github.com/taosdata/TDengine/issues/35523)）
- taosX 同步在空闲刷盘或退出时未提交未满批次的消费位点，重启或对端短暂不可写后重放已同步数据。影响版本：`v3.4.2.0` 至 `v3.4.3.0`。（[#35571](https://github.com/taosdata/TDengine/issues/35571)）
- taosX 关系库同步的查询窗口和断点不正确，大时间范围迁移没有数据写入。影响版本：`v3.4.2.0` 至 `v3.4.2.12`。（[#35510](https://github.com/taosdata/TDengine/issues/35510)）
- OPC UA 数据源重启后，taosX 任务仍显示运行中但不再采集，必须手动重启任务。影响版本：`v3.4.2.0` 至 `v3.4.3.2`。（[#35557](https://github.com/taosdata/TDengine/issues/35557)）
- Windows 上 `NOW` 和 `NOW()` 返回接近 1970-01-01 的值。`v3.4.1.0` 起实时时钟与单调时钟的编号冲突。影响版本：`v3.4.1.0` 至 `v3.4.3.1`。（[#35565](https://github.com/taosdata/TDengine/issues/35565)）
- dnode 心跳里的 vnode 负载列表为空时，`SHOW VNODES` 把 vnode 显示为 offline。影响版本：`v3.4.2.0` 至 `v3.4.2.8`。（[#35481](https://github.com/taosdata/TDengine/issues/35481)）

### 4.2 查询

- 多分支 `UNION ALL` 中可以折叠为空的分支在解析期剪枝，减少无效扫描。（[#35483](https://github.com/taosdata/TDengine/issues/35483)）
- `UNION ALL` 去掉空分支时，把输出列别名同步到保留分支，外层按别名引用不再失败。（[#35539](https://github.com/taosdata/TDengine/issues/35539)）
- 客户端执行大量同类型 `UNION` 或 `UNION ALL` 时，不再因嵌套过深导致栈溢出。（[#35503](https://github.com/taosdata/TDengine/issues/35503)）
- 开启 `keepColumnName` 时，单参数聚合或选择函数的隐式列名与显式别名冲突，不再误报列歧义。（[#35498](https://github.com/taosdata/TDengine/issues/35498)）
- 按行内 schema 版本找不到元数据时，保留底层错误码，不再一律显示为 `NOT_FOUND`。（[#35542](https://github.com/taosdata/TDengine/issues/35542)）
- `information_schema.ins_columns` 等系统表在 `db_name = DATABASE()` 时只访问当前数据库，不再连到无关的离线 vnode。（[#35535](https://github.com/taosdata/TDengine/issues/35535)）
- `information_schema.ins_tags` 扫描虚拟子表引用标签时不再产生无法中断的 RPC 风暴。（[#35515](https://github.com/taosdata/TDengine/issues/35515)）
- 虚拟超级表查询在 split vgroup 导致批量元数据失败时结束 catalog 任务，查询不再挂起。（[#35520](https://github.com/taosdata/TDengine/issues/35520)）
- 虚拟表查询引用已删除的源表或源列时释放临时内存，重复查询不再使 taosd 内存持续增长。（[#35530](https://github.com/taosdata/TDengine/issues/35530)）
- 联邦查询 `DESC` 外部表时保留列名大小写。（[#35493](https://github.com/taosdata/TDengine/issues/35493)）
- 普通用户可以查询已注册的外部源，以及引用它的虚拟表，不必再持有同名本地库表权限。创建、修改和删除外部源仍按原权限校验。（[#35569](https://github.com/taosdata/TDengine/issues/35569)）

### 4.3 流计算与虚拟表

- `CREATE STREAM` 从虚拟普通表或虚拟子表读取引用标签时，带上物理来源表，不再报 Not found。（[#35564](https://github.com/taosdata/TDengine/issues/35564)）
- `EVENT_WINDOW` 只写 `START`、省略 `END` 时可以部署。`START` 变为假时，在最后一条满足条件的数据处关闭窗口。（[#35533](https://github.com/taosdata/TDengine/issues/35533)）
- 嵌套窗口流在 `PRE_FILTER` 产生空子表切片时跳过该切片，后续数据继续计算。（[#35511](https://github.com/taosdata/TDengine/issues/35511)）
- 虚拟表引用暂时解析失败时，不再把整条流重新部署，乱序重算结果得以保留。（[#35477](https://github.com/taosdata/TDengine/issues/35477)）
- 读取虚拟表的流在算子重置或销毁时释放系统表扫描请求。（[#35525](https://github.com/taosdata/TDengine/issues/35525)）
- 多个通知地址中，已经发送成功的地址在后续重试时不再重复收到同一通知。（[#35529](https://github.com/taosdata/TDengine/issues/35529)）
- 流计算通知经 WebSocket 非阻塞发送时，重试和超时处理完整。（[#35478](https://github.com/taosdata/TDengine/issues/35478)）
- 首次部署流任务时，注册失败不再泄漏任务对象。心跳遇到正在部署的流会跳过，不再等待慢连接。（[#35561](https://github.com/taosdata/TDengine/issues/35561)）

### 4.4 写入、订阅与客户端

- STMT2 interlace 模式下，子表被外部删除后，向另一超级表写入同名子表不再误报表已存在于其他超级表。（[#35522](https://github.com/taosdata/TDengine/issues/35522)）
- STMT2 按绑定字符串的小数位和指数计算 `DECIMAL` 的 scale，长度为 8 或 16 的合法十进制字符串不再被当成二进制。（[#35540](https://github.com/taosdata/TDengine/issues/35540)）
- `DROP TABLE` 只提交被删表自己的 last cache 脏项，开启缓存时删表速度恢复。（[#35499](https://github.com/taosdata/TDengine/issues/35499)）
- MQTT 按数据库或超级表订阅时，返回数据包含子表名。（[#35489](https://github.com/taosdata/TDengine/issues/35489)）
- 数据订阅读取变长列时按实际长度分配内存，并拒绝超出列定义的数据，超过 65535 字节的字符串不再使 taosd 崩溃。（[#35546](https://github.com/taosdata/TDengine/issues/35546)）
- TMQ 消费者关闭时，即使取消订阅失败也会释放本地资源，连接数不再持续上涨。（[#35497](https://github.com/taosdata/TDengine/issues/35497)）
- Go 连接器 TMQ 的 `getData()` 释放原生缓冲区，长时间消费不再持续增长内存。（[#35484](https://github.com/taosdata/TDengine/issues/35484)）
- 从 3.3 升级到 3.4 后，未完成的订阅 rebalance 消息不再因格式不兼容导致订阅超时。（[#35496](https://github.com/taosdata/TDengine/issues/35496)）
- taosAdapter 在 WebSocket 查询结果集空闲超时后释放结果。开启 gzip 时 `/metrics` 不再被重复压缩。（[#35516](https://github.com/taosdata/TDengine/issues/35516)、[#35488](https://github.com/taosdata/TDengine/issues/35488)）
- taosBenchmark 在子表查询失败时不再二次释放结果。（[#35538](https://github.com/taosdata/TDengine/issues/35538)）
- taosdump 使用 `-Z websocket` 时默认端口为 6041。Windows 上可以备份含冒号或中文的库表名。（[#35517](https://github.com/taosdata/TDengine/issues/35517)、[#35482](https://github.com/taosdata/TDengine/issues/35482)）
- JDBC WebSocket 在连接时区与 JVM 时区不同时，不再对 `TIMESTAMP` 多做一次换算。（[#35562](https://github.com/taosdata/TDengine/issues/35562)）
- `taos` 以 WebSocket 模式启动时，未实现接口的提示写入客户端日志，不再打印到终端。（[#35558](https://github.com/taosdata/TDengine/issues/35558)）
- Windows 上 taosd 以服务方式可以拉起 xnoded。先以前台管理员启动、再以 LocalSystem 服务启动时，不再因流临时目录属主不同而失败。（[#35501](https://github.com/taosdata/TDengine/issues/35501)、[#35555](https://github.com/taosdata/TDengine/issues/35555)）
- Windows 未配置 `timezone` 时保留系统识别出的时区名，建流不再因名称被截成 `System` 而失败。非法时区的 `ALTER` 在事务开始前被拒绝。（[#35563](https://github.com/taosdata/TDengine/issues/35563)、[#35567](https://github.com/taosdata/TDengine/issues/35567)）
- 字符串时间戳解析不再因时区库缺少优化编译而变慢。（[#35518](https://github.com/taosdata/TDengine/issues/35518)）
- 客户端库不再导出静态链接的第三方符号，避免在 Intel macOS 上与 OpenSSL 链接冲突。（[#35543](https://github.com/taosdata/TDengine/issues/35543)）
- 找不到 xnoded 可执行文件时，`CREATE XNODE` 返回明确错误，不再显示 Unknown error 65534。首次 `CREATE XNODE` 会等待控制端点就绪后再发送。（[#35549](https://github.com/taosdata/TDengine/issues/35549)、[#35548](https://github.com/taosdata/TDengine/issues/35548)）
- 社区版 `taos` 不再展示 `restore` 等专有命令。（[#35576](https://github.com/taosdata/TDengine/issues/35576)）
- 社区版 taosd 在受支持的 Linux 上，不再因安装了 dpkg、残留其他发行版标识或 os-release 不一致而拒绝启动。（[#35551](https://github.com/taosdata/TDengine/issues/35551)）

- mnode 拒绝超过 128 字节的配置名，以及越界的 vgroup 副本数和过长的共享存储迁移库名。（[#35688](https://github.com/taosdata/TDengine/issues/35688)）
- `DECIMAL` 拒绝超大指数和非法 precision、scale，避免越界访问。（[#35689](https://github.com/taosdata/TDengine/issues/35689)）
- 查询计划和 SQL 解析校验节点类型、必要子节点、长度和嵌套深度。畸形计划返回错误。（[#35690](https://github.com/taosdata/TDengine/issues/35690)）
- TMQ 与 MQTT 在解码前校验响应头、消息类型、数据块长度和批量元数据，并拒绝非法 topic 过滤器。（[#35691](https://github.com/taosdata/TDengine/issues/35691)）
- 虚拟表元数据在列引用数不一致、批量响应类型错误或缺少表名时按无效消息拒绝。（[#35692](https://github.com/taosdata/TDengine/issues/35692)）
- 消息解码不再信任对端声明的长度。（[#35693](https://github.com/taosdata/TDengine/issues/35693)）
- TDgpt Analytics 服务收紧缓冲区边界和访问控制，并限制 taosanode 的创建地址。可以配置是否允许接入内网部署的 taosanode，且不再自动转发到 taosanode 的请求。（[#35694](https://github.com/taosdata/TDengine/issues/35694)）
- taosdump 恢复时校验不可信备份的长度和列数。（[#35695](https://github.com/taosdata/TDengine/issues/35695)）
- `taos` 交互历史按语句写入。含 `PASS`、`TOKEN`、`TOTP_SECRET` 的创建和修改语句不再写入历史。`~/.taos_history` 权限收紧为 `0600`。服务端返回文本中的控制字符在显示时丢弃。（[#35696](https://github.com/taosdata/TDengine/issues/35696)）
- macOS 上相关日志文件改为以 `0666` 权限创建，普通用户可以写入 root 创建的日志文件。（[#35697](https://github.com/taosdata/TDengine/issues/35697)）
- 目录配置不再做命令替换。日志和归档文件不跟随符号链接。压缩解码拒绝非法 codec 标记和会回绕的长度。（[#35698](https://github.com/taosdata/TDengine/issues/35698)）
- taosd 不再信任 dataDir 下的 xnoded pid 文件、unix socket，以及 udfd 和 taosmqtt 的运行时文件。pid 文件不跟随符号链接，只结束属主和可执行文件名都匹配的 xnoded。伴随进程只从安装目录加载。（[#35699](https://github.com/taosdata/TDengine/issues/35699)）
- 删除后重建的同名用户不再继承原 XNode 任务属主权限。（[#35494](https://github.com/taosdata/TDengine/issues/35494)）

### 5.2 安全加固

- 新增 `xnodeDsnProtection`，默认 `0`。打开后，`SHOW` 和 taosExplorer 中的 XNode DSN 密码显示为 `******`。编辑时提交占位符则保留原密码。错误信息和日志不再输出密码、证书或私钥路径。连通性检查、采样和预览只携带 `task_id`。（[#35700](https://github.com/taosdata/TDengine/issues/35700)）
- `SHOW XNODE TASKS` 和 `SHOW XNODE JOBS` 支持 `WITH ENCRYPTED`。（[#35701](https://github.com/taosdata/TDengine/issues/35701)）
- 流计算 `wss://` 通知默认校验证书链和主机名。不受信任、过期或主机名不匹配的证书会被拒绝。`ws://` 不变。（[#35702](https://github.com/taosdata/TDengine/issues/35702)）
- 打开 vnode 前校验数据库加密密钥。密钥错误时返回明确的校验错误。（[#35703](https://github.com/taosdata/TDengine/issues/35703)）
- taosBenchmark 对超出容量的 CSV 行和标签表名报错退出，不再静默越界。（[#35704](https://github.com/taosdata/TDengine/issues/35704)）
- 安装和打包收紧 data 目录与驱动库权限，临时文件使用 `mktemp`。（[#35705](https://github.com/taosdata/TDengine/issues/35705)）
- 加固 TSZ 解码和压缩时的容量校验。（[#35706](https://github.com/taosdata/TDengine/issues/35706)）
- 对象存储下载和 TDB 页偏移做边界检查。（[#35707](https://github.com/taosdata/TDengine/issues/35707)）
- 流计算的心跳、任务部署和结果数据块校验长度、下标和任务类型。（[#35708](https://github.com/taosdata/TDengine/issues/35708)）

## 6. 升级须知

### 6.1 升级路径

- 支持直接升级的源版本：`v3.3.7` 及后续版本。
- 是否支持滚动升级：支持，范围为 `v3.4.3.0` 至 `v3.4.3.3`。
- 是否支持降级或回滚：支持，范围为 `v3.4.3.0` 至 `v3.4.3.3`。
- 客户端与连接器的最低配套版本：`v3.4.3.0`。

### 6.2 行为变更

- `BALANCE VGROUP LEADER` 默认改为随机再平衡。需要原先的强制均匀时，显式加上 `FORCE`。副本落后过多时，强制方式可能暂时选不出主。
- 等值 `JOIN` 在输入无序时改用 Hash Join。结果不变，行顺序可能变化。需要稳定顺序时写 `ORDER BY`。
- 子查询排序与 `JOIN` 时间条件不一致时不再报错，按实际时间条件返回结果。
- `CREATE SMA INDEX` 返回不支持。已有 SMA 仍可查询和删除。
- 列压缩设为 TSZ 时，该列编码必须是 `DISABLED`。
- 已注册到一个集群的 taosX 不能被另一个集群接管。
- taosX 的 WebSocket 连接默认在多个 taosAdapter 之间均衡。要固定单个端点，在任务 DSN 中设置 `adapter_ha=false`。
- 定时备份在上一周期未完成时不再丢弃到期周期，结束后立即补跑。实际间隔可能短于配置周期。
- 流计算 `wss://` 通知默认校验服务端证书。不受信任、过期或主机名不匹配的连接会失败。`ws://` 不变。
- 非 `ON_FAILURE_PAUSE` 的事件通知默认异步发送。负载过高时可能丢弃通知。
- JDBC 的 `TSWSPreparedStatement` 由类改为接口。升级驱动后需要重新编译，否则运行时抛出 `IncompatibleClassChangeError`。`close()` 之后不能再使用该 Statement。
- 设置了连接时区且使用 WebSocket 时，`getTimestamp()` 的 epoch 恢复为正确值，`toString()` 跟随 JVM 默认时区。未设置连接时区时无变化。
- `~/.taos_history` 在下次启动 `taos` 时权限变为 `0600`。同一行多条语句会写成多条历史。含 `PASS`、`TOKEN`、`TOTP_SECRET` 的创建和修改语句不再写入历史。
- 慢查询、UDF、MQTT 和 XNode 的日志文件名改为 `taos` 前缀。按旧文件名采集的规则需要调整。
- 社区版普通用户不能再 `ALTER DNODE`，也不能修改 IP 白名单。执行专有功能时返回带功能名的错误，不再静默不生效。
- TDgpt Lite 的容器重启后不自动启动模型。

### 6.7 升级前操作

从 `v3.3.6` 升级到本版本时，旧流计算不能直接沿用。未删除旧流、TSMA、snode 及其数据目录时，taosd 会启动失败。步骤见 [流计算兼容性说明](../../07-stream-processing/02-instructions.md#兼容性说明)。已经在 `v3.4.0.0` 及之后按新流计算重建过的集群，滚动到本版本时不必重复上述步骤。

从 `v3.4` 以前的版本升级到本版本时，taosX 不会自动迁移已有任务。此前任务存在 SQLite 中，`v3.4` 起存在 mnode 中。升级前在 taosExplorer 中导出任务；升级后导入，再启动需要运行的任务。没有在升级前导出时，升级后的 taosExplorer 中看不到这些任务。步骤见 [从 v3.4 以前的版本升级到 v3.4.x 时迁移任务](../../12-operations-and-tooling/03-components/06-taosx.md#从-v34-以前的版本升级到-v34x-时迁移任务)。已经在 `v3.4.0.0` 及之后运行、任务已在 mnode 中的集群，滚动到本版本时不必重复上述步骤。

另外确认这三件事：

1. 使用 `wss://` 流通知时，证书受信任、未过期，且主机名与 URL 一致。
2. taosX 仍有未重放的 cache 时，先排空再回滚。旧格式文件仍可读取。
3. JDBC 应用如果持有 `TSWSPreparedStatement`，升级驱动后重新编译。
