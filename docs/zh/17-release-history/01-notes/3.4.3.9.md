## 1. 版本亮点

- **联邦查询**：Linux 上可以查询 SQL Server 和 Oracle。Windows 上可以查询 SQL Server、MySQL、PostgreSQL 和 InfluxDB。外部表和虚拟表的外部源都可以使用这些数据源。
- **Neuron**：taosExplorer 可以把 Neuron 或 NeuronEX 采集的数据经 eKuiper 写入 TDengine，并在数据采集代理中完成接入、刷新和监控。
- **Kepware**：taosExplorer 和 taosX 可以接入 Kepware Server 7.1，扫描 OPC UA 点位，并以订阅或轮询写入选定数据库。
- **安全修复**：会让 taosd 崩溃或越界访问的畸形元数据、WAL、查询、流计算、订阅和同步输入会被拒绝。

## 2. 新特性

### 2.1 查询、流计算与联邦查询

- 联邦查询可以把本地部署的 SQL Server 2019 和 2022 登记为外部数据源，并查询其表和视图。Linux 上还可以登记 Oracle。Windows 上可以登记 MySQL、PostgreSQL、InfluxDB 和 SQL Server。外部表和虚拟表的外部源都支持这些类型。说明见 [联邦查询](../../05-tdengine-sql/04-data-query/06-federated-query.md)。
- 流计算可以使用引用 SQL Server 列的虚拟表，并与本地列混合计算。短引用和显式 database、schema 引用指向同一张远端表。动态重绑定后，已完成窗口的结果仍然保留。
- 新增聚合函数 `BIT_DURATION`，统计整型或布尔测点按位掩码处于指定状态的持续时长，可用于窗口和流计算。自 `v3.4.3.7` 起可用。说明见 [BIT_DURATION](../../05-tdengine-sql/04-data-query/03-function.md#bit_duration)。
- `SHOW CREATE TABLE`、`SHOW CREATE STABLE`、`SHOW CREATE VTABLE` 和 `SHOW CREATE RSMA` 可以带 `FULL`。带 `FULL` 时用 BLOB 返回完整建表语句，不再按 65535 字节截断。不带 `FULL` 时仍返回截断后的 VARCHAR。说明见 [SHOW CREATE](../../05-tdengine-sql/09-system-info/03-show.md)。
- 每个流计算通知事件都增加 `triggerTableName`。按 `PARTITION BY tbname` 分组时，它是不带库名前缀的触发子表名。虚拟子表使用虚拟子表名。其余情况为空字符串。说明见 [流式计算的通知机制](../../07-stream-processing/01-syntax.md#流式计算的通知机制)。

### 2.2 订阅、数据接入与 taosExplorer

- 表订阅和库订阅新增参数 `msg.consume.start.ts`。只消费主键时间不早于该 Unix 毫秒时间戳的数据。默认 `0` 表示不过滤。列订阅不受影响。说明见 [msg.consume.start.ts](../../10-developer-guide/07-subscription-api.md#msgconsumestartts)。
- OPC DA 点位任务支持 PI 兼容的质量码和数字状态映射。迁移工具可以把 PI 归档复刻到 PI 服务器，再按 OPC DA 回放并映射到已有 TDengine 表。说明见 [OPC DA](../../08-data-ingest-and-delivery/01-no-code-ingestion/06-opcda.md)。
- taosExplorer 可以把 Neuron 或 NeuronEX 采集的数据经 eKuiper 写入 TDengine，并在数据写入的数据采集代理中完成接入、刷新和监控。说明见 [Neuron](../../13-ecosystem-integrations/01-collection/11-neuron.md)。
- taosExplorer 和 taosX 可以接入 Kepware Server 7.1。可以扫描 OPC UA 点位，选择订阅或轮询，写入选定数据库。安装时也可以接入。说明见 [Kepware](../../13-ecosystem-integrations/01-collection/12-kepware.md)。
- taosX 节点故障后，Agent 先确认旧任务已经退出，再由接管节点启动同一任务。过期的启动、停止和取消不能把任务抢回去。无法确认旧任务已退出时，接管失败，不会同时运行两份。
- 自部署 taosExplorer 的 SQL 编辑器可以设置本次执行的前端超时。默认 60 秒，范围为 1 至 3600 秒。请求超时会显示黄色警告，且不取消服务端仍在执行的查询。

### 2.3 客户端与 TDgpt

- 原生客户端可以在公开 API 边界录制连接、SQL、STMT 和 schemaless 调用。`workloadRecord` 默认 `0`，只在客户端启动时读取；设为 `1` 后需要重启该客户端才开始录制。`workloadRecordDir` 默认是日志目录下的 `workload`。`workloadRecordBufferSize` 默认 256，单位 MB，范围为 16 至 4096。写盘跟不上时会阻塞该客户端的业务线程。`taosreplay` 只在 Linux 上从源码编译，不进入安装包。
- TDgpt 增加主成分分析 PCA、偏最小二乘 PLS，以及 KMeans、DBSCAN、GMM 聚类。聚类接口目前只能通过 REST 调用，不能通过 SQL 调用。

## 3. 优化

### 3.1 查询

- 查询 `information_schema.ins_tables` 并用 `table_name` 等值或 `IN` 过滤时，按表名索引定位目标表，不再扫描 vnode 中的全部表。
- 按表名查询 `information_schema.ins_tags` 时直接读取该子表的标签。库名、超级表名和表名上的等值条件也会提前筛选，子表很多时不再遍历全部元数据。
- 查询 `information_schema.ins_databases` 时，语句没有请求 `ntables` 就不再为了统计表数扫描全部 vgroup。列和 `ntables` 的数值不变。
- 列数很大的虚拟表在建表和查询时按列号定位引用列，SQL 分析不再逐列反复扫描。
- 虚拟超级表查询时，客户端保存列引用和标签引用的内存更少。
- 查询和流计算按顺序遍历节点列表。节点很多时，开销随节点数线性增长。
- 单表标签上的 `SUM`、`AVG`、`COUNT`，以及按标签分区的 `INTERVAL` 查询更快。
- 超级表上同时带 `INTERVAL` 和 `LIMIT` 的查询可以使用 `INTERVAL_LIMIT()` 提示，在取到所需窗口后结束扫描。该提示没有参数，语句里不写则不生效。说明见 [INTERVAL_LIMIT](../../05-tdengine-sql/04-data-query/01-query.md#interval_limit)。
- 多数 BLOB 列查询更快。满足条件的 `count(blob)` 重新使用块级预计算结果。部分中等长度的 `SELECT` BLOB 可能变慢，内存占用也会增加。
- 超级表上按子表分组的 `last_row` 查询在缓存扫描尚未结束时就开始输出，子表很多时更快返回。
- 不含 BLOB 列的查询不再逐行检查 BLOB 长度。
- 开启 DEBUG 日志时，标量计算不再为每个列参数写调试日志，`JOIN` 不再因这些日志变慢。
- 分组 `last()` 查询不再在复用的扫描块上保留过期的空值标志。每条查询的 reader timing 日志从 INFO 降为 DEBUG。
- 查询计划解码时复用已经解析的时区句柄，不再为同一进程反复加载时区数据。
- 区间查询的分组键只是表名或单个标签时，扫描块只保留一份分组键，不再逐行复制。查询结果不变。
- 联邦查询已用 PostgreSQL 18.6 做测试验证，支持范围仍是 14 及以上。说明见 [外部数据库版本](../../05-tdengine-sql/04-data-query/06-federated-query.md#外部数据库版本)。

### 3.2 流计算与 XNode

- 流计算从外部表取计算数据时，按计算语句中的时间表达式确定范围。窗口连接只裁剪引用这些时间列的一侧。到期的 `PERIOD` 窗口不再因空闲节流被跳过。
- 使用独立 `SLIDING` 并设置 `IGNORE_NODATA_TRIGGER` 的流，不再为大段时间空档逐个生成空窗口。窗口结果不变，其他分组也不再被这段空档拖住。
- XNode 异常或 Agent 重新连接后，仍应继续运行的 Agent 任务会自动恢复。
- `xnodeDsnProtection`、`xnodeDsnPublicKeyFile` 和 `xnodedDsnPrivateKeyFile` 可以用 SQL 修改，结果会保存，重启 taosd 后生效。`xnodeDsnProtection` 是全局参数，默认 `0`，使用 `ALTER ALL DNODES` 修改，按单个 dnode 修改会失败。两个密钥路径是局部参数，使用 `ALTER DNODE` 修改。taosExplorer 和 taosX 的私钥路径仍通过各自的配置文件设置。

### 3.3 客户端与 taosExplorer

- `libtaos.so` 不再依赖 `libtaosnative.so`。只使用 WebSocket 时也可以单独加载客户端。
- taosExplorer 不再内置用户手册。中文和英文手册分别安装。未安装对应语言的手册时，帮助入口打开官网，不再返回 404。
- taosX 的数据源插件改为单独安装。主机没有对应插件时，不能在该主机上运行这种数据源任务。taosExplorer 仍列出该数据源，并提示缺少的插件和安装包。
- taosExplorer 浏览器标签页使用与官方文档一致的 favicon。

## 4. 问题修复

### 4.1 严重问题

- InfluxDB 连接器可能在读线程启动前退出。迁移任务被报为成功，但实际没有写入数据。影响版本：所有版本。
- 分组窗口流在某个分组于某个 vgroup 上没有有效输入时，仍可能输出空聚合。输出顺序错乱，流进入 Failed。影响版本：`v3.4.2.9` 至 `v3.4.2.14`。
- 分配 TDB 空闲页时先改写页面再写入回滚日志。意外重启后空闲页链可能被写坏，再次分配时因非法页号退出。升级不会修复已经损坏的 TDB 文件，这类文件仍可能表现为超大文件或非法页号。影响版本：所有版本。
- 加密备份写满一个加密块后没有清空缓冲长度，后续写入可能重复输出旧数据，恢复时报 Invalid message。影响版本：`v3.4.3.3` 至 `v3.4.3.4`。
- `v3.4.3.5` 拒绝 `v3.4.3.0` 至 `v3.4.3.4` 写出的流 checkpoint，报 Invalid message，流进入 Failed。本版本可以重新读取这些 checkpoint。影响版本：`v3.4.3.5`。
- 虚拟表流在历史计算中，条件比较被过滤后为空的列时，taosd 崩溃。影响版本：`v3.3.0` 及后续版本。
- 虚拟超级表按源表标签分组聚合，且时间条件可以下推时，客户端崩溃。影响版本：`v3.4.0` 及后续版本。
- 流计算任务销毁时先释放数据缓存，再释放仍在使用该缓存的迭代器，taosd 在关闭阶段访问已释放内存。影响版本：`v3.3.8` 及后续版本。
- 流计算使用 `%%trows`，且窗口含变长列、行序与写入顺序不一致时，taosd 越界崩溃。影响版本：`v3.3.8` 及后续版本。
- taosX 的 OPC UA 采集在订阅失败、重连或任务退出时未关闭会话。会话累积后，后续连接被拒绝，任务也无法再次启动。影响版本：所有版本。
- 短时间按 UID 反复查询 `information_schema.ins_tables` 以获取虚拟子表名时，可能把 taosd 资源打满。影响版本：所有版本。
- 状态窗口流的外层过滤条件在结果写入前生效。不满足条件的窗口不再输出。历史回填结束时，未达到 `TRUE_FOR` 时长的尾窗不再触发计算。影响版本：`v3.3.7` 及后续版本。
- 流被删除后用同名重建时，过期的部署动作不再继续占用部署状态。部署失败和计算任务卸载时也会释放尚未完成的管理状态，taosd 内存不再因此持续增长。影响版本：`v3.3.7` 及后续版本。
- taosd 启动较慢时，流心跳不再在消息回调注册前发出，启动过程不再因此崩溃。影响版本：`v3.3.7` 及后续版本。
- 监控指标标签值含逗号、等号、引号或大括号时，taosKeeper 报告不再把 taosd 打崩溃。写出标签时这些字符替换为下划线。影响版本：`v3.3.7` 及后续版本。
- 虚拟表流设置 `PRE_FILTER` 且 TAG 使用引用写法时，不再把源表全部裁掉。修复前流状态可以是 RUNNING，但没有输出。影响版本：`v3.3.8` 及后续版本。
- 虚拟表流在运行中变更虚拟表后，不再反复重试虚拟表补丁并把 trigger 卡在 Invalid parameters。影响版本：`v3.3.8` 及后续版本。
- 虚拟表流开启 `NODELAY_CREATE_SUBTABLE` 时，初始化响应交错不再使流停在 Retry needed 或 Internal error。结果子表仍会提前创建。影响版本：`v3.3.8` 及后续版本。
- 流重启或重新部署后，读取位置对应的 WAL 已被回收时，不再反复报 WAL log does not exist 并持续无输出，改为从仍保留的 WAL 继续处理。影响版本：`v3.3.7` 及后续版本。
- 流计算实时进度已经推进且自动重算队列为空之后，再删除数据且没有后续写入时，删除重算不再一直挂起，结果表不再因此缺行。影响版本：`v3.4.2` 及后续版本。
- taosX OPC 异常退出并重启后，监控指标上报或 OPC DA 初始连接阻塞时，任务不再一直处于 running 且没有数据写入。影响版本：`v3.4.2` 及后续版本。
- 流计算读取虚拟子表上直接添加的数据列时，引用可能缺失，结果为空或为 NULL。删除未使用的自有源表后，继承列计算不再因此失败。影响版本：`v3.4.3` 及后续版本。

### 4.2 查询与虚拟表

- 虚拟表 `SERIES` 的 `ALTER` 语句解析结束后不再泄漏别名、外部源名称和标签条件。重复执行不再持续占用客户端内存。
- 虚拟表在 `ORDER BY ts` 且带 `LIMIT` 时，会下推排序方向和行数上限，不再先全量扫描再额外排序。
- 虚拟表列比源列窄时，`UNION` 和 `UNION ALL` 按较宽的列输出，不再报输入无效。
- `DECIMAL` 转为 `VARCHAR`、`BINARY` 或 `BLOB` 时，目标宽度不足以容纳完整文本就不再越界读取内存。
- SQL Server 停服后，联邦查询按配置的 `connect_timeout_ms` 返回失败，不再被驱动内部重试拖过这个时间。正常连接不受影响。
- 非 Windows 平台从源码构建 Arrow 时，内置 Thrift 使用项目自带的 OpenSSL 3.1.3，macOS 编译不再选中不兼容的 OpenSSL 4。
- 用户手册现在明确：`FIRST` 和 `LAST` 对非主键时间戳按有效时间线取值，不等价于按参数列 `ORDER BY ... LIMIT 1`。
- 用户手册现在明确：用户和角色同时拥有同一类型权限时优先使用用户权限；用户未设置时，多个角色取更新时间较晚的权限。
- 两侧已按主键时间有序、另有普通列或标签等值条件的普通 Inner Join，默认改回 Merge Join，不再因附加等值条件改走 Hash Join。结果集合不变。

### 4.3 流计算与虚拟表

- 单起始条件的 `EVENT_WINDOW` 配置 `TRUE_FOR` 后，历史扫描结束时窗口尚未关闭但时长已经满足，也会发送历史 OPEN 通知。
- 显式事务中 `CREATE STREAM` 新建输出超级表或 `NODELAY` 普通表时，语句成功返回后，当前事务即可看到该表。
- 虚拟表列改绑后，流计算重新部署若在 60 秒内没有完成，不再无限重试，而是返回明确错误并使流进入 Failed。60 秒内完成的重新部署行为不变。
- 流计算只使用虚拟表部分列时，改绑未使用的列不再补充计算 Reader 并引发不必要的重试。参与计算或出现在 `WHERE` 中的列改绑后，仍会按需部署 Reader。
- 以虚拟超级表为源的流在解析标签引用时，不再重复向 mnode 获取库路由，也不再展开未使用的列引用。
- 创建未配置 `FILL_HISTORY` 的虚拟表流后，Trigger 线程不再因为立即初始化历史上下文并按分组全量匹配虚拟表而占满 CPU。
- 流计算外部数据源的拉取请求在响应被丢弃时会释放句柄，不再因此泄漏内存。
- 超级表心跳响应或表元数据解码失败时，释放已经解析的部分数据，这条异常路径不再泄漏内存。

### 4.4 存储、集群与订阅

- 0 级挂载多块磁盘时，WAL 保留策略和回滚会删除非主挂载盘上的 WAL 文件。这些文件不再使磁盘占用持续增长。
- `BALANCE VGROUP LEADER` 未能把某个 vgroup 加入平衡事务时，会记录该 vgroup、数据库和失败原因。
- 快照恢复 vnode（包括 `REDISTRIBUTE VGROUP`）按文件时间和 `KEEP` 配置选择存储级别，不再把数据全部写到 0 级目录。
- 对不存在的 `vgroup_id` 执行 `SPLIT VGROUP` 时返回 vgroup 不存在，不再返回成功。
- 带仲裁的双副本库执行 `SPLIT` 后，`SHOW ARBGROUPS` 去掉被拆分 vgroup 的仲裁组，并为拆出的两个 vgroup 各建一个新的仲裁组。
- 仲裁器指派 vnode leader 时始终校验成员令牌。`force` 不能再跳过校验。未通过校验的请求不能把 vnode 设为指定 leader。
- `ONLY META` 或 `WITH META` 的超级表订阅，在元数据快照中按 `WHERE` 条件过滤子表。指定子表名时，不再把全部子表的建表事件推给消费者。
- 未显式设置 `session.timeout.ms` 的消费者，默认值由 12 秒改为 45 秒。心跳处理延迟时，消费者不再因此被移出消费组。
- 消费者退订与再均衡提交交错时，过期的再均衡结果不再把消费者改回就绪。刚退订的主题可以立即删除。
- 开启监控协议日志时，taosd 按内容大小估算多行 JSON 的行数，日志文件按 `numOfLogLines` 正常切换并压缩。
- 日志文件已可写但无法把权限改为 `0666` 时，taosd 和 `taos` 不再因此启动失败，而是沿用现有权限并给出警告。

### 4.5 写入、客户端、taosX 与 taosExplorer

- C/C++ 客户端使用 STMT2 参数绑定写入时不再泄漏内存。固定表且未开启 interlace 时，执行失败后的下一次成功写入仍保留已绑定的固定标签。
- schemaless 在超级表已存在时再次创建，不能再修改已有列和标签的类型、缩短其宽度或删除它们。变长类型仍可加宽。taosX 同样不能改类型或缩短宽度，但跨集群复制仍可删除列和标签。
- taosdump 备份改为使用 `SHOW CREATE ... FULL`。列数很多的虚拟表不再因为建表语句被截断而漏表。导入时也不再因为截断报 Row length exceeds max length。
- Windows 上创建或重启 `XNODE` 时，xnoded 就绪探测的单次等待由 100 毫秒改为最多 3 秒。已经启动的 xnoded 不再被判为不可访问并被停止。
- Windows 上 taosd、taosAdapter、taosKeeper、taosX 和 taosExplorer 异常退出后，会按 10 秒、30 秒、90 秒、180 秒和 300 秒自动重启，最多五次，之后不再自动重启。
- taosdump 导入 AVRO 时，表结构预检查不再把刚创建的表误报为不存在。创建数据库失败会中止后续导入，创建子表时也会显示进度。
- Rust WebSocket 文档示例在 tokio 1.54 及以上版本创建数据库时，不再因零容量缓冲区断言而 panic。
- 经 taosX Agent 执行的任务，在 Agent 尚未连上时启动失败后不再一直停在排队中。Agent 恢复连接后会自动启动。
- taosExplorer 使用 pSpace 数据源时，点位列表为空会显示错误，不再弹出无文字的提示。Chrome、Edge 86 上，任务运行后的指标弹窗不再偏移，也可以滚动。
- TDgpt 模型在容器重启或 worker 被结束后，不再卡在 started 并使加载接口持续返回 500。启动时和请求前会按实际进程和已安装文件校正状态。

## 5. 安全

### 5.1 漏洞修复

见 [安全公告](https://docs.taosdata.com/security-guide/security-advisories/)。

- TMQ 客户端解码 ask-ep 响应时校验字段长度和剩余报文。超长 topic、数据库名和 FQDN 会被拒绝，不再造成客户端栈溢出。CWE-121。
- WAL 恢复不再把记录体内伪造的帧头当成新日志记录，也不会据此采用伪造索引并截断日志。非法记录长度不再导致 taosd 崩溃或恢复卡住。
- 查询执行和流计算解码数据块时，按计划列宽校验长度。非法块返回错误。正常查询结果不变。
- `ALTER STABLE` 在字段数组为空或长度不一致时不再继续处理，避免 mnode 崩溃。`CREATE TSMA` 不再保存之后会被按错误类型读取的查询语法树。`SHOW STABLES` 拼接 rollup 函数名时不再写出栈缓冲区。缺少运行时信息的流计算拉取请求不再导致 taosd 崩溃。
- `CREATE STREAM` 拒绝节点类型不符或缺少必要子节点的客户端计算计划，也拒绝缺少名称、数据库或表名的请求。`DROP XNODE JOB` 和 `REBALANCE XNODE JOB` 拒绝空值或缺少操作数的 `WHERE` 条件。嵌套的批量元数据请求会被拒绝，短于消息头的批次内容也不再被写入。CWE-674。查询 `information_schema.ins_dnode_variables` 时不再使用非法的系统表类型下标。
- 创建超级表时，固定宽度列的长度必须落在该类型允许的范围内。非法长度会被拒绝，不再把越界的列宽写入订阅和流计算的数据块。
- snode 校验流计算 checkpoint、fetch、calc 和 drop 消息的长度、运行参数和任务类型，并拒绝畸形输入。
- 查询元数据和 `EXPLAIN` 报文在使用前校验长度、计数和指针。`SHOW CREATE` 输出增加边界检查。备份在建表语句超出缓冲区时改用回退生成。
- mnode 应用已提交的元数据记录时校验记录头的长度和类型，长度越界或绕过事务的直接写入会被拒绝。订阅相关的元数据解码会检查字符串长度和条目数量，对端提供的超长内容不再造成 mnode 堆溢出。
- 社区版对用户执行 `GRANT` 或修改角色时，不再使用未初始化的用户对象。用户与会话管理补上权限检查，未授权用户不能再设置 TOTP 密钥、结束他人会话或修改角色。
- `SHOW VARIABLES` 不再返回对象存储访问串等敏感配置，包括已具备查看配置权限的用户。社区版进一步对安全类和审计类配置显示掩码。未认证连接不能再拉取整份全局配置。集群内部的配置同步仍使用真实值。
- 查询落盘的临时文件改为随机文件名、排他创建和仅所有者可读写，不再跟随 `tempDir` 中预先放置的符号链接。CWE-59。
- Grafana 数据源插件将 kin-openapi 从 0.144.0 升级到 0.149.0。该升级修复 CVE-2026-100347（GHSA-fh4f-47mf-f2gj）、CVE-2026-100348（GHSA-mh7x-f8wq-4jhx）、CVE-2026-100351（GHSA-23vg-4cjm-66q5）、CVE-2026-100352（GHSA-rj39-cv6w-8wv7）、CVE-2026-100353（GHSA-vrcc-3ch7-hppw）和 CVE-2026-100354（GHSA-g8cf-rcjf-c8cf）。
- JDBCDemo 示例将 jackson-databind 从 2.18.9 升级到 2.18.10，修复 CVE-2026-83557（GHSA-gx83-3vf8-gh7j）。服务端行为不变。
- 创建和修改 vnode 时校验副本数和学习副本数的上下界，也拒绝引用未注册 dnode 的 vgroup 配置。超出范围的请求被拒绝，不再造成栈溢出。TD-SEC-2026-034，GHSA-c6c6-fm4m-fj5w。CVE 尚未分配。安全公告页还没有这一条。
- dnode 拒绝非法管理消息和伪造的响应。超出动态范围的配置不再被应用。
- 同步超时和选举超时消息不再从网络接收。未认证的对端不能再靠这两条消息强迫重新选举，也不能再写入 Raft 日志。投票请求如果声称来自本节点，或在同一任期声称来自当前 leader，会被丢弃。领导者只按实际发给该副本的日志范围计票，伪造的确认不能再凑成多数派。指定仲裁组主副本必须通过权限检查。节点已经登记机器标识后，状态心跳必须带上相同的标识。

- 创建超级表时，`DECIMAL` 和 `DECIMAL64` 列必须带有精度和范围。缺少这些信息的列会被拒绝，查询 `information_schema.ins_columns` 不再因此导致 mnode 崩溃。

## 6. 升级须知

### 6.1 升级路径

- 支持直接升级的源版本：`v3.3.7` 及后续版本。
- 是否支持滚动升级：支持，范围为 `v3.4.3.0` 至 `v3.4.3.8`。
- 是否支持降级或回滚：支持，范围为 `v3.4.3.0` 至 `v3.4.3.8`。
- 客户端与连接器的最低配套版本：`v3.4.3.0`。

### 6.2 行为变更

- 未设置 `session.timeout.ms` 的消费者现在使用 45 秒。原先默认是 12 秒。
- `ONLY META` 或 `WITH META` 的超级表订阅，只向匹配 `WHERE` 的子表发送元数据建表事件。按名称过滤时，不再为每张子表都发送建表事件。
- `SHOW VARIABLES` 不再返回对象存储访问串，包括原先可以查看该配置的用户。社区版对安全类和审计类配置显示掩码。未认证连接不能再拉取整份全局配置。
- 社区版中，未授权用户不能再设置 TOTP 密钥、结束他人会话或修改角色。
- 虚拟表列改绑后，重新部署超过 60 秒仍未完成时，流进入失败，不再无限重试。将该虚拟超级表上的流删除后重新创建即可。60 秒内完成的重新部署行为不变。
- 每个流计算通知事件现在都包含 `triggerTableName`。拒绝未知 JSON 字段的消费者需要接受该字段。
- 单起始条件且设置了 `TRUE_FOR` 的 `EVENT_WINDOW`，在历史扫描结束时窗口仍开着但时长已满足，会发送以前不会发送的历史 OPEN 通知。
- 快照恢复和 `REDISTRIBUTE VGROUP` 按文件时间与 `KEEP` 选择存储级别，不再把文件全部写到 0 级。
- Windows 上 taosd、taosAdapter、taosKeeper、taosX 和 taosExplorer 在异常退出后会自动重启，最多五次。
- 部分中等长度的 `SELECT` BLOB 可能变慢，内存占用增加。满足条件的 `count(blob)` 更快。结果不变。
- taosX 主程序包不再包含各数据源插件。使用前按数据源另行安装。taosExplorer 仍显示全部数据源；所选插件未安装时给出警告。任务可以在已安装该插件的 Agent 上运行。
- taosExplorer 如需打开本地手册，请另行安装中文或英文手册包。只安装一种语言时，另一种语言的帮助入口打开官网。
- taosX Agent 任务被其他 taosX 节点接管时，会先等待旧任务退出。无法确认退出时接管失败，不会同时运行两份。升级 Agent 后才有这层确认。
- `connect_timeout_ms` 现在限制整次 SQL Server 连接等待。停服时到期即返回连接失败，不再等待驱动默认的重试间隔。
- 查询使用的会话时区规则在进程内首次加载后会被缓存，之后不再重新读取系统时区数据。运行期间升级系统 tzdata 后，需要重启 taosd 和客户端应用才能生效。
- schemaless 在超级表已存在时再次写入，不能修改已有列或标签的类型，不能缩短宽度，也不能删除列或标签。变长类型仍可加宽。taosX 跨集群复制仍可删除列和标签。
- 对不存在的 vgroup 执行 `SPLIT VGROUP` 会返回错误，不再返回成功。
- 标量表达式里的 `AES_ENCRYPT` 现使用完整的 16 字节初始化向量。读取修正前通过 `SELECT` 或 `INSERT INTO ... SELECT` 保存的 CBC 密文时，`AES_DECRYPT` 需要传入原密钥、原 16 字节 IV，以及 `legacy`。ECB 密文、`INSERT ... VALUES` 生成的密文和修正后的密文仍使用原来的两参数或三参数调用。初始化向量长度不是 16 字节时返回参数错误。
- taosdump 备份改为执行带 `FULL` 的 `SHOW CREATE`。超过 65535 字节的建表语句会完整写入备份。
- taos-ws-py 的安装最低版本从 Python 3.7 改为 Python 3.8。Python 侧 API 签名不变。
- 监控指标标签值里的逗号、等号、引号和大括号会写成下划线。其余字符保持不变。
- `xnodeDsnProtection`、`xnodeDsnPublicKeyFile` 和 `xnodedDsnPrivateKeyFile` 现在可以用 SQL 修改。修改会保存，重启 taosd 后才改变运行行为。`xnodeDsnProtection` 默认 `0`。
- 两侧已按主键时间有序、另有普通列或标签等值条件的普通 Inner Join，默认改回 Merge Join。结果集合不变。没有 `ORDER BY` 时，行序可能与此前不同。

### 6.3 配置参数变更

订阅有两项变化。客户端新增三项录制参数。

| 参数 | 作用 |
| --- | --- |
| `msg.consume.start.ts` | 表订阅和库订阅只消费主键时间不早于该 Unix 毫秒时间戳的数据。默认 `0`，表示不过滤。列订阅忽略该参数。 |

| `workloadRecordDir` | 录制文件目录。未设置时使用日志目录下的 `workload`。目录不可用时录制保持关闭。 |
| `workloadRecordBufferSize` | 录制缓冲，单位 MB。默认 256，范围为 16 至 4096。写盘跟不上时会阻塞该客户端的业务线程。 |

### 6.7 升级前操作

从 `v3.3.6` 升级到本版本时，旧流计算不能直接沿用。未删除旧流、TSMA、snode 及其数据目录时，taosd 会启动失败。步骤见 [流计算兼容性说明](../../07-stream-processing/02-instructions.md#兼容性说明)。已经在 `v3.4.2.0` 及之后按新流计算重建过的集群，滚动到本版本时不必重复上述步骤。

从 `v3.4` 以前的版本升级到本版本时，taosX 不会自动迁移已有任务。此前任务存在 SQLite 中，`v3.4` 起存在 mnode 中。升级前在 taosExplorer 中导出任务；升级后导入，再启动需要运行的任务。没有在升级前导出时，升级后的 taosExplorer 中看不到这些任务。步骤见 [从 v3.4 以前的版本升级到 v3.4.x 时迁移任务](../../12-operations-and-tooling/03-components/06-taosx.md#从-v34-以前的版本升级到-v34x-时迁移任务)。已经在 `v3.4.0.0` 及之后运行、任务已在 mnode 中的集群，滚动到本版本时不必重复上述步骤。
