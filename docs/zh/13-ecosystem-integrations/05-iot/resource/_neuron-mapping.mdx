## 数据映射与采集配置规范

接入前，先了解 Neuron 中的对象如何对应到 TDengine，以及什么样的采集配置能顺畅接入。

### 对象映射

| Neuron 对象 | TDengine 对象 | 说明 |
| --- | --- | --- |
| 设备（南向节点）`node_name` | 子表 | 每台设备一张子表，子表携带 `device` 标签记录设备名 |
| 采集组 `group_name` | 超级表 | 一个采集组对应一张超级表，组内设备共用表结构 |
| 点位 `values.*` | 测量列 | 每个点位对应一个测量列 |
| 报告时间戳 `timestamp` | 时间列 `_ts` | 毫秒精度 |

一键接入按上表自动完成映射，并额外附加固定标签：`device`（设备名）、`group_name`（采集组名）、`protocol`（设备所用插件协议）和 `gateway`（Neuron 网关地址，用于区分多个网关写入同一数据库）；子表名默认为「前缀 + 设备名」，设备名无法原样写入或同一设备属于多个采集组时，由 TDengine 按标签集合自动命名。手工接入可自行定义标签与子表命名。位置、单位、业务层级等属性不属于采集配置，一键接入不会自动推断，需要时请使用手工接入自行定义。

### 命名与分组规范

以下规范针对 Neuron 侧的采集配置本身，与接入方式无关。遵循这些规范，接入得到的表结构最清晰、可读性最好：

1. **设备名全局唯一**。同名设备会写入同一子表，造成数据混写。同一 Neuron 实例内设备名天然唯一；多台 Neuron 网关写入同一数据库时，设备名可能重复，此时应为每个网关设置不同的子表名前缀。
2. **设备名使用规范字符**。字母、数字、下划线、连字符、中文均可，数字开头也没有问题；避免点号 `.`、引号、反斜杠和控制字符，否则设备名无法直接用作子表名，只能改用自动生成的名称，排查时不直观。
3. **一个设备只放入一个采集组**。TDengine 库内子表名全局唯一、不按超级表隔离，跨组设备无法在各组复用设备名作为子表名。
4. **同一采集组内设备结构一致**。采集组对应超级表，组内设备的点位名称和类型应当相同，否则同名列出现类型冲突；结构不同的设备请分到不同采集组。
5. **组名使用合法标识符**。小写字母、数字、下划线，不以数字开头，最长 64 字符的组名可直接用作超级表名。
6. **点位名使用规范字符**。点位名转为列名时会做归一化（转小写、特殊字符转为下划线、数字开头自动加前缀）；`ts`、`_ts`、`ets`、`device`、`group_name` 等保留名会被自动改名；含反引号、反斜杠的点位名无法转为列名。

### 类型映射

点位的 Neuron 类型按下表映射为 TDengine 列类型。一键接入自动按下表执行，首次写入时自动建表；手工接入可参照此表自行编写规则：

| Neuron 点位类型 | TDengine 列类型 | 说明 |
| --- | --- | --- |
| `INT8`/`INT16`/`INT32`/`INT64`、`UINT8`/`UINT16`/`UINT32`、`BIT`、`WORD`/`DWORD`/`LWORD` | `BIGINT` | |
| `UINT64` | `BIGINT` | 超出有符号 64 位范围的值会被截断（已知限制） |
| `FLOAT`、`DOUBLE` | `DOUBLE` | |
| `BOOL` | `BOOL` | |
| `STRING` | `NCHAR` | |
| `BYTES` | `NCHAR` | 按 base64 文本写入 |
| `ARRAY_*` | `NCHAR` | 按 JSON 数组文本写入 |
| 带标度（scale）的整数点位 | `DOUBLE` | 按标度换算为浮点值 |
