# TDengine-TSDB 研发文档仓库

本仓库是 TDengine 时序数据库产品的研发过程文档库，覆盖产品从需求、设计、测试、安全到发布的全生命周期。所有文档以 Markdown 格式存储，图片统一放在就近的 `images/` 目录中；涉及架构图、流程图或时序图时，建议优先使用 PlantUML 或 Mermaid 等文本化方式绘制。

---

## 目录结构总览

```
.
├── overview/       # 全局性文档：路线图、总体设计、各模块长期规格说明
├── releases/       # 按版本迭代组织的过程文档（需求/设计/测试/发布等）
├── unplanned/      # 尚未纳入迭代计划的技术文档
├── reports/        # 员工日报，按季度和小组归档
└── templates/      # 各类标准化文档模板
```

---

## 一、`overview/` — 全局文档

存放跨版本、长期有效的全局性文档，不与特定迭代绑定。

### 1.1 `overview/01-产品路线图/`

按年份组织的产品路线图，如 `2025/`、`2026/`。

### 1.2 `overview/02-总体设计/`

产品总体设计方案和总测试方案，如 `TDengine v3.4 总体设计` 等。

### 1.3 `overview/03-各模块设计/`

按模块分类的**长期规格说明书**，每个模块包含四类标准文档：

| 文档类型 | 命名格式 | 说明 |
|---------|---------|------|
| Requirement Spec | `模块名-Requirement Spec.md` | 需求规格说明 |
| Function Spec | `模块名-Function Spec.md` | 概要设计（功能规格） |
| Design Spec | `模块名-Design Spec.md` | 详细设计说明 |
| Test Spec | `模块名-Test Spec.md` | 测试规格说明 |

模块按以下四大分类组织：

- **`内核模块/`** — 基础库、通信、存储、缓存、查询、流计算、订阅、标签索引、预聚集、多副本管理、集群管理、虚拟表、自定义函数、授权、跨平台（共 15 个子模块）
- **`接口模块/`** — C/C++、C#、Go、JDBC、Node.js、ODBC、Python、Rust 连接器（共 8 个）
- **`工具组件/`** — 命令行工具、可视化管理工具（Explorer）、监控指标导出工具、基准测试工具、数据备份工具、数据管道工具（taosX）、数据接入适配工具（共 7 个）
- **`安全模块/`** — 加密算法、安全函数、身份鉴别、访问控制、传输安全、存储安全、安全审计（共 7 个）

### 1.4 `overview/04-行为变更/`

存放跨版本行为变更记录、兼容性差异说明与升级注意事项。

## 二、`releases/` — 版本迭代文档

每个迭代版本对应一个独立文件夹，命名规则为：

```
TSDB-v{major}.{minor}.{patch}-[{YYYYMMDD}]
```

其中日期为该迭代的计划截止日期。当前共有 20 个版本文件夹，从 `TSDB-v3.0.3-[20230228]` 到 `TSDB-v3.4.2-[20260630]`。

### 2.1 当前版本结构（v3.4.x 系列）

自 v3.4.0 起采用统一的 10 分类结构：

```
TSDB-v3.4.x-[YYYYMMDD]/
├── 01-项目管理/       # 项目立项、计划、进度跟踪、变更记录
├── 02-安全管理/       # 威胁建模、安全实施计划、安全评审
├── 03-质量管理/       # 质量保证报告、风险登记、培训记录
├── 04-需求文档/       # 需求规格说明书（RS）、用户需求
├── 05-设计文档/       # 概要设计（FS）、详细设计（DS）
├── 06-功能测试/       # 功能测试报告（TS）、测试用例
├── 07-系统测试/       # 系统测试计划与报告
├── 08-发布文档/       # 发布报告、Release Notes
├── 09-会议纪要和评审记录/  # 按类别分的会议和评审记录
└── 10-其他文档/       # 客户相关、调研等杂项
```

### 2.2 历史版本结构

早期版本（v3.0.x ~ v3.2.x）采用较简化的 3 分类结构：

```
├── 01-需求&设计/
├── 02-测试文档/
└── 03-发布文档/
```

中期版本（v3.3.x）过渡为 5 分类结构：

```
├── 01-版本规划/
├── 02-需求文档/
├── 03-设计文档/
├── 04-测试文档/
└── 05-发布文档/
```

### 2.3 迭代文档命名惯例

文档文件名中常见以下缩写后缀：

| 缩写 | 含义 | 对应模板 |
|------|------|---------|
| RS | Requirement Spec（需求规格） | `需求规格说明书 - 模版.md` |
| FS | Function Spec / Functional Spec（概要设计） | `概要设计说明书 - 模板.md` |
| DS | Design Spec（详细设计） | `详细设计说明书 - 模版.md` |
| TS | Test Spec（功能测试报告） | `功能测试报告 - 模板.md` |

```
    ├── agile-group/
    ├── analysis-group/
    ├── query-group/
    ├── storage-group/
    └── tools-group/
```

## 通用规则

- **图片存放**：每份文档的关联图片存放在同级 `images/` 目录下，图片通常以 `img_` 或 `wb_` 开头（来源于飞书导出）。
- **绘图建议**：新增或更新图表时，优先使用 **PlantUML** 或 **Mermaid** 等文本化绘图方式嵌入 Markdown，便于版本控制和 AI 阅读理解；避免使用纯截图替代可文本化的架构图、流程图和时序图。
- **文件格式**：文档统一使用 Markdown (`.md`)，偶有 `.pptx` 培训材料。
- **目录编号**：文件夹使用数字前缀（如 `01-`、`02-`）控制显示顺序和流程阶段。
- **占位文件**：尚未填充内容的目录使用 `placeholder.md` 标记。
