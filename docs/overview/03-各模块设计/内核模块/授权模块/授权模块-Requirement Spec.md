## 2. 引言

### 2.1 术语与缩写名词

1. **机器码（Machine Code）**：根据服务器的 CPU ID、核数和主板等硬件信息生成的固定字符串，是用于授权控制的输入信息。
2. **授权码 (activeCode)：**对可授权的部分或所有功能项加密生成的字符串，用于辅助完成对 TDengine 可授权功能项的控制。

### 2.2 相关文档资料

无

### 2.3 优先级要求

授权许可证控制机制影响到 2024 年的产品，因而在 2023-12-25 的版本规划会议上，提升为最高优先级。

### 2.4 版本要求

仅企业版支持。

## 3. 需求目标

1. 通过授权许可证，让企业版功能控制更加灵活，支持多种产品定价策略
2. 所有功能通过授权码控制，包括数据库引擎之外的其他组件产品，例如：taosX、TDengine TSDB等
3. 自动识别集群复制或硬件扩容导致的机器码变更，避免未经授权的使用

## 4. 功能需求

集群创建后自动进入未授权状态，然后在已授权、授权过期、授权回收三种状态之间转换。这几种状态覆盖了新建集群、集群首次授权、集群授权过期、集群授权叠加、集群授权回收、复制集群、集群硬件变更等典型的场景。

| 状态名称 | 产品行为 |
| --- | --- |
| 未授权状态 | 授权项有固定取值 |
| 已授权状态 | 授权项的取值来自于授权码，允许叠加多个授权码 |
| 授权过期状态 | 授权项有固定取值 |
| 授权回收状态 | 授权项有固定取值 |

### 4.1 授权码定义

| 需求编号 | **需求描述** |
| --- | --- |
| R101 | 企业版所有功能通过单一授权码控制，包括 taosd、taosX 等各个组件提供的基本功能和可选功能 |
| R102 | 授权码生成时需要提供 clusterId，也可提供其他信息且被记录在授权码中 - 可选择是否提供机器码（1-3个）（用于弥补集群复制的漏洞） - 可选择是否提供上次授权码（交付人员有历史记录，用于弥补集群复制的漏洞） |
| R103 | 授权码有两种类型 - 完整授权：在设置授权码操作时使用，必须设置所有的必选授权项 - 叠加授权：在叠加授权码操作时使用，包含任意数目的授权项 |
| R104 | 授权码包含 encode / decode 的版本号，便于以后扩展解析、加密方法 |
| R105 | 授权码包含生成时间、激活时限，以应对“必须在发放日期的 3 天之内使用，超过 3 天后失效”的需求，其中“激活时限”的默认值为 3 天 |
| R106 | 授权码支持不检查硬件变更的选项，作为超融合需求的后门 注意：使用此类授权码的集群，可以随意复制，不会自动进入回收状态（可手动进入） |
| R107 | 授权码的字符串内容只包含大小写字母和数字，不包含其他字符（涉及 base64 算法改造） |
| R108 | 授权码的字符串长度不固定，随授权项数目不同而变化，完整授权的授权码很长，叠加授权则很短 |
| R109 | 授权码的字符串内容不宜过长，通常不超过 1000 字节 |

### 4.2 授权码生成

| 需求编号 | **需求描述** |
| --- | --- |
| R201 | 授权码通过 taosGrant 可执行程序生成，支持本文列出的所有授权项 |
| R202 | taosGrant 只能在固定的几台服务器上运行，如需在其他服务器上运行需要重新编译 |
| R203 | taosGrant 和 grant 库的源代码使用独立代码仓库，仅部分人员有权限查看，源代码不下载到 CI 环境 |
| R204 | taosGrant 生成授权码时，支持以命令行参数方式输入具体授权项 |
| R205 | taosGrant 生成授权码时，支持以文件方式输入具体授权项，建议为 JSON |
| R206 | taosGrant 生成授权码时，两种不同类型的授权码有不同的默认行为 - 完整授权：各必选授权项取值必须显式设置，无默认值 - 叠加授权：各授权项取值未显式设置的，无任何默认值（不进行授权） |
| R207 | taosGrant 可以查看已有授权码的具体授权项，支持输出到控制台 |
| R208 | taosGrant 可以查看已有授权码的具体授权项，支持输出到文件，建议为 JSON |

### 4.3 授权码保存

| 需求编号 | **需求描述** |
| --- | --- |
| R301 | 授权状态、授权码的历次变更都会保存在集群中 - 授权状态变更有最大数量限制（例如 30 个） - 授权码变更有最大数量限制（例如 10 个），授权码仅记录前 30 个字符 |
| R302 | 支持通过 SQL 语句查看历次授权状态变更记录，包括时间、原因、源状态、结果状态、授权码（部分显示） |
| R303 | 授权码在被激活后不可在本集群内被重复使用，即处于回收状态的集群只能通过新授权码恢复 |
| R304 | 已经完成授权的企业版不能回退到开源版本 |

### 4.4 集群授权

| 需求编号 | **需求描述** |
| --- | --- |
| R401 | 集群支持本文列出的所有授权项，授权项失效时产品行为应与描述完全一致 |
| R402 | 集群授权状态分未授权状态、已授权状态、授权过期状态、授权回收状态 |
| R403 | 授权状态转换遵守本文的状态机规则，例如集群一旦设置过授权码，不能通过清空、回收等操作将集群重新设置为未授权状态 |
| R404 | 未授权状态、授权过期状态、授权回收状态下各授权项的取值与本文一致 |
| R405 | 已授权状态下各授权项取值则来自于授权码，支持叠加多个授权码，叠加策略与本文描述一致 注意：各必选项过期时间需要 <= 基础功能的过期时间 |
| R406 | 如果集群中任何一个授权项的{{当前值}}超过{{授权值}}，则授权失败，并给出错误提示。 |
| R407 | 授权码必须在激活时限前使用，超出后无法激活 |
| R408 | 支持通过 SQL 语句查看集群当前的授权状态 |
| R409 | 支持通过 SQL 语句查看集群当前各授权项状态（信息更加丰富，例如多行显示） 区分授权项名称、授权项显示名称 |
| R410 | 支持通过 SQL 语句实现设置激活码、叠加激活码、回收激活码三种操作，完成授权状态之间的转换，叠加激活码可与设置激活码采用同样的 SQL 语句 |
| R411 | - 集群创建并生成 clusterId 时记录首个 dnode 的机器码 - 当有新 dnode 加入集群时会保存机器码到历史列表中，保存数量与授权数目相同 - 删除 dnode 不会删除历史列表中的已保存值 - 当新增 dnode 导致保存数目超过限制时，会被识别为硬件变更 |
| R412 | 支持通过 SQL 语句查看各 dnode 所在服务器的机器码 |
| R413 | 授权回收状态迁移至已授权状态时，必须使用“完整授权”类型的授权码，其中需要包含机器码，可以包含上次授权码的摘要。授权码中的机器码需要与 dnode 机器码完全对应，授权码中如有“上次授权码”时，也需要与历史机器码列表完整对应。 |
| R414 | 集群在运行状态时，可在 5 分钟内识别 dnode 的机器码变更，并转换集群的授权状态 |
| R415 | 集群的某个机器重启后，可立即识别 dnode 的机器码变更，并转换集群的授权状态 |
| R416 | 过期时间判断采用自然时间，不采用累计运行时间、自定义时间序列等方案 |

## 5. 性能需求

激活授权码过程、授权运行时检查，不影响系统的写入和查询性能。

## 6. 安全需求

安全需求需围绕机密性、完整性、可用性及抗攻击性展开，包括以下几个方面：
授权信息加密：采用灵活加密方案保护授权文件或密钥，支持本地授权并确保授权内容安全和不被破解。
数据校验与签名：对授权文件或关键配置实施数字签名，运行时校验文件完整性，拒绝被篡改的授权内容。
风险分析与应对：针对非授权操作、软硬件漏洞等风险，设计应急响应机制（如授权自动冻结），确保系统在攻击下的最小权限可用。
操作审计与日志：记录授权相关关键行为（如激活、权限变更、验证失败），日志需包含时间戳、用户/设备标识及操作结果，支持安全审计与追溯。
多因素验证：本地授权可绑定硬件特征码（如CPU序列号、主板序列号、MAC 地址）。

## 7. 第三方依赖需求

无，授权模块不依赖任何第三方的库或源代码

## 8. 其他需求

### 8.1 兼容性需求

| 需求编号 | **需求描述** |
| --- | --- |
| S101 | 老版本升级至新版本时，由于未记录 mnode，自动进入未授权状态 - 无论用户是否已经使用非必选功能，均需进行授权操作，因为各授权项的默认值已经发生变化，交付人员必须清晰了解该集群之前各授权项状态 - 兼容性让程序之后的维护变得复杂，可能会持续维护几年，而交付人员付出的成本目前阶段可接受 |
| S102 | 新版本升级至新版本，所有授权项保持不变，不需要做任何授权操作 |
| S103 | 授权码中各授权项以名称标识 区别于数值标识，目的是提高兼容性，例如新增 taosX 授权项和新增复合主键功能时不需要升级 taosd 和 taosGrant |
| S104 | 内部供给云服务组无限授权的企业版本 - 集群创建后即可进入已授权状态，各参数不做任何限制，也禁止各种状态迁移 - 此部分的特殊逻辑封装到 grant 库中，考虑使用不同的链接库 |
| S105 | Windows 版本、Linux 版本、Arm 版本按同样逻辑实现，机器码生成方式不一定采用 cpuid |
| S106 | 不为企业版本发布单独的云服务版本，授权码生成时设置为不检查硬件变更 解决的问题：单独发布无限授权的云服务版本（即便只是镜像），使得获取无限授权的企业版变为可能；采用特定类型授权码，用户只能通过拷贝 docker 中的数据文件完成集群复制 |
