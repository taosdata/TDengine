## 2. 引言

在物联网、运维监控等实时性要求极高的场景中，时序数据的价值随时间迅速衰减，对最新数据的访问频率远高于历史数据。业务系统迫切需要实时获取最新数据以驱动实时决策、即时洞察和动态监控，这意味着数据处理系统必须具备毫秒级的响应能力。
为应对这一挑战，TDengine 作为高性能时序数据库，亟需一个专用的时序最新数据的缓存层。该模块旨在将最新的“热数据”常驻内存，为高并发查询提供内存级访问速度，从而显著降低读取延迟、提升吞吐量，并有效缓冲写入压力。这不仅是优化性能的关键手段，更是确保 TDengine 能够满足实时业务需求、发挥时序数据即时价值的核心架构保障。

### 2.1 术语与缩写名词

| 术语/缩写 | 全称/别名 | 解释 |
| --- | --- | --- |
| NONE | NONE 值，也称未制定值 | 用于表示字段未被赋值的特殊标记，该字段不会更新已写入的相同时间戳该字段的前值 |
| NULL | NULL 值 | 用于表示字段值为空的特殊标记，该字段会更新已写入的相同时间戳该字段的前值，对用户而言，NONE 值和 NULL 值均表示空值 |
| Cach | 缓存 | 用于临时存储数据以加快后续访问速度的高速存储区域 |
| Hot Data | 热数据 | 指近期产生、访问频率极高的数据 |
| LRU | Least Recently Used | 最近最少使用算法，一种常用的缓存淘汰策略 |
| Last | 最新非空值 | 各字段中最新（对应时间戳最大）的非空值 |
| Last Row | 最后一条记录 | 最新（对应时间戳最大）一条行数据，数据中可包含空值 |

## 3. 需求目标

本需求旨在设计并实现一个高效的时序数据缓存模块，具体目标如下：
1. **降低读取延迟**：通过将高频访问的最新数据（热数据）存储在缓存中，实现毫秒级的最新数据查询响应，满足实时监控和决策的业务需求。
2. **提升系统吞吐量**：利用内存的高速读写特性，支持高并发的数据写入与查询，减轻底层存储引擎的压力。
3. **优化资源利用**：通过合理的缓存淘汰策略（如 LRU），确保有限的内存资源优先服务于最有价值的数据。
4. **保证数据一致性**：在缓存与持久化存储之间建立可靠的同步机制，确保用户获取的数据准确无误。
5. **灵活的缓存配置**: 支持用户自定义缓存策略，满足不同业务场景的需求。
6. **无缝集成**：作为 TDengine 的核心组件，缓存层应 transparently（透明地）服务于上层应用，无需用户修改现有查询逻辑即可享受性能提升。

## 4. 功能需求

| 序号 | **功能类别** | **功能名称** | 功能描述 |
| --- | --- | --- | --- |
| FR-01 | 缓存启停 | 系统支持功能的动态启动或停止 |
| FR-02 | 缓存参数设置 | 系统支持主要参数的热更 |
| FR-03 | 缓存写入更新 | 当新数据写入时，需同步更新缓存中的对应数据。写入新数据后，立即查询 last 缓存应返回最新值。 |
| FR-04 | 缓存策略 | 支持基于内存使用量或 LRU 策略淘汰冷数据。当内存达到阈值时，自动清理最久未访问的数据。 |
| FR-05 | 数据删除更新 | 当删除的数据影响缓存内部数据状态时，删除缓存内的数据 |
| FR-06 | 查询优化 | 缓存命中加速查询 | 当缓存命中时，直接返回缓存中的结果，避免再次执行查询逻辑。 |
| FR-07 | 系统监控 | 缓存统计监控 | 提供缓存命中率、内存占用、淘汰数量等监控指标，可通过系统表或 API 查看缓存运行状态指标。 |

## 5. 性能需求

| 序号 | **功能类别** | **功能名称** | 功能描述 |
| --- | --- | --- | --- |
| PR-01 | 数据更新性能 | 缓存写入延迟 | 写入操作增加的额外延迟 < 10%，缓存更新逻辑不应显著拖慢整体数据写入流程。 |
| PR-03 | 查询性能 | 缓存读取延迟 | 1. 在缓存命中时，last 查询响应时间应低于 10ms（在 1000 并发场景下）。 1. 在缓存未命中时，单表查询性能应与未启用缓存时基本一致。 |
| PR-04 | 系统初始化性能 | 启动/恢复时间 | 缓存模块初始化时间 < 5s，模块加载不应显著延长数据库整体启动时间（不含大规模预热数据加载时间）。 |

## 6. 安全需求

| 序号 | **功能类别** | **功能名称** | 功能描述 |
| --- | --- | --- | --- |
| SR-01 | 访问控制 | 缓存层必须遵循数据库整体的权限控制策略，禁止未授权用户访问缓存数据。 |
| SR-02 | 数据隔离 | 不同租户或不同数据库之间的缓存数据必须严格隔离，防止数据泄露。 |
| SR-03 | 资源安全 | 资源配额限制 | 限制单个用户或租户可使用的最大缓存内存。 |

## 7. 其他需求

| 序号 | **功能类别** | **功能名称** | 功能描述 |
| --- | --- | --- | --- |
| OR-01 | API 透明兼容 | 缓存层的引入对上层应用必须透明，现有的 SQL 查询和写入接口保持不变。 |
| OR-02 | 数据类型全覆盖 | 缓存模块必须支持 TDengine 所有现有的数据类型，包括数值、布尔、字符串及时间戳。 |
| OR-03 | 客户端版本兼容 | 保证旧版本客户端驱动程序能够正常连接并与带有缓存模块的服务端交互。 |
| OR-04 | Schema 变更适配 | 当表结构发生变更（如增加列）时，缓存层应能自动适配或失效旧缓存，不引发错误。 |
| OR-05 | 动态配置支持 | 支持在不重启数据库服务的情况下，动态调整缓存内存上限等关键参数。 |
| OR-06 | 详细诊断日志 | 提供分级的日志记录功能，能够记录缓存命中情况、淘汰触发、内存分配异常等关键事件。 |
| OR-07 | 手动管理工具 | 提供运维命令或工具，允许管理员手动清除指定表或全部的缓存数据。 |
| OR-08 | 监控指标 | 提供缓存模块的运行指标（命中率、内存使用率等）的展示方法 |
| OR-09 | 故障自愈与隔离 | 当缓存模块内部发生非致命错误（如内存分配失败）时，应自动降级为直读存储，不影响主流程。 |
| OR-10 | 易用性需求 | 详细的文档说明 | 提供详细的文档说明，指导用户如何配置和使用缓存功能。 |
