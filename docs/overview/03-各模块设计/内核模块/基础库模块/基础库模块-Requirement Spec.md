## 2. 引言

### 2.1 术语与缩写名词

- **TDengine**: 涛思数据开发的专为物联网设计的高性能时序数据库
- **CMake**: 跨平台自动化构建系统
- **外部依赖**: 通过 CMake ExternalProjec t机制从外部源码构建的第三方库
- **内部基础库**: TDengine 项目内部维护的基础功能库，位于`contrib`目录
- **系统依赖**: 操作系统提供的标准库和运行时库

### 2.2 相关文档资料

1. TDengine 源码仓库: https://github.com/taosdata/TDinternal
2. CMake 构建系统文档
3. 各第三方库的官方文档

### 2.3 优先级要求

- **高优先级**: 核心压缩库(zlib, lz4, xz)、加密库(OpenSSL)、网络库(libuv, libcurl)
- **中优先级**: 测试框架(googletest)、JSON处理(cJSON, jansson)、正则表达式(pcre2)
- **低优先级**: 平台特定库(Windows 平台相关)、可选功能库(S3/COS 存储支持)

### 2.4 版本要求

- **开源版**: 支持所有基础库依赖
- **企业版**: 额外支持 SASL2 认证、企业级存储集成等
- **版本兼容性**: 需保持向后兼容，确保老版本构建系统能正常工作

## 3. 需求目标

TDengine 作为高性能时序数据库，在编码过程中需要依赖众多基础库以实现核心功能。本需求文档旨在明确 TDengine  开发过程中所需的基础库依赖，包括：
1. 明确外部第三方库的版本要求和构建方式
2. 规范内部基础库的管理和维护
3. 确保跨平台（Linux、macOS、Windows）的兼容性
4. 提供清晰的依赖管理策略，便于新开发者理解和维护

## 5. 性能需求

1. **构建性能**: 外部依赖的构建应支持并行化和缓存机制，减少重复构建时间
2. **运行时性能**: 基础库的选择应以高性能为首要考虑，特别是压缩、加密和网络库
3. **内存使用**: 内存敏感环境下，应优先选择内存效率高的库（如 jemalloc）
4. **启动时间**: 依赖库的加载不应显著影响 TDengine 的启动时间
5. **二进制大小**: 在嵌入式场景下，应支持裁剪不必要的依赖以减小二进制体积

## 6. 安全需求

1. **加密通信**: 所有网络通信应支持 TLS 加密，使用最新版本的 OpenSSL
2. **认证授权**: 支持 SASL2 认证机制，确保访问安全
3. **依赖安全**: 定期更新第三方库，修复已知安全漏洞
4. **代码审计**: 关键安全相关库（如加密库）应进行代码安全审计
5. **许可证合规**: 确保所有依赖库的许可证与 TDengine 许可证兼容

## 7. 其他需求

### 7.1 兼容性需求

1. **平台兼容性**: 支持 Linux（多种发行版）、macOS、Windows 操作系统
2. **架构兼容性**: 支持 x86_64、ARM64 等多种 CPU 架构
3. **编译器兼容性**: 支持 GCC、Clang、MSVC 等主流编译器
4. **版本兼容性**: 保持与主流 Linux 发行版自带库版本的兼容性

### 7.2 接口需求

1. **C 语言接口**: 所有基础库应提供稳定的 C 语言 AP I接口
2. **头文件规范**: 统一头文件包含路径，避免路径冲突
3. **符号导出**: 控制库符号的可见性，避免符号冲突
4. **错误处理**: 统一的错误码和异常处理机制

### 7.3 运维需求

1. **构建可重复性**: 构建过程应可重复，不依赖网络环境
2. **版本锁定**: 第三方库应锁定具体版本或 commit hash
3. **离线构建**: 支持完全离线环境下的构建
4. **依赖检查**: 提供依赖检查工具，确保依赖完整性

### 7.4 易用性需求

1. **文档完善**: 提供完整的依赖管理文档
2. **一键构建**: 简化构建过程，减少用户配置
3. **问题排查**: 提供详细的错误信息和排查指南
4. **配置灵活**: 支持通过 CMake 选项灵活启用/禁用特定依赖

### 7.5 测试需求

1. **依赖测试**: 对每个基础库提供基本的集成测试
2. **兼容性测试**: 定期测试不同版本组合的兼容性
3. **性能测试**: 评估不同依赖库版本对性能的影响
4. **安全测试**: 定期进行安全漏洞扫描和测试

## 9. 构建配置说明

TDengine 使用 CMake 作为构建系统，依赖管理主要通过以下机制实现：
1. **ExternalProject**: 用于下载和构建外部第三方库
2. **contrib 目录**: 存放内部维护的基础库
3. **条件编译**: 通过 CMake 选项控制可选依赖的启用/禁用
4. **系统检测**: 自动检测系统已安装的库，避免重复构
关键 CMake 选项：
- `BUILD_CONTRIB`: 是否构建内部基础库
- `BUILD_TEST`: 是否构建测试相关依赖
- `BUILD_WITH_UV`: 是否启用 libuv
- `BUILD_WITH_S3`: 是否启用 S3 存储支持
- `BUILD_JEMALLOC`: 是否启用 jemalloc
- `TD_EXTERNALS_USE_ONLY`: 仅使用已安装的外部库，不下载构建

## 10. 维护指南

1. **版本升级**: 定期检查第三方库的新版本，评估升级必要性
2. **安全更新**: 及时应用安全补丁，特别是加密和网络相关库
3. **兼容性测试**: 升级后需进行全面的兼容性和性能测试
4. **文档更新**: 依赖变更后及时更新相关文档
5. **许可证审查**: 新增依赖时需进行许可证兼容性审查

## 11. 故障排查

常见问题及解决方案：
1. **网络问题**: 配置本地镜像源或使用离线构建
2. **版本冲突**: 明确指定库版本，避免自动升级
3. **构建失败**: 检查系统依赖和编译器版本
4. **符号冲突**: 控制符号导出，使用静态链接
5. **性能问题**: 选择性能优化的库版本和编译选项
