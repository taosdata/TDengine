## 2. 引言

在某些应用场景中，应用逻辑需要的查询功能无法直接使用内置函数来实现，TDengine 允许编写用户自定义函数（UDF），以便解决特殊应用场景中的使用需求。UDF 在集群中注册成功后，可以像系统内置函数一样在 SQL 中调用，就使用角度而言没有任何区别。UDF 分为标量函数和聚合函数。标量函数对每行数据输出一个值，如求绝对值（abs）、正弦函数（sin）、字符串拼接函数（concat）等。聚合函数对多行数据输出一个值，如求平均数（avg）、取最大值（max）等。
期望 TDengine 的 sql 能支持 UDF 的使用，用户用 c / python 语言实现 udf 函数，然后在 sql 中创建 udf 函数，并能像 TDengine 内置函数一样使用。

## 3. 需求目标

1. 实现 udf 需要的功能，包括功能和性能需求两部分，功能需求包括 udf 函数实现需要的接口定义，创建自定义函数时所使用的sql 语句及 udf 调用，性能要求核心为 udf 模块和 taosd 低耦合，异常不一样 taosd 业务。
2. 提供 udf 使用的帮助文档，用户仅依据文档能完成 udf 的接入和使用。

## 4. 功能需求

1. 完成 UDF 实现接口的约定；
2. 提供 UDF 函数的创建方法，创建时可指定 C 语言编译的动态链接库，或者 python 的 UDF 实现文件
3. 创建 UDF 函数之后，能像内置函数一样使用。 
4. 支持标量函数和聚合函数
5. 支持更新 UDF 函数

## 5. 性能需求

暂无

## 6. 安全需求

实现用户自定义函数运行在受控环境下，被严格限定在预设的安全边界内，同时不影响宿主系统及其他模块的稳定运行。
1. 隔离执行环境：自定义函数模块必须在独立的、资源受限的沙箱环境中运行，即一个独立的进程空间中运行。
2. 最小权限：每个模块明确定义并强制执行最小权限集，模块仅能访问其功能所必需的系统资源。
3. 输入验证：所有传递给自定义函数模块的输入参数必须经过严格的验证和净化。这包括类型检查、长度限制（防止缓冲区溢出）、内容过滤（如SQL注入、XSS脚本检查）。
4. 安全内存：系统提供的 API 或模块内部若涉及内存操作，应强制使用安全版本函数（如memcpy_s, memset_s），确保进行边界检查，防止缓冲区溢出。
5. 故障隔离与恢复：单个模块的崩溃或异常不得导致整个宿主系统或其他模块失效。系统应具备快速重启失败模块或切换到安全状态的能力。
6. 安全机制（如系统调用拦截、内存检查）引入的性能开销应在设计可接受范围内，不应严重影响系统核心功能。
7. 安全审计日志：所有安全相关事件，包括模块加载、权限检查结果等，都必须记录到不可篡改的审计日志中，日志应包含时间戳、模块标识、操作详情和结果。

## 7. 第三方依赖需求

自定义函数模块提供 Python 脚本的 UDF 执行支持，UDF 脚本的运行需要 宿主机 Python 环境的支持。TDengine 不直接依赖于 Python 环境运行，用户为了确保 Python 脚本能够正常执行，需要自行确保 Python 环境能够运行相应的 Python UDF 脚本。
