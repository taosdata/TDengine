## 2. 引言

### 2.1 术语与缩写名词

1. **TDengine**：一种高性能、支持分布式架构的时间序列数据库。
2. **FQDN**: 即完全限定域名，是互联网中用于唯一标识一台特定主机或服务的完整、绝对域名。它能够明确指出主机在DNS层次结构中的确切位置，确保信息准确无误地送达。
3. **IP**:  指网际互连协议，Internet Protocol的缩写，是TCP/IP体系中的网络层协议。
4. **Latency**：从发出请求到接收到响应所花费的时间。
5. **EpSet**：集群内各个节点（主副本）地址所组成的集合。
6. **TCP**：是一种面向连接的、可靠的、基于字节流的传输层通信协议。

### 2.3 优先级要求

不同节点间、同一个节点内不同组件进程通信所使用的基础模块，具有很高的优先级。

企业版本具备额外的安全通信、黑白名单等安全相关功能，社区版不具备安全相关的功能。

## 3. 需求目标

### 3.1 背景

本文档旨在定义和描述一个高性能网络传输系统的需求，该系统主要用于并发访问数据、数据库之间的数据传输。系统需要确保高效、可靠、安全的数据传输，以支持大规模数据处理和实时数据同步。

### 3.2 目标

1. 提供高吞吐量和低延迟的数据传输。
2. 实现高效的数据压缩。
3. 支持大规模并发连接和数据流。
4. 提供灵活的配置和扩展性。
5. 提供高级别的安全保障，确保数据传输的安全性、可靠性、完整性，一定程度上防止拒绝服务攻击。

## 4. 功能需求   

### 4.1 数据传输协议

1. 支持 TCP 协议。
2. 实现自定义协议，针对大规模时序数据处理场景中数据传输的特点和需求，提供高性能的传输能力。

### 4.2 自适应压缩

1. 动态自适应压缩

### 4.3 自动错误处理和恢复

1. 自动错误检测
2. 连接/消息发送失败后，自动发起重传机制
3. 服务端断开后，客户端具有自动自动重连

### 4.4 高性能通信

1. 连接复用
2. 内置连接池机制
3. 具备零拷贝机制

## 5. 性能需求

本需求对系统的写入、查询、以及启动等关键方面的性能提出了明确的要求，旨在确保系统具备高吞吐量和低延迟特性。
1. 在数据传输能力方面，系统必须能够在多种不同的数据包大小（package size）情景下，充分消耗掉千兆以太网的全部可用带宽，以确保数据传输的高效性。
2. 吞吐量默认不小于 100,000 QPS，上限取决于线程数目配置和硬件配置。
3. 为了维持高效能，传输协议本身引入的系统开销必须严格控制在小于 5% 的范围内。 CPU 占用率 ≤ 20%，内存占用 ≤ 1 GB。
4. 在系统可用性方面，传输模块的启动时间必须小于 300 毫秒，传输延迟 ≤ 1 ms（局域网内）以保证快速上线和故障恢复。
5. 此外，系统必须具备强大的并发连接支撑能力，能够稳定地支撑大规模（例如 50,000 个）并发连接请求。

## 6. 安全需求

### 6.1 通信机密性

确保所有传输中的数据对未经授权的第三方保持机密。
1. 强制传输层加密：支持并默认启用 TLS/SSL (Transport Layer Security) 协议（TLS 1.3 或更高版本）来加密所有网络传输的数据。
2. 强制加密套件支持：支持并优先使用前向保密性 (Forward Secrecy) 的强加密套件（例如，基于 ECDHE 的套件），并禁止使用已知的弱加密算法（如 DES、RC4 等）。

### 6.2 身份验证

确保通信双方（客户端、服务器、节点）的身份真实性。
1. 服务端身份验证：客户端连接服务器时，通过 TLS 证书验证服务器的身份，防止中间人攻击 (MITM)。
2. 客户端身份验证（互信）：支持可选的双向 TLS (Mutual TLS/mTLS)，以在分布式节点间或需要高安全性的客户端连接中使用，强制客户端也提供有效证书。

### 6.3 数据完整性

确保数据在传输过程中不被篡改。
1. 消息认证码：使用 TLS 协议提供的 MAC（Message Authentication Code）机制（如：HMAC-SHA256 或 AEAD 模式的加密）来验证每个数据包的完整性。
2. 重放保护：使用（使用序列号、时间戳或一次性随机数等）有效机制检测和拒绝重放攻击。

### 6.4 可用性与韧性

确保通信服务能够抵抗拒绝服务（DoS）攻击、缓冲区溢出攻击、注入攻击。
1. 连接资源限制：实现连接数限制、连接速率限制以及会话超时机制，防止资源耗尽型的拒绝服务 (DoS) 攻击。
2. 输入验证预过滤：对所有传入数据（如连接字符串、请求头、协议字段）进行输入长度和格式验证，防止缓冲区溢出和协议注入攻击。
3. 流量控制：根据用户角色或连接类型对数据传输速率进行限速，以保证关键业务的带宽可用性。
4. 黑白名单设置：设置 IP 地址黑白名单，拒绝不在名单范围内的连接请求。

### 6.5 配置与管理

核心需求是确保安全机制本身易于管理和安全配置。
1. 安全默认配置：默认配置下启用最安全的设置（例如，默认启用 TLS，默认禁用弱密码套件）。
2. 证书管理接口：提供安全的接口来加载、更新和管理 TLS 证书和密钥。
3. 安全事件日志：关键安全事件（如连接失败、身份验证失败、证书过期、DoS 限制触发）记录详细日志，以便进行安全审计和监控。

## 7. 第三方依赖需求

通信模块的功能代码自主研发为主，现在依赖一个开源的外部库 `libuv`。libuv 是一个专为高性能网络和文件系统操作设计的多平台支持库。通过事件循环机制，实现了高效的异步 I/O 处理，特别适用于高并发场景。
对于外部依赖的软件，在授权许可变更、安全漏洞等方面带来的查询引擎运行安全风险，需要有积极、快速、完备的应对策略和方案。
