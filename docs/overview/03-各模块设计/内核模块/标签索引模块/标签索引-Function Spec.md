## 2. 背景

在时间序列数据库的架构中，超级表（Super Table）的标签（Tag）是描述数据采集点（如传感器、设备）静态属性的关键元数据字段，例如设备ID、地理位置、型号等。这些标签为海量的时间序列数据提供了重要的维度分类和语义上下文。在实际业务应用，如物联网监控、工业互联网或金融实时分析中，用户需要依据这些标签进行数据查询、过滤与分组聚合，以获取特定维度下的时序信息。
然而，随着业务规模的扩展和数据量的指数级增长（可能达到数十亿甚至万亿条记录），基于标签的查询性能面临显著挑战。尤其是在高并发、低延迟要求的高频查询场景下（如实时监控仪表盘、频繁的条件过滤操作），传统的低效的标签匹配机制会迅速成为系统瓶颈，导致查询响应时间延长、数据库服务器负载激增，最终影响业务决策的实时性和终端用户体验。
针对这一性能瓶颈，一种高效且常见的优化策略是：为超级表的标签字段创建专用的索引（如哈希索引、倒排索引等）。创建索引后，数据库引擎可以快速定位到含有特定标签值的数据子集，避免不必要的全量标签数据扫描，从而显著提升查询性能：大幅降低标签过滤查询的延迟，提高吞吐量；有效降低系统负载：减少CPU和I/O资源的消耗，使系统更能应对高并发压力。改善用户体验：为应用提供更快速、更稳定的数据查询服务，保障业务流畅运行。
因此，对超级表的关键标签字段增加索引策略，是确保查询系统长期高性能、高可扩展性的重要策略和机制。

## 3. 定义

1. **TDengine**：一种高性能、支持分布式架构的时间序列数据库。
2. **超级表（Super Table）**：在TDengine中"一个设备一张表" 的建模设计思路情况下，针对同一类型的每种设备的表，用来标识该类型的全部表集合称为“超级表”。超级表用来代表一组相同类型的数据采集点在数据库中表的集合。由于同一类型的设备拥有完全相同的数据模式，可以像操作普通表一样针对超级表进行写入、查询等操作。
3. **标签（Tag）**：用于描述每个设备的相对稳定的属性信息，每个子表一条标签信息。标签信息也具有模式（schema）的定义，归属于同一个超级表的表的标签具有相同的模式。
4. **结构化查询语言（Structured Query Language，SQL）：**是一种用于管理和操作关系型数据库的标准编程语言。 它允许用户存储、更新、删除、搜索和检索数据库中的数据。 SQL 被广泛应用于各种数据中心应用程序中，是 ISO 和 ANSI 等标准化机构认可的国际标准。
5. **索引（Index）: **针对数据库中数据进行位置定位和组织的一种数据结构，可以快速定位搜索的数据的位置从而提升查询性能。

## 4. 行为说明

### 4.1 SQL语法

`**创建索引**`**:**
`CREATE INDEX index_name ON tbl_name (tagColName）`
其中的 index_name 为索引名称， tbl_name 为超级表名称, tagColName 为标签列名称,  tagColName 不限制类型。 
`**删除索引**`**：**
`DROP INDEX index_name`;    index_name 代表索引名称
`**查看索引**`**：**
`SELECT * FROM information_schema.INS_INDEXES` 
从元数据库中检查获得存在的全部标签索引的元信息。
```c
taos> create index ta_3_db.t2i on ta_3_mt  (t2);
Create OK, 0 row(s) affected (0.080824s)

taos> select * from information_schema.ins_indexes\G;
***************************1.row **************************
 index_name: t2i
    db_name: ta_3_db
 table_name: ta_3_mt
  vgroup_id: -1
create_time: 2023-02-13 21:07:49.874
column_name: t2
 index_type: tag_index
Query OK, 1 row(s) in set (0.014298s)
```

### 4.2 参数修改

  无

### 4.3 其它行为

1. **索引更新**：当超级表的标签字段数据发生变化或增删子表时候时， 自动更新索引。
2. **索引重建**：支持手动触发索引重建。
3. **查询优化**：查询时，首先通过索引定位目标数据，如果索引中不存在，则扫描所有子表，如果索引存在，则通过定位到对应的子表

## 5. 性能

1. **启动性能**：标签索引不对数据库的启动性能造成影响。
2. **写入性能**：标签索引不应显著影响数据写入性能，写入延迟增加不得超过 10%。
3. **查询性能**：
  - 在索引命中时，标签查询响应时间低于 10ms（在 1000 并发场景下）。
  - 在索引未命中时，查询性能应与未启用索引时基本一致。

## 6. 安全

索引文件完整性保证。依托于存储模块提供的加密存储和完整性校验机制，确保保存的索引文件完整性和防篡改的能力。
标签索引操作审计跟踪。记录调用索引的时间和调用缘由、发起调用的用户、调用索引的查询对象，特别是高频率的索引扫描。后续审计员可以利用这些日志监控数据库中的各种行为，追踪非法存取数据的人员和时间，实现追溯和责任认定。
标签索引安全管理。当原始时序数据删除时，确保相关的索引块数据被不可恢复地安全删除，防止标签索引数据导致的信息泄露。

## 7. 兼容性

 索引功能需与 TDengine 现有功能完全兼容

## 9. 使用场景

1. 在需要根据 标签进行高频查询的场景下可使用索引功能。
2. 在需要根据 标签进行范围查询的场景下推荐使用 B+ 树索引。
3. 在需要根据 标签进行精确查询的场景下推荐使用哈希索引。

## 10. 约束和限制

1. **约束**：无
2. **限制**：超级表查询涉及子表数量较多时，推荐在创建 DB 时打开索引，而不是在写入过程中启用索引
