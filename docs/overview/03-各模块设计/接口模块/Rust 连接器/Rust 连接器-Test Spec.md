## 2. 测试目标

1. 功能测试：验证 Rust 连接器的所有 API 功能是否按照设计规范正确工作，包括连接建立、SQL 执行、无模式写入、参数绑定、数据订阅等核心功能。
2. 性能测试：评估连接器在高并发、大数据量场景下的性能表现，包括连接建立时间、查询响应时间、数据写入吞吐量、内存使用效率等关键指标。
3. 安全性测试：验证连接器的安全机制是否有效，包括凭证脱敏、TLS/SSL 加密传输、认证失败处理、SQL 注入防护等安全特性。
4. 稳定性测试：通过长时间运行和压力测试，验证连接器在各种异常情况和边界条件下的稳定性和可靠性。
5. 兼容性测试：确保连接器与不同版本的 TDengine 数据库、不同 Rust 编译器版本、不同操作系统平台以及不同连接方式（WebSocket/Native）的兼容性。

1. 功能测试：

## 5. 已知问题和限制

1. **Native 连接依赖**：Native 连接方式需要本地安装 TDengine 客户端动态库（libtaos.so 或 taos.dll），增加了部署复杂度。
2. **版本兼容性要求**：Native 连接要求客户端的 taosc 版本与服务端 TDengine 版本严格匹配。
3. **WebSocket 连接依赖 taosAdapter**：WebSocket 连接方式需要 taosAdapter 服务正常运行。
4. **异步接口限制**：部分同步接口是通过异步接口封装的，可能存在性能开销。
5. **TLS/SSL 配置复杂度**：高级 TLS/SSL 配置（如自定义 CA 证书）需要通过 DSN 参数配置，不够直观。
