## 2. 引言

在物联网和工业互联网快速发展的背景下，时序数据的存储和分析变得越来越重要。TDengine 作为一款专门针对物联网场景优化的开源时序数据库，需要一个符合标准的 JDBC 驱动来支持 Java 生态系统的应用开发。
驱动的实现需要严格遵循 JDBC 规范，提供标准的接口实现，对于 JDBC 标准无法支持的功能如数据订阅，无模式写入等可以用扩展接口实现。
我们的目标是提供一个功能完备、性能优异、使用友好的 JDBC 驱动，支持完整的 TDengine 核心功能（执行 SQL，参数绑定，无模式写入和数据订阅）。

### 2.1 术语与缩写名词

1. **JDBC**： JDBC （Java Database Connectivity） 是 Java 平台提供的数据库访问标准接口，它让 Java 应用能够统一地访问不同的数据库系统。
2. **无模式写入**： 是指在写入数据时无需预先定义表结构，系统会根据数据自动创建或调整表结构的特性。
3. **数据订阅**： 允许客户端实时接收数据库中的数据变化，适用于实时监控场景。
4. **参数绑定**： 是在 SQL 语句中使用占位符替代具体值的技术，可以防止 SQL 注入并提高性能。
5. **WebSocket**： 是一种基于 TCP 的全双工通信协议，支持服务器和客户端之间的实时数据传输。
6. **SSL： **是一种安全协议，用于在网络上建立加密连接，确保数据在客户端和服务器之间传输时的保密性、完整性和身份验证。它通过使用公钥和私钥加密技术，对网络通信进行加密，防止数据被窃取、篡改或伪造。
7. **WSS：** WebSocket 协议的安全版本，WebSocket 是一种全双工通信协议，允许客户端和服务器之间进行实时双向通信，而 WSS 在 WebSocket 基础上使用 SSL/TLS 协议进行加密，提供更安全的通信方式。
8. **JNI （Java Native Interface）** ： 是 Java 提供的本地接口机制，允许 Java 代码调用用 C/C++ 等语言编写的本地代码，常用于性能优化。
9. **高效写入：**JDBC 连接器提供的一个特性，可以使单线程写入达到多线程写入吞吐量的方式。启动高效写入特性后，JDBC 连接器将自动创建写入线程与专属队列，将数据按子表切分缓存，在达到数据量阈值或超时条件时批量发送，以此减少网络请求、提升吞吐量，让用户无需掌握多线程编程知识和数据切分技巧即可实现高性能写入。
10. **负载均衡：**将客户端请求合理分配到多台服务器的技术，避免单台服务器过载。它能提升系统可用性、响应速度和扩展性，是高并发架构的核心组件之一。

### 2.2 相关文档资料

本连接器采用 Java 语言基于 TDengine 数据库开发，采用 JDBC 4.2 规范。JDBC 规范文档请参考：https://docs.oracle.com/javase/8/docs/technotes/guides/jdbc/jdbc_42.html

 无

### 2.4 版本要求

支持 JDK 1.8 及以上版本。

## 3. 需求目标

1. 提供标准接口:
   - 实现严格遵守 JDBC 规范的标准接口，支持常见的数据库操作，如连接、查询、插入、参数绑定等。
   - 在 BI 工具中，可以使用 JDBC 驱动来访问 TDengine 数据源。
2. 支持核心特性:
   - 支持 TDengine 的关键功能，例如高效的 SQL 执行、参数绑定、批量插入等，确保用户能够充分利用数据库的性能优势。
   - 对于 JDBC 标准接口没有包含的无模式写入和数据订阅功能，可以采用扩展接口提供。
3. 易于使用:
   - 构建一个易于集成和使用的 JDBC 驱动程序，附带详尽的技术文档和代码示例，帮助开发者快速上手。
4. 稳定性和可靠性:
   - 经过严格的测试流程，保证连接器的稳定性和可靠性，确保其能够在实际生产环境中成功部署和运行。

## 4. 功能需求

| 序号 | **功能类别** | 功能描述 |
| --- | --- | --- |
| 通过 JNI 与 taosc 接口交互，访问 TDengine，建立连接。 支持 IPv6。 |
| 使用 WebSocket 或者 wss 协议，通过 taosAdapter，访问 TDengine，建立连接。 WebSocket连接需要支持自动重连机制，默认关闭。 支持压缩，参数可配置，默认关闭。 WebSocket 采用独立协议标识 TAOS-WS。 支持在 WebSocket 连接上设置时区和应用信息。 在 WebSocket 连接上支持无符号数据类型。unsigned tiny int 用 short 实现，以此类推，unsigned long 用 BigInteger 实现。 在 WebSocket 连接上支持 Decimal 和 Blob 类型。 支持 IPv6。 支持负载均衡，节点故障后 failover，支持故障节点恢复后的连接重平衡。 |
| 支持 TDengine 的建库建表的 SQL语句 |
| 支持 TDengine 的插入数据的 SQL语句 |
| 支持 TDengine 的查询的 SQL语句 |
| 支持在执行 SQL 时设置 reqId，用于支持 SQL 执行的链路跟踪 |
| 3 | 无模式写入 | 支持无模式写入三种行协议 （InfluxDB 的行协议、OpenTSDB 的 telnet 行协议和 OpenTSDB 的 JSON 格式协议）并能正确的将数据写入。 |
| 4 | 结果获取 | 通过结果集对象可以获取查询到的数据和 Meta 信息。 |
| 通过参数绑定方式将数据正确的写入 TDengine 数据库，能避免SQL语法解析的资源消耗，从而显著提升写入性能。 通过参数绑定查询可以避免 sql 注入。 |
| 1. 基于标准 JDBC 参数绑定接口，将消息暂时缓存起来，等到满足一定的条件，再进行批量发送，这样可以减少网络请求,提高吞吐量。 1. 提供一个单线程的接口，更加方便用户使用，让用户在使用 TDengine 强大的写入能力同时，又可以不需要掌握多线程编程知识和数据切分处理。 1. 单线程写入性能接近多线程并发写入性能。 1. 仅支持超级表写入，不需要考虑普通表和子表。 1. 写入失败能通过定期接口调用感知。 |
| TDengine 消费者的概念跟 Kafka 类似，消费者通过订阅主题来接收数据流。消费者可以配置多种参数，如连接方式、服务器地址、自动提交 Offset 等以适应不同的数据处理需求。有的语言连接器的消费者还支持自动重连和数据传输压缩等高级功能，以确保数据的高效和稳定接收。 |
| 消费者订阅主题后，可以开始接收并处理这些主题中的消息。 |
| 消费者可以指定从特定 Offset 开始读取分区中的消息，这允许消费者重读消息或跳过已处理的消息。 |
| 当消费者读取并处理完消息后，它可以提交 Offset，这表示消费者已经成功处理到这个 Offset 的消息。Offset 提交可以是自动的（根据配置定期提交）或手动的（应用程序控制何时提交）。 |
| 消费者可以取消对主题的订阅，停止接收消息。当消费者不再需要时，应该关闭消费者实例，以释放资源和断开与 TDengine 服务器的连接。 |

## 5. 性能需求

| 使用场景 | 类别 | 要求 |
| --- | --- | --- |
| 支持10000个子表同时查询最新数据 | 查询 | 1秒内完成查询 |
| 支持10000个子表同时写入最新数据 | 写入 | 1秒内完成写入 |
| 数据订阅，单线程消费 1000 条记录平均时间 | 订阅 | 平均 1 秒内完成消费 |

数据模型以智能电表为例，其表结构为：
```sql
CREATE STABLE meters (
    ts timestamp, 
    current float, 
    voltage int, 
    phase float
) TAGS (
    location varchar(64), 
    group_id int
);
```

## 6. 安全需求

1. 日志/错误输出需脱敏（隐藏密码、token、路径）
2. 支持 TLS 认证
3. SQL 防注入：文档与示例必须优先使用 `PreparedStatement` 参数绑定，明确其为防 SQL 注入的要求。
4. 支持请求超时，避免资源耗尽。

## 7. 其他需求

1. 兼容性需求

2. 接口需求
   - 提供 SQL, 无模式写入, 参数绑定，数据订阅功能的相关接口。
3. 运维需求
4. 易用性需求

5. 测试需求（不含测试例）
   - 对主要功能以及异常情况都需要有测试用例覆盖
