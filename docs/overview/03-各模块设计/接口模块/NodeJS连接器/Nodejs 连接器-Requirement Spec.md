## 2. 引言

随着技术发展，越来越多前端开发者涉足后端和全栈开发，而 JavaScript 作为前端主流语言，在这一趋势中愈发重要。借助 Node.js 实现 TDengine 连接器，能让 JavaScript 开发者轻松与 TDengine 交互，既降低开发门槛，又提高开发效率 。

### 2.1 术语与缩写名词

**无模式写入：**是指在写入数据时无需预先定义表结构，系统会根据数据自动创建或调整表结构的特性。
**数据订阅：**允许客户端实时接收数据库中的数据变化，适用于实时监控场景。
**参数绑定：**是在 SQL 语句中使用占位符替代具体值的技术，可以防止 SQL 注入并提高性能。
**WebSocket：** 是一种在单个 TCP 连接上提供全双工通信的协议。它允许客户端和服务器之间的双向实时通信，避免了 HTTP 请求-响应模型的限制。WebSocket协议的定义和规范是由 IETF（Internet Engineering Task Force）标准化的，其主要文档是 [RFC 6455](https://datatracker.ietf.org/doc/html/rfc6455)。
**FQDN：**全限定域名是互联网域名系统（DNS）中的一种完整的、唯一的域名表示形式，用于明确标识互联网上的特定主机或服务器。
**RFC3339：**RFC 3339 是一种时间和日期格式的标准，旨在规范化地表示时间和日期，以便在计算机系统之间传递和处理。

### 2.2 相关文档资料

本连接器采用 [TypeScript](https://www.typescriptlang.org/) 语言基于 TDengine 数据库开发， 涉及  TDengine 相关资料请参考：https://docs.taosdata.com/

### 2.3 优先级要求

无

### 2.4 版本要求

版本类型：独立组件，开源发布。支持 Node.js 14 以上版本以及 TDengine 3.3.2.0 及以上版本。

## 3. 需求目标

需要为 TDengine 数据库提供官方的 Node.js 语言的 Websocket 连接器，Node.js 开发人员可以通过它无缝的操作 TDengine 数据库。
- 提供 Node.js 语言的 Websocket 接口:
  - 实现连接器相关的接口，支持常见的数据库操作，如连接、查询、插入、参数绑定，数据订阅等。
- 支持核心特性:
  - 支持 TDengine 的关键功能，例如高效的 SQL 执行、参数绑定、批量插入等，确保用户能够充分利用数据库的性能优势。
- 易于使用:
  - 方便用户构建一个易于集成和使用的 Node.js 应用程序，附带详尽的技术文档和代码示例，帮助开发者快速上手。
- 稳定性和可靠性:
  - 经过严格的测试流程，保证连接器的稳定性和可靠性，确保其能够在实际生产环境中成功部署和运行。

## 4. 功能需求

| 序号 | **功能类别** | 功能描述 |
| --- | --- | --- |
| 通过 taosAdapter 组件提供的 WebSocket API 建立与 taosd 的连接 |
| 对连接进行管理，当有申请连接时，从空闲队列中初始化一个提供给使用方，避免频繁创建和销毁连接。 |
| 支持 TDengine 的建库建表的 SQL语句 |
| 支持 TDengine 的插入数据的 SQL语句 |
| 支持 TDengine 的查询的 SQL语句 |
| 支持在执行 SQL 时设置 reqId，用于支持 SQL 执行的链路跟踪 |
| 3 | 无模式写入 | 支持无模式写入三种行协议 （InfluxDB 的行协议、OpenTSDB 的 telnet 行协议和 OpenTSDB 的 JSON 格式协议）并能正确的将数据写入。 |
| 4 | 结果获取 | WSRows 对象可以通过循环遍历获取查询到的数据和 Meta 信息。 |
| 5 | 参数绑定 | 通过参数绑定方式将数据正确的写入 TDengine 数据库，能避免SQL语法解析的资源消耗，从而显著提升写入性能。 |
| TDengine 消费者的概念跟 Kafka 类似，消费者通过订阅主题来接收数据流。消费者可以配置多种参数，如连接方式、服务器地址、自动提交 Offset 等以适应不同的数据处理需求。有的语言连接器的消费者还支持自动重连和数据传输压缩等高级功能，以确保数据的高效和稳定接收。 |
| 消费者订阅主题后，可以开始接收并处理这些主题中的消息。 |
| 消费者可以指定从特定 Offset 开始读取分区中的消息，这允许消费者重读消息或跳过已处理的消息。 |
| 当消费者读取并处理完消息后，它可以提交 Offset，这表示消费者已经成功处理到这个 Offset 的消息。Offset 提交可以是自动的（根据配置定期提交）或手动的（应用程序控制何时提交）。 |
| 消费者可以取消对主题的订阅，停止接收消息。当消费者不再需要时，应该关闭消费者实例，以释放资源和断开与 TDengine 服务器的连接。 |

## 6. 安全需求

| 序号 | **功能类别** | **功能名称** | 功能描述 |
| --- | --- | --- | --- |
| 凭证脱敏 | 所有连接器必须在日志、错误消息、调试输出中脱敏密码、Token 等敏感凭证信息 |
| 安全存储指导 | 文档必须提供环境变量、密钥管理服务（Vault/Secrets Manager）等安全存储方案，禁止硬编码 |
| 2 | 传输加密 | 支持 TLS/SSL 连接 | 支持 TLS 加密连接 |
| 3 | 资源管理 | 会话超时 | 支持会话超时、连接超时 |
| 4 | 认证授权 | 认证失败处理 | 记录认证失败事件，支持速率限制防止暴力破解 |

## 7. 其他需求

描述功能、性能之外的需求。
- 兼容性需求
  兼容 TDengine 3.3.2.0 及更高版本。
- 接口需求
  提供 SQL, 无模式写入, 参数绑定，数据订阅功能的相关接口。
- 运维需求
无特殊运维需求。
- 易用性需求
  接口设计合理，调用简单。
- 测试需求（不含测试例）
  对主要功能以及异常情况都需要有测试用例覆盖
