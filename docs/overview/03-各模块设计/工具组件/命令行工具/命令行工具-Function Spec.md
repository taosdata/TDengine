## 2. 背景

为了方便对 TDengine 数据库做交互操作，需要一款简洁的命令行工具，能够支持远程连接不同数据源的 TDengine 服务器，提供 SQL 语句执行能力，并能够格式化输出 SQL 执行结果。同时对于自动化运营维护 TDengine 数据库的脚本程序，提供非交互式命令行方式执行 SQL 语句的能力。 

## 3. 定义

**命令行参数**：指通过命令行输入的长参及短参
**TDengine Cloud **：全托管的物联网、工业大数据云服务平台
**TAB  键补全**：  指通过在指定位置按下 TAB 键，自动匹配输入可能出现的命令行、关键词等自动化填写技术

## 4. 行为说明

### 4.1 连接功能

| 需求编号 | 功能项 | 功能实现 |
| --- | --- | --- |
| 1.1 | 连接本地部署 TDengine | 通过命令行参数指定连接属性： -h， --host=HOST 设置连接主机名，IP 地址及 hostname 均可 -P， --port=PORT 设置连接端口 -u， --user=USER 设置连接用户名 -p， --password 设置连接密码 -Z， --driver 指定连接方式，0 表示采用原生连接方式，1 表示采用 WebSocket 连接方式，默认采用原生连接方式。 示例： 连接至本地部署的 192.168.0.1 服务器 ```bash taos -h 192.168.0.1 -P 6030 -u root -p taosdata ``` |
| 1.2 | 连接 TDengine Cloud | 通过命令行参数指定连接属性： -E, --dsn=CLOUD_DSN CLOUD_DSN 在登录入 TDengine Cloud 产品主页 -> 工具 -> taos-Cli 中提供，格式如下： ```bash https://gw.cloud.taosdata.com?token=617ffdf3... ``` 示例： 连接至域名为 gw.cloud.taosdata.com 的 TDengine 云服务 ```bash taos --dsn=https://gw.cloud.taosdata.com?token=617ffdf3... ``` |
| 1.3 | 网络检测 | 检测当前网络的连接状态，可分为 1. 测试服务端状态 命令行：-k， --check 独立选项，输出以下值： 0: unavailable 1: network ok 2: service ok 3: service degraded 4: exiting 示例： 以下检测当前连接服务器运行状态 ```bash taos --check ``` 1. 网络速度测试 - -l PKTLEN: 网络测试时使用的测试包大小 - -n NETROLE: 网络连接测试时的测试范围，可选 client（默认） server - -N PKTNUM: 网络测试时使用的测试包数量 示例： ```bash # server is runing taos -n "server" # client to connect send data taos -l 100 -n "client" -N 10 ``` taos 模拟服务端以 “server” 身份启动 taos 模拟客户端向服务端 发送测试包大小为 100， 共 10 个测试包，测试客户端与服务器的通信连接及速度情况 |

### 4.2 执行 SQL

#### 4.2.1 交互执行

| 需求编号 | 功能项 | 功能实现 |
| --- | --- | --- |
| 2.1 | 输入 SQL 执行 | 在交互窗口中输入需执行的 SQL 语句，加分号结尾回车后即可执行 示例： 在交互窗口中输入显示所有数据库命令 ```bash taos> show databases; ``` |
| 2.2 | 翻看历史执行 | 可通过上下小箭头翻看历史记录回车执行 |
| 2.3 | 列式查看执行结果 | 在 SQL 语句末尾增加 \G 选项可按每列式显示执行返回内容 示例： 列式显示表的 BLOCK 分布情况： ```bash taos> show table distributed yc\G; *************************** 1.row *************************** _block_dist: Total_Blocks=[0] Total_Size=[0.00 KiB] Average_size=[0.00 KiB] Compression_Ratio=[0.00 %] *************************** 2.row *************************** _block_dist: Block_Rows=[0] MinRows=[0] MaxRows=[0] AvgRows=[0] *************************** 3.row *************************** _block_dist: Inmem_Rows=[0] Stt_Rows=[1000000] ``` |
| 2.4 | 执行结果输出文件 | 执行结果可通过 >> 重定向符号输入至指定文件 示例： 把 test 库的 meters 超级表所有记录输出到 /root/meters.txt 文件中 ```bash taos> select * from test.meters >> /root/meters.txt; ``` |

#### 4.2.2 非交互执行

| 需求编号 | 功能项 | 功能实现 |
| --- | --- | --- |
| 2.5 | 命令行执行 | -s, --commands=COMMANDS 1. COMMANDS 可为一个或分号分隔的多个 SQL 语句 1. 传入的 SQL 语句被逐个顺序执行 1. SQL 语句中表名前需带数据库名 示例： 使用命令行显示所有数据库命令 ```bash taos -s "show databases;" ``` |
| 2.6 | 文件执行 | -f, --file=FILE 1. FILE 文件中每行一个 SQL 语句 1. 逐行从上至下顺序执行 1. SQL 语句中表名前需带数据库名 示例： 执行文件 sqls.txt 中的命令 ```bash taos -f sqls.txt ``` sqls.txt 中的内容： ```bash create database db; show databases; create table db.meters(ts timestamp, current float) tags(groupid int); ``` |

#### 4.2.3 执行选项

| 需求编号 | 功能项 | 功能实现 |
| --- | --- | --- |
| 2.7 | timestamp 方式展示时间 | -r, --raw-time 1. 独立选项，无参数 1. 所有时间都按 int64 值 timestmap 方式显示 示例： 连接到本地服务器 192.168.0.1 ，所有时间列以 timestamp 展示 ```bash taos -r -h 192.168.0.1 ``` |
| 2.8 | 列显示最大宽度 | --display-width=WIDTH 1. 可变数据类型的最大显示宽度 1. 默认值为 30 个字符 示例： 连接到本地服务器 192.168.0.1 ，可变列最大显示宽度为 100 字符 ```bash taos -h 192.168.0.1 --display-width=100 ``` |
| 2.9 | BI 显示模式 | -B, --bimode 1. 独立选项 1. 以符合 BI 工具的模式显示数据 示例： 连接到本地服务器 192.168.0.1 ，以 BI 模式显示数据及表 ```bash taos -B -h 192.168.0.1 ``` |

### 4.3 导入导出

| 需求编号 | 功能项 | 功能实现 |
| --- | --- | --- |
| 3.1 | 导出数据 | 1. 通过 >> 符号可以将查询结果导出到 CSV 文件。如： `select * from d0 >> '/root/d0.csv';` |
| 3.2 | 导入数据 | 1. 通过 SQL 末尾增加 file 和 文件路径方式，导入数据到表。如 `INSERT INTO meters(tbname, location, groupId, ts, current, voltage, phase) `` FILE '/tmp/csvfile_21002.csv';` |

### 4.4 TAB 键补全

| 需求编号 | 功能项 | 功能实现 |
| --- | --- | --- |
| 4.1 | 数据库名补全 | 1. 数据库名该出现地方补全 1. 数据库名做为全局补全项，在前缀补全无匹配下尝试数据库名 |
| 4.2 | 表名补全 | 1. 表名称该出现地方补全 1. 区分超级表与子表/普通表的不同位置进行补全 1. 子表名仅存储前十万个，防止过多占用 |
| 4.3 | 流计算名补全 | 流计算名应出现位置上补全 |
| 4.4 | TOPIC 名补全 | 订阅名应出现位置上 |
| 4.5 | 命令词补全 | 1. 命令关键词应出现位置上补全 1. 支持全部命令语 |
| 4.6 | 函数补全 | 1. 所有函数名都支持 1. 函数名均在 select 开头语句中出现 1. 不支持函数参数 |
| 4.7 | 空白处补全 | 1. 空白处补此位置可出现的数据库名、表名、命令词等 1. 再次按 Tab 键可切换下一个 1. 多个按使用频率排序出现 |
| 4.8 | 前缀补全 | 1. 此位置可出现的相同前缀可数据库名、表名、命令词等 1. 再次按 Tab 键可切换下一个 1. 多次按 Tab 键，按使用频率排序出现 |

## 5. 性能

TDengine TSDB CLI 主要为交互式工具，以功能为主的单线程运行模式，对性能指标不做要求。

## 6. 安全

- 凭据保护（对应 T-CLI-01）：密码/DSN token 默认不回显、不写入日志/历史；支持交互输入或环境变量读取；显示时仅保留前后少量字符；翻看命令历史记录功能中不提供带密码的命令回翻。
- 传输加固（T-CLI-02）：支持启用 TLS，建议生产系统强制使用 TLS 传输加密并记录配置。
- 路径与权限校验（T-CLI-03）：导入/导出、日志输出路径需存在且在允许目录内，拒绝相对路径穿越；输出文件权限设为 0600；禁止覆盖系统关键文件。
- 输入校验与注入防护（T-CLI-04）：命令行与文件 SQL 做格式校验；拒绝空密码远程连接；导入 CSV/文件执行设置行数与大小上限并失败中断。
- 补全与缓存控制（T-CLI-05）：TAB 补全可配置上限（子表约 100k）；可关闭补全；补全与错误输出不泄露敏感元数据。
- 速率与配额（T-CLI-06）：网络检测命令限制频率/并发，必要时二次确认；批量 SQL/文件执行设置超时与行数上限。
- 日志脱敏与最小化（T-CLI-07）：默认仅输出必要信息；错误/调试日志不含完整路径、凭据或 token 全值。
- 审计与可追溯（T-CLI-08）：为连接/执行生成请求 ID；关键操作可选写审计日志（不含敏感内容），与引擎日志可关联。

## 7. 兼容性

1. 在 TDengine 对外接口没有改变情况下可以做到完全兼容，在少量接口变动情况下，变动接口无法兼容。
2. 对支持命令行参数实现向下完全兼容。

## 8. 运维

1. 软件使用 C 语言编写，运维期间需配置好 core 文件生成，方便崩溃后快速定位原因
2. 软件可多个实例同时独立运行，互不影响
3. 支持重定向符导出输出信息至文件

## 9. 使用场景

1. 数据库管理员日常维护。
2. 开发人员开发测试查询。
3. 数据分析人员手工统计。
4. 自动化脚本执行 SQL。

## 10. 约束和限制

约束：无
限制：
1. 工具为单连接线程模式，大数据量查询时间长
2. 在命令行补全子表名中最大缓存 10 W

## 11. 常见错误和排查

1. 数据库连接失败请参考引擎错误信息
2. 大小写敏感元数据名称需使用反引号
3. 长查询可使用 CTRL + C 命令取消

## 12. 可观测性

是一个命令行交互工具
本工具不直接对 TDengine 产品组件 taos Explorer，TDinsight 产生影响，但其调用引擎会影响这几个可观测组件中管理数据、写入数据及流量、查询数据及流量数据等的变化。
