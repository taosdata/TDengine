## 2. 引言

数据备份及还原功能是数据库运维中保证数据安全的重要功能之一，TDengine 作为开源软件，需要向社区提供一款开源的数据库备份及还原工具，支持对指定的数据库或超级表进行单独备份，并能指定备份数据开始及结束时间，可还原至新指定的数据库中，满足不同备份及还原需求。
向 TDengine 开源社区提供一个高效数据备份及还原工具。

### 2.1 术语与缩写名词

**命令行参数**：指通过命令行输入的长参及短参
**WebSocket**：是一种在单个TCP连接上进行全双工通信的协议。它基于TCP协议，通过HTTP/1.1协议的101状态码进行握手，从而建立连接。WebSocket允许服务器和客户端之间进行实时双向通信，客户端和服务器之间的数据交换变得更加简单和高效。
**Native **:  指直接调用引擎提供的 libtaos.so 客户端库接口的行为

### 2.2 相关文档资料

1. TDengine 引擎文档  [内核](https://taosdata.feishu.cn/wiki/NsOlwRcXbifgbtkbHzYcPC3Mnlg)
2. Apache avro 文件格式：https://github.com/apache/avro

### 2.3 优先级要求

本工具需随 TDengine 3.0 产品一起发布，节奏要与 TDengine 3.0 开发一致

### 2.4 版本要求

本工具无独立版本，跟随 TDengine 版本号

## 3. 需求目标

能够向 TDengine 社区开源用户提供一款简单快速的数据备份及还原工具：
1. 提供连接 TDengine 服务器功能
2. 提供数据库整体备份功能
3. 提供指定表及指定时间段单独备份功能
4. 提供数据库恢复功能
5. 提供多线程并发备份/恢复能力

## 4. 功能需求

以下列出工具主要需求：

| 序号 | **功能类别** | **功能名称** | 功能描述 |
| --- | --- | --- | --- |
| 1 | 连接功能 |  |  |
| 1.1 |  | 连接本地部署 TDengine | 通过提供主机名、端口、用户名及密码可连接至本地部署的 TDengine 数据源上 |
| 1.2 |  | 连接 TDengine Cloud | 通过提供云服务的授权认证 token 及云服务主机地址，可以连接至云服务数据源上 |
| 1.3 |  | 连接驱动选择 | 可指定连接 TDengine 的驱动类型，支持`Native`（原生驱动，默认）、`WebSocket`两种驱动，适配不同网络环境的连接需求 |
| 1.4 |  | 连接失败重试配置 | 可设置连接失败、查询失败时的重试次数，避免因网络抖动导致的操作失败 |
| 1.5 |  | 重试间隔设置 | 可配置连接 / 查询重试的时间间隔（单位：毫秒），灵活控制重试频率 |
| 2 | 数据备份 |  |  |
| 2.1 |  | 备份所有数据库 | 备份当前连接的所有数据库，包括系统数据库 |
| 2.2 |  | 备份指定数据库 | 只备份指定的数据库，可以指定多个 |
| 2.3 |  | 备份指定表 | 可以指定多个特定表进行备份 |
| 2.4 |  | 设置输出目录 | 可设置备份的数据文件输出目录 |
| 2.5 |  | 设置备份时间段 | 可设置备份指定时间段的数据 |
| 2.6 |  | 设置批大小 | 可设置备份的每个批数据大小 |
| 2.7 |  | 备份线程数 | 可设置备份使用的并发数 |
| 2.8 |  | 仅备份 schema | 可只备份 schema 数据 |
| 2.9 |  | 不使用反引号 | 提供不使用反引号的 sql 语句支持 |
| 2.10 |  | 点号换为下划线 | 可以把元数据名称中的点号更换成下划线替代 |
| 2.11 |  | 备份时排除数据库属性 | 不备份数据库自身的属性配置信息 |
| 2.12 |  | Avro 编码格式选择 | 可指定备份数据文件的 Avro 编码格式，支持`null`（无压缩）、`deflate`、`snappy`、`lzma`四种；其中`lzma`编码格式暂不支持 Windows 系统 |
| 2.13 |  | 数据库名转义字符支持 | 支持为特殊命名的数据库名添加转义字符，适配数据库名含特殊符号的场景 |
| 2.14 |  | 松散模式 | 当待备份的表名、列名**仅包含字母和数字**时，可启用松散模式提升备份效率 |
| 3 | 数据还原 |  |  |
| 3.1 |  | 还原功能 | 把备份的数据文件还原至某数据库 |
| 3.2 |  | 还原线程数 | 还原时可指定并发能力 |
| 3.3 |  | 还原时改库名 | 还原时可以修改原来备份时的数据库名，支持可以改多个 |
| 3.4 |  | 备份文件完整性检查 | 在还原前可对要还原的备份文件做检查，输出备份的简要信息 |
| 4 | 通用选项 |  |  |
| 4.1 |  | 导入 / 导出结果文件路径 | 可指定备份、还原操作的**执行结果文件**生成路径及文件名 |
| 4.2 |  | 日志文件路径 | 在备份及还原时指定日志文件生成路径 |
| 4.3 |  | taos.cfg 配置位置 | 在 Native 连接场景下指定 taos.cfg 配置文件位置 |
| 4.4 |  | 连接超时 | 可以设置 WebSocket 下的交互超时时间 |
| 4.5 |  | 调试模式 | 支持调试模式启动运行，打印更多信息 |
| 4.6 |  | 帮助信息 | 打印帮助相关信息 |
| 4.7 |  | 打印简短使用说明 | 支持打印工具的**极简使用语法**，区别于完整帮助信息，快速展示核心使用方式 |
| 4.8 |  | 显示版本号 | 显示当前的版本号及编译信息 |

## 5. 性能需求

数据导出性能要求不低于 200W数据点/ 秒
数据导入性能要求不低于 100W数据点/ 秒

## 7. 其他需求

描述功能、性能之外的需求。
- 兼容性需求
   - 接口兼容：支持原命令行
   - 数据兼容性：向后兼容
- 接口需求
全部为命令行接口实现
- 运维需求
工具要求能够在长时间运行状态下不能有内存泄露情况
- 易用性需求
命令行参数尽可能简洁明了表意
- 测试需求（不含测试例）
   功能有测试用例覆盖
   提供调试模式，方便测试
