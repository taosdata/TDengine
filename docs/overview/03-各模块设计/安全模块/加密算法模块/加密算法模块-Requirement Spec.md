## 2. 引言

本文档定义了加密算法集成需求，旨在为"存储安全"和"身份鉴别"功能提供统一的加密算法支持框架。通过集成国密算法和标准安全算法，并支持自定义算法扩展，构建安全、高效、可扩展的加密服务体系，满足不同场景下的数据保护和身份认证需求。

### 2.1 术语与缩写名词

| **术语/缩写** | **全称/解释** |
| --- | --- |
| **SM2** | 国密非对称加密算法，基于椭圆曲线密码学 |
| **SM3** | 国密哈希算法，输出256位哈希值 |
| **SM4** | 国密对称加密算法，分组长度为128位 |
| **SM9** | 国密标识密码算法，基于身份标识的密码系统 |
| **RSA** | Rivest-Shamir-Adleman 非对称加密算法 |
| **AES** | Advanced Encryption Standard 对称加密算法 |
| **ECC** | Elliptic Curve Cryptography 椭圆曲线密码学 |
| **SHA** | Secure Hash Algorithm 安全哈希算法 |
| **UKEY** | 硬件加密设备，用于存储密钥和进行加密运算 |
| **DLL** | Dynamic Link Library 动态链接库 |

## 3. 需求目标

在"存储安全"和"身份鉴别"功能开发过程中，涉及到很多加密算法。本需求的目标是集成这些算法：
1. **国密系列加密算法**：满足国家密码管理局要求，支持国产密码算法
2. **标准安全加密算法**：支持国际通用加密算法，确保系统兼容性和安全性
通过统一的算法接口和管理机制，为上层应用提供透明、可配置的加密服务。

## 4. 功能需求

| **序号** | **功能类别** | **功能名称** | **功能描述** |
| --- | --- | --- | --- |
| **4.1** | 算法管理 | 算法列表展示 | 通过 SQL 语法查看系统当前的加密算法，增加系统表 ins_encrypt_algorithems |
| **4.2** | 算法扩展 | 自定义加密算法 | 支持用户通过动态链接库方式添加自定义加密算法 |
| **4.3** | 算法集成 | 新增加密算法 | 按照"算法标准接口"封装国密和国标算法 |

### 4.1 算法列表展示

通过 SQL 语法查看系统当前的加密算法，增加系统表 ins_encrypt_algorithems，各列定义如下
1. **算法名称**：简称，例如 sm2、sm3 等
2. **算法描述**：完整的字符串
3. **算法类型**：如 1-散列算法、2-对称加密、3-非对称加密、4-编码方法
4. **算法来源**：内置算法、UKEY、用户自定义
5. **其他信息**：如算法库路径等

### 4.2 自定义加密算法

除内置加密算法外，系统还支持用户自定义的加密算法。增加名为“自定义加密算法路径”的配置项，字符串类型，可配置多个路径。自定义加密算法以动态链接库方式已提供，需实现“算法标准接口”。接口规范在设计时给出，以满足“[存储安全](https://taosdata.feishu.cn/wiki/UYAqwU3GqiBsjCkT6BccKqLmnGh)”功能对接口的要求为准，需要包括：
1. **基本信息获取**：算法名称、描述、类型等
2. **加解密接口**：输入信息、输出信息、密钥信息等
3. 创建和销毁接口等

### 4.3 新增加密算法

改造现有加密算法，按照"算法标准接口"进行封装、使用、展示：
1. **国密算法集成**
   - **SM2**：非对称加密算法，用于数字签名和密钥交换
   - **SM3**：哈希算法，用于数据完整性验证
   - **SM4**：对称加密算法，用于数据加密
   - **SM9**：标识密码算法，基于身份标识的加密和签名
2. **国标算法集成**
   - **RSA-2048+/RSA-4096**：非对称加密，用于证书和密钥交换
   - **ECC-256+/ECC-384**：椭圆曲线加密，高效的非对称算法
   - **AES-128+/AES-256**：对称加密，支持 CBC、GCM 等模式
   - **SHA-256+/SHA-384/SHA-512**：哈希算法，用于数据完整性
3. **算法安全要求**
   - **不实现不安全的算法**：MD5、SHA-1、DES、3DES、RC4、RSA-1024 及以下
   - 所有算法需通过安全审计，无已知漏洞
   - 密钥长度符合当前安全标准（对称算法 ≥128 位，非对称算法 ≥2048 位）

## 5. 性能需求

1. **算法调用延迟**：单个加密/解密操作在 1ms 内完成（在标准硬件环境下）
2. **并发处理能力**：支持至少 1000 个并发加密请求
3. **内存占用**：每个算法实例内存占用不超过 10MB
4. **启动时间**：系统启动时算法加载时间不超过 5 秒
5. **吞吐量要求**：
   - **对称加密**：≥100MB/s
   - **哈希计算**：≥200MB/s
   - **非对称加密**：≥1000次签名/秒

## 6. 安全可控需求

1. **算法安全性**：
   - 所有集成的算法需无已知安全漏洞
   - 提供算法安全证明或权威机构认证链接
   - 定期更新算法库，修复安全漏洞
2. **密钥管理**：
   - 密钥生成使用安全的随机数发生器
   - 密钥存储使用硬件加密模块或安全存储区
   - 密钥生命周期管理：生成、存储、使用、轮换、销毁
3. **访问控制**：
   - 算法调用需要权限验证
   - 敏感操作（如密钥导出）需要多重认证
   - 操作日志记录，便于审计追踪
4. **防攻击能力**：
   - 抵抗侧信道攻击
   - 抵抗时序攻击
   - 抵抗故障注入攻击
5. **代码可控性**：
   - **自研代码控制**：核心加密算法模块优先采用自研实现，确保代码透明度和可控性
   - **第三方库安全审查**：集成第三方加密库时，需进行严格的安全审查：
      - 使用前进行漏洞扫描和安全评估
      - 优先选择经过权威机构认证的加密库
      - 定期更新第三方库，及时修复安全漏洞
      - 建立第三方库漏洞应急响应机制
   - **许可证合规性**：
      - 所有使用的第三方库必须符合项目许可证要求
      - 避免使用具有传染性许可证（如GPL）的加密库
      - 商业使用需确保许可证合法有效
      - 建立许可证管理台账，定期审计
   - **代码审计与验证**：
      - 关键加密代码需经过第三方安全审计
      - 实现代码签名机制，确保代码完整性
      - 建立代码版本控制和安全发布流程

## 7. 其他需求

### 7.1 兼容性需求

1. **操作系统兼容**：支持主流Linux发行版（CentOS 7+, Ubuntu 18.04+）
2. **硬件兼容**：支持x86_64和ARM64架构
3. **数据库兼容**：与系统现有SQL语法兼容
4. **算法兼容**：新算法与旧数据兼容，支持算法迁移

### 7.2 接口需求

1. **SQL接口**：通过系统表查询算法信息
2. **配置接口**：通过配置文件管理算法路径和参数
3. **日志接口**：统一的日志输出格式和级别

### 7.3 易用性需求

1. **配置简化**：提供默认配置，减少用户配置项
2. **文档完善**：提供详细的API文档和使用示例
3. **错误提示**：明确的错误码和错误信息
4. **调试支持**：提供调试模式和详细日志

### 7.4 测试需求

1. **单元测试**：每个算法接口都需要单元测试
2. **性能测试**：验证性能指标是否达标
3. **安全测试**：进行渗透测试和漏洞扫描
4. **兼容性测试**：在不同环境和配置下测试算法功能
5. **压力测试**：高并发场景下的稳定性测试
