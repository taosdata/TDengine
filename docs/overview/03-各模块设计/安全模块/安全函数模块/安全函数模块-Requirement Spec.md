### 2.3 优先级要求

**优先级：高**
安全函数模块是数据库安全体系的核心组件，直接关系到用户数据的安全防护能力和合规性要求。该模块的及时交付对满足企业级客户的数据安全需求至关重要。

### 2.4 版本要求

1. **企业版专属功能**：
   - SM4国密加密/解密函数
   - AES加密/解密函数
   - 完整脱敏函数集（MASK_FULL, MASK_PARTIAL, MASK_NONE）
2. **社区版基础功能**：
   - Base64 编码/解码函数
   - 基础哈希函数（MD5, SHA1, SHA2）
   - 基础脱敏函数（MASK_NONE）

## 3. 需求目标

#### 3.0.1 总体目标

构建一套完整、易用、高效的数据安全函数集，为数据库系统提供全面的数据安全处理能力，满足不同业务场景下的数据加密、编码转换、哈希计算和数据脱敏需求。

#### 3.0.2 具体目标

1. **数据加密能力**：提供国密和国际标准双重加密算法支持，确保数据存储和传输安全
2. **数据脱敏能力**：提供灵活可配置的数据脱敏方案，保护敏感信息不被未授权访问
3. **编码转换能力**：提供标准编码解码函数，支持二进制数据的文本化处理
4. **哈希计算能力**：提供多种哈希算法，支持数据完整性校验和指纹生成
5. **性能与安全平衡**：在保证安全性的前提下，优化函数性能，减少对数据库操作的影响

## 4. 功能需求

### 4.1 加密函数

#### 4.1.1 SM4 加密函数

1. 语法：`SM4_ENCRYPT(str)`
2. 说明：
   - 使用 SM4 算法对数据进行加密
   - 创建用户时，如果指定了“存储加密密钥”，则会自动生成适配算法的密钥
   - 支持在 INSERT 和 SELECT 语句中使用
3. 示例
```sql {wrap}
SELECT SM4_ENCRYPT('abcd');
INSERT INTO t VALUES (1, SM4_ENCRYPT('abcd'));
```

#### 4.1.2 SM4 解密函数

1. 语法：`SM4_DECRYPT(str)`
2. 说明
   - 使用 SM4 算法对数据进行解密
   - 创建用户时，如果指定了“存储加密密钥”，则会自动生成适配算法的密钥
   - 支持在 INSERT 和 SELECT 语句中使用
3. 示例
```sql {wrap}
SELECT ts，SM4_DECRYPT(data) from t;
```

#### 4.1.3 AES 加密函数

1. 语法：`AES_ENCRYPT(str, key_str[, init_vector])`
2. 说明：
   - 使用密钥 `key_str`（和可选的初始化向量 `init_vector`）对明文 `str`进行加密，返回二进制字符串
   - 支持在 INSERT 和 SELECT 语句中使用，参见 MySQL 的语法实现。

#### 4.1.4 AES 解密函数

1. 语法：`AES_DECRYPT(crypt_str, key_str[, init_vector])`
2. 说明：
   - `AES_DECRYPT`使用相同的密钥 `key_str`（和初始化向量 `init_vector`）对密文 `crypt_str`进行解密，返回原始明文字符串。
   - 支持在 INSERT 和 SELECT 语句中使用，参见 MySQL 的语法实现。

### 4.2 编码函数

#### 4.2.1 Base64 编码函数

1. 语法：`TO_BASE64(str)`
2. 说明：
   - 将字符串或二进制数据转换为 Base64 编码的字符串。
   - 支持在 INSERT 和 SELECT 语句中使用，具体要求参见 MySQL 的语法实现。
3. 示例
```sql {wrap}
SELECT TO_BASE64('abcd');
INSERT INTO t VALUES (1, TO_BASE64('abcd'));
```

#### 4.2.2 Base64 解码函数

1. 语法：`FROM_BASE64(str)`
2. 说明：
   - 将 Base64 编码的字符串解码回原始的二进制数据或字符串。
   - 支持在 INSERT 和 SELECT 语句中使用，具体要求参见 MySQL 的语法实现。
3. 示例
```sql {wrap}
SELECT ts，FROM_BASE64(data) from t;
```

### 4.3 哈希函数

#### 4.3.1 MD5 函数

1. 语法：`MD5(str)`
2. 说明：
   - 计算字符串 `str`的 MD5 哈希值，返回一个 32 位的十六进制字符串。MD5 已经不安全，但为功能全面性考虑，仍需提供。
   - 支持在 INSERT 和 SELECT 语句中使用，具体要求参见 MySQL 的语法实现。
3. 示例
```sql {wrap}
SELECT MD5('Hello World');
```

#### 4.3.2 SHA1 函数

1. 语法：`SHA1(str)`
2. 说明：
   - 是一种生成160位（20字节）哈希值的加密哈希函数，其结果通常表示为40位的十六进制字符串。
   - 支持在 INSERT 和 SELECT 语句中使用，具体要求参见 MySQL 的语法实现。
3. 示例
```sql {wrap}
SELECT SHA1('Hello World');
```

#### 4.3.3 SHA2 函数

1. 语法：`SHA2(str)`
2. 说明：
   - 计算字符串 `str`的哈希值，支持 224、256、384、512 位。
   - 推荐使用 SHA-256。
   - 支持在 INSERT 和 SELECT 语句中使用，具体要求参见 MySQL 的语法实现。
3. 示例
```sql {wrap}
SELECT SHA2('Hello World');
```

### 4.4 脱敏函数

#### 4.4.1 MASK_FULL

1. 语法：`MASK_FULL(column_name, replacement_value)`
2. 说明​：将指定列的所有敏感数据替换为一个无意义的、统一的固定值。
3. 示例：
```sql {wrap}
SELECT MASK_FULL(name, 'CONFIDENTIAL') AS masked_name FROM users;
```

#### 4.4.2 MASK_PARTIAL

1. 语法：`MASK_PARTIAL(column_name, visible_prefix_length, visible_suffix_length, mask_char)`
2. 说明​：对数据进行部分遮蔽​，通常保留数据的部分前缀和/或后缀，中间用指定字符（如 `*`）填充。
3. 示例：
```sql {wrap}
SELECT MASK_PARTIAL(phone, 3, 4, '*') AS masked_phone FROM customers;
```

#### 4.4.3 MASK_NONE

1. 语法：`MASK_NONE(column_name)`
2. 说明​：不对数据做任何脱敏处理，直接返回原始值。通常用于白名单或测试场景。
3. 示例：
```sql {wrap}
SELECT MASK_NONE(salary) FROM sensitive_table;
```

## 5. 性能需求

#### 5.0.1 总体性能要求

1. 加解密函数的性能影响应控制在合理范围内，单次操作延迟增加不超过 50%
2. 编码解码函数的性能影响应最小化，目标延迟增加不超过 20%
3. 哈希函数的计算性能需优化，避免成为 CPU 密集型操作的瓶颈
4. 脱敏函数的性能影响应可忽略不计

#### 5.0.2 具体性能指标

1. 基准测试：需提供典型数据量的性能基准测试结果
2. 并发性能：支持高并发场景下的稳定性能表现
3. 资源占用：内存和 CPU 占用应在合理范围内
4. 扩展性：性能应随硬件资源线性扩展

## 6. 安全可控需求

### 6.1 密钥安全

1. SM4 加密密钥必须在数据库中加密存储
2. 密钥访问需有严格的权限控制
3. 密钥轮换机制需支持但不强制要求本期实现

### 6.2 函数安全

1. 所有安全函数需经过安全审计
2. 需防范时序攻击等侧信道攻击
3. 错误信息不应泄露敏感信息

### 6.3 可控性要求

1. **自主实现优先**：核心安全算法（如 SM4 国密算法）应优先考虑自主实现，确保代码可控性和安全性
2. **第三方库审慎引入**：如必须引入第三方加密库，需进行严格的安全评估和代码审计
3. **许可证合规**：所有引入的第三方库必须符合项目许可证要求，避免许可证冲突
4. **供应链安全**：建立第三方依赖管理机制，确保依赖库的来源可信、版本可控
5. **代码透明度**：安全函数的实现应保持代码透明度，便于安全审查和漏洞排查
6. **更新维护可控**：对引入的第三方库应有明确的更新和维护策略，确保及时修复安全漏洞

## 7. 兼容性需求

### 7.1 语法兼容性

1. 函数语法需与主流数据库系统保持兼容
2. 参数顺序和类型需符合行业惯例
3. 错误代码和消息需保持一致性

### 7.2 数据兼容性

1. 加密数据的存储格式需考虑未来版本兼容性
2. 哈希输出格式需与标准实现一致
3. 编码解码需支持跨平台数据交换

### 7.3 升级兼容性

1. 函数接口变更需考虑向后兼容
2. 数据迁移需提供平滑升级方案
3. 版本间性能差异应在可控范围内
