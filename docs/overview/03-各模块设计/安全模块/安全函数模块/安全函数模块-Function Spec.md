## 2. 背景

### 2.1 需求来源

安全函数的需求来自于安全函数需求规格（RS），旨在解决以下业务需求：
1. **数据加密存储**：敏感数据在数据库中应以加密形式存储，防止数据泄露
2. **数据脱敏展示**：在非生产环境或面向非授权用户时，需要对敏感数据进行脱敏处理
3. **数据完整性验证**：通过哈希函数验证数据完整性
4. **数据编码转换**：支持 Base64 等编码格式，便于数据传输和存储

### 2.2 业务价值

1. **合规性**：满足 GDPR、网络安全法等数据保护法规要求
2. **安全性**：降低数据泄露风险，保护企业核心资产
3. **灵活性**：提供多种安全处理方式，适应不同业务场景
**JIRA**: TS-7235

## 3. 定义

### 3.1 适用数据类型

函数中的适用数据类型，表示参数只接受说明中描述的数据类型，其他的数据类型会导致函数报错。

### 3.2 多字节安全

字符串函数的多字节安全（multibyte safe）指的是在处理多字节字符（比如中文字符）的时候，会把该字符当成一个整体来看待，而不是按照字节划分并按照多个个体来看待。
1. 多字节字符在匹配子串的时候，有一个中文字符 `你` 的十六进制表示为 `E4 BD A0`，此时假设有一个字符串的十六进制表示为 `E4 BD` ，该字符串并不会被认为是该中文字符的子串。
2. 在计算字符串的字符长度（CHAR_LENGTH）的时候，会把多字节字符 `你` 的长度算做 1，而非 3。
当前实现，只保证使用 UTF-8 编码的字符串的多字节安全。

### 3.3 不同数据类型比较规则

因为涉及到不同数据类型比较时的类型转换，在此定义比较规则。
1. 如果有任意参数为 NULL ，返回 NULL。
2. 如果输入参数都是同一类型，按照该类型比较，返回值也是该类型。
3. 数值类型和字符串类型比较，按照数值类型进行比较，返回值是字符串类型。
4. 如果输入参数包含 VARBINARY 类型，那么其余的参数必须都是 VARCHAR 或 VARBINARY 类型，否则会报错，此时按照 VARBINARY 类型进行比较，返回值为 VARBINARY 类型。

## 4. 行为说明

下面分四部分说明函数行为：加密函数，编码函数，哈希函数，脱敏函数。分别对应于 RS 中的这四类函数。

### 4.1 加密函数

#### 4.1.1 SM4_ENCRYPT

```plaintext
SM4_ENCRYPT(str, key_str)
```

**功能说明**：使用国密 SM4 算法对数据进行加密。SM4 是一种分组密码算法，分组长度和密钥长度均为 128 位。
**参数说明**：
- `str`：要加密的明文字符串，支持最大长度受数据库字段限制
- `key_str`：加密密钥，必须为 16 字节（128 位）的字符串
**返回结果类型**：`VARCHAR`，返回 Base64 编码的密文字符串
**适用数据类型**：字符串。
**使用说明**：
1. 支持在 INSERT 和 SELECT 语句中使用
2. key_str 为密钥
3. 仅企业版支持
**错误处理**：
- 如果密钥长度不正确，返回错误
- 如果输入字符串为空，返回空字符串
- 如果输入为NULL，返回NULL
**举例**：
```sql
-- 插入加密数据INSERT INTO user_sensitive (id, encrypted_data) 
VALUES (1, SM4_ENCRYPT('敏感数据内容', 'my16bytekey12345'));

-- 查询时加密SELECT id, SM4_ENCRYPT(plain_text, 'my16bytekey12345') AS encrypted 
FROM source_table;
```

#### 4.1.2 SM4_DECRYPT

```plaintext
SM4_DECRYPT(crypt_str, key_str)
```

**功能说明**：使用 SM4 算法对数据进行解密
**参数说明**：
- `crypt_str`：要解密的密文字符串，必须是SM4_ENCRYPT函数加密的结果
- `key_str`：解密密钥，必须与加密时使用的密钥相同
**返回结果类型**：字符串。
**适用数据类型**：字符串。
**使用说明**：
1. key_str 为密钥
2. 仅企业版支持
3. 输入必须是 Base64 编码的密文
**注意事项**：
- 密钥丢失将导致数据无法解密，请务必做好密钥备份
- 建议定期更换密钥，增强安全性
**举例**：
```sql
-- 查询并解密数据
SELECT id, SM4_DECRYPT(encrypted_data, 'my16bytekey12345') AS plain_text FROM user_sensitive;

-- 在WHERE条件中使用
SELECT * FROM user_sensitive WHERE SM4_DECRYPT(encrypted_data, 'my16bytekey12345') LIKE '%特定内容%';
```

#### 4.1.3 AES_ENCRYPT

```plaintext
AES_ENCRYPT(str, key_str[, init_vector])
```

**功能说明**：在 AES-128-CBC 模式下，把字符串加密为密文。AES（Advanced Encryption Standard）是美国联邦政府采用的一种区块加密标准。
**参数说明**：
- `str`：要加密的明文字符串
- `key_str`：加密密钥，支持 128 位、192 位或 256 位长度
- `init_vector`：可选，初始化向量，用于 CBC 模式，增强安全性
**返回结果类型**：字符串。
**适用数据类型**：字符串。
**使用说明**：
1. `key_str` 为密钥，`init_vector` 为初始化向量
2. 支持密钥长度：128 位（16 字节）、192 位（24 字节）、256 位（32 字节）
3. 默认使用 PKCS7 填充
4. 建议使用初始化向量以提高安全性
**举例**：
```sql {wrap}
-- 使用固定密钥加密
SELECT AES_ENCRYPT('重要数据', 'my_secret_key_123') AS encrypted_data;

-- 使用SHA2生成的密钥和初始化向量
SELECT AES_ENCRYPT(
    'text', 
    SHA2('My secret passphrase', 256),
    SUBSTRING(SHA2(RAND(), 256), 1, 16)
) AS encrypted_data;
```

#### 4.1.4 AES_DECRYPT

```plaintext
AES_DECRYPT(crypt_str, key_str[, init_vector])
```

**功能说明**：把字符串密文解密为明文。
**参数说明**：
- `crypt_str`：要解密的密文字符串
- `key_str`：解密密钥，必须与加密时使用的密钥相同
- `init_vector`：可选，初始化向量，必须与加密时使用的相同
**返回结果类型**：字符串。
**适用数据类型**：字符串。
**使用说明**：
1. `key_str` 为密钥，`init_vector` 为初始化向量
2. 密钥和初始化向量必须与加密时使用的完全一致
3. 支持 AES-128、AES-192、AES-256 解密
**举例**：
```sql {wrap}
-- 解密数据
SELECT AES_DECRYPT(
    AES_ENCRYPT('text', SHA2('My secret passphrase', 512)),
    SHA2('My secret passphrase', 512)
) AS decrypted_text;

-- 完整示例
SELECT AES_DECRYPT(AES_ENCRYPT('text', 'key123'), 'key123') as str;
```

**输出**：
```plaintext
             str       
========================
                'text' 
```

### 4.2 哈希函数

#### 4.2.1 MD5

```plaintext
MD5(str)
```

**功能说明**：计算字符串的 MD5 128 位校验和。MD5（Message-Digest Algorithm 5）是一种广泛使用的密码散列函数。
**参数说明**：
- `str`：要计算哈希值的字符串
**返回结果类型**：`VARCHAR(32)`，返回32位十六进制字符串
**适用数据类型**：字符串类型
**使用说明**：
1. 如果输入为 `NULL`，则返回 `NULL`
2. MD5已不再被认为是安全的加密哈希函数，不建议用于密码存储
3. 适用于数据完整性校验和非安全相关的哈希需求
**举例**：
```sql
-- 计算MD5哈希值
SELECT MD5('testing') AS md5_hash;
```

**输出**：
```plaintext
    MD5('testing')                     
=======================================
    'ae2b1fca515949e5d54fb22b8ed95575' 
```

#### 4.2.2 SHA1 / SHA

```plaintext
SHA1(str)
```

**功能说明**：计算 SHA1 160 位校验和，具体可参考 RFC 3174。SHA-1（Secure Hash Algorithm 1）是由美国国家安全局设计。
**参数说明**：
- `str`：要计算哈希值的字符串
**返回结果类型**：`VARCHAR(40)`，返回40位十六进制字符串
**适用数据类型**：字符串类型
**使用说明**：
1. `SHA` 与 `SHA1` 是同义词
2. 如果输入为 `NULL`，则返回 `NULL`
3. SHA-1已发现碰撞漏洞，不建议用于安全敏感场景
**举例**：
```sql
-- 计算SHA1哈希值
SELECT SHA1('abc') AS sha1_hash;

-- 使用SHA别名
SELECT SHA('abc') AS sha_hash;
```

**输出**：
```plaintext
    SHA1('abc')                                
================================================
    'a9993e364706816aba3e25717850c26c9cd0d89d' 
```

#### 4.2.3 SHA2

```plaintext
SHA2(str, hash_length)
```

**功能说明**：计算 SHA2 系列的哈希函数，支持 SHA-224, SHA-256, SHA-384, SHA-512 等算法。SHA-2（Secure Hash Algorithm 2）是 SHA-1 的替代品。
**参数说明**：
- `str`：要计算哈希值的字符串
- `hash_length`：哈希长度，支持 224、256、384、512
返回结果类型：
- SHA-224: `VARCHAR(56)`
- SHA-256: `VARCHAR(64)`
- SHA-384: `VARCHAR(96)`
- SHA-512: `VARCHAR(128)`
**适用数据类型**：字符串类型
**使用说明**：
1. 当 `hash_length` 为 0 时，作为 256 处理
2. 如果输入为 `NULL`，则返回 `NULL`
3. SHA-256 是目前推荐的安全哈希算法
**举例**：
```sql
-- 计算SHA-256哈希值（推荐）
SELECT SHA2('password123', 256) AS password_hash;

-- 计算SHA-512哈希值
SELECT SHA2('敏感数据', 512) AS secure_hash;

-- hash_length为0时使用SHA-256
SELECT SHA2('abc', 0) AS default_hash;
```

**输出**：
```plaintext
    SHA2('abc', 224)                                           
===============================================================
    '23097d223405d8228642a477bda255b32aadbce4bda0b3f7e36c9da7' 
```

### 4.3 脱敏函数

脱敏函数提供数据掩码功能，用于保护敏感信息在展示时的隐私。

#### 4.3.1 MASK_FULL

```plaintext
MASK_FULL(column_name, replacement_value)
```

**功能说明**：将目标数据进行全脱敏处理，用指定的替换值完全替换原数据。
**参数说明**：
- `column_name`：要进行脱敏的列名或表达式
- `replacement_value`：替换值，将完全替代原数据
**返回结果类型**：字符串，与`replacement_value`类型相同
**适用数据类型**：字符串类型
**举例**：
```sql
-- 客户姓名全脱敏
SELECT 
    id,
    MASK_FULL(name, 'CONFIDENTIAL') AS masked_name,
    email
FROM customers;
```

**输出**：
```plaintext
    masked_name    
===================
    'CONFIDENTIAL' 
```

#### 4.3.2 MASK_PARTIAL

```plaintext
MASK_PARTIAL(column_name, visible_prefix_length, visible_suffix_length, mask_char)
```

**功能说明**：将目标数据进行部分脱敏处理，保留前后指定长度的字符，中间用掩码字符替换。
**参数说明**：
- `column_name`：要进行脱敏的列名或表达式
- `visible_prefix_length`：前面保留的字符数
- `visible_suffix_length`：后面保留的字符数
- `mask_char`：掩码字符，用于替换中间部分
**返回结果类型**：字符串。
**适用数据类型**：字符串类型
**使用场景**：
- 手机号部分脱敏：138****1234
- 身份证号部分脱敏：1101**********1234
- 邮箱部分脱敏：abc***@example.com
**注意事项**：
- 如果原字符串长度小于`visible_prefix_length + visible_suffix_length`，则全部用掩码字符替换
- 支持多字节字符，按字符数计算而非字节数
**举例**：
```sql
-- 手机号脱敏：保留前3位和后4位SELECT 
    id,
    MASK_PARTIAL(phone, 3, 4, '*') AS masked_phone
FROM customers;
```

**输出**：
```plaintext
    masked_phone  
===================
    '***2011****' 
```

#### 4.3.3 MASK_NONE

```plaintext
MASK_NONE(column_name)
```

**功能说明**：将目标数据进行空脱敏处理，即不进行任何脱敏操作，直接返回原数据。此函数主要用于脱敏策略的配置中，表示某些特定角色或场景下不需要脱敏
**参数说明**：
- `column_name`：要进行脱敏的列名或表达式
**返回结果类型**：字符串
**适用数据类型**：字符串
**使用场景**：
- 管理员角色查看原始数据
- 内部审计和监控
- 数据导出到安全环境
- 脱敏策略中的例外配置
**注意事项**：
- 此函数不会改变数据，仅用于脱敏策略的一致性
- 需要结合访问控制策略使用，确保只有授权用户能访问原始数据
**举例**：
```sql
-> SELECT MASK_NONE(salary) AS salary FROM customers;
```

**输出**：
```plaintext
    salary        |
===================
    '2011'        |
```

### 4.4 编码函数

编码函数提供数据格式转换功能，支持 Base64 编码和解码。

#### 4.4.1 FROM_BASE64

```plaintext
FROM_BASE64(str)
```

**功能说明**：解码 base64 编码的字符串，将 Base64 编码的数据还原为原始二进制或字符串数据。
**参数说明**：
- `str`：Base64 编码的字符串
**返回结果类型**：`VARCHAR`，返回解码后的字符串
**适用数据类型**：BINARY, VARCHAR 字符串
**使用说明**：
1. 如果输入为 `NULL`，则返回 `NULL`
2. 如果输入为非法的 base64 编码，则返回 `NULL`
3. 支持标准的 Base64 编码（RFC 4648）
4. 自动处理 Base64 URL安全字符（-和_）
**错误处理**：
- 非法 Base64 字符串：返回NULL
- 包含换行符：自动忽略
- 填充字符不正确：返回NULL
**举例**：
```sql
-> SELECT TO_BASE64('abc'), FROM_BASE64(TO_BASE64('abc'));
```

**输出**：
```plaintext
    TO_BASE64('abc')    |   FROM_BASE64(TO_BASE64('abc'))  |
===========================================================
    'JWJj'              | 'abc'                            |
```

#### 4.4.2 TO_BASE64

```plaintext
TO_BASE64(str)
```

**功能说明**：用 base64 编码字符串，将二进制或字符串数据转换为Base64编码格式。
**参数说明**：
- `str`：要编码的字符串或二进制数据
**返回结果类型**：`VARCHAR`，返回 Base64 编码的字符串
**适用数据类型**：BINARY, VARCHAR 字符串。
**使用说明**：
1. 如果输入为 `NULL`，则返回 `NULL`
2. 输出使用标准 Base64 编码（RFC 4648）
3. 每 76 个字符添加换行符（符合 MIME 规范）
4. 支持二进制数据编码
**编码规则**：
- 使用 A-Z、a-z、0-9、+、/共 64 个字符
- 每 3 个字节编码为 4 个字符
- 不足 3 字节时使用 = 填充
- 输出字符串长度是 4 的倍数
**举例**：
```sql
-> SELECT TO_BASE64('abc'), FROM_BASE64(TO_BASE64('abc'));
```

**输出**：
```plaintext
    TO_BASE64('abc')    |   FROM_BASE64(TO_BASE64('abc'))  |
===========================================================
    'JWJj'              | 'abc'                            |
```

### 4.5 特殊说明：

#### 4.5.1 版本支持差异

1. 加解密函数仅在企业版支持
  - SM4_ENCRYPT/SM4_DECRYPT
  - AES_ENCRYPT/AES_DECRYPT
  - 原因：加密功能涉及国家安全标准和技术出口限制
1. 其他函数在企业版和社区版都支持
  - 哈希函数：MD5、SHA1、SHA2
  - 脱敏函数：MASK_FULL、MASK_PARTIAL、MASK_NONE
  - 编码函数：FROM_BASE64、TO_BASE64

#### 4.5.2 语句支持范围

1. 脱敏函数只支持 SELECT 语句
  - 设计原因：脱敏主要用于数据展示，不应改变存储的数据
  - 使用限制：不能在INSERT、UPDATE、DELETE语句中使用
  - 例外情况：可以在CREATE VIEW中使用
1. 其他函数支持 SELECT 和 INSERT 语句
  - 加密函数：可在INSERT中加密存储，在SELECT中解密查询
  - 哈希函数：可在INSERT中计算哈希值存储
  - 编码函数：可在INSERT中编码存储，在SELECT中解码查询

#### 4.5.3 性能考虑

1. 加密函数：计算密集型，建议对热点数据建立索引的明文列
2. 哈希函数：中等计算量，适合批量处理
3. 脱敏函数：轻量级，对性能影响最小
4. 编码函数：中等计算量，Base64编码会增加约33%的数据量

#### 4.5.4 最佳实践建议

1. 密钥管理：使用专业的密钥管理系统（KMS）
2. 算法选择：优先使用 SHA-256 和 AES-256
3. 脱敏策略：基于角色设计分层脱敏策略
4. 性能监控：监控加密/解密操作的性能影响

## 5. 安全可控

1. SM4 的密钥保存在数据库中，已经进行加密。
2. 脱敏函数需要和动态数据脱敏策略结合，实现基于角色的、精细化的访问控制，本期不实现，但留下接口。

## 6. 性能

### 6.1 性能影响分析

下表展示了各类安全函数对数据库性能的影响：

| 函数类别 | 操作类型 | 性能影响范围 | 典型延迟增加 | 说明 |
| --- | --- | --- | --- | --- |
| 加密函数 | 写入（加密） | 20-50% | 35% | SM4/AES加密操作，数据量越大影响越明显 |
| 加密函数 | 查询（解密） | 30-60% | 45% | 解密操作需要计算资源，影响查询响应时间 |
| 哈希函数 | 写入（计算） | 10-30% | 20% | MD5/SHA1/SHA2哈希计算，中等计算量 |
| 哈希函数 | 查询（验证） | 5-15% | 10% | 哈希值验证，相对较轻量 |
| 编码函数 | 写入（编码） | 15-25% | 20% | Base64编码，增加约33%数据量 |
| 编码函数 | 查询（解码） | 10-20% | 15% | Base64解码，需要额外计算 |
| 脱敏函数 | 查询（全脱敏） | 1-5% | 3% | MASK_FULL，简单字符串替换 |
| 脱敏函数 | 查询（部分脱敏） | 2-8% | 5% | MASK_PARTIAL，需要计算可见部分长度 |

### 6.2 性能指标要求

| 指标类别 | 具体指标 | 测量方法 | 目标要求 |
| --- | --- | --- | --- |
| 吞吐量 | 每秒操作数（OPS） | 统计单位时间内的成功操作数 | 根据场景设定基准值 |
| 延迟 | P50（中位数） | 50% 请求的响应时间 | < 100ms（加密操作） |
| 延迟 | P95（95 分位） | 95% 请求的响应时间 | < 200ms（加密操作） |
| 延迟 | P99（99 分位） | 99% 请求的响应时间 | < 500ms（加密操作） |
| 资源使用 | CPU 使用率 | 监控进程 CPU 占用 | < 70%（峰值） |
| 资源使用 | 内存使用量 | 监控进程内存占用 | < 2GB（单个函数） |
| 资源使用 | 磁盘 IO | 监控读写操作频率 | 根据硬件配置评估 |
